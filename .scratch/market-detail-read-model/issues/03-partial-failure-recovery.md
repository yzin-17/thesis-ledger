# 03 — 分段状态与失败恢复闭环

**建设内容：** 为共享读模型补齐可区分的分段状态、局部失败展示和恢复动作，使行情详情在数据源部分不可用时仍然可用且可诊断。
**前置依赖：** Ticket 01 — 股票 Market Detail 最小闭环；Ticket 02 — ETF/基金能力矩阵闭环
**状态：** 已完成（确定性验证通过）

- [x] 统一实现 `ready`、`stale`、`empty`、`unsupported`、`unavailable` 五类分段状态；`loading` 保持为 Desktop 客户端本地状态，不写入服务端读模型。
- [x] 区分无数据、暂时不可用、缓存过期和能力不支持；错误使用稳定 code、用户可读 message 和诊断 ID，不透传 Provider 原始错误。
- [x] 保证 quote、bars、指标、chip、NAV 等分段独立成功或失败；指标共享依赖失败时向用户展示一条共同说明，同时保留各分段状态。
- [x] 为单个分段提供局部重试，为整页提供显式重试；`unsupported` 不进入重试队列。
- [x] 实现 `refresh=1` 的一次性显式刷新语义：绕过新鲜缓存，但允许使用 stale fallback；默认请求继续遵守缓存、single-flight 和超时边界。
- [x] 补齐后端契约、Server 状态映射、Desktop 状态呈现、重试行为和错误诊断测试。

验收标准：

- [x] 任一分段失败时，其他已成功分段仍可见，页面不会被整体错误遮罩替换。
- [x] 用户能够从分段级错误定位诊断信息并只重试失败分段；整页重试会重新读取当前资产的所有请求能力。
- [x] 缓存命中、stale fallback、显式 refresh 和空结果的行为可由确定性测试区分。
- [x] 常见指标依赖失败不会出现三条重复的同因错误提示，也不会隐藏仍然可用的行情分段。

范围外：在线 Provider 服务质量保证、DSA 内部缓存/并发优化和新增业务能力不属于本 Ticket。
