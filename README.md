# ThesisLedger

ThesisLedger 是一个本地优先的个人投资研究与风险管理系统。它统一管理账户、Ledger、持仓投影、行情、风险、策略回测、交易复盘和 AI 研究来源；系统只做分析与提醒，不连接券商下单。

## 架构

- `apps/server`：NestJS API，拥有用户事实和业务编排。
- `apps/desktop`：React 桌面 Web 界面，只访问 ThesisLedger API。
- `apps/mobile`：React Native 客户端边界，目前为只读能力入口。
- `packages/domain`：无基础设施依赖的确定性计算。
- `packages/schemas`：跨模块版本化契约。
- `services/dsa-adapter`：可替换行情 Provider、路由、健康和凭证类型；实际 Contract V1 兼容层在独立 DSA Fork 中。
- `../daily-stock-analysis`：同级 DSA Fork，不属于主仓源码；通过 `DSA_BASE_URL` 和 `/api/v1/thesis-ledger` Contract V1 接入。
- `../thesis-ledger-infra`：固定镜像和同级源码开发编排，不纳入主仓。
- PostgreSQL 保存事实；Redis 只保存缓存、锁和可重建状态。

文档入口：[docs/README.md](docs/README.md)。

## 快速开始

要求 Node.js 22、pnpm 10 和 Docker Desktop。

```bash
pnpm install --frozen-lockfile

cd ../thesis-ledger-infra
test -f .env || cp .env.example .env
docker compose --env-file .env -f compose.yml -f compose.dev.yml up --build -d
cd ../thesis-ledger
```

服务启动后访问：

- API 健康检查：`http://localhost:3000/api/v1/health`
- Desktop 开发环境：执行 `pnpm --filter @thesis-ledger/desktop dev`

首次启动后，可以在另一个终端初始化演示账户和示例标的：

```bash
cd ../thesis-ledger-infra
docker compose --env-file .env -f compose.yml -f compose.dev.yml exec thesis-ledger sh -c 'cd apps/server && ./node_modules/.bin/tsx prisma/seed.ts'
cd ../thesis-ledger
```

然后打开 `http://localhost:5173`。如果不使用演示数据，也可以直接在 Desktop 的“投资组合”页面创建自己的账户。停止服务时进入 `../thesis-ledger-infra` 执行同样的 Compose 命令并追加 `down`；不要添加 `-v`，否则会删除 PostgreSQL 和 Redis 的持久化卷。

`compose.yml` 和 `compose.dev.yml` 共同启动唯一的 `thesis-ledger-dev` 后端栈。前端不是 Docker 服务，继续通过 `pnpm --filter @thesis-ledger/desktop dev` 在本地运行，并访问 `http://localhost:3000` 的 API。

常用质量命令：

```bash
pnpm format
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

## 用户教程

ThesisLedger 的主流程是：选择账户 → 选择手动录入或截图导入 → 获取行情估值 → 分析收益和风险 → 进行策略回测、投资复盘和 AI 研究。Desktop 的所有页面都通过 ThesisLedger API 工作，页面会明确显示“暂无数据”“读取失败”或“数据可能陈旧”，不会把缺失数据伪装成正常值。

### 第一次使用

1. 打开 Desktop，在左侧进入“投资组合”。
2. 进入“录入持仓”。已有账户直接选择账户，主页面展示当前持仓和现金余额；点击“截图导入”后在右侧 Sheet 中上传并审核截图。点击“账户管理”可进入独立账户管理页，点击右上角“创建账户”后在右侧 Sheet 中填写账户，空列表进入该页时会自动打开 Sheet。账户填写名称、机构、类型、实际/影子模式和币种。
3. 手动录入页先查看持仓和现金余额，进入页面时录入 Sheet 默认关闭；点击“+ 添加持仓”或行内“编辑”后在右侧录入 Sheet 中保存绝对余额。证券代码使用带市场后缀的格式，例如 `600519.SH`，场外基金使用 `000001.OF`。截图导入先选择来源，再审核并提交需要更新的行。
4. 保存后点击页面刷新，组合会重新估值。现金在独立区域维护，不计入持仓成本和持仓盈亏；停用账户前需要先清空持仓和现金余额。
5. 接着进入“数据与自动化”检查 Provider 和通知状态，再进入“风险中心”创建第一条风险规则。

### 1. 投资组合

“投资组合”是日常使用的首页，包含以下功能：

- 顶部显示组合总市值、数据时点、持仓成本、累计浮盈亏和最大持仓。
- 当前持仓按市值排序，展示标的名称、代码、数量、成本价、市值、浮盈亏和行情状态。
- 状态为“陈旧”时，表示当前值来自过期行情或部分数据源不可用；应先检查数据时点和 Provider 状态。
- 点击持仓行中的“查看”，可以打开详情面板，查看最新报价、最近日线 K 线和可用的 MA/MACD/RSI/ATR 指标。筹码显示摘要；当 DSA 没有完整分布或主峰时，页面显示“未提供”，不会用猜测值替代。详情同时显示 Provider、行情时间和计算引擎信息。
- 点击“刷新”会重新读取组合和账户数据。读取失败时使用“重新加载”，不要把上一次显示的结果当作最新结果。

持仓编辑会更新同一账户、同一标的的数量和成本，并重新估值。系统不提供券商下单；这里的录入和编辑用于维护研究数据，不代表已经在真实账户成交。

### 2. 截图导入与审核

进入“导入持仓”后，按以下步骤操作：

1. 选择目标账户和截图来源。来源可以选择待识别、支付宝、同花顺或券商。
2. 上传 PNG、JPEG 或 WebP 格式的持仓截图，文件大小不超过 10 MB，点击“创建草稿”。
3. 在左侧导入历史中选择草稿。上传只会创建 Import Draft，不会直接修改持仓。
4. 在右侧逐行检查名称、证券代码、数量和成本价，处理低置信度、代码歧义和数值警告。需要时可以添加一行或删除错误行。
5. 所有字段确认无误后点击“确认并提交”。提交成功后组合会重新估值。
6. 如果需要撤销本次已提交导入，在对应记录中点击“回滚本次导入”，恢复到导入前的持仓状态。

截图应先脱敏再上传。无法确定的证券代码、数量或成本价不要直接提交；导入历史会保留草稿状态和来源置信度，便于之后复查。

### 3. 风险中心与通知

“风险中心”把风险判断、事件记录和通知投递分开管理。

#### 创建和维护规则

在“新建规则”中选择：

- 类型：价格低于、价格高于、成本止损、止盈或持仓集中度。
- 范围：证券、账户或组合。证券范围填写证券代码，账户范围选择账户，组合范围作用于整个组合。
- 阈值和严重级别：提示、警告、错误或严重。

点击“创建规则”后，规则会出现在规则列表。可以启用/停用规则，也可以点击“测试”用当前组合上下文进行人工测试；“扫描当前组合”会批量评估当前持仓并写入风险事件历史。规则的修改和启停都会产生新版本，点击“审计”可以查看操作和版本时间线。

#### 查看事件和通知

- “历史事件”显示触发消息、严重级别、规则版本、证券或组合范围、触发值和数据时间。
- “通知状态”显示渠道、级别、投递状态和尝试次数；失败记录不会被隐藏。
- 风险提醒是研究辅助，不是交易执行保证。事件落库不等于通知一定送达，也不等于系统会自动下单。

规则在缺少必要行情、历史序列或分母时会返回不可用，不会把缺失值当成零，也不会为了产生提醒而猜测结果。

### 4. 收益分析、快照和再平衡

进入“收益分析”后，可以在账户选择器中选择某个账户，也可以选择“全组合”。页面提供：

- 最新总资产：由 Snapshot 市值和现金组成。
- `TTWROR`：时间加权收益，用于尽量排除外部现金流影响。
- `XIRR`：在现金流信息足够时计算年化收益；无法计算时显示“不可计算”。
- 历史 Snapshot：回看每个时点的市值、成本、现金和采集时间。
- 资产配置：按资产类型汇总可用市值和当前权重。
- 再平衡缺口：比较当前权重和目标权重，显示缺口金额以及增配、减配或平衡建议。

在“目标配置”中填写 JSON 对象，例如：

```json
{ "股票": 0.6, "ETF": 0.4 }
```

所有权重之和必须为 `1`。保存后会生成新的目标配置版本。再平衡结果只提供分析建议，不会自动交易；缺失行情的标的不计为零，会保留数据不可用状态。

### 5. 策略实验与回测

“策略实验”用于保存可复现的策略版本并提交回测任务。每次保存都会保留版本，后续修改不会覆盖引用旧版本的历史回测。

#### 策略库与版本

打开 Desktop 的“策略实验”后，先在“策略库”查看策略名称、最新版本、状态、数据时点和最近回测。点击“新建策略”会打开编辑 Sheet：常用配置覆盖标的、信号、止损、仓位、执行和成本；需要完整控制时切换到“高级 JSON”，点击“应用 JSON”后再保存。

创建策略会生成 v1。编辑已有策略时，保存动作明确显示为“保存为新版本”，不会覆盖旧 Schema；回测始终绑定策略库中选中的具体版本。

默认示例包含以下字段：

```json
{
  "version": 1,
  "name": "我的第一条策略",
  "universe": { "symbols": ["600519.SH"], "asOf": "2025-01-01T00:00:00.000Z" },
  "entrySignals": [{ "indicator": "close", "operator": "gt", "value": 10 }],
  "exitSignals": [{ "indicator": "close", "operator": "lt", "value": 9 }],
  "stopLoss": { "type": "fixed", "value": 0.1 },
  "sizing": { "type": "weight", "value": 0.5 },
  "execution": { "price": "close", "tPlusOne": true, "lotSize": 100 },
  "cost": {
    "commissionRate": 0.0003,
    "minimumCommission": 5,
    "stampDutyRate": 0.0005,
    "slippageRate": 0.001
  },
  "riskConstraints": [],
  "benchmark": "000300.SH"
}
```

JSON 必须合法，且应包含可识别的 `universe.symbols`。Schema 校验失败会在编辑 Sheet 中显示字段错误；`entryCondition`、`exitCondition` 和 `riskConstraints` 等高级字段会被保留。

#### 排队和查看回测

在策略库的版本行点击“开始回测”，在 Dialog 中确认策略名称、版本和首个标的，并填写开始日期、结束日期和初始资金。多标的版本会明确提示本次只使用首个标的。提交后 Desktop 按“读取日线 → 创建任务 → 自动启动”的顺序执行；创建任务失败会保留配置 Dialog，自动启动失败则保留 queued 任务，可在“回测任务”中重试。

“回测任务”Tab 会自动轮询非终态任务，使用中文 Badge 和运行进度展示 `排队中`、`运行中`、`已完成`、`失败`、`已取消`。queued 任务可重试运行，非终态任务可取消，成功任务点击“查看结果”打开结果 Dialog。

结果 Dialog 按“摘要、权益数据、交易明细、复现信息”分 Tab 展示最终资产、累计收益、最大回撤、交易胜率、权益曲线、交易明细、引擎版本、数据时点和结果校验和。回测会记录成本、数据完整度和已知偏差；A 股执行模型会考虑 T+1、涨跌停、停牌、最小交易单位、手续费、印花税和滑点。

当前 Desktop 入口默认回测区间为 `2025-01-01` 至 `2025-01-31`、初始资金 `100000`，但可以在开始回测 Dialog 中修改；行情读取仍从选中版本 Schema 的 Universe 取首个标的日线数据。需要更多标的、参数扫描或 Worker 接入时，应使用对应 API/服务配置，并确认真实行情数据已接入。

### 6. 投资复盘

“投资复盘”提供两种确定性分析。输入的是 JSON，分析结果不会直接写入 Ledger，也不会生成订单。

#### 单笔交易复盘

在 `CompletedTrade JSON` 中输入一笔已平仓交易，至少提供标的、入场时间、出场时间和盈亏；如果要分析止损和计划偏差，再提供计划止损、实际出场、计划/实际价格、计划持仓天数、换手和仓位等字段。点击“分析单笔交易”后，系统并行计算：

- 计划与实际：比较计划价格、执行价格和持有期。
- 行为指标：从已提供的交易事实计算行为数据。
- 反事实：在明确的止损价格等假设下，比较假设结果和真实结果。

如果 AI Provider 可用，系统会额外创建一个只解释上述结构化结果的 AI 任务；Provider 不可用时，确定性复盘仍会保留。

#### 行为复盘

在 `CompletedTrade[] JSON` 中输入交易数组。系统根据交易的最早入场时间和最晚出场时间形成复盘窗口，生成行为指标和窗口汇总，再创建带证据边界的解释任务。事实不足时会显示 `insufficient data`；行为标签是对交易记录的研究分类，不是心理诊断。

### 7. 研究助手

“研究助手”采用研究任务工作台，而不是连续聊天：左侧按状态筛选任务，右侧阅读选中任务的结论、风险、证据和未知项。

1. 点击“新建研究”，在右侧 Sheet 中选择范围：全组合、账户、单个持仓或策略版本。
2. 账户、持仓和策略范围必须选择真实对象；持仓会先选择账户，再从该账户的实际持仓中选择标的，策略会选择具体版本。
3. 输入研究问题，或点击“主要风险”“近期变化”“反方证据”“情景压力”填入可编辑模板；问题会持久化在任务中，默认不会自动提交示例问题。
4. 查看“本次预计读取”后点击“开始研究”。任务进入列表并自动选中，排队或研究中的任务会由 Query 自动轮询，不需要反复点击刷新。
5. 已完成任务按“结论 → 主要风险 → 关键证据 → 未知项与限制”阅读。点击“查看来源链”可以按证据主张查看 citation、Tool 权限、Provider、来源 ID 和时间字段。
6. 失败任务会保留原问题、上下文和 checkpoint，可以使用原问题创建新的重试任务；失败记录和审计不会被覆盖。

研究助手只能使用被授权的只读或研究 Tool 获取组合、持仓、风险和日志事实；关键数字需要有 citation。AI 不可以写入 Ledger、Position 或 Order，也不会把 Provider/Tool 失败替换成零值。Provider、模型和 Prompt 版本由服务端路由，客户端不会提交这些审计事实；页面的能力预检会区分“可用、演示模式、未配置、异常”，并说明缺失影响。

研究任务采用“持久化队列 + 专用研究执行器”：创建后进入 `queued`，服务端 Worker 会领取任务、执行只读 Tool、记录 `AiToolCall` 审计并调用 Provider；只有通过 `ResearchResult V1` 和 citation/Tool 关联校验的结果才会进入“已完成”。Worker 租约过期或服务重启后会重新排队，超过重试上限则进入失败终态，不会永久停留在排队或运行中。

要启用 OpenAI-compatible Provider，在服务端配置 `AI_BASE_URL`、`AI_API_KEY` 和 `AI_MODEL`，可选 `AI_PROVIDER_ID`、`AI_TIMEOUT_MS`。`AI_FIXTURE_ENABLED=true` 只用于本地演示，页面会显示“演示模式”，不能当作实时外部事实。未配置 Provider 时仍可浏览历史任务，但新建 Sheet 会在能力预检阶段说明缺失配置并禁用提交。

### 8. 数据与自动化

“数据与自动化”是 Provider、任务调度和数据质量的集中入口。

#### Provider 配置

在“新增或更新 Provider”中填写名称、类型、能力和可选的凭证引用。名称是唯一标识：使用相同名称保存会更新配置，换名称会创建新配置。类型支持通知、行情、AI 和图像；能力通过下拉框多选，必须使用实际 Provider Plugin 声明的能力名。提交后凭证输入框会清空，页面只显示“已配置/未配置”，不会回显密钥。

填写时注意：Provider 表单管理通用 Registry 配置；行情链路仍使用 `DSA_BASE_URL` 与 `THESIS_LEDGER_DSA_TOKEN`。研究助手的 OpenAI-compatible 适配器使用上一节列出的 `AI_*` 服务端运行时配置，能力预检会以实际执行器状态为准。新增、更新、优先级、凭证引用和连通性测试的完整步骤见 [`docs/guides/2026-08-18-user-guide.md`](docs/guides/2026-08-18-user-guide.md) 的“Provider 填写教程”。

在 Provider 列表中可以：

- 查看 Provider 能力、优先级、健康状态和凭证配置状态。
- 修改优先级；离开输入框后会保存。
- 点击“连通性测试”排队执行测试。
- 点击“启用/停用”切换 Provider 是否参与路由。

接入 Provider Registry 的请求按能力和优先级路由，主源不可用时可以走 fallback；当前主行情链路仍通过 DSA Contract 取数，Provider 页面配置不会自动替换 DSA 环境配置。`stale` 表示数据陈旧，`partial` 表示结果不完整；在回测、收益和风控中都应保留这些标记。

#### 自动化与故障排查

自动化任务列表显示任务类型、启停状态和下一次运行时间。可以在页面启用或停用任务，并查看自动化运行历史中的状态、开始时间和错误摘要。服务端会按 cron、timezone、交易日条件、重试策略和 Redis 锁运行任务，避免同一窗口重复执行。

页面还会集中展示通知失败和开放的数据质量问题。遇到异常时，先刷新页面并按顺序检查：Provider 健康历史 → 数据质量问题 → 自动化运行历史 → 通知失败记录。详细排查步骤见 [`docs/operations/2026-08-18-operations.md`](docs/operations/2026-08-18-operations.md)、[`docs/domain/2026-08-18-provider-reliability.md`](docs/domain/2026-08-18-provider-reliability.md) 和 [`docs/domain/2026-08-18-automation.md`](docs/domain/2026-08-18-automation.md)。

### 9. 界面主题与数据状态

Desktop 侧边栏和内容区都提供主题按钮，按“系统 → 浅色 → 深色”循环切换，选择会保存在浏览器本地。系统主题会跟随操作系统的浅色/深色设置。

各页面统一使用以下状态提示：

- 加载中：正在请求 API，页面显示加载占位。
- 暂无数据：当前功能还没有账户、持仓、快照或任务数据。
- 读取失败：本次请求未成功，使用“重新加载”重试。
- 数据可能陈旧：部分 Provider 不可用或结果不完整，页面保留已有结果并显示陈旧标记。

出现陈旧或失败状态时，先查看数据时点和 Provider 健康历史，再决定是否继续使用结果。

### 10. 移动端

Mobile 当前是只读入口，不提供账户、持仓、规则或策略编辑。它包含：

- 只读投资组合：总市值、总成本、累计盈亏和持仓明细。
- 风险事件：严重级别、规则版本、消息和数据时间。
- 重新读取：重新请求 Portfolio 和 Risk 数据。
- 主题切换：系统、浅色、深色。

移动端默认连接本机 API：iOS/Web 使用 `http://127.0.0.1:3000/api/v1`，Android 模拟器使用 `http://10.0.2.2:3000/api/v1`；也可以通过 `EXPO_PUBLIC_API_BASE_URL` 指定地址。移动端同样会显示加载、空数据、读取失败和陈旧状态。

启动移动端开发环境：

```bash
pnpm --filter @thesis-ledger/mobile start
```

然后按 Expo 提示选择 Web、Android 或 iOS。真机运行时，应通过 `EXPO_PUBLIC_API_BASE_URL` 配置设备可以访问的 API 地址，而不是使用模拟器专用地址。

## 数据与安全边界

- Ledger 是交易、现金、费用、税和公司行动的事实源；Position 是可重建投影；Snapshot 是可重建的历史缓存。
- 截图导入在审核提交前不会修改持仓；导入提交后可以对本次导入执行回滚。
- 行情、指标、筹码、收益、风险和 AI 结论必须携带来源、数据时点或质量状态。
- AI 只能读取经过权限控制的 Tool，不能写 Ledger、Position 或 Order；AI 研究和回测结果仅供研究。
- 系统不连接券商下单，不提供自动交易、自动跟单或投资建议。
- `.env`、API Key、Webhook 和 Provider Credential 不得提交仓库。Webhook 和凭证应通过服务端环境变量或安全引用配置，日志和页面不应暴露密钥。

## 进阶能力与非 Desktop 入口

当前 Desktop 主导航覆盖上述日常功能；服务端还提供需要 API 或运维权限的能力：

- Ledger 事件查询、账户重建和过渡持仓迁移。
- 行情 Bar 的同步、回填、已落库查询，以及数据质量问题的确认和解决。
- JournalEntry、TradePlan 的保存、查询和导出。
- AI Run 的 checkpoint、Tool 调用记录、用量汇总和 Decision Log。
- 盘前事件、风险预览、开盘扫描、收盘同步、快照、风险扫描、日报和周报等自动化工作流。
- 账户数据导出、数据库备份/恢复、完整性检查和发布门禁。

这些能力不代表开放了交易执行；相关运维流程见 [`docs/operations/2026-08-18-release-and-recovery.md`](docs/operations/2026-08-18-release-and-recovery.md)，领域边界见 [`docs/specs/2026-08-18-thesis-ledger-product-v1.md`](docs/specs/2026-08-18-thesis-ledger-product-v1.md) 和 [`docs/domain/2026-08-18-domain-model.md`](docs/domain/2026-08-18-domain-model.md)。

## 当前限制

- 免费数据源可能延迟、缺失或限流；界面会显示 stale/partial，而不会伪装为最新完整数据。
- 正式 DSA Fork 已作为同级 `daily-stock-analysis` 仓库接入；Contract V1 已提供 `fund-nav` capability 和 `GET /market/fund-nav?symbol=000001.OF`，生产组合通过固定版本矩阵消费该能力。
- 真实飞书 Webhook、专业 Provider 和跨平台签名仍需要仓库所有者提供外部资源。
- 所有收益、风险、回测和 AI 输出仅供研究，不构成投资建议。

更详细的运行和模块说明见 [`docs/operations/2026-08-18-operations.md`](docs/operations/2026-08-18-operations.md) 与 [`docs/guides/2026-08-18-user-guide.md`](docs/guides/2026-08-18-user-guide.md)。
