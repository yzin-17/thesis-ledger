## 确认的诊断缺口

### 长度异常没有携带响应文本

`ai-sdk-generation.adapter.ts:229` 先执行 `assertFinishReason`，之后才访问并校验 `result.output`。`length` 会在前一步抛出 `AiSdkGenerationError`；`ai-sdk-generation-facts.ts:151` 的完成元数据只带结束原因、总用量、模型等信息，不带本次 `result.text`、`result.reasoning` 或原始响应体。

`trace/ai-trace-error.ts:22` 只从 `NoObjectGeneratedError` 提取文本，长度异常不是该类型；因此 `live-call-diagnostics.ts` 最终保存的 `outputText`、字符数、摘要和独立合同校验均缺失。已有离线用例 `ai-sdk-generation-adapter.integration.test.ts:473` 还明确覆盖“JSON 看似有效但结束原因为 length 仍拒绝”。因此 `jsonStatus=missing` 表示诊断没有得到文本，不能据此断言上游完全没有生成 JSON。保持对截断结果的拒绝是正确的，缺口在于证据保存。

### Arena 没有启用已有细粒度诊断

`ai-generation-diagnostics.ts:19` 仅为 `research/research-generation-v2` 创建 HTTP 与思考流诊断，Arena 合同直接返回 `undefined`。四条失败记录确实都没有 `runtime` 或 `httpRequest`。独立的请求 trace 依赖显式选中的研究任务作用域；Arena 执行链没有建立该作用域，不能假设已有 HTTP 原文归档可读。

SDK 的兼容适配器能够读取 `reasoning_content` 和 `reasoning`，也能读取 `completion_tokens_details.reasoning_tokens`；但 `usageFacts` 只保存输入与输出总量，没有保留推理／正文分项。无法用旧记录判断近十万 token 的构成。

### 模板与结束标记的核对基准
