目标 DSA 的当前路由修订仍为 202；CN 股票／ETF 的 1、5、15、30、60 分钟未复权路由均显式启用，主来源富途、原后备来源保持。只读取控制投影与原文件，没有对上游重新采集或切换来源。

实际盘点目标 `/app/data/arena-history` 的 190 份原档案：两只已有样本 ETF 在 11 月 2～16 日的 11 个交易日、22 个证券日各有 240 根完整且不重复的正常交易分钟，共 5,280 根。原始每日报价额外行不冒充常规分钟，校验按来源声明的时间约定及已核验交易会话进行过滤。11 月 17、18、19、20、23 日没有这两证券的新保存分钟；这是现有档案边界，不是富途返回不可用，也不要求先补齐全市场全部历史分钟。

目标已核验交易日历覆盖 11 月 2～24 日，来源可见时刻为 2026-03-10。通过目标编译的 `MarketArenaReplayReader.next / observe`、正式 DSA 日历 HTTP 入口核对新草案：回放起点为北京时间 11 月 2 日 00:00，首个研究观察为 09:31，状态 open。实际仅有两次日历 GET；行情、历史执行、数据库和模型端口均禁止调用，没有为进入初始研究预取全部证券数据。

股票已有日交易状态路由保持；ETF 历史执行归档的实际生效目标目前为 `eligible=false / reason=admission_expired`，材料只覆盖原两证券 11 月 2～16 日。该缺口由 R4H2 保留，不能用当前正常快照回填历史或伪造准入。后续处理只针对实际选中证券／日期及所需状态，不默认补齐采样政策不需要的公共收费、每日价格边界或全部事件证明。

## 新入口的实际边界

旧 `run-arena-replay-new.mjs` 要求队列无待办并会恢复全局队列，不适用于本次保留旧待办的要求。实际确认共享队列保持原维护暂停，有一条旧比赛 pending；本次没有暂停、领取或修改它。

新增入口及所有权均位于应用仓：

- `scripts/local-runtime/run-arena-scoped-replay.mjs`：预览／显式执行、授权包核对、正式 API 创建一次全新比赛、持锁执行与回执保存。
- `scripts/local-runtime/arena-scoped-replay.mjs`：按新 ID 推进、首次领取、协议／预算校验、失败与运行边界停止，仅暂停本次新比赛。
- `scripts/local-runtime/arena-scoped-replay-runtime.mjs`：装配现有正式回放、领取、研究、预算、提交及交易日历服务；不启动 Nest 或全局生命周期。
- `scripts/deployment/maintenance.json`：登记上述正式维护命令及 idle 约束。

入口不调用全局 `LiveRuntime.start / reconcile / onModuleInit`，不创建队列消费者，不调用全局周期恢复或队列 resume。周期读取显式限定新比赛 ID，实际执行前再核对周期归属；只接受 attempt 0 且未出站的首次待办。领取、调用扣减和提交沿现有正式事务，不直接改写业务行完成验证。错误比赛、协议、预算或已发出的周期均拒绝。

预算耗尽、来源失败、截断、未知结果、模型失败、运行时限或停止信号都结束本次驱动；不重试周期。回放追平进入 live 后也暂停本次新比赛，保留同一账户；进入阶段不认证实际实时成交，R4 的实时业务仍需独立结果。


未来经单独运行授权后，才生成私有 `launch-authorized.json` 并使用以下正式入口；本批未执行：

`executionAuthorized` 字段本身不授予 Agent 权限。实际执行前仍须匹配用户授权的新调用预算、模型准入版本及原队列暂停归属；不会修改旧比赛来满足入口条件。

## 验证与失败事实

使用 Node.js 24.22.2：

```sh
node --test scripts/local-runtime/arena-scoped-replay.test.mjs
node scripts/check-boundaries.mjs
```

19 项受控检查通过，覆盖新旧待办并存且旧对象不变、错误 ID／协议／预算拒绝、其他周期／已领取／已出站拒绝、未知结果停止、重复周期不重试、预算／来源屏障／失败／时限／停止信号、无进展停止、暂停归属变化、JSONB 键序及默认预览／显式授权。

四个新增 JavaScript 文件的 `node --check` 通过，主仓导入边界通过；infra checkout 以 Node.js 24.22.2 执行 `pnpm check`，运行时、部署职责、命令登记及兼容合同全部通过。未改变应用生产源码或依赖，复用已通过的构建与业务证据，不重复构建或全套测试。

另将运行装配函数注入目标容器做只读装配检查：数据库连接强制默认只读，所有网络 fetch、真实 SDK 生成及全局启动函数均设为拒绝端口；使用不存在的受控比赛标识，只装配与核对暂停／模型配置，不读取或执行真实比赛。最终 `assembly=actual_compiled_services / status=passed`，禁止端口尝试为 0、模型调用 0、全局调度启动 0，队列未恢复。

保留的失败事实：首次目录只读查询误用不存在的 name 列、首次日历装配参数顺序错误，均只修正本地查询／参数，没有写表；运行装配首次将三段参数传入实际只接受两段的 `redisKey`，因此正确拒绝错误暂停键，改用正式队列前缀加 `:live:meta` 后通过。没有绕过真实暂停门禁或重试模型。

本次私有完整回执在 `.recovery-artifacts/arena-new-replay-preparation-20261123/`，包括前后保护快照、旧待办身份、资料／路由盘点、首观察、候选、受控装配成功和原失败回执。结束核对 11 张受保护业务表、所有计数及 115 条资格状态记录与开始时相同；共享队列仍为原归属 `paused=true / active=0 / waiting=1`。旧比赛及待办原样保留。
