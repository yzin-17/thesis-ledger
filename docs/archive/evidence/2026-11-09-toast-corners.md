# Toast 圆角裁切修复

日期：2026-11-09。

共享 ToastViewport 同时设置较大圆角和 overflow 裁切，模型 Toast 自身使用较小圆角，四角边框因外层更大圆角被切掉。移除共享视口的圆角，保留卡片自己的圆角、原有滚动行为及通知几何位置；不新增选择器、样式分支或依赖。

排查共享 Toaster 与 ArenaEmptyToast 两处渲染器及其消费者，统一由 Toast 卡片负责外观圆角，视口只负责布局和滚动。

- 四宽（1440、1024、768、390）真实 Edge 验证：模型 Toast 自身有圆角、视口无圆角裁切、纵向滚动仍为 auto；顶部居中、约 3 秒消失、手动关闭、去重、缓存恢复、后台刷新、周期切换、全屏、滚动与迟到结果检查通过。已查看最终窄屏截图，圆角边框完整。
- 共享 Toaster 另在四宽页面中实际挂载验证，卡片圆角保留、视口裁切圆角为零，纵向滚动与手动关闭保持可用；截图为同目录 `global-{1440,1024,768,390}.png`。
- Desktop 类型检查与构建、修改组件 ESLint、差异空白检查通过；未为纯样式调整重复运行此前已通过的全量业务测试。
- 原始结果 `/tmp/arena-empty-toast-qa/results.json`，日志 `/tmp/toast-corners-browser.log`，截图同目录 `toast-{1440,1024,768,390}.png`。

未写入真实业务数据，未执行 Docker 同步、提交或发布。

## 提示卡片投影

后续按用户反馈，为模型空结果 Toast 增加 `shadow-none`，仅保留细边框；共享 Toast 的默认外观保持原契约。四宽实际浏览器验证所有计算投影分量的 alpha 为零，圆角、定位、自动关闭和全屏交互仍通过。构建、ESLint 和差异空白检查通过。计算样式包含 Tailwind 合成的多组透明零投影，因此验证可见性而非要求 box-shadow 字符串恒为 none。日志为 `/tmp/arena-toast-no-shadow-browser.log`。

截图中延伸到提示两侧的水平线对应行情弹窗标题区的 `border-b`，与卡片投影分别处理。

## 共用消息样式

继续按用户反馈，将共享 Toast 根节点的默认 `shadow-sm` 统一改为 `shadow-none`；模型提示删除重复的局部覆盖，继承共用样式。圆角、边框、焦点指示和通知行为保留。

新增 `check-toast-appearance.cjs` 和独立浏览器样本，验证信息、成功、警告、错误、加载五类共用消息。在 1440、1024、768、390 四宽下，投影各分量透明，圆角与细边框存在，视口不裁切圆角，手动关闭可用。结果 `/tmp/toast-appearance-qa/results.json`，截图同目录 `messages-{1440,1024,768,390}.png`。构建、类型检查、ESLint 和差异空白检查通过。

最初动态注入共用通知时遇到 Vite 开发期模块重载，改为独立静态导入的样本页面后完成上述验证，未修改产品逻辑来配合测试。
