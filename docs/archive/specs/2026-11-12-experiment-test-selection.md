# 实验测试候选选择

本规格记录已交付的历史交互；当前行为由[AI 实验自动完成](../../specs/2026-11-12-automatic-experiment-completion.md)接续，已开始测试的历史锁定事实继续保留。

## 目标与范围

用户选择一个或多个候选进入封存测试即可提交；预选采纳是可选的提前选择。Desktop 详情、旧实验结果入口与 Mobile 使用同一提交合同。正式采纳继续独立确认。

## 行为与验收

- AC1：测试前可以选择、取消、切换预选采纳；取消预选保留测试选择，移除某个测试候选只清除该候选的预选。预选一个候选时自动将其加入测试批次，最多三个；满额时不能形成批次外预选。
- AC2：选择至少一个合格测试候选即可提交，`selectedCandidateId` 可省略或为 `null`；服务端统一保存为 `null`。提供预选 ID 时仍必须属于批次。既有必填 ID 请求继续兼容。
- AC3：开始访问测试数据后，批次及预选状态（包括未预选）一并冻结；技术重试不能补选、换选或取消预选，完成结果统一揭示，原有故障恢复和读取限制保持生效。
- AC4：未预选时允许完成封存测试；后续正式采纳按既有已查看测试结果的确认与记录处理，不自动选中或采纳候选，不改写历史记录。
- AC5：按钮具有选中状态、取消表达、禁用及键盘焦点反馈。Desktop 四个代表宽度完成实际浏览器验证，受控提交覆盖有／无预选、取消、批次上限、锁定重试和失败保留。Mobile 同步动作合同与状态，原生配置不变。

## 所有权与边界

Schemas 与 API client 维护提交合同；StrategyOptimization 维护锁定与揭示状态；客户端维护测试前临时选择。数据库现有可空字段沿用，无结构迁移。使用隔离样本和受控浏览器请求验证，不访问用户真实封存测试，不调用 AI、不正式采纳策略。局部检查通过后按正式最小入口同步运行态。
