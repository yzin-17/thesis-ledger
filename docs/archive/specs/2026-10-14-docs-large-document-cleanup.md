## 目标与范围

按用户第二轮授权，减少当前 Spec/Task 的历史实施叙述与一次性运行证据负担，清理经过全仓引用及字节核对的重复载体。沿用现有 archive、Review 和 evidence 路径，不新增文档分类或长期审计门禁。

当前合同、任务编号、验收标准、启动依赖与授权边界继续由原 Spec/Task 维护；未通过验收不迁出当前任务。历史日期、失败与修正、原始输入和可追溯证据保留。第一轮已有改动全部保留，不修改应用、配置、数据源或部署，不提交、不推送。

第三轮按后续授权清理无实际引用的跳转文件，归档历史 Review 与被现行合同承接的旧 Spec。先扫描主仓全部跟踪及未忽略的未跟踪文本、Markdown 链接、原始证据和两邻仓引用，再同步导航与正文路径。只含当时执行路径的历史叙述原样保留，不为这些文字新增旧路径维护义务；原始证据、测试输入和邻仓仍需的实际引用保留兼容入口。验收只检查文档、原文与证据完整性，不重新执行业务门禁。

第四轮收敛同一当前责任的 Task：旧原生父任务/汇总与配色、Portfolio 的点位/摘要/收益指标、现金定期入账分别交给现有任务逐条维护。原文按“被承接、验收仍开放”归档，合同和真实验收继续有效；原待验收条件不能因合并消失。承接按原 Spec 和编号分节，不新增当前 Task 或把无关功能合成巨型文件。源代码、原始证据、暂存区与 HEAD 保持原状，不提交、不推送。

## 验收标准

- AC1：当前任务能直接找到真正未完成工作、必要执行上下文、完成条件与证据，不需先读取完整历史。
- AC2：精简不删除稳定合同、AC、未决要求或有效用户决定；旧章节引用可定位到保留内容或其证据。
- AC3：原始载荷可按原 SHA-256、长度与字节完整还原；去重仅删除确认相同且已保留规范副本的载体。
- AC4：全仓引用与 Markdown 锚点无新增失效，第一轮和无关文件保留；本轮只验证文档和证据完整性，不要求新增真实来源、数据库、Docker 或浏览器验收。

## 顺序

先确定内容归属与重复引用，再精简当前正文、保留必要历史并更新导航，最后检查任务/AC/原始字节及链接。移动证据不代表验收已通过，历史失败也不因后续成功而被删除。
