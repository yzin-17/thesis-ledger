# 标的确认状态与操作反馈

状态：历史合同。独立目录 UI 已由[业务流程内选择证券与港美股票支持](../../specs/2026-11-10-instrument-selection-workflow.md)替代；本文保留当时范围与验收定义，不作为当前导航和市场资格的依据。

## 目标与范围

目录的“确认标的”建立目录证券与资产的已确认身份关联。本次让 Server 搜索读取既有持久化关联，并由 Desktop、Mobile 展示真实状态，解决确认成功仍可反复点击及不支持关联被显示为已确认的问题。保持确认接口、支持市场、持仓数量、交易及数据库结构不变。

## 合同与不变量

- `confirmable` 继续表示市场与类型是否支持关联，已确认标的仍保持此能力值，不能影响持仓选择器继续选用。
- 搜索增加 `confirmed` 布尔投影；只有相同完整证券代码和目录 ID 的关联处于 active、存在 confirmedAt，且关联资产身份已确认时才为 true。最终可见结果一次批量查询关联，禁止逐行查询；查询失败不能解释成未确认。
- 字段为增量兼容字段；客户端只把明确的 true 解释为已确认。兼容旧响应缺字段不生成已确认事实，目标运行态验收必须确认新 Server 实际返回字段。
- 中文状态投影由公共客户端层承载：支持且未确认为“确认标的”，已确认为“已确认”，不支持为“不支持关联”；状态和操作资格分开。不支持原因使用稳定原因码映射，不直接展示内部枚举。
- 确认成功后取消旧搜索请求、更新已有搜索缓存，再失效重读；刷新失败保留成功回执带来的确认状态并显示刷新错误。写入失败不标记已确认，允许重试。重新搜索、切换搜索词及重开页面仍以服务端状态为准。
- 已确认的证券仍可从持仓选择器选择；本次不改变这些入口原有确认调用与保存流程。

## 验收标准

- AC1：Server 搜索准确区分未确认、已确认和不支持；同名跨市场、关联失效、未人工确认、目录 ID 不一致及资产身份未确认不能产生错误的已确认。相同集合一次批量查关联；失败使搜索失败，不回退未确认。
- AC2：Desktop 确认成功立即更新，重搜、重开仍已确认且禁用；请求中防止重复点击；失败可重试，不支持不能误标已确认；缓存刷新失败保留成功状态。
- AC3：Mobile 目录使用相同中文投影，确认后更新缓存与重新读取；持仓选择能力不受 confirmed 影响。公共契约、解析及两端类型检查通过。
- AC4：真实浏览器覆盖 1440、1024、768、390，检查三个状态、确认成功与失败、重搜、重开、聚焦、窄屏边界。写入与失败验证使用受控请求或隔离样本，真实业务只读。
- AC5：按定向、包级、相关门禁和目标运行态顺序验证；目标 Server 返回新字段并与既有持久化事实一致。纯代码快更由 infra 正式入口执行，不作为镜像更新证据。

## 所有权

持久化投影归 Server Market；响应字段归 schemas；跨客户端中文投影归 api-client；缓存及交互由各客户端持有。当时未新增数据库迁移、外部调用或真实持仓写入。实施见[归档任务](../tasks/2026-11-10-instrument-confirmation-state.md)与[验收记录](../evidence/2026-11-10-instrument-confirmation-state.md)。
