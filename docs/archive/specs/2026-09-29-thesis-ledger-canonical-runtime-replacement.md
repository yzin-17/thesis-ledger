## 1. 目标与范围

最终实施与验收见[收口证据](../../tasks/evidence/2026-10-02-canonical-final-completion.md)；当前模块与 API 见[当前运行链](../../architecture/canonical-runtime.md)。

ThesisLedger 只维护一条现行的 Market、Backtest、Ledger 业务链路。Schema、Domain、Server API、Worker、客户端、DSA 中 ThesisLedger 专属数据/控制接口和部署输入须指向同一套合同与运行实现。已有 V3 能力直接成为现行实现，不再以 V2 创建、V3 旁路执行、旧快照回读和旧字段补齐来维持两套语义。模块按领域职责收敛到清楚的所有权；版本后缀不再作为并行实现的理由。

用户明确允许旧 ThesisLedger V1/V2 数据无法再读取。新链路不迁移旧 Run、Snapshot、缓存、Market 证据和 Ledger 旧格式，不提供隐式升级、默认值补齐、协议降级、同名别名或读失败切旧源。旧数据遇到读取请求时必须明确拒绝，不能当作当前事实或自动重新计算。执行前不删除原始数据；开发数据库结构重建、正式环境保留数据升级与备份仍遵守仓库既有数据库规则，属于独立部署门禁。

本范围包括主仓拥有的 Market/Backtest/Ledger 领域合同、数据库读写、Server/Worker、API Client/Desktop 以及 DSA 中 `thesis-ledger` 专属端点、策略、目录、准入与传输。DSA 的非 ThesisLedger `api/v1` 服务、第三方 Provider 自身协议、历史 migration 文件及外部来源的原生版本号不属于本次删除对象。当前不可变证据继续携带可验证的格式标识和摘要，以保证冻结与重放完整性；现行读取器只支持当前格式，不因标识存在而保留旧格式解析。

## 2. 当前已核实的替换边界

- 初始基线中 Server 以 `backtest-v2-run.ts` 创建 `mode='V2'` Run；本轮已将现行创建写入改为 `mode='V3'` 并同步分派和 CAS，但 `backtest.service.ts` 仍保留旧 `jobs` 路径，V3 Runner 仍调用 `backtest-v2-execution-exchange.ts`。执行内核须继续收敛到单一归属，不能按文件名删除。
- Market 公开入口当前为 `api/v2/market` 与 `api/v2/market-data`；`packages/api-client`、Desktop 和 Server→DSA 请求存在对应路径。更新生产者与所有消费者后才移除旧路径。
- `backtest-snapshot.ts` 同时构造/读取旧 manifest，现行 V3 Store 与严格证据读回另有实现；旧 Snapshot 的只读兼容、修订补齐和回放分支是明确的移除候选。
- `packages/schemas` 的 `backtest-v2.ts` 同时定义 V2 及 V3 合同，`packages/domain` 与 Ledger V2 仍为执行依赖；需按实际导出和调用者拆分职责、统一名称和现行类型，不能机械改文件名。
- DSA `api/v1` 是其通用路由命名空间。只替换 ThesisLedger 专属路径与对应消费，非 ThesisLedger API 不随本任务删除。

上述是实施入口，不是完整引用清单。Task 的库存叶必须从源码、Schema 导出、HTTP 路由、Prisma 模型、Worker、缓存键、部署打包和测试逐项生成并核对最终删除范围。

## 3. 合同与行为要求

1. 每项业务能力只有一个可创建、可执行、可查询的现行合同。运行任务状态以 PostgreSQL 为事实源；Market 路由/准入仍按精确来源、能力与修订生效。移除旧路径不得放宽 G0、PIT、覆盖、事件可见性、来源独立性和冻结校验。
2. API 请求和响应不依赖旧版可选字段、别名与隐式默认。客户端使用现行路径与类型；Server 到 DSA 的 ThesisLedger 专属请求使用单一端点/合同。未更新的旧路径在目标态不能继续触发业务运行。
3. 新建 Run 只能落入现行执行状态机、Snapshot 格式和结果模型。Worker 领取、重试、取消、晚到结果及最终 CAS 保留既有原子条件与上限。旧 Run、Snapshot 或证据格式不得被当成现行输入；可返回稳定的不支持版本错误，不启动任务或修改旧记录。
4. Ledger 当前经济事实、数量、费用、税、T+1、拆分和现金分红不变量保持。替换 Ledger V2 合同时需逐项验证创建、投影、撤销/修订与关联 Backtest 行为；不从“无需兼容旧数据”推导可以删除现行业务能力。
   - 2026-10-01 现行入口核对：账户 Ledger 的事件合同、命令及持久化模型没有直接绑定 Run 的既有入口；Backtest 经济执行由独立的 `SimulationLedger` 承载。“关联 Run”验收覆盖场内及 NAV 执行的经济结果与 Run、策略版本、冻结快照和校验和的绑定，验证跨 Run 串用与身份篡改拒绝，并保持账户账本和回测经济状态隔离。按生产入口验证现有能力，不能将回测成交自动写入账户账本。
5. 代码按职责收敛：Provider 专属适配器留在 DSA，领域原语与稳定合同放在拥有该概念的主仓模块；V3 文件成为现行模块时可改为无版本语义名称，禁止把代码机械拆成无所有权的 `common/shared/utils`。跨 feature 依赖变化同步更新 `scripts/check-boundaries.mjs`。
6. 旧缓存键、旧文件/数据库数据可失效且不回填。新写入使用单一命名空间与证据身份；目标运行前明确检测当前结构、旧数据残留和回滚输入。删除数据或重建 `public` schema 仅通过项目显式入口和精确目标确认；正式发布另需保留数据升级方案。
7. Risk、Automation 等分钟线消费者须使用具备真实来源与时序证据的现行精确路由；在该能力未实现时明确返回不可用，不得用旧缓存、测试夹具或日线推导分钟线。已有 DSA 旧数据接口也只支持日线，因此旧接口的存在不能作为分钟线已可用的证据。
8. Control/Provider/Catalog 按生产调用逐端点替换。Provider 凭证继续只写、不回显，并绑定配置修订和来源；Policy Apply 与 Effective 继续保持原子、单调修订和精确目标准入；Catalog Snapshot/Delta/ACK/Job 继续核验 generation、checksum、cursor 与失败恢复。旧 Control 信封、路径或 SQLite 状态不得被悄悄解释为当前策略。各端点必须先更新 Server 消费，再删除旧准入；仅把 URL 改为 V3 不构成合同收敛。Server Policy 的同 revision 重试必须绑定本次 Apply 的 requestId 和独立 attemptId，重复 requestId 也不得混淆不同执行；仅匹配当前 revision 与当前尝试的结果可以提交当前行及历史投影，晚到成功或失败均不得覆盖后续尝试。该尝试标记属于现行 `storageVersion: 3` 路由容器的内部审计元数据，不改变 Desired 的 routes；读取非空 Effective 投影必须通过当前 schema 校验，禁止补版本或把同 revision 的旧格式当作当前事实。
9. 场外 NAV Fund 仍是现行业务能力。其净值事实、申请截止、确认/结算日、申赎费用、份额及现金账本应接入同一当前 Run 状态机、冻结与结果校验。NAV 使用独立的净值来源和冻结产物合同，不将净值捏造成 OHLC 日线，也不将 `fund` 悄悄映射为 ETF `DAILY_BAR` 路由。数据覆盖、实际可见时间或费用模型缺失时在写入前失败关闭；不能为了保留 NAV 而恢复旧 Run/Snapshot 读取兼容。

### Schema/Domain 当前归属

当前 Policy 的准入拒绝原因保留 DSA 已产出的细化状态：`admission_invalid` 表示准入失效，`admission_not_yet_valid` 表示尚未生效，`admission_expired` 表示已过期。共享 Schema、Server 与客户端按同一当前原因集合消费，并显示对应中文标签；这些状态的目标必须为 `eligible: false`，不得因响应解析成功而扩大来源准入。Catalog 的就绪状态仍按其独立现行合同表达。

Catalog 保留现行生产游标 `generation:<正整数>`，游标必须与同份目录 generation 一致，`0`、`generation:0` 及未知游标不能回填为当前目录。Job/ACK 使用当前 Control 信封；触发绑定请求身份、轮询绑定 Job ID，成功 Job 的 generation/checksum/cursor 必须在本地投影前一致。ACK 的当前身份检查与写入共享 SQLite 写事务，本地同期续期也须绑定 cursor。无有效 CatalogSyncState 时不得由历史 Instrument 记录推导当前目录。派生序列读取只接受当前精确时钟算法 `raw-times-factor-over-fixed-anchor-binary64-v2`，旧毫秒时钟算法明确拒绝，不转换或重算为当前格式。

C03 收敛后，Schemas 的 `backtest-values` 拥有资产、币种与金额等回测值合同，`backtest-strategy` 拥有表达式与策略 AST，`backtest-run` 拥有当前配置、创建、响应和跨合同校验，`backtest-result` 拥有成交、交易及当前结果解析。`backtest-contract` 作为同领域公开入口，不承载旧版本解析或同名兼容别名。Domain 的策略词汇与模拟结果词汇分别由 `backtest-strategy`、`backtest-simulation-contract` 拥有，当前执行继续使用 Exchange/NAV 和 SimulationLedger。

`monetary-values` 拥有 JSON 金额原语；当前 Ledger 类型、信封与命令由各包 `ledger-contract` 拥有，Trade、Baseline 和 Import 合同单向消费。公共类型使用 `BacktestStrategy`、`LedgerEvent` 等领域名称；策略 AST 的 `schemaVersion=2`、Ledger 信封 `version=3`、独立经济 `payloadVersion` 以及规则/冻结证据格式标识保持其实际含义。删除旧策略/RunConfig decoder、旧 number 回测及账本算法，不删除这些现行能力。

Strategy 与 StrategyVersion 创建必须显式写入合同版本，数据库不再默认生成旧版本 1；升级仅移除默认值，既有版本及 JSON 原样保留。当前基准收益必须提供冻结费用事实，缺失时返回不可用，不隐式套用旧零费用假设。现行精确 Market、NAV 和 PIT 合同及其证据标识继续保留，冻结读取与来源资格由 C04/E02/E04 的独立门禁验收。

### NAV 净值依赖范围

E01-N1.1 建立纯依赖计划，输入为现行策略、NAV RunConfig 和显式冻结日期证据（严格模式为独立日历，研究模式为下节构造日期），输出为逻辑数据用途、精确净值路由、预热/执行净值日期集合及申赎日历范围。首个接线范围为 CN/CNY 日频、同一基金 `nav` 信号及同基金基准；其他标的、字段、周期、事件信号和非零旧策略费用明确拒绝，完整业务范围继续由后续叶接入。

预热条数复用策略 AST 的入场/退出最大 lookback，要求开始日前已有该数量的估值记录。严格模式按独立日历倒推实际起点；研究模式按已冻结的来源净值日期倒推，不声明独立完整覆盖。执行净值与信号共用这一物理序列，基准只使用运行区间；未引用的来源不进入依赖。净值是否真实存在、发布时间与可见性由准备/冻结阶段逐日核验，计划成功不代表来源就绪。

日期证据同时声明基金估值日期与申赎处理交易日期，绑定基金、覆盖区间、版本、摘要、证据引用和可见时刻。严格模式不得从净值响应反推独立日历；研究模式消费下节明确的来源日期构造合同。申赎处理日历向结束日后延伸 `1 + 最大确认延迟 + max(最大确认后可卖延迟, 最大确认后资金可用延迟)` 个处理日，为截止时间后的申请提供保守预算。收益与权益仍止于用户选择的结束日；结束日后才能定价或确认的申请保留待处理状态，不强行补净值或清仓。Runner 对这一期末规则的实际消费由 N3 验收。

N1.1 只计算与核验范围，不选择真实 Provider、不写 Snapshot、不开放 NAV 创建或执行；N1.2/N2 将计划范围与实际冻结产物绑定，N1.3/N3 接入申赎事实与经济内核。

N1.2 的现行 NAV manifest 必须同时引用净值 Parquet 与冻结上下文 Parquet；上下文保存策略、配置、日期证据及其原文、完整净值响应原文和逐条可见性原始记录。读取按 runId 限定产物路径，校验文件字节摘要、manifest 摘要、配置/策略摘要、费用模型摘要、来源响应摘要、逐条记录摘要及日期证据原文。日历原文使用已归一化的日期证据记录，必须与所声明的估值/交易日期和覆盖一致；严格来源发布时间与研究假设记录分开核验，Provider 专属转换及真实资格仍由 N2/N4 验收。

冻结与读取均重算 N1.1 计划，要求 Manifest 预热起点、完整估值日、费用模型与净值行完全一致。发布时间记录至少绑定同一记录 ID、基金、估值日、正净值及发布时间；保留额外原生字段，拒绝记录缺失、重复、身份/数值/发布时间不符与微秒级未来可见。该校验证明冻结记录相互一致，不能单独授予历史修订完整性或严格 PIT。

NAV 资产适配器复用现有 LocalArtifactStore 与 canonical hash，不引入旧 Snapshot 解析。最终 manifest 通过同目录临时文件及独占链接发布；同 runId 相同输入可幂等读回，不同输入拒绝，发布前失败只清理本次创建的产物。真实创建、来源准入、Worker、重试恢复和客户端继续属于 N2–N4。

N1.3 在冻结读回边界提供纯 Domain 输入适配器，复核 manifest 与上下文后映射 CN/CNY 基金身份、十进制现金、净值事实、来源身份及完整执行模型。策略仍使用净值序列，适配器不生成 OHLC 或申请事件。可见净值查询按微秒核验 occurredAt/availableAt 和评估时刻，供 N3 生成事件前调用；预热事实保留但不得作为预热期间交易授权。

申赎日历只消费冻结日期证据显式声明的处理日期；范围外查询失败关闭，消费阶段不另用静态交易所日历补齐。该日期合同未提供交易时段，适配器的时段查询明确拒绝，N3 依据申请截止和确认/结算日期合同编排事件时刻。费用模型完整传入既有 CnNavSimulation，由内核按申请所属分段计算费用、确认份额及资金，不使用旧策略费率或固定默认截止时间替代。

N2 的真实准备不能直接复用基金显示接口的 `fetchedAt` 作为历史发布时间，也不能把按净值年龄计算的 `freshness=stale` 直接解释为历史事实无效。须核验所选模式的可见性语义、精确来源修订及基金日期覆盖。`serviceCapabilities.fundNav=true` 只说明接口存在；实际创建还要求精确路由准入、生效策略及符合冻结合同的证据。现有接口的字段和当前准入状态在 N2.1 证据中记录；所选模式的时间或日期合同缺失时，相关准备保持不可用。

### NAV 研究可见性模式

2026-09-30 用户确认一般净值按 T+1 可见，并要求核查 QDII 具体规则。新增显式研究假设模式，与来源发布时间严格模式区分；N1 已实施的严格模式及其受控验收保留，研究模式由 N2.3 扩展合同后重新验证受影响的冻结与 Domain 消费。

研究模式使用冻结的历史净值快照，默认普通基金延迟一个工作日；QDII 按具体基金及规则适用区间覆盖，未知规则不按类型自动推测。已核验样本：110011 的 2026-07 招募说明书规定通常 T+1 披露，118001 的 2026-07 招募说明书规定开放日后两个工作日内披露；两者的工作日均指沪深交易日，不等于所有基金申赎开放日。

可见时间假设采用披露日结束后的下一自然日 `00:00:00`（Asia/Shanghai）作为边界；T+n 从估值日之后按所绑定的披露工作日日历计数，不包含 T 日，周末和节假日不按自然日累加。这个边界是明确研究假设，不是实际发布时间。延迟披露或历史净值修订未完整取证时，结果必须标明限制，不能宣称严格 PIT。

RunConfig 与 Manifest 必须显式绑定模式、工作日延迟、边界时间、基金身份、规则版本/适用区间及其文档引用和摘要、独立披露工作日日历。每条净值的可见性证据使用区别于 `source-publication-record` 的研究假设类型，绑定估值日、原始净值记录、规则和计算结果；缺少真实时间不得伪造 sourcePublishedAt。实际响应原文、逐条记录、捕获时刻和来源修订仍须冻结，捕获时刻表示本次快照取得时间。

严格日期合同分别覆盖独立估值日、申赎处理日和披露工作日。研究日期合同按下一段授权的规则构造三个集合；日期缺失不补造，确认/结算与披露延迟各自的尾部预算不足仍失败关闭。

2026-10-01，用户确认采用现有来源能力的共同研究口径：`valuationDates` 使用完整来源快照实际返回的净值日期，保留非沪深交易日估值；`tradingDates` 使用该集合与已核验 XSHG 交易日的交集；`disclosureWorkDates` 使用同一 XSHG 日历作为披露工作日假设。缺净值日期视为该日不可交易，不声明来源之外的独立应有估值日。历史暂停、限购、投资者及渠道差异不纳入本版模拟，结果必须说明这一限制；有净值不证明真实开放申赎。研究构造只允许 `research-assumption`，严格模式拒绝该类日期证据。

研究日期原文继续使用现行三个集合及范围字段；版本使用 `nav-research-calendar-v1:<假设证据摘要>`，引用使用 `research-config://nav-calendar/<假设证据摘要>`。假设证据绑定用户决策原文摘要、来源整批原文摘要及修订、研究规则摘要、XSHG 发布制品摘要/可用时刻、三类日期构造口径与未模拟的限制，并由后续精确接口随来源响应冻结。`coverage.complete=true` 仅表示声明范围内按上述构造规则取得完整集合，不表示来源历史、独立日历或真实申赎状态完整。日期证据可用时刻为本次真实生产时刻，所有来源/规则/配置/生产时刻不得晚于冻结时点。预热、执行净值、申赎尾部或披露工作日不足，以及可见时间晚于冻结时点均拒绝；不使用未来净值补足尾部。

N2.3 精确生产入口为鉴权 `POST /api/v3/thesis-ledger/backtest/nav-inputs`。请求显式包含 V3 精确 RouteKey/RouteTarget、Desired/Effective/Catalog 修订、标的、基金类型、运行起止、冻结时点、预热和尾部预算、可见性模式及研究决策原文。首个生产适配器为 `efinance/eastmoney`，使用精确原文 Reader；其 `FUND_NAV_HISTORY` 适配器/来源修订分别更新为 `efinance-fund-nav-raw-v1`、`eastmoney-fund-nav-raw-v1`，既有旧修订准入不能用于新入口。显示用最新净值能力不随此次改变。

生产入口读取前后均核对真实策略、目录、精确准入、来源修订和请求标的/日期范围；准入须覆盖预热、执行及实际处理尾部，且在整批读取后仍有效。途中撤销、策略或目录改变、鉴权撤销时不发布证据。严格模式在当前来源缺少真实发布时间的情况下明确拒绝，研究模式不授予严格 PIT。生产前使用东方财富基金状态列表的代码和基金类型字段核验身份；名称不能用作类型推断，未知类型及与请求或已审查 QDII 规则不符时拒绝。

成功响应返回现行净值事实、研究规则/日期、准入快照、真实采集时刻及精确来源修订；同时返回完整来源页、逐条原生记录、身份来源原文、官方规则文件原字节、日期/假设/用户决策原文的冻结信封及摘要。规范净值记录明确属于 DSA 投影，其稳定记录 ID 绑定基金和原生记录摘要；原生记录原文和摘要单独保留，不将投影冒充上游原文。响应仅覆盖研究模型实际使用的预热/执行净值，完整来源页及日期构造所需尾部仍保存在证据信封内。精确 API 的生产、鉴权和来源验收由 N2.3 负责，Server 配置准备和业务 Run 接线仍由 N2.4/5 负责。

N2.4 的 Server 消费端在 DSA 适配边界重新核验固定请求、完整信封和来源原文的关联：原文页状态/总量/摘要、原生记录与规范记录、基金类型、规则文件、日期/假设/决策及真实时刻必须一致。HTTP 使用单次精确调用和有界流读取，失败不切换来源。现行 DsaClient 不新增 NAV 编排职责，独立客户端从 DsaModule 导出；Market 负责当前路由及前后状态核对，Backtest 负责 N1 完整计划和准备就绪凭据。原文解析只接受受限数据语法，不执行来源 JavaScript。原文缺失、篡改、预算超限或未核验的 QDII 文件拒绝；来源证据的一致性不授予严格 PIT 或目标部署资格。

Market NAV Reader 核对已应用且未陈旧的 Server Desired、同修订 DSA Effective 和完整 Catalog，目标序列必须逐项一致；按序固定第一个有资格且目录就绪的目标。首个就绪目标缺少当前精确原文适配器时拒绝，不能自行越过它换源。来源读取后再次核对路由修订、完整目标序列、资格和目录状态；目录生成时间不参与状态比较。返回完整来源信封及准入，并核对准入基金、完整日期覆盖、来源修订和返回时有效期。当前 Catalog 不提供准入记录版本，来源范围的实时前后核验继续由 DSA 生产入口负责；Market 的目录核验不扩张为独立的准入登记查询。目标环境须显式提供覆盖真实读取耗时的请求预算，隔离验收配置不修改目标运行态。

NAV 准备意图采用独立合同，显式提供基金类型、完整 CN/CNY 申赎模型、研究模式和日期决策原文；普通基金同时提供 T+1 决策原文，QDII 使用精确来源核查的具体规则。调用方不能指定来源修订、准入、实际可见性规则或最终冻结时点。准备阶段先复用 N1 支持条件与预算确定精确来源请求，来源请求的 `dataAsOf` 表示有界采集期限；来源完成后以 Server 当前时刻确定最终 RunConfig 的 `dataAsOf`，原始请求、响应及其原文保持不变。最终时点不得早于开始时点或晚于采集期限，全部来源/规则/决策/日期与事实时刻及准入有效期均须按最终时点重新核验，不能凭未来采集期限认定未来证据可用。

内部准备结果的 scope 为 `nav-input-plan`，绑定完整 N1 计划与策略版本内容、意图、最终配置、精确来源请求/响应、路由状态及准入摘要，保留当前原文上下文与全部事实。摘要只用于内容关联；独立纯函数返回成功不授予公开 Run 创建权限，N2.4.3.2 与 N2.5 分别负责服务/API 及持久化创建守卫。准备不写 Snapshot 或投递 Run，完整 Parquet 冻结仅作为隔离验收及后续创建路径使用。

NAV 专属准备端点为 `POST /api/v1/backtests/run-config/nav/prepare`。服务读取存储的 schemaVersion=2 策略版本，并在采集后再次核对相同版本的当前内容，缺失或变化阻断。公开响应使用独立 V3 Schema；成功返回最终 RunConfig、完整计划摘要、精确来源/准入与内容绑定，scope 仍为 `nav-input-plan`，不返回原文或净值记录。N2.4.3.2 首先提供内部 `prepareEvidence` 完整证据入口，N2.5 在公开成功路径增加持久引用及创建守卫；独立内部投影仍不授予创建权限，禁止用公开摘要冒充已保管原文或重新采集后沿用旧冻结时点。

N2.5 将准备端点扩展为持久化成功后返回服务器生成的准备引用、准备摘要与有效期，同时保存完整请求、证据及整体内容摘要。有效期取实际冻结后十五分钟与来源准入截止时间的较早值。创建端点消费引用及摘要和幂等键，不接受替换配置或原文；载入时重算完整准备证明、核对当前策略与路由，并检查准入有效期。创建保留原冻结时点，禁止再次读取净值来源。准备记录和策略版本使用数据库锁，V3 Run 与唯一消费关联在同一事务提交；冻结产物提前写入失败时记录失败终态，事务失败产生的无关联文件不构成可消费 Run。

净值 Run 使用当前 `BacktestJob`，`mode=V3`、`inputKind=nav`，并绑定准备引用及实际 NAV manifest。N3 当前已注册 NAV Worker 能力：创建后进入持久化 queued 状态，通过显式能力检查投递，Worker 按 NAV 冻结合同执行。缺少执行能力时收敛为 `failed/NAV_RUNNER_UNAVAILABLE`。NAV 专属读取验证配置、准备、物理 manifest 与结果关联；重试重新验证冻结输入，沿用当前状态和 attempt 原子更新。任务历史只返回严格摘要，经济结果仍须详情校验。N4 单独验收目标部署、真实来源与客户端；独立 PostgreSQL 验收不替代该阶段。

请求格式错误为 400，策略版本不存在为 404，存储策略格式/版本不符合合同为 422。完整输入、来源可用性、准入及采集期间策略变化等已知阻断使用 HTTP 200 的 `blocked` 结果与稳定诊断码；不得原样暴露上游错误内容。未知数据库或程序错误保留 HTTP 500，不伪装成输入缺失。服务使用当前配置的 DSA 请求预算作为整次采集期限；目标默认预算不足仍由 N4 单独处理。

N2.3.1 的现行字段为 `navVisibility`：严格模式 `strict-publication`，研究模式 `research-assumption`。研究规则必须显式提供基金、类型、版本、适用区间、`delayWorkdays`、规则依据、配置时刻及引用；普通基金的 `domestic-default` 只接受一个工作日，QDII 必须使用 `verified-fund-rule`，包括已核验的 T+1 QDII。规则记录的原文冻结于上下文 `ruleRaw`，其摘要为 `contentHash`；`documentHash` 绑定引用的披露文件，文件的真实性与适用区间继续由来源生产验收核查。

DSA 净值生产先复用现有东方财富移动端分页 Reader，提供独立于 DataFrame 的精确原文证据入口。净值必须为来源提供的正十进制字符串，不经 `float` 转换；全部响应页的 UTF-8 原文及 SHA-256、逐条原生记录原文及摘要、请求基金、Reader 修订和真实采集时间整批返回。所有页总量和行数一致、日期有效且不重复、净值有效、传输与预算校验成功后才发布；异常不返回部分证据。来源分页完整只证明该次来源声明的总量已取得，预期估值日与历史修订仍须分别核验。

研究规则生产与日期生产分别验收。普通基金默认规则必须消费显式 `fundType=domestic` 的研究配置及完整用户决策记录，其引用和 `documentHash` 绑定研究配置原文，不能冒充基金法律文件；标的类型由精确生产入口核验，规则构造器不负责从代码或名称猜测类型。QDII 只消费已审查的基金级规则记录，下载原文与固定 PDF SHA-256 匹配后才生成；已核验 QDII 不能通过普通默认配置覆盖。规则适用范围显式受审查范围约束，不将当前规则扩展到基金成立以来；源端内容变化、未核查 QDII、未来配置/采集或历史范围不足时拒绝。

冻结日期原文分别包含 `valuationDates`、`tradingDates`、`disclosureWorkDates`，整个日期证据记录的摘要同时绑定研究规则和逐条证据。研究证据继续使用 `publicationEvidence` 字段，但 `kind=research-assumption`，只声明原始净值记录摘要、规则/日历摘要、推算披露日和假设可见时间；该类型不接受 `sourcePublishedAt`。Manifest 保留真实 `source.capturedAt`；采集时间不得晚于 `dataAsOf`，严格模式发布时间不得晚于采集时间。

计划单独输出确认/结算 `calendarRange`、研究披露 `visibility.disclosureRange` 和两者并集 `requiredCalendarRange`。冻结与离线读回重新计数披露工作日、核验日终边界和原文摘要，不能只信任已写入的假设时间。Domain 输入保留 `navVisibility` 与 `visibilityDisclosure`；研究模式明确不能宣称严格 PIT，严格发布时间模式仍需来源 PIT 准入，不因冻结记录一致而自动取得资格。旧缺少显式模式、采集时间或三类日期的 NAV 冻结格式不由默认值解释为现行格式。

### Ledger 持久格式判别

现有 `LedgerEvent` 表只有 `payloadVersion`，该字段标识经济 payload 结构；事件信封中的 `version=2` 未持久化，因而无法从数据库区分旧信封与新写入。现行信封升级时新增独立、可为空的持久格式标记：新事件写入时显式标记当前信封版本，历史行保留空值并在读取、修订、撤销及投影前拒绝。`payloadVersion=1` 可在经济 payload 结构未变时继续使用，不借它冒充信封版本。不得为历史行设置当前版本默认值、批量回填或宽松解析。当前命令、领域投影、API Client/Desktop 与 Import/Portfolio 消费者须同步迁至新信封；旧经济事实不自动转换。迁移使用新增 SQL，历史 migration 不改写。

## 4. 跨运行时顺序与验收

按“状态机 → 执行面 → 消费面 → 部署验收”实施。先固定现行合同、旧格式拒绝与状态机，再收敛 Server/Worker/DSA 执行，随后统一 API Client/Desktop，最后在隔离数据库和目标 Docker 核查部署。每一阶段完成前保留可编译、可验证的最小纵向闭环，必要的短暂接线过渡须在该阶段内删除，不作为长期兼容层。

通过条件：源码中不再有可达的 ThesisLedger V1/V2 创建、执行、旧 Snapshot 回读或旧协议回退路径；当前 Market/Backtest/Ledger 用户路径和 M1/M2/M3 验收所需能力由同一现行实现提供；旧数据请求明确拒绝；定向测试、包级 build、边界门禁、隔离 PostgreSQL、官方 infra 更新后的 Server/Worker/DSA、客户端和真实业务证据分别通过。仅清理名称、单元测试或容器健康不构成完成。

未通过真实 Provider 权限、严格历史 PIT、目标 raw/hfq 与独立备用、事件、AI、浏览器/桌面以及回滚门禁时，关联多来源任务继续保持未完成。版本替换不能替代这些产品验收。
## 5. Server 镜像构建依赖范围

目标 Server/Worker 镜像构建只安装 `@thesis-ledger/server` 的递归 workspace 依赖与根构建工具。完整 lockfile、必要 workspace manifest、补丁与冻结安装校验继续保留；Desktop/Mobile 的依赖不进入 Server 构建安装范围。相邻 infra 官方入口必须同步维护 Dockerfile 精确变换映射和测试，不能通过绕过入口或删除业务卷解决空间不足。
