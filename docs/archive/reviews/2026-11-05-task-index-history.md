## 优先级与执行规则

**先修现有资金、风险和回测正确性，再推进数据隔离与最小研究链，之后补研究闭环，最后评估阶段化 Agent。** 这里 P0～P3 是全项目的排期，不是缺陷严重程度：IR09/IR10 原审查的 P1 等级不变；研究/DSA 文档原先称“P0 基础”的内容统一列为全局 P1 基础阶段，其合同前置仍是硬约束。

| 优先级 | 排期含义                                         | 选择规则                                                              |
| ------ | ------------------------------------------------ | --------------------------------------------------------------------- |
| P0     | 当前正确性修复：资金/风险/历史可见性及保存一致性 | 优先投入实现；真实目标门禁仍按自身前置，不以源码修复代替运行验收。    |
| P1     | 已承诺的数据服务、最小研究交付与核心功能剩余验收 | 前置就绪即可推进独立叶；资料/授权缺失的真实门禁原地保留，不反复探针。 |
| P2     | 已立项的历史比较/复核与产品收口                  | 排在第一条可用链之后；原依赖满足的离线设计可提前，不冒充产品已交付。  |
| P3     | 有触发条件的实验增强                             | 先固定评价协议，取得效果与预算证据再决定生产激活；不默认启用。        |

优先级和可执行状态是两条轴。表内“可准备”只指输入已能进行只读核对或合同设计，不代表本次已授权代码、迁移、模型、来源或部署操作。后续实施时按“明确授权范围 → 已满足的叶依赖 → 优先级 → 不重叠写集”选择下一叶；被外部条件阻塞时转到同级可做事项，不能靠改路由、购账号、放宽合同或关闭 checkbox 解阻塞。
