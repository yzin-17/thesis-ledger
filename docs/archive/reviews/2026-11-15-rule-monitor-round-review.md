## 结论

2026-11-15完成只读审查，覆盖来源保存、完整目录执行、五组官方文档映射、美国现行规则消费、资源保护、持久化及本地验收证据。未发现本轮引入且尚待修复的阻断问题；已确认的验收项没有遗漏。

不能把结论表述为“所有超时值完全未变”：连接时限曾按用户明确要求评估后从3秒校准为5秒，分别适用于TCP建立及TLS握手。单件15秒和整轮读取300秒的外层预算仍优先，其他网络阶段10秒及资源上限未变。另有两组替代页面只覆盖明确登记的公告正文或修订摘要，不能认证原提交包及全部附件未变，详见下文。

本次没有修改业务代码、运行配置、原资料包、数据库或历史，没有同步部署，也没有重新发起外部检查；仅新增本审查记录。真实运行结论复用最近一次已完成的全目录执行，并通过本地API及只读SQLite重新核对。

## 超时和资源保护

| 保护 | 当前行为 | 相对本轮起点 |
| --- | --- | --- |
| TCP及TLS连接 | 各阶段最多5秒，仍受单件剩余预算约束 | 从3秒校准为5秒，属于已授权的明确调整 |
| 网络读取、写入、连接池等待 | 各阶段10秒 | 不变 |
| 单件读取及摘要等待 | 外层最多15秒，并取整轮剩余预算 | 不变 |
| 整轮外部读取 | 从执行开始计算，最多300秒；到期停止后续外部请求，剩余项目记录`run_budget_exceeded` | 保留，计时起点前移至目录和资料包处理之前 |
| 单件响应 | 解码后累计超过2 MiB即拒绝，64 KiB分块 | 不变 |
| 并发和重试 | 串行、无自动重试、不跟随重定向；普通后台逐件落库后释放结果 | 保留并减少累计正文内存 |
| PDF解析 | 独立子进程，6秒解析等待、5秒CPU、Linux 512 MiB地址空间、最多100页及16 MiB解压内容 | 不变 |
| 正文快照 | 最多250000个UTF-16单元；过大、不可读及解析失败保留原因 | 不变 |
| DOCX内容 | 解压项目声明总量上限为单件响应上限的8倍 | 不变 |
| 任务状态 | 单次领取、租约及owner保护、持久化终态、重复执行及停止保护 | 不变 |

以上网络和读取预算不是所有后处理的绝对墙钟终止承诺：PDF子进程清理、数据库逐项记录及终态提交仍需要有限收尾时间。本轮没有把分阶段时限相加为新的总预算，也没有提高解析、内存、页数、正文或响应大小阈值。
