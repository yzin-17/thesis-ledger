## 三 结果正确性

### R1 合法表达式在会话准备阶段被遗漏

正式 Schema 允许会话数值参与合法算术，运行兼容性检查也允许这种组合。但 sessionExpressions 只递归 all／any、not、compare／cross 和 indicator，没有遍历 arithmetic、absolute 等新增节点。

受控输入为两根价格 100、120，成交量各 10，当前会话 VWAP 为 110：

| 规则 | 正式 Schema 与 V3 校验 | 构建会话序列数 | 实际数值求值 |
| --- | --- | ---: | --- |
| close > sessionVWAP | 通过 | 1 | available，110 |
| close > sessionVWAP × 1.02 | 通过 | 0 | unavailable，数值运算输入不可用 |

第二条本应比较 120 > 112.2，但准备阶段没有生成该会话指标。问题可在真实构建函数和求值器上纯内存复现。

**根因**是新增 AST 节点后，各消费端维护独立递归逻辑，没有穷尽性约束。单独的 Schema 测试或求值器测试无法覆盖这个跨层遗漏。

**最小修复**：先补齐合法算术组合的会话收集；随后抽出有类型的子节点遍历入口，供依赖收集、会话收集、指标构建、回读和引用操作使用。动态会话值不能进入历史预计算的既有禁令继续保留，不能通过泛化递归顺便扩大合法范围。

**验收**：至少覆盖 sessionVWAP × 1.02 和 abs(sessionVWAP − close)，完成“合法定义 → 依赖闭包 → 序列构建 → 求值”组合验证。[S04]

### R2 成交额与换手率混用，影响实验评分

分析层的 turnover 默认计算已闭合交易的 entryValue + exitValue，单位为资金金额。股票／ETF 和 NAV 调用处都没有提供归一化覆盖值。实验评分却将该字段作为换手率：

~~~text
balanced score = totalReturn − |maxDrawdown| − turnover × 0.05
~~~

受控复现保持同一策略、相同收益率与回撤，只将资金规模放大十倍：

| 初始资金 | 收益率 | 最大回撤 | 返回 turnover | balanced 分数 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 10% | 5% | 2,100 | −104.95 |
| 10,000 | 10% | 5% | 21,000 | −1,049.95 |

比例与金额直接相减，惩罚项随计价规模变化，并会淹没收益与回撤。当前 UI 也出现口径分裂：普通结果将该字段标为“成交额”，NAV 页面将其标为“换手率”并按百分比显示。

另一个相关问题是成交统计来自闭合生命周期。买入 100 股 × 10，再卖出 50 股 × 10，实际成交金额为 1,500；因为尚有 50 股未平仓，trades 为空，返回 turnover 为 0。闭合生命周期适合计算胜率和已实现盈亏，不适合代表全部成交活动。

**最小修复**：

- 将成交金额与换手率定义为两个不同指标。
- 成交金额由实际 fills 汇总，包含未平仓仓位的买入和部分卖出。
- 换手率明确定义分母、单双边约定和统计区间，再参与评分。
- 指标合同携带单位／展示方式，评分、Desktop、Mobile 共用。
- 旧指标保留旧版本语义，新分析版本再计算；不能重写冻结历史结果。

**验收**：比例策略在资金同比缩放下应保持归一化换手率与评分不变；部分平仓和期末未平仓的成交不遗漏。[S05]

### R3 不可计算与条件为假混在一起，无关指标缺失又阻断评价

这里有两个方向相反的问题。

**其一，信号不可计算不容易被发现。** 将 R1 的缺失指标输入实际 runDeterministicSimulation，得到：

~~~json
{
  "signals": 0,
  "rejects": [],
  "events": [
    { "type": "signalEvaluation", "payload": { "tick": "当前决策时点" } }
  ]
}
~~~

原始事件中的 tick 是完整时钟对象，上面为可读摘要。事件没有保存入场条件 unavailable 的原因。普通不可计算最终走“无信号则返回”；结果汇总没有纳入普通入场／退出求值不可用的统计。用户难以区分没有机会、预热不足、指标未构建和运行窗口缺值。

这已证明核心执行与汇总诊断存在缺口；本轮没有跑数据库／Worker 落库链，不能据此宣称某个线上结果已经被错误标记 complete。

**其二，指标不可用又被误解释为数据缺失。** 使用完整、恒定权益和一笔零盈亏闭合交易，分析层返回：

~~~text
totalReturn = available 0
maxDrawdown = available 0
tradeCount = available 1
sharpe = unavailable ZERO_VOLATILITY
warnings = []
completeness = partial
~~~

优化评价首先检查 completeness 必须为 complete，否则以“回测数据完整性不是 complete”拒绝。即使优化目标只需要收益和回撤，也会因数学上没有定义的 Sharpe 被判数据不可用。

**最小修复**：

- 按具体用途判断可用性：规则所需输入、该次操作所需价格、评分目标所需指标分别处理。
- 评分只检查目标实际依赖的指标。收益／回撤可用而 Sharpe 因零波动未定义时，继续提供收益／回撤评价。
- 为规则记录总决策次数、可计算次数、成立次数、不可用原因计数及少量路径样本。
- 少数参考时点缺值按已有规则跳过相应判断／操作，并说明受影响次数；不要仅因这一点拒绝整个结果。若关键规则在整个窗口内都不能计算，则说明该策略本次无法得到有效评价。
- 预期预热期与运行窗口内异常分开；未知上市信息、研究费用假设和某个非目标指标未定义，不合并成一个全局“数据不完整”状态。
- 不必保存每根 K 线整棵 AST。[S04][S05][S06]

## 四 交易语义与费用

### R4 添加保护计划会隐式改变入场政策

当前普通策略使用 false → true 边沿触发入场；启用有效 tradePlan 后，空仓入场判断采用条件当前为真。

受控对照：

~~~text
入场条件：close > 10
当前 close：11
前次 entry：true
当前状态：空仓

普通策略：没有新入场信号
仅加入 5% 止损计划：生成 entry
~~~

代码注释明确保留普通边沿和计划生命周期两种语义，因此不能直接认定违反了既有规格。但这个选择由可选模块是否存在隐式决定，用户“只增加止损”时也可能改变重入场频率。

**最小改进**：将入场触发政策显式化，例如“条件由假变真”和“空仓且条件为真”。中文回读、AI 修改范围和差异展示都要包含它。历史策略保持原语义；加入保护不自动选择另一政策。

**验收**：用仅增加保护的成对策略，覆盖持续真值、止损后空仓、普通退出后空仓和拒单后重试。[S07]

### R5 多笔成交需要独立的累计计费合同

#### 已确认缺陷：异价部分成交触发金额校验错误

条件为 raw-events 实际份额记账、美股 actualShares 券商计费、同一订单出现不同价格的多笔成交。默认 wholeOrder 通常不触发；perBarCap 压力测试等部分成交路径会触发。

第一笔 10 股 × 10 美元正常；同价第二笔也正常。第二笔改成 10 股 × 11 美元后，累计计费传入：

~~~text
累计数量 = 20
累计成交额 = 210
本笔价格 = 11
~~~

单笔费用校验要求 quantity × price = turnover，于是以 20 × 11 ≠ 210 抛出“实际股数与成交金额不一致”。正式账本报价未吞掉该异常，运行会被中断。

#### 条件性风险：费率变化重算了历史成交

费用记忆保存累计数量、金额与已付费用，但没有政策分段身份。每次按当前费表计算全订单累计费用，再减已付费用：

| 两笔成交各 1,000 | 实际两笔收费 | 若按各成交时点费率累计 |
| --- | --- | --- |
| 0.1% → 0.2% | 1、3 | 1、2 |
| 0.2% → 0.1% | 2、0 | 2、1 |

是否按订单锁定政策，或按成交分段累计，需要由合同明确；当前行为没有完整表达这两个选择。全区间固定费率的默认研究不受此变化情境影响。

**最小修复**：分开单笔事实校验和订单累计计费；累计接口直接消费累计股数／金额与政策身份，明确最低佣金的作用范围。不要伪造一个平均价格来绕过单笔校验。

**验收**：同价／异价多笔、最低佣金只收一次、平台费上限、费率升降、跨分段成交、取消剩余量。[S08]

## 五 任务与可复现性

### R6 取消意图与计算停止需要贯通

#### 已确认竞态

取消 API 只接收 runId，但更新条件绑定读到的 status 和 executionAttempt。若读到 queued 后，Worker 先领取为 running，取消 CAS 失败后只是返回最新记录：

~~~json
{
  "status": "running",
  "executionAttempt": 1,
  "cancelRequestedAt": null,
  "changed": false
}
~~~

同一个仍在执行的 Run 丢失了用户这次取消意图。现有测试甚至将这个行为作为预期。

#### 已确认的架构缺口

API 的 AbortController 存在本地服务实例 Map 中；正式计算在 BullMQ Worker thread 的独立 Nest context 中。执行器有 signal.aborted 检查，但本轮检查没有发现把 API 取消请求传到该执行线程信号的机制。

现有 attempt CAS 能阻止取消后的晚到成功提交，这是正确保障。问题是计算可能继续占用槽位直到自然结束。实际 Worker 取消测试验证了晚到结果不提交，没有验证计算及时停止。

**最小修复**：取消记录以持久化 Run 意图为准；CAS 冲突后重新判断非终态并有限重试登记。执行线程接收通知，并在可让出执行权的批次边界检查；超出宽限期的计算由父执行环境按明确政策终止，attempt fence 继续保留。

**验收**：分别验证取消意图不丢失、结果不再提交、计算在规定延迟内停止。三项不是同一个断言。[S09]

### R7 NAV 引擎版本没有被现有保护识别

indicatorEngineChanged 只匹配股票 Runner 名称：

~~~text
thesis-ledger-v3-local-runner-vN
~~~

NAV 使用另一种稳定身份：

~~~text
thesis-ledger-v3-nav-local-runner-vN
~~~

原函数受控结果：

~~~json
{
  "stock_v3_to_v4": true,
  "nav_v1_to_v2": false
}
~~~

执行前检查和重试复用该函数，领取时又会写入当前 engineVersion。因此 NAV 引擎升级后，旧失败 Run 可能在同一身份下换引擎重试。冻结行情相同不能证明执行含义相同。

**最小修复**：按执行类型比较完整 Runner 身份；已绑定引擎的 Run 发生版本变化时，使用冻结输入创建新 Run，并保留关联。显式迁移和技术重试分别定义。可进一步保存构建摘要，但无需借此新建通用版本系统。

**验收**：股票与 NAV 对称覆盖同版本重试、版本变化拒绝、新 Run 使用旧输入和历史读取。[S10]

### R8 准备和冻结阶段尚未完整进入持久任务

股票／ETF 创建顺序为：查询幂等键、分配随机 Run ID、构建并 finalized 快照、最后创建 queued 数据库记录。

这使耗时准备阶段没有正式 BacktestJob 可查询／取消。HTTP 或进程在物理快照完成后、数据库建单前中断，现有执行任务框架不能直接恢复这一段。两个同幂等键并发请求也可能各自构建一套物理快照，最终只在数据库唯一键处合并。

这是由代码顺序确认的风险，不是本轮已发生的线上事故。NAV 已有持久准备凭证，可以借鉴其职责分界。

**最小改进**：在昂贵准备前持久化幂等创建意图，由唯一 owner 推进 preparing → freezing → queued；记录临时产物归属和清理／恢复状态。将准备纳入现有任务模型即可，无需引入复杂通用工作流引擎。

**验收**：同幂等键并发、准备取消、快照写完前后进程中断、建单失败及重入恢复。[S11]

## 六 AI 生成设计与验收口径

### R9 上一轮生成问题仍反映同一类合同不一致

原会话累计 33 次调用中有 29 次业务生成、4 次资格探针。9/13 是跨批次保留有效成功回执的覆盖，不是当前版本一次生成准确率。本轮未新增真实调用。

主要结论保持：

- AST 已正确引用 open／high，但模型维护的字段汇总遗漏。
- eventValue 在通用数值表达式中可生成，capture 又可选，使未绑定引用直到完整校验才失败。
- 多周期实际 wire 已含时区 pattern 和 strict，输出仍缺时区；现有证据只能证明该链路未阻止此违约，不能直接断言具体上游实现原因。
- 模型把运行时已经完成／可见的数据再 lag 一根，属于交易语义误解。
- 发现装配首错即停，泛化错误又遮住同份输出中的下一层问题。

建议先统一完整诊断，再收紧事件作用域合同。行情字段依赖若改为确定性编译产物，需正式调整生成协议及规格，记录原始输出、编译结果和版本；来源身份、周期、冻结哪个数值、比较方向等仍由显式策略决定。不能给旧失败输出补字段后记为原模型成功。[S12]

模型漏写字段引用、事件未绑定、时区或 lag 语义错误，首先是生成合同与实现问题。应逐项检查已取得的行情是否已有所需字段，不能把这些失败笼统归为上游数据不足，也不需要因此先增加新的历史数据源。

## 七 现有数据是否足够，以及缺失如何影响研究

### 以策略实际依赖判断，不追求一套输入覆盖全部策略

| 要做的研究 | 实际需要的数据 | 当前判断与处理 |
| --- | --- | --- |
| 单标的日线均线、RSI、MACD、价格突破，按金额或比例投入 | 对应后复权价格、足够预热和日历；下一开盘操作需要开盘价，涉及高低点的规则再使用高低价 | 普通入口已按需取数，纯指标策略无需原价。优先用现有日线来源跑通这类研究 |
| “股价低于 4 元”等实际价格条件，或固定份数投入 | 在上述输入外，增加相应时点的不复权参考 | 已实现独立来源读取；后复权和原价可来自不同已配置来源。具体参考点缺失影响对应条件／操作 |
| 成交量过滤、成交额条件、VWAP、参与率约束 | 算子真正使用的量额字段及适用单位；会话指标还需要对应盘中窗口 | 缺少必要字段时限制这类规则，不连带阻断未使用这些字段的价格策略 |
| 小时级、分钟级和跨周期策略 | 所选周期的价格、预热、可见时点；需要分钟内信息的规则才有业务上的分钟依赖 | 当前回测统一从 1 分钟聚合，实际取数负担较大；先开放已有来源能取得的具体窗口，见下文 |
| 日线费用、滑点、结算与 OHLC 内成交次序 | 已保存参数和明确的模拟政策 | 沿用现有研究默认值。官方历史费率、盘口和完整逐笔成交不是普通研究前提 |
| 公告／财务事件、点差、历史股票池或跨标的策略 | 对应规则真正需要的事件、报价、成员或其他资产数据，以及相应执行支持 | 针对该能力核实当前接入；缺失就明确限制该规则。不要要求价格研究先补齐这些数据，也不要用日线价格替代原规则含义 |

这里的“足够”同时看字段、时间粒度和窗口长度。例如使用 MA20 的日线策略，需要能完成预热并覆盖执行期的日线；无需先证明所有供应商、所有市场、全部历史都有数据。来源目录显示已接入，也不能替代该次窗口是否取到的判断。[S01][S13]

### 现有记录已经支持的可行性

- 2026-11-11 的来源核验中，510300.SH 的 28 个交易日日线可由多家现有来源取得；富途 SDK 也取得过 510300.SH、600519.SH 同窗的原价和后复权样本。600519.SH 严格读取曾在访问上游前因缺上市事实被拒，这不等于供应商没有价格。
- 同日港美后复权准备核验取得 AAPL.US 年度窗口 267 根日线、00700.HK 年度窗口 262 根日线。苹果窗口末日尚未开市，按已有研究假设处理；没有等待末日数据齐全才允许研究读取。
- 2026-11-12，00700.HK 的真实实验准备返回 prepared，后复权和原价参考父窗各 335 根日线；上市状态仍可保持 unknown。
- 同日 300058.SZ 的真实准备使用富途后复权和同花顺原价，返回 prepared，说明两套价格不必依赖单一来源同时提供。

这些记录足以支持“从现有日线数据开展具体研究”的设计方向。它们证明的是对应窗口取数或准备成功，不扩写为所有标的可用或完整实验已经跑完。[S13]

### R10 AI 实验强制原价，增加了纯指标研究的前置依赖

普通回测的 readPriceResearchReference 已有按需分支。AI 实验则要求 priceResearchReference = freeze，并在新实验检查 actualPriceWindow；准备时因此强制读取原价。这个选择是为了让候选随后可以增加实际价格条件，符合现有实验规格。

代价是：已有足够后复权数据而原价来源暂不可用时，连不需要原价的探索也不能启动。

**建议调整**：在准备阶段根据实际可取得的输入确定并冻结本次探索能力。只有后复权时，允许纯指标与金额／比例投入；取得原价时，再开放实际价格阈值和固定份数。复用现有策略能力约束，将本次字段、周期和预热范围传给生成器。候选在这个范围内产生，不在运行中临时补取新行情。

如果用户指定的基线或规则本身需要原价，仍要明确指出这一具体缺项；不能自动删掉条件或改变仓位含义。这项建议需要更新实验规格与生成能力合同，并不要求增加 Provider。[S13]

### R11 共享成交量门槛可能阻断只使用价格的策略

market-data-wire-v3.ts 在响应包含 historicalTradabilityWindows 时，要求日线每根 volume 为正。普通研究常用的 assume-untradable-no-bar 请求又需要同次日级状态证据，因此未使用量字段的价格策略也可能被缺量拒绝。这不是所有 V3 响应的统一要求，但确实覆盖当前常用日线研究路径。

**建议调整**：让研究读取按用途消费字段。有效价格和所需时间范围足够时，缺少未使用的成交量不应直接拒绝价格研究；VWAP、量能过滤和参与率模型继续要求其所需量字段。区分缺失、真实零成交量与价格／状态冲突，不能把缺量补成零或伪造已成交证明。先调整研究用途的合同，不直接删除所有共享校验。[S13]

### 分钟数据按现有粒度使用，避免不必要地要求最细输入

当前 additionalSignalPricePlanV3 将所有非日线逻辑周期映射为 1m，再按周期倍数准备预热。于是 60 分钟策略也依赖原始 1 分钟窗口。这个设计便于统一聚合，但增加了请求量、历史额度和窗口覆盖要求，应按现有来源能力评估其实际收益。

已有真实分钟回测记录覆盖富途 600000.SH 的指定冻结窗口；多周期另有本地及 Worker 受控样本。应先清楚支持这些可取得的范围。若现有来源可以提供所需原生 60 分钟数据，可将其作为后续直接输入方案评估；需接入对应冻结和完成时点语义，不能仅因图表能显示就认为回测已接通。首小时 VWAP、分钟内触发等确实依赖细粒度信息的规则，仍按相应数据能力限制。[S13]

### 缺失只影响真正依赖它的能力

保留现有普通研究选择：后复权用于研究价格和单位，原价按需；研究费用、滑点与结算沿用冻结参数。未知上市日期、未还原分红现金到账、缺少历史整手／价位，不自动阻断这一用途。

具体参考时点缺失时，该条件不可评估；固定份数操作缺少原价时，该次操作不执行，并汇总影响。整个范围不能形成研究窗口，或用户要求的关键条件全程无输入，才说明本次策略无法评价。数据足够但未触发交易，应正常给出零交易结果；Sharpe 等非目标指标未定义，也不影响其他可用指标。研究假设简要展示一次即可，具体失败直接指出缺哪个输入和影响什么。[S01][S02][S06]

### 封存测试的现有保护应保留

源码已有开发／验证指标白名单、封存前候选锁定、测试揭示状态、数据 Artifact 指纹比较及采纳版本保护。这些是实质防护。

研发仍应明确：

- 多轮反馈使用过的 validation 属于调参与筛选材料。
- 封存测试通过只能支持该预先锁定的候选和范围。
- 多次重建实验并反复使用同一历史窗口，不会获得新的独立证据。
- 增加压力费率、滑点和邻近参数稳定性对照，适合放在当前正确性问题修复之后。
- 不以收益排名单独替代样本数量、执行限制和信息可见性披露。[S03]

## 八 推荐修复顺序

### 第一阶段 用现有数据完成常用研究

1. 先明确当前常用研究范围：单标的日线价格策略、现有来源可取窗口、按金额／比例投入及保存的费用假设。继续复用按需取原价与独立来源机制。
2. R10、R11：调整实验原价和共享量字段的用途要求。优先允许数据足够的策略继续运行，限制缺少输入的具体能力。
3. R1、R2：修会话表达式遍历、成交金额／换手率和评分。这是已有输入上的计算错误，不需要通过补更多行情解决。
4. R3：按目标需要的指标评价，保留局部缺失统计，让用户拿到仍有用的收益、回撤和交易结果。
5. 用现有冻结窗口与定向样本检查上述路径。先记录准备失败原因、需要字段和实际取得字段，再决定是否有必要新增来源；本轮不新增真实请求。

### 第二阶段 明确交易合同

1. R4：显式入场触发政策，并保护旧策略含义。
2. R9：统一生成／正式校验诊断、事件作用域与依赖编译边界；候选生成服从本次已有数据能力。
3. R5：实际份额、多笔部分成交和跨费率组合按使用需要修复；默认固定研究费率、整笔执行不等待这部分完成。
4. 以成对语义测试和跨模块组合测试为主，不靠增加孤立单元测试数量。

### 第三阶段 生命周期与运行态

1. R6：取消意图登记、线程通知、停止时限分别验收。
2. R7：统一股票／NAV 引擎身份门禁。
3. R8：准备和冻结纳入可恢复持久任务。
4. 通过仓库已有隔离入口验证 Worker、数据库、队列和故障恢复；目标部署只使用正式 infra 入口。

### 第四阶段 固定基线验收

在源码和协议稳定后，先重放旧输出并明确标为“旧输出在当前代码下兼容”；再按独立授权进行固定提示、固定 Schema、固定模型的真实生成验收。历史覆盖率、首次正确率和技术重试成功率分别记录。

## 九 需要固定的关键不变量

| 不变量 | 推荐的最小验证 |
| --- | --- |
| 未使用的数据缺失不阻断可执行的研究范围 | 纯价格／量能策略缺量对照；只有后复权的受限探索 |
| 缺少必要数据只影响对应条件、操作或能力 | 缺原价参考时点、依赖原价的固定份数、纯指标三组 |
| 数学上未定义的非目标指标不阻断评价 | 收益／回撤可用而 Sharpe 零波动未定义 |
| Schema 允许的表达式在准备和求值链具有一致支持 | 会话指标嵌套算术／绝对值的组合样本 |
| 比例指标不受计价规模任意影响 | 相同策略与资金同比缩放 |
| 成交活动不依赖生命周期是否闭合 | 未平仓、部分卖出、完整平仓对照 |
| 无交易机会与无法计算可以区分 | 恒假规则、预热期、缺序列三组 |
