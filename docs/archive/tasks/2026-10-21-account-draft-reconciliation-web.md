# 账户草稿与对账的无模型 Web 实施任务

关联[规格](../../specs/2026-10-21-account-draft-reconciliation-web.md)及[原 T12/T13](2026-08-18-position-entry-account-model.md)。本次恢复范围由用户明确选择，主线程直接实施，保留数据，只验 Web，真实模型暂停，DG3 TODO 保持。

## 分阶段任务

- [x] A1 状态合同：共享审核响应、当前修订及冻结行的一致只读查询；保持旧截图适配接口。
- [x] A2 执行面：复用现有修订、选行提交和确定性对账命令，验证格式、冻结、版本及账户边界，不自动重试写入。
- [x] A3 消费面：完成账户草稿/对账入口代码、持仓快照审核、显式保存与选行提交、失败保留和脏状态确认；目标开放由 A5 验收。
- [x] A4 本地验收：定向 Schema、服务及挂载 UI 测试通过后执行类型/构建和适当仓库门禁，记录命令与输入范围。
- [x] A5 部署验收：按实际变更选择正式最小更新入口；专用账户/草稿完成真实 Web 修订、部分提交、冲突/冻结与对账，结清停用并核对原数据及零模型调用。
- [x] A6 对账接续：更新原 Spec/Task、任务首页和接续前沿，保留截图及原父项未通过条件，再按原优先级继续。

## 当前核对

当前 Ledger 已支持独立 `ImportDraftRevision`、选行提交和冻结；新增独立的只读审核响应并复用规范化命令。原已经通过的基金、手动余额、T18 与模型暂停证据按未变输入复用。

实际验收前准备专用账户和受控草稿，仅通过正常 API 写入，不改写历史数据。业务/草稿保护表与本次允许差集、失败及清理结果在执行证据中登记。

客户端 57 项、服务端审核 39 项的证据保持；最终对账展示变更复跑 20 项，类型与最终构建通过。发现数量/成本混用后先完成[乱序投影修复](2026-10-21-baseline-projection-consistency.md)，Domain 全量 455 项、Server 定向 43 项及最终 8 组/2301 文件门禁通过。真实 Web 的编辑保存、部分提交、冻结、两次 409 及重读恢复、对账确认/幂等/撤回和窄屏均完成。专用账户结清停用，11 条审计及三份草稿修订保留，原 14 账户完整保护哈希、来源/路由及零模型计数不变。[完整验收](../../tasks/evidence/2026-10-21-account-draft-reconciliation-acceptance.md)和[实际预案](../../tasks/evidence/2026-10-21-account-draft-reconciliation-plan.md)记录失败、回滚保护和清理过程。原 T12/T13 与总 Goal 保持未完成，已按原优先级回查剩余条件。
