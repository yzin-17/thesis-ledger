## 2. 实施任务

### T1：展示与只读查询契约

- [x] T1：建立可测试的任务分类、摘要、结果可用性和查询契约。
  - 覆盖验收标准：A02、A08–A12、A14–A16、A20、A24 的契约断言；A06/A07 的 URL 状态编码契约。
  - 依赖：无；以已核对源码为基线，开始前确认相关未提交修改没有改变事实。
  - 责任范围：AI 研究展示契约及其生产端事实清单；只在确有跨应用复用价值时放入 `packages/schemas`，实验内部编排留在原模块。
  - 交付内容：核对普通研究、实验内部任务及历史入口的写入路径、实验关联、实际执行模型、费用可信度、结果版本和引用兼容条件；形成有限分类与安全输出字段，不以没有实验关联推断手动来源。
  - 接口契约：固定列表搜索、状态、来源、内部范围、排序和游标参数，明确缺省值、非法值及旧调用方兼容；固定 `/ai-chat` 的选中 ID、阅读模式和查询条件编码。明确当前页投影字段、摘要来源、核验原因、能力和覆盖实际验证输入的数据版本。
  - 权威样例：普通有效结果、明确依赖数据缺失、一般未知项、缺失结果、无效引用、旧版缺关联 ID、提供了错误关联 ID、实验内部、未知类型/状态、费用不明；同一事实与版本在列表和详情投影一致。
  - 完成条件：参数和返回投影有实际类型/Schema 与共享权威 fixture；分类与状态规则具有唯一可复用实现或可测试边界；契约测试通过，T2/T3/T4 可直接消费，不需要分别猜测。
  - 验证方式：定向 Schema/映射测试覆盖输入拒绝、缺省值、历史兼容、结果可读性与可信度分离、版本变化和敏感元信息排除。无需部署或调用真实 AI。
  - 后续交接：本任务验收通过即为契约就绪点；契约修改须同步消费者和相关样例，不以口头“基本确定”提前交接。

### T2：服务端查询与批量展示投影

- [x] T2：完成研究列表和详情的只读查询能力。
  - 覆盖验收标准：A02、A08–A16、A20、A22、A24 的服务端断言。
  - 依赖：T1 契约就绪。
  - 责任范围：现有 AI controller/service 和明确拥有查询职责的适配；必要的批量实验/对象关联读取。不得反向导入实验业务编排或创建无所有权共享目录。
  - 交付内容：问题搜索、执行状态、来源及内部任务过滤在分页前执行；更新时间与 ID 稳定排序，游标匹配实际查询模式；旧调用方保持既有语义。批量返回已有摘要、分类、来源、对象、结果可用性和版本，详情复用同一事实判定。
  - 批量与安全要求：仅处理当前页及分页所需前瞻记录；对象和引用核验不得逐行查库，响应不包含完整报告或原始 `modelMetadata`；关联对象访问遵循既有权限规则；不存在、无权限及查询失败可区分。
  - 完成条件：真实查询能够返回普通、内部和未知混合数据的正确范围；开启内部任务开关前后分页无客户端过滤造成的空页；有足够事实的普通成功记录不依赖点开详情才核验；只读请求无业务写入。
  - 验证方式：定向 controller/service 测试通过后，在隔离 PostgreSQL 执行筛选组合、相同更新时间、多个游标页、未知分类、旧查询模式及非法游标；覆盖批量摘要和引用归属。比较 1 条与多条当前页记录的关联查询次数，确认不会按行增加；检查业务表前后事实一致。
  - 验收边界：隔离库数据是受控样例，证明真实查询逻辑，不代表目标 Docker 已更新或线上历史数据全部可分类。目标运行态归 G1。
