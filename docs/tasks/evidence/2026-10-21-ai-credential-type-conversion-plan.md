## 精确写集

正常 AI API 创建固定名称 `controlled-type-contract-20261021`，创建前确认不存在，绑定唯一自有 ID。始终停用，优先级 993，地址 `http://127.0.0.1:9/v1`，模型 `controlled-type-model`，未知价格、无用途、无默认引用，仅持有明显的占位 Key。

Web 编辑同一条目，在同一 Drawer 选择行情，选择报价能力，凭证留空并普通保存；重新打开后切回 AI，重新填写上述地址和模型，凭证仍留空，普通保存。遵循 SDK Spec 的类型专属字段清理：初始 10000 毫秒超时切回后采用新 AI 草稿 30000 毫秒默认值，不恢复旧专属设置。两个阶段均检查名称、停用、优先级、自有 ID、版本递增、原密文及解密摘要；行情设置必须为空，AI 无用途/价格，不取得执行资格。

不点击连接、目录、用途或模型测试，不修改原三份配置、默认、账户和路由。每阶段复用完整保护证明，仅精确排除唯一自有 ProviderConfig 行；原健康记录不可覆盖，自有健康记录和全部模型计数为零。

正常 DELETE 清理自有 AI 条目。若停留在行情且需故障清理，先经正常 AI POST 按当前修订恢复固定停用 AI 输入，显式提供本次占位 Key，再正常删除。保留全部失败和恢复回执，不执行直接数据库写入。完成后完整保护 JSON 必须恢复，Web 返回原账户页。

## 实际地址保护与预案补充

首次反向保存空 Key 被现有 `ai-provider-save.service.ts` 的地址保护拒绝：行情设置已经清理原地址，不能将旧 Key 自动发往新地址。该拒绝符合凭证安全边界，并非生产回归。保留首次检查失败和 Web 提示，新增 `rejected` 阶段精确证明行情原记录及保护状态不变、草稿仍在；随后显式重填本次相同占位 Key，预期解密摘要相同、密文正常重新生成。前文“两个阶段原密文保留”的原假设仅适用于 AI→行情，反向保存按此补充执行。真实用户凭证及连接仍不触碰。

## 工具函数选择

已从 Server 实际依赖解析 `es-toolkit@1.51.0`，检查根导出的 `cloneDeep`、`isEqual` 及对应声明/实现；没有 SHA-256/digest 导出。官方文档确认[深复制](https://es-toolkit.dev/reference/object/cloneDeep.html)和[深比较](https://es-toolkit.dev/reference/predicate/isEqual.html)行为。

| 需求               | 候选                                | 本次选择与条件                                                           |
| ------------------ | ----------------------------------- | ------------------------------------------------------------------------ |
| 已知 JSON 快照复制 | `cloneDeep`、原生 `structuredClone` | 维护脚本只处理可克隆 JSON DTO，使用原生函数，无自写递归或额外根运行依赖  |
| 验收精确比较       | `isEqual`、`node:assert/strict`     | 使用原生断言获得失败位置，拒绝时保留原始快照；业务布尔判定可用 `isEqual` |
| 加密摘要           | `node:crypto`                       | 工具包无相应导出，使用标准 SHA-256，不以普通对象比较代替摘要             |

不为验收改变生产类型转换逻辑；沿用已过 E4 无密钥转换、凭证副本恢复和非 AI 基本路径证据，只补带凭证目标 Web 差集。
