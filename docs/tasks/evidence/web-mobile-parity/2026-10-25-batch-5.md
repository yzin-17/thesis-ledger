## Chrome 与 OAuth 接续补验（2026-10-25，北京时间）

本次新增授权为接受本轮 Android 模拟器 Chrome 首次条款。操作前读取并保存条款页；先经 Manage 关闭可选使用/崩溃统计，截图核对开关处于关闭位置，再选择 Use without an account 接受条款；关闭非绑定首次说明并保留现有搜索设置，最终原生树显示 Signed out。没有登录、注册或授予真实账号权限，未更改设备代理、证书或网络设置。

Android 从应用创建本轮假 OAuth 会话并打开官方白名单地址。默认 `openapi.longbridge.com` 在设备和宿主机直连均出现连接重置，原失败保留；只读对照显示现有白名单中国区地址可直连，因此仅为本机接收端增加中国区测试开关。最初假链接只有 `client_id`，官方返回缺少响应类型；依据[官方 HTTP API 说明](https://open.longbridge.com/docs/api?page=error-codes)补入 `response_type=code` 后，Chrome 在 `openapi.longbridge.cn` 显示安全连接，正文返回 `internal_server_error`，原因为 `validate client err:oauth client not found`。正文由原生截图核对，JSON 内容未进入 UIAutomator 文本树，不能把该项声称为自动文本断言。

这证明官方地址传递及 HTTPS 文档到达，不能证明真实授权页或账号授权成功。顶部仍存在系统网络验证的离线横幅，与本次官方 HTTPS 响应分别记录。返回应用后仍显示等待，随后取消通过；未把浏览器返回或官方错误响应当成授权成功，也未尝试注册外部 OAuth 客户端。

另以本机受控接收端提供 `failed` 和 `succeeded` 两个终态，Android ADB/UIAutomator 与 iOS XCUITest 分别核对失败原因、成功提示和继续授权/取消按钮禁用，均通过。该终态没有 token 交换、凭证落盘或真实回调，只证明手机正确消费 Server 状态。iOS 未重复打开外部授权网页，既有 Safari 启动/返回/取消/过期证据按原输入保留；新增终态与 API 恢复各有独立结果。

本次只修改忽略目录中的夹具、自动操作脚本及当前验收说明，应用、共享 client/Schema 和原生构建输入未变；因此复用 `5c67b4fa` 的四项 CI 与两端原生编译，不以新增 XCUITest 测试运行器编译替代 app 原生编译。当前实现与冻结快照再次核对，旧验收包和所有失败记录保留；详见 `Chrome补验结果.json` 及更新后的本机精简包。
