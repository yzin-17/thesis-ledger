# NAV 创建守卫前置准入

## 问题与修复

当前 Run 准备与 Snapshot 规划只支持股票/ETF 日线，但创建守卫原先把所有非股票标的映射为 ETF `DAILY_BAR` RouteKey。若直接提交基金策略与构造的准备戳，守卫可能先查询错误路由，再由 Snapshot 阶段拒绝并留下失败 Run。

创建守卫现在先校验场内执行、日频和股票/ETF 身份；NAV 或其他尚未接入当前冻结合同的策略在查库、查路由前以 `PREPARATION_STALE` 拒绝。后续 E01-N1 至 N3 将以独立 NAV 合同接入，不借用 ETF 路由。

## 验证

## 剩余门禁

这只保证未接线的 NAV 不被误认作 ETF。净值事实冻结、费用与确认日执行、目标 Worker/DSA/客户端及真实来源均未完成；E01-N1 至 N4、C02/D02 与 AC15 保持未勾选。
