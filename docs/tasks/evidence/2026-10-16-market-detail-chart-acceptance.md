### 受控跨日、乱序与同日修订

在客户端详情 GET 上使用真实响应的副本，保持证券、口径及 V3 形状，并分别匹配已观测的窗口计划：90 根计划起点 `2025-07-27`，180 根计划起点 `2024-10-30`，终点均为 `2026-10-17`。响应的价格与指标按对应窗口同时返回，不写 Server 或 DSA。

| 场景 | 结果 |
| --- | --- |
| 前日缓存重开 | 空客户端先显示截至 10-15 的 60 根；确认关闭后重新打开，缓存先显示但仍发出一次 `refresh=1` 请求。返回 10-16 后，日期、价格 `4.236` 和 MA5 `4.2954` 正确更新 |
| 最新端失败/显式重试 | 实际指针拖动触发最新 GET，单次受控 503 后保留图表并显示失败；立即点击“重试”成功发出同窗刷新，不被 60 秒冷却阻止。进行中与冷却内的重复手势不增加有效请求 |
| 最新请求先发起、历史先返回 | 保持 90 根最新检查在途，再拖历史边界请求 180 根。先返回 90 个有效点的扩窗，再送达含不同末价 `4.336` 的旧 90 根窗口；旧响应未覆盖，新值仍 `4.236`，切换“全部已加载”后仍为 06-04～10-16，历史未截断 |
| 历史请求先发起 | 180 根扩窗在途时回到最新并拖动右边界，不新增独立最新请求；返回匹配计划的扩窗后显示正确末日、价格及历史。V3 通过窗口代次和在途保护处理这一路径，不恢复旧的两侧增量拼接 |
| 同日修订与完成状态 | 普通视图保持日期 10-16，将末价由 `4.236` 改为 `4.336`、MA5 改为 `4.3154`；客户端立即显示新值及“未收盘（当日未完成）”。再返回同日 complete，改为“已收盘”，不要求新增日期 |

两种发起顺序在真实全屏图表上执行指针手势；普通视图用于重开、重试与同日更新。此前宽窄屏、普通/全屏、历史失败、缺值、参数与取消场景沿用本文件的通过证据，固定 09-15→09-17 场景沿用既有 Dialog 集成测试。有效乱序段运行异常为 0。

首次乱序副本误用了 90 根计划起点，客户端拒绝 180 根响应并保留原图；该轮不计通过。修正为匹配计划后从空页面重新验收，结果以上表为准。测试结束清除全部 Fetch 拦截并重载页面，不留下合成行情缓存。
