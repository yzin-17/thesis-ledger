# AI 默认引用目标原子清除预案

用户已授权全部后续验收，按[实施 Task](../2026-10-21-ai-default-lifecycle-target.md)接续。当前默认全局修订 2、Provider 为 `lmstudio`，配置及完整保护基线重新读取并绑定计划指纹。

## 有界正常 API 操作

只使用 `PATCH /api/v1/ai/providers/lmstudio/enabled` 与 `PATCH /api/v1/ai/settings`。生命周期请求始终 `enabled=true`，与现有值一致，不停用、不重新激活来源、不改凭证/设置/模型/用途，也不创建合成就绪证明。现有保存服务先核对已存用途证据；若它不满足，保留拒绝，禁止运行测试来解锁。

1. 当前 Provider 修订、错误默认修订、明确清除标记：应 409，完整状态不变。
2. 当前 Provider 修订、不提供清除标记：应 409，完整状态不变。
3. 当前 Provider/默认双修订、明确清除标记：应 200，同一事务推进 Provider 时间并将默认两字段置空、默认修订 2→3。Provider 仍已启用；其他字段及密文摘要完全相同。
4. 正常设置 API 以修订 3 恢复原 Provider/模型：应 200，默认修订 3→4。不得伪造旧修订或旧时间。

若清除提交后响应或后续检查失败，读取精确状态，仅在仍满足“同一 Provider 仅修订时间改变、默认确为空且恰为原修订+1、其余完整保护相同”时，最多执行一次上述已授权恢复。遇到并发外部更改保留实际结果，不覆盖他人设置。正常流程恢复后不再重复恢复。

## 独立保护及验收范围

同一只读 SQL 语句读取全部配置摘要、自有被测原行的公开字段及密文摘要、排除该 ID 后的其他配置摘要、完整默认行及其总摘要。与完整目标保护绑定后，先精确检查每阶段允许变化，再仅将两个表的已验证元数据摘要归一用于全体比较。任何额外字段、原凭证、启停、业务或模型计数变化均失败。

预案允许的持久差异仅为正常 `ProviderConfig.lmstudio.updatedAt`、`AiRoutingSettings.global.revision/updatedAt`。原默认的 Provider/模型最终恢复；十二账户、十六政策路由及所有模型事实保持，不发连接、目录、生成或费用请求。Web 只读检查默认回显，取消后返回原模拟账户页。

目标原子清除与原 PostgreSQL 删除/停用/竞争、E3 Web 确认/取消证据分层组合；本叶没有实际停用或删除原用户配置，不据此宣称真实研究消费通过。真实模型暂停及 DG3 TODO 继续有效。
