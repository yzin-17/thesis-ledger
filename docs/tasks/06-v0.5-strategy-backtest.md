# V0.5：Strategy 与 Backtest

> 阶段目标：建立独立策略契约、A 股完整交易规则、样本外验证和可复现回测。

- [ ] T146：定义 Strategy 实体与版本模型
  - 涉及范围：包含 name、description、status、strategyVersion、schemaVersion、createdAt。
  - 完成条件：策略修改不会覆盖旧版本；BacktestResult 固定引用策略版本。
  - 验证方式：创建 v1→修改 v2→分别回测，确认结果引用正确。

- [ ] T147：定义 Strategy Schema：Universe
  - 涉及范围：支持显式 symbol 列表、ETF/股票集合、筛选器引用和日期有效性。
  - 完成条件：历史回测的 universe 可版本化，不静默使用今天成分。
  - 验证方式：用固定 3 标的 universe 回测并校验输入。

- [ ] T148：定义 Strategy Schema：Entry/Exit Signal
  - 涉及范围：支持指标/价格/组合条件表达，并与 Rule Engine 共享可复用表达式基础。
  - 完成条件：策略信号不绑定某个 Python 函数名。
  - 验证方式：序列化→反序列化后信号语义不变。

- [ ] T149：定义 Strategy Schema：StopLoss/TakeProfit
  - 涉及范围：将风控退出规则作为策略组成部分，与实时 RiskRule 区分执行上下文。
  - 完成条件：Backtest 可明确记录退出原因为 stop/takeprofit。
  - 验证方式：构造触发止损的价格序列验证 trade reason。

- [ ] T150：定义 Strategy Schema：Sizing
  - 涉及范围：支持固定金额、固定比例等基础仓位模型。
  - 完成条件：每笔订单数量可解释并遵守资金约束。
  - 验证方式：给定资金 100000、20% sizing 验证。

- [ ] T151：定义 Strategy Schema：Execution/Cost
  - 涉及范围：定义成交价模型、滑点、手续费、印花税、最小交易单位。
  - 完成条件：所有成本进入回测结果和交易明细。
  - 验证方式：关闭/开启成本模型比较结果差异。

- [ ] T152：定义 Strategy Schema：RiskConstraint/Benchmark
  - 涉及范围：支持单标的上限、现金下限等基本约束和基准指数。
  - 完成条件：Backtest 输出能记录约束拒单和 benchmark。
  - 验证方式：制造超仓请求验证被约束。

- [ ] T153：定义 Backtest Worker Contract
  - 涉及范围：统一 run/cancel/status/result 输入输出，使 DSA/Vibe/自研引擎可替换。
  - 完成条件：Investment OS 不依赖具体回测框架。
  - 验证方式：Mock Worker 与真实 Worker 通过同一 Contract 测试。

- [ ] T154：建立 Backtest Job 模型与队列
  - 涉及范围：支持 queued/running/succeeded/failed/cancelled、progress、startedAt、finishedAt。
  - 完成条件：长任务不阻塞 API；任务状态可查询。
  - 验证方式：启动多个任务，验证队列与状态。

- [ ] T155：实现 Backtest Cancellation
  - 涉及范围：支持取消排队/运行中的任务，并释放 Worker 资源。
  - 完成条件：取消后不会写入“成功”结果。
  - 验证方式：启动长任务后取消并核对状态和资源。

- [ ] T156：实现 A 股 T+1
  - 涉及范围：当天买入股票不可当天卖出；ETF 等品类按策略配置。
  - 完成条件：交易引擎拒绝非法 sell，并记录原因。
  - 验证方式：同日买卖股票 fixture 必须失败或延后。

- [ ] T157：实现涨跌停限制
  - 涉及范围：根据历史制度/配置判断不可成交价格和订单。
  - 完成条件：达到涨跌停时订单按 ExecutionModel 处理，不假设必成交。
  - 验证方式：构造涨停买入、跌停卖出场景。

- [ ] T158：实现停牌处理
  - 涉及范围：停牌日不生成可成交订单，价格/净值计算规则明确。
  - 完成条件：连续停牌不会凭空成交。
  - 验证方式：固定停牌日历 fixture 验证。

- [ ] T159：实现最小交易单位
  - 涉及范围：A 股按 100 股等规则取整，ETF/基金可按资产类型配置。
  - 完成条件：订单数量符合市场规则并记录 rounding。
  - 验证方式：150 股目标订单验证实际数量策略。

- [ ] T160：实现手续费、印花税和滑点
  - 涉及范围：费用模型可按市场/时间配置；卖出印花税等规则可版本化。
  - 完成条件：交易明细包含每类成本。
  - 验证方式：手工计算一笔买卖对账总成本。

- [ ] T161：实现复权、分红和除权除息处理
  - 涉及范围：区分价格序列调整与现金分红，避免收益双计。
  - 完成条件：历史公司行动与 Ledger/Market 语义一致。
  - 验证方式：用除权日 fixture 对账净值连续性。

- [ ] T162：定义 PIT Data Contract
  - 涉及范围：历史回测只允许读取当时已知数据，fundamental/news 等带 availableAt。
  - 完成条件：Worker 无法通过普通 API 获取未来数据。
  - 验证方式：构造未来财报发布时间案例，确认回测前日期不可见。

- [ ] T163：建立 Look-ahead Bias 测试
  - 涉及范围：为信号、指标、universe、财务数据设计未来数据注入测试。
  - 完成条件：已知作弊策略必须被测试检测。
  - 验证方式：运行故意使用 next-day close 的策略，测试失败。

- [ ] T164：实现 Universe Completeness 检查
  - 涉及范围：回测前验证所有预期标的和日期数据完整度。
  - 完成条件：不完整时 fail/warn 按配置，不静默缩小 universe。
  - 验证方式：删除一个 symbol 数据，确认任务不被误标成功。

- [ ] T165：标记 Survivorship Bias 风险
  - 涉及范围：当数据集无法提供退市/历史成分时，在结果中记录 limitation。
  - 完成条件：结果页面明确提示 survivorship coverage。
  - 验证方式：使用当前成分 universe 回测并检查 limitation。

- [ ] T166：实现 In-Sample / OOS 切分
  - 涉及范围：按时间切分训练/验证区间，防止用同一区间评价。
  - 完成条件：结果分别展示 IS/OOS 指标。
  - 验证方式：固定日期切分验证样本不重叠。

- [ ] T167：实现 Walk Forward
  - 涉及范围：支持滚动训练/验证窗口和多段结果聚合。
  - 完成条件：每个窗口参数、日期、结果可追溯。
  - 验证方式：运行至少 3 个窗口并验证时间推进。

- [ ] T168：实现 Parameter Experiment
  - 涉及范围：支持有限参数网格/实验队列和结果比较，不默认自动选最佳实盘策略。
  - 完成条件：每个参数组合对应独立 run。
  - 验证方式：2×3 参数组合应产生 6 个结果。

- [ ] T169：接入 Benchmark
  - 涉及范围：支持沪深300、中证500或对应 ETF 基准收益。
  - 完成条件：回测结果包含策略 vs benchmark 累计收益和超额收益。
  - 验证方式：固定 benchmark 数据核对差值。

- [ ] T170：接入 QuantStats Analytics Worker
  - 涉及范围：计算通用 period-based 指标和报告，保持与交易级指标分离。
  - 完成条件：Worker 可从收益序列生成结构化指标。
  - 验证方式：用固定 returns fixture 与 QuantStats 输出核对。

- [ ] T171：实现 Trade-based Metrics
  - 涉及范围：计算交易次数、逐笔胜率、盈亏比、平均持有期、换手率。
  - 完成条件：文档明确与 period-based win rate 区别。
  - 验证方式：用手工 4 笔交易 fixture 对账。

- [ ] T172：实现 Backtest Reproducibility Metadata
  - 涉及范围：保存 strategyVersion、schemaVersion、dataVersion、provider、engineVersion、parameters、costModel。
  - 完成条件：同一输入可重跑并定位结果差异。
  - 验证方式：重跑固定 fixture 比较关键 checksum。

- [ ] T173：实现 Strategy/Backtest UI
  - 涉及范围：支持策略列表、版本、编辑、启动、进度、结果、权益曲线、回撤、交易明细。
  - 完成条件：用户能从 UI 完成一次策略创建→回测→结果查看。
  - 验证方式：人工端到端验收。

- [ ] T174：建立 Backtest Regression Suite
  - 涉及范围：覆盖 T+1、涨跌停、停牌、成本、分红、PIT、OOS、Walk Forward。
  - 完成条件：核心交易规则变更导致结果漂移时 CI 可发现。
  - 验证方式：固定多组 expected result 并加入 CI。

- [ ] T175：完成 V0.5 文档与一致性 Review
  - 涉及范围：更新 Strategy Schema、交易规则、bias prevention、指标定义、已知数据限制。
  - 完成条件：AI 生成策略也必须走同一 Schema/Backtest Contract。
  - 验证方式：对照 Spec 全量 checklist 和随机重跑可复现验证。
