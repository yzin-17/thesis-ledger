# V0.4：完整风险中心

> 阶段目标：从简单提醒升级到统一 Rule Engine、组合风险、筹码规则和通知治理。

- [x] T120：定义通用 Rule Schema 与版本
  - 涉及范围：支持 ruleVersion、scope、condition tree、parameters、severity、enabled、effectiveAt。
  - 完成条件：规则修改产生新版本或审计记录，历史事件可追溯原规则版本。
  - 验证方式：创建规则→修改→触发，确认事件引用正确版本。

- [x] T121：实现 Rule Scope
  - 涉及范围：支持 security/account/portfolio 三种上下文和对应 target 解析。
  - 完成条件：规则只加载必要数据；跨 scope 非法字段被拒绝。
  - 验证方式：分别执行三种 scope 的 fixture。

- [x] T122：实现 Rule Evaluation Context
  - 涉及范围：统一提供 Quote、Position、Portfolio、Indicators、Chip、Performance 和 marketTime。
  - 完成条件：规则实现不自行访问数据库/Provider；context 记录 dataQuality。
  - 验证方式：用 Mock Context 驱动规则单测，无外部依赖。

- [x] T123：实现 Rule Audit Log
  - 涉及范围：记录创建、修改、启停、删除、人工测试和执行错误。
  - 完成条件：可查询谁/何时/如何改变规则；个人版至少记录 actor=local-user/system。
  - 验证方式：修改一条规则并核对 audit entries。

- [x] T124：实现 Trailing Stop
  - 涉及范围：基于持有期间高点或用户指定参考高点计算移动止损。
  - 完成条件：高点更新与触发顺序确定；停牌/缺行情不误更新。
  - 验证方式：构造价格序列 100→120→110→105 验证。

- [x] T125：实现 Drawdown Rule
  - 涉及范围：支持 security/account/portfolio 从峰值回撤超过阈值。
  - 完成条件：使用统一历史/快照口径；无足够历史时返回 unavailable。
  - 验证方式：用已知净值序列验证最大/当前回撤。

- [x] T126：实现 MA Rule
  - 涉及范围：支持 price/close 与 MA、MA 交叉等基础条件。
  - 完成条件：指标参数和数据时间进入 RiskEvent context。
  - 验证方式：测试上穿、下穿、相等、指标缺失。

- [x] T127：实现 RSI Rule
  - 涉及范围：支持 RSI 超买/超卖和自定义阈值。
  - 完成条件：RSI 值由 Indicator Engine 提供，Rule 仅判断。
  - 验证方式：固定指标值测试边界。

- [x] T128：实现 MACD Rule
  - 涉及范围：支持 DIF/DEA 交叉或 histogram 阈值等基础条件。
  - 完成条件：条件表达与 Indicator Contract 解耦。
  - 验证方式：用固定 MACD 序列验证触发点。

- [x] T129：实现 ATR / 波动规则
  - 涉及范围：支持 ATR 或 ATR% 超阈值判断高波动。
  - 完成条件：能用于个股和组合高波动资产占比计算。
  - 验证方式：固定 ATR/price fixture 验证。

- [x] T130：实现成交量异常规则
  - 涉及范围：支持 volume/均量倍数等简单异常判断。
  - 完成条件：数据不足时不误报。
  - 验证方式：构造 0.5x/2x/5x 均量场景。

- [x] T131：实现 Chip Peak Rule
  - 涉及范围：支持价格相对主筹码峰、跌破/突破主峰判断。
  - 完成条件：事件记录 chip engineVersion、calculatedAt。
  - 验证方式：固定 ChipDistribution + price 测试。

- [x] T132：实现 Chip Profit Ratio / Concentration Rule
  - 涉及范围：支持获利比例、集中度超阈值条件。
  - 完成条件：输入必须来自同一日期/数据版本或标记不可比较。
  - 验证方式：构造不同日期数据验证时间一致性检查。

- [x] T133：实现 Chip Peak Migration Rule
  - 涉及范围：比较连续两个/多个筹码快照主峰移动方向和幅度。
  - 完成条件：可识别明显上移/下移；数据缺口明确标记。
  - 验证方式：用三日 fixture 验证。

- [x] T134：实现 Sector Concentration
  - 涉及范围：基于 Asset Master 行业分类计算行业权重。
  - 完成条件：覆盖率不足时返回 coverage 和 missing symbols。
  - 验证方式：构造多行业组合并核对 top sector。

- [x] T135：实现 Asset Type Concentration
  - 涉及范围：计算股票/ETF/基金/现金等资产类别集中度。
  - 完成条件：可设置规则阈值并触发事件。
  - 验证方式：构造 90% 股票组合测试。

- [x] T136：实现 High Volatility Exposure
  - 涉及范围：按 ATR/历史波动率定义高波动资产并汇总组合权重。
  - 完成条件：阈值和窗口可配置；缺数据资产不默认算低风险。
  - 验证方式：固定 5 个资产的 volatility fixture 验证。

- [x] T137：实现 Portfolio Correlation Risk
  - 涉及范围：计算持仓收益相关性或相关性暴露，处理历史长度不足。
  - 完成条件：输出 top correlated pairs 和 coverage，不夸大精度。
  - 验证方式：用高相关/低相关人工序列验证。

- [x] T138：实现 Notification Severity Routing
  - 涉及范围：按 info/warning/error/critical 将事件路由到指定渠道。
  - 完成条件：不同 severity 可配置不同 Provider；未配置有明确 fallback。
  - 验证方式：发送四级测试事件核对渠道。

- [x] T139：实现 Quiet Hours
  - 涉及范围：按 IANA timezone 配置静默时段，定义 critical 是否穿透。
  - 完成条件：跨午夜时段正确；延迟/抑制策略有记录。
  - 验证方式：测试 22:00-08:00 跨午夜。

- [x] T140：实现 Daily Digest
  - 涉及范围：聚合低优先级事件形成日报摘要，避免碎片通知。
  - 完成条件：事件仍保留单条记录，digest 仅是发送策略。
  - 验证方式：触发多条 info/warning 后只收到约定摘要。

- [x] T141：实现通知重试与最终失败状态
  - 涉及范围：对可重试错误按 backoff 重试，永久错误不无限重试。
  - 完成条件：DeliveryResult 记录每次 attempt 和最终状态。
  - 验证方式：模拟 500→500→200 与 400 两种场景。

- [x] T142：实现 Risk Center UI
  - 涉及范围：包括规则列表、编辑器、当前风险、历史事件、组合风险摘要。
  - 完成条件：用户可查看规则版本、触发上下文和数据时间。
  - 验证方式：人工完成新建→测试→触发→查看历史。

- [x] T143：建立 Rule Engine 回归测试
  - 涉及范围：对所有 V0.4 规则建立固定 Context/Expected Event。
  - 完成条件：规则引擎重构不会改变既有触发结果。
  - 验证方式：CI 运行全套规则 fixture。

- [x] T144：更新风控与通知文档
  - 涉及范围：记录规则语义、组合风险、筹码估算边界、通知治理和非交易 SLA。
  - 完成条件：用户明确知道提醒不等于交易执行保证。
  - 验证方式：文档 Review 并与 UI 文案核对。

- [x] T145：完成 V0.4 一致性 Review
  - 涉及范围：检查 RiskRule→Evaluation→RiskEvent→Notification→Audit 全链路和所有数值来源。
  - 完成条件：AI/Notification 不重复计算规则；所有事件可追溯 ruleVersion/data timestamp。
  - 验证方式：运行跨模块 E2E 和架构检查。
