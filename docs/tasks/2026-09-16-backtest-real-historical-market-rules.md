# 回测真实历史市场规则数据源实施任务

对应 Spec：[`回测真实历史市场规则数据源`](../specs/2026-09-16-backtest-real-historical-market-rules.md)

> 状态：规划完成；T1 可启动，T2–T5 等待首个真实来源、授权条件和实际历史覆盖

## 任务

- [ ] **T1：确认首个真实来源与有界范围**
  - 覆盖验收标准：AC1。
  - 依赖：无。
  - 涉及范围：只读核对候选来源的字段、历史深度、许可、稳定修订标识、可用时间及故障行为；选定首个市场、资产、标的和日期区间。
  - 完成条件：形成可复核的来源清单与样本响应；明确允许冻结/持久化的数据范围；不能用当前接口可访问代替历史授权证明。
  - 验证方式：来源文档、许可条件、真实样本和缺失样本交叉核对，记录获取时间与修订标识。

- [ ] **T2：收敛版本化规则契约与区间语义**
  - 覆盖验收标准：AC2、AC7 的兼容契约。
  - 依赖：T1 的来源字段和实际变更样本。
  - 涉及范围：`packages/schemas`、`packages/domain` 及相关 Spec；确定单段是否足够，必要时增加有限分段。明确规则只覆盖执行区间还是包含预热区间。
  - 完成条件：契约表达首个来源的真实变化；身份、版本、区间、缺口、重叠和未来信息具有确定失败语义；旧 Snapshot 不被静默升级。
  - 验证方式：Schema/Domain 合法样本、边界日期、缺口/重叠、错误身份、未来事实和旧版本兼容测试。

- [ ] **T3：实现 DSA 历史市场规则 Provider**
  - 覆盖验收标准：AC3、AC6 的 Provider 断言。
  - 依赖：T1、T2。
  - 涉及范围：DSA instrument-facts 的直接 Provider 与规范化层；不扩展到首个范围以外的市场矩阵。
  - 完成条件：真实来源完整时返回稳定版本的规则事实；来源不足、超时或许可范围外返回具体 `missingInputs`，不使用 fixture 或当前值回填历史。
  - 验证方式：DSA service/HTTP Contract、真实样本对账、来源异常和历史覆盖不足测试。

- [ ] **T4：接入 Snapshot 与无模型运行**
  - 覆盖验收标准：AC4、AC6、AC7。
  - 依赖：T2、T3。
  - 涉及范围：Server DsaClient、Snapshot Builder、规则冻结与 Runner 兼容；不修改真实 Ledger/Portfolio/Trade/Journal。
  - 完成条件：无模型运行只在规则完整且适用时进入队列；规则与来源进入 Snapshot 哈希；失败保持结构化错误；显式研究模型路径不回归。
  - 验证方式：Server 定向集成、Snapshot 哈希/重放、旧快照兼容、规则缺失与冲突失败测试。

- [ ] **T5：目标运行态验收**
  - 覆盖验收标准：AC5–AC7。
  - 依赖：T4；目标 DSA、Server、Worker、数据库、队列和共享 Snapshot 已更新。
  - 涉及范围：一个 T1 确认的真实历史场景，以及相同输入重放和一次规则缺失故障恢复。
  - 完成条件：无模型真实运行成功并披露来源；相同 Snapshot 重放一致；缺失规则稳定失败且恢复后可再次运行；前后真实账户域指纹不变。
  - 验证方式：记录镜像/源码修订、runId、snapshotId、规则来源/版本/区间、结果 checksum、账户指纹和故障恢复证据。
