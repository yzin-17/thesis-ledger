# 策略定义统一与双向编辑实施任务

当前阶段为方案合并。验收以[规格](../specs/2026-11-13-strategy-definition-authoring.md)为准。腾讯 EMA 方向修复、原历史与修正版的逐笔核对已有[独立证据](../archive/evidence/2026-11-12-strategy-cross-direction.md)。现行实现与规划分开记录。以下清单以表达覆盖、模型直接生成和人工文字确认排序。

## 第一步：证明目标想法能用配置表达

- [x] 核对现有数值、布尔、风控和精简探索输出节点；用本地构建的生成 Schema 探查 5 个代表样例。两份直接表达的合法配置通过，三个缺少对应原语的探针被拒。核对源码后把缺口及限制写入规格。该步仅验证样例与结构。
- [x] 用两份参数、输出线都不同的 MACD 配置复现价格研究摘要回读碰撞，结果见规格。
- [x] 已盘点本地 18 个从零探索实验中的 13 条存量候选，交叉核对提案、条件与风控。补齐 42 个规则场景、15 组语言／数据／执行／回读能力及相应验收。已用编译产物核对 17 项结构探针及 2 项探索边界对照。见[规则案例与能力清单](../specs/2026-11-13-strategy-rule-capabilities.md)。
- [ ] **数值与时间窗口（C01～C04、C14、C15）。** 先完成 R09～R14 的单标的闭环；再按 R15～R20 增加需状态或多输出的规则。同步维护模型的完整／精简输入说明、确定性算子与可辨认的文字。用 102% 边界、排除当根的前高及“五中取三”对照连续三根。
- [ ] **交易生命周期（C05～C09、C15）。** 按 R21、R23、R26、R29、R31 依次验证实际平仓后冷却、追踪止损、风险预算、分批减仓和定时调仓。明确阶段依赖、风险与普通信号冲突、拒单／部分成交和重放行为。
- [ ] **探索、执行和数据边界（C10～C13）。** 先把 R32 的同标的多周期从模型输出贯通到冻结与执行。另行评估只读参考资产、委托撮合、时点数据及组合经济模型后，分别排期；把未交付能力作为可解释的探索缺口。
- [ ] **模型直接生成与人工回读。** 增加“无法精确表达”的探索结果，保留模型原规则和缺口位置，与可回测配置区分。用 R34 验证模型无需用市价单冒充限价单。在已有采纳步骤对齐最终规则、实验固定字段和模型的研究理由。
- [ ] 对纳入范围的缺口更新策略 Schema、完整及精简模型输出合同、引擎求值、编辑器和文字展示。用固定输入验证每个原语的时点、单位、预热及边界行为。
- [ ] 通过正式探索入口让目标模型直接生成配置。对有表达能力、确实缺节点、模型遗漏约束三种情况分别记录；把研究理由与最终配置展开的中文并列，人工评审语义覆盖。
- [ ] 用腾讯 EMA 和两组 MACD 完成人工回读验收。核对人能看清交易方向、指标参数与输出线，从现有采纳步骤进入保存和回测。调整旧中文匹配检查的阻断职责。

## 随后贯通编辑、确认与执行

- [ ] 盘点手动保存、自然语言确认、探索候选、参数优化、采纳、详情、版本升级、准备及 Worker 的定义输入与输出，特别标注保存前的价格投影和固定 Schema 2 的门禁。把协议版本、业务版本、运行版本和经济模型的术语及取舍补入领域文档和 ADR。
- [ ] 复用现有规则树与显示实现，先打通股票日线「收盘价上穿 EMA20 买、下穿卖」。在隔离样本实现可视录入、JSON 修改、规则回读、确定性摘要、保存、准备、Worker 回测。确认 JSON 未应用的错误不会导致误保存旧草稿。以股票规则形成纵向样例，再切换全部入口。
- [ ] 建立与业务求值实现独立的预期数据。测试正确方向、单独交换操作数、交换操作数同时反转方向、相等边界、持续为真、逆势意图。使用已有腾讯冻结快照对照首次进出日期、原因和全窗交易，不改原业务数据。

- [ ] 自然语言编写复用 Schema 和文字回读，沿用现有确认流程。用同义表达、正反交叉和未明确均线的样例做人工对照；模型输出、程序技术错误和人工修改分别留证。

## 第二步：统一协议生产与消费

- [ ] Schemas 补齐新增的价格口径和读写校验。Domain 承接确定性的树操作与求值。以同一上下文验证旧定义升级后来源、引用、精度和求值结果。对不同运行使用过不同取价口径的旧定义分别验证 `run` 冻结。
- [ ] 打通 Schema 3 的基金净值路径，验证保存、运行准备、冻结、投递、Worker 领取、申赎与费用、结果读取。分别核验股票/ETF 和基金，记录两类来源与经济模型的限制。
- [ ] 手动、AI 编写、实验探索和采纳接入同一正式写入校验。AI 确认和采纳直接复用所选定义，参数优化检验授权路径。用趋势和逆势候选、复杂组合、能力缺口以及一次仅授权周期的修改验证各入口。
- [ ] 按可转换的规则和执行方式适配风险应用、版本选择、详情和读取。确认旧客户端错误可操作、旧版本能够读取、历史任务/快照/结果摘要保持一致，再启用新写入门禁。

## 第三步：补齐双端编辑与验收

- [ ] Desktop、Mobile 复用草稿、节点描述与校验结果。逐组补齐来源、嵌套条件与指标、仓位、风控、执行、费用和基准。验证来源重命名、显式同步、未知节点、多来源、MACD 输出和高精度数值。
- [ ] 覆盖双向编辑、错误定位、未应用文本、离开确认、保存失败恢复。Desktop 覆盖 1440、1024、768、390 宽度；Mobile 验证键盘、长条件树、草稿恢复和导航。
- [ ] 按定向测试、相关包测试与构建、项目门禁、真实运行态顺序留证。用隔离样本执行写入，核对请求、不可变版本、冻结输入、信号和结果。部署复用 infra 正式入口，分别记录浏览器、移动端、队列/Worker 与历史重放证据。已有全量测试失败按本轮范围单列状态。

写集优先限于 Schemas/Domain、Server 策略编写/优化/回测及对应消费者、Desktop/Mobile 策略编辑与详情、相关验收文件。原策略和实验的历史补丁以既有记录为准。本项验收不调整腾讯 EMA 的交易参数。
