# 竞技场条件委托与成交保护实施任务

产品范围、规则清单和验收样例见[产品规格](../specs/2026-11-13-arena-contingent-orders.md)。本次完成事故核查和文档细化。竞技场当前运行的是独立委托与持仓 OCO，以下能力按各阶段的执行门禁开放。

## 已核实

- [x] 对照原始模型响应、请求审计、冻结账户和运行时模块。AAPL 案例的父单分组被拒，空仓去分组仍报 `insufficient_position`，单独父单可挂。三组结果见规格第 1 节。
- [x] 检索本地 22 个研究周期，可读的 12 份决策中有两份包含订单。TOPT 原文写止损，实际仅有价格研究预约，历史失败字段为日期。保留这两种不同的模型输出作为固定回归样本。
- [x] 核对当前 Schema、整笔成交、OCO 预留、成交预约、实时到期日及回放入口。区分已观察到的两份决策与扩展设计样例。

## 阶段一　父单整笔成交后自动激活单一止损

- [ ] **合同与状态。** 确定版本及字段，为独立委托、待激活子单、有效保护和终态分配可持久化的身份。区分父／子期限、未成交撤单、成交但等待可卖。保留旧账户、旧决策和旧 OCO 的读取与回放。
- [ ] **执行。** 提交即保存整份计划，只预留入场现金。复用现有账户版本和事务锁；一次事务落账入场成交及保护，等待下一份有效市场证据撮合。证明零成交零卖出，不因子单误占老仓，重试幂等。
- [ ] **模型与人工查看。** 生成端按当前环境可执行的合同直接输出；更新相关系统提示、示例和精确错误字段。由正式配置生成中文确认，独立呈现模型摘要、自动委托、研究预约、父子关联、有效期及可保护数量。TOPT 样本只生成价格预约时，确认页应明确显示自动卖单为零。
- [ ] **验收。** 用 359.50／355／27 的冻结例进行领域、并发仓储、实时与回放对照。覆盖未成交、全成、撤销、到期、无法出售、报价过期或跳空、模型不再运行、重复领取及进程恢复。开发运行态核对整份计划与账本的因果顺序。变化前后的账号快照与模型调用计数可对照。

## 阶段二　附属 OCO 与部分成交保护

- [ ] 先将已有 OCO 退出组挂到父单。共享预留、成交取消另一腿；回放和实时结果一致。
- [ ] 明确成交量／流动性的数据来源、单次可成交量及取整规则。增加累计成交量、剩余量、每次成交标识和计划退出量，再开放 `on_each_fill`。整笔成交行情回放不能作为“已支持部分成交”的验收。
- [ ] 确定独立退出与其他计划减仓的份额分配、撤入场余量／撤保护／取消整计划三个操作，以及退出已发生时入场余量的处置。用 10 + 17、重复事件、先卖 4 再撤余、到期与并发成交验证数量守恒。
- [ ] 前台逐笔显示目标数量、已成交、余量、已保护、受交收限制及已退出的份额；跨交易日有效期和停止保护的原因可核对。

## 阶段三　动态止损与分批建仓／退出

- [ ] 移动止损显式选择价格来源和参考点、高水位更新时机、百分比／金额、精度和保本触发条件。保存恢复后的高水位，比较实时与回放的保护线。
- [ ] 分批建仓区分并行挂单与前序成交后才挂下一批。为每批指定预算、数量、终止条件和退出归属，复核和平行订单竞争时的资金上限。
- [ ] 分批退出指定每一档比例的分母、手数舍入、尾差和优先级。例如 27 股卖出 9 股后，剩余止损为 18 股。止盈与保护共享的数量不能重复预留。
- [ ] 明确“首次满足才开仓、复位后再入场”属于策略信号语义，持有计划内父子单归属属于订单执行语义。按[规则能力清单](../specs/2026-11-13-strategy-rule-capabilities.md)与此协议分别验收。

## 开放能力前的模型回归和部署验收

- [ ] 对同标的、同数量构造最小对照（到价卖出／到价研究、全成激活／每次成交、撤余／撤保护、立即挂多笔／前批成交才挂）。从原话直接生成，保存模型版本与逐例结果，人工对照配置回读，再以事件序列核实执行。分开记录合同无法表达、模型选错、依赖数据缺失及引擎执行偏差。
- [ ] 先定向测试，再做对应包的构建与仓库门禁。按实际持久化变更验证兼容、进程重启及回放；在开发运行态用独立模拟数据核对账户、委托及展示。没有通过的能力继续标记为计划中。
