# V0.3：Ledger、Performance 与资产配置

> 阶段目标：让 Ledger 成为唯一资产事实源，Position/Snapshot 都可重建，并加入正确收益计算。

- [ ] T095：定义 Ledger Event Schema
  - 涉及范围：覆盖 BUY/SELL/DIVIDEND/FEE/TAX/INTEREST/TRANSFER_IN/TRANSFER_OUT/CASH_DEPOSIT/CASH_WITHDRAW/BONUS/SPLIT/MERGE/ADJUSTMENT。
  - 完成条件：每类事件有必填字段、币种、时间、source、externalUid 和 note 规则。
  - 验证方式：Schema 单测覆盖所有事件类型和非法字段组合。

- [ ] T096：建立 Ledger 数据表与索引
  - 涉及范围：支持 account、symbol、eventTime、externalUid、source 查询和幂等约束。
  - 完成条件：Migration 可从 V0.2 平滑升级；externalUid 重复被拒绝。
  - 验证方式：迁移现有测试库并插入每类事件。

- [ ] T097：实现 BUY/SELL Ledger 写入
  - 涉及范围：支持数量、价格、fee、tax、currency，SELL 做持仓可用数量检查。
  - 完成条件：所有新交易先写 Ledger，不直接改 Position。
  - 验证方式：测试买入→卖出→超卖三种场景。

- [ ] T098：实现 Cash Ledger 事件
  - 涉及范围：处理充值、提现、转入、转出、利息等外部/内部现金流语义。
  - 完成条件：现金余额可仅由 Ledger 重算。
  - 验证方式：从零执行一组 cash events，核对余额。

- [ ] T099：实现 Dividend/Fee/Tax 事件
  - 涉及范围：明确股息、手续费、税费对现金、收益和成本的影响。
  - 完成条件：Performance 能区分费用税费而不重复计入交易价格。
  - 验证方式：构造含股息/手续费/印花税的交易链手工对账。

- [ ] T100：实现 Corporate Action
  - 涉及范围：支持 BONUS、SPLIT、MERGE 等对数量/成本基准的调整。
  - 完成条件：拆股/合股后总成本语义符合规则；事件保留原始记录。
  - 验证方式：使用送股/拆股 fixture 验证数量与平均成本。

- [ ] T101：实现 Adjustment 受控修正
  - 涉及范围：为历史缺失/导入纠错提供 Adjustment，要求 reason、audit metadata。
  - 完成条件：Adjustment 不可无理由创建；UI 明确与真实交易区分。
  - 验证方式：API 测试无 reason 失败、有 reason 成功且进入审计。

- [ ] T102：实现 Ledger 幂等导入
  - 涉及范围：基于 externalUid/source/account 或稳定 fingerprint 避免重复导入。
  - 完成条件：同一券商流水/截图转换重复执行不会重复记账。
  - 验证方式：同一批事件导入两次，第二次新增 0 条。

- [ ] T103：实现 AVG Cost Engine
  - 涉及范围：按事件顺序计算平均成本、剩余数量、实现收益。
  - 完成条件：结果可从任意时间点重放，精度和舍入规则固定。
  - 验证方式：与手工计算 fixture 对比 quantity/cost/realizedPnL。

- [ ] T104：实现 FIFO Cost Engine
  - 涉及范围：维护 lot，SELL 按先进先出消耗，计算 realizedPnL。
  - 完成条件：可按账户切换 costMethod；同一 Ledger 产生不同但可解释结果。
  - 验证方式：用三次买入两次卖出的 fixture 验证 lot 消耗。

- [ ] T105：实现 Ledger → Position Projection
  - 涉及范围：从 Ledger 派生当前 Position，不将 Position 视为可独立编辑事实。
  - 完成条件：清空 Position 表后可完全 rebuild；投影与增量更新结果一致。
  - 验证方式：运行 full rebuild 和 incremental 两种路径比较 checksum。

- [ ] T106：实现 Portfolio Snapshot
  - 涉及范围：按交易日/时间保存账户现金、市值、成本、PnL、持仓摘要和 dataQuality。
  - 完成条件：Snapshot 仅作历史/性能优化，可由 Ledger+Market 重建。
  - 验证方式：删除一日 Snapshot 后执行 rebuild，结果一致。

- [ ] T107：迁移 V0.1 Position 到 Ledger
  - 涉及范围：为现有手工/截图 Position 生成 migration opening balance/adjustment 或可审计初始事件。
  - 完成条件：迁移前后数量、成本、账户总资产在容差内一致。
  - 验证方式：对 V0.1 fixture 库迁移并生成差异报告。

- [ ] T108：升级 Screenshot Commit 为 Ledger 写入
  - 涉及范围：截图审核结果不再直接写 Position，而生成可审计的 Ledger/Opening Adjustment 事件。
  - 完成条件：导入后 Position 由投影刷新；rollback 通过撤销/补偿事件实现。
  - 验证方式：执行截图导入→检查 Ledger→重建 Position。

- [ ] T109：实现 Portfolio History
  - 涉及范围：按 Snapshot/重建结果提供历史总资产、现金、持仓市值和收益曲线。
  - 完成条件：支持 Portfolio/Account 级时间区间查询。
  - 验证方式：查询一个月 fixture 并核对每日点数。

- [ ] T110：实现 TTWROR
  - 涉及范围：正确处理外部现金流分段，计算时间加权收益。
  - 完成条件：现金充值/提现不会伪造投资收益；公式和精度有文档。
  - 验证方式：使用手工可验证案例或第三方标准结果对账。

- [ ] T111：实现 XIRR
  - 涉及范围：基于带日期现金流计算 money-weighted return，处理无解和多解情况。
  - 完成条件：API 返回 XIRR 或明确不可计算原因。
  - 验证方式：使用已知 Excel/XIRR 案例交叉验证。

- [ ] T112：实现 Security/Account/Portfolio 多层 Performance
  - 涉及范围：统一累计收益、实现/未实现收益、TTWROR/XIRR 可用范围。
  - 完成条件：三个层级语义一致且不会混用外部现金流。
  - 验证方式：同一 fixture 从 security 聚合到 account/portfolio 核对。

- [ ] T113：实现 Asset Allocation
  - 涉及范围：按 assetType、account、sector 等维度计算权重。
  - 完成条件：Dashboard 可显示股票/ETF/基金/现金及账户分布。
  - 验证方式：构造多资产 fixture，权重合计约 100%。

- [ ] T114：实现 Target Allocation
  - 涉及范围：允许用户为分类/资产设置目标权重并校验总和。
  - 完成条件：目标配置可版本化；无效总权重被提示。
  - 验证方式：测试总和 100%、超过 100%、缺项三种配置。

- [ ] T115：实现 Rebalance Gap
  - 涉及范围：计算当前权重与目标权重差值及对应金额，仅提供建议不自动下单。
  - 完成条件：结果区分需要增配/减配和数据不完整。
  - 验证方式：用 60/40 目标与实际 70/30 fixture 核对。

- [ ] T116：实现 Performance Dashboard
  - 涉及范围：Desktop 展示历史净值、TTWROR、XIRR、资产配置和 Rebalance Gap。
  - 完成条件：可切换 Portfolio/Account；指标有定义提示。
  - 验证方式：用固定历史 fixture 做 UI 验收。

- [ ] T117：建立 Ledger/Performance 回归测试集
  - 涉及范围：覆盖交易、费用、税、股息、转账、拆股、现金流、AVG/FIFO、TTWROR、XIRR。
  - 完成条件：每次变更可检测收益计算漂移。
  - 验证方式：保存 expected result 并在 CI 运行。

- [ ] T118：更新 Ledger 与收益文档
  - 涉及范围：解释 Ledger=事实、Position=投影、Snapshot=缓存，以及收益指标语义。
  - 完成条件：用户和开发者能理解为何截图导入也最终进入 Ledger。
  - 验证方式：文档 Review + 示例数据从头计算得到相同结果。

- [ ] T119：完成 V0.3 一致性 Review
  - 涉及范围：检查所有写持仓路径是否都已经转为 Ledger；移除或封禁旧 Position 直接写 API。
  - 完成条件：代码搜索无正式业务直接写 Position 的路径，migration/admin 例外有注释。
  - 验证方式：运行重建测试：删除 Position/Snapshot 后从 Ledger 恢复。
