# V0.2：数据稳定与 Provider 框架

> 阶段目标：让免费行情可监控、可降级、可校验、可落库，避免静默缺数据。

- [ ] T071：定义 MarketDataProvider Interface
  - 涉及范围：统一 quote、bars、asset、fundNav、fundamentals 等能力，并定义 capability discovery。
  - 完成条件：业务层只依赖 Provider Interface；新增 Provider 不改 Portfolio/Risk。
  - 验证方式：实现 Mock Provider + DSA Provider，通过同一测试套件。

- [ ] T072：建立 Provider Capability Registry
  - 涉及范围：记录每个 Provider 支持的市场、资产、timeframe、实时/历史/财务能力和限制。
  - 完成条件：运行时可查询 capability matrix；不支持能力不会被错误路由。
  - 验证方式：对至少两个 Provider 执行 capability 查询和拒绝测试。

- [ ] T073：实现 Provider Priority 与 Routing
  - 涉及范围：按 capability/市场/资产类型选择 Provider，并允许配置优先级。
  - 完成条件：同一请求可根据配置切换主 Provider。
  - 验证方式：修改配置后无需改代码即可切换 Quote 来源。

- [ ] T074：实现 Fallback Chain
  - 涉及范围：主 Provider 超时、失败或返回无效结果时自动切备用。
  - 完成条件：Fallback 次序可追踪；返回结果包含实际 provider 与 fallback chain。
  - 验证方式：模拟主源失败，确认备用成功且 metadata 正确。

- [ ] T075：实现 Partial Result Fallback
  - 涉及范围：批量请求仅返回部分 symbol 时，对缺失部分继续调用备用源而非缩小 universe。
  - 完成条件：最终结果明确标识 completed/partial 和缺失列表。
  - 验证方式：请求 20 个 symbol，模拟主源缺 5 个，验证备用补齐。

- [ ] T076：实现 Completeness Check
  - 涉及范围：对 universe、批量 Quote、历史 Bars 做期望数量/标的集合校验。
  - 完成条件：不完整结果不能被当作完整数据进入回测或组合分析。
  - 验证方式：构造缺失 1 个 symbol 的结果，确认被标记 partial 并触发策略。

- [ ] T077：统一 Freshness 模型
  - 涉及范围：定义 marketTime、fetchedAt、age、expectedFreshness、staleReason。
  - 完成条件：Quote/Bar/Indicator/Chip 都能表达数据陈旧状态。
  - 验证方式：模拟盘中旧报价、收盘后日线，验证 stale 判定差异。

- [ ] T078：实现 Provider Health State
  - 涉及范围：聚合成功率、延迟、错误类型形成 healthy/degraded/down。
  - 完成条件：Health 状态可供路由和 UI 使用。
  - 验证方式：模拟 30%/100% 失败率并验证状态迁移。

- [ ] T079：实现 Provider Health Monitor
  - 涉及范围：定时探测关键 Provider，记录延迟和错误；避免探测本身造成限流。
  - 完成条件：有健康历史和最近状态；异常可进入系统告警。
  - 验证方式：停止一个 Provider，确认 monitor 检测并恢复后自动回 healthy。

- [ ] T080：实现 Quote 数据校验
  - 涉及范围：校验价格非负、涨跌幅合理、时间有效、成交量/额类型和市场状态。
  - 完成条件：无效 Quote 不直接覆盖最新有效缓存。
  - 验证方式：构造负价格、未来时间、极端异常样例测试。

- [ ] T081：实现 Bar 数据校验
  - 涉及范围：校验 OHLC 关系、时间排序、重复 timestamp、缺失交易日和 volume/amount。
  - 完成条件：非法 Bar 被隔离并记录 data quality issue。
  - 验证方式：使用乱序、重复、high<low fixture 验证。

- [ ] T082：实现多 Provider 对账
  - 涉及范围：对重要字段抽样比较主备源差异，记录价差/缺失/时间差。
  - 完成条件：可配置容差，超限产生 data quality event。
  - 验证方式：用 Mock 制造 5% 价格偏差确认告警。

- [ ] T083：实现请求超时、重试、限流和熔断
  - 涉及范围：按 Provider 配置 timeout/retry/rate limit/circuit breaker，避免雪崩。
  - 完成条件：连续故障会打开熔断；恢复后半开探测。
  - 验证方式：自动测试失败阈值、半开和恢复。

- [ ] T084：建立 Redis 行情缓存
  - 涉及范围：设计 Quote/最新 Bar/Indicator cache key 与 TTL；缓存值包含数据来源和时间。
  - 完成条件：重复请求优先命中缓存；陈旧值不会冒充新鲜数据。
  - 验证方式：对同一 Quote 连续请求并检查 Provider 调用次数和 TTL。

- [ ] T085：建立 Asset Master 数据表
  - 涉及范围：长期保存 symbol、name、market、assetType、上市状态、行业等基础元数据。
  - 完成条件：Provider 返回的标的先标准化到 Asset Master。
  - 验证方式：导入一批 A 股/ETF，验证唯一性和名称更新。

- [ ] T086：建立 Daily Bar 落库
  - 涉及范围：保存日 K、provider、adjustment、version，并实现幂等 upsert。
  - 完成条件：重复同步不产生重复行；数据来源可追溯。
  - 验证方式：同一区间同步两次，行数不增长，值一致。

- [ ] T087：建立 Minute Bar 落库
  - 涉及范围：保存 V0.2 起新增的分钟历史，按分区/索引考虑长期增长。
  - 完成条件：1m 数据可按 symbol+time range 查询；重复落库幂等。
  - 验证方式：写入大量 fixture 后检查查询计划和重复约束。

- [ ] T088：实现 Trading Calendar
  - 涉及范围：维护 A 股交易日、休市、特殊交易状态接口。
  - 完成条件：数据同步、自动化、回测使用同一日历。
  - 验证方式：测试周末、法定休市和普通交易日。

- [ ] T089：实现历史 Backfill
  - 涉及范围：支持按 symbol/timeframe/range 批量补历史数据，有进度、重试、幂等。
  - 完成条件：中断后可继续，不重复写已完成区间。
  - 验证方式：运行一段历史回填，中途终止后恢复并核对完整性。

- [ ] T090：实现增量行情同步
  - 涉及范围：根据最新已保存时间只获取缺失区间；处理数据源修订。
  - 完成条件：每日同步不会重复抓全量历史；可强制重刷指定区间。
  - 验证方式：连续两天模拟同步并统计请求区间。

- [ ] T091：建立 Data Quality Issue 模型与 UI
  - 涉及范围：记录 provider、symbol、issueType、severity、raw summary、detectedAt、resolvedAt。
  - 完成条件：用户可看到数据缺失/异常而不是静默使用。
  - 验证方式：制造一条 Quote/Bar 异常，确认 Dashboard/管理页可见。

- [ ] T092：完成 V0.2 数据可靠性 E2E
  - 涉及范围：覆盖主源失败→备用源→落库→缓存→健康状态→data quality 展示。
  - 完成条件：核心链路在一个 Provider 不可用时仍能服务且正确标注来源。
  - 验证方式：运行故障注入脚本并通过验收清单。

- [ ] T093：更新 Provider 运维文档
  - 涉及范围：记录能力矩阵、优先级、限流、Fallback、Freshness、故障排查和免费数据限制。
  - 完成条件：开发者可按文档新增 Provider；用户可理解数据状态。
  - 验证方式：由未参与实现者照文档添加 Mock Provider 或排查一次故障。

- [ ] T094：完成 V0.2 一致性 Review
  - 涉及范围：确认 Market/Portfolio/Risk/Backtest 对 freshness/completeness 使用一致，不存在绕过 Provider 的直接数据调用。
  - 完成条件：静态检查和代码搜索无业务层直接 AKShare/easy-tdx/AData 调用。
  - 验证方式：执行架构扫描、Contract 测试和 Spec checklist。
