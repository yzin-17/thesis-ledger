# V0.6：AI Research / Agent

> 阶段目标：让 AI 成为可追溯、只消费确定性结果的研究助手，并加入 Research/Risk/Portfolio 分工。

- [x] T176：建立完整 AI Provider Registry
  - 涉及范围：支持多个模型 Provider、model metadata、baseURL、能力和可用状态。
  - 完成条件：切换 Provider 不改变 Tool/Agent 层。
  - 验证方式：对 Mock + 两个兼容 Provider 执行契约测试。

- [x] T177：实现 Model Routing
  - 涉及范围：按任务类型、成本/能力配置选择模型，并有 fallback。
  - 完成条件：Research/summary 可路由不同模型；实际 model 被记录。
  - 验证方式：模拟主模型失败确认 fallback。

- [x] T178：实现 Prompt Versioning
  - 涉及范围：system prompt、agent prompt、report prompt 均有版本和变更记录。
  - 完成条件：每条 AI Result 可定位 promptVersion。
  - 验证方式：修改 prompt 后新旧分析记录能区分。

- [x] T179：实现 Token/Cost Logging
  - 涉及范围：记录 input/output token、model、估算成本、duration。
  - 完成条件：可按天/任务统计 AI 使用；不记录 API Key。
  - 验证方式：执行若干调用并核对聚合。

- [x] T180：实现 Tool Permission Layer
  - 涉及范围：Tool 声明 read-only/side-effect 权限；V1 AI 只允许读取和运行研究，不允许写 Ledger 或交易。
  - 完成条件：未授权 Tool 无法被模型调用。
  - 验证方式：注册一个禁止 Tool，模拟调用并确认拒绝。

- [x] T181：补齐 Financials/News/Announcements Tools
  - 涉及范围：通过统一 Adapter 提供财务、新闻、公告结构化读取。
  - 完成条件：输出包含 provider、publishedAt/availableAt、fetchedAt。
  - 验证方式：各 Tool 用固定 fixture 验证时序字段。

- [x] T182：实现 runBacktest Tool
  - 涉及范围：AI 可提交 Strategy Schema 进行研究回测，但必须返回 job/result ID。
  - 完成条件：AI 无法绕过 Backtest Contract 直接执行任意代码。
  - 验证方式：提交一条均线策略并查询结果。

- [x] T183：实现 getJournal/getRiskHistory Tools
  - 涉及范围：为后续复盘提供只读日志和风险历史。
  - 完成条件：Tool 受 context/account 范围限制。
  - 验证方式：测试不同账户 scope 不串数据。

- [x] T184：强化 AI Provenance
  - 涉及范围：记录完整 Tool call、参数摘要、数据源、marketTime、availableAt、model、promptVersion。
  - 完成条件：最终报告可展开查看来源链。
  - 验证方式：随机抽一条报告能追溯每个关键结论的数据来源。

- [x] T185：实现 Decision Log
  - 涉及范围：保存研究问题、工具上下文、主要假设、最终结论和后续验证结果。
  - 完成条件：同一标的多次分析可对比历史观点。
  - 验证方式：创建两次分析并查询时间线。

- [x] T186：实现 Research Agent
  - 涉及范围：负责行情、技术、筹码、财务、新闻/公告的证据收集和初步结论。
  - 完成条件：输出结构化 evidence + hypothesis，而不是直接给最终买卖指令。
  - 验证方式：对固定标的检查至少引用 3 类 Tool。

- [x] T187：实现 Risk Critic
  - 涉及范围：读取 Research 结论并主动寻找反例、数据缺口、风险和假设脆弱点。
  - 完成条件：Critic 不修改原始 evidence；输出 objections。
  - 验证方式：给出明显乐观 fixture，确认能指出风险。

- [x] T188：实现 Portfolio Context Agent/Step
  - 涉及范围：将标的研究与用户真实仓位、成本、集中度、现有风险关联。
  - 完成条件：相同标的在不同仓位情境下结论上下文不同。
  - 验证方式：用 5%/40% 仓位两个 fixture 比较。

- [x] T189：实现 Portfolio Gate
  - 涉及范围：对最终输出加入不得自动交易、不得无依据覆盖风险规则、数据不足必须声明的约束。
  - 完成条件：最终分析不会生成执行订单；缺数据时 fail closed。
  - 验证方式：移除关键行情 Tool，验证报告明确不可判断。

- [x] T190：实现 Final Analysis Composer
  - 涉及范围：聚合 Research、Risk Critic、Portfolio Context，输出结论、证据、风险、关注事项。
  - 完成条件：所有关键数值来自 Tool；有数据时间和限制。
  - 验证方式：自动检查报告中的关键数字可在 provenance 找到来源。

- [x] T191：实现 Agent Checkpoint/Resume
  - 涉及范围：长 Agent 流程保存步骤状态，可从中断点恢复而非重复全部 Tool。
  - 完成条件：进程重启后可恢复一个未完成任务。
  - 验证方式：在 Research 完成后人工终止，重启继续 Critic。

- [x] T192：实现 Tool Timeout/Error Handling
  - 涉及范围：单个 Tool 超时/失败有重试或降级，不导致生成虚假数据。
  - 完成条件：Agent 输出能区分“无数据”和“数据为 0”。
  - 验证方式：模拟 News Tool timeout 验证。

- [x] T193：实现 Hallucination Guard
  - 涉及范围：对价格、收益、指标、筹码、回测指标等关键字段要求结构化 Tool source。
  - 完成条件：没有来源的关键数值不得进入最终报告或被标为 unverified。
  - 验证方式：注入无来源数字的模型输出，验证后处理拦截。

- [x] T194：实现 AI Chat UI 与 Context Selection
  - 涉及范围：支持选择整个 Portfolio、账户、持仓、策略作为上下文，并展示 Tool/来源。
  - 完成条件：用户可切换 context，历史消息保留 context metadata。
  - 验证方式：人工测试四类 context。

- [x] T195：建立 AI Regression 测试
  - 涉及范围：固定 Tool fixtures，检查关键事实正确、拒绝自动交易、数据缺失行为。
  - 完成条件：Prompt/模型变更可比较结构化评分。
  - 验证方式：在 CI/离线评估中运行固定问题集。

- [x] T196：完成 V0.6 文档与一致性 Review
  - 涉及范围：记录 Deterministic Compute、Tool 权限、Agent 分工、Provenance 和风险声明。
  - 完成条件：代码无 AI 直接写 Ledger/Position/Order 路径。
  - 验证方式：静态搜索 + 权限测试 + Spec checklist。
