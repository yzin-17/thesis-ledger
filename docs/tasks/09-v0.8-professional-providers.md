# V0.8：专业数据 Provider

> 阶段目标：让用户按能力混合免费/专业数据源，不改变业务层。

- [ ] T220：定义 Provider Plugin 配置模型
  - 涉及范围：支持 provider id、enabled、priority、capabilities、credentialsRef、settings。
  - 完成条件：新增 Provider 不修改核心 Market Service 数据模型。
  - 验证方式：实现一个 Dummy Plugin 验证动态注册。

- [ ] T221：实现 Credential 加密存储
  - 涉及范围：API Key/Secret 加密落库或使用系统 Secret Store，日志全部脱敏。
  - 完成条件：读取权限最小化；UI 不回显完整 Secret。
  - 验证方式：保存、读取、轮换测试并扫描日志。

- [ ] T222：实现 Per-capability Routing
  - 涉及范围：允许 Quote、Daily Bar、Minute Bar、Financial、Announcement 使用不同 Provider。
  - 完成条件：路由配置按 capability 生效并可回退免费源。
  - 验证方式：设置 Quote=A、Financial=B，验证请求路径。

- [ ] T223：实现 Provider 配置校验与连通性测试
  - 涉及范围：保存前验证必需字段和可选 test symbol。
  - 完成条件：错误 Key、权限、额度有明确提示。
  - 验证方式：使用无效 credential 验证。

- [ ] T224：接入 Tushare Provider
  - 涉及范围：按实际权限实现至少资产、日线、财务等可用能力。
  - 完成条件：符合统一 Contract，能力矩阵准确。
  - 验证方式：用测试 token 或 Mock 执行 Contract Suite。

- [ ] T225：接入第二个专业 Provider
  - 涉及范围：从 JQData/RQData/iFinD/Choice 中按实际可用资源选择一个。
  - 完成条件：至少证明 Plugin 框架能支持不同 SDK/认证模式。
  - 验证方式：跑统一 Contract Suite。

- [ ] T226：实现 Point-in-Time Financial 路由
  - 涉及范围：若 Provider 支持，保留 announcement/availableAt 供回测和 AI 使用。
  - 完成条件：PIT 数据不会被普通“最新财务”覆盖语义。
  - 验证方式：用历史财报发布时间 fixture 测试。

- [ ] T227：实现更长分钟历史能力
  - 涉及范围：专业源可补历史分钟数据，仍通过 completeness/freshness/落库流程。
  - 完成条件：回填可中断恢复且 provider metadata 完整。
  - 验证方式：补一段免费源缺失区间并验证。

- [ ] T228：实现 Provider Settings UI
  - 涉及范围：显示 Provider、能力、优先级、状态、延迟、credential 状态。
  - 完成条件：用户可启停和调整优先级，不直接编辑数据库。
  - 验证方式：人工配置主备并触发切换。

- [ ] T229：实现 Provider Cost/Quota Metadata
  - 涉及范围：记录可选额度、调用量和接近上限状态，避免意外用尽。
  - 完成条件：至少能显示调用计数或 unknown 状态。
  - 验证方式：用 Mock quota 验证预警。

- [ ] T230：建立专业 Provider Contract Test
  - 涉及范围：每个 Provider 共用一套 Quote/Bar/Asset/Financial 能力测试。
  - 完成条件：供应商升级时可发现结构变化。
  - 验证方式：CI 或手动运行两个 Provider suite。

- [ ] T231：更新数据源选择文档
  - 涉及范围：说明免费/专业数据适用场景、能力、成本、授权和回测 PIT 注意事项。
  - 完成条件：用户可根据需求选择而非默认推荐昂贵源。
  - 验证方式：文档 Review 对照实际 capability matrix。

- [ ] T232：完成 V0.8 一致性 Review
  - 涉及范围：确认所有业务模块仍只依赖 Contract，未出现专业 SDK 直连。
  - 完成条件：搜索仓库仅 Provider 包含具体供应商 SDK。
  - 验证方式：架构扫描 + fallback E2E。
