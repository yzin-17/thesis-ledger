# V0.7：投资日志、行为分析与 Shadow Account

> 阶段目标：把交易计划、真实执行、风险事件和策略关联起来，形成个人复盘闭环。

- [x] T197：定义 Journal Entry 模型
  - 涉及范围：记录 entryType、account、symbol、content、tags、createdAt、related ids。
  - 完成条件：日志可关联交易、持仓、规则、策略；支持纯文本备注。
  - 验证方式：创建多种关联日志并查询。

- [x] T198：定义 Trade Plan 模型
  - 涉及范围：记录买卖方向、计划价格、目标仓位、止损/止盈、预期周期、理由。
  - 完成条件：计划与实际 Ledger 分离；未执行计划不影响资产。
  - 验证方式：创建计划但不交易，Portfolio 不变化。

- [x] T199：实现买入/卖出理由记录
  - 涉及范围：在交易前后可记录 thesis、catalyst、risk、exit reason。
  - 完成条件：Ledger 事件可关联 Journal/Plan。
  - 验证方式：录入一笔交易并从交易详情跳转到理由。

- [x] T200：实现止损/止盈计划关联
  - 涉及范围：计划中的阈值可选择同步创建 RiskRule，但需显式确认。
  - 完成条件：RiskRule 保留 sourcePlanId；修改计划不会静默改已有规则。
  - 验证方式：创建计划→确认生成规则→修改计划，验证规则历史。

- [x] T201：实现目标仓位与预期持有期
  - 涉及范围：Trade Plan 支持 targetWeight 和 expectedHoldingPeriod。
  - 完成条件：复盘可比较计划和实际最大仓位/持有时间。
  - 验证方式：固定计划+交易序列计算差异。

- [x] T202：实现情绪/备注字段
  - 涉及范围：支持用户自定义情绪标签和自由文本，不作为确定性金融指标。
  - 完成条件：数据可导出并用于后续 AI 复盘。
  - 验证方式：创建、编辑、导出一条记录。

- [x] T203：实现 Planned vs Actual Entry/Exit
  - 涉及范围：比较计划价格/时间窗口与真实成交。
  - 完成条件：输出偏差金额、百分比、是否超计划。
  - 验证方式：用已知计划和成交 fixture 验证。

- [x] T204：实现 Planned vs Actual Stop
  - 涉及范围：识别触发计划止损后是否执行、延迟多久、实际损失差异。
  - 完成条件：基于 RiskEvent + Ledger 判断，不靠 AI 猜。
  - 验证方式：构造触发后未卖、及时卖两种场景。

- [x] T205：实现持仓周期指标
  - 涉及范围：按交易 lot/策略定义计算平均/中位持仓周期。
  - 完成条件：支持账户、标的、时间区间统计。
  - 验证方式：用已知买卖日期 fixture 对账。

- [x] T206：实现逐笔胜率与盈亏比行为指标
  - 涉及范围：从已平仓交易计算 trade-based win rate 和 payoff ratio。
  - 完成条件：与 Backtest/period metrics 口径区分。
  - 验证方式：固定 5 笔交易手工验证。

- [x] T207：实现交易频率与换手行为指标
  - 涉及范围：统计每日/周/月交易次数和换手，识别异常活跃。
  - 完成条件：仅输出指标，不直接贴行为标签。
  - 验证方式：用低频/高频 fixture 比较。

- [x] T208：实现仓位偏离指标
  - 涉及范围：比较计划 targetWeight 与实际 peak/current weight。
  - 完成条件：能识别仓位超计划并量化偏差。
  - 验证方式：计划 10%，实际 25% fixture 验证。

- [x] T209：实现行为规则：未执行止损
  - 涉及范围：基于明确 Trade Plan/RiskEvent/Ledger 判断。
  - 完成条件：结果包含触发时间、实际退出时间或未退出、损失差异。
  - 验证方式：两类 fixture 自动测试。

- [x] T210：实现行为规则：过早止盈
  - 涉及范围：基于计划目标与真实卖出判断，不以事后最高价简单定罪。
  - 完成条件：只有存在明确计划或策略基准时才判断。
  - 验证方式：有计划、无计划两种场景验证。

- [x] T211：实现行为规则：过度交易
  - 涉及范围：基于用户历史基线或明确阈值定义高频异常。
  - 完成条件：输出证据和阈值，不由 AI 直接下结论。
  - 验证方式：阈值边界测试。

- [x] T212：实现行为规则：追涨、锚定、处置效应初版
  - 涉及范围：采用可解释规则和明确数据要求；无法可靠判断时返回 insufficient data。
  - 完成条件：每个标签保存 evidence，而非只存字符串。
  - 验证方式：构造正、负案例 fixture。

- [x] T213：实现 Shadow Strategy Extraction
  - 涉及范围：从历史实际行为提取可描述的进入、退出、持仓规则候选。
  - 完成条件：只生成研究候选，不自动更新真实策略或规则。
  - 验证方式：用固定交易历史得到可重复候选规则。

- [x] T214：实现 Counterfactual Replay
  - 涉及范围：支持“严格执行计划/止损”等反事实回放，复用 Backtest/Replay Contract。
  - 完成条件：结果区分真实收益与反事实收益，标明假设。
  - 验证方式：用已知止损案例核对。

- [x] T215：实现 Single Trade Review
  - 涉及范围：汇总计划、实际交易、风险事件、行情、结果和 AI 解释。
  - 完成条件：用户能完整查看一笔交易生命周期。
  - 验证方式：人工验收一笔完整交易。

- [x] T216：实现 Weekly/Monthly Review
  - 涉及范围：汇总 performance、风险、行为指标、计划执行和主要事件。
  - 完成条件：周/月报可重跑且数据窗口明确。
  - 验证方式：固定时间区间生成报告并核对统计。

- [x] T217：实现 AI Behavior Review
  - 涉及范围：AI 只解释确定性行为指标和 Counterfactual，不自行发明行为事实。
  - 完成条件：报告引用 Journal/Ledger/Risk/Behavior metrics。
  - 验证方式：固定 fixture 检查引用一致。

- [x] T218：建立 Journal/Behavior 回归测试
  - 涉及范围：覆盖计划、执行偏差、止损纪律、持仓周期、胜率、过度交易等。
  - 完成条件：规则调整导致行为标签变化时可被发现。
  - 验证方式：CI 运行 expected behavior set。

- [x] T219：更新复盘文档并完成 V0.7 Review
  - 涉及范围：说明行为分析是辅助，不等同心理诊断；Shadow/Counterfactual 是假设性研究。
  - 完成条件：所有行为标签都有 evidence 和口径说明。
  - 验证方式：Spec checklist + 随机抽样 5 条行为结论审计。
