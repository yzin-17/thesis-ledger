# 收益分析 Snapshot 自动化入口 TODO

状态：待实现

## 背景

收益分析依赖 Portfolio Snapshot 计算历史曲线、TTWROR 和 XIRR。当前服务端已经支持手动调用 Snapshot 接口，也支持通过 `snapshot` 类型的 Automation Job 定时生成；但 Desktop 没有创建或编辑该任务的用户入口。

当前“数据与自动化”页面只能查看已有任务并启用/停用，任务列表为空时用户无法从界面设置 Snapshot 保存频率。

## 待办

- [ ] 在“数据与自动化”页面增加“收益快照”配置卡片或创建任务 Sheet。
- [ ] 支持设置保存频率、时区、启用状态和任务名称；任务类型固定为 `snapshot`。
- [ ] 明确 Snapshot 生成范围：实际/影子模式，以及全部账户或指定账户。
- [ ] 保存后刷新任务列表，显示启用状态、下一次运行时间和最近一次运行结果。
- [ ] 在收益分析无历史数据的空状态中提供“设置自动快照”入口，跳转到“数据与自动化”。
- [ ] 提供“立即创建 Snapshot”操作，并在行情不完整时保留 partial 和缺失标的说明。
- [ ] 补充创建、编辑、启停、失败重试和空任务列表的 Server/Query/Desktop 测试。
- [ ] 进行宽屏、窄屏、键盘操作和实际定时任务运行验收。

## 验收标准

- 新用户无需调用 API，即可在 Desktop 配置并启用 Snapshot 自动保存。
- 收益分析页面能明确显示最近 Snapshot 时间；没有 Snapshot 时能引导用户完成配置。
- 任务失败不会伪造收益数据，页面显示失败原因和可重试入口。
- 现有手动 Snapshot API 和 Automation Scheduler 行为保持兼容。

## 当前入口

- 页面：`/providers`（数据与自动化）。
- 现状：只能切换已有 Automation Job 的启用状态，不能创建 `snapshot` 任务。
