# 富途与 HiThink 筹码能力核查和接入

## 目标与范围

核对富途和 HiThink 的官方筹码 API、当前项目账号认证方式及实际取数结果；仅将当前账号能够取得完整筹码摘要的来源接入 DSA 既有能力注册、诊断与消费路径。

当前筹码摘要要求中国内地股票的平均成本、获利比例、70% 与 90% 成本区间及相应集中度，保持来源身份、报告日期、观察时间、人民币与估算语义。形态筛选、当日资金分布和成交量价分布不得替代持仓成本估算摘要。

## 边界与不变量

- 沿用 `ChipRequest`、`ChipResult` 和 `CAPABILITY_SOURCES`；原协议及 DTO 留在各来源适配层。
- 先核对官方公开合同，再用当前合法凭据执行有界只读诊断。不得猜测字段、绕过认证、获取客户端内部会话或把未登录解释为账号权限不足。
- 仅记录凭据来源、方式和版本，不记录密钥、令牌、Cookie、完整账号标识及带认证信息的原始请求。
- 新来源必须有真实成功和字段合同证据后才能声明可用。认证缺失、外部未开放、权限不足、合同不完整与网络失败分别记录。
- 现有 AKShare／东方财富筹码路由继续保留，不因候选核查而切换；不改写业务历史及现有其他路由。
- Docker 状态变更只能经 infra 正式脚本。只有产生需要部署的源码时，才执行最小目标更新与独立运行验收。

## 验收标准

- AC1：富途公开 REST 筹码合同、项目 OpenD 接入方式及当前认证缺口有可复核证据；具备认证时完成当前账号真实读取。
- AC2：HiThink 核查必须针对项目实际使用的 `fuyao.aicubes.cn` 平台；明确其筹码能力的开放状态、输出语义及当前 Key 的真实读取结果。
- AC3：对当前账号真实可用且合同完整的来源，实现来源适配、精确能力绑定、目录与诊断，并以定向测试覆盖身份、单位、日期、缺失字段、空数据、失败分类和凭据保护。
- AC4：有新适配时，正式更新目标 DSA 并验证目录、真实数据请求和 ThesisLedger 消费；若来源确实不满足接入条件，记录阻塞和解除条件，不登记为已接入。

## 本轮核查决策

富途当前控制配置仅有 OpenD 认证，用户确认暂不新增 REST 认证；REST 账号取数未验证。HiThink 当前 Key 的正常报价成功、筹码形态入口拒绝，官方合同也未开放外部接入且不提供完整摘要。因此本轮没有触发新来源适配与部署，不改变现有 AKShare 路由。后续新增认证或官方开放合同需要按当时状态另行立项核查。
