# 投资复盘工作台交互设计

## 背景

当前 Desktop“投资复盘”页面直接要求用户输入 `CompletedTrade JSON` 或 `CompletedTrade[] JSON`，并以原始 JSON 展示计划偏差、行为指标和反事实结果。该页面能够验证 Journal/Behavior API，但把内部数据结构、ISO 时间和数组格式暴露给日常用户，更接近接口验收页，而不是投资复盘工作台。

服务端已经提供 JournalEntry、TradePlan、Ledger events 和确定性复盘接口，但 Desktop 尚未把这些事实组装成可直接选择的已平仓交易。当前单笔复盘还把确定性计算和 AI 任务串在一次操作中，导致 AI 不可用或响应较慢时也会延迟核心结果。

## 已确认方向

- 默认面向日常投资复盘，不要求用户理解或输入 JSON。
- 默认从账户和 Ledger 中选择已平仓交易；手动表单作为无完整 Ledger 数据时的兜底。
- JSON 保留为高级入口，用于调试、审计和特殊数据输入，不占据默认页面。
- 先展示确定性事实，再由用户显式触发 AI 解读；AI 失败不得影响确定性结果。
- 复盘保持只读研究边界，不写入 Ledger，不生成订单，也不自动保存复盘笔记。

## 目标

- 将主流程收敛为“选择交易或窗口 → 核对证据 → 查看复盘结论”。
- 单笔复盘最多经过两次主要操作即可得到确定性结果。
- 使用中文业务语言展示计划偏差、行为证据和反事实结果，不直接暴露内部字段名。
- 明确区分“发现偏差”“未发现偏差”和“证据不足”，不把缺失事实当作正常结果。
- 让周期复盘具有明确账户和时间窗口，并能追溯到窗口内的交易样本。
- 保持 AI 只解释确定性结构化结果，不新增交易事实或心理诊断。

## 非目标

- 本次不新增交易录入、订单管理或自动执行能力。
- 本次不自动创建或修改 TradePlan、JournalEntry、风险规则或策略版本。
- 本次不把行为标签扩展为心理画像、投资建议或买卖信号。
- 本次不重新定义 Ledger 成本核算、部分成交匹配和盈亏口径。
- 第一版不提供复盘模板管理、分享、导出或跨账户合并报告。

## 页面信息架构

页面标题继续使用“投资复盘”，副标题说明确定性事实、AI 解释和只读边界。标题区域提供账户选择；没有账户时显示空态并引导前往投资组合或录入持仓。

主内容使用顶层页签：

1. `单笔复盘`
2. `周期复盘`

“AI Behavior Review”不再作为独立英文表单出现。AI 是确定性复盘结果上的可选解释能力，不是与单笔复盘并列的数据入口。

### 单笔复盘

单笔复盘由以下区域组成：

1. 已平仓交易列表
   - 默认展示当前账户最近已平仓交易。
   - 支持按标的和日期筛选。
   - 每条交易显示标的、入场/退出日期、已实现盈亏和证据完整度。
   - 选中交易后，不立即发起分析，先展示核对区域。
2. 交易事实核对
   - 展示从 Ledger 得到的实际入场、实际退出、持有天数、数量和盈亏。
   - 展示已关联计划中的计划入场、计划退出、止损、目标仓位和计划持有天数。
   - 缺少计划事实时显示“待补充”或“证据不足”，不得用 `0`、空字符串或样例值替代。
   - “补充证据”在右侧 Sheet 中完成；用户输入只参与本次分析，第一版不回写 TradePlan 或 JournalEntry。
3. 确定性复盘操作
   - 主按钮使用“开始复盘”。
   - 按钮只触发计划与实际、行为指标和反事实计算。
   - 运行期间只禁用当前复盘所需操作，不锁死周期复盘页签和无关导航。
4. 复盘结果
   - 结果总览：盈亏、实际持有天数、证据完整度和最重要偏差。
   - 计划与执行：入场、退出、持有周期和仓位的计划值、实际值、差值。
   - 行为证据：中文标签、状态、证据值和口径说明。
   - 反事实比较：实际盈亏、假设盈亏、差额和完整假设。
   - AI 解读：确定性结果成功后才显示“生成 AI 解读”次级操作。
   - 原始证据：通过“查看原始证据”打开只读 Sheet，展示 API 结构化结果。

### 周期复盘

周期复盘使用当前账户和显式时间窗口：

- 时间范围提供“最近 7 天”“最近 30 天”和“自定义”三种选择。
- 页面在计算前显示窗口内已平仓交易数量；没有交易时使用 Empty 状态，不允许生成空报告。
- 确定性结果展示交易数、胜率、盈亏比、平均/中位持有天数、换手和止损偏离次数。
- 展示“需要重点回看”的交易样本，点击后切换到单笔复盘并选中对应交易。
- AI 解读继续作为确定性结果后的独立操作，并显示 Provider、模型、Prompt 版本和证据边界。
- 周期结果始终展示用户选择的起止时间，不以样本最早/最晚时间静默替代窗口边界。

## 复盘候选读取模型

新增服务端只读的复盘候选读取模型，建议命名为 `JournalReviewCandidate`。它负责把已存在的事实整理成 Desktop 可消费的单笔复盘输入，避免前端自行推断部分成交、成本核算和计划关联。

候选至少包含：

- `id`：稳定的候选标识，不使用数组下标。
- `accountId`、`symbol`。
- 入场、退出时间及实际成交摘要。
- 已实现盈亏及其计算口径。
- 可选的计划事实和计划来源标识。
- 可选的 Journal、Risk 证据引用。
- `evidenceCompleteness`：完整、部分、仅实际交易三种状态。
- `missingEvidence`：明确列出缺失的计划或行为分析字段。

候选组装遵循以下原则：

- 实际成交和盈亏来源于 Ledger，并复用服务端既有成本核算规则。
- 优先使用显式关联的 JournalEntry、LedgerEvent 和 TradePlan。
- 没有显式关联时不得仅凭相同标的和相近日期自动绑定计划；计划字段保持缺失。
- 部分成交、分批建仓和平仓必须在服务端形成一致的已平仓交易生命周期。
- 候选接口只读，不因查询或选择交易创建新的领域记录。

建议提供按账户、标的、起止时间和分页参数查询候选的 endpoint。周期复盘复用同一候选来源，不维护另一套交易拼装逻辑。

## 手动与高级入口

当账户没有可用候选或用户需要复盘外部交易时，提供“手动复盘”入口。手动表单使用业务字段分组：

- 必填事实：标的、入场时间、退出时间、盈亏。
- 实际执行：入场价、退出价、换手、最高仓位。
- 计划证据：计划入场、计划退出、止损、目标仓位、计划持有天数。

可选字段缺失时允许继续计算，但对应结论必须显示“证据不足”。字段错误在字段附近说明原因，不使用统一的“请检查 JSON 和服务状态”。

“高级 JSON”位于次级入口的 Sheet 中：

- 默认填入当前候选或手动表单对应的结构化数据，不再自动展示虚构样例。
- 支持单笔对象和交易数组，但明确标注适用的复盘类型。
- JSON 解析错误、Schema 校验错误和服务错误分别反馈。
- 原始输入不会自动保存或写入 Ledger。

## 结果表达

### 计划与执行

每个指标展示计划值、实际值和偏差，缺失任一必要事实时显示“证据不足”。偏差颜色只表达状态，不作为唯一信息载体；同时提供中文标签和数值。

### 行为证据

行为标签使用中文名称，并保持三态：

- `发现偏差`：确定性规则命中，并展示参与判断的事实。
- `未发现偏差`：事实充足但规则未命中。
- `证据不足`：缺少必要事实，展示缺少的字段或口径。

行为标签是交易研究分类，不是心理诊断。页面不得把 `missed-stop`、`early-profit` 等内部枚举直接作为主标签。

### 反事实

反事实区域并列展示实际盈亏和假设盈亏，差额只在假设可计算时出现。假设说明必须常驻结果区域，至少包含止损成交价、数量归一化、滑点和流动性边界，不只放在 Tooltip 中。

### AI 解读

AI 解读使用独立 mutation：

- 仅在确定性复盘成功后可用。
- 输入只包含已计算的结构化事实和来源引用。
- 加载、失败和完成状态独立于确定性结果。
- Provider 不可用时使用 Alert 说明，确定性结果保持可见。
- 完成后展示 Provider、模型、Prompt 版本和任务编号。

## 状态与异常处理

- 账户加载中：使用 Skeleton，不提前显示空账户。
- 没有账户：使用 Empty，引导创建账户或导入数据。
- 没有已平仓交易：使用 Empty，提供“手动复盘”入口。
- 候选读取失败：在交易选择区域展示可重试 Alert，不清空已完成结果。
- 证据不完整：允许复盘实际事实，相关指标显示“证据不足”。
- 确定性分析失败：结果区域展示具体失败阶段和重试操作。
- AI 失败：只更新 AI 区域，不用错误 Toast 覆盖确定性结果。
- 切换账户：清除不属于新账户的候选选择和临时补充证据；已完成结果标记为旧账户结果或直接收起，避免上下文混淆。
- 切换页签：保留当前页签的筛选和成功结果；进行中的请求由 TanStack Query mutation 状态独立管理。

## 前端组件与模块边界

优先组合项目已有 shadcn 组件：`Tabs`、`Card`、`Badge`、`Sheet`、`Select`、`Alert`、`Empty`、`Skeleton`、`Button`、`Input` 和 `Textarea`。缺失的表单原语只能通过项目包管理器和 shadcn CLI 按需添加，不覆盖已有本地组件。

建议拆分为以下职责单一的模块：

- `JournalDashboard`：账户上下文和顶层页签。
- `SingleTradeReview`：单笔复盘流程编排。
- `ReviewCandidateList`：候选查询、筛选和选择。
- `TradeEvidenceSummary`：实际事实、计划事实和完整度。
- `EvidenceEditorSheet`：本次复盘的临时补充证据。
- `SingleReviewResult`：确定性结果组合。
- `BehaviorEvidenceList`：行为三态与证据展示。
- `CounterfactualComparison`：反事实比较和假设。
- `PeriodReview`：窗口选择、样本和周期指标。
- `AiReviewPanel`：独立 AI 任务状态和来源边界。
- `RawEvidenceSheet`：高级输入和原始证据审计。

请求读取使用 TanStack Query，分析和 AI 使用独立 mutation。不新增手写请求竞态管理，不使用多重嵌套三元表达式，不新增传统页面级 CSS 选择器。

## 数据流

### 单笔复盘

1. 用户选择账户。
2. Desktop 查询该账户的 `JournalReviewCandidate`。
3. 用户选择候选，页面展示 Ledger 实际事实和可用计划证据。
4. 用户可在 Sheet 中为本次复盘补充缺失证据。
5. Desktop 将候选事实和临时补充证据组装为 `CompletedTrade`，发起确定性分析。
6. 页面分别渲染计划偏差、行为指标和反事实结果。
7. 用户可选地创建只解释上述结果的 AI 任务。

### 周期复盘

1. 用户选择账户和时间窗口。
2. Desktop 查询窗口内候选及样本数量。
3. 用户发起确定性周期复盘，请求显式携带 `start` 和 `end`。
4. 页面展示窗口指标和重点交易。
5. 用户可选地创建 AI 行为解读任务。

## 验证策略

### 服务端

- 候选组装覆盖单次买卖、分批建仓、分批平仓、跨窗口持仓和无计划关联。
- 显式计划关联优先；无关联时不按标的和日期自动猜测。
- 候选分页、账户隔离和窗口边界正确。
- 候选查询不产生 Ledger、Journal 或 TradePlan 写入。
- 周期复盘使用用户选择的显式窗口。

### Desktop

- 使用 QueryClientProvider 覆盖账户、候选的加载、空态、失败和成功状态。
- 单笔复盘覆盖完整证据、部分证据、手动输入和高级 JSON。
- 行为结果覆盖发现、未发现和证据不足三态。
- 确定性成功但 AI 失败时，确定性结果持续可见。
- 切换账户不会复用旧账户候选或临时证据。
- 周期重点交易可以进入对应单笔复盘上下文。

### 人工验收

- 使用一笔完整计划交易、一笔无计划交易和一个包含多笔交易的 30 天窗口验证主流程。
- 检查默认页面不出现大段 JSON，原始证据仍可通过高级入口访问。
- 检查键盘焦点顺序、Sheet 标题、字段错误关联和仅靠颜色无法表达的状态。
- 分别模拟候选接口失败、确定性接口失败和 AI Provider 不可用。

## 验收标准

1. 默认页面不展示 `CompletedTrade JSON` 或 `CompletedTrade[] JSON` 编辑器。
2. 页面使用“单笔复盘 / 周期复盘”页签，AI 不再作为独立数据输入页。
3. 用户选择账户中的已平仓交易后，最多两次主要操作即可看到确定性复盘结果。
4. 实际交易、计划证据和临时补充事实来源可区分，缺失值不回退为样例或零值。
5. 单笔结果以中文展示计划偏差、行为三态、反事实差额和假设。
6. 周期结果保留用户选择的明确起止时间，并可追溯到窗口内交易。
7. AI 解读使用独立操作和状态；AI 失败不影响确定性结果。
8. 无账户、无交易、读取失败、分析失败、证据不足和 AI 失败分别反馈。
9. 高级入口仍支持查看原始证据和输入 JSON，但不会自动写入 Ledger。
10. 候选组装位于服务端，只读且不依赖前端按标的、日期猜测计划关联。
11. Desktop 使用 TanStack Query 管理查询和 mutation 状态，并复用现有 shadcn 组件体系。
12. 针对性类型检查、单元测试和组件测试通过；浏览器视觉验收与真实运行时验收单独记录。

## 实施门槛

设计确认后创建独立任务文档，并拆分服务端读取模型、Desktop 工作台、结果表达、AI 解耦和针对性验证任务；在确认前不修改业务实现。
