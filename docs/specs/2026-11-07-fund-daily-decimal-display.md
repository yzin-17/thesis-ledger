# 基金收盘估算误差的精确展示

## 问题与目标

每日收盘估算的两端消费者仍直接调用 toFixed(4)；Desktop 将十进制差额先转成 Number，极小值归零，巨大有限十进制可能变成 Infinity，普通舍入边界也会丢失有效数字。Mobile 尚未展示同一响应中的有符号差额与低覆盖提示。

复用 Market 数字合同显示估算与正式净值；为有符号十进制差额建立稳定 Domain 展示入口，最多六位、非零保留、正差额带正号、零不带符号。复用既有比例文本的有效数字与独立 BigInt 指数实现，保持现有百分比 API 的输出合同。

## 验收标准

- AC1：Domain 共享十进制展示从字符串读取有效数字和独立指数，不将原值转换为 Number；普通分组、六位舍入、极小正负、超出浮点范围、极大指数、零/负零、空与非法值有回归。
- AC2：现有比例文本二/三/六位精度、单位换算、数值入口和所有消费者保持；共享实现单向依赖，不重复维护解析器或新增无所有权的 utils。同步维护依赖门禁。
- AC3：Desktop 和 Mobile 的每日估算、正式净值、估算差额与低覆盖使用同一展示合同；日期、相对绝对误差、待正式净值、空、失败重试和请求行为保持，原始响应及实际缓存不变。
- AC4：定向、完整 Domain/Desktop/Mobile、四包构建和仓库门禁通过；实际浏览器两端四宽覆盖普通/舍入、极小、巨大、零/缺失、等待与失败，复核真实组件重试及文本读取边界。
- AC5：记录最终稳定输入与受控/实际运行态边界，完成文档一致性和归档，继续全线程 Goal。

## 所有权与兼容

新模块属于 Domain 的只读十进制展示，服务比例文本及跨应用的差额读数；Market 数字事实继续由既有模块拥有。DecimalValue 是运算合同，需要展开尺度并进行运算，本任务只需显示独立指数；不改变其解析、运算或存储行为。es-toolkit 的 round、multiply 等 number 工具不能保留原字符串的有效数字和任意指数，沿用已验证的原生 Intl 文本格式化。

公开根入口只增加差额所需的 formatDecimalNumber，原比例 API 保持兼容；内部共享格式器不提升为请求或业务编排能力。没有依赖、Schema、数据库、队列、Docker、外部来源、模型或发布变更，真实数据保持只读。
