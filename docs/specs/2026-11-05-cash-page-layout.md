# 现金页面信息层级与布局优化

## 目标与范围

根据现金页面截图评审，在现有 Desktop/Web 现金页上突出余额、压缩空状态、收紧流水布局并精简说明。复用项目组件、语义颜色和原子类；保持现有业务逻辑与交互。

## 设计约束

- 可用现金为总览主信息，应收、应付为辅助信息；按原币展示，可靠折算判断和金额计算保持原样。
- 单币种且与本位币一致时不重复展示相同合计；多币种保留可靠本位币合计，汇率缺失时继续说明不可合计。
- 无待结算记录、无待确认入账时保留紧凑状态；有记录时显示原有明细与操作。
- 流水维持默认五条及查看全部／收起，固定日期与金额位置，将币种靠近金额，结算状态集中说明。
- 定期入账按待处理事项、入账计划和入账历史组织。没有待确认记录时，状态靠近分区标题；存在待确认记录时，显示独立待办及原有操作。
- 入账计划和入账历史采用独立、顶部对齐的内容容器；内容区域足够宽时并排，窄屏上下排列。计数靠近标题，金额与时间采用稳定位置。历史记录保留状态、计划名、期次、实际金额与到账时间。
- 定期入账保留新建、修改、暂停、恢复、结束、确认、跳过及历史入口；已结束计划继续可见，其没有可执行项目的菜单不显示；不改变弹窗表单。
- 保留查询、缓存、刷新、加载、失败、部分数据、禁用条件、名称解析及冻结语义；不新增请求或编造账户关联信息。
- 复用当前样式系统，不新增页面 CSS、依赖或动画；不改变其他账户页面及 Mobile。

## 验收标准

| 编号 | 断言 | 实现与验证归属 |
| --- | --- | --- |
| AC1 | 余额主次明确，原币、可靠合计、缺汇率及部分数据语义正确 | T1；组件回归与浏览器截图 |
| AC2 | 空待结算区紧凑；有记录时名称、日期、方向、金额、备注保留 | T1；组件回归与多状态截图 |
| AC3 | 流水默认五条与展开收起不变，日期、金额和币种易扫描 | T1；现有回归与交互验证 |
| AC4 | 定期入账空状态紧凑，有待办时操作完整，计划及历史入口保留 | T2；现有交互回归与截图 |
| AC5 | 桌面、平板和窄屏无横向溢出，按钮可达，错误／加载状态保留 | T3、T5；类型检查、构建、门禁与浏览器检查 |
| AC6 | 定期入账的计划与历史分组明确，空待办状态紧凑，金额和记录状态易扫描 | T4；组件回归与 T5 截图 |
