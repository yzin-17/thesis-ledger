# 日历发布证据与可用时间

归属主任务 R01.10。当前 `calendar_fact` 把请求起日作为 availableAt，不能证明修订后的日历在该历史时点已存在。2020 年临时延长春节休市是明确反例：原安排与 2020-01-27 调整公告不同。

## 已核验证据

[PyPI 4.13.2 元数据](https://pypi.org/pypi/exchange-calendars/4.13.2/json) 记录 wheel 发布时间为 `2026-03-10T03:24:37.055242Z`，wheel SHA-256 为 `fc5a2ad0d61b5c3a6539a3061cd4cbb55c59f4a903455cec7926e4b798919996`。本轮只读下载到内存、核对摘要并解包比较：wheel 的 `exchange_calendars/` 下 93 个文件均为 Python 源码，与宿主安装文件逐字节一致。

按路径排序，将每个文件编码为 `相对路径:文件SHA-256`，以换行拼接且末尾无换行，再做 SHA-256，得到包源码树摘要 `3dd6286cd2404bbe188e843a7ada5625164fff6059eb18c69d080213c3e29dea`。该摘要用于绑定安装内容，版本字符串本身不足以证明内容相同。

## 行为合同

1. 新读取的实际日历仅在版本、包文件集合和源码树摘要匹配已核验发布记录时返回；未知版本、缺失或修改内容必须不可用。运行请求不访问 PyPI。
2. 匹配时 availableAt 使用该制品公开发布时间，含义是该版本日历最迟已有公开制品证据的保守边界，不声称各历史公告最早发布时间。
3. dataAsOf 早于发布时点时返回 unavailable，不能使用当前修订包重建更早知识状态；未来若支持历史发布版本，须独立登记证据，不能回填时间。
4. 事实仍受实际 XSHG 包覆盖范围和结算请求预算约束。请求起止日期变化不得改变 availableAt。
5. 发布证据适配修订进入 providerRevision，以区分旧回填语义；旧冻结快照保留原字节和原身份，不在读取时重写。fixture 明确保持测试用途。
6. 只证明公开日历制品可用性，不能用于授予事件、行情或准入完整性。

## 验证与部署

先验证源码树摘要、缺文件/修改/未知版本拒绝和发布时间前后边界，再验证实际 HTTP 日历。Server 需验证新事实不晚于 dataAsOf，以及旧已冻结快照不变。依赖锁定涉及 requirements 时必须完整 `update.sh dsa`；后续仅源码变化按兼容性选择官方入口。实际镜像、协议及 HTTP 验收分别记录，不用健康状态代替行为。
