## 交互与视觉方案

### 页面头、动作与 Tab

页面层级统一为“标题与页面动作 → 全页上下文 → 一级 Tab → 当前 Tab 的筛选及工具栏 → 内容”。页面没有相应层级时直接省略，不留占位框。

页面动作只放跨 Tab 有效的创建或刷新；列表操作放该列表工具栏；字段或区块重试贴近失败位置。创建动作采用主按钮，刷新采用现有带可访问名称的图标按钮，同组对齐。相同作用范围不重复放置两个刷新或取消入口。页头按钮与中文主标题对齐，不以英文眉题顶部对齐。

保留既有装饰性英文副标题约定及研究、策略的既定例外；压缩重复中文标题和解释，不通过全站删除副标题制造新的合同冲突。一级导航使用现有下划线 Tab；局部范围选择使用低权重分段控件。Tab 的选中态由已生效路由决定，路由被草稿保护拦截时不得先切换选中态。

### 全局账户范围

实际／模拟继续只有一个全局入口。桌面将其放入品牌下方、与导航内容左对齐的上下文区，显示“账户范围”及两个可见选项；收起侧栏时保留当前模式的可读提示和可访问名称。窄屏放入正常文档流的紧凑上下文行，不浮在页面内容上，也不与主题偏好混成同一语义组。

切换继续执行现有草稿和在途操作保护、持久记忆及查询范围更新。浏览器样本仅用于验证呈现与交互；隔离语义必须复用现有自动化并单独验证，不能从两种模式下相同的样本内容推断正确。

### 信息密度与容器

- 每个业务区块保留一层主要容器边界，内部优先使用留白、行分隔和浅底色；输入控件、危险操作和独立浮层保留必要边界。
- 首批调整组合引导、市场路由、研究工具栏；风险静态摘要减少无语义阴影。不得全局删除所有 border 或给单页增加专用 CSS 覆盖。
- 已有持仓时，引导压缩为未完成事项摘要，可展开完整步骤；空组合保留一个主要录入动作。配置提示不挤掉首屏资产摘要。
- 复盘只显示一个与当前阶段匹配的主提示；候选读取失败时给重试，成功空集时给下一步，已有候选未选择时给选择提示。常规说明、聚合规则和原始 JSON 移到可展开帮助；影响数据解释的异常、费用、来源时间和执行限制仍保留。
- 用户选项与当前回显共用中文标签映射。提供方名称、证券代码、模型标识可保留原文；内部枚举和协议错误不充当主要操作说明。
- 策略操作列保证“回测”等动作完整显示；必要时压缩次要列或使表格局部滚动。窄屏导航提供可发现的文字或明确展开入口。

### 读取、写入与恢复

读取状态必须区分首次加载、成功有数据、成功空集、筛选无匹配、失败无数据、保留旧数据但刷新失败。风险指标未成功读取时显示“—／暂不可用”，不以零表示未知；收益读取失败时不同时建议“完成数据配置”；市场失败时停止“正在读取”的描述。

写入反馈优先使用服务端稳定业务错误码和已验证的字段错误；网络中断或 5xx 使用“暂时未能完成，请重试”等操作语义，并保留输入。不能把 503 统一解释成标的、数量或组合数据错误。技术状态码可放入诊断详情，不作为唯一正文。仅有真实输入校验失败时才要求用户修改字段。

写入结果不确定、已成功写入但后续读取失败继续使用现有幂等、找回和确认流程。不得因精简错误信息而隐藏成功事实、清除提交身份或开放重复提交。

市场路由草稿在内部 Tab 切换时保留；跨页、历史后退及关闭窗口遵守既有未保存保护。保存失败后仍属于脏草稿。确认放弃才丢弃；成功保存并完成既定确认后再清除脏状态。

研究提交结果未确认时，关闭确认必须明确“关闭面板”和“取消任务”的区别，保留找回原提交能力；不得继续只称为“未保存的修改”。

### 具体表单与图表

- 实验重命名补充可见的“取消”，保留已实现的 Esc。提交中及写后确认阶段沿用互斥保护；失败后允许取消并恢复名称链接。
- 实验四个日期字段分别显示开发集开始、开发集结束、验证集结束、封存测试结束；使用独立字段身份和可访问名称，区间说明作为组说明。不得用同一个 Field 上下文覆盖四个控件的名称。
- 当前股票／ETF 复盘草稿的计划入场价、计划离场价、止损价非空时必须为有限且大于零的十进制值；空值仍表示未补充。错误就近提示并阻止应用及分析请求。仅约束新编辑的草稿，不重写历史快照。若未来支持可为负价格的资产，应由独立领域合同扩展，不能默许现行字段接受任意负数。
- 390 宽行情全屏只保留一个标题；主图类型、周期、缩放等高频操作紧凑排列，次要指标配置进入可展开区域。初始主图绘图区在首屏可见，不让全部配置占据半屏以上；关闭、重置和已选状态保持可发现。

## 验证与兼容边界

优先使用项目现有原子类、共享组件变体和 TanStack Query；不增加页面级选择器、`!important` 或重复渲染分支。遵守文件规模 ratchet，超限文件的新增职责应提取到有明确归属的组件或纯函数。

先定向状态／交互测试，再 Desktop 类型检查和 build，最后分页面浏览器验证。至少在 1440×900、768×1024、390×844 检查关键修复，补深浅主题、键盘焦点和可访问名称；源码样式通过不替代截图。

浏览器拦截必须先建立再触发动作；所有写入留在本地样本，未知写入失败关闭，未命中读请求可以使用现有 API。记录每项样本的匹配范围与响应合同，避免把样本错误误报为产品缺陷。读取成功、写入成功、写后读取失败、写入结果不确定分别验收。真实 Provider／AI／通知、Docker、Electron 安装包是独立证据层，不由本次样本验收代替。
