# 桌面列表边框与分隔一致性

> 任务标识：desktop-list-frame-consistency
> 日期：2026-11-05
> 对应任务：[实施任务](../archive/tasks/2026-11-05-desktop-list-frame-consistency.md)

## 范围与目标

统一桌面 Web 所有业务列表的边框规则，覆盖主页面、详情、弹窗、响应式列表和状态分支。沿用现有字体、颜色、数据、查询、交互与原子类；不调整移动原生工程、服务端或数据库。此前确认保留的走势图外框与无框组合指标不属于列表，不改变。

## 分类规则

1. 独立的多列表格使用一层 `rounded-md border border-border` 外框和内部行分隔，表头与内容保持同列对齐。外框内保留必要的首尾内边距；横向滚动与固定操作列不变。
2. 当卡片本身就是这张表或列表的容器时，内部表格使用显式 plain 模式，不重复套框。复合区域包含表格与其他状态时，外层承担唯一边框，内部只承担滚动或行分隔。独立子表与其较大的工作区属于不同语义层级，仍可各自有清晰边界。
3. 账户、现金计划、定投等独立操作列表使用一个整体外框及行分隔；同一组不逐行加卡片。位于已带框的设置卡片内时，只保留行分隔。当前、待确认、历史等分组保持原有业务含义与折叠行为。
4. 新闻、公告、资料、历史说明，以及现金页待结算/最近流水等只读明细使用留白和轻行分隔，取消每条记录的小框。承担独立预览、编辑或复杂操作的对象卡片保留逐对象边框，圆角与边框色统一。
5. 空态、加载与读取失败沿用所属区域的一层边界，不叠加空态小框。单行“暂无待确认”等状态说明保持无框。菜单选项、表单控件、告警、指标、图表和正文项目符号保持各自语义，不机械套用业务列表样式。

现金总览采用浅底色分组，待结算与最近流水按只读明细使用轻分隔；对应局部样式与三种宽度检查见[现金页线条密度复核](../archive/reviews/2026-11-05-account-cash-visual-density.md)。

## 实现边界

现有 `components/ui/table.tsx` 拥有表格容器与 outlined/plain 语义，原生表格复用该容器，已有共享 Table 复用同一默认值。仍有明确外层框所有者的复合区域声明所有权。不得用通用 CSS 选择器扫描 DOM 后自动增删边框。

各 feature 仅组合共享容器与原子类。共享 UI 不依赖业务 feature、API 或查询。超过尺寸阈值的存量文件不得增长；不通过放宽门禁、增加 ignore 或机械拆文件规避。旧边框规则若妨碍原子类，应局部移除旧冲突，而不增加 `!important`。

## 验收

- AC1：所有原生/共享表格声明、抽取行和业务列表族有分类盘点，保留或调整均有原因。
- AC2：独立表格框线、圆角、内边距、行分隔一致；已有同组外框时明确 plain，避免双框；空态/加载/错误与正常状态有一致的边界所有者。
- AC3：操作列表、只读资料列表和复杂对象卡片按以上规则落实；保持选中、折叠、分页、编辑、筛选与危险操作行为。
- AC4：定向测试先通过，再执行 Desktop 构建、边界和相关静态门禁；在最终生产预览中检查代表页面、详情、状态样本及 1440/768/390px。边框统一不能破坏表头对齐或产生页面水平溢出。

真实业务数据只读，状态与写入相关检查用受控组件样本完成。本次不提交、推送、发布或更新 Docker、镜像和安装包；本地 Web 验证不替代部署验收。
