# AI 模型价格的显式保留迁移

接续[配置原 Spec](2026-09-21-ai-provider-model-usage-configuration.md)的 AC-03 及完整设计 AC-25/26，由[原 Task](../tasks/2026-09-21-ai-provider-model-usage-configuration.md)持有最终状态。现有实现只有 `migration/dry-run` 规划，不能证明数据库值迁移、冲突事务及重复执行幂等。本次不调用模型、修改凭据或开启用途。

## 状态与操作边界

- 新增 AI 模块拥有的维护 CLI；默认只读预览，不新增 HTTP 或界面入口，不在启动、普通读取或保存时自动迁移。
- 预览精确限定 `type=ai` 及可选 Provider 名称，返回数据库/角色、原始数据指纹、逐项修订、精确价格文本、待补模型、保留模型与冲突。指纹绑定行 ID、范围、修订及完整原始 JSON 文本；不返回完整 settings 或凭据。
- 应用必须显式给出预览指纹和数据库/角色。缺失范围、数据库身份不符、预览过期或任一选中项冲突时整批不写。复用既有 AI 配置/默认设置跨进程事务栅栏，并使用原行修订/原 JSON 的条件更新。
- 只有全部选中项已完成或无需迁移时可返回只读 no-op；重复执行不再次变更时间或追加审计。仍有待迁移项时必须与预览指纹一致，不能把重复执行当作覆盖新编辑的许可。

## 保留数据的执行面

模型级已存在价格完整保留，包括显式未知字段和旧版本元数据；只为本次模型列表中没有价格项的模型复制完整旧价格。显式零值保持零，不完整/非法旧价格或重复用途路由报告冲突，不合并或补零。

实际更新由 PostgreSQL 的 JSONB 字段复制完成，不能将整个 settings 经 JavaScript 数值反序列化后写回。高精度 JSON 数字、其他设置和既有模型价格必须精确保留；维护预览/审计用数据库提取的价格文本，不以浮点预览代替原值。

成功迁移后删除三个 Provider 级旧价格键，价格原值在模型项和本事务审计中保留，防止未来新增模型隐式继承全局价格。即使现有模型均已有价格，也须明确清除旧全局键；后续新增模型保持未知。

每个实际变更 Provider 追加一条 `AuditLog`，记录原价格精确文本、补齐/保留模型、来源指纹及前后修订。修订必须推进且对齐现行毫秒版本格式；旧微秒修订不能导致后续 API 条件更新永远失败。任一步失败回滚全部价格、修订与审计。

不修改名称、类型、启用、优先级、能力、凭据、健康、quota/cost、默认引用、路由、历史任务、费用事实或业务数据；不引入数据库结构变更。已有非法模型价格的已知字段应报告冲突，未知元数据保留。

## 验收

1. 规划检查覆盖完整/零/缺失/非法价格、已有模型级值与路由冲突；不输出凭据。
2. 正式隔离 PostgreSQL 验证精确 JSON 值、审计、未来模型不继承、同计划重试无第二次写入、预览后编辑拒绝、跨进程应用竞争及中途故障整批回滚。其他配置、默认和历史任务逐字段不变。
3. CLI 参数缺失或错误在连接数据库前拒绝；默认预览只读，显式应用有目标及指纹约束。
4. 定向→类型/构建→工程门禁通过后，按正式最小更新入口同步；目标仅只读预览、实际模块摘要和完整保护对账，不为造旧记录向目标写入 legacy 配置。只有对应证据足够才关闭原 AC-25/26；真实模型和其他完整 AC 保持原边界。
