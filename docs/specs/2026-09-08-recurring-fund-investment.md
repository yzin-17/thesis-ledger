# 基金定投计划 Spec

- 日期：2026-09-08
- 状态：实现完成，待运行时验收
- 适用项目：`thesis-ledger`
- 类型：增量设计

## 背景与问题

基金账户的成交记录目前只能逐笔录入真实成交，无法表达“每月固定金额申购某只场外基金”的持续计划。定投到期时系统也不能假设外部基金平台已经成交，因此不能直接制造真实账本事实。

## 目标

1. 在基金账户的“成交记录”中创建和管理月度固定金额定投计划。
2. 到期生成待确认记录；用户核对实际份额、单位净值、费用和成交日期后，才写入一次真实 `BUY_EXECUTION`。
3. 复用现有 Automation Scheduler 补齐服务停机期间的启用月份，并保持计划月份与确认写账幂等。

## 非目标

- 不连接外部基金平台下单，不自动写入 Ledger。
- 不支持证券账户、现金账户、模拟账户、每周计划、工作日顺延、目标市值或按比例定投。
- 本轮不新增定投通知渠道，也不修改现有定期现金入账语义。

## 现状与约束

- 基金账户只允许持有 `.OF` 场外基金，成交资产必须先完成身份确认。
- 真实成交由 Ledger V2 的 `CREATE_EXECUTION` 写入，并由账本投影统一更新份额与现金。
- 定期现金入账已有月末截断、暂停区间、漏期补齐和待确认状态机，但它属于现金账户领域，不能直接复用其模型或文案。
- 调度必须进入现有 Automation，不创建第二套 Scheduler。

## 设计方案

### 计划与到期记录

计划绑定一个启用中的真实基金账户和一个已确认的 `.OF` 基金标的，保存计划名称、每月计划金额、账户币种、每月日期、开始月份、`Asia/Shanghai` 时区、状态、下次到期时间和乐观版本。每月日期为 1–31；当月不存在该日期时取月末；到期时间为当地 09:00。

到期记录以 `planId + periodKey` 唯一，并冻结计划名称、标的、基金名称、计划金额、币种和计划时间。新记录为 `PENDING`；跳过后为 `SKIPPED`；确认后为 `CONFIRMED`。

### 确认成交

确认时要求填写实际份额、单位净值和成交日期，手续费可选且必须使用计划币种。系统以稳定的定投实例 ID 作为来源外部 ID，写入 `BUY_EXECUTION`；同一实例重复确认不重复写账。确认与实例状态变化必须在同一账户写事务中完成。

### 自动化

现有 Scheduler 增加一个固定的 `fund-investment-materialization` Handler。它扫描到期计划，补齐启用期间的全部月份；暂停月份不补齐，恢复后从恢复月份继续，结束后不再生成记录。

### Desktop

基金账户的“成交记录”内新增“基金定投”区域，展示待确认记录和计划列表。用户可创建、编辑、暂停、恢复、结束计划；待确认记录可确认或跳过，已跳过记录可恢复。非真实基金账户不显示入口。

## 对外行为或接口变化

- 新增定投计划列表、创建、修改、暂停、恢复和结束接口。
- 新增到期记录列表、确认、跳过和恢复接口。
- API 金额、份额和净值继续使用规范十进制字符串；所有状态变更携带预期版本。

## 数据、状态或兼容性影响

- 新增 `RecurringFundInvestmentPlan` 与 `RecurringFundInvestmentOccurrence`，不修改已有 LedgerEvent 结构。
- 新增 Automation Job 类型和固定任务；旧数据与定期现金入账接口保持兼容。

## 测试策略

### 关键可观察行为

- 非真实基金账户和非 `.OF` 标的无法创建计划。
- 到期只生成待确认记录，不改变 Ledger；确认后恰好生成一次买入成交。
- 暂停、恢复、结束、跳过、恢复待确认与并发补期保持确定状态。
- Desktop 只在真实基金账户成交页显示完整入口和操作。

### 优先测试层级

Schema 与日期纯函数 → Server Service/API → Automation Handler → Desktop API/UI → 浏览器验收。

### 可复用的现有测试入口

- 定期现金入账的日期、状态机、Automation runtime 和 Desktop cash 测试模式。
- Ledger V2 execution command 与账户资产类型验证测试。

### 需要新增的测试入口

- 定投 Schema、Service、Automation runtime 和成交页 UI 定向测试。

### 关键边界与回归场景

- 月末截断、重复物化、重复确认、版本冲突、错误账户/标的、跳过恢复和现有成交录入不回归。

## 风险与备选方案

- 直接按计划金额推导基金份额会把未知费率和外部确认结果伪装成事实，因此确认时录入实际份额和单位净值。
- 直接复用定期现金入账模型会混淆外部入金与基金申购，故采用独立模型但复用其已验证的调度模式。

## 未决问题

### Blocking

无。

### Non-blocking

- 默认手续费为可选单项 `COMMISSION`；更复杂费用仍可在成交写入后通过既有“更正成交”补充。本轮不扩展费用类别交互。

## 验收标准

- AC1：启用中的真实基金账户可为已确认 `.OF` 基金创建月度固定金额计划，其他账户或标的被拒绝。
- AC2：到期只生成唯一 `PENDING` 记录，不改变 Ledger；停机恢复后补齐启用期间漏期。
- AC3：确认实际份额、单位净值、可选手续费和日期后恰好写入一次 `BUY_EXECUTION`，并可在成交记录中看到。
- AC4：计划支持编辑、暂停、恢复和结束；到期记录支持跳过和恢复，乐观版本冲突可识别。
- AC5：基金账户成交页提供定投入口、待确认列表和计划管理，其他账户不显示。
- AC6：既有逐笔成交、定期现金入账和 Automation 行为保持兼容。
