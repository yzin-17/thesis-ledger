> 状态：本主题实施、分层验证与获准的目标 Web 保存验收完成；现行产品合同继续有效
> 对应任务：[已完成实施记录](../archive/tasks/2026-10-19-ai-provider-database-only.md)

## 背景与目标

AI Provider 当前同时支持数据库与部署环境来源，启动注册和动态刷新均会读取部署配置。现统一为：页面是产品配置入口，数据库是唯一持久化事实源，服务端负责校验、加密和调用。

本规格取代 [OpenRouter 接入规格](2026-09-14-openrouter-free-ai-provider.md) 的环境来源、同名覆盖、接管与删除后重现合同；其他配置、验证、费用和业务验收义务保持原有边界。

## 设计与行为

1. Server 不解析或消费 `AI_PROVIDER_CONFIGS_JSON`、`AI_PROVIDER_ID`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`；遗留值无论合法或非法均不影响启动和 Provider 列表。取消 `AI_FIXTURE_ENABLED` 及测试环境隐式注册，测试替身仅由测试显式注入。
2. Registry 初始为空，由 `AiProviderService` 启动加载数据库。创建、更新、启停和删除后按既有原子替换机制刷新；查询失败明确报错，不合并其他配置来源。刷新失败保留上一份完整快照，不发布部分状态。
3. 无配置时 Server 可启动，页面显示新增入口，业务生成在发送前按既有路由门禁拒绝，并引导用户到配置页。数据库不可用与数据库为空必须区分。
4. 页面删除部署来源标签、接管入口和相关草稿状态，统一提供新增、编辑、启停、删除。保留模型目录、用途验证、执行路由、价格、默认引用保护、版本竞争和未保存保护。
5. API 路径和数据库结构保持不变。摘要 `source` 暂保留固定值 `database`，兼容现有读取方；任何服务端接口均不返回环境来源记录。
6. API Key 仍由服务端加密落库、脱敏回读；编辑留空保留已存凭证。`authMode = none` 的服务继续按既有合同使用。数据库连接、`CREDENTIAL_ENCRYPTION_KEY`、超时、预算策略与功能开关等基础设施配置仍由部署环境管理。

## 兼容与部署

- 保留所有现有数据库记录、加密凭证与历史任务，不执行自动导入或清理。
- 仅存在于环境中的 Provider 升级后不再可用，部署指南须在更新前提示通过页面重新录入。不得读取实际凭证生成迁移文件。
- infra Compose、示例配置和契约测试移除上述透传项；实际 `.env` 不改写。生产/开发运行态更新仍只通过正式脚本进行。
- 本次不改变市场数据、通知 Provider、数据库 Schema、Worker 生命周期、业务生成预算和暂停状态；不调用真实外部模型。

## 测试策略与验收

- AC1：遗留 Provider 环境变量和演示开关无论合法或非法，均不影响配置解析、启动注册、列表与能力；没有隐藏回退。
- AC2：数据库配置支持创建、编辑留空保留密钥、启停、删除与重新加载；停用与删除后不因遗留环境变量恢复。现有默认引用和版本竞争约束保留。
- AC3：数据库为空时启动和查询成功、没有 Provider；数据库查询或刷新失败明确报错且原 Registry 不被部分替换。
- AC4：页面只有统一配置流程；不出现部署来源和接管操作；空态可新增，保存后可编辑且密钥不回显。
- AC5：部署模板、错误提示和现行文档使用同一合同，迁移提示完整，基础设施配置仍保留。
- AC6：定向服务/客户端测试、类型检查、包构建与相关仓库门禁通过。隔离持久化/重启语义和浏览器交互独立记录；目标 Docker 验收须独立保留状态，不能由本地测试替代。

测试先验证定向行为，再执行受影响包检查和仓库门禁。目标运行态采用只读验收，不修改实际凭证、默认值或启用状态；若无法在该边界证明保存闭环，保留独立验收项，不把历史证据当作本次验证。

2026-10-20 用户单独授权 T5-W 的临时配置例外：通过正式维护入口创建 `controlled-web-save-20261020`，保持停用、无密钥、无用途路由；仅在 Web 将优先级 991 改为 992，再删除并核对原配置、默认、密文和业务数据恢复。该例外仅覆盖此条专用配置，真实连接、生成和原有配置继续保持原边界；本轮客户端只验 Web。

## 风险与未决问题

仅环境配置的服务会在升级后消失，必须执行上述重新录入流程。没有阻止本地实施的未决问题；实际部署和真实凭证验证与本地实施分开。
