# 数据质量问题自动记录

对应任务：[已完成实施任务](../archive/tasks/2026-11-09-data-quality-observation-log.md)

## 目标与边界

把已有业务读取中的明确数据质量异常写入 `DataQualityIssue`，使诊断页可以定位问题。复用现有表、查询和人工关闭接口，不新增检测任务、数据库结构、远程探针或历史补录。

首批接入当前报价、基金净值与净值历史、基金持仓、日线窗口与交互 K 线，以及实际交易日历的既有响应校验。记录响应格式错误、响应标的不匹配、响应合同不一致，以及实际请求需要的日历无效或覆盖缺失。输入参数错误、来源超时或离线、认证与权限不足、未配置、路由关闭或修订变化、正常休市、正常前一交易日净值均不属于本次数据质量记录。损坏缓存不归因于上游来源；研究冻结和已有业务事实保持原语义。

## 验收合同

- AC1：上述业务校验实际失败时自动写入问题，保留能力、可信请求中的来源和完整标的、稳定错误码、中文说明、首次与最近发生时间、发生次数。只有明确校验或合同错误才记录，不从原始异常中文文本推断类别。
- AC2：同一能力、来源、标的、错误码及稳定请求范围的未关闭问题并发合并，增加次数及最近发生时间；人工确认状态保留，关闭后再次发生创建新记录。成功读取不自动关闭历史问题，不修改原记录的首次发现时间。
- AC3：日志只包含允许的摘要字段，不保存响应正文、凭证、请求头、URL、原始错误文本或金额数据。记录失败输出安全告警，但不得覆盖原业务错误、取消信号、缓存降级或成功结果；不得新增上游调用。
- AC4：诊断区使用“未关闭的数据质量问题”，包括待处理与已确认但未关闭的问题，显示实际记录的发生时间与次数。空白不能解释为全部数据健康，读取失败不能解释为成功为空，既有查询与刷新状态继续复用。
- AC5：验证严格分层：定向单测与相邻回归、隔离 PostgreSQL 的并发合并及关闭后再发生、受控业务校验到真实持久化再到查询的闭环、目标模块装配及真实浏览器只读验收分别记录。不在真实共享库制造测试问题，不向真实 Provider 请求失败样本。

## 所有权与依赖

Quality 拥有问题持久化、并发合并和生命周期；Market 拥有现有数据校验及将其投影为通用观察记录的边界。沿用 `MarketModule -> QualityModule`，Quality 不反向依赖行情、DSA 或 Provider 协议。`DataQualityIssue` 的事实不参与报价、估值、交易与回测计算。

无需 migration；使用有界数据库事务及按问题指纹的事务级锁维护现有 JSON 摘要。部署使用 infra 正式入口的最小 `thesis-ledger` 目标，兼容性预检必须通过。真实来源调用、模型调用、故障注入、通知投递和共享业务数据修改均不属于本次验证。
