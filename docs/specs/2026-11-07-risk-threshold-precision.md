# 风险百分比阈值的原值与展示

## 问题与目标

风险规则两端都在打开时把比例阈值乘以 100，再在提交时除以 100。只修改严重级别等其他字段也可能改变原比例。Desktop 同时把阈值展示与输入直接绑定，普通百分比长尾影响阅读。

保留现有 number API、风险类型、账户约束和范围限制。明确 Domain 的比例与百分比单位合同，配置目标通过自己的语义导出消费该合同，风险编辑器直接消费稳定单位接口，不反向引用配置目标或另一客户端。

## 验收标准

- AC1：Desktop 实际表单和 Mobile 命令在未编辑阈值、仅聚焦失焦或只改严重级别时，提交比例与原 number 相同。
- AC2：长小数、极小非零值、Number.MIN_VALUE、零及非法输入得到明确处理；百分比须大于 0 且不超过 100%，非零下溢不能变成零提交，规则预览及当前阈值摘要不能把极小非零值显示为零；常规精度会归零的摘要使用科学计数展示，输入仍保留完整原值。其他原始数值规则仍按原合同校验。
- AC3：Desktop 复用 DecimalInput，失焦适度压缩、聚焦恢复完整文本，焦点变化不脏；失败保留输入。说明直接表达业务范围，不展示内部转换过程。
- AC4：原证券/账户/组合范围、必需账户、已有绑定清空限制、只读、pending、导航保护和命令错误恢复均保留；配置目标既有回归继续通过。
- AC5：Domain、两端定向及完整包、构建、适用门禁通过；1440/1024/768/390 真实 Desktop 编辑器验证实际提交、焦点、失败保稿及边界，业务请求与写入为 0。

## 边界与所有权

比例单位转换是稳定、跨应用、无业务编排的 Domain 合同，放在明确的 ratio-percent 模块。保留配置目标现有语义导出；不增加 common/utils 目录，不移动风险类型与账户编排。复用已核对的 es-toolkit 1.51.0 选型证据：round、compat multiply/divide 不满足原值无损往返，使用原生文本位移。后者已有测试，本轮不复制实现。

风险执行、通知、估值、服务器协议、历史规则和真实数据保持原范围；不修改数据库、依赖或原生工程，不执行 Docker、外部来源或模型调用。
