# 任务状态对账规格

> 任务标识：`task-state-reconciliation`
> 日期：2026-10-03
> 对应任务：[文档对账任务](../archive/tasks/2026-10-03-task-state-reconciliation.md)

## 目标与范围

核对当前 Spec、Task、Review、TODO、导航与已有验收证据，修正旧环境阻塞、被替代的执行入口、重复门禁和取消计划造成的状态误导。各功能 Task 继续拥有实施与验收状态，本主题只拥有文档治理的执行记录。

仅修改说明性文档；允许读取三仓状态、现有源码、脱敏日志和本机无副作用的存量查询。保留所有既有改动，不提交、推送、修改应用或部署输入，不创建业务数据，不请求真实 Provider，不更新容器或进行故障注入。对账完成后列出建议顺序，由用户选择下一项。

## 状态与证据规则

剩余义务在原权威 Task 中区分：未实现、部分实现、已实现待验收、真实前置阻塞、用户取消或跳过、已完成且已有证据有效。一个 Task 可以包含多种状态，不能用单一包级成功或健康检查关闭全部验收。

任务清单的未勾选项必须与当前范围一致。历史失败和已取消计划允许保留原文，但须明确历史时点和当前归属；取消不改成通过。原 Spec 的验收断言只有在后继任务明确承接、证据范围匹配或用户已有范围修订时才能标记替代。没有证据的义务保留未勾选，不迁入 TODO。

复用验证须核对输入、断言、版本及环境；区分本地测试、隔离数据库、目标运行态、真实来源、浏览器与 Electron/原生设备。历史集成测试中的环境跳过不计通过，单独执行证据只覆盖其实际场景。

README 只提供分类与链接；Review 保存对账依据，不建立第二套功能状态表。TODO 只索引已明确延期且尚未正式立项的实现，已有 successor 的义务由 successor 跟踪。归档只移动完成全部声明范围的 Task，保留原证据与稳定标识，当前产品 Spec 可继续保留。

## 验收标准

- AC01：记录三仓初始状态与只读核对边界，全部写入限定为中文说明性文档。
- AC02：旧 404、旧备用源要求、旧 V1/V2 路径和过期测试环境结论有准确的当前状态与证据边界；无证据的验收不补勾。
- AC03：原 Spec 断言、后继责任及未覆盖义务能够追溯；取消/跳过不再作为待用户输入或当前强制动作。
- AC04：Task、TODO 和轻量导航一致，已完成条目退出当前实施分类，当前义务不转入 TODO；相对文件链接、锚点、差异和写入范围检查通过。
- AC05：完成一次最终一致性 Review，交接真正剩余的实现、验收及启动依赖，只提供后续顺序，不实施下一项。
