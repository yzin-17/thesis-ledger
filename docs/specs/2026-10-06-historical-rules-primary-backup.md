# 历史收费与特殊状态：主备数据源实施方案

> 日期：2026-10-06  
> 状态：P1～P5有界费用主备与首类日级停复牌闭环已完成目标验收，B1～B4费用与基准净收益闭环保留。000995真实任务、冻结重放、Web及诊断下载通过，旧complete／partial结果和policy40保留；P6其他状态及港股／美股按需求扩展，有限窗口不代表完整历史或严格PIT。
> 适用项目：ThesisLedger / DSA。  
> 对应任务：[主备数据源实施任务](../archive/tasks/2026-10-06-historical-rules-primary-backup.md)。已核对当前代码接缝；各项实际实施与运行验收状态以 Task 为准。

> 2026-10-09 后续入口：股票结构化状态、基础生命周期与有界 ETF 分红候选的按需扩展由[新 Spec](2026-10-09-history-data-on-demand.md)及[Task](../tasks/2026-10-09-history-data-on-demand.md)承接。原费用/P6 的完成范围保持；新主题不重开本页已完成任务，也不新增完整历史证明义务。

## 1. 最终决策

**优先让系统跑起来：复用现有数据源配置、主备路由和 Snapshot，只增加计算真正需要的能力，不建设额外的准入、证据或审计系统。**

### 首批冻结与执行接缝

真实运行阶段沿用已实现的腾讯原生股票日线适配，将 `CN / STOCK / DAILY_BAR / 1d / none,qfq`、`tencent / tencent` 接到基础价格配置路径。两种口径已实际读取同一标的窗口；股票 hfq、其他股票来源及扩展能力继续保持各自状态。回测研究沿用现有 qfq 归一化、固定 Provider 快照协议，公共费用按模拟成交额计算；实际请求决定覆盖结果。

真实场景窗口扩展为 `2023-08-23..2023-08-29`，使现金起始、下一交易日成交的策略能在 08-25 与 08-29 分别卖出并验证费率变化。原公共文件中变化前费率在新增两日仍适用，生产包只扩展这两日的声明范围；不扩展为完整历史。P2 的 `08-25..29` 请求样本继续作为原合同回归切片，其内容版本随生产包更新。

公共收费独立冻结到 `metadata/public-fees-v3.parquet`，由现有 manifest 的可选引用和 Artifact 哈希覆盖；原 RunConfig、已选执行模型及其内容哈希保持原身份。完整响应包含来源文件、内容版本与历史可用时钟限制，不写回旧 Snapshot。

创建新股票 Snapshot 时按整个执行区间读取当前收费路由一次；无配置、来源不可用或缺少可计算设置时，冻结使用已选执行模型的原因。已存在 finalized Snapshot 直接重放，不重新读取收费。只有已选模型才能提供收费兜底，不将未知费用自动改成零。

Runner 在原身份校验后，将冻结公共费率与原模型的日期分段求交。公共费项已单独计费时只替换费率、买卖侧和币种，保留最低额、取整与扣收分组；包含于佣金的项目保持包含关系。若公共费用在模型中标记不适用且没有计算设置，首批使用原模型并明确原因。佣金、价格限制、结算与单位规则不因收费源改变。原模型历史事实的 `knownAt` 通过研究组合来源的可选 `historicalKnownAt` 保留，按原事件时钟继续约束执行。策略和基准共用同一组合模型，结果另行披露收费来源或模型兜底；组合模型表达研究配置，不整体声明为历史事实。

第一条交付链路：

```text
配置可用主源 → 取得收费或状态数据 → 使用已有计算链路 → 冻结 Snapshot → 完成回测
```

随后补齐备用源：

```text
主源失败或返回数据不能满足本次计算
  → 尝试用户配置的备用源
  → 仍不可用：使用已明确选择的研究假设，或者对必要依赖报错
```

主备源不必同时具备才能上线。不能因为港股、美股或某类特殊状态尚未接入，阻塞已经可用的市场与普通价格研究。

## 2. 范围与边界

### 2.1 纳入现有数据源配置

在现有页面增加“历史规则与状态”分组，默认按“市场 × 资产类型 × 数据能力”配置主备；已有路由需要交易场所、通道或粒度时沿用，不预先扩展复杂配置矩阵。

| 逻辑能力 | 内容 | 首版处理 |
| --- | --- | --- |
| 历史公共收费 | 税费、交易所及结算费用、豁免和暂停征收 | 优先接入一个实际可用来源 |
| 历史交易制度 | 价格限制、交易单位、价格档位、结算及可卖规则 | 复用现有能力，按实际来源补充 |
| 历史停复牌 | 整日或盘中停牌、复牌记录 | 优先支持与当前回测粒度匹配的数据 |
| 历史风险标记 | ST 等市场原生标记及解除记录 | 有源则接入，不作为所有研究的前置 |
| 历史上市状态 | 上市、退市和必要身份变化 | 有源则接入，不用当前状态覆盖历史 |

上表是逻辑划分，落地时复用已有 capability、RouteTarget 与 Schema；不得另造一套平行路由协议。

分红、拆股继续复用既有公司行动能力，不重复建设。券商佣金和用户费用假设单独配置，不作为公共收费的备用源。

### 2.2 首版不做

- 不要求三市场、全部标的、全部历史年份一次覆盖，也不逐证券、逐区间申请人工准入。
- 不强制双源对账、完整历史证明、独立证据平台、复杂审核后台或新微服务。
- 不为普通回测额外抓取公告、批量探测接口、反复核对全部外部来源；不要求每条规则人工审批。

不做上述工程门禁不等于绕过供应商账号权限或已知使用限制；按实际接口权限接入即可，不把证明流程另建成产品。

## 3. 主备路由

### 3.1 配置与职责

每条能力配置一个主源、最多一个备用源；备用可为空。沿用现有保存、凭据管理、健康状态、超时和路由修订机制。

- 前端：选择来源并展示实际结果，不新增单独的审批或验证流程。
- 统一路由层：明确执行主备选择，记录实际选中来源与回退原因。
- Provider：只负责对应来源的读取和规范化，不在内部偷偷调用第三家。
- Runner：只消费 Snapshot，不执行外部选源。

主源和备用源采用同样的必要计算检查。不能为了“能返回结果”把备用源口径、粒度或标的改掉。

### 3.2 切换条件

| 情况 | 行为 |
| --- | --- |
| 主源未配置必要凭据，或明确不支持请求能力 | 直接尝试已配置备用源，不增加网络探测 |
| 主源超时、限流、接口失败 | 按现有有界请求策略尝试备用源 |
| 主源必要字段缺失、明显身份错误、必要区间数据不足 | 本次主源结果不可用，尝试备用源 |
| 返回合法空事件集 | 按接口语义处理；空数组本身不触发切源，也不自行证明全区间正常 |
| 主备均不可用 | 根据本次实际依赖和已选择的研究假设继续或报错 |

不增加无限重试，不要求主备同时请求。若以后发现两源事实冲突，记录问题并修正来源数据；首版不为了寻找冲突而逐次双读。

### 3.3 替换粒度

**同一标的、同一能力、同一请求区间整体替换。** 不把主源部分数据和备用源部分数据自动拼接。

允许收费来自 A、停复牌来自 B，因为它们是不同能力。某个收费源内部按日期返回多个历史费率版本，也是正常行为，不属于跨源拼接。

切换只发生在 Snapshot 准备阶段；选中后冻结。修改配置、上游修订、主源恢复，都不改变已有 Snapshot 的执行数据。

## 4. 最小数据契约

不以完善抽象为前置。先查看现有合同，只补计算缺失的字段，以下为逻辑字段要求而非另建协议的要求。

### 4.1 历史收费

首版需要表达：

| 字段 | 用途 |
| --- | --- |
| 费用代码、适用市场/资产、买卖侧 | 确定是否适用于本次交易 |
| 生效起点、可选终点 | 按历史日期选择费率，不拿当前费率回填历史 |
| 收费方式与参数 | 使用现有或有限的金额比例、每股、固定金额公式 |
| 币种 | 保持金额口径明确 |
| 最低额、最高额、取整与计费分组 | 仅在所接入规则需要时补充，不提前实现复杂表达式系统 |
| 豁免或暂停状态 | 区分明确不收费与数据未知 |

金额计算复用现有 Decimal/货币工具。按实际来源要求处理最低收费、费用分组和取整，不用一个通用默认值冒充所有市场规则。

客户佣金保持独立配置。已知包含某项公共费用时避免重复扣费；包含关系未知时明确费用口径，不宣称已复原券商实际账单。

### 4.2 特殊状态

状态分维度记录：交易状态、风险标记、上市状态、价格约束可以同时存在，不做互斥的总状态枚举。

优先消费来源已有的日状态或事件，不要求每家 Provider 实现复杂的事件存储。来源提供日期就保留日期，提供盘中时间才使用盘中粒度，不补造精度。

必要字段为证券身份、生效日期或时间、状态类型及值；来源有发布时间等字段就保留。

停牌与复牌分别在各自生效时应用。策略只读模拟时点可用的视图，不暴露未来复牌日期。来源没有可靠历史可用时间时不声称严格 PIT，但也不因此阻塞不依赖该证明的价格研究。

### 4.3 来源元数据

自动保存实际 Provider、实际上游、请求区间、采集时间、来源已有版本或系统生成摘要。来源有公告地址、生效时间、发布时间时一并保留。

这些是响应与 Snapshot 元数据，不是需要用户提交的证据包。没有供应商修订号时可生成内容摘要，不因缺少“稳定官方版本号”阻塞普通运行。

采集时间与历史生效时间分开；不得把今天的采集时间或公告日期自动冒充当年的公开可用时刻。

## 5. 收费来源与拉取

### 5.1 官方规则整理库作为普通 Provider

```text
官方公告或其他可用规则数据
  → 导入/整理必要历史收费记录
  → 本地版本化数据包或现有存储
  → 收费 Provider
  → 统一主备路由
```

可以先提供维护好的 JSON/YAML 规则包，记录来源和生效日期，不等待自动采集或审核后台。规则数据不能用测试 fixture 冒充真实来源，也不能把当前值直接覆盖过去。

第一段历史至少取得起点有效规则及区间内已知变化；针对本次使用的费用核对即可，不先建设全市场法规档案。

### 5.2 拉取时机

收费按版本保存、按需扩展历史区间，不逐交易日下载公告。特殊状态按 Provider 的现有批量能力和历史窗口读取、缓存，复用既有请求基础设施。

回测创建时查询已有数据或对应 Provider；Runner 不临时抓公告或联网补数据。

### 5.3 更新发现

首版保留人工触发更新即可。跑通真实链路后，再按需要接入 changedetection.io 或现有定时任务发现公告变化，不同时部署多套监测系统。

公告监测是数据维护入口，不是可直接替代收费数据的备用源。监测失败提示更新状态未知，不使已有 Snapshot 失效。

## 6. 最小校验与可用性策略

### 6.1 只保留三类检查

1. **能够调用：**必要配置可用，以实际请求结果为准，不另加每次运行前的探针。
2. **能够计算：**必要字段存在、身份与日期没有明显错误、参与计算的数值合法；对实际命中的冲突或缺失给出错误。
3. **失败可处理：**主源失败可尝试备用；两者均不可用时，明确使用已选假设或报告必要输入缺失。

能从返回数据直接判断的问题就在规范化时处理一次，复用现有边界校验，不在 Provider、路由、Server、Runner 四层重复实现同一套证明逻辑。

不额外索要全历史完整性证书，不为补齐元数据反复联网，不要求所有高级能力先就绪。

### 6.2 按实际依赖处理缺失

| 缺失场景 | 行为 |
| --- | --- |
| 公共收费不可用，但运行已明确选择费用模型 | 使用该模型并在结果标明，不静默假设免费 |
| 特殊状态不可用，普通价格研究不依赖它 | 继续研究，注明未纳入该类真实约束 |
| 状态未知，但运行已选择相应简化假设 | 按假设执行并披露，不改标为“已确认正常” |
| 本次计算必须使用某项真实输入，且无已选替代模型 | 报告该能力、标的和区间缺失，不输出虚假的正常结果 |
| 分红、拆股等未启用业务能力缺失 | 不阻塞与之无关的研究；实际依赖它们的记账仍按现有要求处理 |

不把缺行情自动解释为停牌，不把无事件记录一律解释为已确认正常。主源有数据也不自动宣传“全市场完整历史支持”。

## 7. Snapshot 与执行

复用现有 Snapshot 流程，冻结实际用于计算的收费、状态、选源结果、版本或摘要，以及已选研究假设。

```text
确定本次依赖与请求范围
  → 统一路由取得结果
  → 完成必要计算检查或选择已配置模型
  → 保存实际内容与来源元数据
  → 进入现有队列和 Runner
```

只保存可变化的 URL 或数据库主键不足以离线重放，应复用现有内容冻结方式。无需新建独立发布平台或审核流程。

收费默认按实际可能成交的执行区间读取。策略确实使用预热状态时再扩展对应数据范围；结算等已有消费者需要尾部日期时按该依赖扩展，不对全部能力一刀切索取完整预热区间。

Runner 不再检查官网是否在线、账号是否过期或监测工具是否成功；同一 Snapshot 的运行与重试不切源、不重取外部数据。本次不迁移、重写历史记录，也不写真实账户事实域。

收费规则描述“该收多少钱”，状态规则描述“何时允许交易”；仅有日线仍需沿用明确的撮合假设，不能用触及涨跌停价保证成交。相关假设按已有方式冻结即可，不扩建撮合系统。

<a id="benchmark-net-return"></a>
### 7.1 基准净收益：复用已有逐笔费用计算

当前计算边界：`calculateBacktestV3BenchmarkReturn` 复用策略使用的 `calculateExecutionModelFees`，并以 `fitNormalizedQuantityToAvailableCash` 约束买入资金。执行模型型合同、版本化解析、结果消费与有界目标验收已按B1～B4完成；新快照支持完整冻结费用，旧快照沿用原对称比例摘要。不另造基准收费计算器，不新增收费来源，具体证据与覆盖边界以Task为准。

- 策略和基准消费同一份冻结公共费率与用户费用设置的组合模型，但按各自成交日期、方向和金额分别计费。支持现有计算器已支持的最低佣金、买卖分向收费和生效日切换，保留含规费关系、逐项取整和滑点设置；不使用策略总费用、平均费率或一个比例参数替代基准逐笔计算。
- 保留当前基准的“首个对齐日收盘买入、最后对齐日收盘清算”定义。因此基准末日卖出计费是已有模拟交易，不是新增交易；不顺带改变策略的期末持仓估值规则。双方成交、资金比例及期末定义分别披露。将来若增加期末持有估值模式，未卖出就不扣卖费，该模式不在本批范围。
- 成本假设增加执行模型型描述，用已有版本／指纹绑定实际冻结费则和计算设置；保留旧 zero-cost／proportional／unsupported 的明确语义，不把最低额或分向模型伪装成比例费。兼容性比较的是采用的规则，不要求策略与基准的成交次数、金额或已付费用相同。只拿比例摘要的旧快捷算法不能猜算最低费，必须由已有执行模型路径提供结果。
  - B1 合同为 `{ kind: 'execution-model', version, fingerprint }`。`version` 标识计算语义，`fingerprint` 沿用确定性报告校验和的16位小写十六进制格式，绑定完整冻结费用分段和计算设置，包括生效区间、币种、收费方向、计费基础、最低额、包含关系、逐项取整与滑点。摘要生成由 B2 的冻结模型解析入口负责，合同不接收已付总费用或成交列表。
  - 同一计算版本和费用指纹可用于兼容比较，双方分别按自己的成交计算；费则或计算版本变化必须产生不同身份。旧两点价格快捷算法遇到该合同返回 `BENCHMARK_EXECUTION_MODEL_REQUIRED`，不能只凭版本／指纹推算费用。旧三类成本合同的读取和计算行为保持。
- 复用现有买入可负担数量求解，买入金额加费用不得超过基准可用资金；日期无适用费段、必要币种不匹配或计算器确实不支持的情况仍局部不可用。不能仅删除 `BENCHMARK_COST_MODEL_UNSUPPORTED` 判断就宣称支持。
- 结果至少提供策略净收益、基准净收益和口径兼容时的净收益差，并能核对基准买卖金额、费用、余额；不做短窗口年化包装。研究性质和部分指标状态按[个人研究结果可用性](2026-10-03-multi-source-remaining-acceptance.md#research-result-availability)解释，不以缺少未启用的严格 PIT 证明阻断普通比较。
  - B3 消费保持服务端逐指标状态：概览展示策略净收益、基准净收益与净收益差，后者要求兼容报告通过且双方收益有效；缺失或不可比较时展示具体原因，不在客户端计算替代结果。部分结果说明列出实际不可用项目，有效策略指标、权益与成交继续展示。
  - 执行模型型成本说明明确双方按各自日期、方向和金额逐笔计费，并在现有首末收盘基准协议有明确记录时说明末日清算及收益差定义。诊断导出升级为格式2，以既有白名单／脱敏规则增加原始基准指标、兼容报告及成本版本／指纹；格式1历史导出和持久结果不回写。
- 不改写历史 Snapshot、结果或校验和；新算法／成本描述使用可区分的现有版本字段。旧快照按原冻结版本保持读取和重放，新能力用新结果验收。仅在现有版本接缝内处理兼容，不新建平行引擎或批量迁移旧任务。
  - B2 核对发现现有 manifest 没有独立基准成本版本；在同一 `snapshot-manifest-v3` 增加可选 `benchmarkCostVersion: 'execution-model-cost-v1'`，由新股票／ETF Snapshot 创建入口写入并纳入内容哈希。旧快照缺字段时沿用原对称比例成本解析、身份和结果；已 finalized 快照复用时保留原字段集合。未知版本由严格 Schema 拒绝，缺省不自动升级。
  - 新版本成本身份覆盖同一完整冻结费用分段、适用范围／时区、记账口径和滑点，不包含已实现成交、初始资金或已付费用；各自资金决定各自买入量和结果。旧算法身份中已有的资金绑定仅为保留历史语义，继续留在旧版本路径。

首批仅用已验收的 `600000.SH`、`2023-08-23..2023-08-29` 固定快照场景验证；先沿用已有真实输入做离线对照，再验证新结果与页面。不扩展标的、日历、分红、PIT、状态或灾备作为这项修复的前置。

## 12. 实施验收标识与首批边界

P5 首类状态为 A 股日级停复牌，首个切片是 `000995.SZ`、`2023-08-16..2023-08-21`。使用皇台酒业在巨潮披露的 [2023-029 公告原件](https://static.cninfo.com.cn/finalpage/2023-08-17/1217557800.PDF)：明确 08-17 停牌一天，08-18 开市复牌。作为普通本地生产规则包读取，只将这两个日期记录为已知状态，其余日期返回 unknown；不从周末、缺行情或复牌安排推断未披露日期的正常状态。首次切片不应用公告中的风险警示、价格限制变更，这些属于其他独立维度。

停复牌复用 V3 data 路由，能力为 `HISTORICAL_TRADING_STATUS`；来源身份 `official-states / cn-stock-daily-suspension`。读取消费区间一次并冻结实际状态、来源、版本和未纳入真实约束时的原因；已知停牌接入执行器现有 suspended 约束，策略不读取未来复牌日期。没有状态源时，已有普通价格研究的明确假设继续有效，不能将 unknown 改为已确认正常。该来源的历史首次可见时间标记 notVerified，只用于既有固定来源快照研究；严格 PIT 维持原限制。

停复牌以 `frozen-trading-status-v1` 独立产物存入 `metadata/trading-status-v3.parquet`，引用和实际状态不写入原价格响应或执行模型。产物绑定原 RunConfig 校验和；实际来源响应还绑定 CN STOCK 标的与执行窗口，保留原始日级状态、公告、来源版本及整窗回退原因。未配置或全部来源不可用时冻结 `notIncluded` 与简短原因，沿用已有显式普通研究假设，不能构造正常状态。适用范围外不新增该产物；历史快照没有可选引用时继续原行为，已 finalized 快照不得回填。先独立交付读取／冻结接缝，再接入创建、执行和结果披露；基准版本与状态来源分别冻结，不能因加入状态字段升级旧基准计算。

Runner 只在内存执行视图中给当日已有行情附加 suspended 约束，不改冻结 Bar、可知时钟或策略信号输入。停牌日期无 Bar 时沿用原缺日行为，不补价格或交易时刻；已知复牌不清除其他已有执行约束，unknown 不生成正常事实。同一冻结状态也约束基准买卖日期：已知停牌报价不作为买入／清算时点，沿用现有缺日估值对齐；基准费用版本及计算器不变。结果新增可选停复牌披露，旧快照没有状态引用时不新增字段或说明，保持原结果与校验和。

P4 首个备用沿用 `official-rules` Provider，新增精确来源 `cn-stock-auction-fees-archive`，读取独立生产规则包。它使用另行核对的上海税务局公告、政府公开经手费及过户费转载；印花税法和监管费文件与主源共享政策依据。覆盖 `2023-08-22..2023-08-29`，金额设置和历史时钟限制保持现有契约。这是本地规则包的备用读取路径，能够承接主包读取失败或覆盖不足，不宣传为独立政策事实或官网在线容灾。

主源读取失败、必要区间不足或返回规则不能与已选模型组合时，均继续尝试已配置备用。实际使用备用时，将简短回退原因与完整备用响应一起冻结，并在结果中展示；旧 Snapshot 不要求新增字段。两源都失败继续沿用已选模型，不创建零费用默认值。目标验收使用主包不能覆盖而备用能覆盖的真实窗口验证切换，再用两包均不能覆盖的窗口验证模型兜底；不破坏目标文件、不停用其他路由。

P3.4 真实股票运行的必要依赖：沿用现有独立日历和上市事实接口，补入浦发银行官网披露的 `600000.SH` 首次交易日期及上交所 2023 年休市公告支持的 `2023-08-01..2023-08-31` 日历。该月无公告节假日休市，周末仍休市；范围包含此次价格预热。上市事实的 `knownAt` 使用实际引用文章的 2023-02-01 日期，不回填为 1999 年首次公开时间。只补当前计算所需事实，其他未知标的、未覆盖年份保持原行为。

P5.4 的必要上市事实补充为 `000995.SZ`：皇台酒业 [2020 年年度报告原件](https://static.cninfo.com.cn/finalpage/2021-04-28/1209836916.PDF) 印刷第6页明确2000-08-07在深交所上市交易。引用2021-04-28发布文档，按该日结束后的2021-04-29零点记录保守的 `knownAt`，不回填为2000年首次公开时钟。八月窗口复用现有独立日历，交易所会话仍包含08-17；个股停牌由独立状态维度约束，不能改写交易所日历或由缺行情推断状态。

- **AC1 收费主源：**复用 V3 `kind=data` RouteKey 和 RouteTarget，能读取一个明确市场/业务/区间内的公共收费，正确表达窗口内变化并保留来源与内容摘要。
- **AC2 冻结执行：**实际收费与已选研究计算配置进入 Snapshot，一个真实标的回测完成且重放不重新选源。
- **AC3 主备与假设：**同一能力整窗切换到已配置备用；两源均不可用时，只使用已明确选择的研究假设或报告必要输入缺失。
- **AC4 特殊状态：**接入一类实际可用状态并影响对应执行；未知保持未知，无关缺失不阻止普通价格研究。
- **AC5 可见性与兼容：**现有配置入口显示已接入能力，结果披露实际来源、回退或假设；既有回测与 Snapshot 行为保持兼容。
- **AC6 基准净收益：**按§7.1复用同一冻结规则及既有费用计算，支持最低佣金、分向费用和成交日费段变化；基准自身资金与费用独立复核，净收益及兼容比较可用，旧快照语义保持。
- **AC7 按指标解释结果：**已有效策略指标不因基准缺失被隐藏；比较缺失不补零，固定快照研究说明不单独制造 partial；新结果按实际必要缺口决定可用性，并经真实页面验证。
