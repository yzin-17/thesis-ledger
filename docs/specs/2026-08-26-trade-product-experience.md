# 交易与成交记录产品界面子 Spec

上位 Spec：[`2026-08-26-trade-execution-ledger-system.md`](2026-08-26-trade-execution-ledger-system.md)

依赖：[`交易账本写入与修正协议`](2026-08-26-trade-ledger-write-correction.md)、[`历史基线、导入与对账`](2026-08-26-trade-baseline-import-reconciliation.md)、[`Trade Projection 与收益读取模型`](2026-08-26-trade-projection-read-model.md)

## 背景与问题

当前“录入持仓”以当前状态维护为中心，用户无法自然录入真实成交、查看修正历史或理解 Trade 与 Position 的区别。Trade 分析若与录入混在同一页面，又会让用户误以为 Trade 是可编辑事实。

## 目标

- 让真实成交成为账户数据的默认录入方式。
- 将持仓、成交和现金作为三个平级账户事实视图。
- 将 Trade 列表、详情和复盘入口放在投资组合分析层。
- 清晰表达修正、Baseline、证据不足、多币种和待结算状态。

## 非目标

- Trade 直接编辑、合并或拆分。
- CSV 导入、券商同步和订单状态界面。
- 在界面自动提交 Baseline 对账建议。
- 将实际账户和影子账户的结果合并展示。

## 现状与约束

- Desktop 请求读取和 mutation 使用 TanStack Query。
- UI 复用现有 shadcn 组件和原子类，不新增页面级传统 CSS。
- 资产选择先通过 Instrument 搜索，再显式确认到 `Asset.symbol`。
- 可选字段不能以样例值、0 或显式 `undefined` 伪造完整数据。

## 设计方案

### 导航与账户数据

侧边栏“录入持仓”更名为“账户数据”。账户选择区继续显示账户名称、本位币和实际/影子模式。

账户数据使用三个同级页签，默认打开“成交记录”：

1. `持仓`：当前 Position、证据状态和次级“校准持仓余额”。
2. `成交记录`：主操作“录入成交”、当前有效成交历史、修正状态和其他账本事件筛选。
3. `现金`：按币种展示已结算余额、待结算应收/应付和证据完整度。

### 成交录入

表单字段：账户、标的、买入/卖出、数量、价格、成交币种、成交时间及精度、可选结算时间、费用明细和备注。

- 默认当前账户；影子账户明确标记“模拟成交”。
- 标的选择后展示市场、资产类型和规范 symbol；新 Instrument→Asset 关系必须确认。
- 数量和价格必须大于 0；能力元数据未知时显示“交易规则未验证”提示，但允许通用高精度校验后提交。
- 成交时间默认为当前时间，用户选择仅日期时不显示伪造时分秒。
- 提交使用稳定客户端命令 ID；重复重放不产生重复成功反馈。

### 修正与审计

成交列表默认只显示当前有效版本。每行展示已更正、已作废、来源和数据完整度；详情 Sheet 可展开完整 REPLACE/VOID/RESTORE 链。

- 操作名称使用“更正”“作废”“恢复”，不使用会暗示原地更新的“编辑”“删除”。
- 修正原因必填；陈旧 Ledger Revision 冲突后保留用户输入并提示刷新比较。
- 跨账户更正明确展示原账户作废和目标账户新建的双重影响。
- “其他账本事件”筛选展示 Baseline、余额观察、公司行动和对账事件。

### 持仓校准、导入与对账

- “校准持仓余额”说明其创建观察检查点，不代表真实成交，并可能降低 Trade 证据完整度。
- FULL/PARTIAL 批次提交前展示受影响资产，FULL 对缺失资产为 0 的影响必须二次确认。
- ImportDraft 页面展示有效行、重复行、冲突行、孤立卖出和原始证据入口。
- 对账候选展示确定性匹配依据、覆盖后残量及冲突；只有显式确认按钮写入账本。

### 投资组合 Trade 页面

投资组合内增加“交易”页签。列表支持当前模式、账户、资产、生命周期、退出进度、证据完整度和统计资格筛选。

列表字段：资产、账户、状态、开仓/最早证据时间、结束时间、总买入数量、剩余数量、平均买入/卖出价、已实现净收益、已实现净收益率、证据状态和排除原因。

Trade 详情包含：

- 基本信息、生命周期与证据状态。
- Entry Leg 与 Baseline Component。
- Close Slice 及其 Close Allocation。
- 公司行动、分红和费用明细。
- 原币结果、本位币折算状态和汇率证据。
- 账本证据与投影版本。
- 顶部“完整交易复盘”和每个 Close Slice 的“减仓复盘”入口。

Trade 始终只读；更正成交跳转到账户数据中的对应事实。

### 状态与异常

- 没有账户、没有成交、没有 Trade 分别使用 Empty。
- Query 加载使用 Skeleton；读取失败保留上次成功结果并提供局部重试。
- 投影世代变化使旧游标失效时，提示“数据已更新，请刷新”，不静默拼接。
- 汇率缺失时保留原币结果，本位币卡片显示不可用或部分可用。
- 旧 Trade 链接无法唯一解析时展示旧快照和需要重新确认，不自动跳到相似 Trade。
- 切换账户或实际/影子模式后清除不属于新上下文的选择、草稿和临时证据。

## 对外行为或接口变化

- Desktop 新增账户数据成交、现金和 Trade feature API/query/mutation 模块。
- Query key 必须包含账户、模式、筛选、Projection Generation 和分页游标等全部结果参数。
- Command 错误区分 Schema、幂等内容冲突、陈旧 Revision、投影冲突和服务错误。

## 数据、状态或兼容性影响

- 原“录入持仓”路径和导航迁移到“账户数据”，保留可理解的导航重定向但不保留两套页面实现。
- 当前持仓录入改名并降级为校准入口，不再隐式生成 BUY。
- Trade 页面不读取旧 Journal 候选作为数据源。

## 风险与备选方案

- 三页签增加导航层级，但多币种现金和成交审计需要独立空间。
- 证据与审计信息较多；默认列表保持业务摘要，详细链路放入 Sheet/详情。
- 账户数据默认进入成交记录会改变旧习惯，通过清晰持仓页签和导航文案降低迁移成本。

## 未决问题

无。

## 验收标准

1. 账户数据默认进入成交记录，并显示三个同级页签。
2. 录入成交是主操作，持仓校准不伪造成交。
3. 成交修正链可审计但默认列表不重复计数。
4. FULL/PARTIAL、ImportDraft 和对账影响在提交前可理解。
5. 现金按币种区分已结算和待结算。
6. Trade 列表与详情位于投资组合且不可直接编辑。
7. 完整 Trade 和 Close Slice 具有独立复盘入口。
8. 汇率缺失、证据不足、游标失效和旧链接歧义分别表达。
9. 实际/影子和账户切换不会复用旧上下文状态。
10. 浏览器验收覆盖键盘、焦点、错误关联和非颜色状态表达。
