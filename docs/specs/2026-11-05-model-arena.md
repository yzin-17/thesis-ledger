# 多模型模拟交易竞技场规格

标识：model-arena。首次建立：2026-11-05。[实施任务](../tasks/2026-11-05-model-arena.md) · [方案来源](../reviews/2026-11-05-thesis-ledger-feature-proposals.md#10-codex-本地复核)

## 使用方式与范围

Desktop「策略中心 → 模型竞技场」，Mobile「研究 → 策略 → 模型竞技场」。用户从目录选择标的，或复制自己的自选分组，配置并启动一场比赛。后台按交易日自主研究；模型各自决定买、减持／清仓、持有或空仓观望。比赛页负责配置、暂停、净值、排名、仓位和逐轮分歧，标的详情按所选比赛和模型显示模拟成交。无投资账户、无自选均可从策略中心建赛。读取与写入均按比赛 owner 授权，专用虚拟资金与用户实际／影子账本隔离。

首版同一市场、同一币种、只做多的股票与 ETF。每场选择 1 至 12 个不同的显式模型绑定、等额虚拟现金、同一规则；冻结标的池、市场日历、时区、赛期、初始本金、基准、仓位上限、费用／滑点、决策期限和预算。启动后变更协议另开一期。首个可运行市场取决于可证明的时点行情、交易限制及费用输入；缺失时拒绝相应配置或执行。基金申赎、杠杆、卖空、券商下单不在首版。

## 轮次和决策

每个交易日收盘后冻结公共材料（公布和可取得时间均不晚于材料截止）、指纹及提示词版本。各模型独立读取相同公共输入和自己截至本轮材料截止时的现金、份额和估值（包含当日已落库的成交、费用与已知公司行动），不读取本轮他人输出。模型返回逐标的目标权重、动作、简短依据、证据引用和判断失效条件。使用组合完整目标，显式区分保持原仓位与调仓；重复标的、越界引用、合计超额或动作冲突拒绝整份指令。记录请求／实际模型与可获得的版本、截止时间、回执时间、耗用和决策 ID；无静默切换。账户快照和轮次绑定；若运行恢复时仍缺该截止点的合格快照，该参赛者记录材料不足，禁止退用上一轮持仓。主动观望、材料不足、超时、输出无效、预算停用分别可查。

桌面推理服务分开报告模型标识与量化版本时，仅对已显式配置同源 LM Studio 原生目录的接入核对量化绑定。派发前匹配唯一目录项，回执后核对同一模型、文件大小、量化版本及实际加载的实例标识。目录不明确、存在多种可切换量化、回执缺标识或目录变化时，记录身份未核实。其他接入按回执标识与冻结绑定精确匹配。费用按真实请求回执结算，历史回放保留当时结果。

招商银行（600036.SH）的同花顺个股时间线使用正式新闻路由。详情和竞技场共用最近三天的标的新闻读取；轮次封存保留标的身份、来源条目标识、发布时间和材料可用时间。已封存的决策不补入后到新闻。开发环境准入仅覆盖该股票与该来源，每次以新的一页来源证据登记，有效期最多七天；到期后按相同范围续验。旧准入及其证据保留可核查的前后版本。

即时回放在全员额度预留和派发之前校验整份输入。任一新闻的发布时间或材料可用时间晚于决策截止点时，整份材料退回。收盘后模拟下一次开盘前的决策时，可加入已在截止前采集的当日完整日线，逐项核对其来源回执。每次获准的独立回放使用独立比赛和不可覆盖的回执。已收盘的单日草稿可以承载回放，须确认没有调度记录；回放结果单独保存。

比赛以数据库状态控制草稿、运行、暂停、结束；暂停禁止新调用和待执行指令成交，恢复从未来轮次起步。按比赛和交易日创建唯一轮次，按轮次与参赛者唯一领取和封存结果。队列不可用时保留数据库待投递状态并显示延迟；成功确认队列缺失才补投。Worker 按状态及 attempt 原子领取、提交和取消；基础设施重试上限写入冻结协议，超限收敛失败。无法确认是否已发生上游调用时保留未知费用，不重复发送；迟到结果留审计，禁止回填成交。比赛暂停期间禁止开轮。

**全员额度齐备才开轮。** 调度器按冻结的参赛名单和每个模型本轮的次数、令牌及费用上限，一次事务校验各模型余额和全场合计余额，将全员预留与开轮状态一并提交。提交成功后才可派发模型请求。同一比赛与交易日重复调度复用已有结果。任一模型无法定价或预留、或全场余额不足，记录本轮未开及具体原因，本轮新增预留、调用和交易指令均为零；既有持仓按原规则估值。开轮后的单模型超时或失败仍按实际结果结算，其他参赛者的有效决策保留。

## 成交、估值与下游合同

先封存决策，再取后续市场事实。默认收盘后决策、下一交易日开盘一次执行；截止点设在该次开盘前。按冻结的可用开盘价、固定滑点、费用、交易单位、可卖数量、现金和仓位限制计算。持有指令锁定已有份额，空仓观望保持现金；隔夜涨跌造成的权重漂移只有在模型明确调仓时才产生交易。按规则先卖后买，多个买单资金不足按目标缺口同比缩量、向下取整，余款留现金；停牌、缺价、价格限制或剩余不足一手记录原因，该次未执行部分到期失效。决策、模拟成交与收盘估值分别记录时间、身份、数量、币种以及来源版本；原子写入资金流水、持仓及成交，重复投递不得重复扣款。交易与估值需要的公司行动或换算事实缺失，标明影响范围并暂停对应计算。模型研究费用与交易费用分别展示。

对周报提供按 owner、比赛、参赛者、轮次与期间读取的冻结事实，包括公共证据指纹、私有持仓快照引用、开轮结果及未开原因、决策及状态、成交、收盘现金／持仓／净值、基准、费用、交易日历和数据完整性。客户端只消费投影。以同一估值点比较扣交易费净值、累计收益、最大回撤、换手和有效轮次；同期展示现金与等权买入持有基准。不可比期间标明缺数据并退出该期排名。程序计算绩效，证据可追到模型原输出。比赛领域拥有事实与模拟资金账，单向使用 Market／研究冻结材料、AI 执行及稳定交易规则，不向真实或影子账本写入。[冻结执行](../../apps/server/src/ai/ai-research-execution-v2.ts)、[严格路由](../../apps/server/src/strategy-optimization/strategy-optimization-model-routing.ts)、[可交易性](../../packages/domain/src/backtest-tradability.ts)

默认比较方法按同币种收盘净值计算。单位区间收益为期末净值除以期初净值减一；回撤以各估值点相对迄今峰值的最大跌幅表示；区间换手采用买卖成交绝对金额之和除以区间平均有效净值。现金基准保持等额本金，等权买入持有基准按同一首次可执行时点、费用、交易单位及余款规则建仓。证券价格、公司行动和估值的调整口径须能对账。实际模型调用费单列币种与已知／未知状态。缺估值所致的不可比情况同时标在模型和基准上。

## 验收

| 标准 | 可验证结果 |
| --- | --- |
| A-AC1 | 无账户从目录建赛，或复制自选分组；赛期、模型、资金和风险协议可回读，后续目录／分组变化不重写比赛。跨身份访问被拒。 |
| A-AC2 | 关闭客户端自动产生轮次；两模型公共指纹相同，私有持仓独立。当日已成交的份额计入本轮输入，截止后的公告不可见，观望、分歧及单方失败均可追溯。 |
| A-AC3 | 全员及全场额度恰好充足时只预留并开轮一次；任一方不足或无法定价时整轮零调用且无残留预留，调换领取顺序结果相同；身份不符或暂停不发新请求；队列故障、重复、迟到及重启收敛且不重复收费请求或成交。 |
| A-AC4 | 从已封存决策到下一交易日模拟成交和估值可逐项复算；可交易、未成交、费用、现金不足、公司行动缺证均有样本；现有实际／影子账本无写入。 |
| A-AC5 | 两端竞技场提供独立入口和同期比较；标的详情按比赛／模型显示成交，可从点位回到对应轮次与证据，决策日与成交日清晰。 |
| A-AC6 | [每周复盘](2026-11-05-arena-weekly-review.md)所需区间事实可按权限重读、版本稳定；基准、金额及完整性和排名口径一致。 |
| A-AC7 | 保数据升级、实际调度与 Worker 恢复、浏览器与移动宿主均独立取证；两个获准真实模型的前向决策先封存，再等待真实后续价格核对。受控回放单列。 |

真实运行前需明确模型名单、可用路线、调用次数、定价／费用上限、目标环境及市场数据资格。本规格不授予调用、付费或部署权限；以上条件只阻塞涉及它们的验收。
