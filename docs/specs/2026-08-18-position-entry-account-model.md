# 录入持仓与账户模型重构规格

账户模型原则保持。当前 Ledger/Market 信封与接口以[Canonical 架构](../architecture/canonical-runtime.md)为准，设备与产品验收见[已完成 Task](../archive/tasks/2026-08-18-position-entry-account-model.md)。

2026-10-21 当前范围：草稿/对账无模型路径已完成，实施边界以[补充规格](2026-10-21-account-draft-reconciliation-web.md)为准，[验收记录](../tasks/evidence/2026-10-21-account-draft-reconciliation-acceptance.md)承接目标 Web 与数据保护证据。

2026-10-22 最终核对：账户身份、类型/模式、字段锁定与生命周期继续由本规格约束；导航和余额交互沿用[账户数据产品规格](2026-08-26-trade-product-experience.md#导航与账户数据)，多币种和账本语义沿用[Ledger 规格](2026-08-26-trade-execution-ledger-system.md)，完整/部分快照及修订沿用[基线与导入合同](2026-08-26-trade-baseline-import-reconciliation.md)。以下已同步这些后继合同；ADR-009 至 ADR-014 保留决策时的协议与迁移背景。

## 背景与问题

录入持仓围绕选定账户展示当前持仓、现金与录入操作，账户管理作为独立能力；账户机构与本次录入来源分别建模。

账户模型还把 `shadow` 与证券、基金、现金放在同一类型枚举中，无法表达影子证券账户等组合。基金账户缺少独立净值契约，持仓草稿需要可靠的并发冲突基线。

正式 DSA Fork 位于三仓工作区的同级仓库 `daily-stock-analysis`。本功能遵循 ADR-014 的仓库边界，由正式 DSA Data/Control V3 合同提供基金净值能力。

## 目标

1. 将页面重构为以选定账户和录入方式为核心的“录入持仓”，让已有账户直接开始录入。
2. 将录入来源记录在本次 Ledger 变化或 Import Draft 中。
3. 建立类型、模式正交且具备完整生命周期约束的账户模型。
4. 让证券、场外基金和现金分别使用正确的资产身份、录入和估值语义。
5. 为持仓草稿建立审核、冲突检测、重新基线、提交与回滚边界。
6. 通过主仓、正式 DSA Fork 和基础设施仓的原子版本组合交付，拒绝不兼容组件混跑。

## 非目标

- 不连接券商下单，不实现自动交易或自动跟单。
- 第一版影子账户不自动镜像真实账户，也不接收策略自动写入。
- 不自动修复历史账户类型与资产类型冲突，不自动拆分或创建账户。
- 不为旧主系统 `/api/v1` 客户端维护兼容层。
- 不改写历史 ADR、审计或已经完成的迁移文档。

## 领域与数据规则

### 账户身份

Account 使用稳定 ID，名称允许重复，字段包括名称、可选机构、类型、模式、币种和状态，不包含录入来源。

- `type`：`securities | fund | cash`。
- `mode`：`actual | shadow`。
- `institution`：自由文本，可从历史值及支付宝、同花顺等内置建议中选择。
- 账户本位币使用共享 Schema 支持的 `CNY | HKD | USD`；成交与现金按币种独立投影，折算和缺失汇率状态遵循后继 Ledger 合同。
- 账户产生首个 Ledger 事件后，类型、模式和币种锁定；名称和机构仍可编辑。
- 当前持仓和现金均为零时可以停用，即使存在 Ledger 历史也保留全部审计记录；停用账户可以查看和重新启用。
- 原账户模型升级将历史 `type=shadow` 迁移为 `type=securities, mode=shadow`，其他历史账户迁移为 `mode=actual`；当时预检发现账户与资产类型不匹配须中止并报告，不静默纠正。既有迁移证据保留，当前结构由完整 migration 输入与 Canonical 结构门禁校验。

证券账户承载 A 股股票、交易所 ETF 和现金；基金账户承载 `.OF` 场外基金和现金；现金账户只承载现金。第一版证券资产范围仅包括 A 股股票和交易所 ETF。

### 资产身份

录入前必须解析标准 Asset。场内证券使用交易所后缀，场外基金使用 `000001.OF` 形式。

Provider 无法识别资产时，用户可以提供名称并确认资产类型为股票、ETF 或场外基金，系统保存“用户确认”的 Asset Identity。后续 Provider 结果与用户确认身份冲突时，阻止该资产的新录入并要求人工确认，不得静默改映射。

### 真实与影子范围

影子账户拥有独立 Ledger、持仓、估值和风险数据，默认排除在真实资产总额之外。Portfolio、Risk、Performance 和 AI 默认只读取真实账户；用户可显式切换到影子范围，结果必须标注“模拟”。Desktop 和 Mobile 均提供真实/影子切换，Mobile 第一版只读。

影子风险事件必须标注模拟。通知默认关闭，每条规则可以显式选择是否通知影子风险事件。

## 交互设计

### 页面与导航

- 页面和导航名称为“账户数据”，规范路由为 `/accounts`；旧 `/position-entry`、`/import-review` 转到此路由并保留可识别的账户参数。
- 页面提供账户选择及持仓、成交记录、现金三个同级页签，默认成交记录；现金账户只显示现金页签，全部账户视图只读。
- 手动持仓快照及现金余额通过当前账户的 Sheet 录入，已有账户无需重新创建；从账户列表跳转只选择账户，不自动打开录入 Sheet。
- 账户设置在同一 Drawer 内切换列表与表单，支持创建、编辑、停用、重新启用和查看停用账户。打开 Drawer 时若列表为空，自动进入一次创建表单；账户读取未完成或失败时保留对应状态。
- 按实际/模拟范围分别记住最后选择的账户，URL 显式账户参数优先。
- 存在未保存内容时切换账户、页签或全局模式必须确认；请求在途和已保存后读取失败遵循现行交互恢复合同。
- 账户选择器使用机构、类型、模式和币种区分同名账户。

### 手动录入

手动持仓快照表示“设置当前余额”。例如当前数量 100，输入 120 后结果为 120；“记录持仓快照”写入带 `source=manual` 的 `POSITION_BASELINE_OBSERVATION`，使用当前持久信封 V3。

- 证券/基金持仓先通过标的搜索选择目录结果，搜索支持代码、带市场后缀的代码和名称；选择结果后自动带入标的名称与类型，不再要求用户重复填写。
- 目录未找到标的时允许展开手动录入分支，要求补充代码、名称和类型后写入绝对数量和成本状态。
- 数量单位根据资产类型显示为股票“股”、ETF/基金“份”；成本字段对用户显示为“平均成本”，内部字段仍为 `costPrice`。
- “清空持仓”是独立的破坏性操作，经确认后写入数量为零的 `POSITION_BASELINE_OBSERVATION`。
- 现金使用独立区域设置当前现金余额，Ledger 写入 `CASH_BALANCE_OBSERVATION`，不伪装为入金事件；不允许负现金。
- 证券和基金账户在同一手动页的次要区域显示现金；现金账户只显示现金区域。
- 持仓列表根据最近一次相关 Observation 显示录入来源，来源与原因可从账本审计读取。

### 持仓草稿

部分更新（`PARTIAL`）草稿只修改用户最终提交的行，未提交的现有持仓和现金保持不变。完整快照（`FULL`）按基线合同处理遗漏标的归零，提交前须展示影响并取得本次明确确认。

- 草稿资产与账户类型不匹配时阻止提交，不自动分配或创建账户。
- 同一草稿中的重复标准代码必须由用户合并为一行后才能提交。

Import Draft 保存 Ledger 基线与草稿修订。提交携带打开草稿时读取的账户账本修订号，在账户写事务内检查；冲突后保留输入并重读账本和草稿，重新确认后再提交，不自动换用新版本重试。已提交行冻结，部分提交后仅未提交行可形成后续修订；回滚仍须检查后续事实，不能覆盖新的账本变化。

## 估值与展示规则

- 组合总资产包含现金。
- 现金单独展示，不计入已投资成本和持仓盈亏。
- 已投资成本和盈亏只计算可定价持仓。
- 场内证券使用 Quote；场外基金使用 Fund NAV。
- Fund NAV 包含单位净值、净值日期、Provider、抓取时间和新鲜度。
- 最新可用净值可以标记为延迟；落后超过一个预期公布交易日为陈旧；没有可用净值为不可用。

## 三仓实现边界

### `thesis-ledger`

- 负责 Account、Asset Identity、当前 Ledger Observation、Import Draft 和聚合查询的数据库、Schema 与 `/api/v1` Contract；Ledger 持久信封版本固定为 3，`payloadVersion` 独立表示经济载荷结构。
- 负责 Desktop/Mobile 交互、DSA client、Fund NAV 缓存和 Portfolio/Performance/Risk 消费逻辑。
- 保留 DSA Stub 和确定性 Contract Test；Stub 不作为生产 Provider。

### `daily-stock-analysis`

- 通过 `/api/v3/thesis-ledger` Data/Control V3 合同提供 `FUND_NAV`、`FUND_NAV_HISTORY`；当前净值入口为 `GET /market/fund-nav?symbol=000001.OF`，历史入口为 `GET /market/fund-nav/history`。
- 使用真实基金净值 Provider，返回稳定的来源、净值日期、抓取时间和结构化错误。
- 提供确定性 fixture、接口测试、能力声明、Contract 文档和 `docs/CHANGELOG.md` 更新；不改写 DSA 原生 API。

### `thesis-ledger-infra`

- 锁定兼容的主系统镜像、DSA 镜像和数据库迁移版本。
- 同级源码开发通过显式 override 开启；生产使用不可变镜像 digest。
- 启动与发布门禁分别检查主系统版本、完整 migration 派生的数据库结构 head，以及 DSA Data/Control V3、运行配置和所需净值能力。

## API 与兼容性

主系统直接更新 `/api/v1` 的 Account、Portfolio、Risk、Performance、Import Draft 和相关 Schema，不新增 v2。旧客户端连接新 Server 时必须因版本握手失败而停止，不允许有损映射旧 `source/type`。

主系统健康接口的 API 合同版本仍为 1，DSA Data/Control 与 Ledger 持久信封分别为 3，三个版本含义独立。当前 DSA Fund NAV 请求必须检查能力、精确来源及路由状态；不可用时保留明确状态，不得把 Quote 作为替代。旧 DSA V1 路径不作为当前接口。

## 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 绝对余额录入覆盖较新的修改 | Import Draft 基线与提交前 Ledger 版本检查 |
| 历史脏数据被错误迁移 | 预检中止并报告账户和资产，不自动修复 |
| 三仓版本漂移 | 基础设施版本矩阵、镜像 digest 和启动门禁 |
| Provider 无法识别或身份冲突 | 用户确认状态、冲突阻断和人工确认 |
| 基金净值延迟被误当实时行情 | 独立 Contract 和明确新鲜度状态 |
| 影子数据污染真实资产 | 查询默认 actual、独立 Ledger、显式模拟标签 |

## 验收标准

1. 已有账户用户进入 `/accounts` 后无需经过创建账户即可手动录入；旧 `/position-entry`、`/import-review` 正常重定向，无账户用户获得明确创建引导。
2. Account 不再包含 `source`，机构与录入来源在数据库、API、界面和审计记录中边界一致。
3. 账户类型、模式、币种锁定和停用规则均由服务端约束并有迁移预检。
4. 手动录入按绝对当前余额写入 Ledger，现金语义、清空操作和最近录入方式可审计。
5. 部分更新草稿只更新已提交行；完整快照须明确确认遗漏标的归零。类型冲突、重复代码和基线冲突均会阻止提交。
6. 真实与影子数据默认隔离，Desktop/Mobile 和跨账户查询展示一致。
7. 正式 DSA Fork 提供真实 Fund NAV Provider、capability、fixture 和 Contract Test；主仓完成缓存与估值消费。
8. 三仓兼容版本通过原子发布门禁；不兼容组件或数据库 Schema 会快速失败。
9. 相关定向测试、迁移测试、Contract Test、类型检查和最终一致性 Review 通过；视觉与移动端人工验收有明确证据。
