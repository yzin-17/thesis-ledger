# 桌面列表列对齐一致性

> 任务标识：desktop-list-column-alignment
> 日期：2026-11-04
> 对应任务：[已完成任务](../archive/tasks/2026-11-04-desktop-list-column-alignment.md)

## 问题与范围

投资组合交易列表的状态表头靠右，状态标签组却从单元格左侧排列，难以辨认列归属。同类问题存在于原生表格默认右对齐、共享表格表头与内容默认值不同、操作组自行居中及提供方表头居中而内容靠左等位置。

盘点桌面 Web 所有原生表格、共享 Table、抽取的行与详情表格，包括账户、组合、收益、研究、复盘、市场、风险、数据与自动化、策略及其任务与实验详情。无表头的卡片列表检查自身信息排列，不强行改为表格。保留原有数据、排序、筛选、分页、操作、空态和横向滚动。

## 列规则

- 文字、标的、日期、版本、来源、状态与说明左对齐；同列的表头和内容使用同一方向。
- 独立金额、价格、数量、比率、次数等数字列右对齐；占位值与不可用说明沿用该列方向。
- 操作列右对齐，内部按钮组也靠右；固定操作列仍在横向滚动时可见。混合说明与进度列按文字处理。
- 共享表格与原生表格的默认方向一致。数字与操作通过既有原子类明确声明，不使用按列号猜测语义的全局选择器。
- 首列缩进、表头和单元格内边距必须匹配。排序按钮、状态标签与多行按钮组需检查真实位置，不能只检查 text-align。

## 实施约束与验收

在现有表格基础样式、共享组件与各业务列声明上局部修正，不引入通用业务表格框架，不调整接口或业务行为。超过尺寸阈值的文件不增加规模。

- AC1：所有桌面表格声明及抽取行/详情均有盘点结论，文字、数字、状态、操作的对齐一致。
- AC2：回归覆盖原生表格、共享表格、动态列、状态组及固定操作组，包含用户截图中的交易列表。
- AC3：定向测试、桌面构建与边界门禁通过；浏览器检查实际表头/内容位置、横向滚动与窄屏。没有真实数据的分支用明确标记的本地样本补充，不写入业务数据。
