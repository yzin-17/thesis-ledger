# 回测准备失败纳入任务记录

日期：2026-11-08。对应[归档任务](../archive/tasks/2026-11-08-backtest-preparation-failure-jobs.md)与[验收证据](../archive/evidence/2026-11-08-backtest-preparation-failure-jobs.md)。

## 目标与范围

用户要求普通回测的准备、预检失败创建真实的失败回测任务，在任务列表与详情查看原因，退出顶部“后台提交”错误提示。本轮覆盖普通回测及已有阻塞普通提交，不改变净值回测与优化实验的独立确认合同，也不实施其他数据源选源方案。

## 行为与约束

- 准备或预检失败原子地创建一个 `failed` 回测任务并关联原提交。关联使用已有提交幂等键及状态／attempt 条件，重复处理、并发和故障恢复不得重复创建任务。
- 保存原始准备请求、策略版本、日期、资金、执行模型与完整诊断。使用独立的准备失败输入合同和阶段，不伪造正式 RunConfig、行情快照、来源冻结、预检通过或回测结果；不投递队列。
- 任务摘要、分页分组、详情和失败筛选接受这个严格受限的终态合同；运行、快照重试与结果读取不得将其当作已准备 Run。详情展示业务失败原因与预检诊断，重新创建通过原策略入口进行。
- 已成功关联失败任务的普通提交不再在顶部重复显示。已有阻塞普通提交仅利用保存的请求和失败信息补建任务，不再次访问来源；保留原始提交输入与诊断。创建回执不确定的提交继续沿用原恢复流程。
- 所有权校验和原数据准入保持；授权失败不产生跨用户任务。任务持久化失败不得丢失原提交及其可恢复状态。

## 验收标准

- AC1：默认阻塞、准备异常及中断恢复均产生一次失败任务；重复、并发和事务失败可安全恢复。
- AC2：失败任务可在既有列表、筛选和详情读取，配置及诊断正确；伪造输入、结果、快照或可执行状态被拒绝。
- AC3：顶部不重复显示已有失败任务，详情明确准备阶段失败并禁止直接执行重试；普通执行失败与其他提交行为不变。
- AC4：定向、包级构建及边界通过；隔离数据库验证原子性，正式运行态只对已有普通阻塞提交做无外部调用的关联转换；四宽浏览器验证列表、详情和导航。

数据库现有列足够，不新增 migration。不修改真实策略、账本、来源开关或凭据，不执行真实回测，不提交推送。
