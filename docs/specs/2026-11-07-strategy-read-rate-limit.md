# 策略读取请求的限流分类与恢复

日期：2026-11-07。对应[实施任务](../archive/tasks/2026-11-07-strategy-read-rate-limit.md)。

## 问题与范围

工作区身份读取、策略列表和回测状态轮询被路径前缀整体计入每分钟 20 次的重任务 GET 窗口，多个读取入口共享额度后出现 429。既有客户端冷却只作用于后续请求，工作区读取关闭重试，首次 429 会留在错误状态。

- AC1：策略与身份 GET/HEAD 读取不进入任务启动额度。当前全接口成本、主体和配额由[全接口按成本限流](2026-11-07-api-cost-rate-limits.md)承接；该文件归档任务中的 120 次普通额度是当轮历史基线。窗口回收和 Retry-After 语义保持。
- AC2：工作区上下文只对 429 按 Retry-After 最多重试一次，缺少时间时等待 60 秒；取消读取时中断请求及等待。其它错误不自动重试，身份上下文保持 Query 缓存与会话隔离。持续失败提供手动重读和中文业务错误，不展示 API 内部前缀。
- AC3：不自动重放模型调用、登录、注册、回测提交等写请求，不更改业务数据或历史终态。真实服务只读验证，限流耗尽与恢复由隔离请求验证。
- AC4：先定向验证分类、额度仍生效、窗口恢复和一次重试，再验证构建、门禁、维护脚本同步与策略列表四宽实际页面。正常用户页面流量不得触发 20 次重任务读取阈值；不保证无限次刷新不会触发普通读取保护。

## 所有权与检查范围

Server 平台模块拥有 API 限流分类。Desktop 工作区上下文拥有本次有界读取重试，保留共享 transport 的冷却与取消行为。检查原 heavy 路径下的 GET 控制器、策略状态轮询、SSE、身份上下文及现有恢复测试；GET 均为状态、列表或设置读取，计算与外部调用由写入口发起。API 契约不新增字段，不调整 Provider 限流与权限。
