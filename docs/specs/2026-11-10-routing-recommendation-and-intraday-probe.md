# 精确主备推荐、节流移除与盘中采样

## 目标与边界

按精确口径提供可解释的主备推荐，移除应用层主动休眠及本地频次计数，并安排北京时间 2026-11-11 的只读盘中采样。新增 Redis 缓存、缓存范围和 TTL 调整等待实测后实施；本次保留所有现有缓存。

任务：[当前执行状态](../tasks/2026-11-10-routing-recommendation-and-intraday-probe.md)。来源与采样实现由同级 DSA 仓库拥有，公共目录契约由本仓 Schema 拥有。

## 验收契约

- AC1：每个精确口径独立筛选已启用、配置完整、依赖和权限合格的来源；凭证存在本身不增加排序优先级。主源依次比较大类偏好、可比较的精确证据和有依据的用途优先级，同等时保留有效的现有具体来源；仍无法决胜时按 AC9 核对现有整组绑定，原绑定不完整或不合格时待选择，不按标识字母或目录顺序决胜。
- AC2：备用独立选择，优先已确认与主源上游独立的其他 Provider；未知上游不冒充独立。同源备用允许保留并说明。来源归属与推荐说明由来源注册层通过兼容的可选目录字段提供，纳入目录修订。
- AC3：采用建议只修改目标大类及子项，绑定具体来源；允许保存已确定的建议，未决项保持采用前的原配置，不自动挑选同等候选。主配置与细分配置的保存入口保持一致，保存确认页显示待选择而保留原配置的项数。撤销本类建议恢复采用前的该类草稿，并保留其他大类修改。
- AC8：点击“待选择 N 项”直接打开本类细分配置，仅显示当前仍待选择的精确口径；筛选条件与清空筛选继续限定在待选范围内。完成具体来源选择后更新待选数；关闭后从普通“细分配置”入口打开仍显示完整范围，不修改其他口径或自动保存。
- AC9：推荐候选无法唯一决胜时，若已有主备的每个提供方均已绑定具体接口且仍符合该精确口径的配置、启用与权限条件，则保留完整已选绑定，状态为已确定，并说明保留原因。缺少具体绑定或任一已选来源不合格时仍待选择；不要求用户更换有效的已选来源来清除待选标记。
- AC4：移除应用主动等待和本地频次计数，覆盖业务与诊断路径；保留 SDK 内部机制、超时、重试退避、熔断、权限检查冷却和资源并发保护。准确区分上游限频、额度不足、权限拒绝，不因限频立即重复请求。备用继续遵守原策略与具体来源 pin。
- AC5：只读采样以已配置、已启用、符合读取条件的来源和单标的为范围，代表周期为 1m、60m、1d、不复权；绕过应用结果缓存，不改业务政策，不启用或购买来源。每来源每市场最多十二次逻辑查询，明确限频、额度不足或权限拒绝后停止对应读取。
- AC6：中港于 11-11 10:05、10:15、10:35、11:05 采样；美股于 11-11 23:05、23:15、23:35、11-12 00:05 采样，均为北京时间。记录实际时间、接口、末端 OHLCV、原始确认标识和错误；仅值相同不足以判定仅返回已确认数据。延迟、漏采与未知如实报告，最终停止计划。
- AC7：原始凭证不进入日志和证据，真实业务数据与历史冻结保持不变；定向检查、包级检查、仓库门禁和最小部署依序验证，浏览器覆盖代表宽度与采用、撤销、保存、隔离行为。真实盘中采样验收单独保留。

## 默认决策

没有可信精确实测证据时不进行质量加权，不新增实测数据库。已有宽泛健康记录仅作为风险说明。缓存改造不属于本轮代码范围；本轮不重复在线试读来源。
