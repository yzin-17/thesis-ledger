# 成交规则能力数据合同

本合同承接[原成交产品 Spec](2026-08-26-trade-product-experience.md)与 [T18.C3b](../archive/tasks/2026-08-26-trade-execution-ledger-system-follow-up.md)。仅定义可追溯数量/价格规则包的跨运行时数据边界；实施见[已完成子任务](../archive/tasks/2026-10-21-trade-rule-capability-contract.md)。现有 Ledger 写入、C1/C2、账户隔离、来源启用及路由不改变。

## 问题与目标

当前每手参考与静态信息没有完整规则内容、精确适用范围和有效时间，不能作为表单或 Server 的已验证依据。[当前官方来源核对](../tasks/evidence/2026-10-21-trade-rule-source-contract.md)还表明，申报整手不能代替部分成交数量，单笔价格不能自动覆盖聚合均价。

先形成一份只表达规则能力的稳定 V3 Schema，要求请求与响应在范围、时间和内容上自洽。结构校验不证明发布机构可信或来源字节实际匹配，不能授予 `capabilityVerification=VERIFIED`。本阶段不新增来源、路由、准入系统、业务入口或数据库结构。

2026-10-21 用户明确将本轮 T18 收敛为“基本校验＋规则参考”，见[范围决定](../tasks/evidence/2026-10-21-trade-rule-source-contract.md#trade-rule-compromise)。本合同已完成的 Schema 和时钟边界继续保留；真实规则生产、来源资格核对、服务端命令正向验证及完整规则 Web 消费移出本轮必须交付范围，仍未通过原完整实源验收。当前交付以[成交产品 Spec](2026-08-26-trade-product-experience.md#成交录入)为准，不能由规则参考授予 `VERIFIED`。

## 请求与响应

Schema 所有对象为严格对象，不接收来源未声明的额外字段。

- 请求：`contractVersion=3`、`consumer=thesis-ledger`、非空 `requestId`、精确 `scope` 和闭区间 `window.start/end`。窗口起点不得晚于终点。Ledger 消费方负责把既有时间精度和时区转换为完整窗口，不能把仅日期输入缩成一个伪造时刻。
- 时间边界按[精确证据时钟修复](2026-10-21-trade-rule-evidence-clock.md)执行，不截断毫秒以下精度；等价已知偏移表达相同瞬时，未知偏移和超出既有时钟范围的值拒绝。
- `scope`：单一规范 `symbol`、`market=CN/HK/US`、交易所、明确板块或明确不适用的 `board=null`、`assetType=STOCK/ETF/MUTUAL_FUND`、币种、业务方式、买卖方向和 `subject=SINGLE_EXECUTION/AGGREGATED_EXECUTIONS`。不接受通配市场/标的，不接受把申报规则伪装为成交规则。只校验 symbol 与市场关系，不假定 CN 全部为 CNY，也不按代码前缀补造板块资格。
- 不可用响应：回显请求，`status=unavailable` 及稳定原因码，不能附带可消费规则包。原因包括来源缺失、范围未覆盖、时效未证、成交语义不支持、来源冲突和内容未核验。
- 可用响应：回显请求，`status=available`，提供完整规则包；不包含命令的 `VERIFIED` 标记。`available` 只表示该来源提供了结构自洽的能力数据。

## 完整规则包

| 维度 | 必需内容和约束 |
| --- | --- |
| 内容版本 | `ruleVersion=sha256:<64位摘要>`，代表规范化规则内容、范围、时效及来源引用的整体内容；不能用路由修订、请求 ID 或抓取时间代替。Schema 只检查格式，实际摘要计算与来源字节核验由生产/消费链验证。 |
| 来源 | 发布机构、文号、发布日期、原始 URL、附件角色与 SHA-256。至少有一份正文；修订及暂缓资料按实际登记，并显式声明已检查修订、暂缓与来源冲突。抓取时间与发布日分别保存。 |
| 范围 | 与请求的 scope 每个维度一致。当前原始来源不具备的板块/业务/成交语义不能由 Schema 猜测。 |
| 时间 | `effectiveFrom`、可空且排他的 `effectiveUntil`、`verifiedThrough`。已核对边界不得晚于抓取时刻，且有效范围覆盖请求整个闭区间；已知失效边界不允许触及。不能用无失效日期宣称已验证未知未来。 |
| 数量和价格 | 二者均有有限精度的十进制正数 `step` 与 `decimals`；步长去除小数末尾零后必须能用声明精度表达，不能依赖浮点数取模。两个维度都必须具备，不能由每手值补造价格规则。 |

来源核验与命令校验是独立阶段：受支持的生产方须证明真实内容、修订/暂缓和精确适用语义；Server 再按本次命令实际输入验证并决定状态。客户端提交的合法响应或 `available` 不构成证明，C2 的拒绝边界保留。仅支持部分维度时必须继续不可用或准确保留未验证，不把来源可信等同于命令已通过。

## 边界与验收

本次只实现 Schema 与定向测试，不创建 Provider/DSA 实源包，不执行新业务写入，不恢复历史原件追补，也不调整当前表单状态。原事件及其验证标记不被改写，既有幂等重放保持。

- AC1：只有包含数量、价格、精确来源/范围和有效窗口的自洽包能通过可用响应结构校验。
- AC2：跨 symbol/市场/币种/方式/方向/成交语义、未生效或过期、未来未核对窗口、步长精度矛盾、缺正文或额外字段均拒绝。
- AC3：不可用响应保留稳定原因且不能夹带可用规则；仅日期的整段窗口必须完整覆盖。
- AC4：Schema 定向与包级、类型/构建、公开导出门禁通过；真实来源、Server 命令判定和完整规则 Web 正向未通过，不能用本次确定性测试替代。该完整实源分支按上述用户决定移出本轮必须交付范围，不据此勾选为通过。
