# 提供方健康记录统一

## 目标与范围

健康历史统一使用当前事件契约，修复服务端返回成功但客户端校验失败的问题。范围包括共享 Schema、独立测试记录生产者、Desktop 类型和开发数据库中的旧测试记录；保持页面布局、提供方配置、预算授权、账本和当前路由验证凭证不变。

## 记录契约

- 普通健康检查继续使用空 `details`。
- `ai_provider_validation` 表示当前用途验证，保留 `operationId`、`requestId`、`fingerprint`、用途、模式、计量及 `pending/passed/failed` 状态。
- `ai_provider_validation_operation` 表示已授权验证操作，保留计划指纹和 `running` 状态。
- `ai_provider_probe` 表示独立连接或生成探测，保留实际模型、配置指纹、合同、用量和费用，状态为 `passed/failed/cancelled`。它不提供当前用途验证凭证。
- 独立探测的连接类型不能携带用途或业务合同；生成类型有用途和合同时两者必须一致。
- 客户端仅接受以上当前事件类型；共享 Schema 是 Desktop 类型的来源。

## 数据转换

仅处理 `ProviderHealthCheck.details.kind = ai_provider_test`。根据旧记录明确状态、顶层健康状态及错误码确定结果；保留已有字段和十进制字符串，不重新执行模型。转换结果必须通过当前探测契约；缺少必要事实、状态矛盾或错误归因的记录删除。保留被转换记录的主键、提供方、时间、延迟、顶层状态和错误码。

维护入口默认只读计划；实际执行需指定开发目标和私有备份目录，核对真实数据库名称及 owner。在事务中锁定健康记录表，核对原记录未变化后原子转换或删除；失败回滚。执行前保存受影响原记录，完成后验证当前 Schema、重复执行无变更及非目标记录保持不变。

## 验收标准

- AC1：共享契约接受全部当前事件，拒绝旧事件和非法状态，保留必要验证及计量字段。
- AC2：独立测试的成功、失败、取消均产生合法当前探测记录，不改变其业务结果和当前路由凭证。
- AC3：维护入口经转换、删除、目标保护、并发变化与幂等测试；实际开发库完成处理且非目标记录保持不变。
- AC4：目标运行态更新后，真实 API 全部分页通过共享校验，浏览器健康历史正常显示，桌面、平板和窄屏均无读取错误；不发送外部模型请求。
