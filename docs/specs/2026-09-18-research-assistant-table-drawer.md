## 2. 目标与范围

### 2.1 目标

1. 在列表中直接比较研究问题、对象、来源、已有摘要、结果状态和更新时间。
2. 打开详情后优先阅读结论、风险与证据，运行元数据默认折叠。
3. 分开处理执行状态、结果可用性与请求读取状态，避免成功误报和重复告警。
4. 支持已加载范围内连续浏览、完整阅读、深链接、刷新恢复和列表上下文恢复。
5. 默认排除可确认的实验内部任务，保留未知来源历史记录和用户主动发起的策略研究。

### 2.2 边界

- 保留现有新建研究流程；本期必须补齐只读查询、批量摘要和状态契约，不将服务端改动视为可选美化。
- 不重写 Provider、Worker、队列、重试和研究生成协议，不修改历史结果或批量改名。
- 不新增任务类型的完整实验报告编辑器、策略采纳、候选对比、风险规则编辑或实验日志系统。
- 不新增聊天、收藏、标签、批量操作、导出、统计卡片、布局切换或新的全局状态管理库。
- 不新增服务端浏览快照，不保证动态更新时间排序下所有尚未加载记录都能在一次浏览中出现。
- 不调整全局导航和其他模块整体样式；只读导航不创建研究、自动重试或改变业务终态。
- 默认基于现有持久化事实实现只读投影，无历史数据迁移或数据库重建。发现必须改变生成协议或数据库结构时，先报告具体影响并修订范围，不能通过前端伪造信息绕过。

## 3. 任务分类与可见范围

| 类别 | 默认列表 | 详情行为 |
| --- | --- | --- |
| 用户独立研究 | 展示 | 通用研究结果 |
| 从策略、持仓等业务入口明确发起的研究 | 展示 | 研究结果及可验证的业务来源 |
| 实验内部探索轮次、模型执行及内部重试 | 排除 | 开启内部任务范围后可查看已有摘要，或跳转来源实验 |
| 来源或类型不能确认的历史记录 | 保留并标记 | 安全只读展示，不强行套用通用结果契约 |

「来自策略实验」与「实验内部任务」分别表达来源和用途，不能仅因研究上下文是策略就排除。来源筛选中提供「包含实验内部任务」，默认关闭；选择实验来源不会隐式打开该开关。

分类依据限于结构化元信息、可验证的业务关联和已核对的生产端契约。实验关联核对包含已有元信息与执行记录关系；数据不完整、冲突或无法确认时保留未知分类，不能仅靠标题或上下文范围猜测。普通研究不能仅因没有实验关联就被标成手动创建。

分类及来源过滤在分页前执行；分页范围、筛选与可选总数使用同一条件。不能读取一页后在客户端排除内部任务。默认未知来源保留；用户明确选择具体来源时，按该筛选条件展示。不存在或无权访问的来源不生成跳转入口，接口不泄露无权访问对象的名称。

## 4. 全宽列表

### 4.1 页面与列

页面由紧凑页头、单行工具栏和全宽表格组成；窄屏允许工具栏换行。保留「研究助手」和「新建研究」，移除独占行的英文标题、常驻长说明和旧双栏外层卡片。帮助可放入标题旁提示；Provider 正常时弱化显示，未配置或不可用时明确提示并链接已有设置页面。历史读取不依赖 Provider 可运行。

| 列 | 内容 |
| --- | --- |
| 研究问题 | 主行是真实问题或名称，次行是已有摘要或必要状态说明 |
| 研究对象 | 可确认的策略名称与版本、标的名称/代码、账户等 |
| 来源 | 可确认的来源类型及来源名称；未知时明确标记 |
| 状态 | 第 7 节的统一主状态 |
| 更新时间 | 精确到分钟，并可查看完整时间 |
| 操作 | 可聚焦的「查看」；有其他真实能力才出现更多菜单 |

- 常规行高 64–72px，问题和摘要各一行；长文本截断，支持聚焦/悬停提示及详情阅读，提示不是唯一入口。
- 问题列占剩余宽度，其他列稳定宽度；不把每行变为卡片，不使用大面积黑色完成胶囊。
- 服务端提供已有结论的确定性摘要，不新增 AI 调用。不将未验证正文的摘录作为已验证结论展示；不可用结果的列表次行优先说明原因，文本阅读留在详情。
- 无摘要时仅展示必要说明，避免重复状态。字段缺失用「未提供」「来源未识别」等回退，不虚构来源、对象、费用或结论。
- 同名任务用对象、来源和时间区分；不追加完整 UUID，不重复「策略版本 · 策略版本」。类型已知但对象名称缺失时显示「策略版本 · 对象未提供」。

### 4.2 查询、刷新与分页

工具栏提供问题搜索、执行状态筛选、来源筛选、内部任务范围开关和刷新，不使用横向滚动状态 Tab。

- 搜索至少覆盖问题/名称；对象和来源名称搜索不属于本期保证。使用项目既有输入防抖方式；若涉及工具函数选型，按项目规则核对 `es-toolkit`。
- 执行状态筛选为全部、排队中、研究中、执行完成、失败及已有的已取消。「执行完成」只表示执行成功，仍可包含有缺口、不可用或待核验的结果。
- 默认按 `updatedAt` 降序、`id` 降序排序；服务端游标必须与查询排序一致。没有可验证更新时间的兼容记录不得由客户端伪造为最新更新。
- 复用游标和「加载更多」，默认每页 50、最大 100，保持已有容量限制；不一次拉取所有任务。不新增页码跳转或结果质量筛选。
- 搜索或筛选改变时丢弃旧范围游标并回到第一页。查询键包含全部实际条件；不同范围的游标不能串用。
- 刷新保留条件，重新读取当前范围；已加载多页的窗口刷新要使用连贯的游标链，不能只刷新末页后拼接旧页。刷新后按 ID 去重。
- 动态任务更新可能跨越已取页边界；返回列表后的刷新用于取得当前顺序，不承诺未加载集合的快照一致性。
- 总数仅在服务端准确提供时展示，不能用已加载数量冒充。没有可信证据证明「只有内部任务」时，使用通用空状态。

### 4.3 行交互与响应式

点击行的非交互区域或「查看」打开详情；来源链接和菜单独立处理事件。保持语义化表格与真实可聚焦入口，不让整行鼠标点击成为唯一入口。

| 主内容区可用宽度 | 展示 |
| --- | --- |
| ≥ 1080px | 六列紧凑表格 |
| 768–1079px | 对象和来源合并到问题列次级信息，适度增加行高 |
| < 768px | 紧凑记录列表，保留问题、对象、状态、时间和查看入口 |

按容器可用宽度判断，不仅按浏览器宽度；关键操作不依赖横向滚动。优先组合既有原子类与组件变体，不为单个断点复制业务逻辑或建立页面专用样式系统。

## 5. 详情、完整阅读与导航

### 5.1 容器与阅读层级

复用现有 `Sheet`，从右侧覆盖列表，背景不可操作并保留轻遮罩。大屏复用 `detail` 尺寸，宽度受视口约束；1024–1279px 适当收窄，低于 1024px 全屏。不得压缩背景列表形成旧双栏。

固定头部放标题、统一状态、上一条/下一条、展开阅读和关闭；标题最多两行，元信息与操作合理换行。完整研究问题放在可滚动正文中；超长问题区域默认收起并可在正文内展开，避免 2,000 字问题占满首屏。普通问题可以直接显示。200% 缩放时关闭与阅读操作仍应可用；2026-09-18 用户明确确认该倍率的实际浏览器验证不再作为本次完成门禁，仅保留为非阻塞人工观察项。

正文顺序为研究问题与背景、核心结论及适用条件、风险与未知项、证据与来源、默认折叠的运行详情。保留已有免责声明和演示模式标识。结论或明确结果状态优先出现，不生成不存在的报告章节，不把每段包成卡片。研究数据时间与任务运行时间分开，不能以完成时间替代来源时间。

内容区独立滚动，没有只读详情常驻大型底部操作栏。关闭按钮、Esc 和遮罩可关闭；Esc 优先处理已打开的子菜单。

### 5.2 上下文与连续浏览

- 打开前保存搜索、筛选、排序、已加载分页窗口、滚动锚点和触发入口，并固定已加载记录的有序 ID 集合。
- 上一条/下一条只在这个集合中移动，不在 Drawer 内加载下一页、不循环。到边界禁用相应操作，并提供返回列表加载更多的说明或入口；已无更多数据时说明已到范围边界。
- 内容和状态可以更新，但本次导航集合不重排、不插入新记录。记录变为不存在或无权限时显示对应状态，不重新拼接其他范围补位。
- 切换后正文回顶部，标题、正文、状态及操作始终属于当前 ID。请求乱序不得覆盖当前记录。
- 关闭或返回列表时先恢复原窗口、滚动与焦点；不立即重排导致入口跳动。后台新顺序在随后列表刷新时应用。
- 原入口已消失时聚焦相邻入口或列表标题。直接链接或刷新后没有可恢复导航集合时隐藏连续浏览，不能把查询条件相同当成集合已重建。

### 5.3 完整阅读与历史

「展开阅读」进入当前研究的完整阅读模式，沿用 `/ai-chat`，复用同一详情 Query、正文、状态、来源及能力判定。阅读区居中，最大宽度 960–1120px；技术诊断仍默认折叠。提供「返回研究列表」，恢复可获得的上下文。

选中 ID、阅读模式及搜索筛选排序写入可分享和刷新恢复的 URL 查询状态；滚动、入口和已加载导航集合保存在页面会话状态。T1 统一参数编码与默认值，T5 负责实现；不新增路由系统。

| 操作 | 历史行为 |
| --- | --- |
| 列表打开详情 | 增加一个历史项 |
| 上一条/下一条 | 替换当前详情项 |
| 展开阅读 | 替换当前项的阅读模式 |
| 关闭或返回列表 | 有可验证的列表来源时返回原项；直接进入时安全导航到列表 |
| 刷新详情地址 | 保持当前 ID 和模式，不自动选中列表首条 |

直接访问必须处理加载、读取失败、无权限和不存在，不能盲目后退到外部页面。完整阅读只改变容器，不重新生成研究或改变操作权限。

### 5.4 创建、重试与覆盖层

新建表单复用既有交互、模板预填和校验，模板不自动提交。创建成功后先关闭表单，再打开新任务详情；保留提交前的搜索、筛选及列表窗口，关闭详情后返回原列表。新任务不属于原范围时隐藏连续浏览；属于范围但未进入已加载导航集合时同样不虚构相邻记录，刷新列表后再建立导航集合。

从详情进入既有重试或新建流程时先退出研究详情，保留列表上下文。提交失败保留表单错误和草稿；放弃创建返回列表。同一时刻最多一个覆盖式 Drawer。

证据在正文内展开或使用适合的提示/独立页面，保留引用与实际 Tool 调用审计的读取能力。访问策略、实验等来源时跳转已有页面，不叠加业务 Drawer。

## 6. 任务类型与结果读取

先识别任务类型，再选择结果解析器。普通研究遵循现有 `ResearchResult V1`、引用/Tool 关联及历史兼容规则；实验内部任务不套用普通研究校验。已有实验摘要可复用，没有完整展示能力时给出可验证执行摘要、只读说明和有效的来源入口。

结果缺失、契约无效和类型不支持分别保留原因。普通用户只看到单一主要说明区，原始 Schema 字段错误、任务类型及状态值进入技术诊断。

- 结果缺失：显示「未返回可展示结果」，不造正文。
- 类型不支持：显示「此类结果暂不支持在研究助手中展示」，允许展示安全摘要及来源，不将任务执行状态判成未知。
- 结果契约或引用校验失败：主状态「结果不可用」；可安全提取的文本保留，紧邻标注「未验证内容」和原因。不得作为可信报告呈现，不展示未验证的关联跳转。
- 历史记录缺少旧协议未提供的 `toolCallId`，按已有兼容规则展示；不伪造关联，也不能仅凭此判定校验失败。已经提供但属于其他任务或无法验证的关联按现有契约处理。
- 不渲染可执行原始 HTML、原始模型日志或内部推理文本；仅展示既有内容清洗策略允许的公开结果字段。

## 7. 状态模型与缺口判定

### 7.1 独立维度与主状态

执行状态、结果可用性和读取状态分别建模；UI 文案不是新的数据库终态枚举。

| 执行与结果条件 | 主状态 | 内容行为 |
| --- | --- | --- |
| 排队 | 排队中 | 等待说明 |
| 执行中 | 研究中 | 执行说明；可读阶段结果标为非最终结果 |
| 成功，契约有效且无明确数据缺口 | 已完成 | 正常结果 |
| 成功，契约有效且有明确数据缺失依据 | 结果有缺口 | 保留正文并说明影响 |
| 成功，尚不能取得足够事实完成核验 | 结果待核验 | 明确核验范围或原因；不是列表接口缺能力的常规替代 |
| 成功，结果缺失、无效或类型不支持 | 结果不可用 | 单一说明；无效但安全可读文本按第 6 节保留 |
| 失败 | 研究失败 | 失败说明；已有可读内容不代表最终成功 |
| 取消 | 已取消 | 取消说明及可读历史信息 |
| 执行状态不能识别 | 状态暂不可识别 | 安全只读内容与诊断 |

### 7.2 可执行的判定边界

| 已有事实 | 判定 |
| --- | --- |
| 合法报告中的普通风险，或「未来政策变化无法预测」等一般不确定性 | 不触发数据缺口降级 |
| 仅 `unknowns` 非空、报告短、字段少或没有外部 URL | 不足以自动降级；按实际契约核验 |
| 结构化结果明确记录所需数据缺失，或当前研究实际依赖的工具读取失败且结果仍符合契约 | 结果有缺口，并保留具体依据及影响说明 |
| 与当前研究所需数据无关的工具失败 | 不仅凭失败条数降级 |
| 引用或必需结果字段违反适用契约 | 结果不可用，不归入非致命数据缺口 |
| 旧版未提供引用关联 ID，但符合已有兼容条件 | 保留历史兼容状态，不伪造映射 |

若现有文本没有可验证的结构化缺口标记或所需数据关系，不使用关键词/文本猜测进行分类。保留原始未知项供阅读；按其余可验证事实决定状态。T1 的权威样例必须覆盖上述区别。

首次加载显示骨架屏；网络失败显示「研究详情加载失败」和重新加载入口，不改写业务主状态。缓存可继续只读展示，但明确更新失败。仅在成功读取并确认结果问题后显示相应不可用状态。

首屏仅有一个主要状态说明区。明确失败使用错误样式，非致命缺口弱化提示，正文对应位置可以解释影响，但不重复堆叠同一告警。

## 8. 运行详情与能力

运行详情默认折叠，可在折叠标题显示真实模型和耗时摘要。展开后分组展示模型与消耗、创建/开始/完成时间及重试来源、技术诊断。

- 毫秒转换为易读秒数，Token 分组显示；长 ID 展示短值并可复制完整值。
- 消耗未返回时显示「未提供」；费用仅在金额、币种及计量语义明确时显示，未知不变为零或免费。
- 模型来自真实执行元信息；不根据路由名称猜测实际模型。时间沿用应用时区，必要时标明时区。
- 省略非必要空字段，不用大量「无」填充。密钥、授权头、原始请求日志和内部推理不得输出。
- 重新加载只读当前详情；重试、取消仅在已有 API 和当前类型/状态明确支持时显示。不能因原始状态是 failed 就对任意内部任务显示普通研究重试。
- 提交期间防重复；未知状态默认只读。查看来源必须有可验证关联和访问权限，不能生成无效按钮。

## 9. 接口、共享边界与缓存

### 9.1 必要的接口扩展

| 接口 | 本期必需能力 |
| --- | --- |
| `/ai/runs` 列表 | 问题搜索、执行状态、来源、内部任务范围、更新时间排序和匹配游标；对当前页批量提供分类、对象、来源、已有摘要、结果可用性及原因 |
| `/ai/runs/:id` 详情 | 与列表一致的展示事实和数据版本、适用结果及操作能力；缺失/无权限可明确识别 |
| 既有 Tool 调用读取 | 保留按任务读取与分页，验证实际引用归属，按需读取审计详情 |

扩展现有 API，保留现有调用方所依赖的字段和分页行为。新增研究列表查询模式由 Desktop 显式传入；旧调用方不因新增默认排除内部任务或排序而静默改变语义。参数、游标版本及非法值处理由 T1 作为可测试契约统一锁定，T2/T3 不分别发明。

列表摘要与可用性必须由服务端在当前页范围批量计算或消费现有验证事实；数据库读取可提取必要结果字段，但列表响应不返回完整报告。关联对象、结果核验及引用归属同样批量读取，不以逐项 `findUnique` 或逐行详情 HTTP 请求形成 N+1。

数据版本必须覆盖展示状态实际依赖的结果与关联验证事实，不能把客户端取数时间当作版本。列表和详情使用同一判定，不仅凭二者到达顺序相互覆盖。

### 9.2 概念所有权

研究展示投影和接口契约由 AI 研究边界拥有；实验事实继续由实验模块拥有。跨 feature 集成遵守源码与 Nest Module 的同向依赖，可使用拥有方提供的稳定契约或明确归属的读取适配，禁止研究核心反向导入实验业务编排服务。

不为复用新增无所有权的 `common/shared/utils`。只有确有跨应用稳定价值的契约进入 `packages/*`。改变模块依赖时同步检查并维护 `scripts/check-boundaries.mjs`。大文件修改遵守复杂度 ratchet，按查询、适配、正文、容器等职责拆分，不放宽门禁。

### 9.3 客户端请求与版本一致性

- 使用 TanStack Query，列表条件和任务 ID 分别进入对应查询键；开详情不刷新整份列表。
- 列表、Drawer、完整阅读消费统一映射及正文能力，按 ID 和数据版本关联缓存。较旧详情不能覆盖较新列表投影；新版本不得继续沿用旧核验结论。
- 同版本的列表摘要状态与详情状态一致；版本不同可短暂显示各自明确的读取状态，刷新后收敛。请求失败不能用「缺失结果」覆盖已有有效状态。
- 复用现有运行中任务轮询，终态停止；不新增整页高频轮询或后台逐条读取所有详情。
- 快速切换时取消旧请求或忽略过期响应，不以旧标题、旧正文充当新任务加载内容。

## 10. 视觉、可访问性与边界

沿用浅色/深色主题、语义颜色、圆角、边框和间距变量；中性底色、细边框，蓝色用于链接和焦点。主按钮保持现有主题，普通完成状态使用低权重样式。选中态强于悬停态，不单靠颜色传达状态。优先原子类和现有组件变体，不引入常规 `!important` 覆盖。

`Sheet` 使用正确标题关联与模态语义；打开后焦点进入详情，Tab 不进入背景；关闭恢复入口。图标按钮提供中文可访问名称。切换任务同步可访问名称与正文。表单标签遵守共享组件的默认激活限制，不使用全局 `pointer-events` 阻断控件。

| 场景 | 行为 |
| --- | --- |
| 无研究 | 「暂无研究」及新建入口，保留现有模板预填能力 |
| 条件无匹配 | 显示无匹配及清除条件入口，保留当前条件 |
| 可确认只有内部任务 | 提示当前范围及开启内部任务入口；无法确认则通用空状态 |
| 首次加载 | 表格/正文骨架，不闪现空状态或旧任务 |
| 列表或详情读取失败 | 对应局部错误与重试；缓存可读但明确更新失败 |
| 不存在或无权限 | 准确说明并可返回列表，不无限加载 |
| Provider 不可用 | 历史可读；创建能力按真实预检限制 |
| 未知类型/状态 | 分别处理，安全回退及技术诊断 |
| 长问题、长正文、窄屏 | 标题不挤掉操作和正文，内容可完整读取 |

## 11. 测试策略与证据边界

- 契约与单元测试：任务分类、历史兼容、缺口依据、状态映射、字段回退、耗时/费用格式、查询及游标兼容。
- 服务端集成：隔离数据库中真实执行搜索、过滤、排序、分页和批量关联核验；按 1 条与多条记录比较查询次数，验证不会随每行线性增加，且只读操作不修改业务事实。
- 组件与集成：全宽列表、正文复用、能力、请求乱序、缓存版本、新建后恢复及加载/错误分支。T3 尽早通过实际 API 连接真实查询逻辑，不等到全部容器完成才集成。
- 浏览器与目标运行态：代表性的普通研究、实验内部、历史、无效引用、明确缺口和未知记录，检查范围过滤、摘要状态、导航历史、焦点、响应式及主题。真实已有数据不足的异常分支使用受控 fixture，并明确标注其证据范围。
- 验证依次执行定向测试、包级测试与 build、仓库门禁、目标运行态。数据库与浏览器门禁不能由 mock、typecheck 或静态扫描替代。
- 目标运行态代码更新遵循 infra 的 `sync-code.sh` / `update.sh` 预检和最小目标规则。源码通过不等于容器通过，快更不等于镜像已更新；完整条件与执行证据记录于 Task。

## 13. 风险、默认与完成条件

主要风险为历史分类事实不足、结果可信校验与旧兼容冲突、动态排序分页变化及长问题占用视口。分别通过未知保留、同一核验规则、限定已加载导航集合、头部限行与正文展开控制。

默认采用必要的只读接口扩展，不增加快照、数据库字段或新的任务系统。具体参数和样例固化属于 T1 的独立契约交付；不允许实现者改变已确认的产品语义。Blocking 产品问题：无。运行环境、权限和代表性数据是否就绪由 G1 核查，不在文档生成时宣称通过。

功能完成要求 A01–A24 全部通过，实施任务与目标运行态门禁完成，旧入口及历史只读能力无回归。当前范围内难以验收的事项继续留在 Task，不能转入 TODO 使本主题表面完成；普通非目标不自动进入 TODO。旧任务的外部门禁仍由原任务跟踪。执行顺序、证据和最终一致性 Review 只维护于对应 Task。
