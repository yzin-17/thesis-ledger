# 加仓百分比生成语义修复

## 目标与边界

用户要求修复 AI 将上涨 0.5% 编成 50% 的问题，以真实 AI 重新生成加仓计划，复用原冻结行情回测，实际触发加仓且含费用、滑点不超过投入上限，保留全部历史。

`gainPercent.value` 始终是相对首次实际成交价的比率，0.5% 对应 `0.005`；`0.5` 本身是合法 50% 阈值，不能全局拒绝或静默改写。修复字段元数据、共用生成提示与明确原文的一致性检查，不改变执行器、历史数据、资金上限或现有合同的结构。ATR 倍数不是百分比，不除以 100。

语义检查只处理能唯一对应单个加仓阶段的明确上涨／浮盈百分比，不猜测歧义、多阶段映射、否定或其他基准的收益。普通 AI 编写对照已审核需求，局部修改计划以本次修改意图为准；实验发现对照当前生成的 description/reason，不能从标的范围推断未提供的用户意图。真实验收另对照独立自然语言意图检查原输出。

生成和应用建议时执行原文检查；审核保存继续检查当前定义及审核摘要，不用保留的旧需求覆盖已确认的局部修改或人工编辑。实验缓存建议进入候选保存边界时同样检查当前 reason。

运行态收口时，工作区并行改动令基准身份函数直接读取联合类型的 `routeKey.timeframe`，阻断构建。仅补充调用链已有的 K 线来源不变量检查，保留按冻结来源读取周期的行为；不回退该改动或扩大基准计算调整。

## 验收条件

- AC1：生成 Schema 直接说明百分比小数单位，并区分涨幅、数量比例、权益比例和 ATR 倍数；共用提示覆盖小于 1% 的例子。
- AC2：普通编写、计划局部修改及实验发现的精简／完整生成边界拒绝明确的 0.5% 与 `0.5` 矛盾，合法 50%、等价小数字符串与明确修改意图通过；不修正输出。
- AC3：沿用现有无凭据本地 Qwen，真实生成一次加仓计划，300 秒总墙，不自动重试；固定自然语言意图不提示字段名。新请求使用修复后的 Schema 和提示，保留原始输出、AiRun、实验、候选、版本和回测。
- AC4：读取原 Run `9c7efea9-9242-494b-8bec-cef825ed4b1d` 的同一 282 行冻结输入，行摘要与可比指纹完全相同；1% 滑点、0.1% 佣金、最低 HK$10，实际发生加仓，逐笔已有持仓占用加新成交额及全部费用不超过设定投入上限，完整复跑一致。
- AC5：只读核对原策略、6 个版本和 14 条回测不变；旧失败、旧隔离版本与回测不覆盖。沿用已确认的隔离真实服务验收方式，不将其提升为产品 HTTP／队列或绩效优选证据。
