# 竞技场 Desktop 界面与交互重设计

## 目标与边界

以比赛任务组织信息，覆盖首页、创建、自主比赛、日频比赛和轮次详情。截图中的日频详情为首要修复面。沿用现有字体、颜色、组件和交易语义；现有历史记录、原始精度、预算、来源准入及模型调度均不改写。不为截图生成收益、排名或估值，也不以现金替代净值。父级功能及真实市场门禁继续由[自主竞技场任务](../tasks/2026-11-12-autonomous-model-arena.md)持有。

## 验收合同

- U01：详情只保留一个比赛主标题；返回列表或原来源、刷新、周报及生命周期操作有明确层级。决策与成交在比赛详情内查看，列表返回条件和原来源深链保持可用。
- U02：日频详情分为收益表现、模型账户、决策与成交和比赛设置。账户信息由模型账户页签统一承载；“查看最近决策”定位到本比赛的决策与成交页签、最近日期和对应模型。收益表现聚焦净值与比较结果。无可用净值时显示一次准确原因及前往已有记录的入口；部分可用时保留每行真实缺失。全部费项、预算和冻结规则仍可查阅。
- U03：长模型标识在容器内换行，账户现金明确标为现金；已结束比赛的零预算不占默认表现区域。模型／基准比较和数值精度沿原结果，不重新计算历史事实。
- U04：决策与成交按交易日期和模型筛选，页面内展示决策及成交，调用与冻结资料可展开；保留原摘要、失效条件、执行原因、来源引用、费用、请求标识和冻结快照。页签、日期和模型通过 URL 保存，刷新与前进／后退恢复；切换模型复用同轮读取，日期切换不会显示旧轮次结果，后台刷新仍保留同轮内容并等待相关请求结束。旧轮次地址及模型锚点重定向至同一比赛内的对应记录；无记录、无匹配模型、无效链接和读取失败分别表达。
- U05：自主比赛与日频比赛沿用同一页头和内容层级，自主收益曲线、图例、周期、净值、成交标记与模型账户联动保持可用。创建页按基本信息、市场范围、模型、资金预算、研究设置和行情观察设置分组；研究设置默认展开，步骤与时限直接可见，监测标的数量、观察间隔和行情延迟单独归入行情观察设置。两组沿用其他模块的标题、间距和分隔样式，两端分组一致，保留原保存契约及网页搜索开关。
- U06：沿用共享组件与原子类，以标题、留白和对齐分组内容；独立模块之间使用单条轻量横向分隔线与统一上下间距，线条与内容边缘对齐。概览、账户、设置、创建、轮次、空状态和折叠区域遵循全局内容分组准则。1440／1024／768／390 无页面横向溢出、遮挡及不可达控件。初始加载、失败、同范围刷新保留内容并等待相关请求结束，单范围仅一个加载圈。
- U07：受控样本验证状态操作和提交，真实业务数据只读；实际页面消费与受控数据、原生宿主和三市场执行验收分开记录。
- U08：列表、新建、日频及自主详情的全部页签、周报列表与详情统一操作、折叠、模型标题和模块分组。日期标签仅保留业务名称；时间复用共享格式化；令牌额度用语一致。精简重复指引与按钮中的错误说明，保留预算消耗、时区、缺失数据、现金与净值差异和冻结事实。周报返回本比赛，明细进入本比赛的对应日期与模型。

- U09：自主及日频创建的参数校验在对应字段或分组显示具体中文原因，输入标记错误并关联说明；参赛模型不足显示在模型选择处，标的范围或导入问题显示在范围处，日期、金额及研究限制分别归位。Desktop 提交后定位首个错误，两端修改后重新校验；校验未通过不发送请求。服务端结构化字段错误按字段路径投影，不解析异常文案猜测位置。网络、服务或响应确认失败保留在保存区域，编辑后的输入不显示旧提交的字段错误。两端相关入口保持相同校验语义。

## 信息结构

比赛详情：返回与来源 → 比赛标题、状态、市场、赛期和操作 → 简洁事实摘要 → 内容页签。收益表现为默认页签，账户和轮次可从空状态直接进入，设置拥有完整规则及预算。

创建页：明确的新建标题与返回 → 基本信息和市场范围 → 参赛模型和网页搜索 → 模拟资金及交易规则 → 模型调用预算 → 研究设置 → 行情观察设置 → 保存草稿。研究设置及行情观察设置均直接展开，字段使用现有标签、数值输入和选择组件，保存前不触发创建、研究或行情调用。
