# 研究详情与投资复盘阅读布局

## 目标与边界

以当前未提交工作区及实际路由为基线，优化 Desktop 的研究详情、完整阅读、单笔与周期复盘及其快照。保留既有计算、请求、模式隔离、历史冻结、错误恢复和显式保存语义。不提交、不推送、不部署，不发起真实模型请求或修改业务数据。

## 验收合同

- AC1：研究抽屉及完整阅读共享正文，短主题之后依次呈现结论、重要风险与缺口、关键依据。背景、字段、来源和运行信息按需展开；保留论点与证据的对应关系、历史原文及完整字段。失败、待核验及账户模式语义保持。
- AC2：比较与复核为正文之后的紧凑次级入口，保留报告选择及历次复核。优先呈现数值、状态和证据变化，仅文字变化称为表述变化；选择具体项后再左右对照，窄屏上下排列，不推断观点反转。
- AC3：单笔维持抽屉，未分析展示标的、事实、完整性与开始操作；分析后先看结果，按项目、计划、实际、偏差同行对照，异常和影响判断的缺口可见，反事实与实际分开。来源和运行细节按需查看。每次开始生成本次解读，显式保存才留存。
- AC4：周期维持外层页面，以完整交易周期、单次减仓为两列放入同一张表，先展示各自合格样本数，保留观测、排除、时间未知、指标适用性、缺失依据与下钻。双零时简明说明不可计算指标，单零不隐藏另一组，区分零、不适用、证据不足。
- AC5：单笔及周期快照复用对应结果阅读结构，显示保存时刻与冻结结果，已知过期状态可见，兼容旧快照，不重算或改写历史。
- AC6：定向测试、Desktop 类型与构建检查以及实际组件浏览器交互覆盖研究两种阅读、单笔、周期、快照；尽量覆盖 1440、1024、768、390，有数据、零样本、部分缺失与旧快照。受控样本验证与真实服务验收分别记录。

## 实施入口

`AiResearchDetailView → ResearchSavedReport`；实际路由 `JournalReviewWorkspace → JournalObjectReview / JournalPeriodReview`；历史使用 `JournalSnapshotDetail / JournalPeriodSnapshotDetail`，AI 正文使用 `JournalAiResult`。复用共享组件与原子类，减少普通内容的嵌套边框。
