# 能力首次使用与自动验证

## 产品要求

当前来源已启用、连接配置完整、具备已适配的精确能力并被用户路由选中时，能力尚未验证不应阻止第一次真实使用。一次真实请求完整成功后，即持久保存该能力验证通过的结果，后续读取和服务重启应复用。

验证以来源、上游、市场、资产类型、能力、周期、复权口径及当前来源配置、凭据与适配修订为边界。成功记录不能泛化到其他能力；配置或实现变化后重新显示未验证。成功只要求一次，后续临时故障独立表达运行状态，不抹去同版本已成功的历史事实。

## 行为与不变量

- AC1：首次使用不以缺少验证成功记录为拒绝条件；保留用户启用、选源、连接配置、实际权限、调用预算及输入合法性校验。未适配的能力不伪造实现。
- AC2：日线、分钟、报价、普通查询与事件按实际请求合同接受结果后才记录成功；HTTP 200、格式错误、未完成分页、失败状态、无效覆盖或受控 fixture 均不能生成真实验证证据。缓存数据须仍绑定当前配置、凭据及请求合同。
- AC3：记录关联精确能力与配置上下文，包含首次成功时间和非敏感请求证据摘要。并发成功幂等，配置变化期间返回的迟到结果不能认证新版本；重启后仍能读取。
- AC4：能力目录区分可尝试性和是否已验证，Server 与客户端消费同一结果。未验证的可尝试能力不显示为不可用；已验证状态须有实际成功记录支撑。
- AC5：定向测试覆盖首次成功、失败不认证、重启、上下文失效、并发及真实首次请求；通过正式更新入口应用，保留运行态和数据保护证据。

## 兼容与范围

复用 DSA 对来源能力与本地控制库的所有权，ThesisLedger 维护共享读取合同及客户端展示，infra 维护部署编排。不修改历史冻结业务记录，不自动启用来源或修改选源，不购买权限，不遍历调用全部外部能力。真实验证选择当前已启用来源的小量代表请求，并遵守现有预算与超时。
