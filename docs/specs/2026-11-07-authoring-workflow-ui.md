# 自然语言策略编写流程展示

## 问题与范围

自然语言创建在空草稿阶段同时展示分析、生成、局部修改、实际定义和保存区，用户难以确定下一步。此次优化 Desktop 编写工作页的展示与操作层级，沿用[自然语言策略编写规格](2026-09-18-natural-language-strategy-authoring.md)的领域流程与安全约束。

## 展示契约

1. 按「描述策略 → 确认条件 → 审阅保存」组织工作页。首次应用分析结果后进入条件确认，首次应用生成结果后进入审阅；用户仍可返回前一阶段修改。
2. 描述阶段填写名称、策略想法并明确选择编写模型，主操作为分析。条件阶段确认问题、需求与交易条件，满足既有条件后才能生成草稿；展示尚缺事项。
3. 调用状态、费用及待应用结果在阶段内容之前展示。分析和生成结果均须明确确认应用，不能自动改写草稿。
4. 有定义后才展示定义审核、局部修改和正式保存。空草稿不以错误状态提示缺少定义；无效的已有定义仍须显示错误及修正入口。
5. 草稿状态保持可见，复制、服务器恢复和丢弃作为次级操作；替换内容与丢弃保留既有确认。实际定义使用共享平面分组，减少重复边框与重复摘要。

## 保留边界

不修改服务端、接口、持久化与版本语义。不新增自动模型调用、费用回退或默认交易条件。保留自动保存、并发修订检查、未知提交恢复、确认失效、需求排除、历史费用追溯、最终逐项审核和原导航保护；真实业务数据只读。

## 验收

- 空白、已分析、已生成、定义无效、保存后及调用失败状态，均保留正确的可执行动作。
- 定向测试覆盖阶段迁移、不可跳过的确认与过期审核、草稿恢复确认。
- 构建通过后，在实际浏览器的 1440、1024、768、390 宽度检查布局、聚焦、切换、菜单、确认及原返回导航。
- 真实页面只读检查与受控样本的完整应用、审核和保存流程分别记录；受控样本不代表真实模型或业务写入验收。
