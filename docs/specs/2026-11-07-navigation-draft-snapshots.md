# 导航确认的草稿快照保护

## 问题与目标

全局 `NavigationGuardProvider` 在异步确认后只重新检查忙碌状态，随后丢弃当前全部草稿并提交原转换。确认期间编辑内容刷新、替换编辑目标或注册新的草稿时，旧确认仍可能清除新内容。Provider 卸载后，晚到确认也不应提交转换。

导航与账户模式切换共同消费当前已提交的草稿身份。局部关闭保护已定义的快照可直接桥接；旧编辑器在实际持有字段的组件内登记快照，父级继续负责页面或账户切换的协调。

## 验收标准

- AC1：确认期间任何受保护草稿的内容或业务身份改变，原转换返回拒绝，不丢弃任何草稿、不改路由或账户模式；下一次请求重新确认。
- AC2：确认期间新增、移除或替换受保护编辑会话，旧确认失效；Provider 卸载后不执行丢弃或转换回调。
- AC3：普通重渲染和回调更新不误判为内容变化；内容及会话不变时使用最新丢弃回调并只提交一次。取消、重复请求、忙碌和成功保存后的 bypass 保留原行为。
- AC4：共享 `useDraftCloseGuard` 的 20 处调用通过桥接获得导航保护；旧账户、持仓、交易、导入、策略与来源编辑入口按字段所有权登记快照。只保护在途状态的入口保留原职责并记录理由。
- AC5：定向挂载回归、Desktop 完整包、构建和相关仓库门禁通过；四宽真实浏览器覆盖模式切换、路由离开及确认期间草稿更新，不写业务数据、不调用外部服务。
- AC6：AST 边界门禁拒绝实际导航登记中缺失或为空的草稿快照；显式 `dirty: false` 的忙碌保护、注释及测试输入不误报。
- AC7：取消后快速再次离开仍能重新确认；确认期间切换路由目标时，旧确认不能用于新目标，也不能先丢弃草稿后停留原页。

## 实施边界

导航层只校验转换资格，不持有业务表单、保存请求或持久化状态。草稿内容按可序列化快照比较，注册身份用于区分编辑器会话；不能按 React 对象或回调引用变化拒绝所有普通渲染。业务身份和未保存内容由拥有字段的组件提供，不把表单上提到全局 Context。已有非受控表单可以复用编辑事件产生的版本号；聚焦、失焦及显示格式化不产生编辑版本。

不修改业务数值、历史记录、保存幂等键或外部调用条件。不改变来源、模型、通知及部署授权。执行与当前缺口由[任务](../archive/tasks/2026-11-07-navigation-draft-snapshots.md)维护。
