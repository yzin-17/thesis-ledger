# 严格校验与数据投影排查

## 目标与范围

检查自选添加弹窗修复以外的同类问题：完整接口、持久化或导航对象被传给只描述子集的严格 Schema，导致合法对象因额外字段失败，继而被过滤、隐藏、禁用或错误降级。范围包括 Desktop、Mobile、Server 与 API Client；以实际源码和数据合同为证据，不把所有严格校验失败都当作缺陷。

## 约束与验收

- AC1：盘点校验调用及失败后的处理，优先核对标的选择器、筛选和准入路径，再核对其他静默丢弃路径；记录正常保留项及理由。
- AC2：确认缺陷后在拥有该投影的边界修复，保留严格响应、身份、来源和历史事实约束。不用全局放宽 Schema 或吞掉异常代替修复。
- AC3：用包含完整合法字段的实际生产者样本复现；非法身份、必要字段缺失和真正错误仍按原合同拒绝。修改 UI 时验证真实组件和代表宽度，真实业务默认只读。
- AC4：按定向验证、相关包构建/类型、门禁、所需运行态分层验收；保留既有工作区变更，明确受控样本、真实接口和跳过项的边界，不提交 Git。

检查不扩展为改造全部 Zod 调用、更新业务事实或重写所有历史兼容逻辑。命中项按同一原因复核，不根据命名或正则匹配直接修改。

## 已确认修复边界

- 复盘 API Client：完整快照请求的合法 `aiRunId` 不属于新建 AI 解读请求。先按完整请求校验，再投影解读字段；保留完整请求和响应的严格性、作用域关联，不发起真实 AI 任务做验证。
- 研究复核材料、回测执行窗口预检、冻结 raw 派生接缝：Market 合同已经允许经过校验的多窗口响应，消费方不能再次用单窗口 Schema 将其误判为覆盖不完整或拒绝。复用 Market 的现行证据解析器，保留多窗口观测、内容指纹、来源、固定请求和可用时点校验，不放宽成任意附加字段。Market 提供同一解析器的成功/失败投影供原有布尔门禁使用，边界脚本限制这些消费者重新旁路。
