# 工具归档、界面回归与数据库恢复规范

## 背景与范围

按[工具审计](../reviews/2026-11-15-scripts-maintenance-audit.md)实施用户明确要求的三项整理：归档 5 个已结案专项脚本、把 7 个界面验收脚本纳入可重复回归、修复 `restore-db.sh` 与当前指南，并更新引用及 CI。待复核文件、其他回归及当前任务保持原职责。

## 稳定行为

- 专项脚本按原任务进入 `scripts/archive/<任务标识>/`，保留文件名、历史边界与配套测试；更新相对依赖和实际引用，不保留旧路径副本。归档的交叉修复测试继续由 CI 明确执行。
- 界面回归按标的、提供方、风险分组置于 `scripts/local-runtime/browser/`。统一入口管理专属 Vite 服务、临时端口、输出和清理；默认使用 Chromium，允许显式选择本机浏览器渠道。CI 自动执行全部 7 项，失败保留报告。
- 界面回归仍覆盖 1440、1024、768、390 宽度和原交互断言；外部来源、模型、通知及真实 API 不可到达。原健康历史真实只读检查转换为固定数据分页回归，其历史证据仍保持原范围。
- 恢复入口默认只预检。`--apply` 必须同时提供实际数据库名和 owner 的精确确认；活动连接未停止时拒绝写入。备份必须有匹配的 SHA-256；当前 migration head 与预期 Prisma/raw-owned 表复用 Server 结构发现能力，不复制清单。
- 仅支持与当前源码结构一致的可信备份；不自动升级历史备份，不自动清库、不操作容器或卷、不停止运行中的消费者。恢复 SQL、完整表检查和 SchemaVersion 检查在同一事务执行，失败整体回滚；不将数据库结构就绪宣称为产品 E2E 通过。
- 保留现有 `backup-db.sh` 产物格式。恢复工具从自身位置定位仓库，不能依赖调用目录；连接凭据不进入报告。指南准确陈述预检、写入、恢复及验收边界。

## 实施边界

不修改业务 UI、领域计算、Prisma schema/migration、进行中的任务、维护锁登记或 13 个待复核文件；不执行目标业务数据库恢复、部署、模型或真实通知。新增隔离 PostgreSQL 验收入口只拥有唯一命名的临时资源，验证结束清理自身资源，不挂载业务目录或卷。

## 验收标准

- AC1：5 个专项脚本完整归档，原路径移除，运行定位和配套测试有效，历史引用指向新位置。
- AC2：7 个浏览器回归可经统一入口执行，全部原代表宽度与交互断言保留，自有服务自动清理，受控请求隔离真实业务。
- AC3：恢复预检不写数据库；缺失/错误校验和、目标不匹配、活动消费者、结构不完整、版本不匹配和数据库命令失败均不能产生成功结论。恢复及结构校验在同一事务，隔离 PostgreSQL 验证成功与回滚。
- AC4：CI 明确覆盖归档测试、恢复定向测试和 7 项浏览器回归；指南、审计路径与新工具索引一致。
- AC5：待复核项及原有工作区修改保留。定向验证和受影响静态门禁通过；并行业务引发的问题单独记录，不扩大通过结论。

## 验证与证据边界

顺序为脚本合同/失败测试、归档测试及静态引用检查、受影响检查、真实 Chromium 回归、专属隔离 PostgreSQL 恢复与事务回滚。无需目标运行态更新；该工作不改变产品界面，也不验证原生编译或线上来源。历史冻结内容只修正可执行路径，不重写当时结果。

本规格继续作为当前工具行为合同；已完成[实施任务](../archive/tasks/2026-11-15-scripts-maintenance.md)与[验证证据](../evidence/2026-11-15-scripts-maintenance.md)分别归档和保存，不重复维护执行状态。操作入口见[工具索引](../../scripts/README.md)。
