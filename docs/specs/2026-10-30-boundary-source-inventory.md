# 导入边界门禁的维护源码输入

对应[已完成实施记录](../archive/tasks/2026-10-30-boundary-source-inventory.md)。

## 问题与范围

前四项接续时，全仓导入门禁把 `apps/mobile/release/` 内另一会话保存的 Git 忽略源码副本当成正式模块，按副本路径产生 BullMQ 非法依赖误报。本项只校正输入清单，保持原全部依赖断言、允许边界、TS/TSX 范围及既有 node_modules/dist/coverage 范围不变。

## 合同与验收

- BI1：以当前 Git 工作区已跟踪文件与未忽略的新文件的并集为输入；在 apps/packages/services 内检查原 TS/TSX 范围。
- BI2：未跟踪且已忽略的生成副本不进入检查；即使被 ignore，已跟踪的维护源码仍进入检查。待删除的缺失文件不再读取，路径以 NUL 分隔，保留空格和中文。
- BI3：不添加针对 release 或本次副本名称的特例，不提高阈值或放宽任何依赖规则；新增文件的非法导入仍报错。
- BI4：Git 清单获取失败应失败关闭，不回退为不完整结果；本项不修改 Git 索引、源码副本、生产代码或 Docker 状态。

用独立临时 Git 仓库验证忽略副本、跟踪但忽略的源码、新维护源码、待删除文件及真实非法导入；通过后执行原全仓入口。原业务 Task 不由此代收真实 Provider 或运行态。
