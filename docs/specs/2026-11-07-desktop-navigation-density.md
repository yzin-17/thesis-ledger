# Desktop 公共导航图标与间距

## 问题和目标

四宽页面验收发现，390 宽度的底部导航图标被压成细线。导航同时使用传统 CSS 的 11px 间距、9px 垂直内边距和原子类的纵向排列；固定栏高度下，可收缩 SVG 承担了空间缺口。实际 DOM 确认为 19×2。另有 800 宽度恰好处于两套媒体条件之间，长短标签同时隐藏；导航排列、间距和短标签须与既有 800px 及以下布局使用同一条件。

## 验收标准

- AC1：公共导航使用组合原子类表达尺寸、间距和内边距，移除同一属性的旧覆盖；不新增传统选择器、重要性覆盖或渲染分支。图标保持 19×19，不被压缩。
- AC2：保留全部 9 个路由、中文可访问名称、当前页状态、键盘焦点、展开/收起及账户模式交互。窄屏导航在自身横向滚动，文档不横向撑宽，标签和图标在各自控件内可见。
- AC3：覆盖 1440、1024、768、390 及 320、520/521、800/801 断点附近的实际浏览器尺寸；检查图标、文本、内容边缘和折叠往返。定向验证后运行 Desktop 完整包、构建与适用门禁。
- AC4：记录稳定输入与实际证据，完成本叶后归档，继续全线程 Goal。

## 所有权与边界

导航结构属于 AppShell；由同一组 className 负责导航项尺寸和间距，原状态、路由以及共享交互继续由原 Module 维护。已有颜色、选中、强制颜色与布局规则保持所属职责。检查全部导航消费者和折叠、断点派生状态，不改变业务页面、API、精度和数据。

基线为上一轮生产资源的只读副本 `/tmp/goal-navigation-before-dist`。业务请求通过隔离响应读取；不执行 Docker、真实来源、数据库、模型、通知、提交、推送或发布。实施见[任务](../archive/tasks/2026-11-07-desktop-navigation-density.md)。
