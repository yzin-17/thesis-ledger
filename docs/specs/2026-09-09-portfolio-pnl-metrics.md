## 背景与问题

当前“投资组合 > 组合概览”展示总资产、今日持仓收益、累计浮盈亏和最大持仓。最大持仓可以通过下方按市值排序的持仓列表获得；“累计浮盈亏”实际上读取的是当前持仓相对成本的未实现盈亏，名称会让用户误以为已经包含已卖出交易。

仓库已有统一真实账户链路：`LedgerEventV2` 记录 BUY/SELL 事实，Core Projection 生成 `Trade` 与 `TradeCloseSlice`，其中 `netRealizedPnl` 已按账户成本策略和成交费用计算。Portfolio 估值已经由 Server 计算上一交易日收盘到当前持仓的每日变化。本次只补齐组合级收益字段和展示语义，不另建一套客户端财务计算。

## 目标

- 将四项核心指标统一为“总资产、今日收益、累计盈亏、已实现盈亏”。
- 保留今日收益现有“当前持仓相对上一交易日收盘”的计算口径，并让名称、金额和收益率一致。
- 区分当前仍持有部分的未实现盈亏、已经卖出部分的已实现盈亏，以及二者之和的累计盈亏。
- 复用现有 Ledger/Trade 投影和 FX 视图；不使用 mock、固定值或从当前持仓倒推已实现盈亏。
- 保持现有组合概览 2×2 布局、视觉风格、列表字段和交互不变，只调整必要标签与数据。

## 非目标

- 不新增交易系统、订单系统、成本策略或新的 Prisma 持久化模型。
- 不重构 Portfolio、Trade Projection、Performance 或 FX 模块的既有架构。
- 不改动持仓列表除“累计收益”改为“未实现盈亏”及其对应语义外的字段和交互。
- 不把本次 Desktop 指标调整扩展为移动端页面重设计；API 保留现有 `totalPnl` 兼容字段。

## 领域语义与计算口径

### 1. 总资产与今日收益

- `总资产 = 当前证券市值 + 现金`，沿用 `/portfolio/valuation` 的 `totalMarketValue`，其中现金沿用现有 `cashValue` 与现有币种/FX 汇总边界。
- `今日收益`金额沿用 `dailyChange.pnl`。
- `今日收益率`沿用 `dailyChange.returnRate`，分母为当前持仓对应的上一交易日收盘市值。
- `dailyChange.basis` 必须继续为 `PREVIOUS_CLOSE_CURRENT_HOLDINGS`。缺少任一持仓上一价格时保持不可用，不用 0 掩盖缺失。

### 2. 未实现盈亏

- `未实现盈亏 = 当前仍持有部分的当前市值 - 当前持有部分成本`。
- Server 新增 `unrealizedPnl` 与 `unrealizedPnlRatio`，金额在组合本位币中计算；当前持仓估值或本位币转换不完整时结果为不可用。
- 现有 `totalPnl` 保留为兼容字段，继续表示原有当前持仓盈亏；新的组合概览不再用它冒充累计盈亏。

### 3. 已实现盈亏

- 数据源为当前账户范围和 `actual/shadow` 模式下有效 Trade Projection 的 `TradeCloseSlice`。
- 每个 SELL/部分卖出对应的 Close Slice 使用已持久化的 `netRealizedPnl`；该值已经由领域成本策略分配来源成本，并扣除可确认的买入费用和卖出费用。
- `已实现盈亏 = 所有已卖出 Close Slice 的已确认净实现盈亏之和`，再按现有 FX View 转换到组合本位币。
- 没有任何卖出记录时返回真实的 `0`，收益率因没有已实现成本分母而为不可用。
- 任一已卖出 Slice 的实现盈亏、成本来源、`costEstimated` 估算标记、费用币种或本位币转换不可确认时，组合级 `realizedPnl` 和相关累计结果返回不可用；不得使用毛实现盈亏、当前持仓成本或固定值替代。

### 4. 累计盈亏与收益率

- `累计盈亏 = 已实现盈亏 + 未实现盈亏`。
- 只有已实现和未实现两部分均完整且可转换到组合本位币时，Server 才返回 `cumulativePnl`。
- `累计盈亏率`的分母为“当前持有部分成本 + 已卖出部分成本基础”，其中已卖出成本基础来自 Close Slice allocation 的 `originalCost + allocatedBuyCharges`，与领域层已实现净收益率的成本口径一致；两部分先转换到组合本位币再相加。
- 分母为 0 或收益数据不完整时，`cumulativePnlRatio` 返回不可用。UI 必须展示不可用状态，不以未实现盈亏率冒充累计盈亏率。

Server 响应新增以下明确字段，旧字段保留用于兼容既有客户端：

| 字段 | 语义 |
| --- | --- |
| `unrealizedPnl` / `unrealizedPnlRatio` | 当前持有部分的未实现金额与相对当前成本收益率 |
| `realizedPnl` / `realizedPnlRatio` | 已卖出部分的已确认净实现金额与相对已卖出成本基础收益率 |
| `cumulativePnl` / `cumulativePnlRatio` | 已实现与未实现之和及相对总成本基础收益率 |

## UI 方案

保持现有 2×2 四宫格和 `Metric` 组件，仅替换指标内容：

| 位置 | 主标签 | 主值 | 辅助信息 |
| --- | --- | --- | --- |
| 1 | 总资产 | `totalMarketValue` | 证券与现金拆分 |
| 2 | 今日收益 | `dailyChange.pnl` | `dailyChange.returnRate · 较上一交易日` |
| 3 | 累计盈亏 | `cumulativePnl` | `cumulativePnlRatio · 已实现 + 未实现` |
| 4 | 已实现盈亏 | `realizedPnl` | 完整时“来自已卖出交易”，不可用时说明成本未完整确认 |

移除“最大持仓”卡片。持仓列表仍按市值排序，并将“累计收益”列名改为“未实现盈亏”；该列继续使用当前持仓的 `pnl/pnlRatio`，不改其他列和交互。

## 验收标准

- **AC1：** 组合概览保持 2×2 布局，四项卡片依次展示总资产、今日收益、累计盈亏、已实现盈亏，不再展示最大持仓。
- **AC2：** 今日收益金额和收益率继续来自 `PREVIOUS_CLOSE_CURRENT_HOLDINGS`，缺少上一交易日价格时明确不可用；UI 不只改文案。
- **AC3：** Server/API 提供明确的未实现、已实现和累计金额/收益率字段；累计金额严格等于已实现金额加未实现金额，不把旧 `totalPnl` 直接改名为累计盈亏。
- **AC4：** 已实现盈亏只使用真实 Trade Close Slice 的已确认净实现数据，覆盖无卖出、部分卖出、全部卖出和多次卖出；不使用 mock、固定值或当前持仓反推。
- **AC5：** 成本不完整、费用币种不匹配或 FX 不可用时，已实现/累计结果明确不可用且不生成误导性的 0 值；无卖出记录仍显示真实 0。
- **AC6：** 持仓列表“累计收益”改为“未实现盈亏”，金额与收益率继续表示当前持有部分，其他列表字段和交互不变。
- **AC7：** 补充 Server/domain/API/UI 定向测试，覆盖收益公式、交易场景、字段契约和四宫格渲染。
- **AC8：** 不新增 Prisma migration，不引入无关重构；工作区既有未提交修改保持不被覆盖。
