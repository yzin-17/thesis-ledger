# 数据源统一身份与逐功能权限

## 目标与范围

同一供应商使用一个数据源及一份配置，不按免费或收费档位重复注册。TickFlow 合并为 `tickflow`，每个精确能力只提供一个 TickFlow 目标；历史日线保留原免凭证读取边界，分钟和实时行情按 Key 的实际权限检查。其他来源复用逐功能权限展示契约，某项不可用不隐藏整源的其他功能。

当前库存中只有 TickFlow 以收费/免费拆成两个注册身份。其他独立供应商、不同业务协议及本地历史资料保持领域边界；不凭接口名称推断费用或开通状态。

## 行为与约束

- TickFlow 提供“检查功能权限”。无 Key 可检查免凭证日线，Key 缺失的其他功能显示缺凭证，不发送其上游请求；目录就绪、凭证修订和执行入口也按精确能力判断，不能用日线免凭证推定分钟和报价无需 Key。明确拒绝、认证失败、限流、网络错误和未检查分别表达。统一日线沿用已验证的沪深 A 股及3650日、单响应10000行边界，不新增其他市场范围。
- 沿用有界权限检查、凭证快照、草稿隔离与迟到结果保护。当前配置的权限检查结果按[长期保留规格](2026-11-10-provider-access-retention.md)持久化，凭证变更后失效；未保存草稿仍有时限。TickFlow 的精确检查可在18秒总预算内最多进行14次接口检查；其他来源保留原请求上限。读取日线和正式检查保持独立，不将权限成功提升为完整历史、数据质量或可成交证明。
- Tushare 的账号积分和独立权限字段只用于声明该等级契约的来源，不能要求 TickFlow 填积分。逐功能面板展示可用与不可用结果；路由选项仍只允许有效权限。
- 历史 `tickflow-free` 记录保持冻结语义。当前政策通过正式 API 将该目标替换为 `tickflow/tickflow`，重复目标按原顺序去重；不自动开通付费功能或购买权限，保留 TickFlow 当前显式启停选择。免费日线连接不得接收 Key。
- 不修改依赖、数据库结构、模型预算或其他来源凭证。检查接口只在用户操作或受控样本中运行，真实数据默认只读。

## 验收

- AC1：生产目录只有一个 TickFlow 来源，每个精确能力只有一个 TickFlow 目标，原日线规范化与免凭证隔离仍通过。
- AC2：无 Key、有效 Key 部分权限、明确拒绝、限流、网络失败、草稿过期及配置变更均有定向验证；当前权限长期记录和 Tushare 等级契约回归通过。
- AC3：通用界面逐功能呈现状态，TickFlow 不出现积分字段；检查、草稿、取消及路由选项通过受控测试与四种屏宽浏览器验收。
- AC4：正式脚本同步 DSA，独立检查实时目录与当前政策；宿主 Desktop build 和页面通过。任何未完成的真实上游条件明确记录，不以受控样本代替。

官方协议依据：[TickFlow 官方 SDK](https://github.com/tickflow-org/tickflow/blob/main/tickflow/client.py)。已实施，执行任务见[归档任务](../archive/tasks/2026-11-09-provider-functional-access.md)，结果见[验收证据](../evidence/2026-11-09-provider-functional-access.md)。本规格继续作为同源逐功能权限的产品合同。
