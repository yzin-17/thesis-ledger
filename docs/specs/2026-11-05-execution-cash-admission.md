# 成交写入端现金余额校验

## 目标与范围

按用户确认，历史现金原值及配置展示保持可读；新增支出在录入提交时限制，避免本金和费用超过账户可用现金。已核对提现／划转存在余额校验，当前缺口是成交命令及复用它的基金定投确认。

只补 Ledger 成交写入准入及必要消费／验证，不修改历史账本或负余额，不改变收益和配置公式、现金快照吸收规则、资金来源、依赖或数据库结构。

## 契约与验收

- AC1：在账户写锁事务内、幂等命中检查之后、追加事实及调用副作用之前校验；失败使用既有 `LEDGER_INSUFFICIENT_CASH`，不得推进账本、持仓或定投实例状态。
- AC2：按币种复用现金投影，计入买入本金、同币种／跨币种费用和待付款占用；待收款不能当成可用现金，不用浮点或汇率跨币种凑余额。刚好足额允许。
- AC3：新建、更正、恢复和跨账户移动的目标写入均经过同一准入；更正按替代事实的净变化计算，不能把旧成交重复扣款。卖出所得可改善余额，费用造成净支出时也不能绕过。
- AC4：在当前时点及有明确生效日期的成交时点检查，避免以未来入账支付过去成交。沿用现有快照／结算投影；历史已有负余额允许保持或改善，禁止新写入使其继续恶化。
- AC5：历史读取、旧幂等重放、负现金配置展示保持原行为；提现／划转原校验保留。Desktop／Mobile 及定投入口消费同一稳定错误码与中文提示，失败保留输入／待确认状态。
- AC6：定向测试、受影响 Server 回归／构建与模块门禁通过；隔离 PostgreSQL 验证事务与定投失败不落账，真实本地运行态按维护入口更新并进行只读准入核对。不得在现有用户账户尝试可能成功的写入来制造验证数据。

## 所有权

现金准入属于 Ledger，复用 `cash-projection.ts` 与现有写锁上下文。Portfolio、现金计划、定投只消费 Ledger 命令；不得反向导入调用方或新增公共杂物模块。
