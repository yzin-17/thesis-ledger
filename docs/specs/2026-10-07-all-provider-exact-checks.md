# 全部数据源精确接入、配置与检查

对应任务：[已归档实施任务](../archive/tasks/2026-10-07-all-provider-exact-checks.md)。状态：本地、目标 API 与真实 Web 客户端验收完成，现行合同保留；[客户端验收](../reviews/2026-10-08-market-provider-client-acceptance.md)独立记录真实账号边界。

## 范围与问题

覆盖当前登记的全部 16 个数据源和精确目录中的 CN/HK/US 路由。前轮已补齐原生日线与报价接入，本轮核对剩余缺口：连接测试使用宽能力及旧 Fetcher，无法说明实际检查的资产、市场、上游与复权口径；事件专用和官方事实来源还会出现空测试结果或没有诊断入口。

## 行为要求

- 精确库存是检查范围的事实源。每条能力明确其来源、配置、依赖及准入状态，不能以一次股票测试授予 ETF、其他市场或其他口径权限。
- 测试支持用户指定一条精确路由；不指定时按能力选择有界代表性路由。读取复用精确生产读取契约，禁止调用带隐式换源的普通 Fetcher。结果必须携带实际检查的精确路由，未执行项保持未检查。
- 需要认证的全部来源按定义校验完整凭证，页面优先、环境备用；缺凭证不能启用。缺依赖、停用、证据缺失、权限失败和数据覆盖不足分别说明。
- 普通行情不恢复人工窗口准入；高级事件、历史事实、身份映射等继续核验真实证据。检查不签发准入，不修改策略、凭证、健康表或业务缓存。
- 前端为全部来源提供精确检查入口，支持中文能力选择并展示状态与错误；使用 TanStack Query、已有 Sheet/Select 和原子类。配置凭证入口保持可用。
- 外部账号不足或上游读取失败如实记录；本地接入和检查完整不等于全部真实来源已准入。

## 验收标准

- AC1：16 个来源均有精确诊断路径，清单中的全部路由具有配置与准入状态。
- AC2：检查请求固定精确 key/target；非法目标、错口径、错身份及凭证变化被拒绝。
- AC3：配置检查覆盖所有认证方式；空测试结果不会成功，缺凭证不能启用。
- AC4：普通来源读取按精确接口执行，高级证据门槛保留，检查不产生业务状态写入。
- AC5：客户端可选择并检查具体能力，结果回显与选项共用中文标签。
- AC6：定向测试、构建、仓库边界、正式运行态与真实来源证据分别记录。

## 所有权与部署

DSA 拥有精确接口与检查执行；共享 Schema 拥有请求/结果合同；Server 透传并验证；Desktop 选择与展示。不改数据库结构，不安装新 SDK，不购买或申请外部账号。纯代码通过 infra 正式快更入口更新，Desktop 另行构建并核验实际预览模块。
