## 1. 目标与边界

用户用自然语言表达交易规则，AI 帮助识别缺失条件、生成可读且可编辑的策略编写草稿。用户审核并保存后，形成策略库中的新策略及 v1，随后自主决定是否回测。

```text
新建策略 → 自然语言创建 → 描述想法 → 确认问题 → 生成草稿
                                                      ↓
                          手动编辑 ← 审阅规则 → 自然语言局部修改
                                                      ↓
                                确认保存 → 策略 v1 → 自主发起回测
```

### 1.1 已确认的产品选择

| 编号 | 已确认决策 |
| --- | --- |
| NL-D-01 | 先生成可编辑草稿，用户确认后保存；生成或保存不自动启动回测。 |
| NL-D-02 | 使用针对性澄清卡片确认缺失条件，不以长聊天记录承载核心规则，不静默补齐关键交易条件。 |
| NL-D-03 | 首期只支持单标的、单周期，使用现有引擎可表达的条件、仓位与风险能力。 |
| NL-D-04 | 编写草稿自动保存，刷新或离开后可以继续；尚未确认保存的草稿不进入正式策略列表。 |
| NL-D-05 | 入口整合在“新建策略”，提供“手动编写 / 自然语言创建”两种方式。 |
| NL-D-06 | 允许通过自然语言局部修改尚未保存为正式策略的生成草稿；先展示变更，再确认应用，未指定规则保持不变。 |

### 1.2 首期范围

生成目标为现有 `StrategySchemaV2` 可校验、现有执行器可消费的定义。覆盖标的与周期、入场、退出、仓位、支持的策略风险条件、执行时机与费用假设。回测日期、初始资金、数据获取等运行配置继续由后续“开始回测”流程负责，不能将“最近三年回测”等要求丢弃：应归入“回测时设置”提示，并在发起回测时再次确认。

本功能只创建新策略和修改其尚未确认入库的编写草稿。已有正式策略的修改继续通过原有版本编辑流程；不在首期增加对正式版本的自然语言修改。生成流程不创建 AI 实验、不搜索多候选、不读取训练/验证/封存测试区间、不改变账户或风险应用。

“保存为策略”表示用户认可该定义进入策略库，不代表经过回测、研究合格或收益可靠。正式策略仍可处于既有业务草稿状态；这与独立的“策略编写草稿”是不同概念。

## 3. 用户界面与交互

### 3.1 入口、布局与草稿恢复

策略库“新建策略”进入独立工作页。默认保留手动创建习惯，页面顶部可切换“手动编写 / 自然语言创建”。自然语言页包含未完成草稿的恢复入口，显示可读标题、最后更新时间和当前进度；不将草稿混入正式策略列表。直接打开草稿链接、刷新或浏览器返回，恢复同一草稿及其当前修订。

桌面宽屏将输入与可读规则并列，左侧负责输入/澄清/修改，右侧负责当前规则与限制；窄屏按输入、待处理问题、规则、操作顺序纵向排列。使用已有页面密度、控件和主题规范；不新增聊天侧栏，不以全屏 JSON 作为默认视图。

```text
策略中心 / 新建策略                          [继续未完成草稿 ▾]
手动编写    自然语言创建                        已自动保存
────────────────────────────────────────────────────────────
描述你的策略                      当前理解
┌──────────────────────────┐     标的       待确认
│ 价格上穿 20 日均线时买入， │     周期       日线
│ 跌破时卖出，设置止损。     │     入场       收盘价上穿 MA(20)
└──────────────────────────┘     退出       收盘价下穿 MA(20)
[已配置模型 ▾]  [分析描述]         仓位       待确认
                                  止损       待确认
待确认 · 3 项                     执行与费用 待审核
```

线框中的“当前理解”是待审核解释，不是已被用户确认的定义；示例仅说明交互，不是默认交易规则。“已理解 / 待确认 / 当前不支持”的状态除颜色外同时提供文字。

### 3.2 描述与澄清

首次输入后，“分析描述”调用当前明确选定的一个模型。模型不可用时解释原因，并提供已有 AI 配置入口；保留输入，不能自动更换模型。模型选择控件展示名称及已知计费说明；高级参数沿用现有能力配置。

分析结果按需求逐项呈现：

| 类别 | 呈现与动作 |
| --- | --- |
| 已理解 | 显示用户原句对应的规则解释；用户可修正，不把模型置信度当成已确认 |
| 待确认 | 每张卡片只处理一个有意义的缺口或冲突，说明影响，给出适用选项/输入；关键条件没有预先确认的默认答案 |
| 当前不支持 | 保留原句、原因及可表达的替代建议；需用户明确改写或移除，不能静默降低要求 |
| 回测时设置 | 保留日期、初始资金等运行意图，说明将在发起回测时确认；不混入交易信号规则 |

优先先确认会改变后续问题的标的、周期和执行模型，再确认信号、仓位、退出与费用。依赖前项的问题不提前要求无效答案；修改前项后，受影响答案和生成结果标记为需重新审核，保留原值供比较。

标的名称存在歧义时，用现有标的目录选择器确认市场、代码和资产类型；模型输出的文字代码不能直接作为权威标识。单一明确标的也需在摘要中展示目录解析结果。周期必须是现有支持值；不把“20 天”擅自解释成“20 根 K 线”。

所有影响交易含义的条件必须在生成前明确，包括持仓方式、信号确认与撮合时机、必要退出/风险条件、费用假设。用户明确选择“不设置额外止损”可形成答案；缺少条件不能被解释成不需要。若现有引擎只支持下一可交易时点开盘执行，用户要求当日收盘成交时应展示限制并要求修订，不能仅替换底层枚举。

“生成草稿”前展示完整规则摘要、仍保留的回测意图和用户已移除的要求；尚有未解决关键问题、不支持条件或矛盾时不可提交。修改原描述会产生新修订，现有答案和结果的适用性重新检查，不自动覆盖或丢弃用户输入。

### 3.3 审阅与手动修改

```text
策略中心 / 新建策略 / 均线策略草稿                 已自动保存
描述与确认    规则预览                            [返回策略库]
────────────────────────────────────────────────────────────
修改想法                          当前草稿
┌──────────────────────────┐     标的与周期   …
│ 止损改成 5%，其他不变。   │     入场 / 退出  可读条件与参数
└──────────────────────────┘     仓位与风险   …
[生成修改建议]                    执行与费用   …
                                  [编辑规则]  ▸ 完整策略定义
修改建议 · 尚未应用
止损比例        3% → 5%
其余规则保持不变
[放弃建议] [确认应用修改]
────────────────────────────────────────────────────────────
尚未回测。保存后可从策略详情发起回测。         [保存为策略]
```

右侧规则预览按“标的与周期 / 入场 / 退出 / 仓位与风险 / 执行与费用”组织，按需展开完整定义。展示的是当前实际草稿定义，不使用模型重新总结后的文字掩盖定义差异。原始描述、确认答案、被用户移除的条件、生成模型与时间可在来源区查看。

“编辑规则”复用已有结构化与高级定义编辑能力。手动编辑会产生新修订，重新运行结构及能力校验，并使绑定旧修订的未应用建议失效。草稿可保存暂时不完整的编辑内容，但不能将其标记为已验证，也不能保存为正式策略。

“自动保存草稿”与“保存为策略”必须使用不同文案。成功显示“已自动保存”；写入中显示“正在保存”；失败显示“保存失败，重试”，保留本地输入。仅当当前内容已持久化且无待保存修改时允许直接离开；失败、离线或仍在保存时离开应提醒。恢复时如另一个窗口已更新，展示冲突并允许保留/复制本地内容后重新读取，不静默覆盖服务器修订。

### 3.4 自然语言局部修改

用户输入局部修改后，系统先定位变更对象和允许变化的范围。对象不明确时继续使用澄清卡片，例如多个止损条件时需选定目标；不能让模型自行扩大“其他不变”的含义。

模型输出是待确认的变更提案。页面按语义展示字段前后差异、涉及的用户要求及可能影响；“确认应用修改”才写入当前草稿，“放弃建议”保持原定义。不存在变化时说明“没有需要应用的修改”，不创建空变更。

服务端在生成和应用时均检查允许修改范围。范围由用户明确意图、必要澄清和服务端允许字段共同确定；不能仅信任模型自行声明的修改范围。对范围外结构做规范化后的深度比较，任何额外改变均拒绝该提案。数值以策略契约单位存储，界面按百分比等用户单位展示；不能以字段名相同为由忽略条件引用、执行方式或风险意义的变化。

若必须连带修改其他字段才能形成合法定义，应单独解释并让用户扩大确认范围后重生成；不得偷偷修改。提案绑定基线修订，期间任何手动编辑或其他窗口更新都会使旧提案不可应用；提供基于当前草稿重新生成的动作。

### 3.5 保存、切换方式与下一步

点击“保存为策略”先完成当前草稿持久化、校验和规则审核，展示最终名称、标的/周期、可读规则及“尚未回测”。存在未应用提案时，要求用户先应用或放弃；不让“保存”隐含接受提案。确认针对明确修订，成功后导航到服务端返回的策略及 v1，不由客户端猜测 ID 或版本号。

保存后的来源展示“AI 辅助创建”；详情可查看原始描述、澄清答案、生成及修改记录、用户审核后的最终定义。用户手动调整过 AI 草稿仍保留这一来源，并标明手动修改事实。普通手动新建、AI 辅助创建、实验采纳分别记录；不能为 AI 辅助创建伪造实验/候选引用。

保存不会触发回测或风险应用。用户在详情点击“开始回测”后才进入现有运行配置，展示编写时保留的运行意图作为待确认项；本轮不自动获取行情。

切换创建方式时保留各自未提交输入。已生成的 AI 草稿可在同一编写草稿内进入结构化编辑，仍保留来源；切换到另一份手动创建表单不应隐式把 AI 草稿入库或覆盖。已保存的编写草稿为只读来源记录，“继续”进入对应正式版本；后续编辑走正式版本流程。

## 4. 领域契约与状态

### 4.1 持久化对象

| 对象 | 最小职责与不变量 |
| --- | --- |
| 策略编写草稿 | 归属用户、标题、原始描述及其修订、确认答案、需求覆盖清单、运行意图、当前定义/未完成编辑、校验结论、修订号、更新时间和保存后的策略版本引用 |
| 编写操作 | 分析/生成/提出修改的类型，绑定草稿修订与输入快照、选定 Provider/Model、提示词与能力版本、执行状态/attempt、用量/费用/错误、结果引用 |
| 澄清问题 | 稳定问题标识、原句引用、缺口或矛盾原因、可选答案与用户回答、依赖条件、所依据修订 |
| 变更提案 | 基线修订、用户修改意图、经确认的允许范围、前后定义及可读差异、校验结果、待确认/已应用/已放弃/已过期状态 |
| 创建来源快照 | 确认时的需求与答案、明确移除项、模型操作引用、手动修改记录、最终定义与草稿修订；随 v1 固定，不随草稿后续读取变化 |

对象名是领域职责，不要求各对应独立数据表。原始说明、回答及定义可能含用户私有研究内容，按现有用户权限隔离，日志避免记录全文与密钥；来源读取不得泄露其他用户草稿。

### 4.2 草稿与操作分离

草稿持久化状态只表达“编写中 / 已保存 / 已丢弃”。“待分析、待澄清、可生成、可审阅、需重新审核”由当前修订的内容和校验推导，不能与 AI 请求运行状态混成一条状态机。用户可显式丢弃草稿；丢弃后停止接收新操作，晚到结果只记录审计，不能恢复草稿。

操作持久化状态至少覆盖“待执行 → 执行中 → 成功 / 失败 / 已取消”。修订变化导致成功结果不能应用时记录“结果已过期”的处置结论，不将完成的付费调用伪装成未发生。保存/丢弃会阻止后续结果写入草稿。取消不能保证 Provider 尚未计费，费用以实际记录为准。

草稿写入采用乐观并发控制。每次写入必须携带预期修订，服务端原子比较并递增；冲突返回当前修订及可读原因，不以最后写入胜出。模型请求捕获固定输入快照，返回时只有草稿仍为可编辑且修订相同才可挂接结果。分析结果也受此约束，不能用旧描述的答案覆盖新描述。

保存策略采用草稿级幂等与原子事务：重新校验预期修订、创建一个策略与 v1、写入来源、将草稿标为已保存并写入引用。双击、跨窗口同修订提交、响应丢失后重试只返回同一结果；不能出现策略已创建但草稿仍可再次保存的中间事实。确认前修订发生变化则拒绝并要求重新审核，不自动保存较新定义。

### 4.3 AI 执行、费用与恢复

每次用户动作只调用一个明确选定的 Provider/Model；不启用静默回退、多模型投票或自动纠错循环。模型切换影响新操作，历史记录保留实际使用的模型。费用已知时展示计费口径与实际用量；费用或币种未知时需明确确认才能调用，不显示为零。编写费用独立于 AI 实验预算，不跨币种汇总金额。

服务端持久化业务任务状态，浏览器只发起与读取。复用现有执行基础设施前验证任务类型、领取范围和租约；研究执行器不得误领编写任务。队列仅作投递通知，队列不可用时本方案默认拒绝新的付费操作并保留草稿，返回可重试错误；已持久化但未投递成功的操作由有界恢复逻辑处理，不同步降级到请求进程直接调用模型。投递查询失败不能被当作任务不存在。

领取、续租、结果提交和取消确认必须按操作状态与 attempt 原子更新。执行超时或进程重启后，有证据证明尚未调用 Provider 的任务可在有限次数内补投；是否已被 Provider 执行无法确定时标记失败及“结果未知，可能已计费”，由用户手动重试，不盲目再次付费。重试创建可追溯的新操作，并重新绑定当前草稿修订；上次调用的计费记录保留。

设计默认每个草稿同时最多一个活动付费操作；单次请求有明确超时和输出上限。具体限制在 T00 按现有 Provider 能力固化为配置和契约，不以无限等待或无限重试绕过。重复点击同一提交意图用幂等键归并；刷新、离开和断线后查询持久化状态，返回即展示当前进度和已完成结果。

### 4.4 语义与能力校验

AI 输出只作为不可信数据：先验证结构、引用与类型，再验证引擎能力、已确认范围和关键语义。不得执行模型生成的脚本、SQL 或任意表达式代码；原始文本中的指令不能修改服务端工具权限、模型路由或版本保存流程。

首期校验至少包括单执行标的、单周期、允许的信号源/指标/运算符、参数范围、条件引用、仓位、风险、执行模型与费用。是否支持某指标或市场以当前共享契约及执行能力为准，不能将模型自述或实验提示词中的清单当作完整支持证明。首期不支持跨标的信号、组合轮动、多周期、做空/杠杆等超出现有已确认能力的要求。

需求覆盖清单将每项用户要求映射为“已表达 / 待确认 / 不支持 / 用户明确移除 / 回测时设置”，并保留对应定义位置。结构合法但遗漏入场限制、止损、费用或改变成交时点等，必须阻止保存并提示差异。自由文本语义无法完全通过 Schema 证明：以结构化澄清、确定性约束、逐项覆盖及最终用户审核共同降低误译风险，不宣称机器已证明所有自然语言等价。

手动编辑后重新计算能确定的覆盖关系；无法确认的要求保留“待审核”，由用户更新要求或明确接受差异后再确认。不得为了消除红字自动删去原始需求。

## 5. 模块、接口与兼容

### 5.1 所有权与依赖

策略编写模块拥有草稿、澄清、变更提案、编写操作编排和来源快照；单向消费 AI Provider/审计能力及策略版本创建接口。正式策略由现有策略领域持有，不反向依赖编写控制器、模型适配层或实验执行器。共享契约放入现有 schemas 包；只有经确认可跨业务复用的纯能力校验才移到其实际领域所有者，不能为复用探索方法建立模糊公共层。

事务创建策略需要由策略所有者提供可参与原子保存的稳定接口，不能从客户端串联“创建策略”和“标记草稿已保存”。版本来源以通用来源描述和稳定引用接入策略中心，AI 实验来源保持原语义。具体文件与模块命名在实施基线任务确定，并同步模块边界门禁。

### 5.2 最小接口职责

| 接口职责 | 必须提供的约束 |
| --- | --- |
| 创建/读取/分页列出/丢弃草稿 | 用户隔离、稳定 ID、服务端分页、生命周期与当前修订；列表不返回长原文和完整定义 |
| 更新描述、答案或手动定义 | 预期修订、局部更新语义、校验结果与新修订；失败不吞掉输入 |
| 分析/生成/提出修改 | 预期修订、选定模型、未知费用确认、提交幂等键；返回持久化操作引用 |
| 查询/取消操作 | 数据库事实状态、可读错误、用量、结果及是否过期；终态重新读取完整结果 |
| 应用/放弃提案 | 提案标识、基线修订、允许范围和当前状态原子校验；重复请求幂等 |
| 确认保存 | 明确草稿修订与确认意图；原子生成策略 v1/来源并返回稳定引用 |

错误须区分草稿修订冲突、条件未完成、能力不支持、模型不可用、格式/语义校验失败、执行超时、结果未知及服务暂不可用。具体错误码由共享契约统一，前端不解析自由文本猜测重试条件。

### 5.3 策略中心衔接与迁移

本功能的页面接入依赖策略中心 Task 的 T07 独立新建页/版本导航，以及 T01 的来源读取契约；需形成可单独验证的接口交接。策略中心的手动创建与实验流程可独立完成，不以本功能全部完成为前置。本功能后端草稿与生成执行也可独立开发，避免循环依赖。

扩展来源契约时兼容手动、实验采纳、AI 辅助创建及历史未知来源，禁止根据名称或文本猜测老记录来源。保存后的来源区与实验/候选链接按真实来源分别显示。已有 V1/V2 编辑、回测与实验封存/采纳规则保持原边界。

持久化新增采用保留数据的扩展迁移；同步 migration matrix、raw-owned inventory（如涉及）、runtime 打包输入、结构门禁与隔离数据库验证。本轮不执行迁移或清库。草稿默认保留至用户显式丢弃，已保存来源默认保留；清理策略或保留期限若需变更应另行明确，不能在本功能中静默删除历史来源。

## 6. 验收标准

| 编号 | 场景 | 可观察的通过标准 |
| --- | --- | --- |
| NL-AC-01 | 创建入口 | 新建策略中可选手动或自然语言，输入切换保留；正式策略编辑不被扩展为自然语言修改 |
| NL-AC-02 | 分析与澄清 | 完整、缺失、冲突需求分别有正确状态；关键条件未经明确回答不能进入生成 |
| NL-AC-03 | 标的与能力 | 目录确认标的；多标的、多周期、执行模型不支持的要求不被静默替换，用户明确修订后才能继续 |
| NL-AC-04 | 语义保真 | 天/根数、百分比单位、信号与执行时点、仓位及费用被明确表达；Schema 合法但漏掉要求仍被拦截或标为待审核 |
| NL-AC-05 | 可读草稿 | 预览对应实际定义，支持结构化和高级编辑；保存前完成校验与用户审核，不伪造回测结论 |
| NL-AC-06 | 自动保存与恢复 | 输入、答案、手动编辑、生成结果可刷新恢复；失败保留本地内容，离开提示与修订冲突不覆盖输入 |
| NL-AC-07 | 局部修改 | “止损改为 5%，其他不变”只提出被授权的修改；应用前展示差异，范围外变化被服务端拒绝 |
| NL-AC-08 | 过期与并发 | 旧分析/生成结果、旧提案与旧保存确认不能覆盖新修订；手动修改、另一窗口与晚到结果均覆盖 |
| NL-AC-09 | 幂等入库 | 双击、并发与网络重试只产生一个新策略及 v1；来源和草稿状态与版本原子一致 |
| NL-AC-10 | 来源与后续动作 | 来源为 AI 辅助创建、可追溯且无虚假实验引用；保存不回测，用户明确发起才产生回测任务 |
| NL-AC-11 | 模型与费用 | 使用明确选择的单模型，无静默回退/自动循环；未知费用确认有效，失败/过期请求费用仍可追溯 |

| NL-AC-13 | 权限与输入边界 | 跨用户读取/更新/确认被拒；模型输出不能越权调用工具、执行代码或绕过服务端校验 |
| NL-AC-14 | 兼容与迁移 | 老策略/实验/来源正常读取，新增结构可保留数据升级；边界门禁与结构清单一致 |
| NL-AC-15 | 真实纵向闭环 | 实际配置 Provider 完成描述到 v1，再由用户操作发起真实回测；记录生成、定义校验、数据完整性、成交/拒单与结果，不以 succeeded 单独判定 |
| NL-AC-16 | 浏览器可用性 | 宽/窄屏、主题、键盘、加载/空/错误态、草稿恢复和差异确认可用；无嵌套长弹窗，标签不触发非预期控件动作 |
