# 回测真实历史市场规则数据源 Spec

> 任务标识：BACKTEST-HISTORICAL-MARKET-RULES-V1
> 日期：2026-09-16
> 状态：规划完成；T1 可启动，后续实现等待首个真实来源及授权条件确认
> 对应任务：[`回测真实历史市场规则数据源实施任务`](../tasks/2026-09-16-backtest-real-historical-market-rules.md)

## 背景与问题

当前 DSA 能为 CN Stock 提供身份、lot/tick、交易日历和 BaoStock 历史可交易性，但真实路径仍返回 `executionRules.status=unavailable`。现有回测通过显式、冻结并披露的 `execution-model-v1` 提供价格限制、费用和结算研究假设，已经形成可信研究闭环；该路径不应继续被真实历史规则来源建设阻塞。

法定收费、制度版本、区间内规则变化和来源证明获取成本高，且与当前产品/引擎正确性可以独立验收。本 Spec 将“不提供研究模型时也可使用真实历史规则运行”拆为后续数据能力增强。

## 目标

- 为一个明确市场、资产类型和历史区间接入可复核的真实市场规则来源。
- 让 DSA 在来源、身份、时间和覆盖均可信时返回 `executionRules.status=supported`。
- 正确表达价格限制、法定收费、持仓与现金结算的生效区间；区间内规则变化不得被单一当前值覆盖。
- 让未提供研究模型的运行在规则完整时成功，在规则缺失或冲突时继续失败关闭。
- 将规则与来源版本冻结进 Snapshot，使同一输入可确定性重放。

## 非目标

- 首次交付不要求一次覆盖 CN/HK/US、Stock/ETF/NAV 和全部周期。
- 不还原券商或客户个性化佣金、优惠、可取资金和银行卡到账。
- 不建设通用法规档案或全文审计平台。
- 不取消显式研究模型路径，也不把研究假设改写为真实历史事实。
- 不通过 fixture、静态常量或当前规则回填历史区间。

## 现状与约束

- 当前 `executionRuleSnapshotSchema` 只表达一段规则；若首个目标区间存在制度变化，需要先扩展为有限的版本化分段契约。
- 当前 Server 对 Provider 规则使用 Snapshot 预热起点至结束日做覆盖校验；实施前必须决定是否改为实际可能成交的执行区间，并让请求、校验与文档保持一致。
- DSA 必须保留 Provider 原始状态。来源不足时返回 `unavailable` 和具体 `missingInputs`，不能为通过回测而提升为 `supported`。
- 真实来源的访问授权、许可范围、历史深度与稳定修订标识属于实施前置条件。

## 设计方案

### 有界首个切片

首个切片默认只覆盖 CN Stock 日频的一个代表标的和一段明确区间。先完成来源清单、授权核对与样本对账，再确定具体标的和日期；未经证据确认不把默认范围写成已支持能力。

### 规则事实

实际返回的规则至少包括：

- 基于前收盘价的上涨与下跌价格限制；无价格限制必须显式表达；
- 法定收费项目的稳定代码、买卖侧、费率、最低额及必要生效日期；
- 持仓可卖、买入扣款和卖出款可再投资的交易日语义；
- 规则版本、适用身份、适用区间、来源修订及事实可用时间。

规则在目标区间发生变化时使用有限分段，端点不能重叠或留缺口。来源无法证明某段规则时，整个受影响运行返回不可用。

### 来源和时间语义

每条规则必须能追溯到官方来源或具有合法历史授权和清晰血缘的供应商。DSA 输出稳定的 `provider`、`providerRevision`、生效时间和 `availableAt`；`availableAt` 晚于回测 `dataAsOf` 的事实不得进入 Snapshot。

### 消费边界

Snapshot Builder 只消费 DSA 已证明支持的规则，不自行补默认值。规则身份、版本、区间与策略执行标的不一致时返回 `MARKET_RULES_UNAVAILABLE`。成功冻结后的 Runner 只读 Snapshot，不在重放时重新访问外部来源。

## 对外行为与兼容性

- 现有带 `execution-model-v1` 的运行保持不变。
- 无模型运行在 DSA 规则完整时可进入队列；规则不足时继续返回 `DATA_UNAVAILABLE / MARKET_RULES_UNAVAILABLE`。
- 旧 Snapshot、旧结果和数据库记录不回填、不重写。
- 如果契约需要版本化分段，使用向前扩展并显式区分版本；不得让旧 Runner 静默消费新结构。

## 测试策略

- Schema：合法单段/分段、缺口、重叠、非法数值、身份与版本冲突。
- DSA：真实来源样本、来源异常、历史深度不足、未来可用时间和许可边界。
- Server：执行区间请求、规则覆盖校验、Snapshot 冻结、哈希变化和旧快照兼容。
- Runtime：目标 Docker 环境中执行一次无模型成功运行、同 Snapshot 重放和缺失规则失败恢复。
- 证据边界：fixture 只证明契约；只有真实来源响应和目标运行态才能证明数据能力可用。

## 风险与备选方案

- 来源可能只能提供当前规则或缺少稳定历史版本。此时保持 `unavailable`，不缩小时间语义冒充历史覆盖。
- 某些收费由券商或客户协议决定，不纳入法定收费；继续由研究模型或未来客户级模型表达。
- 若真实来源成本或许可不可接受，保留显式研究模型为唯一成功路径，不降低关键事实门禁。

## 未决问题

### Blocking（T2–T5）

- 首个真实来源、访问方式、历史授权和再分发/持久化许可尚未确认。
- 首个交付的市场、标的与日期区间尚未以来源实际覆盖能力确认。

以上问题由 T1 负责收敛，不阻止 T1 开始只读来源调研，但在确认前阻止契约和实现任务 T2–T5。

### Non-blocking

- 默认从 CN Stock 日频小范围开始；不会据此自动扩大到 ETF、HK、US 或分钟周期。

## 验收标准

- **AC1 来源就绪**：首个来源的字段、历史深度、授权、修订标识和失败语义均有可核对记录。
- **AC2 契约准确**：规则结构能表达目标区间的实际生效变化，缺口、重叠、未来信息和身份冲突均被拒绝。
- **AC3 DSA 支持**：真实来源路径只在完整覆盖时返回 `supported`，否则返回具体 `missingInputs`。
- **AC4 Snapshot 冻结**：实际使用的规则、来源和版本进入 Snapshot 与哈希，相同输入可重放。
- **AC5 无模型运行**：目标场景不提供研究模型也能完成真实运行，并披露规则来源与覆盖。
- **AC6 失败关闭**：来源缺失、超时、版本冲突或区间不足时稳定返回 `MARKET_RULES_UNAVAILABLE`，不进入正常执行结果。
- **AC7 兼容与隔离**：显式研究模型和旧 Snapshot 行为不变，运行不写入真实账户事实域。
