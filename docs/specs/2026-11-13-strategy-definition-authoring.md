# 策略定义统一与可视、JSON、AI 编写一致性

状态与进度见[实施任务](../archive/tasks/2026-11-13-strategy-definition-authoring.md)。此前交叉方向的校验和已经完成的修复分别见[方向一致性规格](2026-11-12-strategy-cross-direction.md)和[冻结回测验收](../archive/evidence/2026-11-12-strategy-cross-direction.md)。

## 要解决的两个偏差

手动编写时，可视界面只覆盖部分 JSON。编辑执行标的或周期时，来源联动依赖特定 ID。保存前的价格坐标转换还可能重建来源、改写引用、删除未使用来源。AI 实验从零探索时，腾讯控股 EMA 策略 v1 的模型说明和可执行条件表达了相反的方向，候选、采纳版本和引擎均沿用了该条件。

优先让模型在产品支持的策略范围内直接生成完整配置，并让用户凭文字准确判断配置会如何交易。可视页、JSON、AI 确认、候选采纳、版本详情和回测消费同一份定义。是否降低交易频率属于策略研究，单独用新策略版本比较。

## 草稿、确认和正式定义

2026-11-21当前源码的新编写、修改与探索采用[整改规格](2026-11-20-backtest-practical-design.md)的V6生成合同；模型负责交易AST、显式来源／周期／方向、capture、lag和entryTrigger，程序从AST派生重复字段与机械依赖。多个可独立判定的错误同时报告；原始输出、编译产物和诊断分别留存。历史操作继续保存的V5合同，旧成功统计不重算。当前值表示最新完成且可见的一根，lag(1)再向前一根。

全新策略保存显式entryTrigger；旧正式版本及可编辑本机草稿先按来源版本物化原政策，再允许增加止损等修改。普通旧路径为rising-edge，已有有效交易计划为while-flat，缺值不重置边沿。待确认保存回执保持原内容。两端编辑与确认必须显示政策，并接受V6完整合法的同标的多周期AST。

1. 编辑器维护一份已应用的结构化草稿。可视编辑直接修改规则节点。JSON 页允许独立保留尚未应用的文本。语法错误显示位置，保留原文和最后一次已应用的草稿，保存不能静默绕过未应用修改。结构可识别、字段未填完的草稿允许进入可视页修复。未知节点保留原文，并标出当前编辑能力。
2. 正式定义沿用现有表达式树。程序根据树生成可读的入场、退出、风控和执行条件。摘要要展示操作数顺序、行情字段、来源、价格口径、周期、指标参数及组合层次。用户原话、模型研究理由和历史说明独立标识，便于追溯与规则的差异。草稿的路径定位、错误提示和显示逻辑由双端复用。
3. 自然语言编写时，模型按正式 Schema 直接生成配置。在现有确认步骤同时展示用户原话与配置所表达的行为，含义取舍由人确认。已确认配置直接保存。用户编辑后可核对差异。
4. 从零探索时，模型生成全部可探索字段。完整与 SDK 精简入口共用节点名称、参数、类型、单位、取值和复合示例。标的、执行方式、费用等已经由实验固定的字段，沿用既有归属并在回读时标出来源。自主实验继续自动探索和回测，在现有采纳环节由人核对最终候选的中文规则。参数优化的技术边界限于授权字段。

5. 正式写入端对收到的定义做严格结构、引用和业务校验，返回具体路径。保存尊重显式来源与坐标，保留未使用来源及有效数值精度。需要根据运行配置决定的取价在准备阶段解析并冻结。版本回读和 Worker 准备必须可追溯到同一条不可变策略版本。

## 协议、编辑覆盖与兼容性

- 新定义统一使用策略定义 Schema 3，覆盖手动、AI 编写、实验及采纳。历史定义继续按原 Schema 2/3 读取。在生产者和消费者都就绪后切换写入口，旧客户端收到明确升级提示。策略业务版本（如腾讯 EMA v2）、策略定义 Schema 版本、运行及快照协议版本分别标识。
- 保留既有 `research` 后复权研究价和 `actual` 实际价格。按原计划扩展 `native-nav` 表达基金原生单位净值，`run` 表达历史策略沿用当次运行口径。股票或 ETF 新研究默认显式研究口径。基金继续按原生净值、份额、申赎时序和费用执行。
- 历史定义升级由用户查看差异后另存新版本。保留来源 ID、引用、未使用来源、操作数和数值原值。旧交易所定义口径未固定时用 `run` 表达，使用原运行上下文验证。无法证明保留原义时展示具体差异。旧定义、旧运行、快照、结果及摘要继续按原义读取。
- Desktop 和 Mobile 保留「可视配置 / JSON」页签。覆盖标的、主周期、来源、入场、退出、仓位、风控、执行、费用和基准。条件支持现行业务可执行的全部、任一、取反、比较、交叉、持仓状态等节点，以及常量、行情字段、嵌套指标和 MACD 输出。协议可解析但业务不支持的节点（如受限的公司行动信号）完整展示并注明原因。
- 执行标的、主周期与来源独立维护。用户通过「使用执行标的」「使用主周期」显式同步。来源改名原子更新引用，被引用的来源或字段须先解除引用。下游版本选择、风险应用与监控按可转换规则、执行方式和真实账户条件判断适用性。

### 编辑覆盖合同

- 当前可编辑值均保留原始十进制字符串；涨幅、原始数量、剩余数量和权益占用不得混为同一单位。
- `tradePlan` 作为独立分组编辑，不隐式改写普通 `entry`、`exit`、`risk` 或 `sizing`。计划覆盖普通仓位时明确显示覆盖关系。
- 草稿允许缺少字段、未完成数值及暂时无效的引用。只有 JSON 语法错误或非对象根阻止应用。未知节点保留原样并提供路径及 JSON 入口，不用默认节点替换；正式保存仍完整校验。
- 未应用 JSON 修改参与离开确认与保存判断；不能通过切回可视页或保存而提交旧草稿。两端共用对象根解析及路径修改合同，各自保留草稿恢复。
- 普通保存不调用价格投影。显式“基于旧策略发起新研究”的转换预览保留；协议升级、研究语义转换和普通编辑分别验证。
- 分组使用标题、对齐、留白和轻量横线，避免给递归条件或计划字段层层套框；复用现有原子类、共享控件和数值输入。

## 模型生成正式配置

### 本轮数值与历史取样合同

通用数值节点增加 `arithmetic`（`add`、`subtract`、`multiply`、`divide`、`min`、`max`，左右数值）、`absolute`（绝对值）及 `lag`（`periods` 个来源观测前的数值）。保留现有 `Highest` 等指标含当根的语义；此前 20 根最高价使用 `lag(periods=1, input=Highest(high,20))`。运算保持十进制精度，除数为零返回不可用；乘除使用比例或明确兼容的单位，不把价格与数量直接相加。

历史引用及滚动窗口必须唯一锚定一个行情来源，按该来源的已完成观测排序，不按主周期索引或自然日移动，不跳过显式缺值凑样本；持仓状态与会话数值不作为历史预计算输入。历史输出保留取值身份与可见时间。不存在第 N 个历史观测、历史输入尚不可见或窗口未满时返回不可用，不回退别的历史位置。R11 的最少输入为当根及此前 20 根，共 21 根；回读明确排除当根。

`rolling` 明确 `periods`、数值 `input` 与统计量：`sum` 求和，`standardDeviation` 必填 `ddof=0|1` 且周期大于自由度，`quantile` 必填 0 到 1 的十进制分位水平，使用排序后的线性插值。标准差使用十进制运算与截取 20 位小数的平方根。`countTrue` 对最近完整 N 根逐根条件计数；`consecutive` 要求最近完整 N 根各自条件均为真。窗口包含当根；要排除当根则外包 `lag`。`cumulative` 从明确的 `anchorAt` 累计求和或最高值，准备阶段须覆盖锚点，缺锚点或区间缺值不可用。

`sequence` 明确 `trigger`、`confirm`、`invalidation`、`within`、`allowSameBar`、`repeat`；可用 `capture` 冻结开始时的数值，在本序列的确认／失效条件中以 `eventValue` 引用。第 i 根开始，i+N 根仍可确认，i+N+1 过期；失效优先于确认，等待中不因开始条件持续成立而改写捕获值，缺值取消等待并须新开始。冻结值只能直接比较或参与当根运算，不能做另一次历史预计算，序列内部不嵌套序列。一次模式确认后不再启动；重复模式允许后续新开始。

ADX 显式选择 `adx`、`plusDI` 或 `minusDI`，使用同源 high／low／close 和 Wilder 平滑；首根建立前值，第 2N 根初始化 ADX，零方向差定义为零，缺值重置预热。`confirmedPivot` 明确高／低方向、左右根数、最近或上一个已确认事件，严格极值不接受邻点等值；只在右侧根数完成后可见，可用 `sample` 读取摆动原时点的 RSI 等值，保留原摆动时点与确认时点。没有足够已确认事件时返回不可用。

本轮继续按原附录交付单标的规则表达、已有多来源能力和能力缺口结果。外部时点数据与组合／多腿执行按用户 2026-11-19 的范围选择保留具体不支持原因，不在本轮另建数据或多资产执行系统；原有历史失败与已完成交易计划回执保持原值。

Schema 和工具说明直接告诉模型各节点能做什么、主语和参照是谁、周期和单位如何填写、哪些字段由实验冻结。模型决定节点、方向、参数及其组合，直接交付可执行配置。服务端装配冻结字段，并检查结构、引用、单位、授权编辑范围和运行支持性。从旧方案移除逐条交易理念翻译、中文语义裁判和每个候选生成一套行情考试的设计。既有中文交叉提示及字符串检查属于历史修复；新方案把文字取舍交还人工，在切换时调整其业务阻断职责。

用真实探索入口对一组目标想法试生成：检查生成是否充分利用可用节点，能否指出缺失能力，有没有悄悄省略条件。覆盖趋势与逆势的有效配置。人工评价生成配置与研究思路的契合程度；算子测试服务于引擎行为，二者分别记录。

### 同标的跨周期冻结

来源各自使用日线或原始分钟物理数据，同一物理周期和价格坐标可复用，其他周期独立冻结。运行配置保存额外信号窗口的冻结身份，准备阶段获取、执行阶段只复用该身份，不重新选择历史版本。快照保存逻辑来源到物理 Artifact 的映射、完整请求／响应证据和内容摘要；Worker 按来源周期聚合并按完成／可见时钟对齐。缺窗口、哈希或价格口径不一致时拒绝，不能把日线当分钟数据或反向冒充。仍只有唯一执行标的；独立参考资产、外部时点数据和组合执行不由本扩展承诺。

### 七例生成失配的修正边界

发现请求必须提供实际继承的成交方式与固定费用；省略execution或原样显式填写普通后开盘市价配置均可，不能使精简合同只允许日线委托。日线说明只适用于明确要求该执行分支的需求，不能无条件命令生成委托。未要求的可选模块不构成能力缺口。模型先生成完整配置，再按实际配置说明理由；历史理由和定义不重写。

指标参数与输出、滚动统计各分支的必填字段应同时出现在正式校验和实际原生 JSON Schema 中。ADX 必须选择输出，参数不允许任意新键；总体／样本标准差分别明确自由度0／1，分位数明确分位水平。结构拒绝仍保留来源和参数的具体路径，不能以严格原生合同为由退化为只有根部报错。来源声明先于引用；跨周期仍由模型声明额外来源，服务端不替模型补源。

通用节点说明必须区分历史位移与窗口聚合，以及摆动定位输入和返回取样值。比较低点价格使用不带sample的low摆动；比较相同低点当时的RSI使用相同low定位及RSI sample，不能把两种比较都写成RSI。保留直接生成AST、人工判断契合度的边界，不增加中文翻译器、语义裁判或输出修补器。离线合同及受控计算通过不能宣称真实模型已经通过；新增真实调用仍须另行授权。

## 配置回读成文字，供人确认

基于最终候选配置和实验冻结字段生成入场、退出、仓位、风险、执行和费用说明。可复用现有格式化函数；模型可润色文字或补充研究理由。原始研究理由和实际交易规则并列，后者包含会改变行为的方向、周期、严格／非严格比较、分组、指标参数与输出、价格口径、触发和成交时点。采纳时确认这份可读规则；随后交给模型解释或修改时，同时提供已确认文字与配置。自动探索、回测沿用原流程。

已复现一处回读缺口：价格研究摘要把 MACD(12,26,9) 的 macd 线大于 0 和 MACD(8,21,5) 的 histogram 大于 0 都输出为“MACD（后复权收盘价）高于0”。两份配置都通过精简生成 Schema。验收时要能凭文字认出参数和输出线，也能区分逻辑分组、固定风控与普通卖出。

## 交叉规则的贯通样例

腾讯候选提出的趋势规则为「收盘价上穿 EMA20 开仓，下穿 EMA20 平仓」。这条规则也可作为自然语言编写入口的给定指令。以收盘价为左项、同一来源的 EMA20 为右项。上穿时前值左小于等于右、当前左大于右，下穿取相反不等式。对换左右项并同时反转方向的表达等价。对换左右项而保持方向的表达会产生相反行为。输入相等、持续在同侧、交叉后持仓或空仓的例子都要验证。

| 核对点 | 可观察结果 |
| --- | --- |

## 验收标准

- AC01：同一定义在手动、AI 确认、采纳、详情及研究转换预览中可辨认地回读来源、口径、操作数、分组、指标参数/输出、普通风控与交易计划。
- AC02：两端共用草稿及路径合同；未完成对象可修复，非法 JSON、未知节点、高精度原值及未应用修改不丢失，错误不导致提交旧草稿。
- AC03：普通保存的来源、引用、未使用来源及数值原义不被投影改变；执行标的、主周期和来源仅显式同步，来源改名更新所有引用，删除保护引用完整性。
- AC04：Desktop 覆盖当前可执行业务节点及计划，字段可定位 JSON 路径；窄屏、聚焦、展开、取消和导航实际验收通过。
- AC05：Mobile 提供相同定义能力，保留本机草稿、待提交恢复、键盘及导航；Web 宿主与原生验证分别记录。
- AC06：Schema 3 的 `native-nav`、`run` 与历史显式升级保持原义；旧定义、任务、摘要和冻结校验不被重写。
- AC07：股票/ETF 与 NAV 各通过准备、冻结、领取、执行及回读；运行经济模型和策略协议独立，运行口径在准备时确定并冻结。
- AC08：全部新增定义生产入口及风险等消费者一致，新写入门禁启用后旧客户端收到稳定错误；不扩大真实账户监控资格。
- AC09：生成、确认、保存、冻结、执行与人工回读的纵向样例采用同一正式定义；既有方向和能力扩展义务按其活动任务保留。
