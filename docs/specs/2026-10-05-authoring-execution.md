# 编写操作执行与调用事实

本规格落实自然语言策略 T02/T05 的执行前置；原规格的 NL-D、NL-AC 和限制保持验收依据。

## 所有权与状态

`strategy-authoring` 拥有操作、修订、领取租约、取消与结果应用；`ai` 拥有 Provider 调用事实。AI 调用审计以通用用途、业务引用和 attempt 关联，不反向导入编写模块或表。审计完成不能以业务租约有效为前提；过期结果仍保留实际模型、用量和费用。研究 `AiRun` 不承载编写操作。

调用事实先持久化准备记录，再记录派发授权，最后记录完成或未知。每次实际请求有独立 UUID；同一请求的事实修订不可覆盖。未知后收到晚到事实可追加明确完成修订，保留此前未知记录。幂等重放须携带完全相同的事实，冲突应拒绝；未派发请求不能伪装成已收响应。未知费用保持空金额和币种，不默认零，不跨币种合计。

## 执行与消费

独立编写队列只传操作引用；数据库是用户状态事实源。首期执行组件为 Server 内独立 BullMQ Worker，与 HTTP 请求及研究执行器分离；进程关闭时中止在途请求，过期操作由恢复扫描收敛。新调用先核验队列和执行组件心跳及选定用途路由，再持久化操作并投递。队列失败拒绝新收费调用，已持久化未投递意图由有界恢复处理。一个草稿最多一个活动操作，重复幂等提交返回历史引用，不再调用模型。

领取、续租和结果提交使用状态及 attempt 原子比较。期限 120 秒、租约 60 秒、20 秒续租；续租失败立即中止执行，无法确定是否派发时保留结果未知且禁止自动付费重试。仅明确未发送且成功确认队列缺失时最多两次补投。独立的分析/生成/修改输出合同必须通过选定模型用途验证，无研究模型回退。

生成、修改现行输出合同为 v2，直接向上游提供布尔 AST 与执行配置的原生结构约束，保留 Canonical 交叉校验及编写语义校验。历史 v1 合同引用可读取；新版执行必须重新完成对应模型用途验证，不能复用旧版探针的成功事实。

## 验收边界

BullMQ 依赖仅允许编写队列和 Worker 两个适配器文件消费；领域仓储、执行器及 AI 模块不得直接使用队列 API。重复领取冲突不能转化为用户取消；心跳首次写入失败后仍保留定时恢复。

先验证调用审计与状态机，再实现队列/执行器，再接 HTTP，最后隔离数据库与受控 Provider 最小链路。目标 Docker、在线 Provider、故障恢复和浏览器分别记录；完成状态以对应 Task 和分层证据为准。
