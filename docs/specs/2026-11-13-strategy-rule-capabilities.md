# AI 策略规则样例与 Schema 能力清单

这是[策略定义统一规格](2026-11-13-strategy-definition-authoring.md)的规则附录。模型直接填写正式配置，研究人员通过具体的中文交易规则确认候选。本文用于决定模型需要哪些表达能力、哪些已有能力要开放，以及哪些规则依赖额外数据或执行模型。工作顺序见[实施任务](../tasks/2026-11-13-strategy-definition-authoring.md)。

竞技场模型生成的是逐轮委托决策。研究预约、父单成交后激活止损及分批成交的执行要求，见[竞技场条件委托与成交保护](2026-11-13-arena-contingent-orders.md)。

## 样本来自哪里

- **项目真实候选。** 2026-11-13 只读查询本地开发库，以 `OptimizationExperiment.sourceMode=discovery` 关联全部已保存的 `OptimizationCandidate`。当时共有 18 个探索实验，7 个实验产生了 13 条候选，候选创建日期为北京时间 10 月 31 日至 11 月 12 日。逐条比对 `proposal.reason`、`strategy.description` 以及入场、退出、仓位、风险字段。同期 22 条探索尝试中有 13 条 succeeded、3 条 failed、6 条 unknown_outcome。后 9 条未提供可供本清单归因的候选提案。实验目标和收益指标均未作为规则原文。
- **扩展样例。** 表中以“设计”标出的规则是为测试语言边界构造的模型提案。突破通道的历史窗口、移动止损、减仓、多周期和横截面排序等另有开源实现可供核对。参数仅使例子可验证。历史候选本身受原提示与 Schema 限制，从其指标分布无法推断模型在开放条件下只会提出这些想法。
- **现状证据。** 阅读本机当前 Schemas、从零探索的完整与精简入口、Domain 求值器及价格研究摘要。另对编译产物运行 17 个精简生成结构探针和 2 个正式定义／探索入口对照。这里的“结构接受”仅说明配置能解析。执行、数据可得性、说明可读性及策略收益分别验证。

## 规则目录与表达差异

每行的规则都需要能读回成一句具体的中文。状态“已有”表示能用现有节点表达，“组合”表示已有等价表达，“缺表达”表示要新增可复用能力，“入口限制”表示一般定义能力和探索范围不同，“执行／数据”表示即使 JSON 能写，仍须扩展相应服务。编号 C 对应后面的交付清单。

## 需新增或完善的 15 组能力

实现顺序是提案。C01～C04 先解决同一标的、同一周期内的多数表达缺口；C05～C09 接着支持持仓生命周期和交易行为。C10～C13 按数据和运行面分别交付。C14 只新增已选指标所需的计算，C15 从第一组能力起同步交付。每组都要覆盖正式配置、模型实际获得的 Schema、相关引擎、双端编辑和中文回读。

| 编号 | 需要支持的配置及运行语义 | 最小验收与人能读到的差异 |
| --- | --- | --- |
| C01 数值运算与单位 | 对标量及序列组合加减乘除、绝对值和上下界；表达收益率、相对偏离、动态阈值。标明比例、百分点、价格、股数和币种，跟随来源价格口径。 | EMA 为 100，阈值 102%；收盘 102 对严格“大于”不触发，102.01 触发。分母为零返回不可用，不能补成 0。文字写明相比谁、分母和倍数。 |
| C02 历史引用与窗口终点 | 在同一数据源上引用前 N 根已完成的可用观测，可作用于行情或指标。窗口明确是否含当根；按该来源周期获取，不用自然日代替。 | 前 20 根最高价为 100，今天最高 105、收盘 104。“突破前 20 根最高”应成立；含当根的对照不成立。预热不足返回不可用。 |
| C03 布尔与数值窗口 | 添加连续成立、窗口计数、求和、标准差、滚动分位、带锚点的累计统计。复用既有 MA、Highest、Lowest；显式规定缺样本、窗口填满、标准差自由度和分位数算法。 | 序列 真、假、真、假、真 满足五中取三，未满足连续三根。均值相同、波动不同的两组样本应产生不同带宽。回读列出窗口范围与统计量。 |
| C04 事件顺序和条件阶段 | 支持先 A 后 B、最迟 N 根内、失效条件、是否允许同根、是否可重复，以及在 A 发生时冻结价格等值。规则只使用有限状态。 | A 在第 1 根，允许后续 5 根，B 在第 6 根可触发，第 7 根过期。失效后旧 A 不可再用；重新出现 A 后按规则更新。 |
| C05 成交与持仓记忆 | 可引用开仓成交时点与价格、持仓内峰谷、上次完整平仓时点／原因、已执行分段、已平仓净盈亏及历史结果窗口。定义分批、拒单、待结算与回放恢复。 | 卖出意图被拒不会启动平仓冷却；最后一份卖出成交后才启动。过去两次止损与两次普通出场可产生不同的后续状态。 |
| C06 动态风控与触发层级 | 支持入场 ATR 冻结或逐期重算、初始止损、跟踪峰值、激活、分段保本、收紧与重置。显式区分收盘评估、盘中触价和成交方式。 | 持仓峰值从 100 升到 120，5% 追踪线为 114，价格回到 116 时保护线维持 114。跳空到 110 不承诺按 114 成交。 |
| C07 动态仓位与风险预算 | 模型能在受支持账户值和市场数据上计算目标数量或权重；识别冻结权益、现金、单笔风险、止损距离、权重上限、最小交易单位。定义计算、封顶、取整顺序。 | 假设权益 10 万、风险预算 1%、每股止损距离 2，在现金与手数约束前为 500 股。零距离或缺价格报告不可用。回读列出单位和计算基数。 |

| C09 交易日历、会话与定时 | 支持交易所时区、交易日内时段、收盘／月末等调度、会话重置和策略限制时段。明确最后可交易日、半日市、假期、跨市场对齐。 | 月末自然日为周日时，在该市场最后交易日触发一次。下一交易日的会话 VWAP 从新会话开始累计。 |

### 模型如何报告能力缺口

现有精简输出的成功分支要求交付 `strategy`。如果模型想表达 R34 的限价单，强制它填写现有的市价配置会改变原意。建议在模型输出的信封增加一种“当前无法精确表达”结果，与可以保存的策略配置区分。最少记录原规则文字、受影响位置（如 `execution`）、缺少的节点／数据／执行能力、已能表达的部分。系统将它保存在探索尝试中并纳入下次能力盘点。仅当模型明确另提替代假设时，才把替代方案当作新候选进行回测。涉及 R32 的情况要能具体指出“现有探索只接纳主周期”，避免误报整个策略协议缺少周期字段。

### 一个生成配置与人工回读的对照

以下是拟议的 JSON 片段。字段名在正式协议设计时确定；今天的精简 Schema 尚不接受其中的 `lag`、`multiply` 和 `countTrue`。既有节点沿用现行写法。例子说明通用算子怎样服务多个策略，模型可以直接写配置。

模型提案为“今日成交量比之前 20 日的平均成交量高 50% 以上，且最近 5 根至少有 3 根收阳，才允许入场”。这里将“高 50% 以上”明确定义为大于或等于 1.5 倍；若选择严格大于，回读也要改变。

```json
{
  "type": "all",
  "conditions": [
    {
      "type": "compare",
      "operator": "gte",
      "left": { "type": "series", "sourceId": "daily", "field": "volume" },
      "right": {
        "type": "multiply",
        "left": {
          "type": "lag",
          "periods": 1,
          "input": {
            "type": "indicator",
            "name": "MA",
            "input": { "type": "series", "sourceId": "daily", "field": "volume" },
            "params": { "period": 20 }
          }
        },
        "right": { "type": "constant", "value": "1.5" }
      }
    },
    {
      "type": "compare",
      "operator": "gte",
      "left": {
        "type": "countTrue",
        "periods": 5,
        "condition": {
          "type": "compare",
          "operator": "gt",
          "left": { "type": "series", "sourceId": "daily", "field": "close" },
          "right": { "type": "series", "sourceId": "daily", "field": "open" }
        }
      },
      "right": { "type": "constant", "value": "3" }
    }
  ]
}
```

应能读回：“按已收盘日线判断：今日成交量达到此前 20 根日线平均成交量的 1.5 倍（均量排除今日），并且含今天在内的最近 5 根日线中，至少 3 根的收盘价高于开盘价。”假设此前均量为 100、今日量为 150、近五根恰有三根收阳，两项均成立；今日量改为 149 或收阳改为两根，则入场条件不成立。该片段仅表示信号条件，实际成交仍由完整配置的执行方式决定。

## 如何验证与交付

1. **先扩单标的表达。** 交付 C01～C03 及对应的 C15 回读，可以一次覆盖带宽、相对成交量、前高突破、连续确认、窗口计数、涨幅等样例。优先用 R09～R14 对照边界，再处理 C04 的多阶段形态和 C14 不可用通用算子精确组合的指标。
2. **再解决交易过程。** C05～C09 按依赖交付。先让可见的成交／持仓状态可重放，再开放追踪保护、动态仓位、分批动作与交易日历。用 R21、R23、R26、R29、R31 分别验证。记录待成交、重复求值、退出与加仓同刻、期末尚有持仓等情形。
3. **跨周期、执行、数据、组合分别立项。** C10 同标的多周期可先行；跨标的要确认冻结来源，C11 要确认市场规则与行情粒度，C12 要确认历史可用时间，C13 要有多资产资金与执行模型。每项的输入缺口应出现在能力说明或候选提案中，不能把枚举扩容视为可回测。
4. **在正式探索入口评估模型生成。** 给实际模型两类样本，一类指定规则用于检查有没有漏掉约束，一类开放探索用于搜集新想法。保留原提案、生成配置、所用 Schema／模型版本与人工回读结果。人工采纳或修改沿用既有流程。统计可精确配置、模型漏写、无法表达、缺数据／超实验边界各多少；交易收益独立评估。
5. **新增支持一项就贯通一项。** 在同一组已冻结的输入上检查模型可写、版本能保存且可回读、Worker 按预期求值、双端文字可区分边界行为、旧定义重放正常。技术校验沿用结构、引用、单位和运行支持检查。人工凭文字确认策略含义，自动探索过程继续运行。
