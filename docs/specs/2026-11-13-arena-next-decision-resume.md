# 自主竞技场：下一次决策与恢复观察

## 问题
当前各模型的 wakeups 已持久化，但只在“研究与预约”明细中散列展示；暂停后恢复没有保底研究触发，事件预约可能让模型长期不决策。

## 约束
- “下一次时间预约”取当前模型未触发 time wakeups 的最早时刻，按比赛市场时区展示；不能把价格/成交条件说成确定时间。时间到期后显示“等待研究调度”，即使休市也可发起研究；价格或成交事件也可能提前触发。
- 暂停不产生模型调用、成交或扣费。恢复时各可正常研究的模型安排一条即刻到期的 time wakeup，不删除旧的价格/成交预约；已有到期 time wakeup 时不重复安排。实际研究仍受比赛运行状态、比赛起止日期、并发周期与预算限制，不受市场开盘状态限制。
- 手动触发仅针对本人运行中的比赛。等待中的指定模型可新增预约；当模型已经在研究、或已有 pending/running 周期时，幂等返回 already_in_progress 且不新增预约或模型调用，避免用户界面轮询与服务端状态竞态造成 409。暂停、已结束、需人工处理、额度耗尽或历史回放被阻塞时仍拒绝。
- 历史回放使用冻结时间游标预约，不能将机器当前时钟塞进历史回放；等待现有观察/研究屏障结束后才可调度。
- 用户可在模型排名、模型详情查看下一次决策状态；显式操作说明可能发生模型费用。盘前、收盘后和休市可以启动研究与预约，交易与模拟成交仍要求开市及合格执行证据。
- 手动触发请求仅表示“预约已受理”，不代表已调用模型；接口需区分新建预约、已有到期预约和已有决策周期。UI 在模型操作区显示提交中、成功、失败与下一步研究状态；账户内错误只出现一次，不在页面顶部重复，研究状态更新后不展示过期 409。**已到期但尚未触发的 time wakeup 视为已等待调度，Desktop/Mobile 不再显示手动触发按钮；未来预约仍可手动提前研究，价格/成交事件预约不被误判为时间到期。回放时使用历史游标。** 不得将市场休市误报为研究被阻塞。
- 保留既有服务端账户事实、模型输入与决策 Schema，不新增数据库字段，不改变正式投资账本。

## 验收
1. 未来 time/已到期 time/仅事件/无预约/研究中/暂停/回放分别正确展示，显示时区。
2. 暂停恢复生成保底观察且去重；盘前/收盘后/休市的时间和成交事件预约可研究，价格事件只依据合格交易会话行情触发；历史回放沿用其冻结游标与研究屏障。
3. 手动触发鉴权、比赛/模型/周期状态、重复请求、失败恢复符合限制；请求是显式操作。
4. 无日历/未知市场状态时，实时赛程仅以比赛市场时区的日期检查赛期边界，研究不猜测市场状态；新委托和撮合继续使用真实交易会话门禁，错误不会影响研究观望结果。
5. 定向类型检查、接口及前端交互测试通过，既有未提交改动原样保留。
