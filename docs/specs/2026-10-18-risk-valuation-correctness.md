> [实施任务](../archive/tasks/2026-10-18-risk-valuation-correctness.md) · [全局优先级](../tasks/README.md#priority-p0) · [IR02 原始核查](../reviews/2026-10-18-starred-project-implementation-coverage.md#local-findings)。

## 1. 目标与依据

修复 IR02：后台风险扫描在同一比较范围内使用一致币种，并将缺价、缺汇率及覆盖不足传递给实际规则评估器，避免把部分组合误报为完整组合。本主题的 P0 是处理顺序，不改写原审查的严重程度或证据等级。

修复前入口为 [AutomationRuntimeService](../../apps/server/src/automation/automation-runtime.service.ts) 的 `buildRiskEvaluationContexts()`：原币市值直接求和，失败持仓过滤后计算 `weight/accountWeight`，上下文标记行情 fresh，`missingSymbols` 另行返回。这是原始本地源码证据；当前修复及目标反例由 Task 和验收记录持有，不据此推断全部历史风险事件错误。

## 2. 修复范围与所有权

Automation 负责扫描编排，Risk 负责规则所需估值上下文及完整性判定，Market 负责价格、NAV 和 FX 事实。先复用真正拥有估值语义的现行服务或稳定原语，不从核心模块反向依赖 Performance 页面编排，不创建第二套行情或汇率适配器。

保持实际/模拟、账户范围、扫描对象和既有规则含义；本轮不把持仓市值权重偷偷改为含现金的总资产权重。若核对发现既有规则合同确实要求不同分母，在实现前原位明确适用规则和版本，而不是混用两种分母。

不改变 Ledger、Position、交易、来源启停、用户主备、模型配置或通知渠道；不重做已完成的 Scheduler 租约及 UI 迁移。

## 3. 行为合同

同一权重分母内的金额必须先转换为明示的比较币种；报价币种、数量、价格、FX 方向、估值时点及来源质量均须可追溯。组合比较币种固定为 CNY；单币账户在自身币种内比较，多币账户转换为 CNY。分母仅含持仓市值，不含现金；各层独立判定，组合缺 FX 不连带拒绝无需该 FX 的单币账户。缺 FX 不按 1:1，失败不按零；保持现行新鲜度、日期上界和未知时区约束。

组合完整性与单账户完整性分别判断。组合缺一个账户的价格，不必把另一个完整账户的独立规则全部拒绝；但依赖全组合权重的规则不得获得看似完整的比例。仅需单标价格且其输入全部有效的规则可继续评估，并明确局部覆盖。

依赖缺失的规则返回现行合同可表达的不可用/跳过原因；若需扩展合同，先在 RVC0 固定生产者、消费者及兼容映射。不可用不能当作未触发、解除风险或恢复健康，也不能基于错误权重产生正常风险通知。保留已有事件和诊断事实，不重放通知。

后台保留缺价持仓的上下文身份，省略不合格数值；`dataQuality.portfolioWeight/accountWeight` 分别使用 `complete/unavailable`，另存比较币种、价格来源/时点、FX 证据版本与原因。Risk 派生账户上下文使用账户权重，组合上下文使用组合权重；同标的跨账户权重求和。新质量字段缺失的旧调用方保留兼容行为。实际扫描通过现有 `results[].error` 明确返回不可评估原因，且不进入事件状态机；Automation 保存该结果与估值摘要供诊断读取，不新建风险终态或重放事件。

金额与数量沿用项目高精度原语；若最终权重接口为浮点比例，转换前后均须检查有限数及分母有效性。负值、零分母或不支持的估值事实不通过补零获得资格。

## 4. 验收标准

| ID | 必须验证的结果 |
| --- | --- |
| RVC-AC1 | 固定合成汇率 USD/CNY=7，100 USD 与 700 CNY 的持仓在同一组合分母内各占 50%；账户内比例独立核验。 |
| RVC-AC2 | 缺一个价格或必要 FX 时，不把其余持仓重标为完整的 100%；单账户与全组合覆盖分别正确。 |
| RVC-AC3 | 同币种、跨币种、基金正式 NAV、缺值、过期、零分母和模式隔离均有定向结果，估算 NAV 不冒充正式输入。 |
| RVC-AC4 | 真实扫描 handler 到规则评估/诊断的受控集成保留质量；缺依赖不解除原风险，不触发不实通知；无跨账户读取。 |
| RVC-AC5 | 正式目标使用匹配源码，在获准的独立验收范围验证实际消费及现有事件保护；外部条件不足时保持未通过。 |

## 5. 验证与交付边界

最小反例的汇率和价格是测试输入，不是市场报价。先定向 Domain/Server，再受影响包与边界，最后独立目标验收。相关入口：[现有 runtime 测试](../../apps/server/test/automation-runtime.test.ts)、[基础执行测试](../../apps/server/test/automation/automation-runtime-foundations.test.ts)。

仅在自己的输入改变时重跑对应门禁；目标更新遵守 infra 正式入口，通知出站默认阻断。风险相关 Market Consumer 可复用相同输入和断言的修复证据，不由一般 UI、收益 G1 或其他来源成功代收。DSA D0/TL T0 的只读盘点和独立标的新闻不依赖整个修复主题完成。
