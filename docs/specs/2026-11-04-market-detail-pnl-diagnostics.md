# 行情详情陈旧原因与标的累计盈亏

> 任务标识：market-detail-pnl-diagnostics
> 日期：2026-11-04
> 对应任务：[已完成任务](../archive/tasks/2026-11-04-market-detail-pnl-diagnostics.md)

## 目标与边界

行情详情应说明哪个分段因何回退，并在持仓入口展示该账户、该模式、该完整标的代码的累计盈亏走势。保留现有净值、行情图及交互。沿用组合累计盈亏的“已实现 + 未实现”定义，不能用净值涨幅或当前数量反推历史持仓收益。

## 陈旧原因

缓存回源失败保留稳定原因码和安全中文解释，包括超时、限流、认证失败、来源不可用、响应格式异常、控制条件不满足。禁止从中文异常文本猜原因或返回可能带凭证的原始异常。基金最新净值及净值历史回退携带原因；详情横幅按分段汇总，分段同时展示。没有来源证据时明确说明来源未返回原因。正常上一交易日净值不因日期较早而自动判为陈旧。

已确认截图对应的历史误报来自 DSA：历史序列中超过七天的日期被逐点标为 `stale`。来源成功返回且通过验证的历史点使用 `delayed`，历史日期不承担缓存新鲜度含义；Server 仍在真实回源失败时将缓存回退标为 `stale`。DSA 所有权与细节见其 `docs/thesis-ledger-nav-freshness.md`。

## 盈亏契约

扩展只读 `/performance/pnl-series`：可选 `symbol` 使用完整规范代码；可选 `asOf` 限定读取截止时间，不晚于当前时间。响应回显标的范围，标的请求额外返回该时点的已实现盈亏。Ledger 按账户、模式、标的批量读取平仓事实，Performance 单向消费，不增加反向依赖。

历史未实现盈亏取冻结快照中的该标的市值、成本与币种，同一标的多行汇总，不能被其他标的缺行情污染。历史缺持仓数组、缺价格、缺成本、缺汇率或范围依据时留空；已清仓且完整持仓数组中无该标的时，未实现为零，仍保留已实现部分。未知成交时间或成本不得算作零。历史读取不回填数据，不调用远程 Provider。

持仓详情传递账户编号、模式、币种与估值计算时间。当前累计盈亏为已有持仓未实现盈亏加同一截止时点的已实现盈亏；无个人持仓上下文的目录详情不构造个人收益。查询缓存包含完整范围，切换标的或账户不得复用旧数据。基金累计盈亏与历史单位净值在同一张图叠加：共用时间轴、区间控制及悬停/锁定交互，左轴为累计盈亏金额，右轴为单位净值；图例明确区分曲线与刻度。缺失历史保留断点，当前盈亏与最新净值日期不同时分别显示日期，不借用另一日期的值。保留零基线、加载、错误和重试。

## 验收

- AC1：基金回退保留稳定根因，详情横幅与对应分段展示原因；未提供原因时不编造，正常延迟净值不误报。
- AC2：标的历史按账户、模式、标的和截止时间隔离；包含历史已实现收益，缺值断线，零值有效；不改历史事实。
- AC3：Schema 与 API 客户端校验范围及取消信号，现有组合请求兼容。
- AC4：桌面基金持仓详情在同一张历史图中展示累计盈亏和单位净值，双轴、共用区间与悬停读数正确；当前金额与同一账户持仓及 Ledger 口径一致，切换范围和错误可恢复。
- AC5：定向测试、相关构建、边界门禁及本地 API/浏览器验收有明确证据；运行态更新只能通过维护脚本，不宣称镜像或原生客户端已更新。

## 验证边界

以确定性测试覆盖多次买卖、同代码不同市场、跨币种及缺失历史；真实运行态使用现有数据验证原因与当前值。保留全部既有未提交修改、数据库及 Provider 配置，不提交或发布。无数据库结构变更。
