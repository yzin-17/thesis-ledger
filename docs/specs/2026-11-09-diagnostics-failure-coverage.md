# 数据与自动化诊断失败覆盖

对应任务：[已完成实施任务](../archive/tasks/2026-11-09-diagnostics-failure-coverage.md)

## 问题与边界

诊断页只读取终态通知失败和开放数据质量问题。现存来源检查异常与自动化异常已有持久化事实，却没有进入诊断页。2026-11-09 只读检查发现：通知记录均为已送达，数据质量表为空，来源检查有 95 条带错误码记录，自动化有 1 条结果待确认记录。带错误码记录包含检查过程状态，不能全部认定为失败。

本次复用现有业务事实做只读诊断，覆盖来源检查异常、自动化失败或结果待确认、通知失败或等待重试、开放数据质量问题。不新增诊断数据库，不反向推断日志或补造历史记录，不触发来源测试、模型请求、自动化执行或通知投递。普通行情请求尚未记录为检查历史，数据质量业务写入尚未接入，不能声称此页已覆盖全部请求失败。研究与回测仍由各自业务入口负责。

## 行为与验收

- AC1：来源检查诊断在数据库分页前筛选异常（降级或不可用），排除 `pending`、`operation_authorized` 和 `validation_cancelled` 等检查过程及主动取消状态；保留异常时间、来源、状态和错误码。慢响应降级可显示，但不能标成调用失败。正常检查不能挤掉旧异常。
- AC2：自动化诊断在数据库分页前筛选 `failed`、`unknown_outcome`，显示任务、状态、开始时间和错误；结果待确认保持独立中文语义。正常成功记录不能挤掉旧异常。
- AC3：通知诊断覆盖 `failed`、`retrying`，并保留已有仅查 `failed` 的 API 行为。重试中的通知不标成终态失败。
- AC4：来源与自动化异常分别分页，列宽不随当前页内容变化；刷新保留已有数据并显示共享加载圈；首次读取失败、成功为空、旧数据刷新失败分别表达。诊断页只使用查询请求，桌面、平板、窄屏表格在容器内滚动。
- AC5：旧历史、通知和质量数据不修改。数据质量说明明确为已记录且未关闭的问题，不能让空表暗示全部数据健康。
- AC6：异常查询使用独立接口，旧 Server 不支持时必须表现为读取失败；即使响应形状合法，包含健康、成功或检查过程状态的内容也不得通过异常响应合同。不得在客户端对普通历史单页过滤后伪装成完整异常分页。

来源异常接口返回来源、检查状态、错误码、延迟、检查时间与检查来源这些公共摘要字段；原始 AI 校验或其他适配器详情保留在历史存储，不要求诊断表解析适配器协议，避免详情格式变化阻断整页诊断。

## 实施与验证边界

Server 由所属 feature 扩展现有只读查询过滤；API client 复用现有响应 Schema；Desktop 复用共享表格与按钮，不改市场路由配置中的既有未提交工作。定向测试先于包构建和仓库门禁，浏览器使用受控请求验证；目标 Docker 同步及真实页面验收须单列证据，未执行不得宣称上线。
