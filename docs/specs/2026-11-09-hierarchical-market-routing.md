# 分级路由与统一本地资料

状态：已实现并完成本功能验收。执行记录见 [任务清单](../archive/tasks/2026-11-09-hierarchical-market-routing.md)，验证范围与共享工作区限制见 [实施证据](../evidence/2026-11-09-hierarchical-market-routing.md)。

## 目标与范围

日常配置收敛为行情与净值、基本面数据、新闻资讯、宏观与市场、交易规则、证券资料与公司行动六类，每类一组默认主备偏好。采用建议时，根据当前部署已配置来源、有效权限与精确能力目录逐项选择主备及具体接口，并用符合条件的免凭证来源补齐；覆盖本类全部细分配置，预览确认后保存。选择与验收见[按可用来源推荐](2026-11-10-routing-available-recommendation.md)。

当前编辑模型为大类默认与完整精确项两级。旧市场、类型、用途及周期汇总规则无损展开为具体项例外，不作为隐藏的当前继承层；兼容处理见 [旧继承整理](2026-11-10-routing-legacy-inheritance.md)。明确未配置阻止继承；恢复继承删除单项规则并直接回到大类配置。普通大类下拉选择保留单项例外；采用建议主备时同时替换本类全部细分配置，可按各项能力选用不同提供方，每项最多两家。主备仅使用各自支持的能力，诊断区分未覆盖、来源不可用、仅单源和绑定歧义。

## 配置契约与所有权

Server Market 持有规则解释、精确路由编译及保存编排。公共 Schema 只定义跨应用数据契约。读取、预览、保存入口分别为 GET `api/market-data/routing-config`、POST `api/market-data/routing-config/preview`、PUT `api/market-data/routing-config`。保存校验策略修订与目录修订，服务端重新编译；规则元数据和精确路由使用现有 JSON 容器，在同一事务写入当前策略及历史，继续使用现有 DSA 应用/重试流程。

旧策略读取时先无损归纳，再规范为大类默认及精确项，差异、明确空配置和已有精确来源绑定保留。读取不写回、不切源；旧规则整理数量单独提示，即使来源变化为零也可预览保存。目录新增仅影响诊断，显式纳入并预览保存后才生效。旧精确策略写入入口清除分级元数据，下次读取重新归纳并整理，防止旧父级规则复活被移除来源。历史版本不改写。

来源恢复资格或目录增加已有能力的绑定时，即使规则草稿未编辑，也显示待确认的精确变更数量并允许主动预览；诊断更新不自动应用。新能力仍须先明确纳入范围。

## 本地资料

新增一个可配置的本地资料来源；内部保留旧身份、文件、出处、版本、生效期和准入。按能力、市场、类型、标的、请求日期选择适用且完整的数据包；重叠仅选一套完整资料，不累加费用。不完整、冲突、日期或标的不匹配时拒绝并返回具体原因；原来源继续供历史冻结读取使用。新入口不得扩大任何资料覆盖范围或绕过原准入。

## 客户端交互

默认全部市场和全部类型。六类展示主备及覆盖诊断，细分配置使用右侧面板，窄屏全屏。面板只平铺当前大类的完整精确路由，行情同时展示用途、周期和复权口径，其他能力展示市场、标的类型和用途。顶部统一按市场、类型、用途、周期和复权独立筛选，可清空筛选；筛选只影响查看。每行直接显示主备下拉框和单独设置/继承大类配置状态，实际选择才创建覆盖。“使用上级配置”删除单项规则并恢复大类默认。所有精确项共用草稿，可从面板底部直接进入统一预览，显示来源变更、清空项、保留例外及旧规则整理后保存；返回主配置保留草稿，失败可恢复。交互细节见 [细分路由直接编辑](2026-11-09-market-routing-inline-editor.md)。资料详情只读显示覆盖、文件和缺项。

## 验收标准

- 继承优先级、明确空配置、例外保留、目录新增、旧策略无损归纳及主备覆盖诊断有定向测试。
- 规则、精确路由和历史原子保存；并发修订拒绝，应用失败可重试且草稿保留。
- 本地资料匹配、重叠消歧、费用不重复、覆盖不足拒绝、旧身份和历史冻结版本保持有定向测试。
- 按定向测试、包级检查、仓库门禁、真实运行态递进；浏览器覆盖 1440、1024、768、390，真实数据只读，保存及故障用受控请求或隔离输入。
