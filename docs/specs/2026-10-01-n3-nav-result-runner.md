# N3 净值结果与离线 Runner 合同

关联主规格：[现行运行链替换](2026-09-29-thesis-ledger-canonical-runtime-replacement.md)。本文件补充 N3 已冻结输入之后、N2 创建持久化之前可独立交付的结果与执行接口，不修改共享主规格。

## 范围与所有权

新增独立 NAV 公开结果 Schema、统一执行结果读取 Schema，以及现行本地 Runner 的 NAV 能力入口。复用 N1 冻结读回和已完成离线申赎实现。不修改 N2 准备、API、Repository、Prisma，或 Worker 投递/领取/终态；不部署或提交。

## 稳定合同

- AC01：NAV 结果必须显式声明 `inputKind=nav`、版本、运行及策略身份、Snapshot 摘要、来源、执行模型、可见性模式、期末时刻与结果校验和；拒绝场内价格协议和 Bar 来源替代。
- AC02：复用当前成交、交易、权益、回撤和指标合同；净值申请及期末待处理状态单独公开。研究结果明确 `strictPit=false`，严格发布时间结果仍声明需要来源 PIT 准入。
- AC03：当前 Runner 提供独立 `runNav` 能力，完整读取 NAV Store 并核对 runId、Snapshot 与精确 Artifact 集合；缺能力、身份不符、篡改和取消时失败关闭。场内 `run` 的现行合同保持稳定，Worker 后续显式选择 NAV 入口。
- AC04：结果逐日权益不超过冻结期末；净值基准使用同基金执行窗口与可见事实，费用只消费冻结内核；结果读取需复核校验和及完整冻结身份。期末待处理和诊断不会被报告为完整执行结果。
- AC05：真实本地 Parquet 离线执行与重复重放一致，覆盖严格/研究模式、缺产物、错引用、结果篡改与取消；不访问 Provider、数据库或队列。

## 验收边界

Schemas 与 Runner 定向、适用包级、类型/构建及边界验证。共享工作区发生并行变更时保留失败证据并对本叶真实依赖做独立验证。Worker 领取到终态、持久取消、晚到结果与客户端消费由后续 N3/N2.5 汇合验证；本文件不授予投递能力。
