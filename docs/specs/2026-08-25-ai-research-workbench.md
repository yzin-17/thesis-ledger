# 研究助手任务工作台交互设计

## 背景

当前 Desktop“研究助手”页面将研究上下文、研究问题、创建按钮、数据状态和研究历史纵向堆叠在同一页面。页面能够创建 `AiRun` 记录并展示基本运行元数据，但主要交互仍接近接口验收表单，没有形成“提出问题、跟踪任务、阅读结论、核查证据”的完整研究流程。

当前实现还存在以下语义和数据关联问题：

- 研究问题只保留在前端本地状态，并用于创建成功 Toast；创建请求不携带问题，`AiRun` 也没有一等字段持久化问题。
- “账户”和“策略版本”只提交 `scope`，没有选择具体 `accountId` 或 `strategyVersionId`；“单个持仓”只提交自由文本 `symbol`，没有明确所属账户。
- Desktop 固定提交 `provider: mock`、`model: research-default` 和 `promptVersion: research-v1`，没有呈现真实 Provider 就绪状态，也没有使用服务端路由结果建立正确预期。
- `POST /ai/runs` 当前只创建一条 `running` 记录，没有在同一用户动作中启动完整研究编排。
- 创建成功后只显示任务编号、Provider、模型、Prompt 版本和静态“来源链”文字，没有渲染结构化研究结果、工具调用或真实来源入口。
- 研究历史只显示截断 UUID、原始英文状态和技术字段，无法通过“研究了什么”识别任务，也不能选择任务查看详情。
- 历史查询已经由 TanStack Query 管理，但“刷新研究历史”仍作为标题下方的高强调操作；创建后的运行状态没有自动轮询。
- 通用“暂无数据”横幅位于创建区和历史区之间，容易被误解为研究前置数据不可用，实际上可能只是历史列表为空。

研究助手的领域模型是可追溯、异步、只读的研究任务，不是可连续追加上下文的聊天会话。本设计因此采用任务工作台，不引入聊天气泡、会话线程或隐式上下文继承。

## 已确认方向

- 将研究助手改造为“研究任务列表 + 任务详情”的工作台。
- 新建研究通过右侧宽 `Sheet` 完成，页面主体不长期占用大面积表单。
- 任务标题使用研究问题摘要，UUID、Provider、模型和 Prompt 版本降级为运行详情。
- 用户必须选择真实研究对象；账户、持仓和策略研究不能只提交抽象范围。
- 研究结果优先展示结论、主要风险、证据和未知项，来源链与工具调用可继续下钻。
- 非终态任务自动更新；手动刷新保留为低强调辅助操作。
- 保持只读研究边界，不写入 Ledger、Position 或 Order，不生成订单。
- 保留现有中性、克制、可信的视觉语言，不引入通用 AI 渐变、聊天拟人化或无依据的动画进度。

## 目标

- 让用户在首屏明确看到最近研究、当前任务状态和下一步操作。
- 让“选择研究对象、提出问题、确认数据边界、开始研究”成为连续且可理解的流程。
- 让用户能够通过问题摘要和业务上下文识别历史任务，而不是依赖 UUID。
- 让运行中、已完成、失败、取消和数据不足状态具有独立、可恢复的交互。
- 让每条研究结论能够下钻到证据、引用和实际 Tool 调用记录。
- 让 Provider 路由、Prompt 版本、Token、成本和耗时保持可审计，但不抢占研究内容的视觉层级。
- 使用 TanStack Query 管理列表、详情、轮询、Mutation 和失效，避免手写请求竞态状态。
- 复用现有 shadcn/Base UI 组件和 Tailwind v4 原子类，不新增页面级传统 CSS。

## 非目标

- 本期不实现连续多轮聊天、消息历史、上下文压缩或跨任务追问。
- 本期不允许 AI 修改 Ledger、持仓、风险规则、策略版本或自动化任务。
- 本期不生成买卖指令、订单草稿或“一键执行”入口。
- 本期不实现研究模板管理、共享、导出、收藏或跨用户协作。
- 本期不实现多个任务并行对比、研究报告版本 Diff 或结论评分排行。
- 本期不允许 Desktop 自由选择 Provider、模型或 Prompt 版本；这些属于服务端路由和审计事实。
- 不修改 `/ai-chat` 路由和主导航“研究助手”名称。
- 不修改全局主题、侧边导航或其他页面的信息架构。

## 现状与约束

- 当前入口为 `apps/desktop/src/features/ai/AiChat.tsx`，请求、Query、Mutation 和类型已经拆分在同一 feature 目录。
- `AiRun` 已持久化 Provider、模型、Prompt 版本、状态、上下文、checkpoint、结果、Token、成本、耗时和时间字段。
- `AiToolCall` 已持久化 Tool、权限、状态、输入/输出摘要、Provider 和时间来源字段，但任务详情查询尚未包含关联 Tool 调用。
- `ResearchResult V1` 已定义 `conclusion`、`evidence`、`risks`、`unknowns`、`disclaimer`、`signals` 和 `createdAt`，结果 UI 应消费该契约，不另造互不兼容的结果结构。
- `aiContextSchema` 已支持 `portfolioId`、`accountId`、`symbol` 和 `strategyVersionId`；当前 Desktop 尚未完整填写这些字段。
- 账户、组合估值、标的搜索和策略列表已有 TanStack Query，可复用其查询或提取共享选择器，不应在研究助手中复制请求实现。
- 项目使用 Vite、React、Tailwind v4、Base UI、`base-vega` 和 `lucide`。
- 现有组件包括 `Sheet`、`Dialog`、`Tabs`、`Select`、`InputGroup`、`Badge`、`Alert`、`Empty`、`Skeleton` 和 Toast；缺失组件只能通过项目包管理器和 shadcn CLI 按需添加，不能覆盖本地组件。
- 表单使用 `FieldGroup`、`Field` 及对应 Label/Description/Error；四项范围选择优先使用 `ToggleGroup`，Select item 必须位于 `SelectGroup`，overlay 必须包含可访问的 Title 和 Description。
- 样式使用现有语义 Token、组件变体和原子类，不新增 `!important`、视觉专用选择器或重复渲染分支。

## 设计方案

### 服务端研究执行链

`POST /ai/runs` 是异步研究启动入口，不是单纯的数据库写入接口。服务端采用“持久化队列 + 专用研究执行器”方案：

1. 校验问题、研究范围、实体存在性和当前用户授权范围。
2. 创建 `queued` 的 `AiRun`，立即返回稳定任务 ID；客户端不得把 `pending` Provider 当作执行结果。
3. 执行器通过条件更新领取任务，将状态转换为 `running`，写入真实 `startedAt` 和执行尝试次数。
4. 通过 Prompt Registry、Provider Registry 和能力策略选择实际 Prompt、Provider 与模型；客户端不提交这些权威事实。
5. 根据研究上下文创建只读 Tool，使用现有 Tool runtime 执行，并为每次调用记录权限、状态、输入/输出摘要、Provider 和来源时间。
6. 调用真实 Provider，支持超时、取消和 fallback；Provider 未配置或全部失败时进入可解释的失败终态。
7. 仅在 `ResearchResult V1` 及 citation/Tool 关联校验通过后写入 `succeeded`；结果契约失败写入 `result_untrusted`。
8. 服务重启时恢复超时的 `running` 任务；同一任务只能由一个执行器持有租约，避免重复写入结果。

执行器优先复用现有持久化任务和 Worker 的状态、条件领取及恢复模式，但不把 AI 研究强行建模为定时自动化任务。真实 Provider 接入前，必须先用 fixture Provider 跑通同一条状态链；fixture 结果始终标记为“演示模式”。

### 可信边界与能力预检

- 研究上下文由服务端领域服务解析，验证账户、持仓、策略版本和重试来源属于当前授权范围。
- 服务端提供研究能力预检结果，包含 Provider 状态、可用模型、所需 Tool、缺失项、具体影响和 `canStart`。
- Desktop 只提交问题、上下文、模板和重试关系，不提交 Provider、模型、Prompt、Token、成本、耗时、Tool 调用或 fallback。
- 新结果的每个 citation 必须关联实际 `AiToolCall`；历史结果没有关联 ID 时保留兼容展示，但不能伪造关联。
- 任务列表使用稳定游标分页，排序键为 `createdAt + id`；详情和来源链不得依赖 Desktop 直接访问数据库。

## 页面头部

标题继续使用“研究助手”，删除重复的英文 kicker 或将其降为无障碍不可见信息。副标题收敛为一句面向用户的能力边界：

> 基于已授权数据生成可追溯结论，不会修改账本或生成订单。

标题右侧依次提供：

- Provider 状态 Badge：可用、演示模式、未配置或异常。
- 低强调刷新按钮：显式重新获取列表和当前详情，不替代自动轮询。
- 主按钮“新建研究”：打开右侧 Sheet。

Provider 未配置时仍允许浏览历史任务；“新建研究”是否禁用取决于服务端是否存在可执行的 mock/fixture 路由。若只能运行 mock，必须明确标注“演示模式”，不能显示为真实 Provider 可用。

## 研究任务列表

左侧任务列表承担任务导航，不使用完整数据表。顶部使用状态筛选：

- 全部
- 排队中
- 进行中
- 已完成
- 失败

每条任务至少展示：

- 研究问题摘要，最多两行，作为主要标题。
- 业务上下文摘要，例如“全组合”“长线账户”“600519.SH”“均线策略 v3”。
- 中文状态 Badge。
- 创建时间或更新时间；当天显示时间，较早记录显示日期。

列表不将 Provider、模型、Prompt 版本或 UUID 作为主信息。任务问题缺失的历史记录回退为“未记录研究问题”，并显示截断任务编号作为诊断信息。

任务默认按创建时间倒序。新建成功后使用 Mutation 结果立即将任务置于列表顶部并选中，再通过 Query 失效读取服务端权威状态。筛选结果为空时使用当前筛选上下文的 `Empty`，不显示通用“完成配置或导入后”文案。

## 任务详情

右侧详情始终对应一个明确任务。顶部显示问题全文、业务上下文、中文状态和时间；技术元数据收纳在底部“运行详情”中。

### 未选择任务

- 有历史任务时提示“选择一条研究任务查看结果”。
- 没有历史任务时显示首个研究空态、简短能力说明、“创建第一次研究”按钮和最多三个示例问题。
- 示例问题只打开 Sheet 并预填问题，不直接提交。

### 进行中

- 显示当前服务端 checkpoint 对应的真实阶段，例如“收集证据”“核对风险”“生成结论”。
- 没有 checkpoint 时只显示“研究正在进行”，不生成虚假百分比或假进度条。
- TanStack Query 只在当前详情或列表存在非终态任务时轮询；所有任务进入终态后停止。
- 用户可以切换到其他任务或页面，进行中状态不锁定整个研究助手。

### 已完成

结果按以下顺序展示：

1. 结论：直接消费 `ResearchResult V1.conclusion`。
2. 主要风险：展示 `risks`，没有风险时显示明确的空结果，不隐藏区块。
3. 关键证据：按 claim 展示证据摘要和引用数量，点击打开来源链 Sheet。
4. 未知项与限制：展示 `unknowns` 和数据缺口。
5. 免责声明：使用低强调固定文案，不与主要结论混排。
6. 运行详情：Provider、模型、Prompt 版本、任务编号、Token、成本、耗时和时间。

`signals` 仅在有真实研究信号时展示，不为了填充页面生成空卡片。关键数字必须能下钻到 citation；缺少引用的结果视为契约错误，不能伪装成正常完成。

### 失败

- 保留原研究问题、上下文和已获得的 checkpoint，不清空详情。
- 显示服务端可公开的失败阶段和错误摘要，不只提示“检查 Provider 状态”。
- 提供“使用原问题重试”操作；重试创建新任务并通过 `retryOfRunId` 或等价字段关联来源任务，不覆盖失败记录。
- Provider 不可用、Tool 不可用、结果契约校验失败和未知服务错误应使用不同文案。

### 取消

若服务端提供取消能力，进行中详情可以提供低强调“取消研究”。取消后保留已有审计信息和上下文。若本期不增加取消 endpoint，则 UI 不展示无效取消按钮，状态映射仍兼容历史 `cancelled` 记录。

### 研究范围

四项范围使用 `ToggleGroup`：

- 全组合：研究当前投资组合整体，不需要额外选择账户时显示组合摘要。
- 账户：必须选择一个有效 `accountId`。
- 单个持仓：必须选择账户和该账户中的实际持仓；提交 `accountId + symbol`，不能只依赖自由文本代码。
- 策略版本：必须选择策略及具体版本，提交 `strategyVersionId`；列表显示“策略名称 + vN”。

切换范围时清除不属于新范围的实体选择，保留研究问题。实体数据加载、空态和错误在对应 Field 内反馈，不用全局横幅覆盖整个 Sheet。

### 研究问题

- 默认问题留空，不自动填入可直接误提交的完整示例。
- Textarea 使用自然语言字体和适中高度，默认约 5 至 6 行，不继承当前面向 JSON 的等宽字体和 180px 最小高度。
- 去除首尾空白后不能为空，建议限制为 1 至 2000 个字符；具体上限由服务端 Schema 统一定义。
- Field 下方展示字符计数或简短提示，但不在用户输入前堆叠长说明。
- 常用问题使用轻量模板入口：“主要风险”“近期变化”“反方证据”“情景压力”。点击后填入可编辑问题，不自动提交。

建议模板文案：

- 主要风险：`请说明当前最主要的风险，并列出支持证据、反例和数据缺口。`
- 近期变化：`请比较最近一个观察窗口与此前状态，说明发生了哪些重要变化。`
- 反方证据：`请主动寻找不支持当前投资假设的证据，并说明假设最脆弱的部分。`
- 情景压力：`请在明确假设下分析不利情景，并说明哪些结论无法由现有数据支持。`

### 数据边界预览

Sheet 在提交前展示“本次预计读取”，内容由研究范围、实体和当前 Provider/Tool 可用性推导：

- 全组合：组合、账户、持仓、行情和风险历史。
- 账户：账户持仓、Ledger 摘要、行情和风险历史。
- 单个持仓：行情、财务、新闻/公告、持仓和风险历史。
- 策略版本：策略 Schema、关联回测、行情和风险事实。

该区域只表达真实能力，不保证每个来源都有数据。来源不可用时使用 Alert 说明“本次结果将缺少新闻数据”等具体影响；不能把失败来源替换成零值或虚构结果。

### 提交

主操作使用“开始研究”，不使用面向系统实现的“创建研究任务”。提交期间按钮禁用并组合 Spinner；失败时 Sheet 保持打开，保留问题和研究对象，字段错误就地显示，服务错误使用可重试 Alert。

提交成功后：

1. 关闭 Sheet。
2. 新任务立即出现在列表顶部并自动选中。
3. 右侧进入真实运行中状态。
4. 列表和详情 Query 开始按非终态轮询。
5. Toast 只简短确认“研究已开始”，不重复完整问题。

## 来源链 Sheet

点击“查看来源链”或证据 claim 打开右侧 Sheet。来源链按 claim 分组，展示：

- 证据主张。
- Tool 名称和权限。
- 来源 ID 和 Provider。
- `observedAt`、`marketTime`、`availableAt`、`fetchedAt` 等适用时间。
- Tool 状态：成功、不可用或拒绝。
- 输入/输出摘要。
- 新结果的每条 citation 都展示对应的 `toolCallId` 和 Tool 审计；不把同一任务的全部 Tool 调用混在每个 claim 下。

来源链是只读审计视图。未经领域允许，不提供“编辑证据”“忽略来源”或“重新写入结果”等操作。某个 Tool 失败时保留失败记录，并在研究结果的未知项或限制中体现。

## Provider 与运行详情

Desktop 创建研究时只提交研究问题、上下文和可选研究模板标识。Provider、模型和 Prompt 版本由服务端根据 Registry、能力、优先级和 fallback 规则选择，并将实际结果写入 `AiRun`。

运行详情默认收起，展开后展示：

- 实际 Provider 和模型。
- Prompt 版本。
- 任务编号。
- 创建、开始、完成时间和耗时。
- 输入/输出 Token 和成本。
- fallback 摘要；具体 Provider 错误需经过服务端脱敏。

mock/fixture 结果必须标记“演示模式”，避免用户将样例研究误认为实时外部事实。

## 对外行为与接口调整

### 创建研究

现有 `POST /ai/runs` 需要从“写入一条运行记录”提升为真正的研究启动入口，或新增语义更明确的研究启动 endpoint。面向 Desktop 的最小输入应包含：

```ts
interface StartResearchInput {
  question: string;
  context: {
    scope: 'portfolio' | 'account' | 'position' | 'strategy';
    portfolioId?: string;
    accountId?: string;
    symbol?: string;
    strategyVersionId?: string;
  };
  templateId?: 'primary-risks' | 'recent-changes' | 'counter-evidence' | 'stress-scenario';
  retryOfRunId?: string;
}
```

服务端负责：

- 校验问题和上下文范围的一致性。
- 校验实体存在且在当前授权范围内。
- 选择 Prompt、Provider 和模型。
- 创建 `AiRun` 并启动或排队研究编排。
- 在实际执行中记录 Tool 调用、checkpoint、Token、成本、耗时和 fallback。
- 只在 `ResearchResult V1` 校验通过后将任务标记为成功；所有进入 `succeeded` 的路径必须汇聚到同一终态提交逻辑，既有 `completeWithProvider` 或等价兼容入口不得绕过结果与 citation/Tool 关联校验。

客户端不得写入服务端审计字段，也不得通过 `modelMetadata` 伪造 Tool、Token、成本、耗时或 Provider 结果。

### 数据模型

`AiRun` 建议增加或明确以下一等字段：

- `question`：原始研究问题。
- `errorCode`、`errorSummary`：可向用户公开的失败分类和脱敏摘要。
- `startedAt`、`completedAt`：区分记录创建、实际开始和终态时间。
- `retryOfRunId`：可选的重试来源关系。

若采用单独的 `ResearchRequest` 记录，也必须保证问题、上下文和 `AiRun` 之间存在稳定关联，列表接口不依赖解析不透明 `modelMetadata` 才能展示问题。

### 读取接口

- 任务列表返回轻量摘要：ID、问题、上下文、状态、实际 Provider/模型、创建和更新时间。
- 任务详情返回 checkpoint、结构化结果、错误摘要、Token、成本、耗时和时间字段。
- 完整来源链 `AiToolCall` 审计使用独立分页 endpoint 读取；任务详情可以返回有界的 citation/来源摘要，但不得无界携带全部 Tool 调用，也不得依赖 Desktop 直接查询数据库。
- 列表支持状态筛选和分页；首期页面可以只读取最近记录，但接口应保留稳定游标或分页能力。

列表接口使用稳定游标，不把 `limit` 当作唯一分页能力：

```ts
interface AiRunPage {
  items: AiRunSummary[];
  nextCursor: string | null;
  hasMore: boolean;
}
```

推荐请求形状为 `GET /ai/runs?status=failed&limit=20&cursor=...`，服务端按 `createdAt` 和 `id` 的复合顺序返回，状态值使用有限枚举。完整来源链使用独立接口（如 `GET /ai/runs/:id/tool-calls?limit=20&cursor=...`），并使用同样的稳定排序和分页规则。

新增 `GET /ai/capabilities` 返回当前研究能力：Provider 状态（可用、演示模式、未配置、异常）、实际可选模型、范围对应 Tool、缺失项、缺失影响和 `canStart`。该接口只返回可公开的健康摘要，不返回凭证或底层错误堆栈。

## 数据、状态与兼容性影响

- `AiRun` 保留 `question`、`errorCode`、`errorSummary`、`startedAt`、`completedAt` 和 `retryOfRunId`；为恢复语义增加执行尝试和租约所需的可空字段，历史记录使用兼容默认值。
- `AiToolCall` 继续保存只读审计事实；新生成的 citation 增加 `toolCallId`，服务端在成功落库前校验引用的 Tool 调用属于同一任务。
- 任务状态至少包括 `queued`、`running`、`succeeded`、`failed`、`cancelled`；Provider 不可用、Tool 不可用、结果不可信和未知错误通过 `errorCode` 区分，不用伪造成功结果。
- 新列表接口返回分页 envelope；Desktop 数据层负责兼容历史空字段和旧任务状态，不把旧记录补写成虚构问题或 Provider 事实。
- 旧的确定性 AI 流程继续保留兼容入口，但新的研究启动契约必须严格拒绝客户端审计字段；兼容入口不能被新工作台使用来绕过执行器。
- 所有新增字段使用可迁移的 nullable/default 策略；迁移不得删除或重写既有 AI 运行和 Tool 审计。
- 当前仓库没有独立的用户主体/会话模型，研究接口继续受 LAN Bearer token 保护；本轮以实体存在性、账户 active 状态、持仓归属、策略版本和重试来源校验落实服务端边界。细粒度跨用户隔离仍属于后续身份模型工作，不在本轮虚构实现。

## 状态与异常处理

- 列表加载中：左栏使用与任务项形状一致的 Skeleton，右栏保留当前已完成详情。
- 列表为空：显示研究专用 Empty 和“创建第一次研究”。
- 列表读取失败：在左栏显示可重试 Alert，不清除仍可查看的已选详情。
- 详情读取失败：只更新右栏错误状态，保留任务列表。
- Provider 未配置：可以查看历史，创建区解释缺失配置和下一步；不能提交后才统一报“服务连接失败”。
- 某个 Tool 不可用：保留部分证据和未知项，由结果契约决定任务是成功、部分受限或失败，不回退零值。
- 结果契约校验失败：任务标记失败，错误分类为结果不可信，不能渲染未经校验的自由结构。
- 执行器领取失败、租约超时或服务重启：任务回到可恢复的 `queued`，超过重试上限后进入 `failed`，并保留公开错误摘要。
- Provider fallback 全部失败：保留已记录的 Tool 审计，任务进入 Provider 失败终态，不写入自由格式结果。
- 切换任务：详情 Query key 包含任务 ID，不复用上一任务结果作为当前任务成功态。
- 切换范围：清理不兼容实体，但保留未提交问题。
- Sheet 关闭：默认保留本次打开期间的草稿还是清空，实施前应选择一种项目级一致行为；若增加未保存确认，必须补充键盘和关闭路径测试。

## TanStack Query 状态模型

建议 Query key：

```ts
const aiKeys = {
  root: ['desktop', 'ai'] as const,
  runs: (filter: AiRunFilter) => [...aiKeys.root, 'runs', filter] as const,
  run: (id: string) => [...aiKeys.root, 'run', id] as const,
  toolCalls: (id: string) => [...aiKeys.root, 'run', id, 'tool-calls'] as const,
};
```

- 列表 Query 管理筛选、分页和是否存在非终态任务。
- 详情 Query 只在存在选中任务时启用。
- 列表或当前任务非终态时按固定间隔轮询；所有相关任务终态后停止。
- 创建 Mutation 成功后更新选中 ID，并失效列表和新任务详情。
- 重试 Mutation 创建新 ID，不覆盖失败任务缓存。
- Tool 调用数据只在来源链 Sheet 打开时查询，或由详情数据按实际载荷大小决定是否预取。
- 旧数据和网络错误通过 `stale` 或局部 Alert 表达，不把旧结果替换成空白成功态。

## 前端组件与模块边界

建议拆分为以下职责单一的模块，具体文件名可按 feature 现状调整：

- `AiResearchWorkbench`：页面 Query/Mutation 编排、选中任务和 overlay 开关。
- `AiRunList`：状态筛选、任务摘要、列表加载/空态/错误。
- `AiRunDetail`：按任务状态选择详情视图。
- `NewResearchSheet`：范围、实体、问题、模板和数据边界预览。
- `ResearchContextFields`：范围对应实体选择，不处理任务提交。
- `ResearchResultView`：结论、风险、证据、未知项和免责声明。
- `ResearchProgress`：只消费服务端真实 checkpoint。
- `EvidenceChainSheet`：引用和 Tool 调用审计。
- `AiRunMetadata`：运行详情和实际 Provider 信息。
- `ai.api.ts`、`ai.queries.ts`、`ai.mutations.ts`、`ai.types.ts`：补齐列表、详情、轮询和启动契约。

容器负责跨区域状态和请求编排，局部组件负责单一可测试交互。不得把任务列表、Sheet 表单、结果渲染和来源链重新集中到一个巨型 `AiChat.tsx`。

## 组件使用

- `Sheet`：新建研究和来源链。
- `ToggleGroup`：四项研究范围。
- `FieldGroup`、`Field`：研究对象和问题表单。
- `Select` 或现有 Combobox：账户、持仓和策略版本。
- `Badge`：Provider 和任务状态。
- `Alert`：Provider、Tool、查询和提交错误。
- `Empty`：无任务、筛选为空和无可选实体。
- `Skeleton`：列表和详情加载。
- `Collapsible`：运行详情；若现有组件未安装，实施前通过 shadcn CLI 查看 docs、预览并按需添加。

所有状态必须同时使用文字和组件语义表达，不能只依赖颜色。按钮使用内置 variant，布局通过原子类组合，不覆盖组件颜色或 typography。

## 可访问性与键盘行为

- 页面首个主要操作可通过正常 Tab 顺序到达，不使用自定义键盘拦截。
- 任务项使用可聚焦的选择控件或链接语义，并通过 `aria-current` 表达当前任务。
- Sheet 打开后焦点进入 Title 或第一个 Field；关闭后返回“新建研究”。
- 字段错误使用 `data-invalid`、`aria-invalid` 和关联错误说明。
- 任务状态变化通过局部 `aria-live="polite"` 通知，不重复朗读完整结果。
- 运行 Spinner 标记为装饰，按钮文字保留可读状态。
- 来源链时间和状态不只通过 Tooltip 提供。
- 强制高对比和减少动效模式继续沿用全局规则。

## 验证策略

### 服务端

- 创建研究校验问题为空、超长问题和上下文缺少必要 ID。
- 账户、持仓和策略版本验证授权范围，不允许跨账户研究事实。
- Provider 路由和 fallback 写入实际执行事实，不接受客户端伪造审计字段。
- 成功任务只持久化通过 `ResearchResult V1` 校验的结果。
- Tool 调用保留权限、状态和时间来源；不可用结果不回退零值。
- 失败任务持久化可公开错误分类，重试创建新任务并保留关联。
- 列表分页、状态筛选和详情读取保持任务隔离。
- 执行器测试覆盖任务领取、queued → running → terminal 状态转换、Provider fallback、全部 Provider 失败、租约超时恢复和重复领取保护。
- 结果持久化测试覆盖 `ResearchResult V1` 校验失败、citation 缺少 `toolCallId`、Tool 调用不属于当前任务和成功终态写入。
- 能力预检测试覆盖 Provider 未配置、演示模式、Tool 部分不可用和健康状态异常；上下文授权测试覆盖跨账户和不存在实体。
- 列表/来源链接口测试覆盖稳定游标、同时间戳排序、`hasMore/nextCursor`、状态筛选和审计载荷边界。

### Desktop

- 使用 QueryClientProvider 覆盖列表加载、空态、错误、陈旧和成功状态。
- 覆盖四种研究范围和对应实体必填校验。
- 切换范围不会提交旧范围残留 ID。
- 研究问题未进入请求时测试必须失败，避免再次出现“只写 Toast”的回归。
- 创建成功后任务置顶、自动选中并进入轮询；所有任务终态后停止轮询。
- 已完成、进行中、失败、取消和未知状态都有兼容渲染。
- 结果覆盖完整证据、部分 Tool 不可用、未知项为空和结果契约失败。
- 来源链 Sheet 覆盖多引用、失败 Tool、时间字段缺失和键盘关闭。
- mock/fixture 任务明确显示“演示模式”。
- Provider 能力 Query 覆盖可用、演示、未配置、异常和具体缺失影响；提交按钮遵守 `canStart`。
- 来源链覆盖 citation 与 Tool 调用的一对多关联、无效 `toolCallId` 和历史无关联结果。
- 列表 Query 覆盖游标分页、筛选切换、重复时间排序和加载更多后的任务隔离。

### 人工验收

- 使用全组合、单账户、单持仓和策略版本各创建一次研究。
- 验证新建 Sheet、任务列表、运行中、完成、失败和来源链视觉状态。
- 验证窄窗口下主从布局不会重叠，Sheet 可完整滚动且主按钮可见。
- 验证键盘焦点顺序、Sheet 标题、任务选择和状态通知。
- 分别模拟 Provider 未配置、某个 Tool 不可用、详情读取失败和结果契约错误。
- 真实 AI Provider、外部新闻/财务来源和长时间任务需要在运行环境中单独验收，不能由确定性测试替代。
- 模拟服务重启、执行租约超时、Provider fallback 和重复轮询，确认任务最终只出现一个可信终态。

## 风险与备选方案

- 持久化队列 + 专用执行器是本期推荐方案：比同步 HTTP 执行更能承受长任务，也比引入外部消息队列改动更小。若未来需要多实例高吞吐，可将执行器替换为外部 Worker，但必须保留相同的任务状态和审计契约。
- 仅配置 Provider 凭证不能自动完成研究；如果 `POST /ai/runs` 未连接执行器，任务仍会停留在 `queued`。上线门槛必须同时验证 Provider adapter、任务领取、Tool 编排和终态收敛。
- 将 AI 任务直接接入通用定时自动化调度器可以复用轮询能力，但会把交互式研究和 Cron 生命周期耦合；本期只复用其锁与恢复思路，不复用其业务任务类型。
- 主从布局在窄窗口可能压缩详情。通过明确断点切换两级页面，不无限缩窄左栏或结果区。
- 将新建入口放入 Sheet 会增加一次点击。首个空态直接提供同一 Sheet 的 CTA，并保留常用问题模板降低输入成本。
- 问题和运行记录若只放在 `modelMetadata`，长期会导致列表查询和迁移困难。优先使用一等字段或明确关联实体。
- Provider 由服务端路由后，用户可能感觉缺少控制。通过提交前展示能力状态、完成后展示实际路由和 fallback 审计解决，不把基础设施选择暴露为日常表单。
- 运行中 checkpoint 不完整时无法显示细粒度阶段。宁可显示诚实的通用运行态，也不在客户端推测或模拟进度。
- 来源链可能很长。首期按 claim 分组并在 Sheet 内滚动；需要分页时由服务端提供稳定排序，不一次加载无界日志。
- 历史任务缺少问题字段。使用兼容回退展示并允许查看既有技术元数据，不对历史数据虚构问题。

## 未决问题

1. 全组合在多 Portfolio 场景下是否需要显式 `portfolioId` 选择；当前只有单一组合语义时可以使用默认组合。
2. 关闭有输入的“新建研究”Sheet 时，是保留页面会话草稿、直接清空，还是弹出未保存确认；应与项目其他编辑 Sheet 的约定保持一致。
3. 是否在首期提供取消研究 endpoint；没有服务端取消能力时不展示取消操作。
4. 首期真实 Provider 的具体实现和凭证由部署环境确定；无论选择哪一家，必须实现统一 `AiProvider` adapter 和健康状态，不把品牌选择暴露为 Desktop 表单。
5. 任务列表 UI 可以首期只加载第一页，但服务端稳定游标分页属于本 Spec 的必需接口，不再作为未决范围。

已确认：单个持仓必须先选择账户，再从该账户实际持仓中选择标的，并提交 `accountId + symbol`。

## 验收标准

1. 默认页面不长期展示大研究表单，而是展示任务列表和选中任务详情。
2. 页面头部提供 Provider 状态、低强调刷新和“新建研究”主操作；手动刷新不替代自动轮询。
3. 没有任务时显示研究专用 Empty 和创建入口，不显示通用“完成配置或导入后”的误导文案。
4. 新建研究通过右侧 Sheet 完成，范围使用四项选择，账户、持仓和策略版本必须绑定真实实体。
5. 研究问题默认留空、可使用模板预填，并作为一等字段进入创建请求和持久化记录。
6. Desktop 不再硬编码 Provider、模型和 Prompt 版本作为用户输入；服务端记录实际路由结果。
7. 点击“开始研究”后创建并启动真实研究流程，不只新增永久停留在 `queued` 或 `running` 的数据库记录。
8. 创建成功后任务置顶、自动选中，非终态任务自动轮询，全部终态后停止轮询。
9. 任务列表以问题摘要和业务上下文为主要标识，中文展示进行中、已完成、失败和取消状态。
10. 已完成详情按结论、主要风险、关键证据、未知项、免责声明和运行详情分区展示。
11. 关键证据可以打开来源链 Sheet，并查看 citation 与实际 Tool 调用审计。
12. 失败任务保留问题、上下文和错误分类，并支持创建关联的新重试任务，不覆盖原记录。
13. mock/fixture 研究明确显示“演示模式”，Provider 或 Tool 不可用不会被伪装为实时正常结果。
14. 列表错误、详情错误、Provider 未配置、Tool 不可用和结果契约错误分别反馈，互不清空仍可用内容。
15. 页面使用 TanStack Query 管理查询、轮询和 Mutation，复用 shadcn/Base UI 组件和原子类，不新增传统页面级 CSS、嵌套三元或手工请求竞态状态。
16. 任务工作台、新建 Sheet、来源链、状态切换和键盘行为具有针对性组件测试。
17. Desktop typecheck、目标测试、build、格式检查、文件大小 guardrail 和 `git diff --check` 通过；浏览器视觉验收、真实 Provider 和外部来源验收结果单独记录。
18. 服务端执行器能够安全领取任务，服务重启或租约超时后可恢复任务，重复执行不会覆盖已有终态或重复写入审计。
19. 服务端验证账户、持仓、策略版本和重试来源的存在性与授权范围，越权上下文不能创建或读取研究事实。
20. Provider、Tool、结果契约和未知服务错误分别拥有可公开的错误分类；所有成功路径都必须通过统一的 `ResearchResult V1` 与 citation/Tool 关联校验，兼容入口不得直接写入 `succeeded`。
21. `GET /ai/capabilities` 和新建 Sheet 能表达 Provider/Tool 的可用、演示、未配置和异常状态，并说明缺失影响。
22. 新生成的 citation 能通过 `toolCallId` 追溯到同一任务的实际 Tool 调用；历史无关联 ID 的结果保持兼容但不伪造映射。
23. 任务列表和来源链接口支持稳定游标分页、状态筛选和任务隔离，不能依赖无界 `take` 或一次性加载全部审计日志。

本轮整改已完成实现与确定性验证：创建任务通过持久化队列和专用执行器驱动，Provider/Tool、结果契约、租约恢复、能力预检、稳定分页和 citation 关联均已接入。真实 Provider、服务进程重启、外部新闻/财务来源和浏览器视觉/键盘 smoke 仍需部署环境凭证与运行条件，详见对应任务文档的“本轮验证记录（实现后）”和最终 Review。
