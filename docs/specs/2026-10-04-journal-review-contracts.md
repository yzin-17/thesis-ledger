## 实施前基线

以下缺口为实施前核对结果。当前实现与尚未完成的验收见[逐项对账](../reviews/2026-10-04-journal-review-consistency.md)。

2026-10-04 源码核对：现有候选继承 `completedTradeSchema` 的 number 字段，`reviewObjectId` 使用未加对象类型的 Trade/Slice ID；Journal 服务按账户整体 projectionFingerprint 判断旧快照，缺少对象级 evidenceFingerprint 和统一 statisticsEligibility；分析继续消费 CompletedTrade<number>；快照只有保存 POST，没有列表/详情 GET。这是实现缺口，不能用目标空列表、健康检查或新增 GET 单独结项。

## 范围与依赖

先交付原 T1 的 domain/schema 契约，再让原 T2 候选、T3 分析和 Snapshot 消费。Ledger、TradeQueryService 的经济事实及成本分配保持其现有所有权。新契约由 domain/schema 统一表达稳定对象 ID、decimal 原始事实、nullable openedAt、时间窗口和统计资格；Server 拥有来源编排、对象级指纹与持久化；Desktop 只消费服务端状态。

实现不得增加 Journal.service.ts 的既有 618 行规模，也不得把适配器搬入无所有权的共享目录。原 number 接口只留在明确的 legacy 适配边界；新增契约不改变当前 Ledger envelope 或已关闭的 Canonical 链路。

## 可观察行为

1. 对象 ID 为 `TRADE_CYCLE:<tradeId>` 或 `CLOSE_SLICE:<closeSliceId>`，由 domain/server 生成。
2. decimal string 保留权威数量、价格、费用、成本和收益；未知时间或金额显式 nullable，不由观察时间或零填充。
3. 统计资格由 domain 判断，排除原因遵循原 Spec；完整周期和减仓片段独立统计。资格不适用的依赖指标显示证据不足，其他有事实支持的指标仍可用。
4. 账户/模式/半开窗口与投影世代绑定分页；旧游标不跨新世代复用。
5. Snapshot 的 STALE 依据相关对象 evidenceFingerprint；无关标的或 Trade 变化不导致该对象快照过期。
6. 正式快照保存原始输入、确定性结果、来源引用与证据指纹；列表/详情读取不重算、不写经济事实。

## 首段领域契约

稳定对象引用使用可区分的 `TRADE_CYCLE` / `CLOSE_SLICE` 联合类型，片段必须属于指定 Trade。引用保留真实 `openedAt`，片段时间只取自身 `occurredAt`；完整周期结束时间只取已结束 Trade 的 `closedAt`，不借用观察时间或当前时间。

资格结果是给定统计粒度下的 `eligible + reasons`：完整周期检查 ACTIVE、非 SELL 结束、未知开仓时间；减仓片段使用自身退出、成本与证据，不因父 Trade 仍 ACTIVE 而被排除。成本冲突、缺 FX、证据不足、过期及未确认 legacy 由调用方提供明确事实上下文，领域规则统一生成原因；不能将资格结果当作所有单项指标的可用性。

窗口先验证带时区的时间端点，再按实际时间戳比较 `[start, end)`。缺少对象时间时，在有窗口约束的查询中不纳入；无时间约束时仍可返回该正式对象并保留空时间。禁止用 ISO 字符串字典序比较不同时区偏移。

候选中的 reviewStatus 描述其最近已保存快照，statisticsEligibility 描述当前分析事实。旧快照的对象指纹不匹配时标为 STALE 并保留旧结果，当前有效事实仍可重新分析；只有输入投影本身过期时输出 STALE_PROJECTION 排除原因。

一致性读取由 Ledger/TradeQueryService 拥有，在同一数据库读取快照中返回账户版本与 Trade 详情；该接口只表达账户、模式和投影，不导入 Journal 的计划或快照概念。Journal 负责显式计划关联、窗口、快照比对与世代游标，不能再并发读取版本与详情后假设两者一致。

计划关联保留原始 tradeId 和关联证明：直接 Trade 引用，或 JournalEntry 的明确 planId + 当前对象事件引用。多重计划或多重事件映射返回待确认；不按标的、时间或价格挑选。结构化 Journal 说明只包含当前对象事件或已选计划显式关联的记录，其正文及关联证明进入对象指纹；无关联记录保留在普通 Journal/legacy，不进入当前分析输入。

减仓片段可以继承已确认计划，但计划关联证明与正文分开保存：其他 SELL 的关联指针可证明计划归属，其正文不进入当前片段。当前片段只保留自身 SELL、已分配成本来源及开仓边界证明关联的说明，以及仅指向当前计划的共享说明。旧 SELL Journal 唯一映射时使用正式片段 ID；歧义保留全部可能引用，正文不附加到多个正式对象。无法确认模式的旧记录保留 accountMode=null，不从当前筛选模式推断历史事实。

## 确定性分析口径

分析使用已经验证的当前候选。原始 decimal 不变，结果以 DecimalValue 运算并按 HALF_UP 输出金额/价格 8 位、比率/天数 8 位小数；结果值与展示层格式分开。算法版本随口径固定保存。

- 已实现净收益和收益率直接使用统一投影，不重新计算成本或增加分红、未实现收益。ACTIVE 周期中已有减仓收益可展示，仍不进入完整周期统计。
- BUY 均价使用原始成交量加权；退出均价使用当前分析范围内的实际 SELL 量加权。Baseline 不充当 BUY，存在公司行动而价格单位无法确认时返回证据不足。片段退出价可以独立显示真实成交价。
- 持有天数只用真实 openedAt 与该对象统计时间；任一未知或时间顺序矛盾时，该指标返回证据不足，其他可计算指标继续返回。
- 计划值与实际值并列返回；计划缺失不导致已有实际收益失效。偏差行为输出发现偏差、未发现偏差、证据不足三态，不把低于止损退出直接断言为未执行已触发止损。
- 止损反事实只替换已发生 SELL 的退出价，使用实际减仓数量并保留投影原成本和费用。假设同价成交，不推断价格路径、触发时间、滑点或流动性。缺少退出、正止损价、统一币种或价格单位证明时不计算假设收益。

候选查询 C3.S2 是分析与快照的输入前置。控制器、API client 和 Desktop 的正式切换需等确定性分析及 Snapshot 读写契约就绪，作为同一消费阶段验证，避免界面再次转换为旧 number 主契约。

保存时使用 Serializable 事务读取投影、计划、Journal 与当前对象证据；Ledger 原子读取接受调用方的数据库事务上下文，仍由 Ledger 负责投影映射，不接收 Journal 契约。账户 state 的共享锁保护本次保存与投影写入的顺序。校验所选指纹后由服务端生成确定性结果并保存，序列化冲突返回刷新错误，不自动重试保存。历史详情保留原始输入和结果；当前指纹仅用于计算 STALE，不重跑旧算法。无法通过当前契约验证的旧快照返回明确兼容状态及原始数据，不伪造正式对象或金额。

周期统计分别返回符合资格的完整周期与减仓片段，不将两者相加形成胜率样本。窗口内不合格对象保留排除原因；无法确认统计时间的对象单列为时间未知样本，不冒充在窗口内。胜率按已知单对象收益正负计算；金额总和及盈亏比只在币种一致时计算，缺少跨币种转换证据时这些指标返回 FX_MISSING，但不清空可独立计算的样本数、胜率或持有时长。没有合格样本时比率不适用；没有亏损样本时盈亏比说明缺少亏损样本，不填零或 Infinity。

Sheet 只允许补充本次计划价、止损价、计划持有天数及说明，不覆盖成交价、数量、成本、收益或真实开仓时间。analysisDraft 与原始 TradePlan 并列保存；空值表示本次明确清除该计划参数，缺少键表示继续使用原始计划。对象 evidenceFingerprint 仍描述实际事实/原计划/Journal 依赖，草稿不写回事实源，也不使另一份历史结果因“用户当前输入不同”而 STALE。快照记录其原始草稿和输出，用户改草稿后须重新分析再保存。

## AI 解读的冻结提交与模块方向

JournalModule 单向依赖 AiModule。Journal 拥有对象范围、相关事实、计划/Journal 证明、草稿和确定性结果；AI 只接收通用的服务端冻结证据与 Prompt，不反向 import Journal。对象级事实选择复用 Journal 指纹的同一依赖范围，减仓解读不携带其他 SELL 正文或未来事实。

AI 复用已有持久化任务状态、领取 attempt、绝对期限、SDK 预算、审计 Tool call、Provider 配置冻结和进程恢复，不另建队列。Journal 在当前预期指纹下重新读取并计算权威结果后显式创建解读任务；模型选择仍由用户已配置的研究默认决定，缺少默认时拒绝提交。冻结证据与 Prompt 仅为服务端内部提交能力，通用 HTTP 输入不能设置这些元数据。执行器读取冻结输入，创建独立可追溯 Tool call，不再次查询当前组合或行情替换原证据。

客户端确定性结果与 AI mutation/轮询互不清空。AI 详情按任务内冻结的账户、模式、对象及指纹返回；任务失败只显示独立错误。显式保存可关联同一事实与草稿的任务编号及 Provider、模型、Prompt 版本，历史读取保留保存时的结果与元数据。数据结构仍使用现有 JSON 持久化字段，不新增 migration。

周期解读在周期确定性结果成功后独立触发。提交携带账户、模式、标的、显式窗口、预期 Ledger revision、投影世代、算法版本及每个入选或排除对象的指纹；服务端在一致读取后核对全部范围，计划或说明变化也必须阻断旧结果提交。冻结输入分别保留完整周期、减仓片段与时间未知对象，不创建第三种正式复盘对象，也不将两种粒度相加。周期解读只保存为独立 AI 任务，不冒充单对象 Snapshot。

实施按冻结提交、执行面、桌面消费/快照、目标验收拆分，先建立独立的显式提交到终态读取闭环，再验证 Provider 与故障恢复。边界门禁固化 AI 不得反向依赖 Journal。

## 验收边界

按契约、候选、分析、Snapshot、客户端消费逐段交付，所有原 AC 继续保留。单元/契约、隔离数据库、目标 HTTP、浏览器、真实 Provider 与设备分别记录；尚未完成的门禁不因局部测试通过而勾选。数据库结构如需变更，另按 migration matrix、runtime 输入和隔离/目标门禁实施，不修改历史 migration。
