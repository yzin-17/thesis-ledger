# 定期现金入账计划 Spec

- 日期：2026-08-30
- 状态：T1–T4 已实现并验证
- 适用项目：`thesis-ledger`
- 类型：增量设计
- 依赖：[`2026-08-30-cash-account-funding-and-transfer.md`](2026-08-30-cash-account-funding-and-transfer.md)

## 背景与问题

用户需要让工资等固定月度资金先进入独立现金账户。系统不能验证银行是否真实到账，因此到期不能直接改变 Ledger；它应生成可追踪的待确认实例，并在用户确认实际金额和日期后才形成外部入金事实。应用停机时不得丢失月份，通知失败也不得阻断待办生成。

## 目标

1. 支持一个现金账户拥有多个固定金额、固定日期的月度外部入金计划。
2. 到期生成待确认实例，支持确认、跳过和恢复。
3. 复用现有自动化框架补齐启用期间的全部漏期并保持幂等。
4. 提供应用内待办和外部通知，补期通知合并发送。

## 非目标

- 不自动写入 Ledger、不执行真实银行操作。
- 不支持工资比例、保留余额后转出、定期内部划转或工作日调整。
- 不支持影子账户、非现金账户计划、跨币种金额或每计划独立通知渠道。

## 现状与约束

- 当前自动化框架有 cron、时区、Redis 锁、重试和运行历史，但 Job 没有业务计划配置。
- 当前通知投递只关联 RiskEvent，需要扩展为通用通知 Outbox。
- 现金入账必须调用现金流专用命令，不能恢复已停用的通用 Ledger 写入口。

## 设计方案

### 计划与实例

计划保存现金账户、名称、预期金额、账户币种、每月日期、`Asia/Shanghai` 时区、开始月份、状态、下次到期时间和乐观版本。金额必须为正数；日期取 1–31，当月不存在时取月末；到期时间固定为当地 09:00。

实例按 `planId + periodKey(YYYY-MM)` 唯一。实例生成时冻结名称、预期金额、币种和计划日期，状态为 `PENDING`。确认允许修改实际金额和到账日期，并在同一事务中写入 `CASH_FLOW / INFLOW / DEPOSIT` 与 `CONFIRMED` 状态；跳过不写 Ledger；恢复只把 `SKIPPED` 变回 `PENDING`。

计划修改只影响尚未生成的月份。暂停或结束后不生成实例；暂停期间的月份不补齐。服务停机或 Scheduler 失败期间仍属于启用期，恢复后补齐全部漏期。

### 自动化与幂等

业务计划存放在专用表，现有 Automation 只新增一个固定的 `cash-deposit-materialization` Handler。Handler 扫描 `nextDueAt <= now` 的计划，逐月 upsert 实例并推进下次到期；数据库唯一约束和锁共同保证并发扫描不重复。

### 通知

通知模块提供通用 Outbox 接口，持久化 subject、消息快照、去重键和投递状态。RiskEvent 迁移为该接口的一个调用方。正常到期按计划通知；一次补齐多个历史月份时，每个计划只排队一条汇总通知。通知未配置或发送失败不回滚实例，只记录失败和重试状态。

## 对外行为或接口变化

- 提供计划列表、创建、修改、暂停、恢复和结束接口。
- 提供实例列表、确认、跳过和恢复接口；所有变更携带预期版本。
- Desktop 现金页显示待确认数量、逾期状态、计划列表和历史实例；计划操作放在上下文菜单中。

## 数据、状态或兼容性影响

- 新增 `RecurringCashDepositPlan` 和 `RecurringCashDepositOccurrence`。
- Notification Delivery 迁移为通用 subject/message Outbox；既有风险通知状态、去重键和重试次数必须保留。
- 新增固定 Automation Job 类型和 Handler，不创建第二套 Scheduler。

## 测试策略

- 纯函数测试覆盖月末、时区、启停区间和补期计算。
- 数据库/Server 测试覆盖唯一月份、并发扫描、重复确认、Ledger 原子提交和通知失败隔离。
- Notification 测试覆盖风险通知迁移、正常到期和补期汇总。
- Desktop 测试覆盖计划表单、待确认实例、确认时修改金额/日期、跳过恢复和错误态。

## 风险与备选方案

- 自动记账会在银行未到账时制造伪事实，故只生成待确认实例。
- 将每个业务计划直接做成 AutomationJob 会把账户和金额配置泄漏到通用调度层，故只使用一个扫描 Handler。

## 验收标准

- AC1：现金账户可以创建多个固定金额、固定月日的启用计划，非现金或影子账户被拒绝。
- AC2：到期只生成 `PENDING` 实例，不改变现金余额或 Ledger。
- AC3：确认实例使用实际金额和日期写入一次外部 `DEPOSIT`，重复确认不重复入账。
- AC4：跳过实例不写 Ledger，恢复后仍可确认；计划修改不改写已有实例。
- AC5：应用停机后补齐启用期间的全部漏期，重复或并发扫描不会产生重复月份。
- AC6：暂停期间不补期，结束计划后不再生成实例。
- AC7：正常到期发送应用内和外部通知；多期补齐只发送一条汇总通知，通知失败不影响实例。
- AC8：Desktop 可创建/管理计划并完成待确认、跳过和恢复流程。
