# 实时行情涨跌展示 Spec

> 任务标识：market-quote-change-display
> 日期：2026-09-18
> 状态：实现完成；Desktop 定向验证通过
> 对应任务：[实施任务](../tasks/2026-09-18-market-quote-change-display.md)

## 背景与问题

实时行情卡片当前展示实时价、涨跌前收和行情时点，但实时价未体现相对前收的涨跌方向，也没有直接展示涨跌幅。用户需要在扫描行情时立即识别当前价格方向和变化幅度。

## 目标

- 实时价按照相对涨跌前收的方向使用金融涨跌色。
- 新增“涨跌幅”指标，展示实时价相对涨跌前收的百分比变化。
- 沿用现有全局涨跌配色配置，默认红涨绿跌；不改变数据新鲜度和状态提示语义。

## 非目标

- 不新增 Server/API、Schema 或数据库字段；不修改行情计算和缓存行为。
- 不新增“涨跌额”指标，不改变“涨跌前收”和“行情时点”的展示语义。
- 不将陈旧、按上游间隔回退等数据状态直接当作涨跌颜色依据。

## 现状与约束

- `QuoteV1` 已提供 `price` 和 `previousClose`，可在 Desktop 展示层计算涨跌幅。
- Desktop 已有 `MarketTone`、`marketToneForValue` 和 `marketToneClass`，颜色必须继续跟随 `red-up` / `green-up` 配置。
- 当前行情卡片为三列布局；新增指标后在宽屏使用四列，窄屏继续按现有响应式规则纵向排列。

## 设计方案

### 涨跌方向与百分比

令：

```text
涨跌额 = 实时价 - 涨跌前收
涨跌幅 = 涨跌额 / 涨跌前收 × 100%
```

涨跌幅保留两位小数，正值带 `+` 号，负值带 `-` 号。实时价和涨跌幅使用同一个由涨跌额决定的金融涨跌色：上涨使用 `up`，下跌使用 `down`，持平使用中性色。

当涨跌前收缺失、非有限或小于等于 0 时，涨跌幅显示 `--`，实时价不着涨跌色；不使用无效除法结果。行情数据为陈旧或按上游刷新间隔回退时，仍按实际价格与前收计算颜色，数据状态由现有提示独立表达。

### 卡片布局

行情卡片依次展示：实时价、涨跌幅、涨跌前收、行情时点。实时价和涨跌幅显示方向色，涨跌前收和行情时点保持中性色。

## 对外行为或接口变化

无。仅改变 Desktop 行情详情的展示字段和颜色，不改变 API、Schema、持久化数据或跨端契约。

## 数据、状态或兼容性影响

无迁移、无缓存变化、无 Provider 变化。旧数据只要包含现有 `price` 与 `previousClose` 即可展示；涨跌前收无效时按上述 fail-closed 规则显示。

## 测试策略

### 关键可观察行为

- 上涨、下跌、持平时实时价和涨跌幅的颜色方向正确，并受全局配色方案影响。
- 涨跌幅公式、正负号、两位小数、无效前收占位正确。
- 行情卡片新增“涨跌幅”，宽屏使用四列，既有行情时点和陈旧提示不回归。

### 测试层级与证据边界

用 Desktop 行情详情定向组件测试覆盖展示和边界格式；包级 typecheck/build 只证明编译与静态集成，不替代真实运行态浏览器验收。由于本次不改变接口和运行时数据获取，不新增 Server、Docker 或 Provider 验收门禁。

## 风险与备选方案

- 用户可能切换为绿涨红跌；实现必须消费现有语义色，不得在组件中写死红色或绿色。
- `previousClose = 0` 时无法计算百分比；采用 `--` 和中性色，避免显示误导性的无限大或 NaN。

## 验收标准

- AC1：实时价按 `price - previousClose` 的方向使用现有金融涨跌色；默认红涨绿跌，切换全局配色后方向同步切换，持平为中性色。
- AC2：行情卡片新增“涨跌幅”，按 `(price - previousClose) / previousClose × 100%` 计算，保留两位小数并对正值显示 `+` 号；截图示例应为 `-0.44%`。
- AC3：缺失、非有限或非正涨跌前收时涨跌幅显示 `--`，实时价不着涨跌色；陈旧提示和行情时点语义保持不变。
- AC4：定向 Desktop 测试和受影响包 typecheck/build 通过；未执行的浏览器或更高层运行态验证不得被表述为已通过。
