# 投资组合每日摘要 Spec

- 状态：已批准，实施中（行情详情与窄屏视觉复核待完成）
- 类型：现有能力增强
- 对应任务：[`../tasks/2026-09-09-portfolio-daily-summary.md`](../tasks/2026-09-09-portfolio-daily-summary.md)

## 背景与问题

当前投资组合首页只展示总资产、持仓成本、累计浮盈亏和最大持仓，随后直接进入持仓表。页面能回答“现在持有什么”，但不能快速回答“今天表现如何”“哪些持仓贡献了变化”“当前仓位是否集中”。用户需要进入收益分析或逐个打开行情详情才能完成每日复盘，首屏信息密度不足。

## 目标

1. 在投资组合首屏直接展示今日持仓收益金额与收益率。
2. 补充累计收益率、现金构成、最大持仓权重等解释信息。
3. 在持仓表中同时展示现价、今日涨跌、今日收益、累计收益和仓位占比。
4. 保持投资组合页作为每日摘要，历史走势、时间加权收益率、资金加权收益率和目标配置继续由收益分析页负责。
5. 对昨收、行情或汇率不完整的情况显式展示不可用状态，不用零值代替未知值。
6. 将持仓行情详情收敛为紧凑、可持续浏览的弹窗，并把最近日线和技术指标从原始数值列表改为图表表达。

## 非目标

- 不在投资组合页复制完整的收益走势图、快照明细或目标配置编辑器。
- 不计算包含日内买卖、已实现盈亏和日内现金流归因的完整会计日收益。
- 不新增行情 Provider、快照任务或历史行情回填。
- 不改变账户、持仓、交易或收益分析的导航结构。
- 不在客户端补算服务端未返回的技术指标，也不以插值伪造缺失行情。

## 现状与约束

- 股票和 ETF 即时报价已经包含现价与昨收价；投资组合估值当前只保留现价。
- 场外基金使用最新净值估值，历史净值能力可以提供上一有效净值，但可能因数据不足而不可用。
- 投资组合可能包含多币种持仓，组合汇总金额必须继续遵循现有 FX 合并和部分可用语义。
- 当前 Portfolio API、共享 Schema 和 Desktop 适配层已形成稳定链路，新增字段必须保持旧调用方兼容。
- “今日持仓收益”按当前持仓数量和昨收价计算，是持仓价格变动摘要，不等同于包含日内交易和现金流归因的完整日收益。

## 设计方案

### 1. 今日持仓收益口径

单个持仓按以下口径计算：

```text
今日收益金额 = 当前持仓数量 ×（现价 - 昨收价）
今日收益率 = 现价 / 昨收价 - 1
```

股票和 ETF 使用 Quote 的 `previousClose`。场外基金使用最新净值之前的上一有效净值。找不到上一有效价格、当前行情不可用或 FX 无法完成组合汇总时，该持仓的今日收益为未知。

组合今日收益金额按现有基准币种和 FX 视图汇总。组合今日收益率以当前持仓对应的昨收市值为分母，不包含现金：

```text
组合今日收益率 = 组合今日收益金额 / 当前持仓昨收市值
```

该口径不会把当前现金余额直接算作收益，但日内持仓变化仍按当前数量估算。页面必须显示“按当前持仓与上一价格估算”，避免与完整会计日收益混淆。

### 2. Portfolio API 扩展

每个持仓增加可空的昨收价、今日收益金额、今日收益率和基准币种今日收益金额。组合响应增加 `dailyChange`：

- `pnl`：完整可计算时的组合今日收益金额，否则为 `null`；
- `returnRate`：完整可计算且昨收市值大于零时的组合今日收益率，否则为 `null`；
- `partial`：是否存在无法计算今日收益的持仓或汇率；
- `missingSymbols`：缺少昨收、当前行情或换算结果的标的；
- `basis`：固定为 `PREVIOUS_CLOSE_CURRENT_HOLDINGS`。

所有新增字段保持向后兼容。旧响应缺少这些字段时，Desktop 以未知状态展示，不推导伪造值。

### 3. 首屏指标层级

首屏保留四个并列指标，但改为：

1. 总资产：补充证券市值与现金构成；
2. 今日持仓收益：展示金额、收益率和估算口径；
3. 累计浮盈亏：补充相对持仓成本的累计收益率；
4. 最大持仓：补充市值和占总资产权重。

任何未知或部分可用状态使用破折号和直接原因说明，不使用 `0.00%` 掩盖缺失数据。

### 4. 持仓表信息结构

持仓表按市值排序，每行展示：

- 标的名称与代码；
- 持有数量与成本价；
- 现价与今日涨跌率；
- 市值与仓位占比；
- 今日收益金额；
- 累计收益金额与收益率；
- 行情状态与详情操作。

金额使用持仓原币种展示；仓位按当前组合基准币种总资产计算。窄屏继续由表格容器水平滚动，不压缩成不可读的多行卡片。

### 5. 持仓行情详情

行情详情使用与其他桌面详情一致的居中 Dialog。标题区和标准关闭按钮固定在滚动容器之外，正文单独滚动，避免用户浏览长内容后找不到关闭入口。头部指标改为紧凑信息组，区块之间使用连续的垂直节奏，不再用大面积空白分隔。

“最近日线”至少用收盘价折线图表达时间趋势，并保留时间范围、最新值和涨跌方向的文本摘要；“技术指标”根据服务端返回结构选择折线图或带零轴的数据条展示。图表必须有可访问名称和文字摘要，缺失数据继续显示明确空态，不从原始行情自行推导指标。

## 对外行为或接口变化

- `GET /portfolio/valuation` 响应增加持仓级每日变化字段和组合级 `dailyChange`。
- Desktop 投资组合首屏与持仓表消费新增字段。
- 现有请求参数、路由、实际/模拟模式和刷新行为保持不变。

## 数据、状态或兼容性影响

- 不新增数据库表或持久化字段；每日变化随当前估值即时计算。
- 场外基金上一有效净值查询失败只影响每日变化，不影响最新净值估值和累计浮盈亏。
- 任一持仓每日变化缺失时，组合每日变化标记为部分可用并隐藏汇总金额与收益率；其他组合指标继续展示。
- 新 Schema 字段为可选或可空，保持对旧 Server 响应的兼容。

## 测试策略

### 关键可观察行为

- 有完整昨收时，组合和持仓正确展示今日收益金额与收益率。
- 昨收缺失、行情缺失或 FX 阻断时，今日收益显示未知原因而不是零。
- 累计收益率、现金构成和最大持仓权重与当前估值一致。
- 持仓表头与每行单元格数量保持一致。

### 优先测试层级

1. Server Portfolio Service 的计算与部分可用边界测试。
2. Schema 和 Desktop 适配层的兼容性测试。
3. Desktop 静态 UI contract 与类型检查。
4. 真实本地页面的宽屏、窄屏、浅色和深色视觉验收。

### 可复用的现有测试入口

- `apps/server/test/portfolio/services.test.ts`
- `packages/schemas/test/api-contracts.test.ts`
- `apps/desktop/test/portfolio-table.test.tsx`
- Desktop `typecheck` 与 `build`

### 需要新增的测试入口

- Portfolio API 适配层对新增每日变化字段的映射测试。

### 关键边界与回归场景

- 昨收价为零；
- 场外基金历史净值不足；
- 一个持仓行情缺失但其他持仓可用；
- 多币种换算缺失；
- 组合只有现金或总成本为零；
- 旧 Server 不返回新增字段。

## 风险与备选方案

- 当前持仓昨收法不能精确归因日内交易。备选方案是后续基于日初持仓、成交和现金流建立完整日收益读模型；本次以明确口径的每日持仓摘要满足首页复盘需要。
- 场外基金历史净值查询会增加读取成本。它只读取最近两个点并沿用现有缓存；失败时降级为每日变化不可用。
- 持仓表字段增加可能造成窄屏拥挤。沿用水平滚动并合并相关数值为主值与说明值，避免新增页面级样式。

## 验收标准

- AC1：完整行情下，投资组合首屏显示按当前持仓与昨收计算的今日收益金额和收益率，并明确估算口径。
- AC2：持仓表逐行展示现价、今日涨跌、今日收益、累计收益和仓位占比，表头与数据列保持一致。
- AC3：总资产展示证券与现金构成，累计浮盈亏展示收益率，最大持仓展示权重。
- AC4：昨收、行情或 FX 不完整时，组合每日收益显示未知及原因，不用零值代替未知值，其他可用指标不受影响。
- AC5：Portfolio API、共享 Schema 与 Desktop 适配层字段语义一致，并兼容缺少新增字段的旧响应。
- AC6：目标测试、类型检查、构建和本地页面宽窄屏及双主题验收通过，或明确记录与本次修改无关的外部阻塞。
- AC7：持仓行情详情使用居中 Dialog，标准关闭按钮位置固定，正文滚动不带走标题和关闭入口。
- AC8：最近日线以价格趋势图展示；技术指标按时序或标量结构显示为趋势图或数据条，并保留可访问文本摘要。
- AC9：详情首屏信息密度提高，区块间距连续且紧凑；宽屏、窄屏和双主题下均不出现页面级溢出。
