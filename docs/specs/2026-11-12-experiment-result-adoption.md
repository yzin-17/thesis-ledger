# 实验期末持仓、可比结果与候选采纳

## 目标与范围

用户确认保留日线信号在下一交易日开盘执行；期末保留持仓并按市值计入收益；修复不同预热窗口造成的封存比较误判和测试结果被占位零覆盖；实验完成后每个已完成评估的合法候选均可由用户采纳为正式策略。

实际样本为实验 `71bbc0a2-89ae-48eb-938f-0b7e534aecb2`。只读诊断确认两个候选与基线的执行期数据一致，差异仅为 `instrumentFacts` 内嵌历史可交易证据的预热范围。候选 1 的测试实际有三笔平仓，旧汇总误写为零；候选 2 有期末持仓，行情完整，但无平仓导致交易指标不可用。

## 行为合同

- 不扩大日期窗口、不追加行情、不在期末强制成交。最后有效时点保留现金、持仓和未实现盈亏；最后时点产生但无法在窗口内执行的信号按“回测窗口结束，待下一交易日执行”展示，不表示市场拒单或数据缺失。窗口内真正过期和缺失行情仍保留原错误。
- 无平仓时交易数为零，胜率和盈亏比按各自原因不可用；不因此降低完整行情及整个结果的完整性。收益、回撤继续来自实际估值。
- 可比指纹只投影实际比较区间的嵌套交易日状态和日历，不改冻结产物；区间内状态、来源、身份、价格与父引用差异继续使指纹不同。
- 评分资格与保存策略分离。实验完成且结果已揭示时，评估终态候选 `valid/invalid/test_valid/test_invalid` 均可采纳；结构、来源、哈希、当前正式版本、幂等、重复采纳和已有测试暴露确认保持。排队、生成、评估、测试中及未完成实验不能采纳。
- 评价失败不覆盖实际收益、回撤和交易数；真实一致性冲突仍保留失败原因并不参与评分。读取已有结果时可由绑定的成功冻结 Run 补充实际指标，保留原评价状态与原因，不重写历史记录，不将补充指标冒充重新通过的评价。
- Desktop 两个消费入口和 Mobile 使用同一采纳规则，直接展示测试收益、平仓数与具体评价说明；不新增审批步骤。
- 从零实验首次采纳发布正式 v1；之后采纳其他候选时，在原策略下发布后续正式版本，并按实际当前版本进行并发确认。每个候选只采纳一次，已采纳版本保持可追溯，不因先采纳一个候选而永久阻断其他候选。
- 采纳审阅中的新增或删除字段允许 JSON 差异只携带实际存在的一侧，双侧均缺失仍为无效差异；页面不得因此把成功返回的上下文显示为读取失败。
- Desktop 点击“审阅并采纳”后打开独立弹窗，加载、失败重试与差异均在弹窗内呈现；长内容内部滚动，底部确认、取消按钮保持可见。取消或 Esc 关闭后返回原操作按钮，提交期间阻止关闭和重复提交。
- 正式 V2、V3 策略结构均支持采纳响应中的风险计划编译；提交后响应异常时，界面重新读取采纳事实再确认结果，详见[采纳响应规格](2026-11-12-experiment-adoption-response.md)。

## 验收标准

- AC1：期末不读取区间外行情、不制造平仓；收益含期末市值，边界未执行原因独立，无平仓不导致数据不完整。
- AC2：同父窗不同预热证据得到相同执行期指纹；实际执行期或来源差异仍拒绝相等。
- AC3：真实指标在有效与无效评价中均保持；旧占位汇总可只读补充且受揭示门禁和 Run 绑定保护。
- AC4：完成候选均可在 Server 两层校验和两端入口中采纳；不削弱策略定义、幂等及并发版本校验。
- AC5：定向、包级与门禁通过；四宽浏览器验证和本地正式快更后，原实验两个候选有采纳入口、测试数据正确；仅打开审阅并取消，真实业务数据不变，无新增模型调用。
- AC6：采纳审阅弹窗在 1440、1024、768、390 宽度内无横向溢出；取消、Esc、焦点返回、读取失败重试和提交等待期间的关闭保护通过浏览器验证。

## 边界

不修订历史冻结回测、实验评价或策略；不启动模型、不真实采纳、不提交或推送。隔离样本允许验证正式采纳事务。本次实施已完成，范围与结果见[归档任务](../archive/tasks/2026-11-12-experiment-result-adoption.md)、[验收记录](../archive/evidence/2026-11-12-experiment-result-adoption.md)及[采纳弹窗验收](../archive/evidence/2026-11-12-experiment-adoption-dialog.md)。本规格保留为当前合同，无未决产品问题。
