# 持仓表账户列的可读性与密度

## 问题与范围

实施前的公共导航验收发现，组合概览的普通中文账户名在窄屏持仓表内逐字折行，显著抬高行高。共享 TableContainer 已正确提供容器滚动；当前持仓是唯一显式允许账户列无限压缩换行的表格。交易周期的账户列保留不换行合同，其他账户入口是选择器或表单，不扩大修改范围。

## 验收标准

- AC1：通过现有原子类为持仓账户列提供 8rem 最小宽度；普通账户名一行可读，长中文、连续英文及未知账户的具体回退完整保留，不裁切文本、改名或修改业务结果。
- AC2：当前持仓只有一个行情详情按钮，固定操作列使用现有共享组件的 className 组合适配该控件；表头、单元格宽度一致，滚动后按钮仍可操作。不改变其他表格的操作列。
- AC3：文档不横向溢出，宽表在原 TableContainer 内滚动；排序、无持仓、刷新保留旧值及详情打开/关闭保持。实际浏览器覆盖 1440、1024、768、390 和上述账户情况，分别记录基线与当前。
- AC4：先定向、再完整 Desktop、构建及门禁；最终输入和其他包复用范围清楚，证据与文档一致后归档，继续全线程 Goal。

## 所有权与实现约束

账户列的阅读宽度和单按钮操作列由 PortfolioPositionTable 组合现有原子类表达；继续复用共享容器与 StickyTableActions。保留 DOM、数据、名称回退、请求、排序、刷新和原始精度，不新增传统 CSS、重要性覆盖、渲染分支或依赖。

上一轮生产资源保存在 `/tmp/goal-portfolio-account-column-before-dist`。共享表格、全部 PortfolioPositionTable 消费和独立交易账户列先检查；Mobile 列表与单账户页面没有该列压缩合同，保留现状。所有业务响应均为隔离数据，详情的来源失败仅用于检查打开/关闭，不代表来源验收。实施见[任务](../archive/tasks/2026-11-07-portfolio-account-column.md)。
