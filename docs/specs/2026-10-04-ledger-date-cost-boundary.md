# Ledger 日期精度成交的成本策略边界修复

- 日期：2026-10-04
- 状态：修复及验收完成；保留当前成本策略时间比较契约
- 类型：基金定投运行时验收发现的必要修复
- 原任务：[基金定投 T2.R1](../archive/tasks/2026-09-08-recurring-fund-investment.md)

## 问题与目标

真实 PostgreSQL 下，首次确认基金定投返回 500。Ledger 为账户自动创建初始成本策略，`effectiveAt` 读回为完整时间戳；日期精度买入的开仓边界为 `YYYY-MM-DD`。Domain 使用字符串比较，把同日零点的策略误判为晚于开仓，抛出 `TRADE_COST_STRATEGY_REQUIRED` 并回滚确认。

目标：按实际时间顺序选择开仓时已生效的成本策略，使首次日期精度成交完成确认，且不允许未来策略生效。保留既有开仓边界、成本算法和事实精度。

## 方案与边界

成本策略排序及生效边界比较使用已受契约约束的日期/时间戳解析结果。日期精度沿用 Ledger 持久化的 UTC 零点表示；不推导盘中成交时间，不改变 Schema、迁移、公共接口或依赖方向。时间相同仍以策略 ID 保持稳定排序。

本修复只改变策略时间比较；基金调度、账户限制、资金或份额计算继续由现有领域模块负责。

## 验证与验收

- AC1：`YYYY-MM-DD` 买入可选中同日 `T00:00:00.000Z` 初始策略，完整时间戳的等时比较结果一致。
- AC2：晚于开仓的策略不能生效；带不同 UTC offset 的策略按实际时间排序。
- AC3：原成本与收益守恒、既有开仓周期策略固定及 Ledger 回归通过。
- AC4：基金定投生产 HTTP 在真实隔离 PostgreSQL 下确认、重复确认、并发确认和竞争回滚通过。
