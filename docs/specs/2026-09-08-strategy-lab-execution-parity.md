# 策略实验执行一致性与体验完善规格

## 背景

策略实验页面已经具备策略配置、版本创建、回测任务和结果查看能力，但部分配置没有进入实际执行链路，部分选项只有界面或 Schema 定义而没有引擎语义。高级 JSON 编辑、历史版本选择、时间范围和结果反馈也存在易误用或信息不足的问题。

本次改动以“用户配置的内容必须可解释、可执行、可复现”为目标，统一 Desktop、Server 与 Domain 的语义，并完善实验闭环。

## 范围

### 包含

- 修正基准、数据截止时间、止盈止损和仓位配置与回测引擎之间的不一致。
- 实现 `trailing` 止损、`atr` 止损、`trailing` 止盈和真实的 `risk` 仓位计算。
- 防止高级 JSON 草稿在切换视图或保存时静默丢失。
- 支持查看并选择历史策略版本发起回测。
- 优化百分比、金额和 ATR 倍数等单位表达，移除具有误导性的默认策略内容。
- 提供动态回测区间、常用时间预设和更完整的结果反馈。
- 修正已发现的可访问性、空状态、状态文案和窄屏布局问题。

### 不包含

- 多标的组合回测。
- 策略版本差异对比、版本删除或版本回滚。
- 新增实时行情源或回测任务调度系统。
- 修改交易日历、撮合时点或 T+1 的既有定义。

## 领域语义

### 数据与基准

- `universe.asOf` 是本次实验的数据可用截止时间，创建任务时写入 `dataAsOf`，不得用任务创建时刻替代。
- Desktop 按用户选择的回测区间请求主标的和基准日线；Server 在回测输入边界将 Market Bar 的 `timestamp` 规范化为 Domain `BacktestBar.date`，不得因字段名不一致静默产生空回测。
- 主标的行情仍是回测成功的必要条件。
- 配置基准时必须获取并传递基准行情；若基准行情不可用，策略回测继续执行，并在结果警告中明确说明基准比较缺失。
- 基准与主标的相同时复用同一份行情数据。

### 止损与止盈

- `stopLoss.fixed.value`：相对持仓成本的固定跌幅，Schema 中保存小数比例。
- `stopLoss.trailing.value`：相对持仓期间最高决策价格的回撤比例；每个交易日先更新最高价，再判断是否触发。
- `stopLoss.atr.value`：ATR 倍数。ATR 使用 14 个周期的 True Range；样本不足时不触发 ATR 止损，并输出可解释警告。
- `takeProfit.fixed.value`：相对持仓成本的固定涨幅。
- `takeProfit.trailing.value`：相对持仓期间最高决策价格的回撤比例，仅在最高价高于持仓成本后生效，避免将普通亏损误判为止盈。
- 同一决策点同时满足多个退出条件时，保持确定且有测试覆盖的退出优先级，并记录具体退出原因。

### 仓位

- `sizing.fixed.value` 保持既有引擎语义，表示固定投入金额；界面不得再标为固定数量。
- `sizing.weight.value` 表示可用现金比例，Schema 中保存小数比例。
- `sizing.risk.value` 表示单笔允许承担的资产风险比例，Schema 中保存小数比例。
- `risk` 仓位按“风险预算 ÷ 每股止损距离”计算，并继续受现金、交易单位和 `riskConstraints` 限制。
- 当 `risk` 仓位缺少可计算的止损距离时，不得退化为现金比例；订单应被拒绝并返回明确原因。

## 交互要求

### 编辑器

- 高级 JSON 有未应用修改时，切换到常用配置必须先校验并应用；JSON 无效时留在高级视图并显示错误。
- 在高级视图直接创建版本时，必须以当前 JSON 文本为准，不能保存旧 `draft`。
- 比例字段以百分比展示和输入，内部仍保存小数；金额、百分比、ATR 倍数均显示明确单位和合理范围提示。
- `stopLoss`、`takeProfit` 和 `sizing` 根据类型显示对应语义字段。
- 新建策略不再预填具体股票和任意价格阈值；必填项缺失时给出可操作的校验提示。
- 成本参数默认收起，保留当前值和原子类样式体系。

### 版本与任务

- 策略列表默认选中最新版本，并允许用户选择历史版本查看、编辑为新版本或发起回测。
- 回测日期默认使用截至今天的最近一年，并提供常用时间范围预设。
- Desktop 日线请求必须携带所选起止日期和覆盖一年区间所需的数量上限；Server、DSA facade 与 Provider runtime 必须逐层透传 `start`、`end`、`limit`，不得先按默认最近 90 根抓取后再做区间过滤。
- Desktop 向 Queue 提交行情时只保留回测引擎需要的日期、OHLCV 与可选交易语义字段，不重复上传 Provider、缓存和新鲜度元数据，确保一年期主标的与基准载荷不超过服务端请求体上限。
- 回测任务空状态提供返回策略库或创建策略的操作。
- 已结束任务不显示没有意义的 100% 进度条；未知服务端状态显示原始状态值。

### 结果

- 结果标题包含策略名称和版本，说明包含标的与回测区间。
- 展示权益曲线、回撤，以及基准可用时的基准比较。
- 展示现有返回数据中可获得的费用、换手、拒单、数据完整性和警告；没有数据时明确标为不可用，不伪造数值。
- 图表必须具有文本摘要或可访问标签，不仅依赖颜色传递信息。
- 结果内容滚动时，标题区与右上角关闭按钮保持可见。

## 验收标准

- **AC-01**：任务使用所选策略版本的 `universe.asOf` 作为 `dataAsOf`；Desktop 按所选区间请求最多 365 根日线并压缩 Queue 行情载荷，Server、DSA facade 与 Provider runtime 逐层透传 `start`、`end`、`limit`，Server 将 Bar 的 `timestamp` 规范化为 Domain 的 `date`；基准行情能从 Desktop 进入 Server 并传给 Domain，基准缺失时主回测仍完成并给出警告。
- **AC-02**：`fixed`、`trailing`、`atr` 三种止损均有确定语义和 Domain 级失败先行测试。
- **AC-03**：`fixed`、`trailing` 两种止盈均有确定语义和 Domain 级失败先行测试。
- **AC-04**：`fixed` 标示为固定投入金额；`weight` 与 `risk` 的行为不同，`risk` 按止损距离计算且缺少止损时明确拒单。
- **AC-05**：高级 JSON 在切换和创建版本时不会静默丢失；无效 JSON 不得覆盖有效草稿。
- **AC-06**：用户可选择任意历史版本并基于该版本编辑或发起回测，默认仍为最新版本。
- **AC-07**：比例、金额和 ATR 倍数的显示与存储单位一致，新建策略没有具体证券或任意阈值的伪默认值。
- **AC-08**：回测日期默认滚动到最近一年，并提供至少三个常用区间预设。
- **AC-09**：结果页显示可访问的权益与回撤可视化、策略名称、版本、区间和可获得的诊断指标；正文滚动时标题区与关闭按钮固定可见。
- **AC-10**：T+1 控件有可访问名称，Sheet 关闭文案为中文，空状态可继续操作，终态任务不展示进度条，未知状态保留原始值，1024px 宽度下页头不发生破坏性挤压。
- **AC-11**：Domain、Server、Desktop 的相关测试、类型检查和边界检查通过。
- **AC-12**：使用本地页面完成新建/编辑、历史版本选择、JSON 防丢失、任务配置和结果展示的浏览器验证；若测试数据不足，记录静态证据与无法验证的运行时边界。
- **AC-13**：配置通过同步的日期、资金、Schema 和主标的校验并启动 Desktop 后台准备后，开始回测弹窗立即关闭并切换到“回测任务”；主行情、基准行情、入队和启动均在后台继续，不阻塞策略页面。准备/入队/启动成功或失败均通过 Toast 和任务查询刷新反馈；客户端启动请求失败时，已入队任务保持可重试状态。

## 测试边界

- Domain：以公开的 `runBacktest` 输入输出验证交易语义，不直接测试私有 helper。
- Server：以 `BacktestService.queue/run` 验证任务持久化和 worker 输入。
- Desktop：以用户可见行为验证策略编辑、版本选择、回测配置和结果展示。
- 浏览器：验证关键路径、窄屏布局、控制台错误和可访问名称。

## 约束与兼容性

- 保持现有策略 Schema 字段名和已存版本可解析；通过界面文案和引擎实现修正语义，不执行数据迁移。
- 不新增无明确所有权的共享目录，不改变既有模块依赖方向。
- 视觉调整使用现有原子类与组件；数据图形可使用局部、可访问的原生 SVG，不为此引入新的图表运行时依赖。
- `StrategyEditorSheet.tsx` 已超过文件尺寸阈值，本次不得继续堆叠无关职责；新增转换、展示或计算逻辑应提取为有明确职责的模块或组件。

## 假设与决策

- ATR 周期固定为 14，本次不扩展 Schema 增加周期字段。
- `trailing` 止盈只在持仓曾经盈利后激活。
- 历史版本选择不包含版本差异对比。
- 主行情为空仍按既有行为阻止发起回测；基准行情为空仅降级比较能力。

## 回测任务启动边界

- “同步配置校验通过并已启动 Desktop 后台准备”是开始回测弹窗关闭和页面切换的边界；日期、资金、Schema 或主标的校验失败仍留在当前弹窗并显示错误。
- 主行情准备、基准行情准备、入队和启动请求均属于 Desktop 会话内的后台 pipeline，不作为弹窗关闭的前置条件。
- 后台 pipeline 的每个结果通过成功或失败 Toast，并刷新策略与任务查询；已有的任务状态轮询继续负责持久化任务的后续运行状态。
- Desktop 关闭或重载期间不保证尚未入队的会话内准备继续；一旦任务已持久化为 `queued`，任务列表继续提供现有“重试运行”入口。
- 本次不新增调度器、客户端队列或 Server API；不把 Server 生命周期可靠性当作本任务已验证事实。

## 未决问题

### Blocking

无。

### Non-blocking

- 尚未入队的行情准备属于 Desktop 会话内后台操作，关闭或重载应用不保证继续；任务一旦持久化，既有任务查询和重试入口负责后续处理。
