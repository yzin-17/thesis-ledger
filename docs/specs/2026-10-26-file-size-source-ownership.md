# 文件尺寸门禁源码归属规格

> 任务标识：`file-size-source-ownership`
> 对应任务：[已完成实施任务](../archive/tasks/2026-10-26-file-size-source-ownership.md)

## 背景与目标

Cloudflare 目录修复的仓库验证发现，文件尺寸门禁递归扫描了两个未跟踪且已被现有 `.gitignore` 覆盖的移动端验收快照；快照中的旧测试副本被误判为新增超长源码。同时，真实 `ai-provider-ui.test.tsx` 的既有 WIP 为 887 行，高于 HEAD 的 865 行，必须按职责收敛。

本规格只修复门禁输入归属并拆分该测试现有职责。保持原尺寸阈值、有效 Git 基线及超长文件不得增长的规则；不增加 ignore，不更改或移动验收快照，不 stage 或 commit，不修改产品组件、数据或配置。

## 设计与验收断言

- AC1：尺寸门禁复用现有 `gitLintCandidates` 的 Git 已跟踪文件与未忽略 WIP 并集。保留原缓存目录排除，忽略已删除文件及同名目录；Git 清单不可用或路径越界必须失败。
- AC2：已跟踪但被 ignore 覆盖的文件仍纳入门禁；未跟踪的验收产物保留原位、不进入源码输入。阈值和 ratchet 比较语义不变。
- AC3：将 Provider 测试现有“专用请求与密钥边界”和“页面操作”分为独立测试文件，提取已有公共记录夹具。全部测试标题、断言与既有 WIP 行为保持；不得仅压缩格式或删除用例以满足门禁。
- AC4：输入归属单元测试、拆分后的全部原测试、Desktop 类型检查及使用 `GUARDRAIL_BASE_REF=HEAD` 的实际文件尺寸门禁通过；验收包保持字节一致。

风险在于误排真实源码或丢失既有测试。使用已跟踪 ignore 路径、未提交源码、中文路径、Git 不可用等固定场景验证清单，并核对拆分前后的测试集合及目标验收快照哈希。该规格不放宽任何产品验证要求。
