# 自主交易竞技场的条件委托与成交保护

本规格用于竞技场模拟交易。模型一次提交入场与退出的结构化计划，执行引擎根据已发生的成交更新委托，研究人员可从同一份配置逐项核对中文交易说明。复用策略定义中的规则含义时，竞技场仍须提供自己的决策合同、订单状态和撮合行为。[策略规则能力清单](2026-11-13-strategy-rule-capabilities.md) · [实施任务](../tasks/2026-11-13-arena-contingent-orders.md)

## 1. 两条真实决策

| 研究周期 | 模型表达的意图 | 原始配置与运行结果 |
| --- | --- | --- |
| AAPL.US，2026-11-13，周期 `8241f49e-6d27-4f2b-a9c9-62272082bf1e` | 摘要称买入时附带止损。买入上限 359.50 美元，27 股，保护性卖出触发价 355 美元。 | 冻结账户空仓。限价买单与止损卖单共用 `exitGroup: "AAPL-01"`。首个错误位于 `decision.orders[0].exitGroup`，整轮 `model_output_invalid`。实际预约为次日 14:35 UTC 及 AAPL 价格 ≤ 357 美元，未预约成交。本轮没有产生挂单或成交。 |
| TOPT.US，周期 `f849609b-8fd5-4e53-b805-03bac10c8d65` | 摘要称以 34 美元限价买 300 股，设置 32.50 美元止损，并在收盘前复核。 | `orders` 只有限价买单。`wakeups` 有价格 ≤ 32.50 美元和时间两项。该轮因 `decision.orders[0].expiresOn` 填入时间戳而被拒。即使单独修好日期，原配置也只会在触价时安排研究，没有自动卖出的指令。 |

样本来自本地开发库 2026-11-13 核查时的 22 个竞技场研究周期。结合已保存决策和请求审计可读取 12 份带订单数组的决策，其中 2 份有委托，即上表两份。下面其余场景是设计样例。两个样本分别说明同一种意图可能生成非法分组，或只留在文字和研究预约里。此前针对 AAPL 的提示与错误展示修复见[原规格](2026-11-13-arena-invalid-output-timezone.md)。

用 AAPL 原始响应、冻结账户和运行中的 Schema、领域提交函数做三组内存对照。成交价来源及交易单位采用受控样例，两组删字段对照均未写库或撮合。

| 输入变化 | Schema | 领域提交 |
| --- | --- | --- |
| 原样保留两项 `exitGroup` | 在买单的分组字段被拒 | 未进入 |
| 两项 `exitGroup` 均设为 `null` | 通过 | 空仓的独立卖单触发 `insufficient_position`，整份决策未提交 |
| 两项去分组后仅保留买单 | 通过 | 生成一张 `active` 买单，账户仍未获得退出保护 |

## 2. 现有协议能表达哪些规则

| 规则 | 当前竞技场 v2 | 需要写进合同的能力 |
| --- | --- | --- |
| 持有足够可卖股份时提交固定数量的卖单；现金足够时挂限价买单 | 已有。每一笔提交即激活，并受各自的资金、持仓和市场条件约束 | 继续支持独立委托 |
| 已持仓，同数量止盈与止损择一成交（OCO） | 已有。`exitGroup` 仅允许同标的、同数量的两条卖出止盈／止损腿，份额预留一次，一腿整笔成交后取消另一腿 | 保留现有语义，并可作为附属退出组合复用 |
| 空仓挂买，成交后激活一笔保护单（OTO） | 缺少。成交预约按标的唤醒模型研究，不能指向某一父单并自动下卖单 | 父单身份、明确的成交触发、等待激活的子单、绑定本计划数量 |
| 买入后同时挂止盈和止损（Bracket / OTOCO） | 退出 OCO 已有，入场到退出组合的关系缺失 | 父单触发一组退出，两腿共享同一批可退出股份 |
| 部分成交立即保护；撤销未成交余量后保留保护 | 撮合按整笔数量成交，订单类型没有部分成交及剩余数量 | 逐笔成交、累计量、未退出量、部分成交后撤余和幂等更新 |
| 跌到阈值自动卖出 / 跌到阈值请模型再看 | 两种行为各自有固定止损单和价格预约。后者仅调度研究 | 中文确认明确执行动作；模型可在同一决策中分别选择自动执行和研究预约 |
| 从持仓后最高价回撤 3% 止损；达到指定收益后移至保本 | 当前为固定价；重新研究后可撤现单再提交新单 | 基准价来源、采价时点、单向更新、激活阈值与持久化状态 |
| 按不同价位分三笔建仓；仅当前一笔成交后才挂下一笔 | 钱足够时可平行挂多笔固定买单。先后依赖、前序未成交时不占用后一笔委托、各批次独立保护缺少结构 | 建仓批次身份、前置成交、批次预算和保护归属、终止条件 |
| 分批止盈，余仓继续受同一止损保护 | 可在已有可卖仓位内挂独立固定卖单；卖出全仓的共同止损与若干分批止盈不能用一个现有 OCO 正确表达 | 退出份额、共享预留、止盈成交后等量缩减止损，剩余数量归属和取整 |
| 挂单到期、修改保护、终止计划 | 可指定日期或取消指定活跃订单再提交；旧止损委托 `expiresOn: null` 在实时路径按当前交易日计算 | 父子期限独立，区分撤入场余量、撤单腿、取消整份计划；跨日保护须有明确期限 |
| 报价穿越时只入场一次，直至信号复位才能再次建仓 | 单笔限价单成交后结束；多个研究周期可再次提出同方向委托 | “本次入场保护”的归属与“何时允许策略再次入场”分别建模；持续信号的触发、复位与重复交易规则见[策略规则能力清单](2026-11-13-strategy-rule-capabilities.md) |

术语参照 [Alpaca 订单文档](https://docs.alpaca.markets/us/docs/orders-at-alpaca)。OTO 可只附一条退出腿。Bracket 可在入场整笔成交后激活两条互斥退出腿。竞技场若支持每次部分成交即追加保护，需要在自身合同中明确该策略。

## 3. 模型直接生成的配置

以下为新增订单项的提案示例，展示现有整笔成交撮合可先实现的 AAPL 路径。外层决策继续承载研究预约等字段。示例的子单有效至激活交易日收盘，是对本样本实时路径到期规则的显式表达；若模型要持仓跨夜，需明确不同的保护期限。具体字段名在协议定版时统一。

```json
{
  "clientId": "AAPL-BUY-01",
  "symbol": "AAPL.US",
  "side": "buy",
  "kind": "limit",
  "quantity": "27",
  "price": "359.50",
  "expiresOn": "2026-11-13",
  "exitGroup": null,
  "onFill": {
    "activation": "on_full_fill",
    "activateOrders": [
      {
        "clientId": "AAPL-SL-01",
        "side": "sell",
        "kind": "stop_loss",
        "price": "355.00",
        "quantity": { "basis": "parent_open_quantity" },
        "reduceOnly": true,
        "validUntil": { "kind": "activation_session_close" }
      }
    ]
  }
}
```

子单继承父单标的，绑定本计划仍持有的数量。单条退出腿无需 `exitGroup`。两条互斥退出腿需要明确的组关系。支持部分成交的版本增加 `on_each_fill`，模型显式选择“全部成交才保护”或“每次成交即按量保护”。提交时应能直接看见当前竞技场支持的选项；新能力须随实际执行能力一起开放。

**这份配置的人工确认文字**可显示为「今日以不高于 359.50 美元的限价买入 27 股 AAPL。27 股全部成交后，自动为这批仍持有的股票设置 355 美元触发的止损卖单，保护至激活当日收盘。买单未成交就撤销或到期时，不会挂卖单。」若选择 `on_each_fill`，第二句显示为「每次买入成交后，立即把本批新增且未退出的股数计入止损保护」。价格研究预约应另列为「到 357 美元或以下重新研究」。止损触发价、提交状态和实际成交价分别展示。

中文说明读取有执行效力的配置，供人核对标的、方向、价量、激活条件、期限和撤单后果。模型摘要单列供对照。例如 TOPT 可同时显示「模型写了 32.50 美元止损」与「配置仅预约到价研究，自动卖出委托 0 张」。无需用自然语言解析去补单。结构校验保留给引用、价量、账户权限等执行不变量；模型若选了错误但合法的规则，仍须依靠配置回读与实际事件序列发现。

## 4. 成交、激活、撤单的执行合同

1. 模型提交成功时，父单及待激活子单一并持久化。未成交阶段仅父单按现有规则占用资金。等待中的保护单可查询，不能撮合，也不能占用账户既有同标的股票。
2. 父单符合激活条件时，在同一账户事务中登记成交、入账、计算计划可保护量并建立或增量更新子单。提交后即能看到已接受的保护。匹配卖单仍需可卖股份、有效交易时段和因果顺序明确的新执行行情。遇交收限制展示等待可卖及数量；遇无有效报价展示当前撮合条件。跌穿 355 美元时记录实际可执行价格。
3. 数量基准为本计划累计入场成交量减去已归属本计划的累计退出量。独立退出腿分别预留，同一份额的 OCO 两腿只预留一次。已有仓位、其他计划、人工减仓和同轮其他委托，都不能使可累计卖出数超过本计划实际买入量或账户可卖量。允许外部减仓时，必须明确定义并落账份额归属，同时重算余下保护。
4. 父单零成交后被撤、到期或拒绝，未激活子单随之结束。若已部分成交再撤余或到期，继续保护已买且未退出部分。计划终止、单独撤保护与撤父单余量是三种操作，分别显示对余仓的影响。多批或可部分成交的计划还需明示“保护单先退出后，是否撤掉未成交入场余量”，防止后续成交意外重新开仓。
5. 以持久化父单／计划身份绑定，不能只凭代码、价格或下一次该标的成交。重复处理同一成交只生效一次。并发撤单和成交按同一账户的提交顺序结算；故障恢复从已记账数量重建，可重试且不重复卖出。
6. 在线与历史回放采用同一领域规则。激活动作进入父单成交的事务。撮合使用成交之后的有效市场证据，同一条只有单价或同根只有 OHLC 的观测不足以推断先买后卖。研究暂停或预算耗尽与比赛撮合状态分别展示；只要比赛撮合允许，已有保护的激活不消耗模型调用。比赛暂停依照现有比赛时钟处理。
7. 旧账户、历史决策和回放以各自版本读取。旧 `exitGroup` 保留现有 OCO 含义。历史被拒的 AAPL 订单保持失败审计；新的合同不重放旧决策。模型生成与人工查看都应能区分“已有能力”“当前环境无法执行”及其具体项。

## 5. 可复核的行为样例

| 输入／事件顺序 | 必须观察到的结果 |
| --- | --- |
| 空仓提交 AAPL 计划；先看到 354 美元；父单仍未记任何成交 | 在任何入场成交登记前，卖出成交 0。若该报价也使限价买符合条件，可先按入场规则成交；子单只能使用更晚的合格行情 |
| 完整买入 27 股；新的可执行行情触及或低于 355 美元 | 记录买入成交的同一事务建立 27 股的保护。此后达到触发条件，按撮合规则至多卖出 27 股，无需研究轮次 |
| 部分成交模式，买 10 股，重复投递该成交事件，再买 17 股 | 保护量按 10 → 10 → 27变化；每笔成交只计一次，只有一份有效保护 |
| 买 10 股后撤掉剩余 17 股，或余量到期 | 保护仍覆盖 10 股。若 10 股中已退出 4 股，只保护余下 6 股。零成交撤单时保护量为 0 |
| 账户原持有 50 股 AAPL，又挂本计划 27 股买单；另一个同标的计划先成交 | 本计划保护量仍为 0；只有本计划成交才增加，既有 50 股不计入 |
| 27 股带止盈和止损；一腿完成退出；或分批止盈 9 股 | 完整 OCO 退出后另一腿取消。支持分批时，9 股退出后仍为 18 股保留止损，总预留至多 18 股 |
| 动态止损，基准为入场后合格观测最高价，回撤 3%；观测 100、105、103 | 卖出保护阈值依次为 97、101.85、101.85。服务重启或回放后相同，价格回落时保护线不下移 |
| 两笔计划各买 10 股，第二笔限定在第一笔成交后；市场先到第二笔价格 | 等待期间第二笔可成交数量为 0。前置成交后才可使用后续行情激活／撮合；取消未成交第一笔时第二笔终止 |
| 市场尚不可卖、行情过期、保护已到期，或价格跳过止损价 | 分别显示等待可卖、等待有效行情、保护到期或实际成交价。保护到期而仍持仓时清楚显示有多少股失去该计划保护 |
| 模型只生成价格预约、模型离线，或父单成交事务中断 | 仅预约时无自动卖单。已有有效挂单按比赛状态独立执行。事务未提交时成交与子单均不可见；重试后各记一次 |

## 6. 实施顺序与代码依据

先交付现有整笔撮合下的父买单加一条保护性退出，连通模型生成、持久化、实时撮合、回放和中文确认。再支持附属 OCO 和完整生命周期，增加实际部分成交及持仓归属后才开放按量保护。动态止损与分批计划分别提供明确的采价、取整和资源分配规则。每一阶段用无字段名提示的中文意图样例试生成正式配置，记录模型版本、输入、配置回读及预期事件，不把一次生成成功概括为整体识别率。阶段门禁见[实施任务](../tasks/2026-11-13-arena-contingent-orders.md)。
