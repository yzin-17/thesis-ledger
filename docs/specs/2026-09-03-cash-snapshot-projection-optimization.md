# 现金快照与现金流投影优化 Spec

- 日期：2026-09-03
- 状态：已实现并验证
- 适用项目：`thesis-ledger`
- 依赖：[`2026-08-30-cash-account-funding-and-transfer`](2026-08-30-cash-account-funding-and-transfer.md)

## 背景

当前现金投影同时重放现金快照和现金流，但没有统一的快照时间边界与资金生效时间。手工快照之后的未来现金流可能被错误地视为已结算并叠加到快照金额上，导致用户无法判断快照是否已经吸收了历史流水。

## 目标

1. 明确现金快照是某个 `asOf` 时点的实际已结算现金状态基准。
2. 以快照边界过滤已被吸收的现金流，避免历史现金流重复重放。
3. 区分业务发生时间、预计资金生效时间和实际结算时间。
4. 使用统一的现金流生效时间参与当前与历史投影。
5. 兼容缺少预计结算信息的历史数据，不要求立即全量迁移。
6. 保持 Position、Trade、成本和无关收益逻辑不变，仅调整现金相关投影与直接消费者。

## 非目标

- 不重构完整 Ledger、Position 或 Trade 领域模型。
- 不删除、修改或重写历史 LedgerEvent。
- 不引入复式记账体系、银行连接或自动转账。
- 不把未来预计时间伪装成实际 `settledAt`。

## 领域语义

### 现金快照

现金快照表示账户在 `asOf` 时点实际已经拥有的已结算余额。快照是状态校准点，不是现金入账，也不是覆盖历史流水的删除操作。快照时间点及之前已经生效的现金流视为已被快照吸收。

### 现金流时间

现金流保留以下三个可区分的时间概念：

| 字段 | 语义 |
| --- | --- |
| `occurredAt` | 业务事件发生时间，例如成交或入账事件时间 |
| `expectedAt` | 预计现金到账或扣款并影响可用余额的时间 |
| `settledAt` | 实际已经完成结算的时间；未实际结算时为空 |

现金流投影生效时间统一按以下优先级确定：

```ts
settledAt ?? expectedAt ?? occurredAt
```

新数据用 `expectedAt` 表达未来预计生效，用 `settledAt` 只表达已经完成的结算。历史数据缺少预计时间时允许使用显式、有限的兼容推断。

## 投影规则

对指定账户、币种和目标时间 `targetAt`：

```text
latestSnapshot.cash
+ effectiveAt > snapshot.asOf 且 effectiveAt <= targetAt 的现金流
```

具体约束：

- 选择目标时间之前最近的现金快照作为基准；没有快照时从零开始。
- `effectiveAt <= snapshot.asOf` 的现金流已经被快照吸收，不再重放。
- `effectiveAt > snapshot.asOf` 的现金流继续参与未来投影。
- `effectiveAt == snapshot.asOf` 视为已包含在快照中，使用严格大于边界。
- 目标时间之前实际已结算的现金流进入已结算余额；目标时间之后预计生效的现金流进入待结算应收或应付。
- 业务发生时间早于快照、但预计或实际结算时间晚于快照的现金流不得丢失，应在其生效时间参与投影。

## 历史兼容

历史现金流可能缺少 `expectedAt`，也可能存在过去把未来时间写入 `settledAt` 的数据。投影保留兼容路径：

- 已有实际 `settledAt` 优先作为生效时间；未来 `settledAt` 仅按历史预计时间兼容处理。
- 没有结算时间但有 `expectedAt` 时，使用 `expectedAt`。
- 两者都缺失时，有限回退到 `occurredAt`；未来的 `occurredAt` 不得被直接视为当前已结算。
- 新写入路径不得继续使用未来 `settledAt` 表达预计到账。

## 典型场景

1. 快照 2000 @ 09-03，现金流 +700 @ 09-05，09-05 投影为 2700。
2. 现金流 +700 已于 09-01 结算，快照 2000 @ 09-03，之后投影仍为 2000。
3. `occurredAt` 为 09-01、`expectedAt` 为 09-05，快照 2000 @ 09-03，09-05 投影为 2700。
4. `expectedAt` 为 09-05、实际 `settledAt` 提前为 09-04，09-04 起进入已结算余额。
5. 快照 1000 @ 09-01，现金流 +500 @ 09-02，快照 1800 @ 09-03，现金流 +200 @ 09-04，09-04 投影为 2000。
6. `effectiveAt == snapshot.asOf` 的现金流不再重放。

## 对外行为与实现约束

- 统一现金投影通过单一生效时间计算入口，不在消费者中重复拼接时间字段。
- 现金快照继续追加 `CASH_BALANCE_OBSERVATION`，不删除既有事实。
- 现金入账、成交、分红及现金划转涉及的预计资金生效信息使用 `expectedAt`；实际结算时才写 `settledAt`。
- 现金账户页的未来入账仍显示为待结算，不进入已结算余额。
- Performance、Portfolio、账户现金校验和核心现金投影使用同一快照边界规则。

## 验收标准

- AC1：快照之前已经生效的现金流不会再次计入余额。
- AC2：快照之后才生效的现金流仍会在目标时间参与投影。
- AC3：业务发生时间早于快照但预计或实际结算晚于快照的现金流不会丢失。
- AC4：连续创建多个快照不会重放更早现金流。
- AC5：未来预计资金不再通过未来 `settledAt` 表达；新数据使用 `expectedAt`，实际结算才使用 `settledAt`。
- AC6：历史缺少预计时间的数据仍可通过有限兼容路径投影，且新旧事件不被删除。
- AC7：快照边界使用严格 `effectiveAt > snapshot.asOf`，同一时点不重复计算。
- AC8：现金账户、投资组合、Performance 和核心 Ledger 重建使用一致的现金投影结果。
