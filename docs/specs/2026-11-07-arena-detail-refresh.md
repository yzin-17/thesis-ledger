# 竞技场与周报详情的刷新反馈

## 问题与范围

比赛、轮次和模型周报在同范围后台读取时应保留已有结果，并在可见结果中央展示一个加载圈。现有列表已经使用共享刷新区域；Desktop 详情没有完整覆盖，Mobile 详情仍使用页首指示且比赛排名另有局部指示。多个相关请求结束顺序不同时，结果区应等待最后一个相关请求结束。

本轮检查 Desktop ArenaPage/ArenaWeekPage、所属策略中心刷新范围与 Mobile ArenaScreen/ArenaWeekScreen 的列表、比赛详情、轮次、周报详情及派生入口。复用现有 ListRefreshRegion/MobileListRefreshRegion 和 TanStack Query；不新增请求、定时刷新、通用工具或共享组件开关。

## 验收标准

- AC1：同范围刷新保留比赛、排名、轮次、周报及中文状态；结果可见部分中央只有一个提示，刷新完成后移除。首次读取、失败重试、离线与空结果保留具体语义。
- AC2：比赛详情的详情及比较请求、轮次的原比赛及报告请求共同决定刷新；以两种响应结束顺序验证，不能提前收起或重复显示。列表及单个周报详情沿用其实际查询状态。
- AC3：策略中心的页面刷新覆盖当前竞技场查询；周报提供使用当前查询状态的共享刷新按钮。原比赛控制、比较、决策/成交/来源链接、周报修订、模型过滤及返回入口保留；本轮只做局部展示组合，真实业务数据默认只读。
- AC4：有意义的受控延迟/失败回归先通过，再进行包级测试、构建和仓库门禁；四宽实际浏览器检查两端真实组件的列表、详情、错误和滚动视口，记录隔离宿主与原生/目标运行态的区别。
- AC5：最终输入、复用范围、证据及活动任务一致性核对完成后归档本轮 Task；原竞技场/周报的目标运行态、前向比赛、自然周与 Native 验收继续独立保留，本轮完成后结束本次实施。

## 所有权与约束

查询状态由现有 feature 查询拥有，客户端仅组合共享刷新区域。比较失败保留可见错误与重试；不改冻结报告、费用、模型输出、数据合同或服务端执行。使用原子间距，不新增传统 CSS、重要性覆盖、依赖或原生配置。
