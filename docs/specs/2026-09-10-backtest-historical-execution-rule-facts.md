## 1. 产品目标与边界

在明确的数据范围和执行假设下，提供可信、可复现的策略研究回测，服务于策略验证、风险规则联动及后续 AI 策略优化。

普通回测不以客户级、可审计的历史交易精确复演为前提。保留 V2 的全部目标：CN/HK/US 股票与 ETF 的 `1d/60m/30m/15m/5m/1m`，国内场外基金日频。目标能力、源码实现和真实验证分别记录；首个 `600519.SH` 日频闭环不代表其余能力完成。

本增量复用现有 Provider、DataSnapshot、Runner、SimulationLedger 和 BacktestResult，不新增引擎、运行时或通用规则平台。先打通 `600519.SH`、运行区间 `2024-01-02..2024-03-29` 的研究闭环；原来源核查区间 `2023-12-17..2024-03-29` 保留为资料范围，实际预热区间由 Snapshot 依策略计算，不固定套用该资料范围。

## 3. 必要正确性与非目标

必须保留：

- 身份、币种、交易日历、Session、时区和 `occurredAt/availableAt`，信号不能读取未来价格、NAV 或公司行为。
- 适用的 lot/tick、价格限制、可卖持仓与已知不可交易状态。不得由缺 K 线推定停牌，也不得前填价格后照常撮合；未知状态影响适用规则且无法合理判定时阻止对应运行。
- 下单占款、成交扣款、释放占款与卖出/赎回款再投资时点，禁止同一资金重复使用；中央交收日不能直接当作客户可用余额时点。
- 国内场外基金的申请截止、适用净值日及可用时间、份额确认与可卖时间、赎回款到账和费用生命周期。
- raw 成交、复权指标、公司行为、持仓与现金口径一致；必要公司行为缺失不能用空列表表示“没有事件”，现金分红不能与复权收益重复计入。
- 输入与配置冻结、确定性重放，与 actual/shadow、真实 Ledger/Portfolio/Trade/Journal 隔离。

移出当前普通回测交付范围：逐证券逐日全量公告原件、完整历史规则版本沿革及凭证归档、各券商各客户收费协议/优惠还原、银行卡提现和不影响再投资的可取时点。当前无外部出金。相关档案如以后有独立需求再评估，不建立来源审计平台，也不增加研究/审计双模式。

### 4.1 按运行需求选择输入

从策略、执行标的、估值币种、周期、预热与运行区间导出输入集合。身份、日历和计算所需价格覆盖预热/估值；成交费用及交收只需覆盖可能发生的交易事件，不要求无交易自然日也有证券公告。跨币种估值才要求相应 FX；不涉及拆股的区间无需另建拆股档案，但必须有可信的公司行为覆盖判断，不能以未接入当作无事件。

DSA 所需区间由 Server 显式传递，不能猜测。规则配置与 Provider 事实分别校验：Provider 的规则 unavailable 不等于价格/身份可用，也不自动禁止一个已明确选择且完整的研究模型。只有必要事实齐备、适用模型明确且校验通过时才能冻结运行输入；原始 Provider 状态保留，不改成 supported。

### 4.2 明确且可复现的模型

每个实际使用的预设/用户配置记录：标识与版本、来源说明或引用、配置时间、市场/资产/币种/区间、数值与简化假设、费用包含关系、舍入与扣收粒度。无最低额应明确表示“本模型不设最低额”，不能用缺值推定为零。

佣金、最低佣金、适用税费和市场收费必须保留；明确买卖侧、基数、费用币种，规费已包含在佣金中时不再另扣。沿用 Decimal/Money，计算过程保留精度，按声明的统一舍入方法与币种精度在明确的扣收边界取整；价格限制另外按 tick 取整。预设允许固定 T+N，但必须明确对应可卖、扣款或再投资事件、使用哪个交易日历，以及适用范围，不能静默填值或声称还原客户协议。

重要制度或费率在目标区间内发生变化且影响结果时，增加有限的生效日期分段；单段足够时不强制升级成复杂日程。生效日端点只命中一个分段、所需事件日期无缺口/重叠；成交时冻结待交收事件，后续变更不回写旧事件。2023-08-28 费用变化保留为边界测试场景，不作为所有 2024 年运行都必须重新补证的前提。

市场观测事实必须遵守信息可用时间。事后选定的研究预设可用于历史研究，但配置时间不能冒充历史 `knownAt`；结果必须说明模型假设，不声称该日客户实付。若声明某项为历史已知事实，就必须满足对应 `knownAt` 与事件时间约束。来源缺少原始档案不妨碍显式假设建模，却不能据此把候选值签核成历史事实。

### 4.4 冻结、兼容与错误语义

T3.3 本地披露沿用完整模型配置：Desktop 在现有回测配置对话框接收配置 JSON、展示解析后的范围/来源/假设并要求确认；留空保持旧语义，不自动提供未经确认的预设。现有任务响应/摘要可选 `executionModelDisclosure` 返回所选完整模型；结果的同名字段附带冻结模型 `contentHash`。选择不代表冻结或 Provider 支持；结果 `completeness` 独立保留。失败任务展示错误码与原始原因，提交返回 failed 时显示失败而非排队成功。真实展示与 Provider 验收仍归 T4；固定 CN 股票日频场景的模型 JSON 解析/确认、真实成功结果披露与失败详情展示已在 T4 完成，完整目标范围仍由 V2 T13 验收。

2026-09-11 T1/T3.1 有界接线契约：RunConfig 可选 `executionModel` 携带完整、显式选择的 `execution-model-v1`；缺省保持旧运行语义，不自动加载预设。模型范围覆盖运行日期（不是预热），标的/市场/资产/执行币种与不可变 StrategyVersion 一致。配置时间可晚于历史 dataAsOf，但不能晚于冻结时刻；历史事实 knownAt 必须不晚于 dataAsOf，并在所用分段首个运行日的本地零点前已知（本轮采用保守日界门禁，同日才公布的规则暂不支持）。

带模型的新快照使用 `snapshot-manifest-v2`，Manifest 记录模型标识、版本、模型内容哈希及 Artifact 路径；完整模型、来源和假设以规范 JSON 写入独立 Artifact，并保留在配置元数据中。V2 Builder 对全部 Artifact 使用内容导出的确定性标识，消除随机标识造成的哈希漂移。相同输入含相同 runId/策略身份时 manifest 哈希稳定；模型内容哈希不依赖 runId，manifest 继续保留运行所有权，不承诺不同 runId 的 manifest 哈希相同。旧 finalized V1 不补字段、不重写、不改哈希算法。

Snapshot Builder 对未选择完整研究模型的运行以及非执行标的，继续要求原有 Provider 规则/关键事实通过 `requireFrozenExecutionRules` 门禁。对执行标的，只有在显式选择的研究模型完整、范围适用且校验通过时，才可由该模型有界替代 Provider 内嵌 `executionRules` 门禁；Provider 整体 unavailable、身份或币种不一致、lot/tick 缺失、日历或公司行为不可用、模型范围冲突等情况仍失败关闭。带模型的 finalized Snapshot 在 Runner 重放阶段继续由 `execution-model-v1` 驱动 Exchange/NAV 执行，不把旧费用/交收规则叠加到模型结果；缺少模型的旧 V1 快照仍按原语义重放，模型快照不能被未实现模型消费的旧路径静默当作旧规则运行。T3.3 的模型与事实分离披露、`contentHash`、`completeness` 及结构化失败语义保持不变。

2026-09-11 T3.2 受控实现：Exchange 覆盖模型费用、最低额/币种/舍入、tick 价格限制、CN 可卖、现金占款/成交扣款/卖出款再投资和公司行为；NAV 覆盖 cutoff、净值可用、延迟确认、份额可用、申购/赎回费用及现金生命周期。Runner 对晚于 cutoff 的 request 保证先于 cutoff 事件消费，并按确认可用时点消费延迟确认及申购扣款；金额型 NAV 申购以申请金额作为 ledger 成交扣款，避免份额除法尾差破坏占款。定向与包级证据见关联 Task 第 8 节。

2026-09-11 T1 NAV 费用适用契约：NAV 不复用 Exchange 的 `turnover`/逐 Fill 语义。申购费固定为买侧，以不含费用的申请本金 `subscriptionApplicationAmount` 为基数，费用另加；赎回费固定为卖侧，以确认份额乘确认 NAV 得到的费前赎回款 `redemptionGrossProceeds` 为基数，费用从赎回款扣除。适用费用逐申请独立应用费率和最低额，先取费率结果与最低额的较大值，再按 CNY 两位小数 `halfUp` 舍入，并在确认时扣收；不适用必须使用 `notApplicable` 并说明原因。Schema 与 Domain 均约束 side、basis、CNY、舍入、粒度和扣收时点，非法冻结输入不得静默按零费用执行。

优先扩展现有契约，不预设必须新增两个目录、通用日程类或 `market-rules-v2` 全量切换。T1 明确实际结构与必要版本；旧 finalized snapshot 保留原样，按旧版本语义重放，不补填新假设、不重写结果。新结构不兼容时显式拒绝；本增量不需要数据库迁移。

| 缺失类别         | 处理                                                                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 关键输入缺失     | 必要价格/NAV、FX、公司行为、身份/日历、适用交易约束或现金生命周期无法合理计算时阻止对应运行；预检可发现的在冻结/入队前失败，执行中才发现的不得发布正常结果 |
| 可建模研究假设   | 完整且显式选择的配置可作为计算模型，冻结并披露限制；不覆盖矛盾的已知事实，不把 unknown/unavailable 改成事实 supported                                      |
| 无关审计信息缺失 | 原公告字节、客户协议、可取凭证等不影响本次计算时不阻塞；只保留资料缺口                                                                                     |

继续使用现有 `MARKET_RULES_UNAVAILABLE` / 外层 `DATA_UNAVAILABLE` 边界并保留 Provider 原因。后续实现须给出缺失字段、标的、区间和原因（例如规则覆盖缺口、模型未配置或适用性未知），不是仅删除 `executionRules.unavailable` 检查。必要规则版本不匹配、分段缺口/重叠、未来数据仍失败。警告只披露假设和有限结果范围，不为关键数据缺失放行。

## 5. 验收标准

- **AC0 输入分类**：为首个运行列出必要事实、模型选择与无关审计项；未齐输入只阻塞对应运行，不阻止独立契约工作。
- **AC1 范围请求**：Server 传递实际所需区间与 `dataAsOf`；缺失/非法范围拒绝，预热和交易规则范围不混用。
- **AC2 模型冻结**：预设/配置具有来源、版本、范围、假设、费用/交收语义，必要分段完整；数据、配置与来源说明参与快照哈希。
- **AC3 缺失分类**：三类缺失行为可区分，关键输入不能由警告、fixture、零费用或前填价格绕过。
- **AC4 兼容**：既有冻结快照保持可读并按原版本重放；不迁移数据库、不重写旧结果。
- **AC5 执行语义**：费用不重复，最低额/币种/舍入明确；适用持仓约束、资金占用与再投资、NAV 生命周期正确；公司行为与价格/现金一致。
- **AC6 边界与复现**：有限分段边界、规则适用性、未来信息和相同快照复跑均有确定性验证。
- **AC7 最小真实闭环**：沿用 T4 固定策略运行 `600519.SH`、`2024-01-02..2024-03-29`，至少 1 次买入、1 次卖出、1 个闭合交易、超过 2 个日度权益点。
- **AC8 隔离**：成功运行前后 actual/shadow、Ledger、Portfolio、Trade、Journal 指纹不变。
- **AC9 诚实边界**：API/结果展示事实与模型区别；未接入市场/资产/周期继续标明未实现或待验证。最小闭环报告保留 `completeness=partial` 的覆盖限制，不等于广义 V2 完成。
- **AC10 运行时验收**：记录实际镜像、共享快照与服务环境，关键输入缺失注入后稳定失败并可恢复；沿用 T13 已有恢复证据，仅重验受改动影响部分。
