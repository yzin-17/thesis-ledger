# 涨跌配色配置 Spec

> 任务标识：market-color-scheme
> 日期：2026-09-15
> 状态：实现完成；Desktop 运行态已验收，Mobile 运行态待验收
> 对应任务：[涨跌配色配置实施任务](../tasks/2026-09-15-market-color-scheme.md)

## 背景与问题

当前 Desktop 与 Mobile 使用固定的 `positive` / `negative` 颜色表达行情涨跌和盈亏，同时部分成功、错误、删除和风险状态也复用相同语义色。不同市场习惯下，用户需要选择“红涨绿跌”或“绿涨红跌”，但切换不能改变固定状态色、涨跌判定或金融数据的符号语义。

## 目标

- Desktop 与 Mobile 各自提供“红涨绿跌”和“绿涨红跌”两个选项，默认红涨绿跌。
- 选择在本机独立保存：Desktop 使用 `localStorage` 并同步同源 `storage` 事件；Mobile 使用 Expo 兼容的持久化存储。
- 切换立即影响该端全站行情、盈亏和 Desktop 已打开的 K 线、成交量、MACD 柱；图表视窗、指标选择和锁定十字光标保持。
- 金融涨跌色与固定成功、失败、危险、错误、删除和风险告警色分离。
- 零值金融数值使用中性色，缺失值保留现有占位；不改变正负号、箭头、涨跌判定以及平盘 K 线、成交量和 MACD 零柱规则。
- 存储读取失败或非法值回退红涨绿跌；写入失败保留当前会话选择并展示可见提示。Mobile 异步读取不得覆盖读取期间用户的新选择，连续选择按最后一次顺序落盘。

## 非目标

- 不新增服务端 API、数据库字段、跨设备同步、行情数据或 Mobile 图表能力。
- 不改变明暗主题、数值计算、涨跌判定、正负号、箭头或指标算法。
- 不把金融配色变量用于连接成功、错误、删除、危险或风险状态。

## 现状与约束

- Desktop `apps/desktop/src/ui/theme.tsx` 已管理主题偏好和 `localStorage`，`AppShell`/窄屏内容区已有主题入口。
- Desktop `apps/desktop/src/features/market-detail/MarketPriceLightweightChart.tsx` 已监听主题属性变化并更新现有 series；本功能应复用该更新链路而不重建图表。
- Desktop 使用 shadcn base-vega、Lucide、pnpm，设置控件优先复用现有 `DropdownMenu`、`ToggleGroup` 或 `RadioGroup`。
- Mobile 使用 Expo/React Native，当前主题颜色在 `apps/mobile/src/theme.ts`，页面入口在 `apps/mobile/src/App.tsx`，不得用浏览器专属存储替代原生持久化。

## 设计方案

### 外观配置与持久化

定义 `MarketColorScheme = 'red-up' | 'green-up'`，各端在外观模块中提供规范化读取、设置和语义颜色映射。无值、非法值或读取异常均返回 `red-up`。金融颜色映射随明暗主题生成独立的 `marketUp`、`marketDown`、对应柔和背景与中性色，固定状态色另有稳定变量。

Desktop 的 key 固定为 `thesis-ledger-market-color-scheme`。设置后立即更新 DOM 语义变量，并通过 `storage` 事件让同源标签页同步；事件中的非法值回退默认。写入异常不撤销内存选择，在设置入口显示错误提示。

Mobile 使用 Expo 兼容的异步存储适配。初始读取不阻塞页面；若用户在读取期间选择，读取结果不得覆盖该选择。保存操作串行化，最后一次选择必须是最终写入；写入失败保留当前会话选择并显示提示。

### 颜色语义

- 金融涨跌：行情涨跌、持仓盈亏、收益率、K 线实体/边框/影线、成交量与 MACD 正负柱使用可变 `marketUp` / `marketDown`；零值使用中性色。
- 固定状态：成功、失败、错误、危险、删除按钮、风险告警、连接状态和完成状态使用固定 `success` / `error` / `warning` 等语义，不随配色切换。
- 普通分类图表、品牌色、指标线和文本层级保持当前语义；缺失值继续使用当前占位。

### 设置交互

Desktop 的明暗主题继续由 `ThemeToggle` switch 控制，并在旁边提供独立的涨跌配色入口；选项示例按对应颜色渲染，说明文本不依赖 `<label>` 默认激活控件。Mobile 在主题按钮附近提供两个涨跌配色选项并展示保存失败提示。

## 对外行为或接口变化

仅增加客户端本地外观偏好，不改变 Server/API/数据库契约。现有消费方通过端内主题/外观上下文或语义颜色对象读取颜色，不直接读取存储 key。

## 数据、状态或兼容性影响

没有迁移和服务端数据影响。旧安装无 key 时使用红涨绿跌。清除本地存储后恢复默认。Desktop 多标签页同步只影响同源标签页；Mobile 仅影响当前设备应用存储。

## 测试策略

### 关键可观察行为

- 默认、非法值、读取异常、写入异常、刷新恢复和 Desktop `storage` 同步。
- 两种配色与浅色/深色主题组合的金融颜色映射；固定成功/错误/危险色保持不变；零值中性、缺失值占位不变。
- Desktop 图表现有 series 即时更新，时间范围、缩放、指标选择和十字光标不重置。
- Mobile 异步读取竞态、连续切换最终写入、页面切换一致性和可见失败提示。

### 测试层级与证据边界

组件/契约测试证明规范化、持久化和颜色语义；Desktop/Mobile 包级 typecheck/test/build 证明编译和定向行为。浏览器验收证明 Desktop 的真实切换、刷新恢复和打开图表即时更新；真实模拟器/设备验收独立记录，无法执行时保持未验收。

## 实现边界与风险

- 金融涨跌色通过独立的 `marketUp` / `marketDown` CSS 变量和主题字段消费，固定状态色继续使用独立语义变量；新增界面布局使用现有原子类组合。
- 图表颜色切换复用已有 `applyOptions`/series 更新链路，保留视窗、指标选择和十字光标状态。
- Mobile 使用 `@react-native-async-storage/async-storage` 保存本机选择，并维护 package/lockfile；Native compile 证据按实际设备/模拟器可用性记录。

## 验收标准

- AC1：Desktop 和 Mobile 均能选择红涨绿跌/绿涨红跌，默认及非法配置为红涨绿跌，切换立即生效。
- AC2：两端分别本机保存并恢复配置；Desktop 同源 `storage` 同步；Mobile 异步读取不覆盖新选择，写入失败保留会话选择并显示提示。
- AC3：行情、盈亏和 Desktop K 线实体/边框/影线、成交量、MACD 正负柱跟随配置；零值中性、缺失值占位及涨跌判定不变。
- AC4：成功、失败、错误、危险、删除和风险告警等固定状态色不随涨跌配色变化。
- AC5：Desktop 已打开图表切换后不重置视窗、缩放、指标选择或锁定十字光标，也不重新请求业务数据。
- AC6：定向测试、包级检查和可执行的浏览器/Native 验收按任务证据边界完成并如实记录。
