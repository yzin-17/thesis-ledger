# 首次保存来源凭据的启停状态

> 日期：2026-10-22
> 状态：实现与目标验收完成，本页保留为当前配置合同
> 对应任务：[已完成任务](../archive/tasks/2026-10-22-provider-first-credential-state.md)

## 问题与范围

TickFlow 尚无配置记录、尚无有效凭据时，来源清单显示 `enabled=false`。首次仅提交凭据时，保存逻辑却采用来源的默认启用值，凭据补齐后来源变为启用。这违反了[原凭据合同](2026-09-14-market-provider-credentials.md)中省略 `enabled` 时保留原状态的要求。

本次只修正 DSA 配置事务在首次建行时的启停基线。Server 的部分更新转发、既有配置行、加密、版本冲突检查、路由及来源读取继续使用原实现。

## 保存合同

- **PC1**：配置行不存在且请求省略 `enabled` 时，以保存前的默认启停与凭据就绪状态共同确定原状态；缺少凭据而停用的来源首次保存凭据后仍停用。
- **PC2**：原本可用且默认启用的环境凭据来源、无需凭据的公开来源保持启用；默认停用的来源保持停用。已存在配置行继续保留原保存值。
- **PC3**：请求明确提交 `enabled` 时沿用显式值及原凭据完整性检查。配置版本冲突仍回滚；凭据更新不能隐式修改其他字段，响应不泄露凭据。
- **PC4**：正式 DSA 更新后，目标代码与已测代码一致。目标凭据部分更新省略 `enabled`，原停用值、凭据内容、其他来源配置及路由保持；仅该来源配置版本按合同递增。

## 验证与停止边界

先以合成凭据、临时 SQLite 和真实 Control HTTP 路径验证无配置记录的首次保存，再执行相关控制面回归与仓库门禁。正式 `sync-code.sh dsa` 因控制文件属于构建兼容性输入而拒绝后，用户已明确授权脚本要求的 `update.sh dsa` 完整更新；使用默认保留数据路径，不调整兼容性门禁。目标已有真实凭据，不删除其配置来制造首次保存：使用既有凭据的空字段补丁验证部分更新，结合代码摘要与本地首次建行证据验收。

不新增真实来源读取，不更改来源启停或路由。出现新的兼容性、版本冲突、凭据解析或运行环境卡点即停止确认，不扩展替代方案。
