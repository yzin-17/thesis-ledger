# 自动化运行历史分页 Spec

任务文档：[`../tasks/2026-09-09-automation-run-history-pagination.md`](../tasks/2026-09-09-automation-run-history-pagination.md)

## 背景与问题

自动化配置台当前通过 `GET /automations/history` 一次读取最近 200 条运行记录。记录增长后，这会产生不必要的数据库读取、网络传输和前端渲染成本；界面也无法继续查看 200 条以外的历史。

## 目标

- 自动化运行历史由服务端分页查询，桌面端按需获取当前页。
- 分页交互、页码摘要和加载禁用行为与 Provider 健康历史保持一致。
- 保留既有 `jobId` 过滤能力，并保持运行时间倒序展示。
- 桌面端在服务端滚动升级期间兼容旧的数组响应。

## 非目标

- 不增加运行历史筛选、搜索、删除或导出功能。
- 不修改自动化任务执行、重试、通知或历史写入语义。
- 不对既有运行历史数据做迁移。

## 现状与约束

- 服务端当前固定 `take: 200`，按 `startedAt desc` 查询。
- 桌面端使用 TanStack Query 读取运行历史，查询键当前不含页码。
- Provider 健康历史已使用 `page`、`pageSize`、`total`、`totalPages` 的页码分页结构，可复用其交互约定。
- 自动化任务执行后会失效运行历史查询；分页查询键必须保留可按前缀整体失效的能力。

## 设计方案

### 服务端分页

`GET /automations/history` 接受可选参数：

- `jobId`：保留既有任务过滤语义。
- `page`：正整数，缺失或非法时使用第 1 页。
- `pageSize`：正整数，缺失或非法时使用 20，最大值为 100。

服务端先按相同过滤条件统计总数，再查询当前页。记录按 `startedAt desc`、`id desc` 稳定排序。请求页码超过末页时回落到末页；无记录时返回第 1 页且 `totalPages` 为 0。

响应结构为：

```text
{
  items: AutomationRun[],
  page: number,
  pageSize: number,
  total: number,
  totalPages: number
}
```

### 桌面端分页

- 默认每页读取 20 条。
- TanStack Query 查询键包含当前页码；立即运行任务后按运行历史前缀失效全部分页缓存。
- 表格下方显示“第 X / Y 页，共 N 条”，并提供“上一页”“下一页”。
- 首末页、空数据或当前页加载期间禁用不可用的翻页操作。
- 若旧服务端仍返回数组，桌面端在本地规范化为相同分页结构，避免滚动升级期间页面不可用。

## 对外行为或接口变化

- `GET /automations/history` 从数组响应升级为分页对象响应，并新增 `page`、`pageSize` 查询参数。
- 桌面端自动化运行历史表新增页码摘要和翻页按钮。

## 数据、状态或兼容性影响

- 不修改数据库 Schema，也不迁移历史数据。
- 桌面端兼容旧数组响应；新服务端不再返回无边界的历史数组。
- 新运行记录可能使后续记录页码顺延；刷新或任务运行后以服务端最新分页结果为准。

## 测试策略

### 关键可观察行为

- 数据库只读取请求页所需记录，并返回正确总数与页数。
- 桌面端切页时发起带页码和每页数量的请求。
- 表格正确展示当前页摘要，并在边界和加载期间禁用按钮。

### 优先测试层级

1. 服务端服务测试验证过滤、稳定排序、`skip/take`、页码回落和空结果。
2. 桌面端 API/类型测试验证分页响应与旧数组兼容。
3. 桌面端组件测试验证页码摘要和翻页按钮状态。

### 可复用的现有测试入口

- `apps/server/test/automation-runtime.test.ts`
- `apps/desktop/test/providers-automation-ui.test.tsx`

### 需要新增的测试入口

无需新增测试文件，在既有入口补充分页行为覆盖。

### 关键边界与回归场景

- 非法页码和过大的 `pageSize`。
- 空历史、第一页、末页和越界页。
- 带 `jobId` 的分页查询。
- 旧服务端数组响应。
- 任务运行后全部运行历史分页缓存失效。

## 风险与备选方案

- 游标分页在持续写入时更稳定，但当前页面需要明确页码和总数；页码分页与现有健康历史一致，交互和维护成本更低。
- 旧数组响应只能在客户端已有数据范围内分页，这是滚动升级兼容路径，不作为长期服务端行为。

### Blocking

无。

### Non-blocking

无。

## 验收标准

- AC1：`GET /automations/history` 支持 `jobId`、`page`、`pageSize`，返回分页对象，并以稳定倒序只查询当前页。
- AC2：非法或越界分页参数得到安全、确定的默认或回落结果，单页最大 100 条。
- AC3：桌面端默认每页请求 20 条，切页会获取对应页并显示页码与总记录数。
- AC4：上一页、下一页在边界、空数据和加载期间具有正确禁用状态。
- AC5：桌面端兼容旧数组响应，任务运行后仍能失效所有运行历史分页缓存。
