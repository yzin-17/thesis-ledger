# 规则监测版本查看与统一自动化记录

> 日期：2026-11-09
> 状态：验收完成，现行合同保留
> 对应任务：[已完成任务](../archive/tasks/2026-11-09-rule-monitor-automation.md)
> 操作补充：[已完成任务](../archive/tasks/2026-11-09-rule-monitor-controls.md)
> 执行时间与页面分工：[现行规格](2026-11-09-rule-monitor-schedule.md)

## 背景与目标

真实页面点击“查看版本”后接口成功返回，但详情追加在32行表格下方，位于当前视口之外。用户需要立即可见的版本详情，并在自动化任务中统一查看收费资料检查的执行记录及失败原因。

## 范围与边界

- Desktop 通过共享 Sheet 展示资料版本，保留版本摘要、观察时间及加载、失败状态，支持关闭、键盘操作和窄屏。
- 规则检查仍由 DSA 调度与持久化。自动化模块只读取投影，不另建执行器、不补跑历史、不自动开启检查、不向外部资料发送验收请求。
- 在自动化任务列表展示已创建的系统托管规则监测任务；来源创建与执行时间设置的页面分工由执行时间规格持有。统一运行历史与失败诊断接入同一事实源。
- 保留现有 PostgreSQL 自动化任务与执行记录；不改写已有冻结资料，不迁移业务数据库。
- Desktop 与 Mobile 均准确显示新增任务、状态、时间和失败摘要；不改动原生依赖与构建配置。

## 接口与数据

DSA 新增只读分页历史接口，按创建时间、任务标识倒序返回记录。单次读取最多100条，支持仅查看异常；结果包含总数、任务状态、来源范围、手动或定时触发、执行起止、统计及该次失败明细。

监测 SQLite 采用增量结构升级：新增逐次触发信息和失败明细表，与领取条件下的观察结果原子提交。历史运行及版本保持不变；旧记录的触发方式为未知，缺少逐项原因时明确表示历史未保留，不能借当前最后一次观察猜测过去原因。

Server 的 Market 模块拥有 DSA 监测读取契约，Automation 单向消费该契约。新增读取聚合服务负责自动化任务和历史投影，不改变现有调度服务与任务创建类型。统一历史按明确时间与标识排序分页，包含手动及定时检查；异常包含部分不可读、失败、中断，不能归为成功。

运行历史允许尚未开始的记录具有空开始时间；排队时间与开始时间分别表达。远端不可用时保留本地记录，并显式显示规则监测读取失败；不得把未知状态显示成停用或无记录。

Desktop 运行历史支持按任务筛选。筛选值同时驱动请求参数、查询缓存与页码；切换任务回到第一页，不显示上一任务的缓存记录。选项与当前回显复用中文任务名称。

Desktop 监测任务与其他系统任务采用相同的启用/停用、编辑、立即运行操作。当前执行时间编辑及规则检测页职责由[执行时间规格](2026-11-09-rule-monitor-schedule.md)持有；取消和关闭遵循共享草稿保护。立即运行使用最新已保存的来源，并沿用监测请求标识，响应未确认时重试同一次检查。配置与执行调用 Market 监测契约，不注册第二套调度器。系统任务不可删除，不加入通用创建选项。Mobile 现有消费与管理范围保持。

## 验收标准

- AC1：点击任何有版本的资料立即打开可见详情，正确切换资料，关闭后回到原入口；失败、空版本和刷新状态正确。
- AC2：定时与手动检查均有可分页读取的持久运行记录；错误明细属于该次执行，重开存储后不丢失，过期执行不能写入。
- AC3：已有监测库增量升级保留配置、运行、最后观察和版本；旧记录的未知信息如实展示。
- AC4：自动化任务列表正确显示监测启停与读取不可用状态；操作入口不创建第二套调度。
- AC5：统一运行历史和异常诊断正确合并、排序、分页及筛选；保留本地历史，远端故障有明确缺口提示。
- AC6：Desktop/Mobile 展示任务名称、排队与开始时间、部分失败、中断、统计及中文失败原因，不显示技术枚举代替业务标签。
- AC7：定向测试、契约检查、受影响包检查及边界门禁通过；实际浏览器覆盖1440、1024、768、390宽度。目标运行态联通独立记录，不能由夹具替代。
- AC8：Desktop 操作列与其他系统任务一致，执行时间编辑原位完成；启停、已保存范围立即运行、缺少来源、配置冲突、响应未确认重试及保存后列表/历史刷新均正确。受控请求验证写入内容，真实配置与外部资料验收保持只读；当前页面分工遵循执行时间规格。

## 验证与停止边界

优先使用临时 SQLite、受控网络与固定时间，验证真实持久化及契约投影。只读核对目标页面和历史，不执行真实检查、自动检查启用、通知或业务数据修改。需要同步目标代码时只通过既有 infra 正式入口，确认所选入口的结构兼容性；新增外部调用或破坏性操作需要额外授权。无需新增 Provider 或预算。

无。本轮验证及运行边界见已完成任务关联的证据；后续契约或运行态约束变更应更新本规格并建立对应任务。
