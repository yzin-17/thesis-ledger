# 收费资料检查执行时间归属

> 日期：2026-11-09
> 状态：验收完成，现行合同保留
> 对应任务：[已完成任务](../archive/tasks/2026-11-09-rule-monitor-schedule.md)

## 背景与目标

用户要求自动化编辑与其他任务一样可以调整执行时间，且该编辑仅设置执行时间；规则检测页只根据选择的来源创建任务，不设置时间，默认每24小时执行一次。

## 行为合同

- 延续当前唯一的收费资料检查任务。规则检测页保留来源选择、创建任务和历史结果/版本读取，移除时间设置、自动检查开关及立即检查操作。首次创建任务默认启用，第一次计划为创建后24小时；已存在任务时允许更新检查来源，保留启停、执行时间与下一次运行，避免重复创建和覆盖时间。
- 自动化页启停、立即运行保持；编辑复用其他任务的执行时间预设与自定义五段 Cron，仅展示执行时间字段。支持恢复默认的每24小时计划。名称、类型、来源与自动检查开关不在该编辑中设置。
- 来源范围属于规则检测页，执行计划属于自动化页；两者使用同一份带修订号的监测配置。保存冲突保留草稿，失败不显示成成功；下一次运行由服务端实际持久计划返回。
- 规则页的“前往自动化”使用应用内路由，直接打开自动化页签，浏览器后退回到规则检测页。
- 继续由 DSA 的唯一监测调度器创建持久执行记录，不再增加调度器。默认24小时采用实际间隔；Cron 按保存时区计算。到期领取和下一计划推进在同一 SQLite 写事务内完成，多实例不能重复创建同一到期任务；存在活动任务时等待，不并发执行。停机只触发一次当前到期任务，不逐次补跑所有错过的计划。
- 手动检查不改写计划时点；编辑执行时间或重新启用过期计划时，计算未来下一次运行。停用只停止后续计划，已有执行和版本保留。

## 接口与存储

监测配置增加是否已创建、计划表达式、时区及下一次运行。默认表达式为 `@every24h`，其余为五段 Cron；使用现成 Cron 库验证与计算，不维护自制解析器。新增只读投影字段及创建/更新来源、修改时间接口，沿用 Control 认证、来源校验与配置修订条件。配置修改与任务入队不触发同步资料读取。

SQLite 增量升级至结构版本3，新增计划表，保留原配置、运行、逐次失败及资料版本。已有非空来源配置视为已创建任务，保留启停，默认24小时计划从最近一次检查建立；不会重置为新建或清空历史。空来源配置不展示自动化任务，创建后才出现。旧代码不支持版本3，回退必须保留新版读取支持。

Market 拥有监测时间写入契约，Automation 仅消费计划投影；前端时间编辑通过现有 API client 的 Market 能力保存。不新增 PostgreSQL 结构或将 DSA 执行映射成第二份成功记录。

创建来源和保存时间只写本地配置，按现有 `write` 成本登记；立即检查继续使用原较高成本分类，不能因为新增入口遗漏登记而阻断正常保存。

## 验证与边界

本地使用临时真实 SQLite、固定时钟和受控 fetch 验证创建、到期、领取、终态及重开存储；覆盖默认间隔、工作日/每日/自定义 Cron、无效表达式/时区、停用/启用、来源更新、并发与晚到提交。契约、客户端、Server 投影与 Desktop 编辑分别验证，实际浏览器覆盖1440、1024、768、390。

新增 DSA 运行依赖需通过 infra 完整更新入口一次装配目标运行态，再只读核对配置、计划、历史及版本。真实启停和计划值保持，不提前到期、不触发新外部资料请求；调度执行通过隔离样本证明，目标业务数据只读。Mobile 维持已有读取范围并正确显示计划，不新增原生依赖。

## 验收标准

- AC1：规则检测页仅选择来源并创建/更新任务来源，默认24小时，页面没有执行时间或立即检查设置；已创建任务再次保存来源保留计划。
- AC2：自动化编辑仅执行时间，预设、自定义与默认24小时均可保存及正确回显；启停和立即运行原行为保持。
- AC3：增量升级、配置修订、计划持久化、到期事务与单执行器约束通过；执行记录、失败原因和版本保持。
- AC4：共享契约、Server 投影、客户端消费、定向测试和包级检查通过；四宽实际浏览器与目标运行态边界分别记录。

## 未决问题

无。当前单任务范围延续既有产品合同，新增独立任务类型或多任务来源分组不属于本次范围。
