## 背景与目标

目录已经包含正确中文名称，但持仓、Trade、风险、研究和定投的部分读模型仍使用 Asset 名称；移动端成交和复盘未消费响应中的目录。延续[目录聚合合同](2026-09-18-instrument-directory-server-read-aggregation.md)，当前名称统一由 Server 返回前按完整代码和市场批量查询本地 Instrument 目录。

## 设计与边界

- Market 拥有公共 `InstrumentDisplayService`，复用 `InstrumentDirectoryService` 的规范化、去重、精确市场匹配、历史 inactive 选择及故障降级。服务暴露一次解析所得的名称查找能力和目录代次，业务读模型使用该能力组装响应。
- 一个业务结果集合一次批量解析；相同代码的多账户持仓不产生逐行查询。未知代码、目录故障或歧义回退代码，业务结果保持完整，不触发远程来源。
- 持仓、Trade、风险规则、当前风险上下文、研究对象与来源、当前定投计划均消费公共服务。现有响应名称字段在返回投影中更新；不修改 Asset、Trade、账本或研究持久化事实。
- 研究展示版本包含实际目录解析结果，目录名称变化可使展示版本变化；运行结果、模型报告和冻结输入保持原值。
- 当前定投计划响应展示目录名称；新计划保存时解析名称，后续生成到期实例时按当次目录解析结果冻结基金名。既有到期实例和通知消息保留原冻结名称，读取不按最新目录覆盖。
- Ledger 事件、Journal 候选继续返回已有目录字段；移动端从各自主响应消费，不新增目录网络请求。历史复盘快照、旧引用快照、导入原文及 Provider 原始名称保持原语义。
- 共享实现留在 Market；消费模块单向依赖 Market，不引入反向依赖或无所有权的共享目录。工程边界门禁约束当前名称读取接缝。

## 数据、权限与兼容性

无数据库结构或依赖清单变更。保留全部已有记录和无关工作区修改。只更新已有名称字段的当前展示语义；业务金额、状态、排序和事实指纹保持。运行态通过 infra 维护入口最小同步，并记录独立 API 与页面证据。页面验收只读，不创建交易、定投、风险事件，不调用模型或发送通知。

## 测试与验收

- AC1：公共服务批量、去重、完整市场匹配，目录未知、故障、inactive 和歧义有明确回退；业务对象及数据库不被改写。
- AC2：持仓和 Trade 在 Asset 名称为代码或旧名时，列表、详情、引用解析均显示目录名称；金额、状态、分页和事实指纹不变。
- AC3：风险规则、风险上下文、研究对象与来源使用目录名称，传入旧名称不遮蔽当前目录；研究展示版本反映名称变化。
- AC4：当前定投计划使用目录名；新冻结实例使用生成时目录名，已有实例、通知、研究和复盘快照保留原值。
- AC5：移动端成交和复盘候选消费已有目录；主查询数量不增加，空目录时回退代码。
- AC6：项目 AGENTS.md 明确名称读取、批量、故障、历史快照和回归规范；边界门禁阻止已确认旧模式。
- AC7：定向回归、受影响包检查与工程门禁通过；目标 API 和真实浏览器的两条当前持仓均显示基金中文名，独立只读解析核对另一已发现占位名称的基金，并验证交易、风险、定投代表入口。移动端页面单独验证，不能以 Web 结果替代。
- AC8：Android Emulator 与指定 iPhone Air 的实际原生应用分别加载当前修复源码，连接真实目标 API；持仓、成交、账本审计和复盘候选页面显示正确目录名称。保存构建/代码来源、实际界面树、断言和截图；保留已有应用数据与设备状态，不产生业务写入，验证后核对历史记录摘要。
