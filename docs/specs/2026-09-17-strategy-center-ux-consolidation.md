## 1. 目标与核心决策

将当前围绕功能堆叠的页面，调整为围绕“策略及其不可变版本”组织的工作流。用户应能够清楚回答：正在处理什么策略、使用哪个版本、结果来自什么实验或回测、下一步可以做什么。

核心决策如下：

| 编号 | 决策                                                                                                                                                                        |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | 手动创建、AI 辅助创建及 AI 实验采纳的策略统一进入策略库，使用相同的版本、编辑、回测和风险规则入口。未采纳候选保留在实验内；尚未确认入库的编写草稿按关联 Spec 管理。         |
| D-02 | 左侧“策略实验”调整为“策略中心”，一级页签保留“策略库 / 回测任务 / AI 实验”，删除 AI 实验下的“策略风险规则”二级页签。                                                         |
| D-03 | AI 实验拆为实验列表、新建实验工作页、实验详情，不再把长表单、历史记录和结果对比连续堆在一个页面。                                                                           |
| D-04 | 风险规则统一从策略库的具体策略版本生成；预览并确认后进入风险中心管理，不因 AI 采纳或策略升级而自动启用、自动更新。                                                          |
| D-05 | 回测任务详情使用独立详情页，默认先呈现结果、曲线和关键限制，不再使用承载全部内容的长滚动弹窗。                                                                              |
| D-06 | 权益曲线与回撤曲线支持联动悬停、区间缩放、平移和重置；原始时点表退居次级位置。                                                                                              |
| D-07 | 哈希、校验和、内部 ID 保留在“诊断与复现”中，支持完整复制和诊断导出；不再逐项占据主页面大卡片。                                                                              |
| D-08 | 简化展示不能掩盖研究假设、事实支持限制、样本数量、封存测试曝光或错误状态。                                                                                                  |
| D-09 | 封存测试全部完成后统一自动揭示；系统访问封存数据与向用户揭示结果是两个概念。                                                                                                |
| D-10 | 封存测试部分技术失败时保持隐藏，仅重试原批次未完成部分；放弃后仍不揭示部分结果。                                                                                            |
| D-11 | 实验基线变旧时，审核候选、原基线与当前正式版本的差异后可追加新版本；不自动合并期间修改。                                                                                    |
| D-12 | 旧版定义保留查看、编辑和回测；AI 优化与风险生成明确限制为定义格式 V2，不隐式转换。                                                                                          |
| D-13 | 缺口无法定位时展示已记录点和完整性限制；不根据日期间隔推断缺口。                                                                                                            |
| D-14 | 全局回测列表中用户回测逐条显示，AI 回测按实验分组并可展开。                                                                                                                 |
| D-15 | 同一实验不允许混用已知的不同计费币种；本轮不引入费用汇率换算。                                                                                                              |
| D-16 | 费用或计费币种存在未知项时，禁用实验总金额上限；明确确认后其他预算限制继续生效。                                                                                            |
| D-17 | 同账户、同标的仅一条策略风险应用可启用；冲突时引导管理，可先保存为停用，不自动替换。                                                                                        |
| D-18 | 相同策略版本、账户、标的和生效范围的应用复用已有记录；通知配置通过显式编辑调整。                                                                                            |
| D-19 | 再次运行沿用明确策略版本与执行配置，重新获取数据、创建新任务，不承诺精确复现。                                                                                              |
| D-20 | 策略详情继续使用可直达的独立页面；页头采用仅图标返回按钮、标题和业务状态组成的紧凑标题行，返回按钮保留可访问名称。                                                          |
| D-21 | 策略定义首屏直接呈现可读的适用范围、交易逻辑、仓位、风险与执行假设；大面积空卡片和折叠后的原始定义不能替代默认摘要。                                                        |
| D-22 | 版本选择器的触发器与选项复用同一主标签；策略修订版本、业务状态和定义格式分开表达，内部 UUID 不作为主回显。                                                                  |
| D-23 | 生成风险规则使用策略详情内的单层 Drawer 完成预览与保存，成功后仍可留在源版本；已有应用的持续管理归风险中心。                                                                |
| D-24 | 已有版本编辑使用保留源详情的右侧 Drawer，新建策略与新建 AI 实验继续使用独立页面；这些入口必须兼容应用实际路由模式，保留未保存离开确认，渲染异常显示可恢复错误而非全页空白。 |
| D-25 | 定义格式 V2 是技术兼容信息，不代表策略已启用或已经获得业务认可；默认页面仅在旧格式导致能力受限时展示兼容提示。                                                              |

### 1.1 本轮应实现的结果

用户可以沿着以下路径完成工作，不需要理解内部 Provider 路由、UUID 或哈希。自然语言路径由关联 Spec 独立实施：

```text
手动创建 ────────── 保存 ───────────→ 策略库 / 具体版本
自然语言描述 → 澄清 → 编写草稿 → 确认保存 ──↑
AI 实验探索或优化 → 候选 → 验证与测试 → 确认采纳
                                            │
                         ┌──────────────────┼──────────────────┐
                       发起回测           AI 优化          生成风险规则
                         │                                    │
                    回测详情与分析                       预览 → 确认应用
                                                              │
                                                           风险中心
```

### 1.2 非目标

本轮不重写回测引擎、策略 Schema、指标计算、确定性规则编译器、任务状态机或 DSA 数据提供逻辑；不把相关领域计算迁移到前端。不得因为页面需要更完整的指标而伪造数据、修改历史结果或以静态规则冒充历史事实。

不新增自动交易，不让 AI 候选自动修改账户或监控规则，不实现完整研究平台、任意策略组合分析或 PDF 报告系统。交易标记、基准曲线等增强展示只消费现有可信数据，不以新增行情 Provider 为本轮前置条件。

## 3. 统一对象与生命周期

### 3.1 对象边界

| 对象         | 职责                                                      | 不代表什么                             |
| ------------ | --------------------------------------------------------- | -------------------------------------- |
| 策略         | 策略库中的管理对象，承载名称、说明、来源和版本关系        | 不等于某一次回测或某个 AI 候选         |
| 策略版本     | 一次保存形成的不可变定义，是后续执行和应用的绑定对象      | 不因后续编辑而自动变化                 |
| 策略编写草稿 | 自然语言创建过程中尚未确认入库的可恢复内容，详见关联 Spec | 不等于正式策略的业务草稿状态或实验候选 |
| AI 实验      | 记录目标、基线、模型、预算、数据区间及候选评估过程        | 不直接成为正式策略，也不直接生效于账户 |
| AI 候选      | 实验内的中间方案，保留参数差异、结果和资格状态            | 生成完成不等于评估合格或已经采纳       |
| 回测任务     | 使用明确配置、策略或候选快照执行的一次任务                | 运行成功不等于策略有效或历史事实完整   |
| 风险应用     | 将明确策略版本的可转换规则应用到具体账户和范围            | 不跟随策略“最新版本”静默更新           |

本文中的“正式入库”表示进入策略库统一管理，不等于已经启用、通过全部质量门槛或适合实际投资；策略状态沿用既有领域语义。

### 3.2 入库规则

| 用户操作                 | 结果                                                                |
| ------------------------ | ------------------------------------------------------------------- |
| 手动创建并保存           | 新策略及首个版本                                                    |
| 确认保存自然语言编写草稿 | 新策略及 v1，保留 AI 辅助创建来源；按关联 Spec 审核，不经过实验采纳 |
| 编辑已有策略并保存       | 原策略的新版本，不覆盖旧版本                                        |
| 从零 AI 实验中采纳候选   | 新策略及首个版本，保留实验与候选来源                                |
| 优化已有策略后采纳候选   | 原策略的新版本，保留基线版本和实验来源                              |

采纳前展示将创建或更新的策略、来源候选及主要变更。成功后提供“查看策略版本”，实验中保留已采纳版本的反向链接；刷新或重复点击不得产生重复策略或重复版本。

AI 优化期间原策略产生新版本时，实验仍固定原基线。若实验基于 v2、当前正式版本已是 v3，采纳确认同时展示候选相对 v2 的变化、候选与 v3 的差异，并明确“使用候选完整定义创建 v4，不自动合并 v3”。用户确认后可追加 v4，保留 v3、原基线与评估来源。

实验基线与采纳时确认的当前正式版本是两个不同字段语义。服务端在原子提交时校验用户确认的当前版本仍未变化；若已出现 v4，则拒绝旧确认，刷新差异后重新确认，不静默追加 v5。相同采纳意图重试返回同一正式版本及一致的响应结构。新版本不自动更新已有风险应用。

### 3.3 状态分层

以下状态必须分开表达，禁止合并为一个笼统的成功标签：

- 运行状态：排队、运行、完成、失败、取消等，以服务端为准。
- 评估状态：未评估、验证完成、测试待运行、测试无效等，展示真实原因。
- 采纳状态：未采纳、已采纳，以及服务端允许或禁止采纳的条件。
- 数据与事实支持：数据完整性、研究假设、历史事实支持情况，不能由任务成功推导。

英文枚举只保留在诊断详情；用户界面采用中文业务文案。状态映射未知时显示“未知状态”及可查看的原值，不擅自归类为成功。

## 4. 信息架构与导航

### 4.1 页面结构

```text
策略中心
├─ 策略库
│  ├─ 新建策略：手动编写 / 自然语言创建（关联 Spec）
│  ├─ 编辑已有版本
│  └─ 策略详情：明确选中版本
│     ├─ 策略定义
│     ├─ 版本记录
│     ├─ 回测记录
│     ├─ AI 实验
│     ├─ 风险应用
│     └─ 生成风险规则 Drawer
├─ 回测任务
│  └─ 回测详情
│     ├─ 结果概览
│     ├─ 交易与订单
│     ├─ 数据与假设
│     └─ 诊断与复现
```

### 4.2 导航要求

列表进入详情后，浏览器返回应恢复筛选、排序、分页和必要滚动位置。详情支持刷新恢复和直接打开，不依赖只存在于上一个页面内存中的对象。

策略详情的版本选择必须可被稳定定位。全局任务页保留全部任务的访问路径：用户回测逐条显示，AI 回测按实验分组，展开后定位基线、候选和阶段；分组不绕过封存测试保护。策略详情展示该策略的相关记录，默认当前版本，可切换全部版本，并显式标注记录绑定版本。

旧 AI 风险入口迁移后，应引导到策略库或能够解析出的具体版本入口，不能保留第二套风险配置表单。无法解析的旧链接显示可操作的说明，不猜测使用最新策略。

新建实验和回测结果分析使用独立页面。短确认、删除确认或必要的简短预览可以使用单层弹窗；生成风险规则使用单层 Drawer。任何弹层内都不继续打开嵌套 Drawer。

已有版本编辑 Drawer、新建策略页和新建实验页进入后必须完成首屏渲染。编辑 Drawer 保留当前版本详情作为来源上下文，关闭后回到同一版本；离开保护须与根路由模式兼容。路由组件抛错时由策略中心边界显示错误摘要、重试及安全返回入口，不允许以空白页面作为失败反馈。

### 4.6 导航、视觉与交互约束

- 详情地址/导航参数保存对象稳定标识、策略版本和当前内容页签；列表保存筛选、排序、分页与必要滚动位置。直接打开详情时返回按钮有确定的列表落点。
- 策略详情返回按钮使用图标、可访问名称和足够点击区域；标题与业务状态组成首行，版本选择及主要操作位于其后的明确操作区。
- 从策略详情发起操作后的返回仍回到原策略版本；采纳/保存新版本成功后通过明确入口进入实际新版本。跳转和刷新本身没有创建、重跑或启用副作用。
- 中性底色、细分隔线、紧凑表格、克制蓝色主动作。状态与正负含义不只依靠颜色；现有告警严重级别仍清晰可读。
- 当前工作区突出一个主要提交动作。更多菜单承载次要操作；危险或放弃动作与主要提交保持区别。
- 不把 UUID、哈希、Provider 路由或大段 JSON 放进默认阅读路径；诊断中保留完整字段和复制能力。
- 同一选择控件的触发器与选项使用同一主标签映射；选项可增加次要说明，但不得让内部值成为触发器的用户可见回显。
- 策略修订版本、定义格式和业务状态是三个不同维度。定义格式不使用“正式”修饰，也不与策略修订号并列为同级版本标签。
- 1440×900 首屏符合 AC-10；窄屏收起次要列或换行，图表随容器重绘，必要宽表只在自身区域滚动。
- 复用原子类、现有组件及变体。涉及 shadcn 实施时先检查实际组件配置和文档；表单标签不触发默认激活，键盘焦点与可访问名称由共享组件规则保障。

## 5. 策略库与策略详情

### 5.1 策略列表

列表建议列为：策略、最新版本、状态、更新时间、操作。策略单元格包含名称及一行辅助说明，标的或适用范围应以可读信息展示。来源可作为轻量标签或筛选条件，不另建“AI 策略库”。

列表不再嵌入版本选择下拉。点击名称进入详情，操作区保留“查看”和更多菜单，回测等快捷操作必须明确其绑定版本。描述截断后可查看完整内容，不能依赖悬停才能访问关键信息。

常用桌面宽度下，不应因冗长描述或操作按钮导致整个页面横向滚动。窄屏隐藏次要列或切换紧凑行布局，不用固定列覆盖其他内容。

### 5.2 策略详情

页头显示策略名、来源、标的或适用范围及实际业务状态。返回图标、标题和状态位于同一标题行；选中版本使用可读选择器表达。主要操作为“开始回测”“AI 优化”“生成风险规则”，次要操作收纳到更多菜单。

所有操作携带当前版本的稳定标识，不能仅依赖界面上的 `v2` 文本，更不能由下游自行解析为最新版本。

默认摘要至少覆盖策略说明、执行标的与市场、主周期、入场条件、退出条件、仓位管理、风险约束及执行假设。已有字段使用紧凑分组或语义块组织，避免为单个短值占用整张大卡片。完整策略定义保留为次级展开内容，不能成为读取核心交易逻辑的唯一入口。

策略版本选择器以“策略版本 vN”为主标签；触发器和选项复用同一格式，选项可补充当前标记、来源与时间。版本 UUID 下沉到诊断信息。`schemaVersion` 只表示定义格式：V2 默认不展示常驻徽标；V1 仅在能力受限时显示“旧版定义”及受影响功能，不能把定义格式表述为已启用、已验证或已认可。

摘要适配器必须区分“定义确实未配置”和“已有定义暂时无法解析”。前者展示缺失项及动作限制；后者展示读取失败、重试或诊断入口。两者都不能伪造默认交易条件。

版本记录显示版本号、创建时间、来源、变更摘要。实验采纳来源跳转对应实验和候选；AI 辅助创建展示关联 Spec 定义的编写来源与审核记录，不伪造实验链接。编辑保存后提示创建了哪个新版本，并保留旧版本可访问性。

“未绑定标的”需要区分两种情况：允许参数化执行的通用策略，应展示“执行时选择标的”；必要配置确实缺失时，才展示“未配置”及相应阻塞说明。

### 5.3 风险应用记录

策略详情不设置“风险应用”页签；生成入口只保留在版本页头，避免与“生成风险规则”动作重复。已保存应用的账户、绑定版本、启停状态、更新时间、通知配置与升级提示统一在风险中心管理；策略存在新版本但应用仍绑定旧版本时，只显示更新提示，不直接覆盖。

## 6. AI 实验体验

### 6.1 实验列表

默认页只包含标题、简短说明、筛选、列表和“新建实验”。不默认展开创建表单。

实验应具有持久化的可读名称；默认生成“策略名称 · 优化目标 · 日期”，从零实验使用“标的 · 探索目标 · 日期”，允许用户在列表更多菜单或详情修改。名称只描述实验身份，不改变配置、冻结数据或评估结果。历史无名称记录采用可追溯字段生成显示标题，无法关联时使用“历史实验 · 日期”，不反推来源；克隆创建新实验并生成独立名称。列表主信息为名称、关联策略或“从零探索”、基线版本、创建时间；辅助信息展示模型、候选数量和阶段。

状态筛选、时间倒序和服务端分页为基础能力；按创建时间与稳定标识确定顺序，超过 100 条的历史仍可访问，筛选作用于全部记录。失败记录显示一行经过脱敏的真实原因摘要。调用次数、Token、费用进入详情，不以这些字段替代实验身份。

运行中的记录展示服务端提供的阶段和进度；没有可信总进度时只显示阶段，不制造百分比。取消、恢复或重试仅在既有状态机允许时出现，不能因为任务是 `failed` 就统一提供恢复按钮。

### 6.2 新建实验工作页

采用三步流程，切换步骤保留输入；返回前一步不提交实验。最终点击确认才创建任务，提交中防止重复操作。离开有未保存输入的页面时给予提示，不将表单草稿误当作已创建实验。

| 步骤          | 默认内容                                         | 次级内容                                   |
| ------------- | ------------------------------------------------ | ------------------------------------------ |
| 1. 策略与目标 | 优化已有策略或从零创建、基线、标的、周期、目标   | 允许修改的参数及已有 Schema 支持的取值边界 |
| 2. 模型与数据 | 模型选择、适用的推理强度、开发/验证/封存测试区间 | 精确日期编辑、模型路由详情                 |
| 3. 预算与确认 | 调用和回测预算摘要、初始资金、费用状态、配置确认 | Token 限制、计算时限、执行模型高级配置     |

从策略详情进入时锁定来源策略和具体基线版本，不再次要求用户从长列表识别同一版本。从全局入口进入时才选择模式和基线。

#### 模型配置

沿用现有最多 3 个模型的约束，搜索和展示以可读模型名称为主，Provider 为辅助信息。完整 Provider/Model 标识在详情或复制入口提供，实际请求仍使用原结构化标识。

推理强度只展示 Provider 声明支持的选项；不支持配置时以说明替代无意义的空控件。模型选择必须严格保留用户指定，不引入自动 fallback。

多模型默认共享相同评估数据、基线和执行假设。每个模型的失败与消耗独立可见；一个模型失败不能抹去其他模型已经产生的有效记录。

#### 参数与执行假设

止损、止盈等策略参数使用复选框或明确选择控件，不使用难以区分状态和动作的黑色按钮。

佣金、滑点属于执行假设，不作为默认允许 AI 优化的策略参数。基线与候选比较时固定这些假设，避免通过调低成本制造表面改善。成本敏感性分析不纳入本轮默认工作流。

初始资金及币种须明确。执行模型先显示当前配置或继承配置的摘要；JSON 编辑收纳到高级配置，提供格式与契约校验。高级配置是显式覆盖，不允许因留空而让用户误解为没有执行约束。

#### 时间划分

先展示三段连续区间及用途，再展开日期编辑。保持既有“三段连续、不重叠，下一段从上一段结束后的自然日开始”的语义；自然日边界与实际交易日覆盖分开表达。

确认页展示最终日期，服务端仍负责有效性和数据覆盖校验。推荐日期只是起点，不代表样本量已经足够，也不能默认把当前日期当成完整行情的截止日期。

#### 预算与费用

输入/输出 Token 字段必须明确是实验累计预算还是单次请求限制；存在两类限制时分开标注。显示配置限制、已消耗和估算费用时，不把不同口径放进同一个无标签的 `1132/2600` 数值。

费用或计费币种未知必须在确认步骤显著提示，并要求明确确认。此时禁用且不提交实验总金额上限，服务端拒绝同时携带未知费用配置与总金额上限的请求；调用、Token、回测和时长限制仍生效。涉及费用风险的模型或预算配置发生实质变化后，原确认失效。已知部分费用可独立展示，不能称为实验总费用。

已知的不同计费币种不能放在同一实验，服务端与前端共同校验；用户需拆开实验。仅全部费用及币种已知且币种一致时开放总金额上限。历史记录的无币种或混币种累计不能通过补一个当前币种变成可信金额，应显示“历史费用合计口径不可确认”，可恢复的单次费用按其记录币种展示。

模型费用必须标明计费币种，不与回测初始资金的币种混用。已确认零费用与费用未知使用不同文案，不能仅凭模型名称含有“free”就推断本次调用费用。

前端预算摘要不能替代服务端预算预留、结算和硬限制，表单折叠不得改变原有服务端约束。

### 6.3 实验详情

页头包含实验名称、来源/基线、模式、创建时间、状态和允许的动作。内容按“候选与评估 / 运行详情”组织，结果与技术日志分开。

运行中优先展示当前阶段、各模型状态和预算消耗。运行结束优先展示候选对比、失败原因以及锁定、测试或采纳等下一步动作。

候选对比采用表格，基线固定为对照行。核心字段为候选名称、主要变更、验证集收益、回撤、明确口径的交易数量、相对基线变化和评估状态。综合分可作为辅助信息，但必须能查看口径，不以未解释的长小数作为主结论。

只比较同一实验中具有相同评估口径的结果，不使用 AI 自述数值排名。表格支持查看参数差异和实际回测详情。展示值恰好相同不等于完全等价；只有精确结果或参数核验支持时，才标注“与基线一致”。

封存测试流程保持为：

```text
比较验证集 → 锁定预选候选 → 运行封存测试 → 揭示结果 → 确认采纳
```

系统开始使用封存数据即记录“测试集访问”，但访问不等于“结果揭示”。所有锁定候选与基线均完成测试后，统一自动揭示，不增加手动揭示步骤。已经得出不合格结论的测试属于完成，但不产生采纳资格；基础设施或数据请求技术失败属于未完成。

部分技术失败时，已完成部分保持隐藏，仅允许在原候选集合、预选候选、区间和数据指纹约束下重试未完成部分；已完成结果复用。原冻结依赖不可用时明确阻塞，不静默换数据或扩大候选集合。用户可放弃该批次，放弃不揭示部分结果，也不抹去已访问记录。

读取保护统一覆盖实验详情、比较、全局任务分组/摘要、回测详情直链、图表及导出；测试指标、完整结果和可推导评估结论的状态均在揭示前隐藏。可展示阶段、完成数量及脱敏技术失败原因，不区分未揭示候选的合格/不合格结论。保护归服务端，不能靠前端条件渲染或隐藏链接替代。

测试揭示后改选候选继续沿用既有曝光记录和限制。历史明确已揭示结果保持可访问；旧记录判定要结合既有完成与曝光证据，不能因缺少新字段重新隐藏。证据无法确定的旧记录保持限制并提供说明，不仅凭访问时间认定已揭示。

采纳资格由服务端的既有门槛决定。前端区分未完成、结构无效、执行失败、样本不足和测试曝光，显示准确阻塞原因，不用“实验完成”推断可以采纳，也不提供静默绕过。

## 7. 从策略库生成风险规则

### 7.1 入口与流程

唯一业务创建入口位于策略详情的具体版本。“生成风险规则”打开绑定该版本的单层 Drawer；风险中心保留管理入口及返回源版本的链接。

流程为：选择账户和生效范围 → 预览转换结果 → 确认保存或启用。策略名、版本和标的上下文始终可见，不再展示 UUID 策略下拉框。保存成功后关闭 Drawer 并保留源策略详情；查看、启停、通知调整、修订历史与升级继续在风险中心完成。

Drawer 内不打开第二层 Drawer。需要管理冲突应用或查看完整历史时，明确导航到风险中心；有未保存输入时，关闭、返回或切换版本均需确认。

默认配置展示账户、生效范围和通知开关；通知严重级别、冷却时间等收纳为高级设置。通知开关使用 Switch；单一可用通知渠道展示名称与配置状态，不做成看似可多选的按钮。

`existingAndFuture`、`warning` 等必须转换为准确的中文业务文案，完整原值保留在诊断信息中。

### 7.2 预览与确认

预览至少说明生成的规则、不能转换的条件及原因、当前账户与行情上下文、保存后是否立即生效，以及是否已有同源应用。

账户、策略版本、范围或会影响编译结果的配置变化后，旧预览失效，必须重新预览。不得提交与当前表单不一致的旧预览。

明确区分“保存为停用”与“确认启用”，复用现有 enabled=false 与 enabled=true 契约。停用应用是已经保存、可以管理的应用，不是额外的草稿生命周期。

同源应用身份由策略版本、账户、标的和生效范围共同确定，通知配置不属于身份。新建判重覆盖未归档应用：相同身份返回已有记录及查看/显式编辑入口，跨会话重复保存也不新增应用；重复请求仍受服务端幂等保护。

同账户、同标的仅允许一条未归档策略风险应用启用，不因策略、版本或生效范围不同而放宽。冲突时显示已有应用及源版本，允许新应用先保存为停用，启用前由用户处理原应用，不自动停用或替换。

历史重复记录全部保留可访问，不自动合并、删除或任意挑一条更新；发现多条同源记录时列出记录供明确选择，并阻止继续新增同源重复。历史归档记录保留追溯，不自动恢复。成功后进入风险中心对应记录，并保留源策略版本追溯。

源版本升级同样检查目标应用身份及当前修订；目标同源应用已经存在时返回查看/管理入口，不覆盖目标记录或制造新重复。

版本升级只提示可预览更新差异；用户确认前，已应用规则继续绑定原版本。

## 8. 回测任务列表与详情布局

### 8.1 回测任务列表

列表使用策略名或候选来源作为主要身份信息，显示版本/候选标识、执行标的、周期、区间、状态和创建时间。支持按策略及状态筛选，不以运行 ID 或 `completed` 作为标题。

点击一行进入独立回测详情页。同一详情页覆盖排队、运行、完成、失败、取消等状态，状态变化不应把用户切换到另一套弹窗结构。

### 8.2 元信息解析规则

优先使用任务创建时冻结的可读元信息，其次通过精确的版本或候选关联补齐。不能从策略当前最新版本推测历史回测身份，也不能将 AI 候选回测伪装成已入库策略。

| 情况             | 展示要求                                      |
| ---------------- | --------------------------------------------- |
| 已入库策略回测   | 策略名称、明确版本及返回该版本的入口          |
| AI 候选回测      | 实验名称、候选编号/名称、阶段及返回实验的入口 |
| 历史元信息未记录 | “来源信息未记录”等明确说明，诊断中保留现有 ID |
| 元信息请求失败   | 独立错误与重试，不伪装成历史缺失              |
| 正在加载         | 骨架或加载态，不短暂显示“未知策略”            |

执行标的取本次任务的实际配置；策略没有固定标的，不等于本次回测标的不可用。

### 8.3 页头与首屏

页头结构建议如下，具体尺寸按项目设计系统实现：

```text
返回回测任务
策略名称 · v2 / 实验名称 · 候选 1                    运行状态    操作
执行标的 · 周期 · 回测区间 · 基准币种
结果限制摘要：研究假设执行 / 数据缺口 / 样本提示（按实际存在显示）

结果概览    交易与订单    数据与假设    诊断与复现

累计收益       最大回撤       期末资产       已平仓交易数或明确口径的次数

                    可交互权益曲线
                    联动回撤曲线

次要指标与样本说明
查看权益时点明细（折叠）
```

页头可显示完成时间和耗时，完整数据时点、执行模型版本等进入对应详情。回测请求区间、实际行情覆盖区间、数据冻结时点、任务完成时间是不同概念，禁止用同一个日期标签混淆。

主要操作为查看源策略/实验、基于本次配置新建回测；其他操作进入更多菜单。基于配置新建固定原策略/候选版本、日期区间及已记录执行配置，重新获取当前可用数据并生成新任务。提交前说明数据修订可能导致结果变化；不覆盖旧结果，也不提供未经验证的原快照精确复现。历史配置缺失时定位缺失字段并要求显式补齐，不能用当前默认配置冒充冻结值；未揭示测试任务不提供配置克隆旁路。

在 1440×900 的桌面视口及正常浏览器缩放下，首屏应能看到身份、关键限制、核心指标和主图的一部分，而不是整屏执行模型长文。滚动时可保留紧凑标题与页签，不重复占用大面积高度。

### 8.4 运行与失败状态

运行中显示阶段、开始时间、耗时及已有进度信息。未经标记的中间产物不能显示成最终收益；没有结果时显示待完成状态，而不是零收益。

失败详情首先显示失败阶段、可读原因和允许的下一步。技术日志折叠并脱敏。有部分产物时标注“未完成结果”，不能继续显示“结果完整”。

取消与超时分别解释，保留可查看的执行记录。恢复、重试、取消遵守既有服务端状态机和操作资格。

## 9. 回测结果指标与语义

### 9.1 指标布局

核心区固定为一行紧凑指标，优先展示累计收益、最大回撤、期末资产和已平仓交易数。若当前契约只提供成交笔数，则如实展示“成交笔数”，不能冒充完整交易次数。

年化收益、波动率、夏普比率、胜率和利润因子进入紧凑的次要指标区，按实际存在的指标自然布局。不为了填满三列网格制造灰色空白单元格。

引擎名称、数据快照和哈希不属于收益指标，不混入指标卡。

### 9.2 数值格式

| 数据                       | 展示规则                                                         |
| -------------------------- | ---------------------------------------------------------------- |
| 收益率、回撤、波动率、胜率 | 确认原始口径后转换为百分比，默认保留 2 位小数                    |
| 最大回撤                   | 统一展示损失幅度的口径，并说明正负约定，不直接复制来源的符号差异 |
| 金额                       | 按任务基准币种格式化，千位分隔，不能全局写死 `CNY` 或 `¥`        |
| 夏普、利润因子等比值       | 有限有效值默认保留 2 位小数；完整值保留于详情或导出              |
| 换手                       | 先明确金额、比率或次数，不能在原始数字后直接补 `%`               |
| Token、次数、数据点        | 整数分隔并标明口径                                               |
| 时间                       | 使用明确时区；日线保留日期，分钟或成交记录显示必要时间精度       |

显示舍入不得改变排序、评分、比较或导出中的原始精度。前端不重新计算年化、夏普或策略评分来“修正”展示。

### 9.3 不可用值与样本提示

真实零值、缺失、计算条件不满足、错误必须区分。`null`、非有限值和请求失败不能默认转成 `0`；不能因为曲线缺失而将回撤回退为 0%。若服务端汇总指标有效、仅曲线不可用，可以独立展示汇总值并说明曲线状态。

例如服务端返回 `NO_LOSING_TRADES` 时，利润因子主值显示“—”，辅助说明“无亏损交易，无法计算有限比值”，原始原因码进入诊断。不能擅自改成 0、一个巨大数字或无解释的无穷大。

界面应展示可靠的已平仓交易数、权益观察点数等样本上下文。只有确实存在 1 笔已平仓交易时，才显示“仅 1 笔已平仓交易，胜率等统计参考有限”；不能把 1 笔成交等同于 1 次完整交易。

短区间年化或服务端给出的样本不足警告应可见，但本轮不新增未经定义的可靠性评分，也不因视觉效果擅自改变质量门槛。

## 10. 权益与回撤交互图表

### 10.1 布局与数据来源

主图全宽展示组合权益，下方以较小高度展示回撤，二者共享时间范围。不要继续把两张没有刻度的静态线图并排放在同等尺寸的空白卡片中。

默认使用现有权威权益金额序列。累计收益视图只在有权威收益序列，或满足明确的无外部资金流归一化条件时开放；存在资金流时不得直接用权益增量冒充投资收益。

回撤优先使用已有权威序列。需要从完整权益序列派生时，应在实施前核对既有口径，并将其限定为展示层派生；不得替换服务端最大回撤指标，也不得从抽样后的图表点重新计算正式指标。

如果数值口径或所需数据不充分，禁用对应视图并说明原因，不为完成 UI 随意补齐曲线。

### 10.2 必须支持的交互

| 编号  | 交互           | 验收行为                                                                    |
| ----- | -------------- | --------------------------------------------------------------------------- |
| CH-01 | 时间轴与数值轴 | 时间、币种/百分比刻度清楚；数值不截断，轴范围不制造不存在的波动             |
| CH-02 | 联动十字线     | 指向任一图时，两图定位同一真实时间，显示权益与回撤；该时点缺值则明确缺失    |
| CH-03 | Tooltip        | 展示日期/时间、序列名、单位和真实数值；触屏可通过点按访问，不只依赖鼠标悬停 |
| CH-04 | 区间选择与缩放 | 支持范围选择器或拖选缩放，图表共同响应；用户能观察局部区间                  |
| CH-05 | 平移与重置     | 放大后可平移，有明确“重置范围”；切换任务恢复该任务默认范围                  |
| CH-06 | 响应式与主题   | 容器变宽、侧栏收起、页签切换、浅深色切换后正常重绘，文字与曲线可辨识        |

图表不应无条件拦截页面滚轮。滚轮缩放仅在明确聚焦或辅助键模式下生效；范围选择、缩放按钮和重置构成不依赖滚轮的操作路径。

区间快捷项应受真实数据范围约束，不显示不可用的“一年”等预设。图例应能区分曲线，不能只靠颜色传达含义。

缩放只改变可见区间，不修改页头的全任务指标，也不从可见起点重置回撤的历史高点。将来增加局部区间统计时，必须另行标注范围与口径，不覆盖全回测结果。

### 10.3 条件增强

有可对齐的基准序列时允许叠加比较，但必须满足区间、币种和收益口径一致；无数据时不出现虚假基准或占位曲线。AI 实验的“基线策略”与行情“比较基准”使用不同标签。

有真实成交事件时，可开关买卖标记；点击标记定位交易记录。标记过密时聚合或在局部缩放后展开，不让标记遮蔽主线。不得从权益变化推测买卖点。

现金、持仓市值等只能在对应时点数据确实存在时进入 Tooltip 或辅助展示，不从单条权益线猜测持仓状态。

### 10.4 数据真实性与性能

按真实时间戳或明确的交易时点顺序绘制，并统一时区。有可信缺口位置或区间证据时，缺口应断开或显式标记；不能补零，也不能把未返回日期补成横线。仅知道结果不完整、无法定位缺口时，展示已记录点，明确“缺口位置未记录，连线不代表区间数据完整”；不得按相邻日期间隔猜测断点。非交易日与缺失行情不是同一种情况。

如果真实权益在退出持仓后保持不变，应如实绘制平直曲线；如果平直来自数据缺失，应展示缺口。曲线形状不是判错依据，需结合成交、现金、持仓和完整性信息核验。

大量数据可以使用保持首尾与极值的渲染抽样，但保留完整原始序列，不能以抽样点重算正式指标。缩放与悬停应能定位可用的真实点，抽样展示不得伪装成完整逐时点数据。

图表库优先复用项目已有能力；确实需要替换时仅替换该图表层，不同时迁移全站图表或引入第二套设计系统。实施前核对依赖与许可。

### 10.5 权益时点表

从独立主内容改为图表下方的“查看权益明细（N 个时点）”折叠区，默认关闭。

展开后分页展示日期/时间、组合权益，以及现有数据支持的现金、持仓市值、回撤等字段。默认每页 25 条，可切换 50 条，不一次铺开全部数据。

提供“导出当前筛选区间”时，应导出该区间所有匹配行而非只导出当前页，并明确时区、币种和字段口径。数据不完整时说明导出范围，不宣称导出了全部历史数据。

## 11. 交易、数据与执行假设

### 11.1 交易与订单

按既有数据区分已平仓交易、成交流水、委托和拒单。某类数据不存在时不构造替代记录，也不把订单数、成交数、完整交易数混用。

表格突出时间、方向、数量、价格、金额、费用及状态。长 ID 进入行详情或复制入口。拒单使用可读原因，技术错误进入展开诊断。空态区分没有成交、尚未完成和数据获取失败。

### 11.2 数据与假设

使用分组键值信息呈现本次冻结配置，至少覆盖现有契约支持的以下内容：执行模型名称与版本、适用市场/币种/时区、请求区间和实际覆盖、费用与撮合假设、规则支持和数据缺口、来源引用。

长来源说明、规则分段、研究假设全文归入此页，不放在所有页签之前。采用摘要与按需展开，而不是一个字段一张大卡片。

不过，影响结论的限制仍须在结果首屏保留紧凑提示，例如“使用研究假设执行，并非完整历史事实复现”。这类提示不能与哈希一同隐藏到深层诊断中。

“结果完整”“行情覆盖充分”“执行假设已记录”“历史规则有事实支持”是不同维度。若现有接口只提供其中一项，不能通过成功状态替其他维度背书。

来源链接使用可读标题、可复制地址和安全的外链行为。展示冻结时适用的信息，不能用当前 Provider 配置覆盖历史回测条件。

## 12. 哈希、内部标识与诊断信息

### 12.1 保留什么，为什么保留

哈希和校验和对判断两个产物是否一致、排查版本差异和校验内容有用，但不帮助普通用户直接理解收益，也不能证明回测逻辑正确、历史事实充分或一定可复现。

因此，本轮调整的是展示层级，不删除底层追溯数据。精确复现还依赖可访问的数据快照、执行模型、策略定义、引擎等条件，不能仅凭存在哈希显示“可完整复现”。

| 信息                                        | 默认展示位置           | 操作               |
| ------------------------------------------- | ---------------------- | ------------------ |
| 策略名称、可读版本、来源                    | 页头与策略入口         | 跳转源版本或实验   |
| 研究假设、缺口与关键限制                    | 首屏摘要及“数据与假设” | 展开解释           |
| 执行模型与引擎可读版本                      | 数据与假设/诊断摘要    | 查看冻结配置       |
| 策略版本 UUID、任务 ID                      | 诊断与复现             | 缩略展示、完整复制 |
| 数据快照 ID、内容哈希、模型哈希、结果校验和 | 诊断与复现的分组键值表 | 完整复制、导出     |
| 日历、市场规则、聚合版本                    | 诊断与复现             | 查看版本与引用     |

### 12.2 展示方式

“诊断与复现”默认展示一段用途说明和紧凑摘要，技术字段按“策略与任务 / 数据与执行 / 结果校验”分组，需要时展开。

长值可显示为前 10 位加省略号和后 6 位；点击复制必须得到完整值，并明确反馈成功。全值可展开查看，窄屏允许安全换行，不撑破布局。

相同值可以在一个分组中减少重复视觉输出，但不同语义字段不能仅因字符串相等就删除或合并为同一事实。例如数据快照标识与内容哈希仍保留各自字段名及导出路径。

缺失字段显示“未记录”，不显示 `undefined` 或空白大卡片。不要在页头、结果摘要和诊断页重复展示同一串长哈希。

### 12.3 复制与诊断导出

提供“复制诊断摘要”和“导出诊断 JSON”。诊断 JSON 使用明确的导出格式版本，包含已有的任务身份、精确版本引用、冻结配置摘要、指标及不可用原因、版本/哈希和缺口说明。

导出只使用允许清单中的字段，不直接序列化完整请求对象、日志对象或 Provider 配置。排除 API Key、鉴权头、Cookie、带凭证的 URL 和无关账户信息；错误消息也需要脱敏。

诊断导出不是完整数据快照包。只包含引用时，应说明还需要哪些原始产物；没有验证依赖可访问性时标记“未验证”，不声称下载文件即可复现。

## 13. 通用视觉与可访问性

采用中性灰为主体、克制蓝色为交互强调，不新增绿色或紫色主题。风险提示可使用橙/红辅助色；数字默认保持中性色，正负与状态通过文字、符号和单位共同表达。

主操作、普通操作、状态标签、复选项和开关使用不同组件语义，不继续全部使用相似黑色胶囊。一个工作区只保留清晰的主要提交动作，危险操作不抢占视觉中心。

复用现有字体、间距和控件规范，减少卡片套卡片。主工作区以标题、留白和分隔线分组；哈希、枚举和 JSON 仅在技术详情中使用等宽字体。

表单标签、提示和错误位置稳定。同一行字段对齐，长标签不造成输入框高低不齐；金额、时间和限制字段明确单位。

所有禁用动作应在附近说明阻塞原因，错误尽量定位到相关字段。请求失败可重试，加载、空数据、权限不足、数据缺失分别处理。

键盘可完成导航、表单、分页、复制、展开与基本图表范围操作；有明确焦点状态。关键信息不能只藏在 hover 中，图表提供表格替代访问。

浅色与深色模式都要覆盖表格、Tooltip、弹层、提示和图表，不能只更换背景色。桌面侧栏展开/收起及窄屏下不出现全页横向溢出；必要的宽数据表仅在自身区域滚动。

## 14. 实现边界与兼容性

### 14.1 前端职责

前端负责页面组织、导航状态、表单分步、已有字段的规范化展示、图表交互和诊断信息分层。可建立共享展示适配层，统一中文状态、数值、时间与缺失原因映射，避免 AI 候选和回测详情各自维护不同解释。

展示适配层不能改变服务端事实、质量门槛、预算限制、候选评分、封存测试状态或风险编译结果。任何为图表进行的展示派生都应有明确口径及测试。

### 14.2 必要的契约补齐

实施前检查元信息、版本来源、阶段、费用口径、指标不可用原因、数据质量和采纳资格是否已可读取。已有字段先复用，不假定本文件中的业务名就是当前 DTO 字段名。

若缺少显示必需信息，可增加向后兼容的只读字段或精确关联查询。列表元信息避免逐行重复查询；历史记录无法恢复的信息如实显示缺失，不从当前最新配置补造。

复用已有采纳幂等、风险停用保存和预览一致性能力；针对统一揭示读取保护、陈旧基线确认、实验名称与分页、费用币种及同源应用判重建立窄范围契约补齐任务。同步统一共享类型及首次/重放返回结构，不借机重构整个状态机。

未经本轮确认，不修改 DSA Contract、指标算法、冻结产物格式或已有业务状态语义。

### 14.3 数据与行为兼容

历史回测、失败实验、已采纳候选、已经揭示的封存测试、已应用风险规则继续可访问。导航迁移不触发重跑、重采纳、重新曝光或规则重新生成。

旧记录允许缺少新增显示字段，采用明确降级文案；不得因为缺少策略名称而导致整个结果页面不可用。

浏览器刷新、前进后退、网络重试和重复点击不应创建额外任务或版本。需要真实服务端幂等保证的地方，不能只依靠前端按钮禁用。

新增名称与读取契约采用保留数据的扩展迁移，不修改历史 migration、冻结结果或追溯来源。历史名称缺失采用读取降级；历史重复应用、已揭示结果和混币种费用按上述兼容规则保留。不得直接建立会因历史重复而失败的全量唯一约束后再清理数据；先盘点并设计保留历史、约束新写入的并发保护。涉及结构变化时同步 migration matrix、raw-owned inventory、runtime 打包输入及部署结构门禁；本轮文档工作不执行迁移或开发清库。

## 15. 验收标准

### 15.1 核心验收场景

| 编号  | 场景               | 通过标准                                                                                                                                                 |
| ----- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-01 | 手动创建策略       | 保存后进入策略库，能定位新版本，并使用相同的回测、AI 优化和风险入口                                                                                      |
| AC-02 | AI 实验从零探索    | 候选未采纳前不出现在策略库；采纳成功后生成策略，双方有来源链接                                                                                           |
| AC-03 | AI 优化已有版本    | 采纳产生原策略新版本；实验期间另有新版本时不覆盖、不静默改变基线                                                                                         |
| AC-04 | 重复采纳与刷新     | 不产生重复策略/版本；已采纳状态与目标版本可恢复                                                                                                          |
| AC-05 | 风险规则入口       | AI 页无独立风险表单；从明确版本打开单层 Drawer 预览并应用，风险中心可返回源版本                                                                          |
| AC-06 | 风险应用变更       | 修改账户/配置会使旧预览失效；策略升级不自动更新已有规则                                                                                                  |
| AC-07 | AI 实验信息密度    | 默认页是可筛选分页列表；创建和候选详情不在列表下方连续堆叠                                                                                               |
| AC-08 | 模型与预算         | 严格保留 Provider/Model；Token 口径明确；未知费用需确认且不冒充免费                                                                                      |

### 15.2 必测数据样例

使用固定测试数据覆盖正常结果、空序列、单时点、全程平直、含缺口、有限负收益、真实零回撤、指标不可用、仅 1 笔已平仓交易和没有已平仓交易。不能只用一条漂亮的上升曲线验收。

至少覆盖 50、250、5,000 个时点，检查渲染、缩放、悬停和表格分页；若现有支持更大分钟级数据，沿用其规模补充性能检查。覆盖日线与带时区的分钟/成交时间，以及 CNY、HKD、USD 的币种展示。

流程样例覆盖全模型失败、部分模型失败、预算耗尽、费用未知、测试已曝光、采纳前基线变旧、风险预览失效、历史元信息缺失及接口失败。

### 15.3 验证方式

格式化、状态映射、缺失值、时间对齐、范围计算和脱敏导出使用单元测试。导航上下文、重复提交、候选采纳、风险预览失效和隐藏测试信息使用集成测试。

浏览器验收聚焦策略详情、AI 三个视图、正常回测详情和失败回测详情，覆盖关键主题和窄屏代表场景；必须从真实导航入口点击“编辑当前版本”“新建 AI 实验”和“生成风险规则”，不得只直接渲染叶子组件；不以全量重复截图代替数据与契约测试。

最终交付应附具体已验证场景、截图或测试结果，以及尚未补齐的契约项。不能仅凭页面能打开或构建通过，就标记全部验收完成。

额外必测：实验历史超过 100 条、相同创建时间的分页稳定性、运行详情直接打开后自动显示终态结果、SSE 断线恢复、采纳确认后当前版本再次变化、首次响应丢失后幂等重放、跨会话保存同源停用应用、未知费用与币种组合、封存部分完成时经每个读取和导出入口访问；策略摘要分别覆盖完整定义、真实缺失和解析失败，版本选择覆盖触发器/选项一致性，路由测试覆盖离开保护与渲染错误降级。

持久化/状态与读取保护、执行面恢复、客户端消费、部署验收分别记录证据。结构与同步 API 在隔离 PostgreSQL 验证；真实 Server/Worker/Provider 路径及目标 Docker 的浏览器闭环另设门禁。受影响源码与启动输入稳定、低成本检查通过后，按 infra 更新入口使目标运行态匹配源码。当前已知新增持久化预计需要 `./scripts/update.sh thesis-ledger`，执行前仍以实际差异和预检为准；文档生成不执行部署。

## 17. 完成定义

用户可以从策略库定位一个具体版本，发起回测或 AI 优化，查看可交互且语义清楚的结果，采纳后回到同一策略体系，并从该版本预览生成风险规则；全过程中版本来源、研究限制和任务状态可追溯。

普通用户不再必须阅读 UUID、哈希、Provider 内部路由或长执行模型说明才能完成操作；需要排查问题时，又能完整获得已有诊断证据。

完成 UI 重组不等于回测算法被重新验证，也不等于研究结果自动具备投资有效性。未完成的契约或验收项必须明确记录，不能以简化界面为由隐藏。
