# 旧路由继承无损整理

状态：已实现并完成本范围验收。任务见 [实施清单](../archive/tasks/2026-11-10-routing-legacy-inheritance.md)，验证见 [验收记录](../evidence/2026-11-10-routing-legacy-inheritance.md)。更新 [分级路由](2026-11-09-hierarchical-market-routing.md) 和 [细分编辑](2026-11-09-market-routing-inline-editor.md) 的当前继承合同。

## 目标与边界

当前编辑模型只保留大类默认及完整精确项。旧市场、标的类型、用途、周期规则不再作为隐藏的当前继承层；其对已纳入精确项的有效设置无损展开为单项例外。保留当前主备顺序、具体来源、明确未配置及已有精确例外；不凭目录新增能力或第三来源。

- AC1：Market 持有纯整理投影。旧获胜规则被展开为对应精确项，大类默认及已有精确规则保留；整理幂等，输入、能力键和来源不变。保留绑定与新获胜规则对应，整理前后在同一目录下编译结果等价，包括来源不可用及多接口场景。
- AC2：读取仅返回整理后的编辑投影及待整理数量，不写数据库或切换实际路由。预览及保存也整理旧客户端输入，服务端继续使用可信保留绑定；不能通过请求伪造来源。元数据、精确路由和新历史仍原子保存，既有历史和冻结记录不改写。
- AC3：存在待整理旧规则时，未编辑来源也可预览保存，预览明确列出整理数量，并将来源变化与配置整理分开。正常来源调整及新能力确认保持；保存后待整理标志清零。修订冲突、预览失效和应用重试沿用既有流程。
- AC4：细分项只有单独设置或继承大类两种状态，“使用上级配置”直接删除单项例外并恢复大类配置。大类只选择提供方，按各精确能力匹配来源；具体来源在精确项选择，不生成非法的大类来源绑定。普通大类选择保留已展开的单项例外；明确采用建议主备时，按[可用来源推荐合同](2026-11-10-routing-available-recommendation.md)逐项生成本类全部子项的主备和精确绑定。
- AC5：定向验证整理、显式空值、精确来源、幂等、可信保留、修订冲突和失败恢复；隔离 PostgreSQL 验证整理结果及历史原子保存。Desktop 构建、Server 包级检查、仓库门禁通过后，使用维护脚本同步最小运行态并验证真实读取、原样预览与四宽浏览器。真实业务配置只读，保存与故障使用受控响应或隔离样本。

## 所有权与兼容

Server Market 拥有旧规则整理及编译；共享 Schema 只维护精确范围形状和兼容的读取/预览字段。Desktop 消费规范化编辑模型，不复制服务端迁移算法。继续使用现有版本和精确路由协议，无数据库结构、DSA 或依赖调整。

旧元数据在读取时不被覆盖，用户预览保存后完成当前配置整理；历史修订继续保留原始内容。新增读取字段采用兼容默认值，旧精确入口及历史编译仍可解析原层级格式。
