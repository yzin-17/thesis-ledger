# 现金账户资金范围与内部划转 Spec

- 日期：2026-08-30
- 状态：已实现并验证
- 适用项目：`thesis-ledger`
- 类型：增量设计

## 背景与问题

当前每个账户都能保存现金余额，但 `type=cash` 仅限制持仓录入，仍会被全部账户估值、收益和目标配置聚合。系统也只有现金余额观察写入，没有可供用户调用的现金流专用命令和跨账户原子划转。用户需要把独立现金账户作为工资等资金的承载容器，并在需要时与证券或基金账户双向划转，同时不让独立现金余额进入投资组合收益口径。

## 目标

1. 将独立现金账户定义为投资组合之外的资金账户，同时保留账户数据中的余额和流水查询。
2. 提供可审计、可更正、幂等的外部现金流命令。
3. 提供独立现金账户与证券或基金账户之间的同币种原子划转。
4. 防止账户聚合口径变化制造虚假的历史收益。
5. 在现金账户页面提供一次性外部现金入账入口。

## 非目标

- 不连接银行或券商执行真实转账。
- 不支持证券转移、跨币种划转、影子账户划转或任意两个投资账户互转。
- 不新增工资卡、账户用途或持久化 Portfolio 模型。
- 不把工资扩展为独立现金流类别；工资仍是带业务名称的外部 `DEPOSIT`。

## 现状与约束

- `Account.type` 为 `securities | fund | cash`，所有账户都是 Position、Ledger、Cash 和 Snapshot 的根。
- 通用 Ledger 写入入口已停用，必须新增专用 V2 命令。
- Ledger Repository 已支持按稳定顺序锁定多个账户并在一个事务中推进各自 Revision。
- `PortfolioSnapshot` V2 任务尚未实现；当前快照只能通过 payload 标记账户口径。
- 证券和基金账户自己的现金必须继续参与投资组合估值、配置和收益。

## 设计方案

### 投资组合范围

投资组合范围只包含真实模式下启用的证券账户和基金账户。显式查询某个现金账户时仍返回其余额、现金流水和账户级数据。Portfolio、Performance、目标配置、组合快照和自动快照使用同一个账户范围模块，调用方不再各自推断。

新组合快照 payload 写入 `accountScopePolicy=investment-only-v1`。旧组合快照缺少该标记时继续可见，但不得与新口径快照共同计算 TTWROR、XIRR 或区间收益；接口返回不兼容原因，不删除或重算历史事实。

### 外部现金流

`CASH_FLOW` 继续使用方向与类别表达现金变化。创建、更正、作废和恢复均为专用 Ledger V2 命令，使用规范十进制字符串、来源外部 ID、预期 Ledger Revision 和 Revision 链。余额观察仍只表示绝对余额检查点，不代替现金流。

Desktop 现金页为真实现金账户提供一次性「现金入账」入口。用户填写金额、预计或实际到账时间和可选备注后，写入 `CASH_FLOW / INFLOW / DEPOSIT`；该入口表示外部资金进入，不与账户间划转或现金余额快照混用。未来时间使用预计生效时间表达，在时间到达前只显示为待结算应收，不计入已结算余额。现金快照与现金流的时间边界见 [`2026-09-03-cash-snapshot-projection-optimization`](2026-09-03-cash-snapshot-projection-optimization.md)。

### 内部现金划转

一次划转只允许一个启用的真实现金账户与一个启用的真实证券或基金账户参与，两个账户模式和币种必须一致。命令在同一数据库事务中写入：

- 源账户：`CASH_FLOW / OUTFLOW / TRANSFER`；
- 目标账户：`CASH_FLOW / INFLOW / TRANSFER`。

两个事件拥有不同 `factId`，通过共同 `transferId`、对手账户 ID 和方向关联。命令只消费已结算余额，余额不足时两端都不写入。创建、更正、作废和恢复必须始终成对执行，不能单独修改一侧。

## 对外行为或接口变化

- 新增外部现金流创建、更正、作废和恢复命令。
- 新增内部现金划转创建、更正、作废和恢复命令。
- 命令响应沿用 `LedgerCommandResponseV2`，同时返回受影响账户的 Ledger Revision 和 Projection Generation。
- Desktop 在账户数据现金页提供一次性现金入账和手动划转入口；划转更正和作废需要原因。

## 数据、状态或兼容性影响

- `CASH_FLOW` 的 `TRANSFER` payload 必须携带 `transferId`、`counterpartyAccountId` 和 `leg`；非 TRANSFER 现金流不得携带该对象。
- 既有现金账户不修改数据，只改变组合级读取范围。
- 旧组合快照保留为旧口径证据；当前摘要只使用同一 `accountScopePolicy` 的连续序列。

## 测试策略

- Schema 测试覆盖现金流与划转命令、payload 严格性和非法账户组合。
- Server 测试覆盖双账户原子性、余额不足、并发 Revision、幂等重放和成对修正链。
- Portfolio/Performance 测试覆盖独立现金账户排除、投资账户现金保留和快照口径隔离。
- Desktop 测试覆盖现金入账和划转表单、未来资金待结算、错误反馈、关闭后状态清理、成功后的查询失效和审计入口。

## 风险与备选方案

- 直接用两个无关联 `CASH_FLOW` 会在并发或失败时产生单边余额，故拒绝该方案。
- 使用账户用途字段能表达更复杂范围，但用户已确认不新增该概念；本版按 `type=cash` 统一排除。

## 验收标准

- AC1：组合级估值、配置和收益不包含独立现金账户，但仍包含证券和基金账户的现金余额。
- AC2：显式打开现金账户时可以读取其已结算余额、待结算金额和现金流水。
- AC3：外部入金确认后形成可审计的 `CASH_FLOW / INFLOW / DEPOSIT`，重复请求不重复写入。
- AC4：现金账户与证券或基金账户的同币种划转原子更新两端余额，余额不足或任一校验失败时两端均不改变。
- AC5：划转更正、作废和恢复始终成对执行并保留 Revision 链。
- AC6：旧口径组合快照不与新口径快照共同计算收益，历史记录不被删除或静默重算。
- AC7：Desktop 可完成一次手动双向划转并在失败时保留输入。
- AC8：Desktop 现金账户可完成一次性外部现金入账；提交后写入一次 `CASH_FLOW / INFLOW / DEPOSIT`，未来时间通过预计生效时间进入待结算应收且不计入已结算余额，成功或关闭后不残留表单状态。
