# 基金分钟估算的复权价格口径

承接[原走势 Spec](2026-09-07-portfolio-valuation-series.md)“使用复权后的底层证券价格”及[原 R3](../archive/tasks/2026-08-28-portfolio-snapshot-system.md)。对应[实施 Task](../archive/tasks/2026-10-21-fund-adjusted-returns.md)。本轮主线程实施，保留全部旧数据，只验 Web，真实模型暂停，DG3 保持 TODO；沿用户已给出的验收授权接续。

## 问题与价格边界

现行分钟消费以原价 Quote 除以不复权日线锚价；分红、拆股等价格坐标变化会被误计为基金损益。刚完成的真实基金样本中报价与锚日价格相同，没有跨该边界，不能替代复权场景验证。

不能仅把锚价改成 qfq 后继续与原价 Quote 相除。DSA 的 `SourcePriceBasis` 可能为 provider-defined、`conversionAvailable=false`，不能从两个 OHLC 数值自行推导并冒称已核实的原价/复权转换因子。

## 消费规则

1. 原价 Quote 继续用于验证底层证券当前可用及定位报价所属交易日；价格必须有限正数，`marketTime` 必须已知且位于本估值分钟上界内。不以抓取时刻填补未知市场时刻。
2. 按底层证券所属 `CN/HK/US` 日历、市场时区和首个常规开市时刻确定报价对应的最近已开市交易日；周末、节假日及盘前回退至上一交易日。日历未知或覆盖不足时该证券不可定价，不猜测工作日。
3. 请求同一份 `qfq/1d` 序列，从 NAV 锚日前七日到上述报价交易日。收益率只使用这份序列内“精确 NAV 锚日收盘”和“精确报价交易日最新可用收盘”：`adjustedCurrent / adjustedAnchor - 1`。不跨原价/复权坐标，不以任意更早日期代替缺失的锚日或当前日；同一日可为零变动。
4. 返回序列必须绑定精确证券、日线、qfq，且携带相符的 `chartContextV3.sourcePriceBasis`。两点均须有限正数、可用时刻不超出本分钟上界，保留当前日 complete/incomplete/unknown 状态和来源原语义。允许读取已知陈旧观察的既有边界保持；缺失对应日期或价格口径时按缺价持平、排除定价覆盖，不回退原价。
5. 原始 Quote 值不参与复权收益率运算；使用可得的 Provider 复权日线收盘，不能宣称精度高于该来源更新频率。保存报价时刻、对应交易日、两点日期/价格、序列 fingerprint 和原始价格口径，标明估算。
6. 零权重继续不请求底层数据。未披露/缺价比例不归一，原 NAV、披露日期资格、正式校准链和实际账本单位保持。

## 验收与部署

- A1：先用合法合同输入复现跨分红、拆股和基准缩放的旧误算；修复后同一复权序列计算正确，与原价报价绝对水平无关。非零收益、缺日期、错误身份/口径、零值、未知/未来时刻和日历边界都有定向覆盖。
- A2：旧零 NAV/零价、未知披露、零权重和原部分覆盖回归保持；收益模块、类型/构建及相关工程门禁按层级验证。
- A3：正式脚本同步最小目标，核对原数据、实际加载代码与模型计数。只改变 Server 消费代码时使用 `sync-code.sh thesis-ledger`；不增加依赖、结构或来源配置。
- A4：复用输入未变的已合格 NAV/披露证据，另行冻结有限复权行情验收预案；真实 qfq 输入、目标当前点及 Web 独立验证。原样本失败及原价分钟点保留为历史，不覆盖或伪称已按新算法生成。新验收账户结清停用，路由及原页面选择恢复。

## 有限目标预案

复用已完成 I10 的 `passed` 回执中两份合格 NAV/持仓原响应，校验完整回执摘要、标准结果与原响应相等、精确基金/来源/日期资格、无 fallback 或 Server 缓存替代及观察不超过 24 小时。保留原观察时刻与当时质量，不把它们描述为重新读取的最新响应；分钟锚值允许已知陈旧观察的原边界保持。本次不重新请求基金 SDK、不写任何路由或来源配置。

只对同一 74 项观察中的 20 项正权重证券，各最多一次当前报价和一次 qfq 日线 Server 读取；共最多 40 次证券数据读取，零权重不请求。先由实际编译 helper 只读核对精确价格日期和复权口径，覆盖低于 50% 时不创建账户，保留来源失败，不追加探针。

合格后新建专用 `fund/actual/CNY` 账户，正常入金 1000、买入 100 × 1.25；只采两个真实当前维护分钟并保留来源价格证据，重复消费本次观察不重新请求来源。Web 只读核对估算口径、金额、覆盖率和质量后恢复原偏好；正常卖出、取回 1000、可恢复停用，保留四条审计及新点。原十个账户、四个既有分钟点、日级修订、13 张保护表/57 个 V3 结果和模型计数保持。

## 当前可得数据的估算误差测量

原走势 AC9 还需要实际基金样本的估算误差记录。同价当前点只证明锚日边界，不能冒充跨日误差。使用已经保留的真实 `2026-10-19 → 2026-10-20` 复权序列及 74 项披露，另取 10-19 的一个正式 NAV 点，与已合格的 10-20 正式 NAV 比较。

测量发生于当前可得时点，采用明确标识的保留观察基准：`估算 NAV(10-20) = 正式 NAV(10-19) × (1 + Σ原权重 × 同序列 qfq 收益率)`，输出绝对误差、相对误差、未披露/缺价比例和全部指纹。该基准计算不创建或回填历史分钟点、不修改日级修订，也不宣称历史 PIT 或曾在过去实盘运行；原精确披露仍未知，核对时钟保持。实际估值时点使用的最近 NAV 选择逻辑不改变。

有限执行只临时追加现有 `efinance/eastmoney` 的 `FUND_NAV_HISTORY` 一条路由，最多一次 Server GET，窗口精确为 2026-10-19、limit=1，先保存原响应。基金当前值、持仓、报价和 qfq 序列均复用已通过的输入，不重新请求；来源/凭据不变。成功或失败恢复原 16 条路由，政策修订号递增，允许该基金 NAV 正常缓存。没有新增账户、Ledger、快照、分钟点或模型请求。

原 Spec 没有数值误差阈值，本测量记录实际误差与方法局限，不自行设阈值或宣称任意误差均可接受；对账结果按原 AC 的实际证据范围判定。
