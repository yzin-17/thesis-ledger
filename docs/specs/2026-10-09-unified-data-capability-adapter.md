## 1. 目标：按能力使用数据，而不是按供应商使用数据

**业务调用统一数据能力；数据源适配器负责实现这些能力。业务无需识别供应商 API、SDK、字段或消息格式。**

两种扩展分别验收：

| 扩展类型               | 应当新增的内容                                                      | 不应反复修改的内容                              |
| ---------------------- | ------------------------------------------------------------------- | ----------------------------------------------- |
| 新来源实现已有能力     | 来源定义、能力绑定、适配实现、样例与合同测试；必要依赖或认证支持    | 业务组件、业务计算、公共 Runtime 中的供应商分支 |
| 首次新增数据能力       | 一次性定义该能力的强类型契约、校验、处理器及必要 API/界面；来源实现 | 已有能力的合同、账本和不相关功能                |
| 已支持能力新增另一来源 | 实现同一能力接口，登记精确范围并通过相同测试                        | 该能力的标准模型、产品 UI、公共生命周期机制     |

“快速接入”以修改范围和可复用验收衡量，不承诺任意 SDK、权限或全新数据语义零成本。新增协议类别、认证机制、市场规则或产品界面有必要建设成本，必须明确归属，不能隐藏为适配器特殊参数。

## 3. 三个边界：能力契约、来源适配、公共执行

```text
ThesisLedger 页面 / 研究 / 风险等消费者
                 │ 只依赖标准能力和数据语义
       Server Market 能力入口与读模型
                 │ 现行版本化 Data / Control 边界
          DSA 公共执行器 + 已保存路由
                 │ 按能力绑定选择实现
      数据源 A 适配器       数据源 B 适配器
                 │ 各自 API / SDK / 推送协议
```

这是一组职责边界，不要求新增三层服务或为每一步增加转发类。

### 3.1 标准能力契约

每项能力拥有稳定标识、契约版本、请求/结果 Schema、必要语义、错误约束和可复用合同测试。标准类型不包含供应商原始 DTO，不反向依赖适配器。

能力内可分别声明 `query` 与 `subscribe` 操作；可以复用数据模型，但生命周期和状态事件不同。一个来源可以只实现查询，未提供订阅时明确不支持，不能由方法存在或空实现推断可用。历史分钟查询不是实时盘口订阅，不要求先实现订阅框架才能使用。

公共包保留强类型，边界输入用 `unknown` 加实际 Schema 校验；泛型只承担类型关联，不能用 `any` 或无约束字符串入口绕过合同。DSA 与 TypeScript 侧通过既有契约发布方式同步，并用同一组 JSON 样例验证，避免各自维护不同语义。新增能力的 Schema/处理器通过显式注册进入目录，不要求修改每个既有能力。

### 3.2 来源适配器

每个来源模块集中拥有显示定义、凭据声明、工厂、精确能力绑定和本地适配修订。来源请求、SDK 参数、标的映射、字段/单位/日期转换、分页协议、推送解析和供应商错误识别留在该模块。

优先组合小型能力处理器，不要求所有来源继承包揽全部功能的巨大父类。已有 Fetcher、BaoStock 规范化器及富途有界查询器可通过薄适配复用，不为本轮同时重写 DSA 原生分析或现有业务模型。

公共执行器通过静态注册绑定获取处理器，不因新供应商增加 `if provider_id == ...`。允许一处显式注册，不要求运行时加载用户脚本。特定认证、连接初始化或预订阅前置，由来源工厂/处理器结合公共生命周期完成，不泄漏给业务页面。

### 3.3 公共执行器

复用现有凭据安全管理、超时预算、错误归类、限流、诊断和来源记录。查询按统一管线执行：请求校验 → 路由/操作/精确要求匹配 → 获取账号配置 → 调用来源 → 标准结果校验 → 来源与状态返回。

公共机制不复制供应商假设：分页结束条件、序列衔接、价格调整算法和市场事件日期仍由来源协议决定。适配器解释实际字段，公共层验证对应契约；不能把未知语义统一成一个看似完整的值。

适配器内不重新选择备用源。现有链路由谁负责切源，继续由该责任方执行；同次查询只有一个切源责任方，避免 Server 和 DSA 双重回退。重试和单次调用共享有界预算，不叠加无上限重试。业务有异步准备需要时复用现有编排，不把所有查询强制变成任务。

## 4. 一个定义产生多个视图，而不是重复维护多个能力表

能力声明与执行实现直接绑定；供应商列表、精确能力目录、处理器查找及本地适配修订视图由已注册定义产生。生成输出不作为第二份人工登记表。能力定义与来源实现分别扩展：新增来源只绑定已有能力，新增能力只增加本能力合同与入口。

静态声明与运行状态分开：

| 事实           | 说明                                                          |
| -------------- | ------------------------------------------------------------- |
| 已适配能力     | 代码实现并通过对应合同测试的精确范围                          |
| 账号与部署条件 | 依赖、凭据、权限和配额是否满足；无法确认时保持未知            |
| 用户配置       | 来源是否启用、是否位于该请求的已保存路由                      |
| 本次读取结果   | 实际覆盖/深度/时间/来源及成功或失败；健康探针不能代替实际读取 |

注册时拒绝重复绑定、缺处理器和操作不匹配。不得用供应商宣传或“SDK 有方法”生成已适配条目。请求时仍检查真实条件，不把静态能力声明当作账号授权或数据完整性证明。

精确范围按有效组合表达：市场、资产类型、能力、操作，以及该能力的周期/复权/深度/覆盖要求。不能把独立数组做笛卡尔积后默认全部成立。

能力专有参数通过本能力 Schema 表达，不向所有 RouteKey 塞入通用可选字段。现行 `data` 路由可承载能力名称，但未知能力/操作不得被接受为可执行。当前路由维度不足以区分新政策时，先做窄范围版本化契约扩展，禁止静默新增字段、改变路由 ID 或绕过校验。

迁移以选定能力切片为边界：同一目标的事实只由一个登记源生成；未迁移功能保留既有路径和状态，不要求先把所有供应商重写才能验证新接入方式。

## 5. 屏蔽实现差异，保留真实语义差异

### 5.1 必须由适配器屏蔽

不同 API 路径、认证参数、SDK 类型、证券代码、字段名称、日期格式、排列顺序、明确可转换的单位及消息格式，不进入业务分支。业务不读取供应商原始字段或 `DataFrame.attrs`；来源内部可保留，但输出经过标准能力边界。

### 5.2 不允许被统一模型掩盖

复权口径、交易场所/覆盖范围、价格和数量单位、支持深度、实时/延迟/轮询采样性质、历史可见性、事件完整性和权限差异必须保留。未知值不填零，不伪造时间、价格、单位、序列号或权限成功。

普通消费者只使用标准字段。尚未标准化的来源独有信息可留在受限诊断/原始观测中，但不能成为隐藏业务入口；业务确需使用时，提升为明确能力字段或独立能力并测试。

错误沿用现有分类并按需扩展，至少区分不支持、未配置、无权限、限流、暂不可用、无覆盖和响应非法。不得把鉴权失败当作空数据，也不把未知映射为正常。

## 6. 现有价格与研究能力的迁移约束

基础价格研究只验证本次消费者依赖的标的、日期、价格、口径、实际覆盖和来源。量额、指标、真实份额和公司行动要求分别检查，不作为所有价格来源统一接入前置。

移除 DSA 基础价格放行和 Server `supportsBasicPriceFallback()` 的供应商名单，改为标准能力事实与研究模式约束；覆盖实际迁移范围的 CN 和港美接缝。不能只换成来源声明的 `allowFallback: true`，仍检查实际绑定、账号/配置条件、响应与消费者需求。

固定快照基础价格研究保留同口径整窗备用、来源披露和同序列信号/基准。不混接价格，不把同名复权口径宣称为算法等价。事件、数量敏感计算和已有严格请求保留必要正确性条件，但不恢复 §0 已取消的能力交付义务，也不加回逐证券人工证明。

按需状态与生命周期继续使用来源明确的事实；有价不等于可交易、缺行不等于停牌、摘牌日不等于最后交易日。未知覆盖现金消费只能沿当前主题明确的研究合同推进；框架不替用户选择更宽松模型，不把部分事件当作完整收益。

冻结重放不在线选择适配器，也不要求当前来源在线。仅迁移代码目录不能伪造上游修订；本地适配语义确有变化时按原规则更新。目录身份变化沿现行控制协议处理，不手工沿用旧修订。已支持的旧冻结格式和结果不改写，不追补已取消的缺失旧资产。

### 6.1 目录日线语义的增量发布合同（2026-10-10）

精确目录条目可追加 `barQuery`：Data V3 合同版本、query 操作、精确价格口径、供应商原生价格基准、单目标整窗读取、每次请求覆盖校验与实际传输协议。该对象由可执行绑定/既有有界适配事实派生，不是供应商自声明的备用许可；静态字段不证明某次查询成功、算法等价或历史可见性。无此对象的旧目录仍可读取，但不能据此新增基础备用资格。

基础备用仍受当前消费者范围约束：CN ETF、港美 STOCK/ETF 日线，以及明确选择基础价格研究/图表的入口；CN STOCK 不因本增量跳过 `invalid_proof`，严格或事件/数量敏感研究不新增资格。消费者必须找到两个不同目标的精确目录事实，备用的配置与目录就绪，校验单次响应、同一价格口径与整窗，沿现有切源责任返回实际来源。不同来源同名复权不等于算法等价。

`barQuery` 是 V3 严格目录 Schema 的可选增量；旧冻结目录无需补写。因旧在线严格消费者会拒绝新增字段，发布顺序必须先更新 Schema/Server/客户端消费者，再更新 DSA 目录生产者；若目标同步中断，保留阶段未完成并修复，不伪称已发布。目录内容修订正常重算，适配/上游修订不因目录移动虚增。

### 6.2 来源错误的标准投影（2026-10-10）

真实图表检查发现现行 HTTP 边界将 HiThink 已分类的 `symbol_not_found` 压成通用暂不可用。本轮补齐 Data V3 的安全错误：`source_symbol_unrecognized` 表示该来源未识别证券，`invalid_request` 表示来源拒绝请求参数，`permission_denied` 与 `authentication_failed` 分别表示权限与凭据失败；原覆盖不足和暂不可用保持。该增量只保留来源事实，不证明证券不存在或全部退市证券不可用，也不放宽研究协议或备用资格。

DSA 的完整窗口与图表共用同一投影，供应商原始消息不进入公开错误。Server 解析强类型错误并保留分类及请求身份；不由适配器增加隐式重试或切源。严格消费者的更新顺序同 §6.1，旧错误信封继续有效，旧快照和离线重放不改变。

### 6.3 框架关联与受保护配置恢复（2026-10-10 H01）

新能力 QueryBinding 必须声明能力专属的精确请求匹配与结果关联校验，注册拒绝缺失校验或将查询处理器标为订阅；查询入口不能绕过已有日线/报价的专用规则。校验包含请求及固定目标，不依赖来源处理器自觉完成。合同版本由能力定义拥有并以对应 Schema 验证，不以公共注册器中的供应商分支处理。

E05 的配置恢复必须避免覆盖并行修改。现有 Provider 配置写接口新增可选 `expectedConfigVersion`，为非负安全整数；在原 SQLite `BEGIN IMMEDIATE` 事务内与当前配置代次比较，冲突返回安全 409 `PROVIDER_CONFIG_VERSION_CONFLICT`，不改配置、凭据或代次。未提供该字段的原调用继续保持原语义；关闭/恢复只提交 enabled 和期望版本，不复制或重新保存凭据。政策仍使用现有递增修订保护，恢复使用新修订而不倒退历史。这个能力不授权实际停用来源或修改用户政策，验收执行仍单独取得具体授权。

产品政策写入口增加可选 `expectedRevision`，在原 PostgreSQL 行锁事务内比较当前修订；该操作条件不进入 DSA Desired Policy 数据合同。它也拒绝“并行者恰好提交相同新内容”的情形，原来未提供条件的幂等调用保留。验收恢复只处理获得明确提交确认的本案例变更；超时等未知结果不凭版本猜测所有权，保留恢复记录并停止自动覆盖。

## 7. 新能力验证案例：盘口，而不是万能 LEVEL2

### 7.1 能力划分

`ORDER_BOOK` 表达盘口；`PUBLIC_TRADES` 表达市场逐笔成交；`ORDER_EVENTS` 表达逐笔委托/撤单。后两项仅用于说明边界，本轮不要求实现。

`PUBLIC_TRADES` 不是账户成交事实或复盘 Trade 周期；市场行情更新不得写入账户 Ledger。

`ORDER_BOOK` 本轮只作为开发/测试注册能力：至少两种不同字段结构、单位或消息形态的确定性输入，经各自适配形成同一标准模型。未有真实接入及权限证据时，不进入生产已适配/可用目录。不是“换两次 providerId”就算两个适配器。

### 7.2 最小标准盘口模型

| 内容       | 必须明确的语义                                                         |
| ---------- | ---------------------------------------------------------------------- |
| 标的与覆盖 | 标准 symbol、市场/交易场所和已知来源覆盖；不同覆盖不默认等价           |
| 买卖档位   | `bids`、`asks` 按合同排序；price、quantity，委托数量仅在明确提供时存在 |
| 数值与单位 | 沿用精确数值约定或显式十进制表示；quantityUnit 已知才换算              |
| 深度       | 请求深度、来源支持上限、实际返回档位分开；盘面不足十档不等于接口不支持 |
| 时间       | 来源事件时间可缺省，本地接收时间独立；不能互相冒充                     |
| 来源与质量 | 目标、本地修订、数据性质、有效/失效状态；不宣称未知连续性已验证        |

合同测试明确空盘口、重复价位/档位、缺字段和排序规则；不把单一市场规则外推为所有盘口规则。请求超出来源支持深度时默认拒绝，仅调用方显式允许且政策允许才降级并披露。

以下仅为目标调用示意，不表示已实现或规定函数名称：

```ts
const book = await market.orderBook.get({ symbol: '00700.HK', depth: 10 });
const stream = market.orderBook.watch(
  { symbol: '00700.HK', depth: 10 },
  { signal: abortController.signal },
);
```

业务选择能力与需求；来源由用户保存路由决定。`watch` 用于验证订阅边界，不表示本轮开放生产推送。

## 8. 查询与订阅：共享定义，分别实现生命周期

本轮交付类型、生命周期协议和隔离测试，不部署真实订阅执行器。以后实际接入时遵守以下边界；本节不是新增生产行情交付承诺。日线/NAV 查询不强改为流，轮询不能冒充原生逐笔。

**连接与释放。** 适配器处理认证、连接协议、上游订阅/取消和消息解释；公共机制协调引用、取消、恢复预算和状态事件。只有同账号/权限、来源、标的及兼容参数的订阅可复用。最后一个消费者离开按明确策略释放；凭据/权限撤销及来源停用须影响已有订阅。

**初始状态与增量。** 区分 connecting、live、stale/resyncing、closed/error。获得有效初始状态前不把局部更新当完整盘口。适配器遵循来源序列规则；公共状态维护可共享。明确缺口使状态失效并重同步，无可验证序列则保留连续性未知。

**切源与晚到消息。** 重连/切源产生新会话代次，拒绝旧连接晚到消息。取得新来源有效初始状态后才恢复 live，B 源增量不能应用于 A 源盘口。订阅回退不能复用日线整窗规则，只能选择用户授权且满足语义的目标，披露切换和实际来源。

**背压与用途。** UI 可合并完整状态，但不能先丢弃重建所需增量。逐笔研究/录制不得默默抽样；有界缓冲溢出明确报告缺口/失效并恢复，不使用无限队列。接收处理与页面刷新预算分开。

**传输与持久化。** 前端仍只连接 ThesisLedger Server，DSA 凭据不进入浏览器。真实实现前再选择两侧流式传输，明确连接数、吞吐、延迟和内存预算，不预设集群。Redis 可存可重建最新状态，不是账户事实源。历史录制/重放及二级行情回测需要独立合同与容量设计，不因实时接通而成立。

## 9. 隔离、配置与用户体验

复用现有凭据声明、配置、密钥存储及权限边界。来源不得默认读取其他账号配置，SDK token、原始认证参数不进入日志、快照、前端或样例。

缓存/订阅共享键包含能力真实身份：来源/上游目标、标的、市场/覆盖、操作、相关参数和必要账号权限/配置代次。安全身份不含明文凭据，缓存命中仍遵守授权；当前缓存不得替换既有冻结结果。

前端消费标准能力目录展示支持、未配置、暂不可用等状态，保留主备手选。新能力可以增加专用 UI，但不按供应商复制业务面板。显示“盘口深度不足”“当前账号无权限”等实际原因，不用内部类型名代替用户说明。

## 10. 演进顺序与兼容约束

先迁移腾讯/HiThink 的选定日线绑定并保持行为，再迁移至少一种已支持的非 K 线能力，随后收敛跨仓特判并验证新盘口测试能力。A01 先确认已授权的精确迁移切片，不把全部来源和当前独立任务合并成一次大重构。

定义派生目录、凭据描述、精确能力和修订视图，不改写已冻结请求/结果。用户路由不静默改序、增加目标或换源；必要协议变更先明确消费者/生产者升级顺序。

只允许显式注册和必要版本化契约接缝，不在 Runtime、Control 核心、Server 业务或前端添加新来源执行判断。边界检查固化方向，以新模块接入的实际改动面证明扩展性，而不是仅搬目录。

本次文档写回不改代码、依赖、数据库、容器、路由或账号；实现任务另待授权。不能为文档修订运行生产构建或请求 Provider。

## 13. 全源适配检查、差异矩阵与功能级路由（2026-10-10 对齐）

### 13.1 交付顺序与完成口径

### 13.2 全源检查的边界与维度

检查对象取当前产品 Provider 清单、精确 RouteTarget 库存、统一注册和实际调用入口的并集，包括聚合库的不同真实上游、内置公告/规则来源、未配置或已跳过的候选。只存在于 DSA 原生分析而未进入 ThesisLedger 产品的来源单列范围，不冒称产品已接入；测试来源排除生产清单。不得只检查统一注册表中已有的腾讯和 HiThink，也不得把一个 providerId 的某项迁移外推为整家来源已经统一适配。

每项至少区分：供应商/库声明、现有读取实现、统一适配层迁移状态、标准合同与消费者接通状态、账号/依赖条件、验证层级及范围、用户是否在该功能启用。未迁移不等于不支持；未测试不等于不可用；一个样本通过不等于全市场/全历史覆盖。代码声明与实际执行不符、存在旧分支或能力挂错路由，必须列为明确缺口。

检查应识别：市场/资产有效组合、真实上游、当前与历史资料、周期/复权/时段、字段与单位/精度、时间性质、覆盖与分页限制、查询/订阅及轮询采样差异、独立错误、缓存/配置失效和已有使用边界。现行有效能力复用现有测试；有合法现成配置且在授权范围内的来源进行有界实读。缺 SDK/凭证/权限或用户已取消的来源，记录静态结论与准确未验证原因，不自动安装、开户、购买、反复探测或恢复旧义务。

相同真实上游经不同 SDK/库接入仍须披露，不能仅因 providerId 不同就宣称是独立故障备用。检查证据绑定工作树输入或修订、执行时间、标的/区间/参数与结果；不复制密钥、token 或敏感配置。

### 13.4 路由按可独立选源的业务能力拆分

独立路由的判断是“是否具有独立数据语义、消费者需求、权限/可用性或合理的来源选择”，不是供应商的方法数量，也不是 JSON 字段数量。各能力保留专属强类型参数；市场/资产、周期/复权以及必要的操作、覆盖、时段/深度参与精确匹配。参数不必全部变成界面上一条新路由，只有确实需要独立选择策略的维度才进入版本化政策身份。

以下是待逐源矩阵确认的功能边界，不是本轮已上线能力清单，也不重新承诺已取消的专业功能：

| 功能组       | 独立选择边界                                   | 拆分原则                                                                                                       |
| ------------ | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 价格行情     | 当前报价、历史日线、历史分钟线                 | 已有独立能力保持；不把 OHLC 四字段拆成四条路由；不复权/前后复权及周期继续精确匹配                              |
| 基金数据     | 最新净值、历史净值、基金持仓                   | 沿用不同含义和时点，不把基金净值混为证券报价                                                                   |
| 公司行动     | 现金分红、拆分/份额变动                        | 已有事件能力分别配置与覆盖；缺拆分不能否定已取得分红，也不能伪造完整事件资格                                   |
| 状态与规则   | 日级停复牌/交易状态、风险警示、价格限制规则    | 不再由一个来源同时包办；粗 ST 与细分类别分别表达，比例规则不能冒充精确涨跌停价格；粒度与字段要求由能力合同约束 |
| 生命周期     | 上市/摘牌基础日期、确有消费需求的上市/退市阶段 | 基础日期不再依附停复牌路由；最后交易日、停牌起日不能由摘牌日期推导；阶段规则按其独立输入处理                   |
| 证券参考数据 | 当前静态资料、每手股数等已有执行规格           | 保留已独立的每手股数路由；资料中的未核验日期不能悄悄成为历史生命周期事实，同一字段不建互相冲突的事实源         |
| 费用         | 公共费用规则；已存在的券商费率配置             | 公共数据与用户假设分开，不因为缺外部费用来源就默认为零或新建第二套费用系统                                     |
| 后续实时能力 | 盘口、市场逐笔成交、逐笔委托；查询与订阅操作   | 本轮仅盘口测试边界；订阅不因查询可用而自动开启，也不把轮询称为逐笔推送                                         |

当前 `HISTORICAL_TRADING_STATUS` 同时承载交易状态、粗 ST/风险警示、价格限制、上市阶段及 basicLifecycle，是优先拆分对象。目标例子是价格取 A、交易状态取 B、风险/价格规则取 C、基础日期取 D；只需要交易状态的来源不能因为缺风险规则而整家不可选。这里只说明组合方式，不为具体来源授予实际能力。

同一供应商接口一次返回多种信息时，允许来源模块复用一次有界读取和适当缓存，再按独立能力投影；逻辑路由拆分不意味着重复请求上游。只共享同身份、权限、参数与时点相容的读取；不能绕过某功能的停用或将额外字段自动当作已启用事实。

聚合消费者根据本次功能需求请求各能力，分别选择已配置主备、保存来源/时钟/覆盖/错误，再组合成业务读模型。不能把“主源返回部分聚合数据”当作全部子能力成功而提前停止，也不能因一个可选能力失败阻断其他已有效结果。确实必需的数据缺失仍阻止对应计算，不自动选择更宽松研究模型。

同一能力内部按所需字段、粒度与覆盖判定是否满足请求；不足时只沿该能力已保存政策及已有兼容规则处理，不擅自逐日或逐字段跨源拼补。不同能力分别使用不同来源是显式组合，不等于允许拼接价格序列。冻结保留各能力独立请求、目标、观察时钟、覆盖与采用事实；同一字段存在冲突时按本能力的明确策略处理，不能用最后返回者静默覆盖。

### 13.5 按需启用、迁移与产品行为

提供三个清晰的决策位置：Provider 总开关与凭据用于允许访问该来源；功能路由可独立启停且保留已保存主备；来源只有被该功能的精确目标选中才允许为它执行。不默认在每层再复制同一种开关。全局停用优先，功能停用不能被主备回退绕过；启用某家来源不会自动启用其全部功能。

“未适配”“未配置”“用户停用”“账号无权限”“本次读取失败”分别展示。来源列表按该功能和参数的精确能力筛选；已适配但缺依赖或权限显示具体原因，不能因某个其他能力不可用使整家来源失去资格。纯迁移未完成但现行合法能力仍在旧路径时保持现有功能，不把审计标签当运行阻断条件。

未启用功能不发起新的网络请求、异步准备或生产订阅；在途结果按现有配置代次隔离，适用缓存不得以“当前启用结果”绕过停用。冻结历史读取不因当前功能停用被重写。页面可按功能分组减少密度，但后端路由、能力匹配、缓存与冻结也必须真正支持拆分，不能只是 UI 分栏。

现行 route 没有独立启停字段时，在对应版本化契约中设计并验证，禁止只在前端保存影子开关。拆分前输出旧路由→新能力/目标/状态映射；保留用户既有主备意图，不按供应商宣传把旧目标复制成所有子能力都可用。不能精确映射的项保持未配置并说明；新功能默认不自动启用。正式保存用户路由、变更目标顺序或上线语义迁移须按既有授权和 CAS 规则执行，本次文档对齐不代替该授权。

既有冻结快照保持原版本读取，新组合使用必要的新契约/冻结版本；旧结果不补字段、不改来源或校验值。已取消的高级资格、指定旧资产追补、开户采购与真实二级行情范围保持原决定。

### 13.7 H05 定稿与 H06 实施合同（2026-10-10）

全来源差异及精确组合以[来源与路由矩阵](../reviews/2026-10-10-provider-adaptation-and-route-matrix.md)为正文。首批拆分为 DAILY_TRADING_STATUS、RISK_WARNING、DAILY_PRICE_RULE、SECURITY_BASIC_DATES、LISTING_PHASE，均为 query；没有真实来源和生产需求的 ORDER_BOOK 继续只用于隔离测试。旧 HISTORICAL_TRADING_STATUS 保留至消费者迁移完成，不把原上游登记为每项均支持，也不重复执行旧聚合请求与新独立请求。

H06 按共享合同 → DSA 同义校验 → 政策兼容拆分：新增能力合同版本 1 沿用现有 Data V3 envelope 与 RouteTarget；请求具有独立能力标识和专有参数，结果保留请求身份、实际目标、原适配/上游修订、观察时钟、逐项覆盖及证据引用。基础日期使用独立 symbol 请求，不要求价格窗口，也不增加最后交易日推断字段；窗口能力保留日期范围和未知项。粗 ST、细分风险、比例规则、精确价格、无价格限制明确区分。返回结果必须与请求/绑定关联，不能靠 Schema 合法就宣称目标正确。

风险请求明确 coarseST 或非空的细分风险类别集合；覆盖只对本次必需类别判定，其他字段仍保留 unknown。价格规则请求区分 rule 与 exactPrices，比例不能满足精确限价需求。证据区分 originalBytes、normalizedResponse 与 unknown；旧公告只有链接时保留未知摘要/观察时间，不将数据包或规范化响应摘要冒充原文摘要。功能结果与本次专有参数也须关联。

现有 Control V3 的 route 增加可选 enabled 字段（原对象不注入默认字段，保持旧序列化与冻结读法）；缺省值仅在执行判定中解释为旧功能已启用。新拆分能力须显式给出 enabled，首次建立默认为 false。禁用 route 保留 targets，Effective 的禁用原因沿用 disabled；旧客户端/旧文件不自动写入新字段。新增组合冻结使用独立版本，在 H09 定义完整独立事实并验证旧版本读法，不能仅升级 Schema 名称后改写历史载荷。

纯政策迁移预览按实际来源支持映射，并保留无法映射的旧行；预览不提交配置。保存、目标变更和真实启停验收另外使用原 expectedRevision/expectedConfigVersion CAS 与具体授权；H01 已完成的单次 ETF 故障验收不扩张此授权。现有研究模型的必需输入、冲突与 invalid_proof 继续 fail closed。

#### 首批参数资格与获取缓存

逐能力 querySupport 由同一来源绑定派生到目录：日级状态的粒度和窗口上限、粗 ST/细分风险及类别、规则/精确价格表示、基础日期字段、可提供的上市阶段。它只描述参数资格，不证明任意证券/窗口已有完整数据；旧目录无此字段时不自动注入。来源前置校验与声明一致，不能把比例来源声明为精确价格来源，或把粗 ST 声明为细分风险。阶段只登记实际来源能表示的阶段集合。

H08 首批获取复用限于 BaoStock 独立查询，沿原执行器取数及返回前控制检查。日级状态和粗 ST 可以共享同一次日历/flags 规范化获取，基础日期独立取数；缓存不保存带 requestId/RouteTarget 的消费结果。键包含原方法及字段、证券/窗口、真实来源与适配修订、政策修订及 Provider 配置代次；来源关闭或配置代次变化后旧键不能复用。缓存属于单个 Runtime，内存有界、短 TTL，同键并发合并具有有界等待，错误、无有效事实或超限结果不缓存；每次投影重新进行结果合同校验。原历史状态持久缓存与旧冻结格式保持现行路径。缓存命中也必须经过当前路由、凭据、准入及返回前代次检查，不构成在线或完整性证明。

Server 侧独立功能读取继续由 DsaDataCapabilityReaderV3 承接：从现有 Effective Policy 读取同能力的人工主备，逐次发送精确 RouteTarget，不在 DSA 适配器内切源。仅已配置且 eligible 的最多两个目标可执行，每个目标最多一次，无新增重试链；每次请求后（包括失败）重新核对政策修订/来源修订与功能路由状态，变化即停止，不能用备用掩盖代次变化。合同非法、请求非法和消费认证失败直接拒绝，已分类的来源不可用等错误才能转人工备用。部分窗口返回显式 partial，基础日期返回 observed，均不声称满足尚未判断的研究需求；字段采用/必需判断与新组合冻结在 H09 完成。
