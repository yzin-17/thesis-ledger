# 市场数据精确接入与用户自主选择

> 任务标识：MARKET-ROUTE-USER-CHOICE
> 日期：2026-10-07
> 状态：本地、正式运行态与真实 Web 客户端验收完成，现行合同保留。
> 对应任务：[已归档实施任务](../archive/tasks/2026-10-07-market-route-user-choice.md)；[客户端验收](../reviews/2026-10-08-market-provider-client-acceptance.md)。

## 目标与当前问题

用户要求补齐数据源的精确接入、配置和检查，并允许自主选择来源。当前前端仅列出 ready 条目，Server 同样按就绪状态拒绝保存；多个底层 Fetcher 尚未接入当前 V3，数据源卡片展示的宽能力与可选范围不一致。

本规格将选择意图与执行就绪分开，覆盖当前应用合同的 CN/HK/US 市场、已声明的日线和非行情能力。第三方 SDK 未被本应用声明的功能及其他市场不在本次接入范围。原数据源检查见[核查报告](../reviews/2026-10-07-market-provider-capabilities-admissions.md)。

## 行为与接口

1. 已登记精确适配的来源保留在主源和备用源下拉列表。缺少必要凭证的选项禁用并显示“凭据缺失”；配置凭证后恢复可选。停用、缺依赖、临时不可用和需要独立数据验证等其他状态作说明，不禁用选项。已有缺凭证选择继续回显并允许清空，不在凭证变化时删除用户配置。不存在的来源、重复主备、非法市场/资产/周期/口径仍属于无效配置。
2. Desired 保存只校验配置结构、精确能力存在及目录完整性，不以账号就绪或独立准入记录作为保存条件。DSA 接收合法选择并保存，Effective 单独报告当前执行状态；不会因保存而伪造凭证、健康或准入。
3. 普通日线、实时行情、当前净值/净值历史、持仓和筹码按精确适配、启用状态和有效凭证判断能否请求，不依赖人工窗口准入。实际请求检查返回身份、日期、价格口径、来源、覆盖和凭证变化，并提供稳定错误。
   普通图表按来源实际返回日期展示，不要求先有独立上市与交易日历事实；图表不生成完整窗口证明。完整窗口、历史交易与回测接口继续核验独立证据，不能借图表读取获得这些资格。
4. 分红/拆分完整覆盖、身份映射、历史公共事实、严格 PIT 和交易单位的独立证据约束保留；用户仍可选择其来源。证据不足影响该数据读取或使用，不剥夺保存选择的能力。
5. 对已存在的 Fetcher 补齐精确读取契约，明确实际来源、市场、资产、价格口径及请求日期。固定默认复权参数不得冒充其他口径；不自行转换不明单位、推定历史可见性或编造交易日历。源 SDK 的接口权限、临时故障与当前请求结果独立披露。
6. 前端来源功能说明消费同一份精确目录；区分应用已接入能力、需配置凭证、已停用或需数据验证。不以 Provider 宽声明暗示所有功能都可用。空路由默认填写唯一精确 HiThink 目标，缺凭证时默认值保持配置意图并显示原因，下拉项禁止新选；已有选择和用户清空操作保持不变。
7. 上游未提供的成交量/成交额保持缺失；价格展示可继续，依赖该字段的指标、聚合或回测明确不可用，不用 volume×close、0 或字符串 null 伪造事实。既有有值响应保持兼容。
8. 需要凭证的数据源必须先具备完整有效的页面或环境凭证才能启用。前端在缺凭证时显示“请先配置凭证”并禁用启用开关；服务端在同一配置事务中检查合并后的凭证，拒绝缺凭证的显式启用。清除页面凭证后若无有效环境凭证，则同时停用来源；既有缺凭证来源在读取清单时按未启用展示，保留原路由意图。免凭证来源不受此条件限制。

## 所有权与兼容

精确适配、有效凭证和执行判断由 DSA 拥有；共享 Schema 定义选择/状态合同；Server 保存选择并消费 Effective；Desktop 展示能力与编辑意图。不新增无所有权共享目录，不修改数据库结构，不通过写入伪造准入修复空库。

现有 Desired、Effective、缓存来源标识和冻结事实继续使用 V3。新增来源的修订反映本地适配实现，无法验证的上游算法修订保持未知。旧人工记录继续为高级能力证据保留，不删除。新行为覆盖旧 Spec 对普通行情人工准入和 ready-only 选择的要求，历史验收只保留其原范围。

## 验证策略

- 选择：Schema、Server 策略保存及 Desktop 选择器的未就绪/缺凭证/停用场景。
- 执行：隔离 SQLite 与真实策略/凭证解析，验证普通能力无人工记录仍按配置执行；失效凭证、来源/口径错配、返回非法字段和晚到结果被拒绝。
- 接入：按中国内地日线、境外日线、报价三个有界批次建立来源合同与测试，不用普通 Fetcher 的隐藏回退冒充精确来源。
- 集成：定向测试通过后执行包级构建与门禁；目标环境通过 infra 正式入口验证，浏览器和真实外部账号结果单独记录。

调查初始 Docker 为空；后续已通过正式入口建立目标服务并验证 API，2026-10-08 实际 Web 客户端交互通过。真实账号权限不足不取消本地接入义务，也不据本地 fixture 声称外部服务可用；账号在线义务继续由凭证 Task 的 T5b 跟踪。

## 验收标准

- AC1：主备下拉保留缺凭证来源并禁用，配置凭证后恢复；已有缺凭证配置可回显、清空和保留保存。其他已接入状态仍可选；Server 不以 ready 限制保存配置意图。
- AC2：普通数据能力不依赖人工准入记录，同时保留精确身份、来源、口径、凭证及响应检查。
- AC3：中国内地日线的精确接入覆盖已有 AKShare/腾讯/HiThink/Tushare 及 efinance、TickFlow、pytdx、BaoStock 的已确认能力。
- AC4：境外及多市场日线覆盖已确认的 yfinance、Longbridge、Finnhub、Alpha Vantage 能力；真实价格语义、请求范围和来源不得串用。
- AC5：普通报价及其他数据能力补齐已声明而缺失的精确接入，配置缺失与执行失败可解释。
- AC6：数据源功能卡片与路由选项复用精确目录，保留能力状态，只有缺凭证选项禁用；HiThink 默认及凭证流程不回归。
- AC7：共享合同、Server、DSA、Desktop 本地集成和正式目标验收证据分别成立；未执行的真实账号、运行时或客户端检查如实保留。
- AC8：凭证是数据源启用前置条件；缺凭证显式启用失败且不产生配置写入，完整凭证与启用可原子提交，清除后无环境凭证则停用，环境凭证与免凭证来源保持可用。
