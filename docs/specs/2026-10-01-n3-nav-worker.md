# N3 NAV Worker 执行汇合

## 范围

消费 N2.5 已持久化的准备凭证、Run 与 NAV Snapshot，在当前 Worker 领取入口按 `inputKind` 选择执行器。沿用现有 attempt、取消、成功及失败的原子提交；执行器不得重新获取 Provider 数据。完成消费汇合后，仅显式注册 NAV 执行能力的创建与队列路径开放投递；公开读取严格验证结果与冻结证据。

BullMQ 属于 Backtest 执行基础设施。源码只能在 `apps/server/src/backtest/` 引用；实际基础设施集成测试只能在同领域的 `apps/server/test/backtest/` 引用。边界门禁明确覆盖这两处，其他 feature、客户端、共享包及其他领域测试继续禁止直接引用。新增许可用于真实 Queue/Worker 验证，没有提升共享层职责或改变生产依赖方向。

## 验收

- AC01：NAV 执行前验证准备凭证、策略版本、消费关联、Run 配置和物理冻结产物；使用创建时刻验证已消费凭证。
- AC02：NAV 使用 `navId`，场内使用既有 Runner；提交前再次验证 NAV 结果及冻结身份。
- AC03：重复领取、晚到结果、取消与失败沿用状态及 attempt 条件，不覆盖较新结果。
- AC04：缺少 NAV 能力、篡改或无效输入收敛为明确失败；现有场内执行回归通过。
- AC05：本地受控测试不替代 PostgreSQL Worker、队列、Docker 和产品验收。
- AC06：公开 NAV 结果、手动重试和创建/队列补投形成完整闭环，缺少能力时保留拒绝；客户端可准备、创建、查看 NAV 结果与研究假设。
- AC07：通过官方 infra 入口更新 Server/Worker/DSA；实际来源、目标 HTTP/Worker、旧合同拒绝及客户端业务验证各自留存证据。
- AC08：目标缺少 NAV 研究准入时，显式操作入口必须先读取并验证真实基金身份、精确来源原文与所需日期范围，保存原文及摘要，再登记当前 adapter/source 修订、基金/日期范围和有界有效期；禁止通过 Policy 或健康检查直接授予准入，禁止自动启动登记，研究准入不能宣称严格 PIT。操作只消费当前专属 Store 合同，不增加普通 Control HTTP 写权限。
- AC09：NAV 任务以独立摘要列表保留可发现性，刷新或重启后可以重开详情；列表不投影未经物理冻结校验的经济指标，旧合同不能借摘要混入当前任务。

用户在实施中明确取消 Electron 验证。本次 AC07 的真实客户端采用当前 Desktop 源码的浏览器运行面，代理到更新后的目标 Server；从实际策略入口准备、创建、读取结果、刷新历史并重开详情。Electron 验证不属于本次验收要求，不用浏览器结果宣称 Electron 已通过。

普通基金 T+1 决策表示研究净值披露延迟，其适用范围必须由用户显式填写，并覆盖策略所需预热和执行日期。界面不得把运行开始日自动当作规则开始日，也不得把该可见性假设描述为真实申购确认时序。申赎确认仍由独立执行模型明确配置；来源守卫继续拒绝缺少预热规则覆盖的请求。

研究日历的搜索上限仅用于查找实际已知日期，必须限制在来源实际采集日内，避免无关的固定 104 天展望跨过已核验日历制品的末日。限制搜索范围不能降低预热、处理尾部及披露工作日的预算校验；不足时仍明确拒绝。目标验收保留短区间的待处理正例，并增加四期均线、较长区间的经济事件验证。

真实来源净值保留原文十进制表达，经济内核可规范化末尾零。结果定价核验必须使用精确十进制数值相等，继续严格匹配日期、可见时刻、Provider 修订、质量与新鲜度；禁止使用浮点容差或改写冻结原文。回归同时覆盖 `1.2300` 与 `1.23` 等值及真实数值篡改拒绝。
