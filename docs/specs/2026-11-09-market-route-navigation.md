## 页面组织

保留“市场数据”下现有的“路由策略、数据源、标的目录、规则监测”一级入口。在“路由策略”内部按业务用途划分六类，以市场和标的类型缩小配置范围。

桌面采用左侧分类、右侧配置；窄屏将分类改为单个选择器。默认进入“行情与净值”，首次范围默认为“全部市场／全部类型”。市场和标的类型使用筛选控件，避免在一级页签下面叠加多排页签。

数据访问由来源配置决定：未配置来源时保持未配置状态，不发起该能力的数据读取；保存有效来源后按主备顺序及准入条件使用。用户通过清空对应路由的来源配置停止使用该能力。

## 分类方案

| 分类 | 包含内容 | 用户要完成的任务 |
| --- | --- | --- |
| 行情与净值 | 实时行情、日线、分钟线、基金净值及历史、股票和 ETF 分笔、期货与期权行情、来源 Greeks 指标、盘后快照 | 调整价格与图表数据来源 |
| 财务与持仓 | 三张财务报表、业绩快报与预告、估值历史、基金持仓与份额、股东户数、筹码摘要、来源 EPS 汇总与预测 | 调整基本面与持仓分析来源 |
| 资讯与资金 | 新闻检索、市场及全球快讯、研报元数据、资金流、融资融券、大宗交易、龙虎榜、股东增减持、机构调研、公司问答、期货会员排名 | 调整研究资讯与资金行为来源 |
| 宏观与市场 | 国债收益率与曲线、LPR、GDP、PMI、社融、宏观日历、回购利率、板块归属、指数成分与权重、涨停／炸板／跌停池及昨日涨停表现 | 调整宏观环境和市场横截面来源 |
| 交易规则 | 历史停复牌、日级交易状态、风险警示、日级价格规则、每手股数、历史公共收费、来源重点监控名单 | 调整交易约束与费用事实来源 |
| 证券资料与公司行动 | 静态资料、上市与摘牌日期、上市阶段、现金分红、份额拆分、回购方案与进度、期权合约清单、可转债条款 | 调整证券身份和公司行动来源 |

分类按业务用途定义，`REFERENCE_*` 等技术前缀不再直接决定分组。宏观日历仍是宏观资料；来源重点监控名单仍保留来源事实语义，不等同于系统风险警示或执行门禁。公司行动分类不会改变分红、拆分或回购的原始数据契约。

未知能力暂时进入“其他数据”并保持可见；测试必须提示新增能力补充分组，避免静默归入行情或从页面消失。该兜底不是常驻的第七个主分类。

## 页面结构与操作

配置面板直接承接一级页签，筛选、分类和表格按页面内容边缘对齐。应用状态放在保存操作区；保存栏在窄屏避开底部导航。

分类导航使用共享 Tabs 的 navigation 变体，当前分类用实色底及对比文字表达选中，普通分类名称使用正文色。表格中的能力标题和已选来源使用正文色；表头、计数说明及其他辅助信息采用次级层级，禁用态独立表达。下拉框选中值继承触发器颜色，保持正文尺度，避免被表格内通用 span 样式弱化。

```text
市场数据
  路由策略 | 数据源 | 标的目录 | 规则监测

  应用状态    未保存 N 项
  市场：全部市场    标的类型：全部类型    搜索能力

  行情与净值          数据能力        主数据源    备用数据源    状态
  财务与持仓          实时行情        ……          ……          ……
  资讯与资金          日线行情        ……          ……          ……
  宏观与市场          分钟行情        ……          ……          ……
  交易规则
  证券资料与公司行动

  当前分类 N 条／已修改 M 项                 保存全部修改（N 项）
```

### 分类与筛选

- 分类旁显示当前筛选范围的路由数；有未保存修改时显示对应修改数。
- 市场支持全部市场、中国内地、香港、美国；标的类型使用现有中文映射。搜索匹配能力名称及其已有中文标签。
- 分类、市场、标的类型和搜索共同决定可见行。切换筛选只影响展示，不增加、删除或重置路由草稿。
- 分类为空时保留导航并显示“当前范围没有此类路由”，提供清除筛选入口。没有合格候选、已停用、未配置和应用失败分别展示，不能混成空状态。
- 已保存但目录已不再就绪的路由继续可见，沿用现有目录与策略取并集的语义。

### 配置行

- 共享表格表达“能力、主源、备用源、状态”，避免每行重复两份字段标题。状态为普通数据列。
- 能力名称为主信息；市场和类型在范围明确时使用次级信息，在“全部”范围下必须逐行可辨认。
- 日线和分钟线的周期、复权配置仍是独立精确路由；同一能力可展开这些子行，父行显示配置数、修改数和异常摘要。折叠只减少同时展示的细节，不合并配置语义。
- 行内保留当前生效来源、未应用变更及具体不可用原因；长技术标识和修订关系可放入详情。停用、失败等影响操作的状态必须直接可见。
- 来源选择支持清空，并准确回显“未配置”；主源清空时一并清空备用源。配置行只保留来源选择和读取状态。

### 草稿与保存

- 继续使用一份完整策略草稿和一次统一保存；底部操作栏在页面滚动时保持可达。
- 按钮明确写“保存全部修改（N 项）”，数字包含被筛选或折叠隐藏的修改。切换分类不自动保存。
- 全局显示已修改总数；分类显示各自修改数。保存提示说明其中多少项不在当前视图，避免用户误以为只提交当前分类。
- 保存与应用状态继续区分；允许重试应用的条件沿用现有契约。分类调整不引入批量套用数据源或新的自动切源规则。

## 边界与兼容性

本方案调整 Desktop 的信息组织和来源配置流程。路由键、候选就绪条件、主备顺序继续沿用现有契约；策略及单项启用字段按下节兼容处理。数据源凭据、供应商级启停与连接测试留在“数据源”，证券数据读取留在“标的目录”等已有入口，规则来源跟踪留在“规则监测”。

所有分类基于目录和已保存策略中实际出现的键生成，不凭分类表创建可调用能力。分类中提到某项数据不代表该市场已有合格来源。

真实业务数据只读，配置保存通过受控请求验证。未授权 Git 提交。

## 来源配置与现有策略兼容

页面以来源配置表达使用意图。未配置与无合格来源必须分别显示；清空配置后不得因目录刷新或默认来源初始化而自动填回。待保存状态明确显示来源清空所影响的能力。

已核对现有协议：策略可保存空 `routes`，每条已配置路由须有主源，部分能力须显式提交路由级 `enabled`。采用 Desktop 投影兼容，保留 Server、DSA 和持久化协议，不做读取时迁移。

兼容边界如下：

- 页面加载、目录刷新和分类切换只读状态，不隐式启用既有策略或重填用户清空的来源。
- 策略级或路由级 `enabled=false` 的旧项在可编辑投影中视为未配置，不重新启用其来源。旧项的精确键仍参与行集合，保证目录缺失时可访问。
- 保存时策略提交 `enabled=true`，仅提交当前实际配置的路由，每条提交 `enabled=true`；全空配置提交空 `routes`。用户重新选择来源只恢复该项，不能顺带恢复其他停用项。
- 清空主源时删除该精确路由，包括备用源；后台未选择路由的准入规则继续生效。
- 当前数据缓存继续遵守配置准入，不能绕过来源清空；历史冻结记录和已有业务数据保持原样。
- 源码核对显示实时报价在读缓存前调用 `MarketCacheControl.read`；DSA 的 `thesis_ledger_cache_context_v3.py` 和 `thesis_ledger_feature_policy.py` 共同提供当前准入事实。实施验证须覆盖来源清空后的真实控制结果。

自动补入默认来源的页面流程停止使用；用户显式选择的主备顺序保持。原默认来源辅助函数仅在尚有独立消费者时保留，不参与当前编辑流程。

分组使用已安装 `es-toolkit` 的 `groupBy`（`import { groupBy } from 'es-toolkit'`），将行按业务分类或行情能力身份聚合；其回调接收元素并返回分组键，结果为键到原始元素数组的对象。例如 `groupBy(rows, row => routeCategory(row.key))`。已核对实际声明和源码，见[官方文档](https://es-toolkit.dev/reference/array/groupBy.html)。筛选使用原生 `filter`，没有需要另加防抖的远程请求。

## 验收标准

- AC1：已知能力按上述归属展示，所有目录及已存路由恰好出现一次；未知能力保留可见。
- AC2：分类与范围筛选可组合；无结果、目录失败、无合格候选、停用及已存失效路由保持准确表达。
- AC3：跨分类编辑、切换和折叠后草稿保留；统一保存包含全部修改，提交的精确键、开关和主备配置保持原语义。
- AC4：周期与复权配置可展开访问；折叠时仍能发现修改和异常。主备来源及当前生效状态可辨认。
- AC5：1440、1024、768、390 宽度实际浏览器验收通过；页面无横向溢出，窄表在自身容器内滚动，选择器及保存操作可用。
- AC6：页面通过来源配置表达使用意图；无来源时不读取，清空后不自动补回。旧停用项投影为未配置，重新选择只应用该项；加载和刷新不隐式启用。保存空路由及各独立能力的有效配置符合现有协议，主备及缓存路径均遵守准入结果。

## 验证与风险

实施时依次进行分组和筛选定向测试、策略编辑交互测试、Desktop 包级检查及构建，再进行真实浏览器验收。真实页面只读，跨分类提交内容通过受控请求验证。复用 `apps/desktop/test/market-data-provider-ui.test.tsx`，按新交互补充测试；静态渲染不能替代筛选、草稿保留和实际提交验证。

最大的交互风险是用户在筛选后忘记隐藏修改，因此全局修改数、分类修改数和“保存全部修改”必须同时存在。分类数量仍可能随能力增长，先用六类和范围筛选验证使用体验；仅按市场分三页仍会让每页重复完整能力清单，作为筛选轴更合适。
