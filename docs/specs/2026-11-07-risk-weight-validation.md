# 风险权重按规则校验与扫描反馈

日期：2026-11-07。任务标识：risk-weight-validation。对应[归档任务](../archive/tasks/2026-11-07-risk-weight-validation.md)与[验收证据](../archive/evidence/2026-11-07-risk-weight-validation.md)。本规格继续维护当前行为。

## 背景与范围

手动扫描在规则评估前汇总持仓，并以 0～100% 校验权重。真实样本持仓市值 176.04 元、现金 −82 元、组合总值 94.04 元，同基金合并权重约 187.20%，请求因此以“输入不符合要求”失败。另一问题是扫描响应内包含规则错误时，Desktop 仍可能提示扫描成功且没有风险事件。

本次修改风险输入契约、规则输入可用性及 Desktop 扫描反馈；检查 Mobile 的现有结果消费。不调整账本、估值分母、持仓原值、历史事件、通知配置或规则阈值，不引入数据库升级。

## 行为约定

1. 传输层检查权重为有限数字并给出中文字段错误，不把负权重或超过 100% 当成格式错误；保留原值，不截断或归一化。
2. 业务权重可用性仅在匹配并实际执行持仓集中度、行业集中度、资产类型集中度或波动暴露规则时检查；价格、止损、回撤、相关性等规则不依赖权重。停用、归档、尚未生效、被扫描选项排除或对象不匹配的规则不触发业务权重检查。
3. 依赖权重的规则缺少所需比例、持仓集合不完整或估值质量不合格时，扫描对该规则返回稳定 `input-unavailable` 原因及中文说明，并继续执行独立规则；人工测试明确返回该失败原因，不把不可评估解释成未触发。
4. 扫描响应提供实际参与规则数，Desktop 在没有规则时提示“当前没有可执行的风险规则，请先创建或启用规则”；存在规则错误时显示失败数量、原因及已记录事件数量。通知排队失败保留事件已写入的语义。
5. 保留现有安全边界：请求结构、模式、时间、行情陈旧检查继续生效，真实业务数据默认只读。

## 验收标准

- AC1：负权重、单条与合并超过 100% 的权重可通过风险输入契约并以真实值评估；非法格式返回中文字段提示。
- AC2：无启用规则、仅价格规则、相关性规则及对象不匹配场景不因业务权重缺失而失败；权重相关规则缺失输入时返回具体原因，混合扫描仍执行其他规则。
- AC3：Desktop 区分无规则、全部失败、部分失败和正常完成；人工测试显示具体原因；Mobile 继续展示服务端逐规则错误。
- AC4：定向测试、受影响包构建及边界检查通过；现有开发服务用正式快更入口更新，真实样本只读试算和受控浏览器响应验证通过。

## 验证与风险

复用 Server 风险服务、估值及小数边界测试，新增规则输入场景；复用 Desktop action 测试验证反馈。先定向测试，再受影响包构建与静态门禁，再执行 infra `sync-code.sh thesis-ledger` 兼容性预检与更新。运行态用真实持仓读取及不写事件的试算验证权重契约，扫描交互使用受控响应；不得为验收启用真实规则或制造真实通知。

有限数字属于传输格式校验，业务可用性属于规则评估，两者分别维护。新增响应字段保持向后兼容。未决问题：无。
