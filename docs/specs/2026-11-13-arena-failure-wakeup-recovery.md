# 自主竞技场：失败决策不丢失下一次观察

## 问题与依据
- 当前 LiveAppointments 先消费预约并生成研究周期；只有完整决策通过 Schema 与执行校验，LiveOrders 才会保存新 wakeups。
- LiveResearchBudget.fail 在输出不合法时仅保留尚未触发的旧预约，无法识别失败的响应中独立合法的未来观察时间。2026-11-13 的美股失败周期仍含有效 time wakeup，但模型进入 needs_attention，账户没有待触发 time wakeup。

## 处理原则
- 不修改 Schema、交易校验、订单或历史失败终态；订单无效不能部分下单。
- 仅对 model_output_invalid 且用量已结算、结果明确的研究错误，独立提取审计中最后一条 schema_invalid 响应的合法未来 time wakeup；只保存最早一个，不采纳失败决策中的买卖指令、撤单、价格与成交事件。
- 如果输出截断、格式无效或无合法未来 time，生成保底的系统观察时间（完成后至少 60 分钟），确保下一轮研究有入口；记录来源，绝不标记本次研究成功。
- 最多自动续接一次连续的 model_output_invalid；下一轮仍输出无效时强制 needs_attention，由用户手动恢复，防止循环消耗模型预算。
- 仅在运行中的实时比赛继续自动预约；暂停/结束、历史回放、未知用量或超额错误不自动追加；已存在待触发时间预约时不重复创建。
- 在同一 PostgreSQL 事务中收敛失败周期、账户预约与模型状态，保留审计与尝试次数；下次研究沿用现有额度/并发/赛期门禁。
- 不对现有失败记录追溯修改或自动发起付费模型调用；部署仅令将来的失败具备续接能力。

## 验收
- 已有合法 time 且订单非法时，仅创建下一次观察并保留失败终态，持仓/订单不变。
- 完全无可解析观察时回退一次 60 分钟以上的观察；再次连续失败进入 needs_attention，不出现无限循环。
- 已有未触发时间不重复添加；价格/成交残留仍可保留但单独不能作为保底。
- 未知用量、预算错误、暂停/结束和历史回放不自动预约；对账无二次扣费。
- 定向测试、相关 TypeScript 编译和 Docker 正式同步的运行态检查都通过；不在真实模型上主动重试。
