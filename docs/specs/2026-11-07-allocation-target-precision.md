# 配置目标的展示与提交精度

## 问题与目标

Desktop 与 Mobile 都先把目标权重乘以 100，再在保存时除以 100。`0.3333333333333333` 等已有值在未编辑时也会发生浮点往返变化；Mobile 修改其他类别时同样会重算未修改字段。Desktop 直接把输入转为 number，也使完整输入文本和展示格式耦合。

配置目标继续使用现有 number API 合同。Domain 提供配置权重与百分比文本的单位投影：从已有 number 的完整十进制表示生成文本，提交时只转换一次，不能用舍入修正已有存储值。两端共享同一单位合同，Desktop 复用现有 `DecimalInput`。

## 验收标准

- AC1：未编辑、仅聚焦/失焦或只修改其他分类时，未编辑目标提交值与原 number 相同；不因格式化产生 dirty 或关闭确认。
- AC2：长小数、科学计数法表示的有限原值、极小非零、零及边界值可以往返；极小值不显示成零，无法由现有 number API 表达的非零新输入明确拒绝，不静默提交零。
- AC3：Desktop 失焦适度压缩百分比显示，聚焦恢复完整原始文本，实际输入后才更新草稿；空值、非法文本、负值、超范围和不合计 100% 不能保存。合计容差与服务端现有 `1e-8` 权重容差一致；临界无效合计不能显示成达标的 100.00%，并直接说明不足或超出原因。
- AC4：Mobile 复用同一投影，保留已有非负普通小数输入约束、版本核对、错误恢复和命令结构；本次不改变原生依赖或构建配置。
- AC5：定向故障与修复回归、Domain / Desktop / Mobile 包检查和构建、适用仓库门禁通过；四宽 Chromium 使用真实 Desktop 编辑器核对原值、实际提交及失败恢复，业务请求和写入为 0。

## 所有权与边界

配置目标语义导出保留在 Domain 的 allocation 模块，单位位移复用 ratio-percent 的稳定比例合同，Desktop / Mobile 单向消费。UI 的草稿文本、聚焦及脏状态仍由客户端拥有；不新增全局表单状态，不更改其他收益/再平衡计算、Schema、迁移或历史记录。

已按 `recommend` 核对项目锁定 es-toolkit 1.51.0：`round` 会舍入，compat `multiply` / `divide` 最终执行普通 number 运算，均不满足无损单位文本投影。采用原生字符串十进制位移及最终一次 Number 转换，不新增依赖、不重复实现通用高精度运算库。
