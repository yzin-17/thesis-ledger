# 显式批量报价与组合估值规格

承接[第4～15项](2026-11-04-todo-4-15-delivery.md)的AC09与AC10；实施见[任务](../archive/tasks/2026-11-04-batch-quotes-valuation.md)。

## 显式批量边界

首个消费者为组合估值已经读取的非零持仓集合。Market拥有报价读取、缓存及单飞；Portfolio消费有限、明确的证券身份，不查询证券目录。新增批量HTTP及API Client合同用于同一显式集合，单标Quote不调用批量接口，也不恢复universe或全市场兜底。

单批最多100个请求身份，按规范证券及STOCK／ETF／INDEX类型去重并保持首次出现顺序。每组最多8条报价链，逐组执行；这是批量接口的资源边界，不改变单条Quote原有缓存、主备、有限重试、超时、控制拒绝及错误语义，也不将一条报价链等同于一次来源HTTP。全批先校验再读取，空批、超额和非法身份零读取。结果逐证券保留ready／stale及已有Quote事实，失败保留稳定错误码及控制拒绝原因，未知不填零。内部消费者保留原Error对象，HTTP只序列化稳定诊断字段。

Portfolio按现有持仓明确类型准备批次，基金仍走净值能力；已清零持仓不得新增请求。同一证券跨账户可共享一次本次批量结果，单证券冲突身份不任意选一种。批量结果仅在本次估值生命周期内持有，不跨账户／模式／价格代次复用。超过100个身份由消费者显式分批；不扩大单批协议。

## 估值性能与正确性

AC10先记录当前FX、LedgerEvent现金投影和realized PnL的实际查询／调用次数、投影点数及阶段耗时。现有FX已按币种集合一次请求，realized按账户集合一次读取，LedgerEvent按账户范围一次读取；这些只由代码观察得到，必须用实际输入或受控存储验证后才能下结论。现有portfolio-benchmark.mjs仅用内存夹具，不能冒充真实数据库证据。

仅对基线确认的瓶颈实施最小优化，优先减少重复和不必要列、保留现金投影完整依赖。若测量没有发现需改动的瓶颈，则记录结果与适用数据规模，保留现有正确行为；不为勾选任务制造查询改动。金额、FX缺失、partial／stale、账户／模式、已实现盈亏与资金时钟不变。真实业务库只读，不产生交易、账本、快照或通知。

## 工具与验收

已核对项目es-toolkit 1.51.0的chunk声明及[官方文档](https://es-toolkit.dev/reference/array/chunk.html)：用于已验证数组及正整数分组，保留顺序，不处理业务去重。groupBy会保留分组数组、keyBy会覆盖同键；本次身份冲突和首次顺序需要显式Map验证，不使用覆盖语义。分组复用chunk，不自行实现通用分块工具。

分叶验收：批量合同／去重／并发与逐项失败；组合消费与零仓位／基金／冲突；实际性能基线及有必要的最小优化；包／边界／正式目标运行态。受控来源或内存计数与真实数据库、真实来源分别记录。
