# 优化参数授权步长的精确校验

## 问题与目标

现有[策略风险与优化规格](2026-09-09-strategy-risk-ai-optimization.md)要求先校验参数白名单、类型、单位、范围和步长，再构建完整策略及执行内容。当前步长校验把 (value - min) / step 舍入到 16 位小数，再用整数文本判断整步，可能接受靠近授权点的长小数。

直接对十进制整数系数与尺度判断整除，消除舍入对授权边界的影响。保留白名单、范围、参数 ID、原始字符串、完整策略校验及候选执行顺序。

## 验收标准

- AC1：DecimalValue 提供精确倍数判断，支持不同尺度、负值、零、长小数、大整数及 DecimalValue 参数；除数为零明确拒绝，不借用固定精度除法或浮点余数。
- AC2：实际 applyOptimizationProposal 拒绝授权点两侧与最小值附近的极小偏差，返回原有不符合授权步长错误；合法最小值、最大值、整步及整数周期继续通过；非正步长以原步长业务错误拒绝。
- AC3：只校验输入而不量化或改写其值；未修改参数和基线保持。原参数白名单、范围与类型校验顺序保持，未授权内容不能进入候选存储或回测。
- AC4：新增反例先在旧实现失败；Domain、Server 定向及适用完整包、构建、lint、边界和尺寸通过。当前客户端没有使用新倍数入口，复用上一轮已有交互证据，不把服务端校验变更宣称为新的 UI 或真实部署验收。

## 所有权与范围

精确倍数判断由 DecimalValue 拥有，Server 参数校验使用其稳定接口，不自行复制 BigInt 对齐逻辑。有限 number 与原始十进制文本分别使用已有显式入口，继续检查相应跨层依赖门禁。已核对的 es-toolkit 常规数值函数不满足任意精度十进制整除，沿用领域表示。

不调整授权范围、步长定义、Schema、AI 提示词、模型预算、候选身份和既有冻结结果。没有客户端样式、数据库或原生工程变更；不执行 Docker、外部服务、模型调用或真实业务写入。
