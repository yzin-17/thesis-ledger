## 目标

承接已合入 #44 的三种生成方式。普通界面默认显示“自动选择（推荐）”，仅手动指定时展开技术方式。首次启用或修改调用相关配置必须经过用途验证；主操作为“测试并保存”。正式任务使用保存时确定的具体 mode，不在失败后换模式、模型或重复请求。

## 行为

- auto 是配置策略，不是第四种 SDK mode。每个启用的模型/用途单独验证，按 native_schema、json_mode 顺序验证；只有明确不支持才可继续下一项。json_validated 必须由用户明确允许兼容路径或手动指定。
- 适配器、协议、认证、地址、模型、契约、输出策略、推理相关配置及有效超时参与验证指纹。修改排序、价格不重新调用模型，但仍检查测试费用及正式任务预算。停用和删除不得被测试门禁阻止。
- 验证使用受控样例及与正式任务相同的流式配置；不读取真实账户，不写入正式研究/策略结果。单次操作有调用次数、输出 Token 和总期限上限，费用明确授权。配置保存失败也保留测试审计记录。
- 成功记录绑定具体配置和用途并由服务端生成，客户端不得伪造。修改中的草稿不覆盖当前已保存配置。只有全部启用用途获得匹配验证后才保存；用户可主动关闭失败用途。
- 旧具体 mode 不静默改变。新建默认自动，编辑旧配置保留手动。运行时依旧消费具体模式及冻结指纹，不新增正式任务隐式探测。
- 费用未知、鉴权/权限失败、限流、超时、取消、结果未知、普通 Schema 失败不视为能力不支持，也不得自动重试。

## 界面文案

生成方式：自动选择（推荐）/ 手动指定。
手动方式：按固定字段生成 / 按 JSON 格式生成 / 通过提示词生成；说明分别解释接口字段约束、JSON 语法约束和文字要求，不暗示校验强度下降。
所有方式都检查最终结果。已保存配置展示实际采用方式和验证来源。首输出与空闲超时放入高级连接设置。

## 验收

1. 新建默认自动；手动才展开三种方式，回显与选项同源。
2. 未经验证的启用用途不能绕过 HTTP 保存；手动同样验证。
3. 自动优先结构化，明确不支持才继续 JSON Mode，文本兼容需授权。
4. 测试与正式任务的传输/参数一致，成功记录不混用模型或用途。
5. 无关修改复用有效记录，调用相关变化重新验证；停用不测试。
6. 失败/取消不覆盖旧配置，不追加未授权请求，保留已知用量且未知不补零。
7. 历史模式不改义，在途任务不改模式，升级/回滚保持显式。
8. Schema、服务、HTTP/SSE、Desktop 交互与构建分别验证，真实运行态不能由单元测试替代。
