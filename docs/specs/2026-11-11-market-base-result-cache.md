## 背景与实施条件

2026-11-11盘点时，周期视图在读取基础日线后才查询派生缓存，不能避免该次基础行情请求；当时`MarketCacheControl`只支持报价、基金净值、净值历史、基金持仓及筹码。现已新增精确K线契约和实现，DSA正式快更、Server目标产物和实际Desktop验收均通过；旧生产者兼容能力继续保留。最终运行态输入和验收边界见[完成证据](../evidence/2026-11-12-market-base-result-cache-completion.md)。

本规格落实已授权的盘点和验收设计。原任务T8美股真实回执已汇总，见[两阶段证据](../evidence/2026-11-11-us-intraday-observation.md)；用户随后选择普通查询60秒复用上限。该值是工程策略，不是供应商更新频率或实时性证明。中港、美股均有当日柱盘中修改证据；值相同、收盘后复试成功和适配器推算的完成标记均不能证明来源只返回确认柱。证据不足的来源不据此取得新资格。

## 目标与范围

先覆盖 Server 已接入的交互基础行情：股票、ETF 的日线与 1/5/15/30/60 分钟线，保持各市场、周期、复权和来源的既有支持范围。原生价格读取继续归 DSA，路由选择继续归 Market；在具体来源已选定、实际调用 DSA 基础行情之前复用成功结果。周期派生与指标继续消费基础行情，保持原冻结与指纹语义。

最初闭环限定富途美股股票1分钟不复权、明确开市且窗口包含当日；随后按C5扩展本节所列既有口径，当前支持规则以下文读取契约为准。该首个口径四批成功；DSA分钟执行创建新适配器，`futu_history.py`新建连接并调用`request_history_kline`，没有新增应用结果缓存。OpenD内部行为不在本次可证范围内，60秒只约束从DSA原始获取时点起的新增Server复用，不认证来源端实时性。

报价、基金、筹码、资料、基本面、新闻等现有缓存保持原状；低频数据扩展须先盘点当前缓存、更新规律和读取时点，再形成独立任务包。研究、回测、PIT、冻结窗口及原始事实不接入交互缓存。

## 读取与控制契约

闭环扩展策略：C4实际Redis通过后，按分钟与日线分别扩展当前已适配且控制允许的股票／ETF交互口径。所有范围统一采用用户已选择的60秒工程复用上限，包括明确已休市及纯历史的普通交互查询；这不是历史长缓存，不认证供应商更正频率或交易所实时性。日历未知时保持原受控读取。日线none／qfq／hfq按精确控制代次隔离；24小时历史长缓存继续未启用。

分钟路径保留MinuteResult原始observedAt，日线路径使用原交互端点给出的sourcePriceBasis.observedAt，Server不重新起算。DSA精确读取不使用通用基础行情结果缓存；SDK／OpenD内部行为不作认证，因此60秒不是行情相对交易所的总延迟上限。错误、未覆盖及资格拒绝不写成成功，扩展不自动启用来源或改变主备。

1. 仍由既有路由选择器逐个决定具体主源、备用及兼容条件；缓存不能把备用成功值当作主源结果，也不能新增切源条件。
2. 扩展现有缓存控制体系，针对精确 `bar` 路由和具体目标投影只读控制事实。最小请求语义包括标的、市场、资产类型、周期、复权、用途、`providerId`、`upstreamSource`、`routeIndex`；不读取价格或启用来源。
3. 代次覆盖实际相关的路由、凭证、配置、启停、权限/依赖资格及适配修订。命中前重新读取控制事实；实际读取完成、缓存发布与结果返回前复核。代次不同、控制未知或资格拒绝均不能返回旧代次命中值，晚到结果不得覆盖新代次。
4. 主仓公共 Schema、DSA 投影与 Server 消费必须采用同一契约并做请求关联验证，保留旧五类调用兼容；不能把 K 线路由伪装成 `kind=data`。
5. 缓存保存经校验的行情有效载荷与原始来源事实，不保存可直接跨请求复用的响应信封。命中后仅重建当前请求关联；价格、来源、有效政策修订、获取时点及指纹不改写，再执行原有请求/响应关联校验。

能力首次成功的verification展示记录不单独改变控制代次，避免首次合法成功被当作配置变更拒绝；若同时发生真实账号资格或权限变化，仍按该控制事实失效。

混合版本兼容：若旧DSA明确返回新控制请求不支持、参数不接受或控制端点不存在，Server不得查询或发布新增缓存，应退回原来的精确行情端点，由其原控制与来源资格继续校验。控制关闭、权限拒绝、代次变化、无效响应及普通网络故障不能据此放行缓存。该降级恢复既有读取，不认证新增缓存可用。

## 键、时点与有效期

键使用稳定规范化编码及版本前缀，隔离标的、市场、资产类型、周期、复权、规范化起止区间、有效 `limit`、用途、具体来源、路由位置及控制代次。凭证只使用既有安全修订标识，不进入原文。请求 ID、当前毫秒时刻不进入基础结果键；显式历史时点用途不进入本闭环。派生视图原有 `evaluationAsOf` 及来源指纹约束继续保留，不能为提高命中率删除。

| 数据范围 | 草案中的有效期处理 | 实施前条件 |
| --- | --- | --- |
| 既有股票／ETF普通交互分钟及日线，包括已知休市和纯历史 | 用户已选择60秒，从DSA原始观察时点计算 | 同来源/身份/控制代次；不表述为供应商更新频率 |
| 完整历史的长缓存 | 未启用；24小时仍非已确认策略 | 更正与复权版本事实不充分，不能据此长期缓存 |
| 日历未知、覆盖不足或边界不能确认 | 不进入完整历史的长缓存分支 | 消费 `MarketSessionReader` 的未知原因；不猜休市，不伪造完成事实 |

有效期从原始获取事实计量；Redis 读入、内存转存、派生计算及重复命中均不重新起算。下层若有结果缓存，须保留其获取时点及缓存事实，按剩余总时效预算决定是否可复用，不能把多层 TTL 相加后隐去额外陈旧时间。来源时间与缓存写入时间分别表达。

## 并发、刷新与失败

- 同一代次、目标及窗口的普通并发读取合并。使用现有 Redis 与并发协调能力，提取职责清晰的 Market 模块接口；不向已超阈值的大文件继续追加职责，不在各 Provider 新建平行缓存、计次或主动休眠。
- 手动刷新跳过新增基础结果缓存和现有派生结果缓存；同一轮刷新允许合并，但不能加入刷新前已开始的普通读取。较早的请求晚到时不得覆盖较新刷新结果。是否抵达 Provider 上游以实际下层路径为准，不能仅因跳过 Server 缓存声称绕过 SDK 缓存。
- 首个闭环只缓存有效非空成功值；错误、未覆盖、权限、限频、额度及无效响应不写为正常结果。该闭环不增加历史成功值回退；当前错误仍进入既有错误与切源规则。已有报价等回退语义不变。
- Redis 读写或协调失败时降级执行原有受控读取；保留进程内合并和既有总时限，不能无限等待锁或吞掉控制错误。取消与超时不得污染缓存或其他等待者。

## 所有权与兼容

公共契约归 `packages/schemas`，控制投影和来源执行归 DSA，缓存与交互编排归 Server Market，部署归 infra 正式入口。修改契约与边界时同步维护 `scripts/check-boundaries.mjs` 及 DSA 对应门禁。无需数据库升级，不清业务数据、Redis 全库或 Docker volume；新增缓存使用独立命名空间和正常到期策略。

## 测试与验收

验收通过真实组件计数、受控来源和可控时钟判定，覆盖明细见[验收矩阵](../evidence/2026-11-11-market-base-result-cache.md#受控验收矩阵)。定向测试通过后运行包级检查、仓库门禁，再进行独立 Redis 集成和正式最小部署。浏览器保留真实页面只读与受控刷新两类证据。既有 T9/T10 的开发服务浏览器结果不作为新 Docker 运行态证据。

- AC1：同目标同窗口有效期内重复与并发读取只执行一次受控 DSA 数据调用；过期后获取新结果，命中不延长原始到期时间。
- AC2：身份、用途、来源、复权、周期、范围、条数及代次隔离；控制关闭、资格变化与读取中的代次变化均不能返回旧命中，晚到结果不覆盖新结果。
- AC3：保留原始行情值、来源、时间和指纹；缓存命中正确绑定当前请求，不能改写原响应或伪造完成/PIT资格。
- AC4：刷新跳过指定缓存且并发次序明确；错误不进入成功缓存，Redis 故障、取消及超时正常降级或保留原错误。
- AC5：交易会话与完整收盘判断来自共享日历；未知不使用新增缓存，复权/更正及多层缓存有明确时效上界。
- AC6：旧控制调用、切源、报价等缓存与冻结事实保持兼容；通过边界、包级和仓库门禁，正式部署与四宽浏览器证据分别成立。
