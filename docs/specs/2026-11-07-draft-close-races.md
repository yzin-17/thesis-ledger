# 草稿关闭确认的异步竞态保护

## 目标

`useDraftCloseGuard` 目前只在打开确认框前检查 `busy`，确认结果晚到时仍调用旧渲染中的 `onOpenChange`。确认期间开始提交、编辑内容变化或面板关闭后重新打开，都可能使旧确认越过当前草稿保护。

共享 Hook 在已提交的最新渲染上判断关闭资格；不承担保存、取消任务或恢复草稿的业务职责，不改变各调用方的确认文案与导航。

## 验收标准

- AC1：打开确认框时未忙碌，但确认期间开始提交，确认结果不得关闭面板。提交结束后，新的关闭请求仍可正常执行。
- AC2：确认期间草稿内容改变，旧确认不得放弃新内容；下一次请求按当前草稿重新确认。
- AC3：面板关闭后重新打开，或组件已卸载，晚到确认不得关闭新面板或调用已卸载组件的关闭回调。
- AC4：确认后使用最新关闭回调；原取消、重复请求合并、初始忙碌保护、调用方文案和未修改草稿直接关闭行为保留。
- AC5：共享 Hook 的调用方回归、Desktop 包检查与构建通过；真实浏览器受控交互验证保存中及重新打开场景。受控样本不写业务数据。
- AC6：仓库边界检查识别真实 Hook 调用中的空草稿快照，防止调用方重新丢失异步确认所需的内容身份；注释、字符串及业务对象中的合法空字段不误报。

## 实施边界

责任归 Desktop 共享草稿关闭 Hook。通过已提交渲染的当前状态、打开会话及草稿快照核对确认结果，不新增全局弹窗、业务提交分支或 Provider 请求。消费者必须传递能够区分当前编辑内容和业务对象的可序列化快照；显式 `dirty` 只决定是否询问，不能用 `draft: null` 代替内容身份。全局 `NavigationGuardProvider` 已在异步确认后重新检查忙碌状态，此次只收敛局部关闭保护的同类缺口。
