# 自动估值快照入口 Spec

日期：2026-09-07　状态：已完成
任务文档：[`../tasks/2026-09-07-automatic-snapshot-entry.md`](../archive/tasks/2026-09-07-automatic-snapshot-entry.md)

## 背景与问题

收益分析的资产走势依赖估值快照。当前页面提供“立即拍一个估值快照”按钮，但快照属于持续运行的数据维护职责，不应依赖用户进入收益页后手动补拍。项目已有 `snapshot` 自动化类型、Scheduler 和自动化配置台，当前运行环境却没有对应的持久化任务，因此用户既看不到定时触发状态，也容易通过手动入口重复生成快照。

## 目标

- 收益分析移除手动拍摄快照入口，只消费已经生成的历史快照。
- 当前运行环境创建并启用一个可在“数据与自动化 → 自动化”中查看、编辑、停用和立即运行的估值快照任务。
- 自动任务继续复用现有 Scheduler、运行历史、锁、重试、交易日保护和 `close-snapshots` 工作流。

## 非目标

- 本次不实现交易后或导入后的事件触发。
- 不扩展 Automation Job 的账户范围、实际/模拟模式或 FX 设置。
- 不修改资产走势图的时间粒度和聚合方式。
- 不修改快照数据模型或删除已有快照。

## 现状与约束

- 收益页手动入口直接调用 `POST /automations/workflows/close-snapshots`，不产生 `AutomationRun`，也不经过任务启停、cron 和交易日判断。
- 自动化配置台只展示持久化在 `AutomationJob` 中的任务；运行时处理器本身不是一条可展示的任务记录。
- 当前自动快照处理器选择启用中的实际投资账户，并调用既有 `close-snapshots` 工作流。
- 当前任务编辑界面支持名称、cron 和启停；默认时区为 `Asia/Shanghai`。

## 设计方案

1. 删除收益分析向资产走势传递的手动拍摄回调、忙碌状态和可用性状态，并删除资产走势中的拍摄按钮。
2. 删除只服务于该按钮的 Desktop mutation 与请求函数；服务端 `close-snapshots` 工作流保留，继续供自动化处理器使用。
3. 通过现有 Automation 创建接口，在当前运行环境持久化一条 `snapshot` 任务：名称“每日估值快照”、cron `0 16 * * 1-5`、时区 `Asia/Shanghai`、启用、最多重试 3 次、锁时长 300 秒。
4. 自动化列表继续以 `GET /automations` 为唯一读取来源，不增加隐藏的前端伪任务或运行时临时状态。

## 对外行为或接口变化

- 收益分析不再显示“立即拍一个估值快照”。
- 自动化列表显示“每日估值快照”，并可使用现有编辑、启停、立即运行和历史能力。
- 现有 HTTP 接口不变。

## 数据、状态或兼容性影响

- 当前数据库新增一条 `AutomationJob` 配置记录，不修改既有任务和运行历史。
- 已有快照保留；收益历史读取行为不变。
- 本次配置属于当前环境的持久化运行设置，不修改 current baseline，也不触发开发卷重建。

## 测试策略

### 关键可观察行为

- 收益分析的空状态和有数据状态均不存在手动拍摄按钮。
- 自动化列表接口返回启用中的“每日估值快照”任务，并给出下一次运行时间。
- 快照运行时处理器和 `close-snapshots` 工作流的既有测试继续通过。

### 优先测试层级

- Desktop 组件与请求契约测试。
- Server 自动化运行时目标测试。
- 当前 dev 栈 API 读取验证。

### 可复用的现有测试入口

- `apps/desktop/test/performance-ui.test.tsx`
- `apps/server/test/automation-runtime.test.ts`

### 需要新增的测试入口

无。

### 关键边界与回归场景

- 删除 Desktop 手动入口不能删除服务端工作流，否则定时任务会失去执行路径。
- 自动化任务必须来自持久化记录，不能只在前端硬编码显示。
- 不改动独立现金账户与组合快照的既有口径。

## 风险与备选方案

- 固定 16:00 可能早于部分基金净值更新；本次沿用已有默认配置，后续可直接在自动化任务中编辑 cron。
- 当前环境配置不会自动写入新建数据库；若未来将该任务提升为系统内置任务，需按数据库 baseline 规则单独立项并安排显式卷迁移。

## 验收标准

- AC1：收益分析的资产走势无论是否已有快照，都不显示手动拍摄快照入口。
- AC2：当前运行环境的自动化任务列表显示一条启用中的“每日估值快照”，计划为每个工作日 16:00，时区为 `Asia/Shanghai`。
- AC3：自动快照仍通过现有 `snapshot` 处理器和 `close-snapshots` 工作流执行，既有逐账户与组合快照行为不回退。
- AC4：Desktop 目标测试、Server 自动化运行时目标测试和 dev 栈 API 验证通过。
