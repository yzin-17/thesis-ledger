# 权限检查限频暂停与接续

## 行为与边界

未声明接口分组的来源在首次明确 `rate_limited` 后停止本轮剩余请求；Tushare采用下方来源声明的分接口约束。等级未包含及缺凭证等原因仍独立表达，不将暂停解释为缺权限。检查不自动重试、不等待到冷却结束发起请求。

相同配置与输入的结果存在限频时，按限频项的检查时间执行至少60秒本地冷却；期间重复点击直接复用结果，不刷新原检查时间。当前记录的冷却跨进程重启生效，草稿仍受现有有界缓存隔离。60秒仅是本地退避下限，不保证上游配额已恢复。凭证、端点或等级变化沿用原隔离契约。

部分检查完成后，后续手动检查只补查 `unknown` 功能，保留已经确认的结果及各自检查时间；全部功能已有确定结论时，保留原手动全量更新行为。预算耗尽也能按相同方式接续。Tushare 每轮最多6次、TickFlow 最多14次的现有上限保持。同一服务进程中，相同来源的并行检查只允许一个执行，其他请求明确拒绝，避免并行重复探测。

页面以简短说明告知限频暂停、冷却及补查行为；区分真正触发限频的请求和因此未请求的功能。保留原凭证按钮与保存流程、私有指纹、长期记录及有界请求预算；不新增数据库结构或公开协议字段，不自动使用真实 Key 验证。

逐项检查时间可以早于整份报告生成时间，均须存在且不得晚于报告时间；配置代次和持久化状态必须一致。草稿逐项到期时间不得晚于报告到期时间，仍须符合逐项检查时间早于到期时间的原约束，避免接续报告被消费端误拒绝。

Tushare 按供应商声明的接口分组检查：`stk_mins` 与 `etf_mins` 各自的五个周期共用一次接口权限事实，不将其作为各周期的数据质量或覆盖证明。单接口限频只暂停对应组，其他接口继续；HTTP全局429仍暂停本轮来源。旧的未携带窗口信息的 Tushare 限频记录采用保守一小时冷却，其他来源保持60秒；实际探测失败不延长已有记录的冷却时间。首次真实响应明确当前账号港股日线每小时1次，不把未知窗口误称为一分钟即可恢复。

## 验收

- AC1：首次限频即停止后续请求，冷却内重复及重启读取为零上游请求，冷却后需手动操作。
- AC2：补查不重复已确认功能，保留原时间；预算接续、配置隔离、草稿、等级排除和并行请求均有测试。
- AC3：页面正确表达暂停，四种代表屏宽及原按钮交互通过实际浏览器验收。
- AC4：相关测试、构建及门禁通过，正式完整更新 DSA 镜像并独立验证运行态，保留真实配置与数据。
- AC5：消费端接受不同逐项检查时间，拒绝未来时间、不同配置代次、不同持久化状态和超出报告的草稿到期时间；真实权限检查能返回及保存结果。
- AC6：Tushare分钟接口每组一请求，单组限频不阻塞其他组，重复及跨重启不绕过冷却；全部组均检查或明确保留外部限频阻塞，不能把未知权限视为通过。
