# 策略中心列表可读性与交互优化

## 2. 目标与范围

本轮不改变“策略库 / 回测任务 / AI 实验”三入口和既有独立详情页，只优化三个列表的首屏密度、信息优先级、列宽、状态表达和操作入口。目标是在常见桌面宽度下，用户无需依赖横向滚动即可判断对象、状态、结果和下一步操作。

本轮不修改策略版本模型、回测执行引擎、AI 候选生成与采纳流程，不新增后端推导统计。接口未提供候选数或回测指标摘要时，界面保持缺省表达，不构造数字或以零值代替未知值。

## 3. 交互契约

### 3.1 页面骨架

- 页头只保留“策略中心”和刷新操作，移除英文眉题与常驻说明。
- 页签下不重复显示页面标题和开发说明；搜索、筛选与主操作收敛到同一工具栏。
- 筛选、页码、展开状态继续保存在可恢复的页面状态中；后台刷新不清空已有列表。

### 3.2 策略库

- 列为“策略名称 / 标的、最新版本、最近回测、更新时间、操作”。
- 移除列表中的 V1/V2 能力列；能力限制仍由版本详情说明。
- 最近回测绑定当前所示最新版本，使用中文状态与紧凑本地时间；无记录显示“未回测”。
- 行尾主操作为“回测”，策略名称进入明确版本详情。

### 3.3 回测任务

- 列为“任务 / 策略版本、回测区间、状态与进度、结果摘要、操作”。
- 业务日期使用紧凑日期区间；任务发起时间放入任务副信息，不单独占列。
- 实验分组显示匹配任务数和各状态数量，展开后显示候选/阶段身份；不再用数据列重复“按候选与阶段展开”。
- 已完成任务提供结果入口；失败任务显示短错误摘要；未完成任务不得展示伪造结果。
- 操作列不固定，不遮挡内容，保持紧凑宽度。

### 3.4 AI 实验

- 列为“实验名称 / 来源、状态、进展与产出、更新时间、操作”。
- 名称下显示标的与来源策略等业务信息，不显示 UUID。
- 状态与阶段分开表达，所有用户可见枚举均使用中文标签。
- 移除模型完整路径；使用接口已有的 AI 调用数、回测次数和已选择候选事实表达进展，不推导缺失统计。
- 实验名称是明确的详情链接，更多菜单只承载改名与克隆等次要操作。

## 4. 验收标准

- AC-L01：页头无英文眉题和重复说明，三个列表工具栏与内容紧凑衔接。
- AC-L02：策略库不展示能力列，最新版本、最近回测与主操作均绑定同一明确版本。
- AC-L03：回测业务区间与用户本地时间采用不同的紧凑格式，原始 ISO 时间不直接展示。
- AC-L04：回测实验分组展示匹配任务数和中文状态数量，展开内容仍可逐项进入详情。
- AC-L05：回测状态、进度和结果摘要语义分离；未知结果不显示零值。
- AC-L06：AI 实验列表不展示 UUID 和模型路径，来源、状态、阶段与实际进展可直接辨认。
- AC-L07：用户可见筛选回显、状态与阶段不直接暴露内部英文枚举。
- AC-L08：三个列表不依靠固定操作列或大于容器的强制最小宽度完成桌面布局。
- AC-L09：空态、加载、失败、分页和现有独立详情导航行为保持可用。
- AC-L10：定向测试、Desktop typecheck 与 build 通过；浏览器检查单独记录，不以静态测试替代。

## 5. 证据边界

组件测试和构建只能证明展示逻辑、类型与打包入口；常见桌面宽度、键盘操作、刷新稳定性和真实数据密度必须通过目标浏览器运行态检查。若本轮未更新目标运行态，浏览器门禁保持未完成。
