# 研究默认模型的配置归属

## 范围与约束

研究默认模型属于研究创建流程。将现有配置从“数据与自动化”移入研究助手的“新建研究”，历史任务“再次生成”复用同一配置能力。沿用 `GET/PATCH /ai/settings`、持久化默认值、候选模型和修订校验，不修改服务端路由或自动选择模型。

## 行为与验收标准

- AC1：“数据与自动化”不再展示研究默认模型配置；提供方编辑、启停、删除及其默认引用保护继续有效。
- AC2：新建研究和历史再次生成可在原表单内查看、选择、保存或清除研究默认模型。使用紧凑字段和现有组件，不引入独立大面板。
- AC3：选择只形成待保存改动；保存成功并刷新设置后才能提交研究，创建请求仍携带当前所见修订。未保存、正在保存、读取失败或默认缺失时禁止新提交；有待确认原提交时锁定模型配置，不改变原提交身份和冻结输入。
- AC4：关闭或切换页面时，未保存模型改动纳入既有草稿确认；保存期间禁止关闭。空候选、加载、保存失败和修订冲突都有可理解的反馈，失败不清空研究问题。
- AC5：定向测试覆盖入口归属、保存/清除、失败恢复、提交门禁和缓存修订更新；浏览器验证两个页面的位置和选择操作。真实模型调用和目标配置修改不是本次验证范围。

## 所有权与兼容

研究表单、模型字段及本地草稿状态由 Desktop `ai` feature 持有，复用现有 `providers` 设置 Mutation 和缓存失效协议。此变更不新增 Server feature 依赖、数据库结构或部署配置，不需要调整 `scripts/check-boundaries.mjs`。

旧研究规格中“不由客户端伪造 Provider/模型执行事实”的约束继续成立；这里保存的是服务端默认配置，创建请求不直接提交或覆盖实际执行事实。
