# 全仓复杂度与文件尺寸告警清理

日期：2026-11-12。当前状态：实施中。对应[任务](../tasks/2026-11-12-complexity-warning-remediation.md)。

## 目标与边界

清除现有复杂度、函数长度、嵌套三元表达式及文件尺寸告警。最近完整检查的基线为 526 条 ESLint 告警（297 条复杂度、173 条函数长度、56 条嵌套三元表达式），涉及 419 个文件，另有 5 条存量文件尺寸告警。共享工作区持续更新，实施时按当前源码验证实际数量。

业务行为、公共接口、校验路径和错误码、金融精度、事务及幂等语义、UI 结构和交互、测试场景及断言保持。纯校验、投影、计算和编排按所属领域提取为职责明确的函数或模块；页面按既有内容职责组织，测试按场景组织。禁止代码压缩、机械分文件、降低测试覆盖、关闭规则、增加忽略、提高阈值或用控制流替换技巧掩盖复杂度。

不调用模型或真实 Provider，不改动真实业务数据，不执行部署或重启。数据库验证只允许明确隔离的样本；默认连接测试不得启用。保留工作区全部既有改动，不提交或推送。

## 验证策略

每个职责批次执行定向 lint 与对应行为测试，通过后进行包级测试和构建。页面结构提取涉及实际渲染时使用受控请求验证桌面、平板、窄屏及原交互，真实数据保持只读。原生依赖和构建配置不在范围内。跨模块提取维护依赖方向和已有边界门禁。

最终执行完整 `guardrails:complexity`、文件尺寸及边界／依赖门禁。检查进程可临时使用 `NODE_OPTIONS=--max-old-space-size=8192`；不改写项目或产品内存配置。

## 验收标准

- AC1：完整 ESLint 检查为 0 错误、0 告警，规则、阈值和覆盖输入不弱化。
- AC2：文件尺寸检查无存量超限告警，提取职责及依赖方向清楚，未产生新的超限文件。
- AC3：相关原有行为测试、包级检查和必要受控页面验证通过；场景及断言未删减，校验路径、数值精度、幂等和 UI 行为保持。
- AC4：没有模型调用、真实业务写入、真实 Provider 请求、部署或重启；保留共享工作区修改，证据和当前任务一致。
