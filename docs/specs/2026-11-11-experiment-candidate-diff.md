# 实验候选的具体策略差异

日期：2026-11-11。对应[归档任务](../archive/tasks/2026-11-11-experiment-candidate-diff.md)与[验收记录](../archive/evidence/2026-11-11-experiment-candidate-diff.md)。

## 目标与边界

完整策略候选当前只有 `full-strategy` 标记，Desktop 又把对象、数组显示成占位文字。读取时按实验绑定的冻结基线版本与候选版本比较，展示具体字段、原值与候选值。沿用现有候选 `diff` 数组响应，不改写历史记录、候选策略、采纳状态和回测指标。

## 行为

- AC1：完整策略差异由 Server 的只读投影生成，使用精确版本 ID，不读取当前正式版本代替基线；批量查询中关联版本，不逐候选补查。
- AC2：保留现有参数候选差异及结果读取门禁；缺失或无效版本明确说明无法比较，确实相同则说明无变化，不用占位内容冒充具体差异。
- AC3：Desktop 候选详情、采纳审阅及已有结果入口显示对象、数组和标量的具体值，字段使用中文标签并保留可核对路径；新增、移除、空值分别表达。Mobile 已有完整 JSON 展示继续消费相同响应。
- AC4：部署后的真实既有实验可展开具体差异，四个代表屏宽无页面横向溢出，验证来源与历史业务数据保持只读。

## 设计与验证

Server 在现有候选读取 SQL 中关联两份不可变版本，复用完整定义比较能力，由专题 helper 生成投影。独立差异组件负责前后值展示，共享给候选与采纳审阅。单元测试覆盖对象、数组、缺失版本、相同定义及权限保护；随后执行受影响包验证、正式运行态更新及真实浏览器验收。

不变更数据库、队列、Worker 生命周期或公共响应字段。没有待用户决定的问题；版本缺失采用明确不可用状态。
