# AI 请求的超时、截止时间与受控重试

任务标识：`ai-adaptive-execution`，首次建立于2026-10-25。对应[已完成实施记录](../archive/tasks/2026-10-25-ai-adaptive-execution.md)。2026-10-27按用户附件更新现有方案；[调用链核对与实施证据](../tasks/evidence/2026-10-27-ai-timeout-governance.md)。本版替换v1的冷启动／24小时学习规则，原AE编号保留。

## 目标与边界

正常慢生成可继续、真正停滞能终止、每次终止可归因。连接探测、用途验证、正式研究与维护诊断共用AI执行模块的策略解析规则，各用途拥有独立预算。SDK只执行一次；业务编排负责授权、重试和终态，数据库是事实源。

保留模型、路由、冻结材料、reasoning、输出合同和结果校验。禁止通过缩减内容、换模型、改变传输或输出格式制造成功；2020-12条件迁移仍属于D41，不在本治理中无条件推广。保留数据、配置、凭据及WIP，不stage／commit。部署仅经infra入口；真实G3受明确次数、费用与失败停止边界约束，冻结额度不自动解冻。

2026-10-29 用户授权持续零付费诊断后，允许在隔离样本中对输入、传输方式和出站 Schema 约束做有明确目的的对照，以定位兼容性或性能边界。每次记录具体差异，继续使用原业务 Zod、数值绑定及其他完整验收条件；局部样本成功不能替代正式 G3，也不能通过裁剪或修补响应制造成功。正式生成策略或通用出站合同的变更须先在本 Spec／Task 明确，再实施和验证；该诊断授权不自动修改 Provider、默认配置、业务数据或旧 GLM 冻结额度。

## 状态机与截止时间

- AE1：新任务提交冻结策略、执行预算与有限排队期限，尚不启动执行时钟。首次成功领取时，在既有状态／attempt／租约保护下持久化firstStartedAt、taskBudgetMs、cleanupReserveMs、taskDeadlineAt和策略快照；模型／工具／重试／切换路由／恢复均复用。taskDeadlineAt=firstStartedAt+taskBudgetMs，执行余量=taskDeadlineAt-now-cleanupReserveMs。收尾预留5000ms包含在原预算内。
- AE8：复用数据库轮询，不引入队列体系。新任务queueExpiresAt=createdAt+排队预算，初始排队预算等于冻结执行预算；领取前过期原子失败且不发送。历史已有deadlineAt优先保留，不延后；缺失时仅由原首次startedAt和冻结预算恢复，无法证明首次时间则失败关闭。
- AE9：阶段截止不晚于任务执行截止。跨进程使用持久化绝对时间，进程内阶段耗时用单调时钟。现有编排器负责业务终态，阶段控制器服从任务及显式用户取消；租约丢失不冒充用户取消，晚到成功不能覆盖终态或新attempt。

## 初始策略与兼容

| 策略档位     | 连接建立目标 | 首有效输出 | 输出空闲 | 执行总预算 |
| ------------ | -----------: | ---------: | -------: | ---------: |
| 轻量连接探测 |      10000ms |    30000ms |  20000ms |    60000ms |
| 普通研究     |      15000ms |   120000ms |  60000ms |   600000ms |
| 深度研究     |      15000ms |   240000ms |  90000ms |  1200000ms |

初值由用户指定，不宣称最佳。当前原生fetch／SDK接口不独立暴露TCP/TLS阶段，连接目标必须报告能力不足，不能将响应头耗时伪装为连接耗时，也不为此更换整层传输。

- AE10：用途验证复用目标用途。沿用研究用途和明确reasoningEnabled／高推理配置映射深度，未声明则普通；不按模型名称猜测，不新建产品模式。轻量连接探测与目录读取使用探测档位，目录为非流式。
- AE11：生效顺序为路由显式、Provider显式、用途基准，再按任务余量裁剪；记录默认、覆盖、来源、版本、裁剪与能力边界。旧timeoutMs保持现有非流式完成／连接探针总等待语义，不改称TCP连接超时、不新增为研究流隐藏上限。旧存数值来源不明标legacy并保留原作用域；不能凭等于旧默认认定为系统设置。可证明system来源的阶段缺省使用新基准，不批量改配置。
- AE12：240000ms贯通共享／Server Schema、配置读取、环境和前端高级字段。时间配置上限与既有任务最大预算86400000ms一致，最终阶段仍裁剪。缺省不得保存为伪用户显式30秒；普通界面展示档位／最长执行时间，阶段覆盖无需必填。

## 执行与首因

- AE13：模型请求开始计首输出，非空正文、可观测非空reasoning、有效工具内容增量算进展。头、200、角色、心跳、空增量、元数据不算。首进展后关闭首输出计时器；有效输出重置空闲，但不延长任务期限。
- AE14：非流式没有首片段／空闲判定，完成等待使用明确覆盖或任务余量。本地读工具初值20000ms，可覆盖且受任务余量约束；父取消传给工具，本地工具期间不运行模型计时。Provider内部工具不能冒充本地工具。禁止只Promise.race返回而让实际调用继续；不合作signal的外部实现必须报告停止保证有限。
- AE15：锁定AI SDK 7.0.107满足语义首输出／空闲要求，复用这两个权威计时器；应用只持有任务和工具计时，禁止fetch层重复实现。先记录首因再取消，后续AbortError不覆盖它；上游错误不被后触发本地timer改写。
- AE16：稳定错误码区分连接、首输出、空闲、工具、任务预算、上游主动超时、用户取消与观察结束。保留安全上游状态／标识；事实包含任务／attempt／request、阶段、起点、单调耗时、阈值、截止、余量、最后进展及版本。不写密钥、完整敏感正文或reasoning；连接不可观测时不伪造时间。

## 重试与观察

- AE4：SDK maxRetries=0，数据库轮询恢复不增加调用额度。应用总尝试最多2次，原预算更严格则保留。只重试明确生成前拒绝且安全的瞬时故障；已有有效输出、有副作用工具、首输出超时、未知结果、鉴权／配置／校验、取消或预算耗尽均不默认重跑。
- AE5：Retry-After、退避和预期执行均装入原余量；每次原子预留授权，使用新子signal，不延长期限。缓存故障只能减少额外重试，最多额外1次，费用／调用边界保持。
- AE17：持久化提交返回ID，页面只观察。刷新、退出、断线或观察到期不取消已存任务，显式取消才调用API；准备阶段仍可中止并保留找回身份。诊断读取实际策略／截止时间，观察结束报告“观察超时，后台最终状态待确认”及ID，不写Provider失败、不默认取消。D41已执行包封存为历史，维护接续入口消费统一解析器，不再次运行旧固定时限脚本。
