# 策略定义摘要的三位文本比例

## 问题与目标

策略版本摘要的仓位、止损、止盈、佣金和滑点收到规范十进制文本，先转 Number 再乘百分比，会丢失极小非零、临界长小数或溢出。该摘要沿用最多三位与千分位，不能直接替换为普通两位或费用六位。

扩展现有 ratio-percent 的有界三位展示模式，继续规范化尾数与独立指数；已有两位、六位和 number 入口保持。策略版本仅更改百分比投影，不改定义、校验、引擎或冻结记录。

## 验收标准

- AC1：三位模式保留千分位、最多三位和零值规则；长小数、临界、极小正负、巨大值、非法输入及指数进位正确；旧两位、六位与 number 测试保持通过。
- AC2：有效策略的仓位、目标仓位、止损、止盈、佣金及滑点均使用该合同，真实 Schema 校验和缺失/非法提示保持，读取不改原始 JSON。
- AC3：定向、相关完整包和构建、lint、边界、依赖与尺寸通过；实际 StrategyVersionPage 在 1440、1024、768、390 验证文本、诊断原文、页签和边界，受控数据不发请求或写入。
- AC4：记录最终输入与范围，关闭 Task 并继续 Goal，不把客户端验收扩大为目标 Docker 或 Native 就绪。

## 所有权与边界

共享展示只增加 fractionDigits=3 的有界选项；2 的固定两位和不分组、6 的最多六位与分组保持。策略定义摘要继续归 strategy-version-summary.model，页面消费方式、校验与操作门禁不变。无新依赖、Schema、服务端产品代码、原生配置或运行态操作。

es-toolkit 的浮点 round/multiply 不适合精确文本，沿用已验证的原生 Intl 与十进制指数实现。实施由[任务](../archive/tasks/2026-11-07-strategy-summary-ratio.md)持有。
