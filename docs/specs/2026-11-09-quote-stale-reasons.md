# 行情时效与缓存回退原因

## 目标与范围

行情详情应说明时效异常的实际判定依据。修复报价原因在 Server、Schema 和客户端之间丢失的问题，覆盖 Desktop 与 Mobile；保持行情数值、来源时钟、缓存窗口和交易新鲜度门禁。

## 行为合同

- 报价增加可选 `staleReason`，包含稳定原因码、安全中文说明及可用的 HTTP 状态。兼容旧响应的 `refreshFailure`。
- 交易时段内行情时间超过现有 600 秒阈值时返回明确原因；休市期间按[共享交易时段判定](2026-11-09-market-closed-snapshot.md)核对最近有效快照，不以自然年龄单独告警，不推断请求失败。
- 刷新超时、限流、认证、权限、响应校验、控制版本、缓存设施、请求冷却和等待并发刷新分别返回原因。禁止将原始异常、地址或凭据透传到界面。
- 新鲜备用来源不能仅因 `fallbackUsed` 被认定为陈旧。来源明确标记陈旧但没有细分原因时，说明该标记及诊断缺口。
- 客户端展示具体原因、行情时间与抓取时间。刚抓取到旧报价不能被解释为正常刷新间隔；冷却必须有明确原因码，不以抓取时间推断。
- 旧数据缺少诊断时明确说明当前响应缺少原因，不能把客户端丢字段归因给数据源。

## 验收

- AC1：报价传输、fresh/last-valid 缓存往返保留原因；原始安全错误分类可追溯。
- AC2：时点超阈值、刷新失败、新鲜备用来源和诊断缺失分别验证，无行情值或交易门禁变化。
- AC3：Desktop 与 Mobile 复用说明投影；Desktop 四种代表宽度验证文案、换行、弹窗边界和重试。
- AC4：定向测试、受影响包构建及仓库边界检查通过；受控样本与真实运行态证据分开记录。
