# 投资复盘工作区布局

## 目标与范围

让用户先确认账户、标的和复盘粒度，再选择交易事实。收敛筛选区、时间窗口和空状态的视觉层级，保持既有浅色设计系统、组件和业务数据契约。

实施状态见[任务清单](../tasks/2026-10-24-investment-journal-layout.md)，视觉与验证证据见[验收记录](../reviews/2026-10-24-investment-journal-layout.md)。

## 设计约束

- 页面问题：当前账户下有哪些可复盘对象，接下来应核对哪笔成交和计划？
- 账户、标的和模式分别沿用原有状态来源，切换账户继续执行未保存修改保护。
- 账户与标的筛选组成紧凑、响应式的范围栏；三个复盘标签页保持原有内容和挂载方式。
- 候选时间窗口使用已有 Sheet 承载，两项完整日期时间输入、可选语义、本机时区与左闭右开规则在面板内明确展示。
- 候选空状态保持结果区边界，使用左对齐的短说明；高级兼容分析保留功能，入口放在标签页工具区。
- 使用原子类和现有组件；不修改全局样式、数据请求、统计口径、快照、AI 调用或数据库。

## 验收标准

- AC-01：桌面账户与标的筛选在同一范围栏；窄屏自然换行，标签、按钮和选项没有截断或横向溢出。
- AC-02：时间筛选默认收起，打开后日期时间完整可读；非法窗口不请求，合法窗口沿用原有参数并清除当前对象选择。
- AC-03：时间筛选退出后保留草稿；成功应用关闭面板，入口区分全部时间与自定义时间。
- AC-04：空集、加载、请求失败、候选列表互不冒充；空状态不撑开整页，高级分析仍可打开原 Sheet。
- AC-05：账户切换保护、标的应用、对象选择、三个标签页及高级兼容分析的既有交互回归通过。
- AC-06：在 1440、768、390 宽度完成浏览器检查，至少覆盖空集、有候选、时间面板及错误状态；截图与结论明确属于固定输入的本地界面验收。

## 执行边界

本次为 Web/Electron 共用 React 工作区的局部界面调整。固定输入浏览器不访问业务服务；不触发真实 AI、不更新 Docker、不提交或推送，也不据此宣称远端或原生客户端验收完成。
