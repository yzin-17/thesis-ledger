# 账户成交记录与定投计划分区

> 任务标识：account-data-transactions-investments
> 日期：2026-11-05
> 对应任务：[已完成任务](../archive/tasks/2026-11-05-account-data-transactions-investments.md)

## 目标与范围

账户数据页面将已发生的成交与未来定投安排分开。简化成交记录中的重复标题、技术文案、单位和操作；基金定投进入当前基金账户下独立的“定投计划”页签，空态紧凑、历史计划可追溯。

沿用 Desktop、React、TanStack Query、Base UI/shadcn 和现有原子类。只修改桌面客户端的导航与展示，不改服务端、数据库、金额事实、定投确认或修正协议，不执行真实业务写入。

## 产品行为

- AC1：页签为持仓、成交记录、现金、定投计划。定投能力沿用现有“启用的实际基金账户”限制；其他账户不显示入口，也不因非法深链启用定投查询。地址支持 `tab=fund-investments`，直接打开、刷新与前后导航保持所选页签。账户切换和未保存定投表单继续经过现有导航保护。
- AC2：成交页签下合并筛选和新增工具栏，筛选使用“买卖成交 / 其他事件 / 全部”，省去重复标题及技术解释。表头使用“标的 / 成交内容”“发生时间”，成交筛选下显示“成交金额”；混合事件显式区分金额与数量。基金成交展示份额、单位净值，其他标的明确数量与成交价，不猜测未知品种的数量单位。金额使用明确币种且保持既有十进制精度，缺少成本时不把数量标成货币。来源渠道复用中文映射；已确认定投显示“基金定投”。
- AC3：行内保留常用更正/修改，作废、移除及“查看历史”进入具备可访问名称的更多菜单。沿用已有确认、版本、修正与审计流程；表头和内容对齐保持。
- AC4：定投页签集中展示待确认记录与当前计划；无待确认记录只保留一行提示，不重复零计数与说明。已结束计划和已跳过记录默认收起，可展开查看；恢复、暂停、结束、编辑、新建及确认的现有能力保留。加载失败不得显示成“零计划”。
- AC5：已确认成交可从“基金定投”来源进入对应账户的定投页签；仅根据已有稳定来源 externalId 关联 occurrence，再通过返回的 planId 定位对应计划。已结束的关联计划自动展开。不存在、读取失败或无权限时明确无法定位，不猜测、不增加远程补名请求。

## 验收与边界

定向测试覆盖页签/账户范围、深链与导航保护、筛选、精度与单位、来源关联、行内菜单及定投空态/已结束/失败分支；再执行 Desktop 构建、相关门禁及生产预览的 1440/768/390px 检查。真实业务数据只读；写入流程使用组件测试样本验证，不创建或修改真实计划、成交或账户。
