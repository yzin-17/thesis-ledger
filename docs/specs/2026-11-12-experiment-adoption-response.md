# 实验采纳响应与正式策略结构兼容

## 目标与事实

完成候选应能发布正式策略并返回可解析的成功响应。实际候选 1 已提交正式 v1（策略结构版本为 V3），随后风险计划读取仍限制 V2，导致事务提交后响应报错。正式发布序号与策略结构版本是两个独立概念。

## 行为与边界

- 正式 V2、V3 结构均可只读编译现有百分比止损、止盈和持有周期规则；持久化结构版本必须与定义一致，非正式版本和无效定义继续拒绝。
- 研究入场、离场、仓位及价格口径不转为真实账户规则；风险预览保留真实账户平均成本语义。采纳不会创建或启用风险应用。
- 新采纳、已有采纳幂等重放以及后续候选采纳均返回有效响应，不能依靠风险服务桩替代真实组合验证。
- Desktop 采纳请求失败后重新读取服务端事实，防止事务已提交但响应失败时继续显示未采纳状态；失败本身不触发再次采纳。
- 真实数据只读，不实际采纳、删除或修订用户记录，不新增模型调用。隔离数据库允许验证完整采纳事务；通过正式快更更新本地 Server/Worker，不提交或推送。

## 验收标准

- AC1：V2、V3 正式版本可编译，结构不匹配、未知结构、非正式及非法风险定义仍拒绝。
- AC2：隔离 PostgreSQL 使用真实风险服务和 Controller 完成四类评估终态候选的首次采纳、重放、第二候选发布及响应 Schema 校验；风险应用与模型调用计数不增加。
- AC3：Desktop 失败后刷新事实；受控已提交后响应失败场景展示已采纳入口且不重复提交。
- AC4：本地正式快更通过，对用户已有正式版本只读生成完整采纳响应并验证 Schema；真实页面显示已采纳 v1，未发送真实业务写请求。
