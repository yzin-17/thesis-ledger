## 问题与范围

行情准备成功后，桌面新建 AI 实验仍可能因预算超出公共契约而在客户端发送前失败。原表单只检查正数，且通用错误文案隐藏了实际校验原因。首张用户截图中的 200 次回测、1 亿输入 Token、2 千万输出 Token 和 180000 秒均超过现有合同上限；本次失败时间段服务端没有实验创建 POST。

## 行为与验收

- AI 调用与回测次数上限允许显式填写整数 `0`，表示不限制对应累计次数；正数分别遵守 1–30、2–100 范围和计划所需最小次数。AI 调用合同见[零值不限额](2026-11-12-unlimited-ai-call-budget.md)。其他预算上限及精度要求保持原合同，不自动截断输入。公共预算合同与桌面输入约束使用同一份数值边界。
- 输入、输出 Token 上限也允许显式填写整数 `0`，表示不限制对应累计用量；正数范围及默认值保持原样。单次输出与结算规则见[Token 累计预算](2026-11-12-unlimited-token-budget.md)。
- `0` 必须从表单到公共客户端、创建合同、冻结预算和后台原子准入原样传递，不得按零额度拒绝或转换为默认值。空输入不视为 `0`；后台继续累计实际调用、回测次数与 Token 用量，其他预算、取消、有限轮数和状态终态条件继续生效。
- 创建前完整检查各项预算的整数、上下限、金额格式，显示具体中文字段和允许范围。字段输入保留，修正后沿用已有准备结果和同一提交意图重试。
- 客户端合同校验错误不得退化为笼统的“创建失败”；保留服务错误及网络错误原有处理。
- 默认预算仍可发送创建请求；使用浏览器拦截真实创建 POST，验证服务端失败后重试的幂等键保持不变，成功确认后正常导航。不在共享工作区创建真实实验或调用 AI。
- 验证桌面 1440、1024、768、390 四宽、范围提示、错误显示和修正后恢复。Mobile 当前独立 JSON 输入通过相同预算合同接受次数和 Token 累计上限 `0`，就近说明其语义，不重设计其流程。
