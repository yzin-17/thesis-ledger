# 标的多选入口一致性

## 目标与范围

用户要求检查其他标的多选入口，统一为输入框内标签回显。排查 Desktop 与 Mobile 的目录选择、研究、策略、复盘、自选及竞技场入口；实际多标的集合编辑入口为两端竞技场的自主比赛和日频比赛标的池。

Desktop 沿用 `InstrumentMultiSelect` 与 `ComboboxChips`。Mobile 使用原生控件表达相同行为，继续复用 `InstrumentPicker` 的目录查询、错误和请求竞态处理；不跨平台引入 DOM 组件。

## 行为与验收

- AC01：全部标的多选入口在同一边框内展示已选名称、代码和搜索输入；支持换行、逐项移除和继续添加。
- AC02：成功添加清空搜索文字；添加失败保留文字和已选集合。已选标的仍可搜索，结果显示选中状态并支持取消；禁止重复添加。
- AC03：保留市场、类型、启用状态、标的数量和同市场限制，以及分组导入、草稿提交的原业务数据。
- AC04：单选表单、逐条入库的自选添加、持仓/交易行编辑、只读标的集合、导入行批量勾选保留各自语义，记录排查及保留理由。
- AC05：定向测试覆盖多选与单选隔离；浏览器覆盖 Desktop 既有证据及 Mobile 实际组件的四档代表宽度、连续选择、已选搜索、移除和无页面横向溢出。

## 执行边界

只修改客户端组件、对应测试和验收入口。真实业务数据只读，浏览器多选验证使用受控目录输入，不创建比赛或持仓；不改依赖、原生工程、服务端接口或 Docker。
