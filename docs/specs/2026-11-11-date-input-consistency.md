# 日期组件显示一致性

## 目标与范围

修复桌面 Web/Electron 日期、月份、日期时间输入聚焦后显示浏览器原生分段、与失焦格式不一致的问题。审计所有当前源码消费者及 Mobile 的日期入口。Desktop 继续统一消费 `DateInput`，原生 Mobile 的文本输入按其运行时保留，不将 DOM 组件引入 React Native。

本规格补充 [日期选择统一合同](2026-11-06-desktop-date-selection.md)，明确取代其中可见输入必须使用原生日期编辑器的约定；原始值、约束与表单兼容性继续保留。

## 展示与行为

- AC1：日期、月份、日期时间采用同一个文本输入外观及共享弹层。空值默认占位文字统一为“请选择日期”；已有值在聚焦、失焦、鼠标打开和键盘打开时均按 `YYYY-MM-DD`、`YYYY-MM`、`YYYY-MM-DD HH:mm` 显示，已有秒和毫秒完整保留。
- AC2：手动输入与面板选择更新同一原值。格式不完整或非法时保留草稿并阻止提交，显示中文错误；清除、重置、受控更新、只读和禁用可恢复。聚焦与开关弹层不修改业务值。
- AC3：保留原生表单原值、ref、name、required、min/max、step 与变更事件；日期时间提交仍含 `T`，不转换时区、不舍入精度。原生约束控件仅承担原值与校验，可见文本输入承担编辑和可访问交互。
- AC4：日历中已选日期、今天、悬停、键盘焦点及月份选中态有一致优先级；中文面板不受浏览器语言影响。页面、Drawer、Dialog 在 1440、1024、768、390 宽度无溢出，Escape、标签及焦点行为正常。

## 参考

[Ant Design DatePicker](https://ant.design/components/date-picker) 将格式化文本输入、面板及选中状态分开管理，并提供统一格式、清除与日期时间确认入口。本次沿用项目的 shadcn/Base UI 与 react-day-picker，不增加 UI 库依赖。业务日期范围和冻结时间语义仍由原消费者维护。
