# 按可用来源逐项推荐主备

状态：已实现并完成本范围验收。任务见[实施清单](../archive/tasks/2026-11-10-routing-available-recommendation.md)，验证及受控样本边界见[验收记录](../evidence/2026-11-10-routing-available-recommendation.md)。

## 目标与边界

采用建议时，依据当前部署的提供方配置、有效权限及精确能力目录生成各子项主备。Desktop 负责提出可审查草稿，Server Market 继续拥有编译与保存校验；沿用现有协议，无新增接口、权限探测、来源启用或自动保存。

本合同承接[整类采用推荐](2026-11-10-routing-recommendation-children.md)：覆盖本类全部子项的用户操作语义保持，子项改为按实际可用候选单独选取，不再要求全部继承同一组合。

## 选择规则

- AC1：仅在已有能力键内按完整市场、标的类型、能力、周期与复权匹配 `ready` 项。提供方必须存在、启用且配置完整；需要凭证时必须已配置。需要权限检查的来源仅允许当前配置版本有效、未过期且为 `allowed` 的结果，拒绝未知、等级未包含、缺权限和凭证失效。
- AC2：同一口径先选择已配置凭证的候选，再选择无需凭证的候选；同组优先沿用当前大类提供方顺序，其余按提供方与接口标识稳定排序。此顺序是明确的使用偏好，不代表经实测的质量排名。每个子项最多两家提供方，各绑定一个具体接口，同一提供方不同接口不充当主备。
- AC3：候选不足时自动使用其他符合条件的免凭证来源补齐；只有一个则单源，没有则明确空配置。多接口通过上述稳定规则选择具体来源；不保留旧子项绑定阻碍采用，不跨市场或复权补齐，不启用停用来源、不新增能力键。其他大类、输入对象及历史记录不变。
- AC4：大类默认只从本次合格候选生成，保留其中仍可用的大类偏好顺序并补足至最多两家；子项全部生成精确配置。页面说明按可用来源逐项配置，并说明排序依据；区分普通下拉保留子项与明确采用推荐。草稿已修改且尚未完成保存前检查时，仅对应大类显示“待保存”，不将已保存配置的覆盖徽标或异常说明套在新选择旁；未编辑大类保持已保存诊断，口径数量仍按草稿范围显示。按类隔离详见[展示合同](2026-11-10-routing-category-coverage.md)。最终确认前只改草稿，失败和返回仍保留草稿。
- AC5：定向测试覆盖无 Key 用户、已配置来源优先、免凭证补齐、权限失效、依赖和准入失败、多接口、单源、空配置、跨市场及输入保护；包级构建与门禁通过后，四宽实际浏览器验证真实读取和预览，并以受控无 Key 样本及保存失败检查实际提交，真实业务数据只读。

## 实现所有权

保存入口统一显示“保存配置”，检查期间显示“正在检查配置”，随后进入“确认保存配置”界面，由“确认保存”提交实际写入；未提交的修改标为“待保存”。保存前继续使用现有检查接口生成差异和有效确认凭据，检查失败保留草稿。用户文案采用保存语义，内部 API、字段及确认校验保持现有协议。

推荐纯函数归属 Desktop 的行情路由编辑功能，复用现有权限投影及共享精确键标识，不改变目录或权限事实。排序与按提供方去重复用已安装 `es-toolkit` 的 `orderBy`、`uniqBy`；前者支持多条件排序且不修改输入，后者保留排序后首次出现项。两者为组合步骤，均从 `es-toolkit` 导入。
