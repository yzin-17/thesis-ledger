# 目标保数据升级与部署基线

## 范围与约束

复用[保留数据升级规格](2026-09-27-preserve-data-database-upgrade.md)及 infra 官方入口，完成本次目标升级和部署。默认保留全部业务数据；保留三仓既有未提交修改，不提交、不清库、不删除卷。本轮结束后停止，其余产品验收沿用各自任务。

## 验收标准

- AC-01 状态与结构：重新核对三仓、实际 migration/预期表输入、目标库名及 owner、源 head、现有表和消费者；计划必须绑定实际输入。
- AC-02 升级执行：停止 Server 和全部 Worker 后，取得受限权限备份；在隔离副本恢复并演练同一增量，验证结构、应用角色权限和全部旧列数据保留。输入、身份或演练失败时不得提交源库；单事务失败回滚并保持消费者停止，备份保留用于恢复。
- AC-03 数据保护：升级前后核对两受保护账户及现有标记账户的身份、修订、投影代次、事件与有效账本摘要；Journal 正式对象、快照、分析和 AI 历史保留；现行 Provider/路由配置保留。摘要不包含共享 instrumentDirectory，不创建验收账户。
- AC-04 服务消费：通过 infra 官方 `update.sh` 最小必要目标更新镜像及启动消费者，核对实际镜像、代码/结构输入、Server/Worker 健康及无缺表错误，核验现行 API 与关键新入口的 Schema/失败语义。本次只读镜像核验确认 DSA 缺少现行日历/周期指标合同，故选择 `all`。
- AC-05 证据边界：记录实际命令、输入、最后结果、备份恢复证据及代码/镜像/结构身份。不把部署基线作为完整真实行情、缓存故障、AI 在途恢复、Backtest hard-kill、Desktop/浏览器或内容质量通过。
