# 全接口按成本限流

日期：2026-11-07。对应[实施任务](../archive/tasks/2026-11-07-api-cost-rate-limits.md)。

## 背景与范围

用户要求检查全部接口，按实际成本设置，避免正常浏览和轮询触发 429。基线已将 GET/HEAD 从重任务路径移到普通额度，但仍以来源 IP 和方法共用窗口，且无法区分 POST 查询、预览、模型调用及任务提交。当前源码盘点 328 个接口、Desktop/Mobile 共 44 处轮询配置；清单随实施证据维护。

## 行为合同

- AC1：每个现有 HTTP 操作有明确成本分类与来源依据，覆盖 `/api/v1`、`/api/market`、`/api/market-data`。数据库列表、状态轮询、交互行情、计算预览、普通写入、任务启动、模型调用、外部维护、身份验证、全量导出及运维观察分别预算。POST 查询与 GET 高成本接口按实际调用链分类。
- AC2：按已验证用户或本地工作区识别主体；匿名请求回退来源 IP。不得信任客户端自行声明的用户或随机会话头，也不得改变既有权限、会话撤销及资源归属检查。主体验证基础设施故障返回简洁 503，不泄露异常、不静默降级匿名。接口模板和成本类分别限流，参数、查询和 HEAD 别名不得绕过同一操作额度。来源 IP 另保留高阈值总量保护；预检和健康观察不消耗业务窗口。
- AC3：正常读取、轮询、保存与取消不消耗模型及任务启动预算；Desktop 传输冷却按来源、方法及请求路径隔离，同一操作的查询参数变化保留冷却，避免一次任务 429 拖延其它 POST 查询及取消。按当前 1 秒来源监测及 1.5～2 秒业务状态轮询，验证同一用户 8 个活动页面、每页 6 个业务轮询，叠加来源监测、POST 状态查询、首次浏览及自选刷新，连续多个窗口不产生平台 429；同 IP 的多个已验证用户独立。异常流量仍明确 429 和 Retry-After，拒绝不执行处理器，等待后恢复。
- AC4：完整路由覆盖及成本分类有自动门禁；新增接口未登记、重复或失效登记失败。日志可追踪限流类别和状态，不记录会话或凭证。客户端不新增写请求重试，不改变模型、来源预算、缓存、数据或历史记录。
- AC5：按定向、类型/构建、门禁、维护入口同步、实际只读浏览器验证推进。高频边界通过隔离中间件和真实 HTTP 受控处理器验证；真实业务仅正常浏览，不以耗尽开发服务额度测试。运行态验证必须区分代码同步与镜像更新。

## 成本与预算依据

预算由操作实际行为和现有调用节奏决定，不以方法或业务前缀一刀切。列表及轮询每操作 600 次/分钟、各类合计 3000；行情交互每操作 600、合计 1800，保留领域缓存及来源侧额度；计算预览每操作 120、合计 600；普通写入每操作 120、合计 600；任务启动每操作 20、合计 40；模型调用每操作 10、合计 20；外部维护每操作 10、合计 30；登录注册每操作 10、合计 20，按 IP；导出/全量重放每操作 10、合计 20；运维观察每操作 120、合计 600，按 IP。来源总量保护每分钟 12000 次，正常业务和运维观察分离。

负载预算：8 × 6 × 40 = 1920 次/分钟，叠加八页 1 秒来源监测 480 次和 POST 状态查询 320 次，共 2720 次；最繁忙单操作为 480 次，低于操作 600、轮询总量 3000。页面初始化和交互突发另行计入读取及行情类。报价与图表使用独立行情预算，不能侵占后台状态读取。该预算为当前客户端负载合同，不宣称任意无限并发都不触发保护。

## 架构、兼容与验证边界

平台模块拥有限流窗口、路由成本登记与 HTTP 中间件；身份模块提供已验证主体，根启动入口组合，不让平台反向依赖身份业务。复用既有身份验证并在同一请求内复用其结果，既有 Guard 继续检查权限和归属。所有操作明细来自 Controller 源码，AST 门禁核对登记。

不新增依赖、数据库结构或外部来源调用。限流为当前单 Server 进程内窗口，重启恢复和多实例共享额度不属于本次范围。额度为请求接收频率，已有 Worker 并发、任务幂等、模型预算及 Provider 实际调用控制继续负责执行成本。

未决问题：无。最终验收包括无业务写入的真实导航，以及隔离条件下的额度、主体、取消入口、时间窗口和失败恢复验证。
