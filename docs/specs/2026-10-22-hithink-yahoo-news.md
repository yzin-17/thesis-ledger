# HiThink 新闻接入与 Yahoo 新闻验证规格

实施见[已完成任务](../archive/tasks/2026-10-22-hithink-yahoo-news.md)与[最终复核](../reviews/2026-10-22-hithink-yahoo-news-final-review.md)。用户授权接入现有 HiThink，并验证 Yahoo Finance；原 AKShare/NVIDIA 的 DG3 证据继续复用，模型与研究发布条件保持独立。

## HiThink 的明确边界

- 使用已配置的 HiThink Key，配置及凭据版本不变。官方 `GET /api/news/stock/timeline-list` 以 `thscode`、`offset=first` 和有界 `size` 读取个股新闻；当前账号探针已返回 `600519.SH` 的五条真实元数据。
- 增加 `hithink / hithink-news-stock-timeline / CN / STOCK / NEWS_SEARCH` 精确绑定；不调用官方明确未开放的资讯事件库，也不读取正文或生成摘要。
- 复用现有新闻身份、总预算、执行进程、当前政策与准入保护。固定 HTTPS 地址、单次请求、禁止重定向，限制字节/条数；业务限流与 HTTP 限流均如实表达，不伪造 HTTP 状态。
- 只提供标题、媒体、内容标识、跳转页和明确的毫秒发布时间；原始发表地址与来源首次可用时间保持未知。仅取首屏，分页或窗口完整性不足时保持 partial，不宣称完整历史或 PIT；公共游标本次仍不支持。
- 复用 HiThink 当前 HMAC 凭据修订，首次准入仅覆盖 `600519.SH` 的已审阅近期窗口，有效期最多七天。登记时事务内再次核对凭据与首次记录，已有准入不覆盖或续期；不创建其他股票的准入。
- 通用新闻桥校验当前控制与固定凭据快照；实际从 adapter 读取密钥的专用搜索来源负责校验自身 adapter 凭据一致性。HiThink 新闻直接使用 `ReadContext.snapshot`，不依赖行情工厂的空快照。保留旧行情的凭据读取次数和晚到轮换拒绝，不扩展 Runtime 存量大文件。
- 在原 CN 新闻路线中将 HiThink 设为首源，AKShare 保留为显式备用；其他十七条路线及全部原目标保持。界面展示本次实际数据来源，覆盖说明与原请求取消行为保持。

## Yahoo 验证范围

使用现有安装的官方 yfinance SDK，分别核对 `Ticker.get_news` 和 `Search.news`，有界读取公开美股样本。先确认真实 HTTP/业务结构、非空标题/链接/时间及标的关联，再判断可用性；空列表不等于“没有新闻”或接口通过。探针仅用进程内缓存，不持久化 Cookie，不改变当前来源配置或新闻路线。若宿主与目标结果不同，保留差异及首个未通过层；不以样例或其他来源替代。

## 验收标准

1. HN-AC1：HiThink 精确绑定、元数据/时间、首屏覆盖、传输边界、业务错误与当前凭据守卫通过定向验证。
2. HN-AC2：正式首次准入与政策保护通过，原数据、凭据及其余路线保留。
3. HN-AC3：目标 V3、Market 和实际 Web 返回 HiThink 真实非空新闻，展示实际来源；原 AKShare/NVIDIA 的未变证据继续有效。
4. YN-AC1：Yahoo 官方 SDK 路径与宿主/目标的真实结果可核验，结论明确区分可用、空结果、结构失配和网络/权限失败。
5. HN-AC4：正式更新、运行态代码摘要、数据保全、文档总表和最终复核一致；无模型调用、研究写入或无关配置变更。
