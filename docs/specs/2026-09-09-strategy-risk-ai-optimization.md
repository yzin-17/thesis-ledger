## 1. 背景与目标

本次增加两条直接面向用户的能力：策略保存后能够生成对应的风险监控规则；用户能够调用一个或多个 AI，在明确的修改范围和预算内自动优化策略，执行真实回测并比较候选结果。

产品主流程为：

```text
创建或选择正式策略版本
  → 定义优化目标、可修改参数与预算
  → 一个或多个 AI 独立提出候选
  → 服务端校验并执行回测
  → 对比候选，锁定最终验证方案
  → 查看最终验证结果并采纳新版本
  → 自动生成该版本的风险规则预览
  → 选择账户、确认差异、启用实际持仓监控
```

不使用 AI 的用户仍可直接保存策略、运行回测和生成风险规则。手动创建的风险规则继续保留；用户不必先进入风险中心创建规则，才能配置策略止损。

本规格的关键约束是：**策略是判断条件的来源，AI 只提出候选，回测引擎产生绩效事实，实际监控只产生风险事件与提醒。**

以下边界继续由 V2 负责，本规格不重写：

- 一个策略版本可有多个 Signal Source，但只有一个 Execution Instrument。

## 4. 领域职责与最小模型

### 4.1 职责分离

| 概念 | 职责 | 不负责 |
| --- | --- | --- |
| StrategyVersion | 不可变的交易逻辑、仓位配置、风险定义、执行与成本假设 | 真实账户通知状态、某次实验的预算与测试集状态 |
| MonitoringPlan | 将策略中可监控部分确定性编译为规则定义与覆盖报告 | 调用 AI、读取真实账户、自动启用规则 |
| StrategyRiskApplication | 把某个正式版本应用到具体账户与标的，管理升级和通知配置 | 修改策略、伪造持仓归属、真实下单 |
| OptimizationExperiment | 固定基准、数据、目标、允许修改范围、模型与预算，编排实验 | 计算成交与绩效、修改已发布版本 |
| OptimizationCandidate | 固定的一份候选策略快照及来源、差异和验证关系 | 覆盖基准、凭 AI 文本生成收益指标 |
| AiRun | 一次具体模型调用及审计 | 充当实验总状态或回测任务 |
| BacktestRun | 使用自己的 finalized Snapshot 执行一个固定候选 | 调用 AI 决定成交、读写实际账户 |

以上是逻辑模型，不要求每个概念都新增独立数据库表。优先扩展已有版本、任务、规则和审计模型。只有实验编排和策略风险应用是本次明确新增的业务所有权。

### 4.2 最小持久化信息

**实验**至少保存：所有者、基准版本、参数边界、目标协议及版本、切分协议、数据基准摘要、模型配置、预算、状态与阶段、最终候选锁定信息、测试暴露状态、时间与停止原因。

**候选**至少保存：不可变策略版本引用、执行内容哈希、来源提案、父候选、结构化差异、校验状态、各区间 Run 引用、是否为重复候选及采纳关系。

**风险应用**至少保存：所有者、账户、执行标的、来源正式版本、应用修订号、编译语义版本、不可变规则内容与来源键、适用持仓周期模式、启用与通知设置、覆盖度、创建与升级审计。

实验候选复用 StrategyVersion 的 Schema 校验与不可变快照机制，可增加 `origin=experiment` 等元数据。不得复制一套仅 AI 使用的策略契约。策略库默认隐藏实验中间版本；候选使用实验内编号展示。正式版本的“最新版本”查询不得选中实验候选。

采纳时创建正式新版本并复制已验证内容，保留源候选和 Run 引用；不把旧候选内容就地改写。展示名称的变化可以不影响执行哈希，任何可执行字段变化都要求新候选与重新验证。

## 5. 策略参数与执行内容的结构化

### 5.1 参数描述

在现有 Typed AST 和风险、仓位字段之上生成参数描述，不维护第二份可独立修改的参数值。

每个可优化参数至少具有：`parameterId`、中文名称、确定的目标节点/字段、类型、单位、当前值、Schema 合法范围、可选的优化范围与步长。

`parameterId` 在一个基准版本内稳定；表达式引用继续使用已有 Source/节点身份，不由 AI 拼接任意 JSON 路径。提交提案后由 Server 根据参数 ID 修改规范化策略，重新走完整校验。

例如：

```json
{
  "parameterId": "risk.stopLoss.percent",
  "label": "成本止损比例",
  "valueType": "decimal",
  "unit": "ratio",
  "currentValue": "0.08",
  "optimizationRange": {
    "min": "0.04",
    "max": "0.12",
    "step": "0.01"
  }
}
```

上述参数仅用于说明契约，不是推荐配置。前端把 `0.08` 展示为 `8%`，金额展示币种，周期使用整数。金额、价格、比例等边界采用项目 Decimal/十进制字符串契约，不使用不透明的“原始数值”表单。

### 5.2 首版允许修改

用户逐项授权后，可以修改已存在指标的周期和数值阈值、固定止损/止盈比例、最大持有期，以及已有 sizing 的数值。默认锁定 sizing，只优化信号和风险参数；开放 sizing 时必须说明降低仓位也可能降低回撤。

禁止更改执行标的、Signal Source、周期、AST 结构、风险类型、交易方向、成交时机、市场规则、成本模型、回测区间、数据来源和评价协议。禁止删除既有保护条件。改变这些内容必须另开实验或进入后续结构优化能力。

参数合法性由 Schema 与用户授权范围共同决定；AI 不可放宽用户的硬性风险限制，也不可自行扩大预热范围后重新拉取数据。

### 5.3 实验配置与策略版本分离

实验目标、预算、模型选择、开发/验证/测试时间、初始资金与本次数据截止时间属于 Experiment/RunConfig。它们不成为每次修改策略都要更新的业务参数。

成本和执行假设可以继续作为 V2 策略内容存在，但实验启动时必须锁定；本规格不因 UI 分组而迁移这些字段的领域所有权。

## 6. 策略到风险规则的确定性编译

### 6.1 自动生成的含义

正式策略版本保存后即可查看其自动编译的 MonitoringPlan。编译可以按需计算并按版本缓存，但同一版本、编译器版本与能力输入必须得到相同结果。

此时只生成规则定义和预览，不自动创建启用的实际监控。点击“生成并应用风险规则”、选择账户并确认后，才持久化应用及对应规则版本。

编译器不调用 LLM，不把结构化策略重新交给 AI 解释，不写账户状态。AI 实验候选不批量进入风险中心；只有正式版本可创建实际风险应用。

### 6.2 映射与非映射

| 策略定义 | 首版输出 | 语义 |
| --- | --- | --- |
| `fixedStop` | 成本止损规则 | 已完成评价价格相对平均成本达到指定跌幅 |
| `fixedTakeProfit` | 成本止盈规则 | 已完成评价价格相对平均成本达到指定涨幅 |
| `maxHoldingPeriod` | 持有期到期提醒 | 按 V2 的有效执行 Bar 或 NAV 估值事件计数 |
| 技术离场表达式 | 暂不支持项 | 保留原表达式与缺失能力，不拆成独立阈值规则 |
| 入场条件 | 非风险项 | 后续可做策略信号订阅，不伪装成风险 |
| sizing 比例/金额 | 非风险项 | 资金分配方式不等于仓位上限 |
| 历史最大回撤等回测结果 | 非策略约束 | 不从历史表现反推出实时强制阈值 |
| V2 不支持的风险类型 | 拒绝或兼容性错误 | 不自动转换为近似规则 |

“价格低于”与“成本止损”不得混用。尤其不能把旧风险模块中绝对价格语义的 `fixed-stop`，直接用来承接策略中的固定百分比止损。

### 6.3 统一判断口径

新生成规则与 V2 使用版本化的纯判断内核。至少固定以下语义：

- 成本止损：`price / averageCost - 1 <= -percent`。
- 成本止盈：`price / averageCost - 1 >= percent`。
- 等号边界、正负号、舍入规则和 Decimal 精度一致；旧手工规则的历史比较符号不因此被更改。
- `averageCost` 读取上下文已经确定的单位平均成本，不再次添加费用；记录 `costBasisPolicy`。不得用回测买入价替换实际成本，也不扣除尚未发生的假设卖出费用。
- 编译阶段固定要求的成本语义，运行适配器校验兼容性。成本政策不兼容、成本为零或缺失时，该规则为 unavailable；不得强行宣称完全等价。
- 价格来自策略 evaluation tick 当时已可用的完成价格/NAV，不用盘中最新价替代日线收盘条件。交易计价币种与平均成本币种必须一致。场内成本类规则使用与持仓成本同口径的 raw price；拆股后的单位成本由上下文校准，不将 adjusted Indicator Series 与原始平均成本直接比较。
- 单纯标的不同或数据源不同导致的数值差异，不应被包装为同一回测触发时刻的复现承诺。

### 6.4 覆盖报告

MonitoringPlan 返回：生成规则、未映射的风险/退出条件、非风险条件，以及每项所需的数据、时钟和持仓状态。

分别输出 `riskCoverage` 和 `exitCoverage`，取值为 `full/partial/none`。入场与 sizing 不计入风险规则覆盖分母；技术离场未映射时，不能把整项策略标为“完整监控”。

应用页必须逐条展示未覆盖原因。存在可用规则但覆盖不完整时，用户可以明确确认只启用选中部分；没有任何可运行规则时禁止创建启用应用。不得通过隐藏 unsupported 项来获得 full。

## 7. 实际持仓上下文与监控行为

### 7.1 作用范围

首版风险应用绑定 `accountId + executionSymbol`，监控该账户整项持仓。Signal Source 仍按策略定义读取，但不能因此为其他标的生成账户交易行为。

同一账户与标的首版只允许一个启用的策略来源应用；替换需预览差异并原子停用旧应用。手动风险规则可并存，界面提示重复监控，但不自动删除或覆盖手动规则。

不推断某笔真实成交来自某策略，不把整项持仓拆成虚构策略份额，不修改 Trade Projection。

### 7.2 应用到已有持仓或下一持仓周期

应用时明确选择 `existingAndFuture` 或 `nextPositionCycle`。默认预选前者，但启用确认中必须显示实际成本、持有起点、当前是否已经满足条件及各项未知状态。

已有持仓缺少可信开仓起点时，持有期规则不可运行，成本止损/止盈在成本可信时可单独启用。不能把应用创建时间当成开仓时间。

下一持仓周期从投影确认的零持仓到正持仓开始。追加买入不自动重置连续持有期；清仓后重新开仓重置。持有期计数与 V2 保持同一计数定义，不用自然日差替代交易 Bar/NAV 事件计数。

账户停用、权限变化、实际投影成本/起点修正后必须重新校验上下文。数据校准不能修改已保存风险事件；新评价记录新的投影修订与成本政策。

### 7.3 评价结果与状态

共享纯判断返回 `triggered / not_triggered / unavailable / not_applicable`，并记录实际值、阈值、来源、语义版本和原因码。

- 无持仓通常为 not_applicable，不是止损未触发。
- 预热、价格、成本、持有起点或周期计数缺失为 unavailable。
- unavailable 不能当作 false，更不能经 `not` 变成 true；复用 V2 表达式的未知值语义。
- 数据读取时间与事实 `occurredAt/availableAt` 分开记录；评价事件时间不能用当前服务器时间冒充历史市场时间。

风险评价按策略时钟推进，即使没有新交易信号也必须检查持仓。调度延迟时，只回放当时可用的事实，记录检测延迟，不以最新数据伪造过去的触发。

### 7.4 提醒与交易动作分离

回测风险结果按 V2 转换为 Risk TargetIntent，经执行模型成交或拒绝；`risk > exit > entry`、level 风险重算、下一可执行时点和 DAY 拒单语义保持不变。

实际监控只生成 RiskEvent 与通知/建议，不产生券商订单，不调用 Ledger 买卖命令。严重级别、通知渠道和冷却时间不决定模拟清仓数量。

首个有效评价若发现既有持仓已满足 level 风险条件，可以发出一条“启用时已满足条件”的提醒，但不能追补未发生过的监控事件。持续满足条件按通知冷却策略去重，风险状态与消息发送次数分开记录。

评价状态、事件 ID 和缓存必须包含运行命名空间；BacktestRun、实际应用、账户和持仓周期之间不得串用峰值、计数、触发去重或成本状态。

## 8. 风险应用版本、升级与编辑

每条生成规则保留 `sourceStrategyVersionId`、稳定 `sourceRuleKey`、`compilerVersion`、`semanticsVersion`、应用修订与内容哈希。来源键不能只用可变数组下标冒充跨版本身份；若原 Schema 没有稳定 ID，升级 Diff 必须使用明确的增删匹配并保留歧义，而不是错误就地更新。

已有应用持有生成时冻结的规则定义，不随编译器或引擎部署重新解释。采用新的判断语义必须形成可见差异与应用新修订，经用户确认，不原地更新旧事件。

创建与升级均采用服务端预览：检查所有权、账户状态、标的一致性、数据能力、成本兼容性、现有应用冲突，返回 `previewHash` 与覆盖报告。提交时重新校验预览依赖和预期修订；过期预览返回冲突并要求刷新。

规则与应用的数据库更新应原子完成。幂等请求不得生成重复应用、重复规则版本或重复启用通知。

正式策略发布新版本仅产生“可升级”提示，不自动修改已启用应用。升级保持旧版本历史，重建新修订规则，并停止旧修订的后续评价；排队中的通知发送前检查修订号，防止升级后继续发旧规则消息。

在风险中心允许直接调整启用、渠道、严重级别与冷却时间；核心判断条件只允许：返回策略创建正式新版本，或复制为独立手动规则。复制后明确解除跟随关系，不做双向同步。

来源策略归档不自动删除已启用应用，页面持续显示来源已归档。不能硬删除仍被应用引用的正式版本；删除实验 Artifact 也不能删除已经采纳的策略定义或实际规则。

## 9. AI 优化输入、提案与信任边界

### 9.1 创建实验

用户必须选择：正式基准版本、优化目标、硬约束、可修改参数与范围、开发/验证/封存测试时间、一个或多个 Provider+模型，以及调用/回测/时间预算。

使用已连接且能力可用的模型列表，不在业务代码里硬编码模型品牌。模型未配置或必要能力缺失时说明原因，不创建空转任务。

启动后基准、参数边界、数据协议、成本、执行、评价协议和模型身份不可变。修改需要克隆为新实验，并继承实验族谱和已知测试暴露状态。

### 9.2 发给模型的上下文

包含：基准策略的必要结构、被授权参数、能力清单、锁定目标、开发区间基准诊断、允许披露的验证反馈，以及结构化输出契约。

默认不发送真实账户、凭证、完整 Ledger、私人 Journal 或整包行情。模型只通过受限实验工具取得允许区间的汇总或必要片段，不得到 Artifact 路径、数据库权限或自由查询工具。

不同模型第一轮接收同一规范化任务材料。后续只接收自己候选的允许反馈，首版不进行模型互相辩论、互看答案或自动集成。

### 9.3 结构化提案

示例：

```json
{
  "schemaVersion": "1",
  "baseStrategyVersionId": "9e65f0d0-d1a2-4d81-a4b8-662e94e63e96",
  "changes": [
    { "parameterId": "risk.stopLoss.percent", "value": "0.06" }
  ],
  "rationale": "验证止损范围变化是否改善开发区间的主要亏损交易。",
  "expectedTradeoff": "可能增加止损次数；效果需要引擎验证。",
  "evidenceRefs": ["development:baseline:loss-cluster-1"]
}
```

首版每个提案的 `changes` 都相对于固定基准版本；未列出的参数沿用基准。父候选只记录谱系与反馈关系，不改变补丁应用基点。累计修改仍必须满足最初授权范围。

AI 的理由和预期只作为假设显示。任何自报收益、回撤、胜率或“已完成回测”文本不能写入系统绩效字段。

校验顺序为：结构和大小限制 → 参数白名单 → 类型/单位/范围/步长 → 完整策略 Schema → 能力与依赖闭包 → 用户硬约束 → 执行内容哈希。

拒绝未知参数、任意代码、超限 AST、NaN/Infinity、越界数值及隐式类型转换。错误回馈模型时只暴露可修复的字段信息，不泄露内部路径、密钥或测试内容。

### 9.4 权限

AI 提案视为不可信输入。模型、提示模板或工具结果中的指令不得扩大权限。允许的写入只有受控提案提交；采纳版本、启用规则、修改真实账户和删除实验证据均只能由用户权限路径执行。

模型提供者调用复用现有 AiRun 和凭证管理。封存测试的隔离必须覆盖工具、通用 AI 研究查询、日志摘要与缓存，不是仅隐藏前端 Tab。

## 10. 冻结数据与开发、验证、封存测试

### 10.1 实验级数据基准

新增 ExperimentDataBundle：由 Server 一次准备实验允许依赖的冻结市场数据。它不是 BacktestRun 的共享 Snapshot，也不包含可变策略身份。

预先根据全部允许参数的最大 lookback 推导数据依赖上界，包含 Signal Source、执行标的、Benchmark、FX、公司行动、日历、市场规则、基础分钟数据及预热。缺失依赖时实验失败或不可启动，不让某个模型临时获取另一批数据。

Bundle 保存数据分区哈希、来源与修订、规则/日历/聚合版本、`occurredAt/availableAt` 语义、完整度、区间和预热边界。事实仍须满足 `availableAt <= dataAsOf`；这是知识截止，不是允许引擎提前消费事实。

### 10.2 与 Run-owned Snapshot 的关系

每个新 BacktestRun 继续创建自己的 DataSnapshot，使用固定 Bundle 的所需区间和预热数据生成独占 Artifact。首版直接复制，不增加跨 Run 去重、引用计数、pin、共享可变文件或在线回退。

同一 Run 的 finalized Snapshot 重试继续复用原 Snapshot。Bundle 重建必须是新数据基准，不能让已启动实验部分候选切换数据。

公平比较记录 `marketDataFingerprint` 与 `evaluationProtocolHash`；完整 Run Manifest 还包含候选策略身份和 RunConfig，因此不要求不同候选的完整 Manifest 哈希相同。

### 10.3 时间切分与账户状态

必须按时间顺序配置非重叠的开发、验证、封存测试区间。边界按绝对时间保存，并展示市场时区。系统按已知数据校验范围，不只检查字符串格式。

首版各区间作为独立模拟运行：使用相同的初始分币种资金，重置持仓、挂单、风险和信号运行状态，不把开发区间的盈利或持仓带入验证/测试。

指标可以消费本区间开始之前已知的 warmup 数据，但不得生成该区间外的交易或绩效。首个有效信号及 cross 初始化遵循 V2；不同候选不能因预热长度不同改变实际计分起点。

区间末尾持仓按 V2 估值，不为制造已平仓交易数强制卖出。已平仓交易数、未平仓持仓和风险暴露分别展示。

### 10.4 封存测试的可见性

开发与验证 Run 的允许摘要可以进入迭代反馈；封存测试行情、指标、交易、绩效和衍生摘要不进入模型上下文。

测试 Artifact 由服务端单独授权读取。预热只允许使用测试开始之前的数据，不能经跨区间查询、缓存命中、日志或通用结果接口泄露测试区间。

测试的所有读取和结果揭示记录在暴露审计中。程序的未来函数防护和模型可能已知历史事件是两类问题；系统不宣称限制提示材料即可消除模型训练中的历史知识。

## 11. 评价目标、指标与优化循环

### 11.1 先约束，后排序

实验开始前锁定评价协议，至少包含：数据与执行完整性要求、最低已平仓交易数、最大允许回撤，以及用户选择的暴露/换手限制。

采用以下可解释模式，不由 LLM 生成不透明评分：

| 模式 | 合格候选内的排序 |
| --- | --- |
| 回撤优先 | 回撤从小到大；需满足最低收益与最低交易数，平手再比较扣费后收益 |
| 收益优先 | 扣费后收益从高到低；需满足最大回撤等硬约束，平手再比较回撤 |
| 低换手 | 换手从低到高；需满足最低收益、交易数及暴露要求，平手再比较收益 |

阈值由用户选择并在运行前固定。不存在适合所有资产和长度的统一收益或交易次数默认值；服务端按协议校验必要项，缺失时拒绝启动。

可选展示 Sharpe、Sortino 等指标，仅在引擎已实现且数据有效时显示。不得为了显示完整把未定义、样本不足或零方差指标填成 0。

收益、回撤、费用、换手和交易数沿用 V2 结果定义，保存分析版本；不同 bar 周期的风险统计使用同一日估值/年化协议。候选没有交易不能作为“低回撤优胜方案”。

优化硬约束是历史实验筛选条件，不是未来亏损上限保证。仅降低仓位的候选需要单独标记，并展示平均暴露差异。

### 11.2 有限迭代

每个模型独立经历：基准诊断 → 提案 → 校验 → 开发/验证回测 → 允许反馈 → 下一轮提案。第一版不另加一套由 AI 执行的回测工具实现。

失败提案、重复提案和修复重试均记录并占用相应提案/调用额度。开发表现用于诊断；按验证区间锁定的评价协议筛选候选，不拿最好的某一段结果替代整体协议。

相同执行内容在同一实验中只产生一个规范候选，多个模型的重复提案关联同一候选及原始结果。保留各自来源与尝试次数，不创建一个假装重新执行过的 Run。只做执行内容精确哈希去重，不做未经证明的表达式等价推断。

所有候选不满足约束、未优于基准或有效样本不足时，允许输出“没有发现更优候选”，不能强行生成获胜方案。

### 11.3 诊断证据

回测结果应提供可追溯的信号原因、条件实际值、风险退出、订单拒绝、费用及主要亏损交易摘要，并关联原始事件/Run。

风险阈值触发不等于成交。报告分别统计触发、生成意图、成交、拒绝和持续未解除情况。没有交易要区分无信号、数据 unavailable、资金不足和市场约束。

本阶段不要求为了 AI 重建全部分析平台；优先从既有事件与结果生成最小读模型。没有证据的数据返回 unavailable，而不是让 AI 补写。

## 12. 多模型比较、预算与运行可靠性

### 12.1 模型身份与比较边界

每个模型通道固定 Provider、请求模型、实际返回模型/版本（可获得时）、参数、提示模板版本和工具权限。不能静默 fallback 到其他 Provider 或模型；普通 AI 研究的容错行为保持原状。

同一实验各模型有相同的提案数、轮数、反馈协议、上下文材料和可修改范围。调用成本与速度分别展示，不用“用了更多尝试得到的最高收益”证明模型更强。

模型版本不可确认时记录 unknown，不能承诺重新调用得到相同文本。可复现目标是保存提案后重放同一候选与数据得到同一回测结果。

某模型失败时，其他通道可继续；界面保留失败通道及原因，标记比较不完整。AI 可解释结果，但不能改写排序和裁决。系统只说明本次候选的表现，不输出普遍的模型投资能力排名。

### 12.2 默认规模与预算计算

建议默认 2 个用户选择的模型、每轮每模型最多 2 个提案、最多 2 轮；支持 1–3 个模型。按最大规模估算而不是仅按最终赢家收费。

默认示例最多产生 8 次候选提案。若每个独特候选分别跑开发和验证，预算需覆盖 16 次候选回测、2 次基准回测，以及最终最多 2 个入围候选和基准的 3 次测试，即最多 21 次逻辑回测。重复候选可以减少实际运行，不因此增加提案额度；技术重试另占执行尝试预算。

必须同时配置：模型调用次数、提案次数、回测执行尝试数、输入/输出 token 上限、运行时长，以及可用时的费用上限。保留最终验证所需预算，不能把预算在优化阶段耗尽后静默跳过最终检查。

费用计量记录币种、价格表版本、预计与实际用量。价格或用量未知时费用显示 unknown，不按免费计算；无法估算费用的 Provider 只能启用调用/token/时间硬限制，并要求用户确认费用上限不可保证。

调用前预留本次最大可估计成本与额度，结束后结算。并发预留必须原子完成。达到预算、不再改善、用户取消或超时后停止创建新任务；已经发出的外部请求尽力取消并记录迟到用量，不承诺绝对零超支。

### 12.3 并发、恢复与状态

默认全局 AI 并发 2、每模型通道并发 1、单实验回测并发 1；Server 可以按资源配置更小上限。前端多开页面不会创建新实验或额外轮询任务。

等待用户发起最终验证时释放 Worker 租约，不占用模型/回测并发；用户等待时间不计入计算时长预算。

实验状态使用独立状态机：`queued → running → awaiting_final_test → running → completed`，并允许 `failed/cancelled`；阶段字段区分冻结、基准、提案、回测、候选锁定与最终验证。

没有合格候选可以直接 completed，附 `no_feasible_candidate/no_improvement/insufficient_evidence`。部分模型失败、额度耗尽等作为明确停止原因和质量标志，不假装所有计划都执行成功。

复用项目可恢复任务基础；如不足，只补实验所需的持久化队列/租约、心跳与幂等，不建设通用 Workflow 平台。实验不得仅依赖进程内 Promise 或浏览器打开状态。

同一逻辑提案/回测步骤使用稳定幂等键。进程崩溃后读取已保存结果与租约继续；外部模型调用结果不明时记录 `unknown_outcome` 并保留费用预留，不能声称外部调用恰好一次，也不能无限盲重试。重试限额覆盖失败与超时。

## 13. 最终验证、测试暴露与候选采纳

### 13.1 最终候选锁定

查看封存测试之前，锁定各模型最多一个入围候选、跨模型的预选采纳候选，以及最终通过条件。基准必须一起测试；重复入围候选只运行一次。

最终测试由服务端按固定协议执行，不再把测试结果反馈模型。最终比较页面按预先确定的候选顺序展示，默认不根据测试收益重新生成冠军。

若预选候选未通过，应显示最终验证失败，不自动换成测试区间收益更高的另一个候选。用户仍可人工采纳其他方案，但标记“测试后选择，尚无新的独立验证”，并记录明确确认。

### 13.2 暴露记录

同一实验族谱克隆后继承已知测试暴露，不能通过换实验 ID、调整数据修订或重新下载数据恢复“未见测试集”标签。对系统已知的相同来源标的及重叠区间读取做关联检查。

创建实验时提示是否曾用该区间进行研究，并记录用户声明；系统不能检测全部线下知识或所有外部研究，因此“封存”只代表本系统访问控制与已知暴露状态。

封存测试因基础设施失败可复用完全相同候选与 Snapshot 重试。测试已揭示后的反复查看不是重新获得独立证据。策略、参数或选择规则变化后，需要新实验与未用于选择的数据；沿用旧数据只能标记再次研究。

### 13.3 采纳与规则生成

用户查看策略差异、验证结果、成本、暴露状态及将生成的规则差异后，显式点击采纳。服务端校验候选内容哈希和预期正式基准版本，防止另一页面已发布新版本时覆盖用户改动。

采纳创建正式新版本，不改写旧正式版本、候选或历史 Run；返回该版本的 MonitoringPlan 预览。采纳不会自动启用风险规则、修改现有账户应用或产生真实交易。

需要再次调整任何执行字段时，另建候选并验证，不允许在采纳弹窗中改参数却继续引用原回测结果。

## 14. UI 与交互

### 14.1 策略创建与详情

新建入口只承担必要定义，保存后进入策略详情工作区。不要将 AI 模型、预算、候选对比和账户应用继续堆进现有长抽屉。

编辑内容分为交易信号、仓位与风险、执行与成本；运行区间和实验预算独立展示。条件编辑器明确全部/任一关系、固定值/指标比较、指标参数与判断周期，并仅暴露实际支持的能力。

详情提供“运行回测”“AI 优化”“生成风险规则”，以及定义/版本、回测、AI 实验、风险应用区域。复用既有页面和组件，不为本次新增另一个策略库。

### 14.2 AI 实验与对比

创建实验时按目标、修改边界、时间切分、模型与预算组织，始终展示锁定项和预算估算。选择模型使用现有 Provider 能力列表。

进度页显示每个模型的真实阶段、提案、校验失败、Run 状态、耗时和已用预算，支持取消、返回后恢复查看和分页读取。

对比页固定一列基准，候选列展示变更、验证指标、暴露/交易数、费用、来源模型及有效性。开发、验证与最终测试必须分开展示；测试未开放时不显示其数据摘要。

状态至少覆盖加载、未配置模型、能力不足、部分模型失败、全部无有效候选、无改善、预算不足、用户取消和结果证据缺失。排序字段 unavailable 的候选不可伪装成第一名。

### 14.3 风险应用

预览展示中文自然语言条件、单位、周期、来源版本、适用账户、已有持仓状态、覆盖度与未支持条件。支持“只预览”“保存但不启用”“确认启用”。

风险中心的生成规则增加来源标识与跳转；新版本提示展示增删改差异。原“创建后立即启用”明确表示加入实际持仓监控，不再混同回测里的风险退出。

使用现有 shadcn/Base UI、原子类和 TanStack Query。保持浅色/深色一致，颜色克制，以中性色为主，不新增绿色或紫色主题。固定主要操作区，避免双层 Drawer、全页面重载和重复提交；保持键盘可用、焦点管理与错误定位。

## 15. 服务端接口与错误契约

以下为本次逻辑接口，挂在项目现有 API 前缀下；复用既有策略/Run/AiRun 查询，不新增同义接口。所有操作均校验所有权。

| 方法与路径 | 作用与关键约束 |
| --- | --- |
| `GET /strategy-versions/:id/monitoring-plan` | 正式版本的确定性计划与覆盖报告，不创建实际规则 |
| `POST /strategy-risk-applications/preview` | 账户适配预检，返回 previewHash、覆盖、冲突及当前触发状态 |
| `POST /strategy-risk-applications` | 按预览创建应用，显式 enabled，幂等提交 |
| `PATCH /strategy-risk-applications/:id` | 修改启用与通知元数据；不接受核心条件变更 |
| `POST /strategy-risk-applications/:id/upgrade-preview` | 计算目标正式版本与现有修订的差异 |
| `POST /strategy-risk-applications/:id/upgrade` | 预览哈希＋预期修订，原子切换 |
| `POST /strategy-optimization-experiments` | 固定输入并排队；前置能力与预算校验失败不创建空转任务 |
| `GET /strategy-optimization-experiments` | 分页列表，可按策略过滤 |
| `GET /strategy-optimization-experiments/:id` | 状态、各模型进度、预算、质量标志与最终测试可见性 |
| `GET /strategy-optimization-experiments/:id/candidates` | 分页候选、差异、允许阶段的真实指标与 Run 引用 |
| `POST /strategy-optimization-experiments/:id/cancel` | 幂等取消；停止新调用，已有调用尽力中止 |
| `POST /strategy-optimization-experiments/:id/finalize` | 原子锁定入围、预选方案和协议，执行一次逻辑最终验证 |
| `POST /strategy-optimization-experiments/:id/adopt` | 校验候选和正式版本并创建新版本，不启用实际监控 |

写入使用幂等键；涉及版本升级、最终候选锁定和采纳时使用 expectedRevision/expectedVersion。用户提交的指标、费用、覆盖度和候选验证通过状态均不作为可信输入。

稳定业务错误至少覆盖：`CAPABILITY_NOT_READY`、`UNSUPPORTED_STRATEGY_VERSION`、`RULE_MAPPING_PARTIAL`、`COST_BASIS_UNAVAILABLE`、`HOLDING_ORIGIN_UNKNOWN`、`STALE_PREVIEW`、`APPLICATION_CONFLICT`、`PARAMETER_NOT_ALLOWED`、`DATA_BASELINE_MISMATCH`、`SEALED_TEST_ACCESS_DENIED`、`MODEL_ROUTE_MISMATCH`、`BUDGET_EXHAUSTED`、`NO_FEASIBLE_CANDIDATE`、`FINALISTS_ALREADY_LOCKED`、`STRATEGY_VERSION_CONFLICT`、`EVIDENCE_UNAVAILABLE`。

错误响应包含中文消息、字段路径或缺失能力、可重试标志和关联任务 ID；不返回凭证、内部文件路径或封存数据。

## 16. 模块边界、数据生命周期与发布

实验编排属于 Server 的策略/回测研究业务，单向调用已有 AI Gateway、Backtest 命令和查询能力。AI Provider 不反向依赖实验业务；Backtest 引擎不依赖 LLM。

纯策略判断和规则编译放在真正拥有策略语义的 domain 模块，由回测与实际监控两个消费者复用。账户读取与通知留在 Server 风险应用适配层；不得把 Provider DTO、账户仓储或通知副作用提升到公共 domain。

DSA 继续负责数据能力和事实，不承担 AI 实验、风险应用或 Snapshot 生命周期。Server 使用现有本地 ArtifactStore，不要求新增 MinIO/S3。

实验保留期间保留其输入摘要、提案、成本审计、候选、结果与 Bundle。每个 Run 保留自己的 Snapshot。删除 Run 仍删除其独占 Artifact，但被实验引用时必须提示证据将缺失或通过明确的实验级清理流程完成，不能留下“已验证”但无法读取证据的假状态。

删除实验时清理其专属 Bundle、未保留的候选 Run 与临时数据；已采纳正式版本和风险应用不级联删除。保留必要的来源标识、执行哈希和审计摘要，原实验细节被删除后显示证据不可用。

上线采用两个独立能力开关：策略风险应用、AI 优化实验。关闭 AI 优化不应停用已启用风险规则；关闭规则应用只停止相关监控，不影响现有手工规则和旧回测查询。

数据库迁移优先增量字段与关系，不批量重写旧策略或旧风险规则；迁移需要 dry-run、约束检查和回滚/关闭开关方案。同步维护边界与复杂度门禁，不扩大已有大文件或放松阈值。

## 17. 验收标准

下列标准为首版门禁。任务中的完成勾选必须关联实际证据；只有文档或 Mock 演示不代表在线 Provider、数据库或浏览器验收通过。

| 编号 | 主题 | 验收条件 |
| --- | --- | --- |
| AC01 | 边界与能力门禁 | V1 不隐式转换；G1/G2/G3 按真实能力检查；不增加 V2 排除的执行、风险或真实账本能力。 |
| AC02 | 参数契约 | 单位、Decimal、范围、步长、字段身份与不可变版本一致；实验目标和时间预算不混入策略参数。 |
| AC03 | 确定性规则生成 | 正式版本无需 AI 即可生成固定止损、止盈和持有期计划；重复编译输出一致，候选不进入风险中心。 |
| AC04 | 覆盖完整度 | 风险与退出覆盖分别展示；技术离场、入场和 sizing 不被错误映射；部分启用显式确认，零可用规则不能启用。 |
| AC05 | 判断口径 | 价格/比例语义、等号、平均成本、费用与币种一致；旧手动规则行为不变；成本不兼容显式 unavailable。 |
| AC06 | 时钟与未知状态 | 日线不使用盘中价；availableAt、warmup、cross 和未知值传播正确；未来事实变化不影响此前评价。 |
| AC07 | 实际持仓适配 | 已有/下一周期明确；加仓、清仓重开、起点缺失与投影修正正确处理，不以启用时间伪造持有期。 |
| AC08 | 风险应用范围 | 账户＋标的一项启用策略应用；无持仓为 not_applicable；实际监控不下单，不制造策略份额或真实账本事实。 |
| AC09 | 事件与通知隔离 | 回测/账户/应用修订/持仓周期状态隔离；trigger 与通知去重分开，旧修订迟到消息不会发送。 |
| AC10 | 应用版本与并发 | 预览哈希、所有权、预期修订和幂等有效；升级不自动覆盖，编辑核心条件必须新版本或脱离为独立规则。 |
| AC11 | AI 授权边界 | 只接受已授权参数修改；标的、数据、成本、结构和评价协议锁定；AI 指标与任意代码均不可信。 |
| AC12 | 多模型真实身份 | Provider/模型严格固定、无静默 fallback；同初始材料和额度，独立反馈；失败或未知版本如实显示。 |
| AC13 | 冻结数据关系 | 各候选同一市场数据基准，各 Run 独占 finalized Snapshot；重试、哈希损坏、清理不改变实验数据。 |
| AC14 | 切分与预热 | 时间区间不重叠；每段重置资金与持仓；预热不产出区间外交易，不以不同 lookback 改变计分起点。 |
| AC15 | 封存访问控制 | 封存数据不能通过 AI 工具、通用研究、日志、缓存或普通结果查询进入优化反馈；读取留审计。 |
| AC16 | 候选校验与去重 | 提案经过完整校验和精确执行哈希；重复提案关联真实既有候选与结果，尝试次数不被隐去。 |
| AC17 | 真实回测与诊断 | 所有绩效来自 Run；信号、风险意图、成交、拒绝与费用可关联；不按止损价保证成交，不把无数据当无信号。 |
| AC18 | 评价可信度 | 先硬约束再排序；最低交易数、暴露和未定义指标处理正确；无交易/无改善/证据不足有明确结论。 |
| AC19 | 预算 | 预算含基准、候选、最终验证和重试；并发原子预留；未知价格/迟到用量如实展示，达到限制不新增任务。 |
| AC20 | 恢复与取消 | 持久化状态、租约、幂等和有限重试有效；浏览器关闭/Server 重启后状态可信，不出现重复采纳或永久 queued。 |
| AC21 | 最终验证锁定 | 测试揭示前锁定入围、预选方案和通过条件；基准同测；不能因测试失败自动换一个测试赢家。 |
| AC22 | 测试暴露 | 克隆实验继承已知暴露；重复研究不冒充独立样本外；技术重试只复用固定候选与 Snapshot。 |
| AC23 | 结果对比 | 开发/验证/测试分开；基准、参数差异、暴露、交易数、费用、失败通道和模型来源可比，不用 AI 投票替代排序。 |
| AC24 | 采纳 | 显式创建内容一致的正式版本，校验当前版本冲突；任何执行字段变化需重测；不自动启用规则或交易。 |
| AC25 | 闭环与 UI | 正式新版本返回规则差异预览；策略工作区和风险中心可互相追溯；部分覆盖和冲突状态可操作。 |
| AC26 | 前端可靠性 | 复用既有组件、TanStack Query 与原子类；无重复请求/提交、双层抽屉；键盘、错误定位和深浅色通过验收。 |
| AC27 | 权限与安全 | 跨用户实验/账户/Run 访问被拒绝；提示注入不扩大工具权限；凭证和账户隐私不进入模型或错误日志。 |
| AC28 | 证据生命周期 | Run/实验删除正确清理独占数据；已采纳策略与风险应用不级联删除；缺失证据不能继续显示为可复核通过。 |
| AC29 | 模块与迁移 | AI、Backtest、Risk 依赖单向；纯判断无持久化副作用；增量迁移不改写旧历史，边界和复杂度门禁保持。 |
| AC30 | 市场与资产验证 | 以 CN/HK/US 场内及 CN NAV 代表 fixtures 检查适用语义；真实能力不足标为不可用，不以 Mock 宣称上线。 |
| AC31 | 验证证据 | 离线单元/契约、数据库集成、真实模型小额闭环和浏览器验收分别记录；未执行、失败和环境限制明确。 |
| AC32 | 文档一致性 | Spec/Task/架构/导航职责分离；V2 仅增加增量指向，不伪造原任务完成；全部任务勾选有对应证据。 |

## 18. 发布顺序与本次不做的事

先交付 G1 和策略风险应用，再交付 G2 上的参数优化与多模型实验。测试隔离、预算限制、真实回测和来源追溯是首版组成部分，不能以“先演示 AI”为由后置。

完成后只在旧 V2 Spec 的非目标说明和导航中增加本增量规格链接，原文保持 V2 当时范围，不把当前实施状态回写成历史已完成。架构与用户指南仅在实现后更新当前事实。

不自动修改真实账户，不将模拟盈亏导入持仓，不通过模型讨论替代验证，不承诺优化必然提高未来收益，不把部分数据或未跑完的测试报告成成功。

## 19. 主要风险与控制

| 风险 | 控制与呈现 |
| --- | --- |
| 原 V2 能力未完成 | G1/G2/G3 分开检查，依赖回到原任务，相关入口明确不可用 |
| 同名止损的绝对价格/比例语义混淆 | 显式编译、比较与成本语义版本，旧规则不静默迁移 |
| 真实账户成本与回测不同 | 使用各自可信上下文，记录成本政策，保证公式而非触发日期相同 |
| 多次试验选择到偶然赢家 | 全部尝试可见、锁定评价、封存测试和已知暴露记录 |
| 模型训练已见历史 | 限制为通用参数提案，披露历史知识限制，不称绝对独立验证 |
| 费用未知、外部请求无法取消 | 调用/token/时间上限、预留、迟到用量和 unknown 状态 |
| 模型失败或数据缺失 | 保留失败通道、无候选结论和质量标志，不静默换模型或行情 |
| 更新规则产生重复/旧版通知 | 幂等、修订检查、旧任务失效与通知发送前校验 |
| UI 与模型输出越权写真实账户 | 服务端权限、工具白名单、禁止代码执行、账本写入隔离测试 |
