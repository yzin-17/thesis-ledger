# 回测公告自动准备与增量更新

## 目的与边界

新建中国内地股票回测，在冻结快照前自动获取已选择的本地停复牌或风险警示来源所需公告。页面不新增获取按钮，复用现有配置准备流程及进度展示。计算 Worker、重试和旧快照重放不联网。自然语言策略草稿准备不触发获取。

公告查询、原文下载和事实解析分别记录结果。查询成功且没有公告只能说明检索完成，不能推断正常交易。未知状态继续由现有研究假设及实际依赖规则处理，不增加逐公司、逐时间段人工准入。

## 行为与契约

1. 按证券及自然月拆分请求。巨潮查询必须指定证券与机构标识，不能使用全市场关键词检索后过滤作为精确接入。完成的历史月份复用，最近七天涉及的月份六小时内复用；失败或截断不记为完成。
2. 原文按摘要保存，记录原子替换。摘要核实通过的 PDF 复用；刷新失败保留已有可用原件和事实。下载失败与解析不支持不阻止其他成功项。
3. DSA 维护持久化获取任务：待执行、执行中、成功、失败。领取和终态提交校验执行标识；崩溃后租约过期可恢复，最多三次尝试，单任务有界。相同证券月份合并；结果包含完成数量、错误及检索/下载/解析统计。
4. Server 的市场模块负责公告准备契约，回测模块单向调用。配置准备返回 `preparing` 时客户端自动轮询并显示进度；完成或失败后继续原有价格准备及未知状态规则。直接创建入口在快照构建前检查同一准备状态，未准备完成返回可重试冲突，不落一个伪失败回测。
5. 默认每天上海时间 22:00 更新过去三十天用于回测准备的证券，回查最近七天。后台更新不续期使用时间；数据源被停用或不再路由到本地公告来源时停止新增获取。积压任务重启恢复。
6. 原有 CLI 与显式获取 API 保留维护用途。所有库存和任务写入已有 DSA 数据卷，不新增 PostgreSQL 结构，不重写历史快照。
7. 风险警示结构化解析作为独立执行阶段：仅解析公告明确的生效日期、风险状态和涨跌幅；缺少明确事实保持未知。与自动获取交付分开验证，不能把显示公告当作结构化状态已可用。

## 验收

- AC1：真实公司过滤检索可取得目标公告；历史复用不重复网络查询，有效 PDF 不重复下载，空结果不制造状态。
- AC2：任务并发合并、限次重试、崩溃恢复及晚到结果隔离通过；单项失败保留已有可用数据。
- AC3：现有配置准备自动触发并轮询进度，无新增获取按钮；直接创建不会跳过准备，草稿和冻结重放不触发网络。
- AC4：每日任务只更新最近使用且仍被选用的本地公告来源；重启可恢复，任务状态持久化。
- AC5：真实目标 API、调度执行、页面流程和新快照消费经过验证；原有数据源策略、凭证、数据库及冻结快照保留。
- AC6：风险解析有真实公告与消费验证，未知信息不被补成正常状态。
