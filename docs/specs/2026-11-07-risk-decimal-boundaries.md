# 风险有限数值的十进制计算与事件摘要

## 问题与目标

风险编辑器能够保留极小阈值，但执行链把 number 转为 String 后传入只接受普通十进制文本的 DecimalValue。有限数值采用科学计数法时，成本止损、止盈及风险权重汇总会抛错。成本比较先除法再取差，还可能在 40 位小数舍入后误判极端边界。新事件名称的旧格式化也会把极小非零阈值写成 0。

建立明确的有限 number 到 DecimalValue 的输入边界，保留原始十进制字符串合同和精度。成本规则直接比较等价的十进制乘积和差值，保持原严格及策略复制的包含边界语义。风险事件与 Desktop 当前摘要消费同一领域格式化，既有事件消息继续按冻结事实读取。

## 验收标准

- AC1：DecimalValue 的显式有限 number 入口覆盖普通值、负数、零、科学计数、Number.MIN_VALUE 和 Number.MAX_VALUE；非法非有限数值拒绝。原字符串入口不经浮点转换，也不扩大语法范围。
- AC2：成本止损及止盈对科学计数的价格、成本、阈值可计算；严格与包含边界、历史负阈值语义及成本为零返回不可计算均保持。极小正价格相对 100% 止损不能因除法舍入误触发。
- AC3：证券、账户和组合风险汇总接受极小非零权重，重复代码合并与账户权重选择保持；合计末位超出 1 的既有容差保持。
- AC4：新风险事件名和 Desktop 当前阈值摘要共用领域展示合同，正常数值保持原 3/6 位精度，极小非零值使用科学计数。既有冻结消息不重写，账户、标的及组合名称语义保持。
- AC5：新增反例在旧代码失败；Domain、Server 风险相关定向、Desktop 定向后再逐级完成适用包、构建、lint、依赖及尺寸门禁。真实 Desktop 四宽受控浏览器复核共享摘要，业务请求与写入为 0。

## 所有权与执行边界

DecimalValue 拥有十进制表示及显式数值入口；风险计算、阈值展示和事件生成仍归 Domain 风险模块。Server 只转换其已持有的数值，不增加远程调用；Desktop 通过现有公开导出消费。检查并维护依赖门禁，不增加 common、shared 或 utils 聚合层。已核对的 es-toolkit 1.51.0 round、compat multiply/divide 不提供十进制精确表示；此处使用已有 BigInt 系数与十进制尺度，不复制普通工具函数。

不调整 API 阈值范围、数据库、历史规则、通知开关或执行日程，不运行 Docker 或外部来源，不写真实业务数据。没有原生工程变更。现有事件冻结文本和 number 响应字段保持。
