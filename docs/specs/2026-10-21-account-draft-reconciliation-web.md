# 账户草稿与对账的无模型 Web 路径

本规格承接[账户规格](2026-08-18-position-entry-account-model.md)、[基线与导入合同](2026-08-26-trade-baseline-import-reconciliation.md)及[原 T12/T13](../archive/tasks/2026-08-18-position-entry-account-model.md)。2026-10-21 用户明确选择“恢复草稿/对账的无模型路径”。实施见[配对任务](../archive/tasks/2026-10-21-account-draft-reconciliation-web.md)。

## 范围与边界

恢复账户数据中的持仓草稿审核及确定性对账入口，沿用当前 Ledger 草稿修订、选行提交、冻结和对账命令。草稿来自既有集成或明确的人工输入 API；本次不调用模型。

草稿保存只产生草稿修订，只有用户单独确认提交所选行才写账本。保留原始证据引用、业务观察时间、采集时间和来源时区，不以当前时间补造历史观察。T12/T13 的最终核对见原任务的归档记录。

## 数据与消费合同

- Import 适配层提供只读的审核列表，返回草稿身份、账户、状态、当前修订及元数据、当前修订行和历次已提交行 ID。响应由共享 Schema 校验；缺失修订明确不可审核，不能推断当前行。
- 查询通过同一只读数据库事务取得一致快照。新审核页面只读取规范化的修订数据。
- 当前页面审核持仓快照行。其他行类型显示原问题或范围提示，不强制转换成持仓，不自动删除。已提交行和已完成/取消草稿冻结，当前修订变化后需重新读取及确认。
- 基线行的代码、数量和成本可人工更正，保留稳定来源行 ID、币种及时间元数据；修改后必须先显式保存修订，再选择并提交。重复代码、未解决行、数量/成本格式、账户资产类型及已确认身份仍由共享合同和 Server 拒绝。
- 提交携带打开草稿时读取的账本修订号，冲突后保留草稿并要求重新读取；不得自动改用更新版本重试。默认不替用户选行。完整快照须明确提醒遗漏标的归零并取得本次确认，部分更新保持未提交标的。
- 查询、缓存、失败和请求竞态使用 TanStack Query。切换账户重置当前审核上下文；读取失败或刷新中禁止新增提交，不能消费旧成功缓存继续写入。
- 对账仅显示确定性候选及数量/成本、依据与冲突，查看和选择均不写账本。仅明确确认且原因非空时提交；读取失败、账户不匹配、候选不可用或刷新中禁止确认。

## 验收

1. 草稿入口可打开；无模型请求、来源或路由变化。
2. 新只读响应验证账户及当前修订、时间精度、行与冻结信息；错误合同不回退旧结构。
3. 人工修订、选行提交、失败保留、重复/类型/版本冲突、冻结及账户隔离有定向证据。部分更新不改未提交持仓和现金。
4. 对账候选读取和选择不写入；确认才产生新审计事实，错误或陈旧读取不允许提交。
5. 按定向测试、类型/构建、门禁、正式脚本更新、真实 Web 分层验收。只操作专用账户及草稿，结清停用并保留审计；原业务表、历史结果、配置和模型计数按差集保护。
6. 本范围完成后继续核对原剩余任务；截图及真实模型的未过条件保留，不据此关闭 T12/T13 或总 Goal。
