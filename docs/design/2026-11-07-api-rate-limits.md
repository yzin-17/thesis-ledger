# API 成本分类与限流

现行需求见[全接口按成本限流](../specs/2026-11-07-api-cost-rate-limits.md)。平台拥有接收频率保护，领域服务、Worker 和 Provider 拥有实际执行的并发、幂等、调用资格和资金预算；请求频率不能替代执行成本控制。

## 预算与操作所有权

`platform/api-rate-limit-policy.ts` 定义每分钟窗口，查询和命令成本清单保存每个操作的“方法＋路由模板”。新增接口必须同时登记，Server 的 AST 覆盖测试拒绝缺失、重复或失效登记；仅查看业务前缀或 HTTP 方法不足以判断成本。

| 类别 | 每操作／分钟 | 每主体合计／分钟 | 依据 |
| --- | ---: | ---: | --- |
| 普通读取 | 600 | 3000 | 数据库列表、详情与现有配置读取，容纳初始化及多页浏览。 |
| 状态轮询 | 600 | 3000 | 业务状态 1.5 秒、来源监测 1 秒；八页六路加监测和 POST 状态查询共 2720 次。 |
| 行情交互 | 600 | 1800 | 报价、资料、图表、批量自选和可轮询的准备进度；沿用缓存及来源额度。 |
| 计算预览 | 120 | 600 | 本地复盘、收益、规则测试和纯输入预览；包含无昂贵副作用的 POST。 |
| 普通写入 | 120 | 600 | 表单保存、版本落库、启停、结果应用和取消；不占启动额度。 |
| 任务启动 | 20 | 40 | 回测、重试、优化、批量回放及扫描，可能创建执行工作。 |
| 模型调用 | 10 | 20 | 生成、研究、OCR、测试、周报修订及可能调用模型的自动化启动。 |
| 外部维护 | 10 | 30 | 来源测试、目录同步、资料采集、手工通知、OAuth 创建与配置应用。 |
| 登录注册 | 10 | 20 | 密码计算与防爆破，按来源 IP，不随会话头变化。 |
| 导出与重放 | 10 | 20 | 全账户导出、全量账本重放、完整性扫描等高成本 GET。 |
| 运维观察 | 120 | 600 | 健康和指标，按 IP 独立计数，不被业务窗口耗尽影响。 |

同一主体先检查操作窗口和成本类总窗口，两者均允许才一起计数；更换资源 ID、查询、HEAD 或尾斜线不能获得新操作额度。成本类总量防止轮换多个同类操作绕过保护。未知路由使用固定兜底窗口，不随随机路径生成新状态。

## 主体与组合

`identity/identity-rate-limit-subject.ts` 使用已有 `IdentityService.requireSession` 验证实际会话，返回用户 ID；本地模式使用已有工作区 ID；未取得有效用户时由平台使用来源 IP。会话和凭证不进入限流键或日志。每个请求重新验证，已撤销、过期、禁用及资源归属语义继续由原 Guard 负责；同一请求内复用已验证身份以免重复查询。

根入口组合身份投影和平台中间件；平台不 import 身份模块。来源 IP 另有每分钟 12000 次总量保护，作为认证前的高阈值保护。OPTIONS 不计数；运维观察使用独立预算。单进程状态具有数量上限和过期回收，来源和资源参数不形成无界动态操作键。

## 拒绝、观测与客户端

拒绝返回既有 429 业务响应及 `Retry-After`，处理器不执行。身份验证基础设施故障返回简洁 503，不泄露内部异常，也不静默降级；该捕获范围只包含主体解析，后续处理器保持原错误语义。请求日志先于限流中间件安装，能够记录被拒绝请求的 trace、状态与成本类，不记录身份头或密钥。当前限制为 Server 进程内窗口，重启重置；多实例配额共享需要独立运行态设计。

Desktop transport 将后续冷却限定到来源、方法与路径；同路径查询变化共享等待，其它读取和取消入口可以继续。等待沿用 `es-toolkit.delay` 的 AbortSignal 支持，不自动重放写请求。服务端仍以完整操作模板和成本类控制所有客户端，客户端冷却不能替代服务端额度。
