# 风险规则以账户持仓为目标

风险规则中的“标的”不单独建立 `AccountAsset` 关系，而以现有 `Position` 的 `accountId + symbol` 作为账户持仓目标；`Asset` 继续作为跨账户共享的证券主数据。成本、持有峰值和移动止损下穿状态必须按账户持仓隔离，其中观察峰值可在同一目标下的多条规则之间共享，下穿状态则按规则独立保存。这样可以复用持仓唯一约束和生命周期 ID，避免导入、Ledger 与风险模块出现双重关系事实。

## 考虑过的方案

- 规则只绑定全局 symbol：配置简单，但会混用不同账户的成本和持有状态。
- 新增 `AccountAsset` 关系实体：语义显式，但会与 `Position` 重复并引入双写一致性问题。
- 账户持仓目标：复用现有持仓投影，同时保留账户级成本、生命周期和风险状态隔离，因此采用此方案。

## 后果

- 持仓状态类规则需要账户和证券两个目标字段。
- 同一证券被多个账户持有时，持仓类规则需要分别配置；全局证券观察规则仍可按 symbol 去重。
- 清仓后重新建仓通过新的 Position ID 重置移动止损峰值，但不会自动删除规则。
- Ledger 重建必须更新同一账户、同一标的的现有 Position，而不是无条件删除后重建，否则加减仓会被错误识别为新生命周期。
- `RiskRuleTriggerState.positionId` 只保存当前生命周期引用，不改变 `Position` 的账户聚合唯一键，也不引入 `AccountAsset` 关系表。
- 普通规则的 `activeEventId` 用于通知失败重试；移动止损额外使用 `breachActive` 表达触发区间边沿，二者不等同于“所有规则只触发一次”。
