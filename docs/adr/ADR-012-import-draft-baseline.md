# ADR-012：导入草稿使用 Ledger 基线检测冲突

## 背景

截图草稿创建后，目标账户的同一标的可能被手动录入或其他草稿更新。若旧草稿继续提交，会覆盖较新的绝对持仓余额；若随后回滚，还可能恢复到草稿创建时的更早状态。

## 决策

导入草稿记录创建时的 Ledger 基线版本。提交前比较草稿涉及标的的当前版本；发生变化时阻止提交并展示差异，不自动合并也不直接覆盖。用户逐项确认后可以重新基线，保留已审核行，并以确认时的当前状态作为新的冲突检测和回滚起点。

## 后果

Import Draft Contract 需要保存基线版本和重新基线审计信息，提交与回滚必须验证基线。重复标准代码也必须在审核阶段合并为单行后才能提交，避免幂等键静默折叠数据。

## 替代方案

最后写入覆盖会丢失较新的调整；自动合并无法为绝对数量和成本提供可靠通用规则；冲突后强制重新上传会丢失人工审核成果，因此均不采用。
