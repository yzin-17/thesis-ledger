# 文档目录与生命周期

三仓按内容使用七类目录，文档入口为 `docs/README.md`。同一事实只维护一份正文；文档的职责由其主题、正文和导航分类明确。

## 七类目录

| 目录 | 职责 |
| --- | --- |
| `design/` | 长期系统架构、领域模型与 ADR |
| `specs/` | 需求目标、范围、行为与验收合同 |
| `tasks/` | 当前执行计划、状态、阻塞与最新证据指针 |
| `guides/` | 使用教程、开发规范、部署、维护、备份与恢复说明 |
| `reviews/` | 审查判断、差异分析、发布门禁结论及待评估方案 |
| `evidence/` | 验证记录、原始材料、截图、固定样本与可重复基准 |
| `archive/` | 已完成任务、结案报告、被替代合同与退役产品资料 |

按实际内容创建目录。无活动 Task 时不创建空任务目录或独立的空状态索引，当前入口在本仓 `docs/README.md` 说明。DSA 暂无独立 Review 正文，其来源验证入口由证据导航维护。`TODO.md` 记录已确认延期且尚未立项的实现；`CHANGELOG.md`、README 和工具约定文件保留原名。

## 内容与唯一事实源

目录合并不合并文档正文，也不改变责任：

- 产品 Spec 维护目标、范围、行为、兼容性与验收标准；不保存逐轮实施日志。
- 系统设计说明维护当前运行链、接口与跨仓职责；领域文档维护术语和不变量；ADR 保存已接受的决策。它们在 `design/README.md` 中分组导航，不复制产品 Task 的状态。
- Task 是当前执行状态的唯一责任入口，保存依赖、写集边界、完成条件、未满足的门禁和最新证据链接。历史批次和详细命令进入证据记录。
- Review 维护审查判断、差异与结论；详细验证过程和原始材料由 `evidence/` 保存。
- Guides 维护可供当前使用和运维的操作正文，不复制已执行的历史验收过程。
- 已归档文档只提供历史背景，不能作为当前运行状态或新实现的需求依据。

冲突时先确认事实所属文档及适用基线，再更新拥有该事实的正文并修正引用；不得复制同一方案或建立第二套当前状态。

## TODO 与当前任务

只有已明确延期到后续、且不属于当前完成条件的实现，才能进入 `TODO.md`。普通非目标、未决设计和推测性想法不自动进入 TODO。

当前任务的代码、迁移、真实 Provider、权限、网络、Docker、Worker、数据库、浏览器、设备、用户确认、受保护数据操作及发布门禁，继续由活动 Task 持有。已有 successor Spec/Task 的事项引用 successor，不同时作为 TODO 维护。

TODO 启动实施时，先建立成对的 `specs/YYYY-MM-DD-<topic>.md` 与 `tasks/YYYY-MM-DD-<topic>.md`，再移除 TODO 条目。Spec 首次日期、文件名、任务 ID 和 AC 保持稳定。

## 生命周期与归档

Spec 与 Task 分别判定生命周期：Task 的完整范围与必要验收完成后归档；Spec 不再作为当前需求合同、且原范围已有明确收口或承接时归档。仍有效的需求合同继续留在 `specs/`，长期设计由 `design/` 的独立正文维护。

1. 新主题按范围建立 Spec 与 Task；稳定决策以 ADR 独立保存，当前实现和领域规则更新各自正文。
2. 执行中原位维护 Task 的当前摘要与门禁；范围或接口变化先更新 Spec，详细过程进入证据。
3. Task 的完整范围、必要门禁和最终一致性 Review 均完成，且不再持有未决义务时，移入 `archive/tasks/`。外部条件未满足时继续保留活动任务。
4. 长期系统设计、领域规则与 ADR 留在 `design/`；失效或被替代的设计进入 `archive/design/`。需求 Spec 按自身适用性归档到 `archive/specs/`，结案 Review 进入 `archive/reviews/`。
5. 已结案且仅属于归档任务的证据进入 `archive/evidence/`；活动或跨任务、脚本、CI 共用证据保存在 `evidence/`。可重复基准位于 `evidence/benchmarks/`。
6. 退役产品的整组指南、旧 API 规格与关联素材进入 `archive/legacy/`，保留原语言、原日期和历史适用性说明。
7. 归档保留原文件名、任务 ID、AC、原始失败与验证边界；修复相对链接、跨仓引用、回链、锚点和实际文件消费者。已归档 Task 的原位置不保留跳转壳。
8. 已有历史决策或审计价值的文档归档而非删除。导航条目可合并到现行入口，不重复维护任务状态或证据正文。

原始响应、签名、摘要样本及冻结记录保持字节和历史语义；不能仅为更新文档位置改写业务事实。大型原始日志、备份、凭据和可重建产物不因此进入 Git。新文档使用中文；第三方原文、既有英文资料和工具约定内容保留原语言。

## 跨仓所有权

- ThesisLedger 维护产品领域、账户与研究、客户端、消费侧 API、缓存及兼容边界。
- DSA 维护 Provider 适配、数据合同、原始凭据与 Provider 配置和数据执行语义。
- infra 维护 Compose、镜像、挂载、正式更新、兼容顺序与恢复操作。

跨仓只链接拥有该事实的正文，不复制相同实现或运维说明。文档整理不扩大外部调用、部署、预算和数据操作授权。

## 整理验证

核对文档责任、当前任务与 TODO 的边界、归档条件、重复正文、链接及锚点、命令和实际文件输入；区分本地、受控、真实运行态、来源、设备与费用证据。路径变更不使历史证据自动失效，也不证明当前产品门禁通过。
