# 策略收益研究

普通股票和 ETF 的日线回测默认使用后复权序列，计算指标、模拟操作、研究权益和基准。具体价格条件使用不复权参考行情，例如“实际收盘价低于 4 元”。保存预览会显示每个条件采用的价格口径；均线交叉默认使用后复权，独立条件可以组合。不同坐标的价格不能直接比较。

## 创建与运行

新建策略时核对“保存口径预览”，保存后选择日期和初始研究资金。旧策略开始新研究时，会先显示口径预览；点击“采用研究口径并保存新版本”后，使用新版本准备回测。原版本、原任务和原结果保留。

准备完成后，来源、价格版本、费用与研究假设随本次任务冻结。使用备用来源等需要确认的情况，页面会显示“确认本次冻结输入并创建”。来源失败时保留输入并给出原因。重试历史失败任务仍使用原冻结输入；要采用本模式，应从策略版本创建新的研究任务。

公司行动事件信号需要改写为本次要研究的价格规则，再保存为新版本。系统会指出这一具体限制，不把事件规则自动变成其他策略。

## 投入与结果

固定金额、按研究权益比例及目标权重均表达研究投入。“固定 100 份”表示以模拟操作时点的不复权开盘价计算这 100 份对应的投入金额，再按当时后复权开盘价换成研究单位。后续持仓价值按研究单位和后复权价格计算。

结果中的“模拟盈亏”“研究权益”“研究资金余额”和“研究单位”属于该研究模型。操作明细保留后复权价格、不复权参考价、投入参考份数和计划投入；图表及 CSV 使用同一口径。模型收益依赖供应商后复权方法及冻结版本，不用于还原真实分红到账或真实持仓股数。

## 数据缺口

只有具体价格条件或参考份数需要时才读取不复权行情；AI 实验可预留原价参考，供后续候选复用。两套行情分别按各自路由选择已配置并准入的来源，并独立冻结来源、价格基准和内容证据。原价参考不可用时显示具体来源、窗口和原因。冻结后保留原输入，不重新选源。

AI 实验的开发、验证和测试区间复用完整冻结行情中的子窗口。父窗口引用用于确认采集来源，子窗口有独立内容哈希；裁剪日期范围本身不代表行情版本变化。

实验准备的两套父窗口都覆盖候选预热预算，基线预检使用自身所需子窗口。候选回测执行失败会保存具体原因和已有 Run 引用，并停止后续模型轮次；策略正常完成回测但未通过验证，继续沿用原验证规则。

原价会话缺失时，相关条件不可评估；操作时点缺原价时，参考份数投入不执行。系统不借用前一日价格确定投入。上市日期未知会继续保留为未知；身份、交易日历及现行行情完整性检查仍须通过。

已启用的独立状态能力分别读取并保留事实。来源报告本次数据无效时，只能按现有人工配置尝试备用；可选能力未取得数据会随快照保留失败与警告，其他能力继续处理，不把缺失状态补成正常。必需能力缺失、成功响应身份错误、畸形错误信封、认证或政策变化继续阻断。

## 维护核验

需要重新检查代表窗口时，从主仓使用 Node.js 24 或仓库支持的更新版本执行：

```sh
node scripts/local-runtime/verify-price-research-live.mjs --output <尚不存在的绝对报告路径>
```

该入口核对当前目标服务，复用真实行情和准备代码，允许正常行情证据写入；不创建正式策略、回测或路由。读取范围固定为 510300.SH／600519.SH 的已登记代表窗口，调用前应核对脚本中的区间与外部调用范围。输出分别列出两种口径的来源、根数、冻结摘要和准备状态。

已有准备失败任务可追加 `--run-id <任务 UUID>`，按任务中保存的策略版本、完整日期、投入与费用核验。此模式要求采集后冻结，允许采集新的市场观测；在临时目录生成隔离快照、运行正式计算器并核对离线重放，完成后清理临时产物。报告保留来源、快照摘要、结果和业务表摘要检查，不改写原任务。

追加 `--prepared-report <先前成功报告路径>` 时，只复用该任务已成功准备的冻结输入，重新核验当前路由和内容身份后生成隔离结果，不重新采集价格；这只能作为原观测的复算证据，不表示来源当前可用。

已有冻结配置的任务可使用 `--run-id <任务 UUID> --frozen-input`，直接复算原任务的冻结价格和日期区间。此模式禁止重新采集价格，仍正常读取配置所需的日历及状态事实；不创建任务、不恢复实验、不调用 AI。业务表摘要须保持一致。原失败记录继续保留，新的实验结果需要重新发起实验。子窗口修复的实际验收见[证据](../archive/evidence/2026-11-12-price-research-frozen-subwindow.md)。

在上述冻结输入核验中追加 `--status-source-error`，可在独立进程的 HTTP 边界向已配置的交易状态目标注入标准来源 502，核对失败冻结、其他能力保留及离线重放。该选项只允许与 `--frozen-input` 一起使用，不修改 DSA 或真实路由；报告明确列出注入目标。来源失败隔离的验收见[证据](../archive/evidence/2026-11-12-status-source-failure-isolation.md)。

候选因冻结预热范围不足失败时，使用 `--run-id <候选开发任务 UUID> --candidate-warmup --output <尚不存在的绝对报告路径>`。入口只接受已失败实验，按原基线及预热预算重新采集两套价格，在临时快照中复算已有候选的开发／验证区间并核对离线重放；不运行封存测试。另在连接私有临时表中验证开发／验证执行失败的状态留存，事务结束自动删除。报告检查包括候选表在内的业务摘要，原实验、AI 调用及真实路由保持原样。该模式不能与其他核验模式混用。

需求合同见[规格](../specs/2026-11-11-backtest-return-research.md)，部署及验收边界见[实施证据](../archive/evidence/2026-11-11-backtest-return-research.md)。
