# 桌面端 UI 组件约定

## 组件来源

桌面端 UI 组件通过 shadcn CLI 生成并维护，配置位于 `apps/desktop/components.json`。当前使用 `base-vega` 风格，组件源码落在 `apps/desktop/src/components/ui/`。

shadcn 是组件源码生成与更新工具，不是运行时组件库。生成的组件可以使用 `@base-ui/react` 作为底层无样式原语；这属于 shadcn 组件的实现依赖，不代表项目另行维护一套 Base UI 组件封装。

因此，新增或修复组件时应优先使用 shadcn registry 中的组件结构，避免重新设计同一组件的 Provider、状态管理、Portal、Viewport 或交互生命周期。

## 可清空下拉输入

同时提供清空与展开操作时，尾部顺序统一为“清空 → 下拉箭头”，下拉箭头固定在最右侧。两个按钮使用相同尺寸，在同一个 `InputGroupAddon` 中以共享间距排列；清空出现时不隐藏已配置的展开入口。

`ComboboxInput` 的业务清空等尾部按钮通过 `endActions` 传入，内置清空使用 `showClear`。业务组件不要再追加第二个尾部容器或通过 CSS order 调换顺序。清空、失焦、禁用和选择的业务语义由原消费者保留。

## 列表表头

有列标题的 Desktop 表格统一使用 `TableHeader` 和 `TableHead`，固定操作列表头使用 `StickyTableActionHeader`，其默认样式复用 `TableHead`。默认表头为 `bg-muted`、`text-xs`、次级文字色、适中字重及 40px 高度，单元格内边距为横向 12px、纵向 8px。

消费者只声明列宽、数字对齐、响应式隐藏等业务布局，不重复指定表头背景、字号、字重或内边距。排序按钮保持同一字号和字重，当前排序可使用正文色突出。固定操作列保持不透底背景和左边界；窄屏表格继续在自身容器滚动。键值资料表、无列标题的卡片列表与分区标题保持原语义。

## 数据区域的加载与刷新

桌面端和移动端的表格、卡片列表、图表均按实际读取的数据区域显示圆形加载指示。

- **首次读取**时，在结果区预留空间，居中显示一个加载圈。请求成功返回空集后才展示空态。
- **同一范围再次读取**时，保留已有行或曲线。将加载圈叠放在数据区域与当前滚动视口交集的中央，横向或纵向滚动时随可见区域重新居中。浮层不占布局空间，允许继续滚动，并保留焦点、筛选和滚动位置。切换账户或模式时按新范围取数。
- **同一区域由多个请求共同绘制**时，共用一个加载圈。例如“资产总值与累计盈亏”图将加载圈放在图内，两项请求中较快的一项返回后即可展示其数据，较慢的一项结束后再收起。其他区域的请求独立管理自己的加载态。
- **读取失败**时，就近显示失败原因和重试入口，保留当前范围内仍可展示的数据。该区域所有相关请求均已结束时收起加载圈。离线暂停、追加分页和表单提交分别使用对应状态。

密集结果区可使用 `Table` / `TableContainer` 的 `refreshAvoidText` 或 `ListRefreshRegion` 的 `avoidText`：仍优先位于可见交集中央；若与文字重叠，则沿竖向选择最近的可用空隙，避免价格、日期等可读内容被覆盖。默认消费者保持严格居中。

桌面端优先复用 `TableContainer` 的刷新状态或 `ListRefreshRegion`，移动端复用 `QueryList` 或 `MobileListRefreshRegion`。加载指示须有可访问的中文名称，并遵循减少动态效果的偏好。

验收使用可控慢请求，覆盖首次读取、有数据刷新、失败重试，以及两个请求以相反顺序返回。在桌面和窄屏实际滚动长表或卡片列表，检查圈的位置、原数据的可见性和布局稳定性。

## 列表链接

表格行、卡片列表和资料列表中的链接在默认、悬停和键盘聚焦时都不显示文字下划线。可通过文字颜色或行背景提示悬停，并保留可见的键盘焦点框。页签的选中指示线沿用原样式。

## 侧栏与页签的焦点留白

独立滚动正文优先使用 `SheetBody`。滚动边界保留四周 4px 内边距及 `scroll-p-2`，容纳当前 3–4px 焦点外环；负外边距用于补偿留白，不额外增加内容分组间距。等效手工滚动区也须遵守同一合同，包含账户列表、嵌套导入内容和按钮。

长错误说明放在滚动正文内，避免固定错误区把编辑内容挤没。标题、正文和底部操作区不相交；整体滚动的侧栏须限制在动态视口内并保证末项可达。横向页签的滚动视口同样保留焦点空间，控件高度和栏到面板的有效分组间距由共享 Tabs 维护。

浏览器验收量取实际外环到 overflow 祖先的距离，并检查长内容、错误、末项及关闭操作。高于视口的编辑框分别验证上下边缘可达；不能仅用没有横向溢出作为无裁切或无碰撞证据。

## 草稿关闭保护

含未保存内容的侧栏和弹窗复用 `useDraftCloseGuard`。`draft` 传入可序列化的当前编辑字段及业务身份，例如账户、记录 ID、研究模型和目标版本；`dirty` 仅控制是否询问，不能替代内容快照。已有 `key` 在目标切换时卸载整个编辑器的消费者，可沿用该会话边界。

确认期间开始保存、内容更新、切换目标或面板重新打开时，旧确认不得关闭当前编辑器。共享 Hook 核对最新已提交状态；保存成功后的关闭由业务流程负责。不要在确认回调内自行提交或清理其他会话的草稿。

新增消费者须验证取消、未修改直接关闭及晚到确认；目标可切换时覆盖新目标保留。仓库边界门禁拒绝真实调用中的 `draft: null`，合法业务字段中的空值仍可使用。

路由离开与账户模式切换复用 `NavigationGuardProvider`。字段所有者通过 `useNavigationGuard` 登记真实 `draft`；非受控表单可登记由实际编辑事件递增的版本。只保护在途动作时显式使用 `dirty: false`。父页协调和子编辑器同时登记时，成功保存后的导航 bypass 要传递到实际字段所有者。

全局确认同时核对草稿集合、注册会话及路由请求归属。确认期间新内容、编辑器替换或请求目标变化时拒绝旧结果，保留当前输入并允许重新请求；不要把回调引用变化当作草稿变化。新增入口须覆盖保存后合法离开及取消后快速重试。

## Toast 约定

Toast 使用 shadcn `base-vega` 的 `Toaster` 结构：

- 应用根部渲染 `Toaster`，由它组装 `Toast.Provider`、`Toast.Portal`、`Toast.Viewport` 和 Toast 列表。
- 业务代码通过组件导出的 `toast` 或 `useToastManager` 创建和管理通知。
- 自动关闭、队列、堆叠、滑动关闭和动画由底层 Toast 原语处理，不在业务组件中增加自定义计时器或重复的关闭副作用。
- 项目可以保留中文无障碍文案、语义颜色变量和 `layer-toast` 层级类；这些属于项目主题适配，不改变 shadcn 的组件结构。
- 错误通知如果显式设置 `timeout: 0`，表示需要用户手动关闭或执行操作；这与成功通知的短时展示策略分开处理。

## 更新组件

更新已安装组件前，先在 `apps/desktop` 目录执行：

```bash
pnpm exec shadcn docs <component>
pnpm exec shadcn add <component> --dry-run
pnpm exec shadcn add <component> --diff <component>.tsx
```

先检查 registry 与本地差异，再将必要的主题变量、中文文案和无障碍属性合并回本地源码。不要用手写的平行实现替代 shadcn 组件，也不要在未确认影响范围时直接覆盖其他已安装组件。
