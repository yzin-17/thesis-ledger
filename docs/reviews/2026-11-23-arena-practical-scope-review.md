# 竞技场数据依赖与收尾边界复盘

日期：2026-11-23。范围为[竞技场主规格](../specs/2026-11-12-autonomous-model-arena.md)、[历史回放规格](../specs/2026-11-12-arena-replay-live.md)及其当前阻断代码。主任务状态仍由[竞技场任务](../tasks/2026-11-12-autonomous-model-arena.md)维护。

## 结论

现有设计把普通模拟账户的可用条件扩大成了完整市场执行事实的共同证明。随后通过补来源、归档、准入和诊断维持这些前提，实际可运行的最小路径没有及时收敛。这是本轮 Agent 的设计和推进问题，不能统一归因于数据源不足。

必须区分三类事项：应收缩的模拟依赖、确实缺少的业务实现，以及需要真实模型或远端环境才能完成的独立验收。复盘提出下述收敛建议，未据此修改现行 Spec、业务代码、来源配置或验收状态。原合同要求仍然有效，不能通过改文档把既有失败改为通过。

已完成的两证券官方事件重建及区间证据继续复用；本次复盘不要求重做或删除这些成果，也不把已明确要求的完整历史回放缩成短窗口验收。

## 同时确认的实现问题

### D01 港股读取器没有成功路径

[港股执行读取](../../apps/server/src/market/market-hk-live-execution.ts)在报价合格后记录若干可用字段，再无条件加入价格限制和两类结算的缺失诊断，最终仍返回 `status: 'unavailable'`。函数没有生成 `observation`、交易日期映射及费用函数的成功分支。

因此继续补数据不能单独使港股通过。本轮前序修复完成的是币种、当前观察和诊断，不是完整模拟执行。此前把剩余事项仅表述为来源缺口不准确。收敛合同后仍须实现本期支持范围的成功路径，并用实际领域提交及撮合验证，不能删除返回值校验制造成功。

### D02 策略与基准的边界比较不一致

[策略撮合](../../packages/domain/src/arena-live-match-orders.ts)在价格等于涨跌停边界时双向拒绝；[等权基准](../../packages/domain/src/arena-live-valuation.ts)只在越界时拒绝，等于边界仍可建立持仓。

这说明即使补齐精确价格边界，也没有自动获得一致的撮合口径。应先明确并统一策略与基准的模拟政策，再验证边界案例；该问题属于实现一致性，不能用继续收集资料解决。这里不据静态比较判断真实订单簿在边界处一定能否成交。

## 收尾管理问题

1. 主任务、历史回放子任务和工程 CI 的验收层级混在“剩余任务”中汇报，未持续说明独立范围、交接归属和授权边界。已通过的普通回测整改不应因关联任务继续保持未完成印象。
2. 来源失败后优先增加诊断和资料核验，没有先复查业务成功路径是否存在。港股是具体反例。
3. 阶段检查缺少收敛停止条件。当前报价读取、真正盘中成交资格、真实模型准入和完整历史追平各有不同结果，不能以一项未通过反复要求其余已通过范围重验。

真实 v6 准入、用户明确要求的完整历史追平及修复版本远端 CI 仍是独立未验收义务。本轮没有新增模型、比赛或推送授权，不能删除这些义务来宣称总体完成，也不能把它们继续绑成普通数据修复的启动前提。

## 必须保留的约束

- 报价身份、币种、来源时刻、当前会话与实际允许的延迟；历史决策不得读未来或未完成的输入。
- 明确停牌、退市及已知无法处理的公司行动要按真实状态处理；未知不能被写成已核验正常。
- 资金与可卖份额预留、交易数量及价位精度、费用口径、保护委托关联、事件顺序和策略／基准的一致性。
- 账户版本、事务、幂等、取消、晚到结果及未知耗用保护；真实／影子账本和历史失败回执保留。
- 真实模型资格、预算、来源路由、部署入口及用户授权。契约变更后，只重验受影响范围，保留输入未变的有效证据。

## 建议的有限整改顺序

1. 原位收敛主规格 AC06／AC12、当前三市场规则章节，以及历史规格受影响的依赖要求；明确本期模拟撮合、费用、可卖与交易资金可用政策和不支持的范围。复用现有协议及证据字段，不新增通用规则平台。原严格口径和历史结果继续保留。
2. 修正实际依赖和成功路径：沪港读取、规则刷新、公司行动／估值、历史用途分离及日历窗口，仅改受影响职责。同时统一策略与基准的边界口径。
3. 先用已有冻结材料完成零模型调用的成对验证：可选资料缺失时支持范围可运行；真实必需输入缺失或停牌、资金／可卖数量不够时准确拒绝。沿实际提交、撮合、费用和账户查询入口验证沪港成功分支，保留原失败回执。
4. 必要包检查通过后再核对目标运行态；源码变化需要同步时遵守既有正式入口及当次授权。真实模型准入、完整回放和远端 CI 分别按原所有权处理，普通修复不等待这些外部门禁才能交付自身结果。

收敛完成条件是既有支持范围存在可运行的成功路径、关键拒绝保持正确、实际费用和模拟限制可读、策略与基准口径一致。缩小合同后的通过只证明新口径，不追认原严格市场执行验收。

## 本轮核对与结论边界

本轮核对现有 Spec、Task、上述业务源码、DSA 当前规则代码和 11-23 已保存回执。未调用模型、未读取新行情或抓取新规则正文，未操作比赛、业务数据库、Docker 或 Git 提交／推送。未修改业务代码，不运行与本轮文档复盘无关的构建或全量测试。

结论为：现行共同前提和收尾边界需要整改；港股成功分支及策略／基准边界还存在实际实现问题。复盘本身不证明这些问题已经修复，G03、T06.2 及历史回放等当前未验收状态保持。
