# ThesisLedger 用户体验评审与优化建议

评审日期：2026-10-14（Asia/Shanghai）  
评审方式：以普通用户身份操作当前 Web 界面，完成模拟账户录入、查看分析、策略编辑、历史回测阅读和复盘保存，再用局部源码核对问题。  
文档性质：当前体验评审、用户已确认的产品要求与候选优化建议；实施范围与进度仍由后续 Spec、Task 维护，不替代运行验收。

## 1. 总体判断

项目已经具备比较完整的投资记录、研究、策略和复盘能力。实际使用中，持仓录入、成交记录、行情详情、策略列表、历史回测和复盘快照能够串起来；对缺少证据的收益、真实开仓时间和历史假设，也没有简单补成确定答案。这些基础应当保留。

目前最大的体验障碍是：**功能很多，但用户经常需要先理解系统内部概念，才能判断下一步该做什么。** 页面同时呈现主操作、配置要求、执行模型和证据说明，视觉重点被分散；一些“可用”“就绪”“总资产”的标题，又比实际满足的条件更宽泛。

建议先修复会使用户走错或走不通的流程，再调整首页与工作台的信息层级，最后增加每天都能用到的自选、对比和复盘辅助功能。整体深色主题、表格和抽屉已有一致性，可以在现有设计系统内改进。

用户在本轮评审后明确要求：**实际 / 模拟账户使用一个全局开关，各页面统一跟随，不再分别控制。** 该要求作为 R01 纳入第一批优化，并统一 E01 的建账户行为与下文页面布局。

## 2. 实测范围与证据边界

### 2.1 运行环境

- 前端：当前工作区代码，通过 `pnpm --filter @thesis-ledger/desktop dev --host 127.0.0.1` 启动，访问 `http://127.0.0.1:5173`。
- 后端：使用既有本地 Docker 开发服务，前端代理到 `http://localhost:3000`。本轮没有更新镜像、同步代码或迁移数据库，前后端版本一致性未单独验收。
- 浏览器：主要在 Codex 内置浏览器中操作；检查常规桌面视口、`1024 × 768` 和 `390 × 844` 的 Web 布局，结束后恢复视口。
- 主题：深色。浅色、完整键盘流程、屏幕阅读器、Electron 和 Android/iOS 原生端不在本轮已验证范围。
- 仓库存在大量既有未提交工作。本轮仅新增本评审文档，没有修改应用实现，也没有提交或发布。

这是一轮覆盖九个主入口和主要用户路径的体验评审，**不是所有功能均已端到端通过的验收报告**。导入未开放、模型未配置、行情能力缺失等状态，本身不等于实现缺陷；下文评估的是这些状态如何被用户理解和处理。已有回测结果能打开，也不代表当前环境中新建回测已经通过。

证据分为三类：**实测**指界面操作及返回状态；**源码核对**只用于确认相关渲染或判断逻辑；**建议**是体验判断或候选能力。没有把短暂加载状态、现有测试数据的命名，或未运行的外部服务作为缺陷证据。

## 4. 具体问题与优化建议

### R01｜实际 / 模拟账户使用唯一全局开关（P1，用户已确认）

**用户已确认：** 把实际和模拟账户做成全局开关，所有页面跟随同一次选择，用户不需要在每个页面重新控制。

**当前源码核对：** `AppRoutes` 已维护共享的 `portfolioMode`，初始化为 `actual`，投资组合、收益分析、风险中心各自渲染 `PortfolioModeSwitch` 并调用同一个更新函数。因此，当前三个开关并非三个独立状态；本项重点是收敛可见入口，并让所有账户相关流程完整消费同一上下文。刷新后的恢复、深链接、研究对象、复盘账户及新建表单仍需逐项验收。

**建议交互：**

1. 桌面端将“实际 / 模拟”开关固定在应用侧栏品牌区域下方；侧栏收起后仍能识别当前模式。窄屏端放在应用顶栏。每种布局只保留一个全局切换入口，各业务页显示必要的模式说明。
2. 建议记住本设备上次选择，刷新和重新打开后保持；首次使用默认实际。先恢复模式，再加载依赖该模式的数据，避免先闪现另一模式的内容。
3. 页内账户下拉继续承担“选哪个账户”的职责，只列当前模式的账户；“全部账户”指当前模式内的全部账户。两种模式可分别记住最近使用的账户，恢复时检查账户仍有效。
4. 新建账户继承全局模式，表单用只读文字清楚展示归属。创建另一模式的账户时，通过全局开关切换；现有账户的模式属性及锁定规则保持不变。
5. 切换后，依赖账户的列表、汇总、详情和表单一起更新。目标模式没有账户时展示该模式的空状态和创建入口，不回退到另一模式的数据。

**页面作用范围：**

| 页面或对象 | 跟随全局模式的内容 | 需要保留的语义 |
| --- | --- | --- |
| 投资组合、账户数据 | 账户列表、持仓、现金、成交、估值与新建账户归属 | 切换浏览范围不会改变既有账户和账本事实 |
| 收益分析 | 可选账户、资产汇总、收益序列及相关配置上下文 | 不合并实际与模拟结果；目标账户失效时明确重置选择 |
| 风险中心 | 组合、账户、风险结果与事件的展示范围 | 现有共享规则仍明确标为共享；模拟通知限制与后台执行规则保持原义 |
| 投资复盘 | 可选账户、候选交易、周期统计和账户关联的历史快照 | 快照保留原账户和保存时证据；不能随开关改写历史归属 |
| 研究助手 | 全组合、账户、持仓类研究的对象范围及账户关联任务 | 策略类或其他无账户归属的研究按自身对象展示；已创建任务保留创建时的对象范围 |
| 策略中心 | 涉及账户的策略应用、账户选择和跳转上下文 | 通用策略库、版本、回测结果按自身语义展示；仅支持实际账户的动作在模拟模式下明确说明限制 |
| 市场数据、数据与自动化 | 全局开关继续可见，进入账户相关操作时沿用当前模式 | 行情目录、来源配置、模型与价格等共享设置保持共享；既有后台任务不因浏览模式切换而改变目标 |

**切换过程的边界：**

- 有未保存输入时，复用离开保护；取消切换后，开关、页面和草稿仍处于原模式。不能把已填写的实际成交静默改成模拟成交，或反向转换。
- 查询缓存与请求按模式及账户范围隔离；切换中的旧请求晚到时，不覆盖当前模式的数据。切换失败或加载中有明确反馈。
- URL 中的旧 `accountId`、交易或复盘对象属于另一模式时，说明其归属并引导使用全局开关；不通过局部 URL 参数悄悄改变全局模式，也不保留跨模式的无效选择。
- 全局开关控制当前操作与浏览上下文。已经提交的交易记录、研究任务、复盘快照及后台任务继续遵循提交时确定的对象和范围。

**验收：**

1. 在全局切到模拟后，连续访问九个主入口，账户相关内容均保持模拟；返回、刷新和重新打开后的模式符合记忆规则。
2. 投资组合、收益分析、风险中心不再各放一个可独立操作的模式开关；侧栏折叠及窄屏下仍能查看和切换全局模式。
3. 新建账户默认且实际保存为当前全局模式；账户选择器不混入另一模式；目标模式为空时只呈现该模式的空状态。
4. 用两种模式的不同账户、同一标的和明显不同的金额检查切换，旧缓存与晚到请求不会造成串数据。
5. 输入未保存的成交或研究问题后切换模式，继续编辑可完整恢复原状态；确认切换后不会把旧输入写到另一模式账户。
6. 跨模式深链接和浏览器前进后退有明确处理；共享配置、独立回测结果及已经提交的任务不会被误分类或改变归属。

### E01｜从模拟组合创建账户时丢失模式上下文（P1）

**实测：** 投资组合切到“模拟”后，点击“去创建账户”，新建表单默认选中“实际账户”。需要再次手动切换，才能创建预期的模拟账户。

**影响：** 新用户容易把演练数据写入实际账本。虽然这是本地记账模式而非券商交易，模式错误仍会污染后续分析。

**建议：** 按 R01 继承全局模式，创建表单展示账户类型、币种和只读的“模拟/实际”归属；说明进入记账后哪些字段会锁定。所有创建入口使用同一规则。

**验收：** 全局分别处于模拟和实际时，从组合、账户页及空状态入口创建，默认与保存后的模式均一致；表单内不再提供另一个模式切换器；返回原页面后仍保持相同模式和有效账户范围。

### E02｜放弃跳转后，策略页签与页面内容不同步（P1）

**实测复现：**

1. 在自然语言策略编辑中创建草稿，修改名称或描述。
2. 自动保存完成前，点击顶部“回测任务”。
3. 在离开确认中选择“继续编辑”。
4. 页面仍显示新建策略编辑器，但“回测任务”已处于选中状态；再次点击该页签没有进入任务列表。
5. 先切到“策略库”，再点“回测任务”才恢复正常跳转。

**建议：** 页签选中态以已提交的路由为准，离开保护取消后恢复当前页面状态。自动保存状态应与离开保护一起处理。

**验收：** 分别在自动保存前、保存中和保存后尝试跳转；选择继续编辑时内容、地址和选中页签一致；之后再点击目标页签可以正常导航，草稿内容保留。此处记录了界面现象，具体状态竞态仍需实施时定位。

### E03｜AI 实验存在“无参数可选但要求选择”的死路（P1）

**实测：** 选择“优化已有策略”后，当前基线的固定投入金额、佣金比例、滑点比例均不可选，“下一步”仍能点击，随后显示“至少授权一个可优化参数”。切换到“从零探索”后，原错误提示仍留在页面。

**建议：** 先判断基线版本可优化的参数集合。集合为空时，直接解释不支持的原因，提供“选择其他版本”或“从零探索”；切换模式时清除不再适用的错误；字段错误显示在对应字段附近。

**验收：** 无可用参数的版本不会进入无法满足的校验循环；至少有一个参数的版本可完成选择；模式切换后只保留当前模式的校验。

### E04｜研究“已就绪”与实际生成前提不一致（P1）

**实测：** 研究助手顶部显示“服务已就绪”，新研究抽屉却提示“尚未选择研究默认模型”，生成按钮不可用，抽屉内没有直达相应设置的按钮。默认模型设置还在没有选中候选模型时显示“价格尚未填写”。

**源码核对：** 首页状态依据 `canStart` 显示；价格说明在 `selectedCandidate?.priceConfigured` 不成立时统一落入缺少价格分支。这两个提示没有把“未选择”和“已选择但未配置完整”清楚区分。

**建议：** 面向当前研究动作显示“待选择默认模型 / 待补充价格 / 可开始”等状态，保留服务健康作为独立信息；在阻断处提供直达设置的入口，返回后保留对象、问题和预算草稿。

**验收：** 无默认模型、有模型但缺价格、服务异常、配置完整四种情形的提示与可执行动作一致；选择模型或补价格仍由用户明确操作。

### E05｜估值不完整时，“总资产”容易被当成完整金额（P1）

**实测：** 样本账户已包含现金和持仓，收益分析显示“总资产 ¥10,000”，小字说明“当前估值，行情不完整”；资产配置区域进一步提示缺失 `510300.SH`，权重与再平衡暂停。

**判断边界：** 这里没有认定汇总算法算错。问题是可用部分金额仍被最醒目的“总资产”标题包装，缺失信息需要向下阅读才能完整理解。

**建议：** 卡片改为“已计价资产 ¥10,000”，就近展示“1 个持仓暂未计价”和查看原因；完整后恢复“总资产”。让组合页、收益页对估值完整度使用同一套可读状态。

**验收：** 缺报价、缺汇率、全部可计价三种状态可一眼区分；不把缺失金额补成零；点击缺失提示能定位到具体标的、币种和能力。

### E06｜新手引导长期占据投资组合首屏（P2）

**实测：** 完成账户和持仓录入后，四步引导仍完整展示，剩余项包括行情/通知配置与风险规则。`1024 × 768` 视口下，资产指标约从页面纵坐标 668 开始，持仓标题约在 955；首屏主要用于阅读引导。未发现收起或稍后处理入口。

**建议：** 首次成功录入后，已完成步骤压缩为一行；未完成项变成紧凑提醒。通知与风险配置按用户任务解释，可选择稍后设置。保留重新打开完整引导的入口。

**验收：** 常用桌面视口首屏能看到资产摘要和至少持仓区域入口；已完成任务不重复展开；延后配置不造成虚假的“配置完成”。

### E07｜现金空状态的原因和下一步不够准确（P2）

**实测：** 新建 CNY 账户的现金页显示零余额和“证据完整度：完整”，同时提示“本位币合计暂不可用（缺少可靠汇率）”。现金余额录入放在更多菜单中；只有一个账户时，“账户间划转”禁用，但缺少就近解释。

**源码核对：** `convertedTotal` 或本位币条件未满足时，界面统一显示缺少可靠汇率，不能由这条文案反推实际失败原因。

**建议：** 按真正缺失的条件解释；空状态优先提供“记录现金余额”等可完成的操作；划转不可用时说明需要什么账户条件。

**验收：** 单币种零余额、未设本位币、确实缺汇率分别显示正确原因；用户不需要打开更多菜单才能发现第一步。不得把余额观察误写成真实入金事实。

### E08｜零风险规则时，主操作仍是“立即执行”（P2）

**实测：** 风险总览显示零启用规则、零事件和零通知失败，主要按钮却是“立即执行风险规则”。创建规则需要再切换页签寻找。成本止损的帮助文案为“提交时将输入值%转换为 decimal”。

**建议：** 没有规则时，主要按钮改为“创建第一条规则”；已有规则后再突出执行。阈值输入给出单位和自然语言预览，例如“低于成本价 8% 时提醒”。共享配置与模拟账户通知限制继续明确展示。

**验收：** 用户从空状态能直接进入新规则；无需知道小数存储方式即可填写阈值；预览、输入单位和实际语义一致。

### E09｜策略编写页重复标题多，关键输入出现得太晚（P2）

**实测：** 新建策略页同时出现策略中心、面包屑、新建策略标题和内部配置卡片标题。名称、描述与完整交易逻辑分散在页面下方。自然语言草稿中，恢复和版本相关操作占据上方，尚未输入或生成时已出现醒目的未生成定义提示。

**建议：** 顶部只保留一个任务标题和明确的保存状态；先呈现“策略名称、我想研究什么、使用什么标的”，再进入规则和高级约束。空白草稿采用中性引导，真正失败才使用错误样式。常用配置应能读懂当前买入与退出逻辑。

**验收：** 首屏能找到核心输入和下一步；创建前能用自然语言复述策略的进入、退出和仓位规则；恢复记录、版本信息和高级配置仍可访问。

### E10｜普通回测配置过早要求处理原始 JSON（P2）

**实测：** “再次运行”的配置中，执行模型使用大块 JSON 文本框；“数据与假设”页包含密集的模型字段、资金 JSON 和来源标识。高级用户可以审查，但普通用户很难判断哪些值需要改。

**建议：** 给常用配置提供结构化摘要与控件：日期、初始资金、价格口径、成交假设、费用、基准。JSON 保留在高级编辑中；重要限制先用简短说明展示，完整证据再展开。

**验收：** 常见回测可以不手写 JSON 完成配置；高级模式与表单之间有明确转换和校验；不会静默丢弃高级字段、历史可得性约束或不支持的设置。

### E11｜技术标识直接进入选择器与结果表（P2）

**实测：** AI 实验的基线选择器当前值显示 UUID，展开选项才看到“策略名称 · v1”；从零探索中市场和资产类型回显 `CN`、`stock`；回测成交表出现 `buy`、`sell`、`signal`；标的目录出现 `MUTUAL_FUND` 等值。

**建议：** 当前回显和选项共用显示标签映射；以名称、代码和版本帮助识别对象。技术 ID 仅在详情中用于复制和排查。不同市场的交易术语按业务语义翻译，未知值有明确兜底。

**验收：** 已选值与选项的名称一致，初次加载及刷新后均正确；常用页面不要求用户识别 UUID；未知枚举不会变成空白或被错误归类。

### E12｜回测成交数字保留过长，难以比较（P2）

**实测：** 一个已有回测的数量显示为 `7.3764367439917651610204289422242141929937`，价格也保留很多小数位。表格横向阅读负担很大。

**判断边界：** 该结果采用归一化研究口径，长小数或非整数数量不能直接判为真实交易规则错误。

**建议：** 按金额、价格、比例和数量统一显示精度，数字右对齐并使用等宽数字；提供完整精度详情或复制。归一化单位与实际股数的区别就近标明。核算仍保留原始精度。

**验收：** 常用视口可比较成交方向、时间、数量和金额；小额、负值与接近零的收益显示一致；复制原值不会丢精度，显示格式不改变计算结果。

### E13｜复盘时间输入和显示不符合日常使用习惯（P2）

**实测：** 候选、周期和历史筛选出现“带时区的 ISO 8601 时间”输入；历史按钮直接显示 `2026-10-13T21:07:17.688Z`。同一笔账户成交在复盘中也显示原始 UTC 时间。

**建议：** 使用日期/时间选择器，默认按当前明确的用户时区展示；常用周期提供快捷项；需要排查时再展开 UTC 原值。结束时间是否包含应以用户可理解的说明呈现。

**验收：** 无需手写时间格式即可筛选；跨日和边界样本与当前区间语义一致；账户、成交、复盘历史显示相同时间口径；时区信息可查。

### E14｜复盘证据很完整，但结论和补充路径被淹没（P2）

**实测：** 持有中样本的多个不可统计原因重复拼接；周期分析暴露很长的 `TRADE_CYCLE:trade:trade-projection-v1:…` 标识；结果一次呈现 17 项指标，反复显示证据不足。“证据一致”与不能计算胜率同时出现，用户需要自己区分含义。

**建议：** 先给一个可读结论：“仍在持有，暂不计入已结束交易统计”；将原因按真实成交、原始计划、基线观察分组去重；区分“保存后是否变化”和“证据是否足够”两个状态。缺失项提供合法的补充入口或说明无法补证，完整指标和审计信息保留在展开区。

**验收：** 用户能先看懂当前可得结论和缺什么，再查每项证据；不引导把今天补写的计划当作当时已存在的事实；保存后重新打开仍保留原输入和结果。

### E15｜市场路由页一次呈现过多配置（P2）

**实测：** 路由页面挂载了 96 个选择框，对应约 48 组主备配置；需要在很长的页面中找到特定市场和能力。未看到帮助收敛这些选择框的页面级筛选。

**建议：** 按市场、能力类型和异常状态筛选；默认优先展示与当前使用场景相关的路由；分组折叠，保存前展示具体变更。为常见场景提供可审阅的配置建议，但不自动启用来源或扩大准入。

**验收：** 能快速定位“港股静态资料”等具体能力；筛选不会丢失尚未保存的修改；主备关系、不可选原因和保存范围清晰。

### E16｜启用、配置和真实可用的状态需要进一步区分（P2）

**实测：** 市场数据摘要显示“14/20 个数据源可用”，列表同时有启用、待检查、配置就绪、来源尚未准入等状态；组合报价显示“最新”，但详情中实时能力不可用。

**建议：** 数据源摘要分别说明“已启用、已配置、近期检查通过”的范围；报价明确时间和口径，例如某交易日收盘价、延迟行情或实时行情。最近拉取成功与数据本身的时间分别保留。

**验收：** 用户不会把已启用理解为所有能力均已可用，也不会把最近取得的日线值理解为实时价格；未知与未测试状态明确保留。

### E17｜标的搜索与能力错误缺少任务导向（P2）

**实测：** 搜索 `00700` 返回多条以相近数字开头的基金及其他模糊结果；输入完整 `00700.HK` 后，仍看到其他市场的模糊结果，未明确指出精确项是否找到。静态资料查询返回“ThesisLedger API 503：当前 Control 未配置对应能力路由”。

**判断边界：** 不能据此认定腾讯控股在所有来源都不存在，也不能把内部路由未配置说成上游收费或请求失败。

**建议：** 完整代码优先精确匹配，未命中时明确提示并单列相似结果；提供市场筛选。错误用“港股静态资料尚未配置读取路由”等任务语言描述，附带直达对应配置的入口；原始错误保留在详情。

**验收：** 精确命中、无精确项、多市场同代码和能力未配置四种状态明确；不自动改用其他市场标的；能区分未发起上游请求与上游确实失败。

### E18｜不可用和空状态经常缺少就近操作（P2）

**实测：** 导入、对账入口标为暂未开放；通知无可用服务；诊断文案让用户通过 Notification API 处理重试。用户知道功能不可用，却未必知道能在产品里做什么。

**建议：** 对“未开放、待配置、没有记录、查询失败”使用不同空状态。能操作的给直达入口，未开放的给当前替代路径。自动化列表补充最近一次业务结果摘要与失败处理入口，复用现有运行记录。

**验收：** 每个阻断状态都有明确原因；不存在指向普通用户无法使用的 API 操作指引；已有人工录入和设置入口可直接到达。计划任务已有可读时间选择，不需要重做为新的调度系统。

### E19｜用户文案混入内部实现，并且未适配模拟模式（P2）

**实测：** 模拟账户中仍显示“录入真实成交”；录入说明包含稳定客户端命令 ID、重复重放、`PARTIAL` 观察等概念。风险阈值说明要求理解 decimal。

**建议：** 界面先说明业务含义，例如“记录这笔模拟成交”“更新这一只标的的持仓观察”。“成交记录与余额观察不同”是重要约束，应保留；幂等、原始枚举和存储格式移入帮助或诊断详情。

**验收：** 模拟与实际文案匹配当前模式；不会把模拟事实描述成真实发生的交易；普通录入无需理解实现术语，同时仍能分辨观察值、成交和现金流。

### E20｜窄屏底部九个图标不利于发现功能（P2）

**实测：** `390 × 844` Web 视口底部展示九个仅图标入口，需要横向滚动；测得单项约 `44 × 48`，根页面未出现横向溢出。因此这里的问题是辨识和导航层级，并非已经确认触控尺寸不达标。

**建议：** 选择少量高频入口，显示图标和短标签，其余放入“更多”；选中态与当前位置清楚对应。复杂配置优先采用单列布局与局部展开。

**验收：** 窄屏用户无需猜图标即可找到主要任务；全部原有入口可达；弹层、底部导航和页面主操作互不遮挡。本条仅是 Web 检查结果，不能代替原生端验收。

### E21｜有成交数据时，表格仍带有空表语义（P2）

**实测：** 模拟成交保存后，表格已有数据行，但 DOM 可访问性结构仍出现表格说明“暂无成交记录”。

**建议：** 将表格名称与空状态文案分开：表格始终叫“成交记录”，仅在成功加载且确实为空时显示无记录；加载中与失败采用各自状态。

**验收：** 空列表、加载、失败、有数据四种状态的视觉与可访问性描述一致。需要补充屏幕阅读器验证，本轮未执行。

## 5. 视觉调整方向

当前界面的主要问题是层级和密度。建议沿用已有色板、原子类、表格、抽屉和组件变体，通过减法整理页面。

| 维度 | 当前观感 | 具体调整 |
| --- | --- | --- |
| 页面标题 | 面包屑、分类名、主标题、卡片标题重复 | 一个主标题；副标题只解释当前任务；内部标题避免重复页面名 |
| 主操作 | 执行、创建、配置、恢复等同级出现 | 每个状态突出一个下一步，其余使用次级按钮或更多菜单 |
| 卡片层级 | 边框和容器层层嵌套 | 同一任务内优先分区与分隔线，把卡片留给真正独立的信息 |
| 文字层级 | 大量说明同为小号灰字，重要限制容易被忽略 | 结果、限制、解释分层；关键限制靠近结果，长说明可展开 |
| 状态颜色 | 初始空白、未配置和真实错误容易共享强提示 | 空白中性、待处理克制、错误明确；涨跌色继续由用户偏好控制 |
| 数字排版 | 长小数、单位、缺失原因在表格中抢空间 | 统一单位与显示精度，右对齐；缺失状态与零值明确区分 |
| 时间与名称 | UTC、UUID、枚举穿插在人类可读信息中 | 默认使用本地时间、业务名称与中文标签，原值可查看和复制 |
| 信息披露 | 工程配置、假设和结果同屏展开 | 先结论，再原因，最后完整证据与高级配置 |
| 账户模式 | 同一模式的切换入口分散在业务页 | 固定在应用外壳，页面内保留当前模式说明与该模式下的账户筛选 |

应用外壳固定展示全局模式；投资组合页可以按下面的阅读顺序组织：

```text
应用侧栏：ThesisLedger → 全局实际 / 模拟开关 → 主导航

投资组合                              账户范围      录入成交

资产估值及完整度        累计表现        可用现金        待处理事项

紧凑提醒：缺少 1 项报价 / 尚未配置风险规则              查看或稍后

持仓列表：名称、数量、现价及时间、成本、收益、仓位、操作

资产趋势与配置（有足够数据时展示；不足时说明还需要什么）
```

这只是信息排序建议。收益口径、数据可用性和哪些摘要有可靠输入，应沿用既有领域契约，不为了填满布局制造指标。

## 6. 更便于日常使用的候选特性

以下是候选增强，不是已经确认完全缺失的底层能力。实施前应与现有 Spec、Task 和需求池核对，优先复用已有查询、行情详情、研究任务、策略版本和复盘快照。

| 编号 | 场景与建议 | 最小可用范围 | 关键边界 |
| --- | --- | --- | --- |
| F01 | **独立自选与观察笔记**：想跟踪一个标的，但暂时没有持仓 | 从标的目录或行情详情收藏；分组、排序、一句话观察理由；进入行情与研究 | 收藏不创建持仓、不产生交易事实；已有非持仓标的行情查询应直接复用 |
| F02 | **每日待办摘要**：打开产品先知道哪些事情值得处理 | 汇总报价缺失、待复盘交易、失败任务等可操作事项；每项直接进入对应页面 | “未配置”与“运行失败”分开；用户可延后可选事项；不能用红点制造无意义负担 |
| F03 | **回测并排对比**：同一策略改参数后，判断变化来自哪里 | 选择 2–4 个已有结果，比较收益、回撤、成交和参数差异 | 对时间范围、价格口径、初始资金、费用与执行模型提示不可比差异；不直接宣布某结果更优 |
| F04 | **图上复盘**：把买入、卖出、计划和当时价格放到一张图中 | 在既有行情图上显示真实成交标记，点击查看原始记录及关联计划 | 观察值与成交分层；历史计划时间、复权和单位明确；缺失事实继续未知 |
| F05 | **收益来源拆解**：知道资产变化来自行情、投入、费用还是其他事件 | 在收益分析中先提供能够可靠对账的金额桥接及明细，再扩展复杂归因 | 入金不算投资收益；分红、汇率、未实现损益和费用按既有口径分开，证据不足时不强行分摊 |
| F06 | **跨页面连续操作**：从一个持仓直接研究、设规则、复盘，不重复选账户和标的 | 持仓与标的详情提供上下文入口；返回后保留筛选、已加载范围和草稿 | 沿用 R01 的全局模式与有效账户范围；跳转不自动执行 AI、规则或写入交易；避免重做已有列表/详情抽屉 |

建议先评估 F01、F06：它们可以复用现有对象与页面，直接缩短日常路径。F02 需要统一状态含义后再做；F03–F05 涉及比较或财务口径，应分别建立可验证的需求边界。

## 7. 建议推进顺序与验收方式

### 第一批：把当前流程走通

优先落实 R01，并同步修复 E01，统一模式入口、状态传递和新建账户归属；同时处理 E02–E05 与 E11 的错误回显。验收覆盖“全局模式一致性、取消跳转、无可优化参数、研究配置阻断、部分估值”。全局切换使用两种模式的固定账户验证，其余场景使用模拟账户；状态修复需要有针对性的行为测试，不能只核对截图。

### 第二批：让首屏与输入更清楚

处理 E06–E14 中的首页层级、现金与规则空状态、策略编辑、时间控件、数字格式和复盘摘要。先优化投资组合与一个典型编辑页，再把已验证的模式推广到其他页面。纯布局调整以实际浏览器检查为主，保留业务行为。

### 第三批：把配置变成可完成的任务

处理 E15–E19 及 E21，建立状态含义、错误处理入口和可访问性描述的一致性。涉及模型、报价、通知和调度时，把真实服务验证单列，不能以表单可保存代替运行成功。

### 第四批：增强高频使用与窄屏体验

评估 F01、F06 和 E20，再决定是否进入对比、图上复盘和收益拆解。涉及跨模块契约或系统性调整时，按仓库规范建立成对 Spec/Task；本报告保持问题与建议的证据入口，不替代实施设计。

### 建议保留的回归场景

- 新用户从模拟入口创建账户，录入一条持仓和现金观察，回到组合即可看到结果及估值范围。
- 全局切换后跨页、刷新、返回、深链接、空账户和未保存表单行为一致，慢请求不会把另一模式的数据带回来。
- 编辑草稿后取消跳转，再次导航正常；自动保存、未保存提示和页签状态一致。
- 未配置服务时看懂缺什么，进入设置后返回，原问题和对象不丢失。
- 不支持优化的策略版本有明确出口；支持的版本可以选择参数进入下一步。
- 一条有报价、一条无报价的持仓同时存在时，所有总额与完整度表述一致。
- 持有中、已结束、缺少计划和含基线观察的复盘分别说明可统计范围，保存后能按原证据读取。
- 常规桌面、`1024 × 768`、窄屏 Web 分别检查主操作可达、长名称、数字列、弹层和导航；原生端另外验收。

## 8. 已有能力应当继续保留

- 实际与模拟账户隔离，以及观察值、成交和现金流之间的语义区别。

- 回测中的执行模型、数据假设和复现信息；调整展示层次后仍应完整可查。

- 自动化已有的人类可读时间选择、收益分析已有的目标配置与再平衡限制。
- 模型选择、费用授权、来源准入和共享规则的明确边界。
