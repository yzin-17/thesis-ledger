# 页面一致性、信息密度与状态表达评审

日期：2026-10-19。范围：Desktop Web 的九个一级页面；按用户要求先核对任务文档，再使用 Taste Skill 的应用界面规则审查真实渲染，并补充有数据、空状态和读取失败场景。本文是评审与修复建议，未修改产品源码，未关闭原任务验收项。

## 1. 结论

用户指出的问题成立。主要原因是页面头、全局上下文、页签和局部工具栏缺少统一的层级规则；已有共享组件不能自动解决这些组合差异。反复套框和说明文案又进一步抬高了操作与数据的阅读成本。

更应优先处理的是状态真实性：收益读取失败仍出现无历史引导，风险指标在请求失败时显示为零，复盘空列表下仍要求选择对象。建议实施顺序为：**纠正失败与空状态 → 统一页面骨架和全局模式入口 → 压缩首屏文案与边框 → 修复窄屏细节**。

## 4. 优先发现

### U01｜读取失败被混成空数据或零值（P1）

- **收益**：读取失败横幅与“暂无收益历史／完成数据配置”同时出现。`PerformanceTrendSection.tsx:302–355` 在没有点位时无条件进入 `EmptyTrend`，错误横幅随后与它并排渲染。用户可能误以为需要重新配置数据。
- **风险**：请求失败后仍显示“启用规则 0／严重事件 0／通知失败 0”。`RiskCenter.tsx` 将缺失查询值转为空数组，`RiskOverview.tsx:55–57、102–114` 无条件按数组计数。未知风险被表达成零，优先级高于纯视觉调整。
- **市场**：服务不可用时，部分区块仍显示“等待策略数据／正在读取路由策略”，已结束的失败和加载语义混杂。

修复方向：成功空结果才显示空态；无缓存读取失败显示破折号、原因和就近重试；有旧数据时保留旧数据并明确时效。加载、失败、缺能力和没有记录应各有独立文案。不要让失败态把用户引向与故障无关的首次配置流程。

证据：[收益失败](../../.recovery-artifacts/ui-taste-audit-2026-10-19/performance-error-1440.jpg)、[风险失败](../../.recovery-artifacts/ui-taste-audit-2026-10-19/risk-error-1440.jpg)、[市场失败](../../.recovery-artifacts/ui-taste-audit-2026-10-19/market-error-1440.jpg)。

### U02｜页面头、创建动作和刷新缺少稳定规则（P2）

多数页面使用眉题、中文标题、说明三层；研究和策略标题更简洁；复盘同时显示“投资复盘”和“投资复盘工作台”。刷新在页面头、列表工具栏或错误卡片中出现，视觉权重也不一致。`PageHeader.tsx:22、42` 顶部对齐加 `pt-1`，导致按钮与眉题而非中文标题对齐。

“新建研究”在页头，“新建策略”在搜索行，“新增或更新 Provider”在区块头。不同业务范围允许不同位置，但需要统一“页面级”和“当前列表级”的规则。不能把所有刷新机械搬到页头，研究列表已有明确的局部刷新合同。

建议中文标题成为统一锚点，移除不提供新增信息的眉题及说明；保留真正影响判断的数据时点。主动作与标题同一行基线，局部动作与所属列表工具栏同一行。统一图标、按钮尺寸、加载态与可访问名称。

证据：[研究有数据](../../.recovery-artifacts/ui-taste-audit-2026-10-19/research-populated-1440.jpg)、[策略平板](../../.recovery-artifacts/ui-taste-audit-2026-10-19/strategy-populated-768.jpg)。

### U03｜Tab 本身已有复用，组合顺序仍不一致（P2）

多页已共用下划线 Tab；主要差异来自 Tab 前面插入账户筛选、状态徽章、说明或配置摘要，造成相同导航层级不断上下移动。研究“当前模式研究／历史报告”使用实心按钮式选择，又与“新建研究”的主操作争夺注意力。

建议固定层级为“标题与页面动作 → 必要的上下文 → 一级 Tab → 当前 Tab 的筛选及工具栏 → 内容”。全页适用的账户上下文位于 Tab 上方；仅作用于当前表格的筛选位于下方。导航用下划线 Tab，局部范围选择用较弱的分段控件，执行动作才使用主按钮。

### U04｜首屏由引导占据，已有数据仍难以看到（P2，复现旧 E06）

已有账户及三项持仓时，四步引导仍完整展示在资产指标和持仓之前。1440×900 下持仓表接近首屏底部；390×844 下首屏主要是引导，投资者关心的数据被推到下方。

建议已有持仓后将完成步骤收起，未完成配置压缩为一条提醒，保留展开完整引导与稍后处理入口。空持仓时集中保留一个明确的录入动作，避免空态说明与完整引导重复解释。

证据：[桌面有持仓](../../.recovery-artifacts/ui-taste-audit-2026-10-19/portfolio-populated-1440.jpg)、[手机有持仓](../../.recovery-artifacts/ui-taste-audit-2026-10-19/portfolio-populated-390.jpg)。

### U05｜层层边框制造了过多同等权重的容器（P2）

组合引导是外框、步骤分块、编号圈与按钮边框叠加；市场策略是 Card、路由行、表单控件多层框；研究工具栏和列表分别成框，手机列表又逐行卡片化。风险概览静态卡片还使用 `shadow-sm`。

建议同一业务区块保留一层主要边界，内部用留白、行分隔或浅底色表达结构。输入控件、表格行、独立可操作区块的必要边界继续保留；不要全局删除边框。优先处理引导、市场路由和研究工具栏三个区域。

证据：[市场路由](../../.recovery-artifacts/ui-taste-audit-2026-10-19/market-populated-1440.jpg)、[研究手机](../../.recovery-artifacts/ui-taste-audit-2026-10-19/research-populated-390.jpg)。

### U06｜说明、技术标识与重复空态抢占阅读空间（P2）

- 收益走势图总是展开周期聚合规则；这类说明适合帮助入口，影响当前数据解释的异常信息仍应保留。
- 市场页反复呈现修订、同步及服务信息；提供方列表混用“提供方／Provider／unknown”等表达。普通使用视图应使用稳定中文标签，诊断详情可展开查看。
- 复盘同时出现“没有可复盘对象”和“选择一个复盘对象”。`JournalReviewWorkspace.tsx:107–129` 在候选组件后，只要未选中便再渲染第二个空态；候选查询失败时也会这样出现。
- 复盘日期要求输入“带时区的 ISO 8601 时间”，并直接展示“含／不含”边界；用户需要承担接口格式转换工作。

建议每个区域只保留一个当前状态说明及一个有效下一步；复盘由父层协调列表与详情空态。时间输入使用本地化日期时间控件，时区及区间精度通过简短帮助说明，底层查询语义保持不变。此项延续旧评审 E13、E15、E19。

证据：[复盘空态](../../.recovery-artifacts/ui-taste-audit-2026-10-19/journal-empty-1440.jpg)、[复盘手机](../../.recovery-artifacts/ui-taste-audit-2026-10-19/journal-empty-390.jpg)。

### U07｜实际／模拟切换缺少清楚的上下文归属（P2）

当前开关在品牌和导航之间居中悬置，宽约 70px；窄屏又单独位于顶部左侧，与主题按钮同一排。它控制全局账户范围，却看起来像一个轻量偏好设置。源码位置为 `AppShell.tsx:56–58`。

建议继续保持唯一全局入口，放入明确的上下文区：桌面与品牌左对齐并显示“账户范围”，提供“实际／模拟”两个可见选项；窄屏在正常文档流内显示紧凑上下文行。不要重新引入各页面独立模式开关。必须保留模式隔离、持久记忆、未保存草稿和进行中操作的保护；该布局调整需要同步修订现行 Spec。

证据：[桌面研究](../../.recovery-artifacts/ui-taste-audit-2026-10-19/research-populated-1440.jpg)、[手机市场](../../.recovery-artifacts/ui-taste-audit-2026-10-19/market-populated-390.jpg)。

### U08｜窄屏操作列发生逐字换行（P2）

768×1024 的策略库里，“回测”被拆成上下两个字，多行重复。标题已截断，但操作列未得到稳定的最小宽度。应优先保证动作完整，调整次要列展示或表格横向容纳策略，避免仅给文字加不换行后造成新的溢出。

390 宽底部导航仍有多个无文字图标，功能发现成本较高；这与旧 E20 一致。本轮不将“横向页面未溢出”当成导航可用性的证明。

证据：[策略 768 宽](../../.recovery-artifacts/ui-taste-audit-2026-10-19/strategy-populated-768.jpg)。

## 5. 建议统一的页面规则

| 元素 | 统一规则 | 必须保留的区别 |
| --- | --- | --- |
| 页面标题 | 单一中文标题，动作与其对齐；说明按需出现 | 时点、数据不完整等当前事实不能隐藏 |
| 创建按钮 | 页面主任务放页头；只属于当前列表的创建放该列表工具栏右侧 | 不把录入成交、创建账户和新建研究视为同一作用域 |
| 刷新 | 统一图标按钮、尺寸和加载反馈；就近刷新所属范围 | 页面刷新与列表刷新应有不同的可访问名称 |
| Tab | 同级导航同一外观与间距，固定在同一层级 | 过滤、范围选择与执行按钮分开表达 |
| 容器 | 一个独立区域一层主要边界，内部优先行与留白 | 控件、可操作区域仍要可辨识 |
| 空态 | 一个说明、一个当前可执行动作 | 筛选无结果、未配置、成功无记录各有原因 |
| 失败态 | 不输出伪零值；错误、旧数据和重试就近组合 | 保留有效旧数据与其时效，未知保持未知 |
| 全局模式 | 壳层唯一上下文入口，实际和模拟含义清楚 | 模式切换门禁和草稿保护不能因视觉调整丢失 |

## 6. Taste 观察与工具结果

按应用界面规则评价，当前优点是导航较克制、数据颜色基本有业务语义、表格与走势图已有明确结构。最明显的三处视觉问题为：有数据组合页的引导压住首屏、全局模式孤立、标题和局部工具栏的排列不稳定。修复它们应先于换配色、加动效或重绘整套组件。

独立检查器检查了组合空持仓视图的 1440、768、390 宽截图，测得页面水平溢出为 0；已人工查看三个尺寸首屏。它没有覆盖所有页面和状态。自动检查仍报告眉题、勾号字符和系统字体检测告警，因此不能写成“检查器全部通过”。

静态 Taste 扫描涉及 473 个文件，报告 5 个失败项和 152 个警告；这些是启发式结果，不能直接当作缺陷数量。例如图表紫色是数据系列色，输入框中的 example.com 是示例，日期组件的透明文字用于原生控件叠层，都需要按用途判断。未因此改动依赖、过滤规则或现有样式。

## 7. 后续实施的最小验收边界

1. 先覆盖收益、风险、复盘、市场的“无缓存失败／成功空结果／有旧数据刷新失败”，避免失败归零或重复空态。
2. 确认页面骨架与全局模式的新合同，再调整共享组件和页面组合，继续使用已有原子类、组件变体与 `className`。
3. 对组合、研究、策略、市场在 1440、768、390 宽进行同状态对照；确保主动作、Tab、操作列、全局模式和首屏数据均清楚。
4. 局部 UI 与测试通过后，再分别记录 Web、Electron、真实 Provider 和业务流程证据；本次模拟截图不替代这些门禁。

第一轮仅新增此评审及被忽略的本机证据附件，保留其他任务的工作区改动，未修改任务勾选状态或执行配置保存。后续按用户要求完成第二轮交互排查并建立下方 Spec/Task。

## 8. 填充数据后的交互排查
