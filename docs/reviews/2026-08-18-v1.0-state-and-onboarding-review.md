# V1.0 状态体验与首次启动 Review

## 本轮实现

- Desktop 使用统一 `DataStateBanner` 表达 loading、empty、error、stale，已接入 Portfolio 详情、Risk、Import、Performance、Strategy、AI 和 Provider 页面；Market 详情继续保留加载骨架，并在 Quote 陈旧时显示 stale。
- Mobile 只读 Store 使用同一组状态值，Portfolio/Risk 数据都通过 `@investment-os/api-client` 读取，不直接调用 DSA。
- Desktop 账户、持仓和 Risk 规则表单在异步提交前保存原始 form 引用，Mobile Store 对并发刷新使用序列号保护，旧响应不会覆盖新状态。
- Desktop 的 Strategy、AI、Provider、Performance、Risk、Import 和 Position Detail 异步读取也使用序列号保护；切换账户、重试或快速刷新时，旧响应不会把页面回写成正常最新状态。
- Electron release 窗口最小尺寸已降到 520×520，允许实际进入 CSS 的 800px/520px 响应式断点；静态可访问性门禁会校验该配置。
- 空组合页显示四步 First-run Onboarding：创建账户、手动或截图导入、数据源与 Feishu、风险规则与提醒限制。界面只说明服务端安全管理敏感凭证，不向新用户暴露环境变量名；部署层仍由 `FEISHU_WEBHOOK_URL` 提供 Webhook。

## 已执行验证

- `pnpm test`：Desktop UI 契约测试、Mobile 6 项状态/运行时配置测试和既有 Domain/Schema/Server/DSA Adapter 测试均通过。
- `pnpm --filter @investment-os/desktop build`：Vite production 静态资源构建通过。
- Desktop Electron 生产入口已补齐；本机生成未签名 macOS DMG 与 Windows NSIS EXE，DMG `hdiutil verify` 通过。目标平台安装启动仍属于 T272 发布门禁。
- `pnpm typecheck`、`pnpm lint`、`pnpm format`：通过。
- 开发服务浏览器已实际点击 8 个主导航并核对页面标题，且在 800px/520px 视口验证主导航和 Portfolio 内容；该证据不替代 release 包安装或设备验收。
- 2026-08-01 在最新 Vite 开发服务中清空 mock 组合后，浏览器实际看到 `四步完成第一次闭环` 区域、4 个步骤及账户/手动录入/截图导入/数据与自动化/风险中心入口。发现并修复异步表单读取已失效 `event.currentTarget` 导致 `onSaved` 不执行的问题后，mock API 创建账户即时出现在选择器，创建持仓即时显示 `¥178,000.00` 和持仓列表。该流程只证明 Desktop 开发服务的交互接线，不替代真实数据库、Feishu、Data Provider 或 release 包验收。
- macOS DMG 安装包通过 `scripts/desktop-qa-fixture.mjs` 实际观察到 `empty`（首次启动）、`error`/`stale`（已有数据刷新失败时保留陈旧提示）、`stale`（`partial=true` 与持仓 `stale=true`）和 `ready`（账户/持仓创建后）四类页面状态；pending 请求也观察到 Portfolio、Risk、Import、AI 的 loading。逐页状态矩阵与 Market empty/loading 的证据边界见 `docs/reviews/evidence/desktop-macos/2026-08-18-state-matrix.md`；真实 Compose/设备逐页注入仍待完成。
- 2026-08-01 又在 macOS release 窗口连接真实 Docker Compose API，完成账户/持仓录入、截图导入草稿与提交、Risk 规则、Strategy/Backtest、Journal、AI 和 Provider/Automation 页面烟测；真实 API 的操作、窗口尺寸与截图见 `docs/reviews/evidence/desktop-macos/2026-08-18-compose-release-e2e.md`。这补齐了主要真实 API 写入路径，但不等同于全新数据库 onboarding 或逐页五类状态注入。
